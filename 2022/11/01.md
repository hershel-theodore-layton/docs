# 2022-11-01

## Highlights

- Module import and export rules now survive compilation and are exposed through reflection. Runtime enforcement is not enabled by this change. [a2e15b83bd](https://github.com/hershel-theodore-layton/hhvm/commit/a2e15b83bd3ff360068dcf584264a42d85fe0c90)
- `internal` methods may now use `<<__DynamicallyCallable>>`; private and protected methods remain rejected. [235cd7a253](https://github.com/hershel-theodore-layton/hhvm/commit/235cd7a253ad79b283f0f56997bf9dc584696882)
- The typechecker is more reliable when inferring disjunctive subtype constraints, and an internal error involving already-solved type variables has been fixed. [e1e756b3f7](https://github.com/hershel-theodore-layton/hhvm/commit/e1e756b3f79a00d41b6cae599e53ec5cc6c732d2) [4500589618](https://github.com/hershel-theodore-layton/hhvm/commit/4500589618c3b217d94e1f5f8d069af5f17bd8c2)
- `HH\execution_context()` now declares `[read_globals]` instead of implicitly requiring `[defaults]`. A capability list is the callee's requirement, so this narrows the obligation on callers rather than granting the callee extra access: a caller that provides `read_globals`, or any superset such as `defaults` or `globals`, can call it. [0f776c17fd](https://github.com/hershel-theodore-layton/hhvm/commit/0f776c17fdb3ac0dcfb0045f0feb76e1496e174c)
