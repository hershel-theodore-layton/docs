# 2022-12-02

## Highlights

- Invalid types encountered while localizing `where` constraints are now reported. This closes a type hole involving generic type-constant accesses and can reveal errors in signatures that previously passed. [b614e9be2f](https://github.com/hershel-theodore-layton/hhvm/commit/b614e9be2fc5d9cef68eeddb45a4d2d48518400e)
- `Pair<T1, T2>` is now typed as a `ConstVector<T1 | T2>`. Collection operations such as `at()`, `map()`, `values()`, and `toImmMap()` consequently preserve the union of the two element types instead of widening to `mixed`. [dd7ca5fa24](https://github.com/hershel-theodore-layton/hhvm/commit/dd7ca5fa244acf5a9b33504b294481e0296f5de0)

## Future Changes

- A trait and its required class may declare the same private property without producing a spurious ambiguous-access error in the pre-stable `require class` feature. In this case the declarations describe the same property rather than shadowing one another. [81231622de](https://github.com/hershel-theodore-layton/hhvm/commit/81231622de2f197b16651370f965b2805ccb6857)
- The unstable type-refinement implementation now supports loose `as` and `super` bounds, including their subtyping rules. Accessing a type member through an inexact refinement is rejected because the member is not known exactly. The feature still requires the `type_refinements` unstable-feature opt-in. [1eaa4bece4](https://github.com/hershel-theodore-layton/hhvm/commit/1eaa4bece45601e0f1a2ca5e8b8f6b1991c49f42)
