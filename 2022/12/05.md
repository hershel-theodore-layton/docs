# 2022-12-05

## Highlights

- A type structure derived from an unbounded type constant no longer exposes class-specific fields such as `classname`. Add an appropriate classish bound before accessing those fields; an unbounded type constant is treated consistently with one bounded by `mixed`. [ad69f94600](https://github.com/hershel-theodore-layton/hhvm/commit/ad69f946003e1530e0b981600f5b26bb0bc4d0cd)
- Hovering over declarations now explains the `class`, `interface`, `trait`, `enum`, `enum class`, `type`, and `newtype` keywords. [d079884920](https://github.com/hershel-theodore-layton/hhvm/commit/d0798849205113b2dbd315e0445d29cb7b231844)

## Future Changes

- Unstable type refinements now use dedicated typing error codes: 4468 for access through an inexact refinement, 4469 for unsupported refinements, and 4470 for invalid class refinements. Suppressions written against the former generic error codes may need updating when adopting the feature. [c50044fcc6](https://github.com/hershel-theodore-layton/hhvm/commit/c50044fcc6c2da86eaeffee073067a54d00e2be0)
