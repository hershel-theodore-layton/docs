# 2023-09-18

## Highlights

- Corrected repo-authoritative support for soft deployments has relanded. Soft-package functions, classes, methods, and constants remain in the repo and emit boundary warnings rather than collapsing into undefined-symbol failures. [d786fbef34](https://github.com/hershel-theodore-layton/hhvm/commit/d786fbef34a10f405fea153e6d3601b9a061a915)
- `hh_single_complete --resolve` now exposes completion signatures, making the IDE's resolved completion data available to command-line tests and tooling. [8a7ff6c02c](https://github.com/hershel-theodore-layton/hhvm/commit/8a7ff6c02cdadfee971195d0630f46c5b8b8cccb) [cc442823ec](https://github.com/hershel-theodore-layton/hhvm/commit/cc442823ec18f161a7a25e668fc8a03531a90391)

## Breaking Changes

- A source file may now contain at most one `new module` declaration. Projects that collected several module definitions into one file must split them into standalone files. [21f428203b](https://github.com/hershel-theodore-layton/hhvm/commit/21f428203bad0ca6f4e765b4dcd8388bee8682d4)
