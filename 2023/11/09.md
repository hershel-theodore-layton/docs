# 2023-11-09

## Highlights

- A static method call through an invalid `string` receiver still reports the receiver error, but its result is now typed `dynamic` rather than an unconstrained variable that commonly collapsed to `nothing`. This keeps code behind a fixme from gaining an unsoundly precise type. [26b37f5439](https://github.com/hershel-theodore-layton/hhvm/commit/26b37f54393b98cbc61d36378d43402977058455)
- Array access through a nullable value now continues with the array's element type after reporting the nullability error. Suppressing that first error no longer causes downstream expressions to infer `nothing`. [d0ff8a66a2](https://github.com/hershel-theodore-layton/hhvm/commit/d0ff8a66a207650b0db017728be8ff47bb694287)
- XHP auto-close edits now place the cursor before the generated closing tag. [a9b6c46a54](https://github.com/hershel-theodore-layton/hhvm/commit/a9b6c46a5499619c40319791a62cff1b5b7ae089)
- The VS debugger's variable command now serializes all remaining HHVM datatypes instead of failing on unsupported values. [92655846f6](https://github.com/hershel-theodore-layton/hhvm/commit/92655846f6210c9f88558a22547a3b8260ea1c4d)
