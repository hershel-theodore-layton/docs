# 2024-03-06

## Highlights

## Security

- Opaque representations of internal generic classes now preserve their type arguments across module boundaries. Distinct instantiations are no longer treated as compatible outside the defining module. [86f1847927](https://github.com/hershel-theodore-layton/hhvm/commit/86f1847927fe266b3ea966541d558747cdc883dd)

## Future Changes

- `HH\classname_to_class()` and `HH\class_to_classname()` now accept preview `readonly classname<T>` arguments while remaining pure, allowing readonly class values to pass through the migration helpers without a mutable-value error. [03233e7456](https://github.com/hershel-theodore-layton/hhvm/commit/03233e7456d5bf587c7c9850e921180ec51f2d61)
- Function type hints in ongoing release now support the `optional` qualifier without a per-file opt-in. Types such as `(function(int, optional int): void)` can describe functions whose trailing parameter has a default, but the feature remains pre-stable. [6e9dfb645d](https://github.com/hershel-theodore-layton/hhvm/commit/6e9dfb645d49ecc835d0ed238f54434d9b945af9)
