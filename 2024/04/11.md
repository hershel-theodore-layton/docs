# 2024-04-11

## Highlights

- Repo-authoritative optimization no longer loops forever when a subclass-analysis split contains exactly 25,000 classes. [8c73cc33e2](https://github.com/hershel-theodore-layton/hhvm/commit/8c73cc33e22def26863422e3badf45e5bfa088a0)

## Future Changes

- JSON rendering of pre-stable function types, including `hh --type-at-pos-batch`, now preserves whether a parameter is `optional`. Consumers can distinguish `(function(int, optional bool): int)` from a function whose second parameter is required. [8fb398ec31](https://github.com/hershel-theodore-layton/hhvm/commit/8fb398ec3149e42a4923936d1af98ef193b7a4ab)
- Expression-tree lowering now passes XHP element names to `visitXhp()` using `nameof`, producing strings instead of the class-pointer values previously emitted with `::class`. This affects experimental expression-tree DSLs that inspect those visitor arguments. [0f8bb1e8f8](https://github.com/hershel-theodore-layton/hhvm/commit/0f8bb1e8f813ee6bfc8956b800c0e94453b3577c)
- A disabled-by-default `class_pointer_levels` migration setting can lint or reject a direct `C::class` argument where a string parameter would trigger an implicit conversion, and offers `nameof C` as the fix. The first implementation is deliberately syntactic and does not follow the value through a local variable; it is groundwork for the future `class<C>` type. [ffb5154a11](https://github.com/hershel-theodore-layton/hhvm/commit/ffb5154a1189c545a0bc6c5164c15dadda74e88d)
