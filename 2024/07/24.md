# 2024-07-24

## Highlights

- When `hh` is invoked with `--from`, an explicit `--error-format` now takes precedence instead of being silently replaced with plain output. [392e317d12](https://github.com/hershel-theodore-layton/hhvm/commit/392e317d126098dfd7a4513ab424a12fbfd23537)

## Breaking Changes

- The HHI for `HH\ImplicitContext` now exposes the abstract `IS_MEMO_SENSITIVE` boolean and `CRun` context constant introduced in systemlib earlier this month, so typed subclasses must define both. Calls to `runWith()`, `runWithAsync()`, `get()`, and `exists()` must provide a capability set that is a superset of the subclass's selected `CRun`; `[this::CRun]` states a callee requirement and does not grant that capability to the caller. Both `runWith()` and `runWithAsync()` additionally carry the callback's contextual requirement through `ctx $f`. [0746e19f3f](https://github.com/hershel-theodore-layton/hhvm/commit/0746e19f3fb2692aabd5f9af92681151595ce63e)
- The `hh --xhp-autocomplete-snippet` command-line option has been removed. [ac67a519c5](https://github.com/hershel-theodore-layton/hhvm/commit/ac67a519c549de2fc6e583355a04558eedc09a57)

## Future Changes

- The disabled-by-default `.hhconfig` option `type_refinement_partition_shapes=true` enables constraint-based `is` refinements for closed shapes with required fields. Open shapes and shapes with optional fields are not yet handled by this path. [e99ed3d046](https://github.com/hershel-theodore-layton/hhvm/commit/e99ed3d0460ac7aa43fb73e93f853e61cbb996d9)
