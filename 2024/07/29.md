# 2024-07-29

## Highlights

- When the VS Code debugger is attached to a server, only explicit evaluation output is now sent to the debugger's stdout stream. This avoids unrelated request output flooding the debug console and makes evaluation output consistent. [723c132357](https://github.com/hershel-theodore-layton/hhvm/commit/723c132357511463228cb3c0d2258969a5b3d7ce) [783f6ccf7a](https://github.com/hershel-theodore-layton/hhvm/commit/783f6ccf7ad20292037e0f8be23f39459f7fabb9)

## Breaking Changes

- The `disallow_direct_superglobals_refs` configuration option has been removed. Direct references to superglobals such as `$_GET` and `$_SERVER` remain parse errors; use `HH\global_get()` and `HH\global_set()` instead. [351be32993](https://github.com/hershel-theodore-layton/hhvm/commit/351be32993d6029d6c8482d2808c19c8d3f17031)

## Future Changes

- An experimental `set_oom_multiplier(int): bool` API lets a critical request raise its out-of-memory termination threshold by a multiplier of at most 100. The implementation notes that future cost attribution work is still required, so this is not yet a general-purpose memory-management API. [8ec4a3eead](https://github.com/hershel-theodore-layton/hhvm/commit/8ec4a3eead440fc190cd51467ab84be520fcaad8)
- Experimental case-type expansion now preserves the typing environment while simplifying members, avoiding dangling type variables and parameters in later checks. [19275f0ab4](https://github.com/hershel-theodore-layton/hhvm/commit/19275f0ab49a041ef3281ad9f187c5ad625b43c3)
