# 2024-10-07

## Highlights

- Typechecker diagnostics now have stable ordering by phase, then source position and error code. This keeps naming errors ahead of typing errors without making output depend on worker completion order. [42102418a6](https://github.com/hershel-theodore-layton/hhvm/commit/42102418a6337452313529b3cbd0c1e4be6d443d)
- Extended type-error reasons recover useful claims for sound-dynamic constraints, arithmetic-result flows, and generic types, reducing vague or misplaced primary messages. [7c185b5191](https://github.com/hershel-theodore-layton/hhvm/commit/7c185b5191974e786d4aca9e63d9b71a598dd059) [8658ff652b](https://github.com/hershel-theodore-layton/hhvm/commit/8658ff652b89475b5b3e29b92be228245b2b9a0b) [41ce724047](https://github.com/hershel-theodore-layton/hhvm/commit/41ce724047b06a4905ef78875ce62c117c3c754a)
- Emitted calls of the form `$c::foo()` now retain the call's source position rather than the class-expression position, improving AST and source-mapping consumers. [2184a6754b](https://github.com/hershel-theodore-layton/hhvm/commit/2184a6754b676969c26e35c793d75d57cdab81dd)

## Future Changes

- Runtime type information now preserves the nullable part of an explicit like-nullable hint, so a value accepted as `~?T` can actually be `null` at runtime. [5743f65f39](https://github.com/hershel-theodore-layton/hhvm/commit/5743f65f39b1b0596ad1991e7fcef59426465fe8)
