# 2024-11-13

## Highlights

- Out-of-memory exception messages now include both the request's measured memory usage and its numeric limit, making production OOM reports more actionable. [ecb246b358](https://github.com/hershel-theodore-layton/hhvm/commit/ecb246b358d15deb9ff7a54ef0270fb83cc1d79e)
- JSON produced and consumed for function types by batch type-at-position tooling now preserves readonly receivers, readonly returns, and contexts. The serialized `capability` is the callee's required context; when the field is omitted it decodes as `[defaults]`, not as an unrestricted or capability-granting function. [210b4af6eb](https://github.com/hershel-theodore-layton/hhvm/commit/210b4af6eb65ed8ad2fd7b2da6033f3136c4bb22)
- `Server.RequestMemoryMaxBytesSet` is now a recognized runtime setting, so `ini_get('hhvm.server.request_memory_max_bytes_set')` no longer always returns `false`. [5c81805ef8](https://github.com/hershel-theodore-layton/hhvm/commit/5c81805ef8764bf2610433b1454bf8417deaee90)

## Future Changes

- The unstable `shape_destructure` feature now permits `tuple(...)` as a destructuring lvalue and deliberately forbids mixing `list(...)` inside shape/tuple patterns or shape/tuple patterns inside `list(...)`. [b315173511](https://github.com/hershel-theodore-layton/hhvm/commit/b3151735110602f7786fd9f08cef65b5e4967693)
