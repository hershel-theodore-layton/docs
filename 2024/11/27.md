# 2024-11-27

## Future Changes

- The `class<T>` parser switch is now enabled by default, and HHVM shallowly enforces `class<T>` hints. `Eval.ClassTypeLevel=0` accepts strings, lazy classes, and class pointers with optional string notices, while level 1 rejects strings. As with `classname<T>`, `class<T>` is not yet permitted in `is`/`as` or reified generics. [dfca3a4cbe](https://github.com/hershel-theodore-layton/hhvm/commit/dfca3a4cbe22eb213eedad587de400813d1d543d)
- The class-pointer syntax has entered ongoing release, and the compatibility type `HH\class_or_classname<T>` has been added for APIs that temporarily accept both class pointers and class names while the subtype relationship is separated. It likewise cannot be used in `is`/`as` or reified generics. [b154e2745f](https://github.com/hershel-theodore-layton/hhvm/commit/b154e2745f0ef1a60ce97a719a144792531c401c)
