# 2024-12-09

## Highlights

- With error streaming enabled, `hh --error-format raw` once again prints `No errors!` when the check succeeds. [2cb35690cd](https://github.com/hershel-theodore-layton/hhvm/commit/2cb35690cd69f8963bb071ec82a248416ac7981a)
- Sound-dynamic error reasons now retain the provenance of a like type as it passes through a function that supports dynamic calling. [d7ae8d1528](https://github.com/hershel-theodore-layton/hhvm/commit/d7ae8d152846894f8fe351beb9d13b0a83fa0cc8)

## Breaking Changes

- `class<C>` no longer satisfies a generic `string` or `arraykey` bound merely through the transitional `class<C> <: classname<C>` relation. Type hints such as `dict<class<C>, V>` are rejected at the generic boundary; use `classname<C>` for string keys, or keep class pointers out of array-key positions. [bb07c68abe](https://github.com/hershel-theodore-layton/hhvm/commit/bb07c68abe3aa84ebaaf5d0e7a8df1b4873609e2)

## Future Changes

- Pre-stable function references are now enabled by default. A pointer such as `foo<>` is typed as `HH\FunctionRef<(readonly function(...): ...)>` rather than only as its underlying function type; the wrapped signature retains the function's declared capability list. Projects can temporarily restore the previous typing with `enable_function_references=false`. [76890b5a62](https://github.com/hershel-theodore-layton/hhvm/commit/76890b5a623d956d7777558936418398913caffb)
- The staged package-v2 checker accepts `package_v2_exclude_patterns` as a comma-separated list of path regexes. Matching source or target files are exempt from package-boundary checks; the initial default excludes `.*/__tests__/.*`. [bf5b18d2dc](https://github.com/hershel-theodore-layton/hhvm/commit/bf5b18d2dcc355c592a633004850033d8520a9d8)
- Package-v2 boundary errors now point separately to the illegal reference, each file's package membership source, and the relevant `PACKAGES.toml` relationship. [d5bbd48c44](https://github.com/hershel-theodore-layton/hhvm/commit/d5bbd48c446d42cad74e7bf6207920e7a9f3b06e)
