# 2025-01-17

## Highlights

- The new `HH\gc_is_conservative()` builtin reports whether HHVM's garbage collector is operating without any conservative type scanners. [3f6dfef71e](https://github.com/hershel-theodore-layton/hhvm/commit/3f6dfef71e34c6ab24cc3609ac60783b4b9e4632)

## Future Changes

- Runtime type structures for open tuples now preserve required elements in `elem_types`, optional elements in `optional_elem_types`, and a variadic tail in `variadic_type`. Absent optional or variadic parts omit their corresponding fields. [4c9affb24d](https://github.com/hershel-theodore-layton/hhvm/commit/4c9affb24d07594b72290efcb5718b7c85e5c1fb)
- A type used after the experimental splat operator must now be known to be a tuple—typically through a bound such as `T as (mixed...)`. Unconstrained generics used in tuple or function-type splats now produce a constraint error. [700abe325e](https://github.com/hershel-theodore-layton/hhvm/commit/700abe325eeba6f130db69e369490353bcec0db8)
- Recursive case-type runtime handling now preserves generic arguments, resolves cycles involving aliases more reliably, and refuses recursive `is`/`as` enforcement that could recurse without bound. [0d7f21793a](https://github.com/hershel-theodore-layton/hhvm/commit/0d7f21793a1ae7e40a0c728ee5996bb664324324)
