# 2025-02-19

## Highlights

- HHVM now correctly locks a `const` object while unwinding from a constructor invoked through the interpreter, preserving the object's immutability guarantees on this exception path. [e35e12ac41](https://github.com/hershel-theodore-layton/hhvm/commit/e35e12ac41ae6c86de321198a52c6704742c4779)
- `hh --dump-config` prints the configuration parsed by `hh_client`, making it easier to diagnose differences between client and server settings. [10dde3aab4](https://github.com/hershel-theodore-layton/hhvm/commit/10dde3aab4427e78091964a940c6dc45d41ec9de)

## Future Changes

- The class-pointer migration gained a `classname_class` level in `class_pointer_levels`. At an error level above 1, using a `classname<T>` variable in `new`, static method, class-constant, or static-property access is rejected in favor of `class<T>`. [b7d8bb6c32](https://github.com/hershel-theodore-layton/hhvm/commit/b7d8bb6c3239d099db16594576a1780f6df2964e)
