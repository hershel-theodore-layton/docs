# 2025-03-03

## Highlights

- Type printers now collapse nested nullable wrappers, so TAST and diagnostic-oriented tooling displays types such as `~?int` instead of the invalid-looking `~??int`. [6acb549bd8](https://github.com/hershel-theodore-layton/hhvm/commit/6acb549bd849f6223134d9a34e946cbd840f42fb)

## Security

- `gmp_pow()` now rejects exponents greater than `UINT32_MAX`, raises a warning, and returns `false`. This prevents unbounded allocations inside GMP that are not charged to HHVM's request heap. [94defb1921](https://github.com/hershel-theodore-layton/hhvm/commit/94defb192104959e46a769b548e55a32d2438a52)

## Breaking Changes

- Transparent type aliases may no longer put constraints on their type parameters. A declaration such as `type T<X as Foo> = ...` is now a parse error; use `newtype` when the constraint is part of the abstraction, or remove the constraint. [fb39956d48](https://github.com/hershel-theodore-layton/hhvm/commit/fb39956d48a621210ed6b4f1a1546c53e548b5c2)

## Future Changes

- With `.hhconfig` option `safe_abstract=true`, accessing an abstract class constant through a receiver that may denote an abstract class now produces warning 12018. Concrete constants remain safe. [280387469b](https://github.com/hershel-theodore-layton/hhvm/commit/280387469b70b1b0f04812e9185d2a2c5b1fbdde)
