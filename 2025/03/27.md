# 2025-03-27

## Highlights

- Errors for abstract type constants now suggest the corresponding `this::TConst` form when that is likely what the author intended. [9033b41694](https://github.com/hershel-theodore-layton/hhvm/commit/9033b4169442ef12f73dee38e25fdc773ea12303)

## Breaking Changes

- The `.hhconfig` options `strict_wellformedness` and `enable_strict_const_semantics` have been removed after their strongest levels were fully rolled out. Well-formedness checks on requirements and type localization, and strict inherited type-constant semantics, are now unconditional. [0ae558f29a](https://github.com/hershel-theodore-layton/hhvm/commit/0ae558f29a571139f718d8d93c50ee97b6859563) [2deb722ba4](https://github.com/hershel-theodore-layton/hhvm/commit/2deb722ba4eab8577564182f3d7a3a3efab3d584)

## Future Changes

- `parent::` inside a trait now resolves against the parent of the class named by the pre-stable `require class` or `require this as` constraint, rather than against the required class itself. The typechecker rejects `parent::` when that class has no parent and points back to the requirement. [05e9f87a89](https://github.com/hershel-theodore-layton/hhvm/commit/05e9f87a89e00fe7b615645208ebe23046276da4)
