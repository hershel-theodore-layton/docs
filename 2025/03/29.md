# 2025-03-29

## Highlights

- Switch cases whose values are disjoint from the scrutinee now produce warning 12007 explaining that the case can never match. This check is part of ordinary typechecking and is not limited to the staged exhaustivity checker. [8ccb15e063](https://github.com/hershel-theodore-layton/hhvm/commit/8ccb15e063e19a83668b565b1759ce2cbf57c457)

## Breaking Changes

- The legacy typed switch linter has been removed. Its impossible-case check is now warning 12007, while replacement exhaustivity behavior is provided by the staged checker described below. Tooling that depended on lint codes 5607, 5614, or 5640 should migrate to the new warning and typechecker diagnostics rather than expecting a one-to-one lint-code replacement. [7585768d07](https://github.com/hershel-theodore-layton/hhvm/commit/7585768d07ffea3e11f6ed54739b3a09886aa1cb)

## Future Changes

- With `.hhconfig` option `new_exhaustivity_check=true`, every `switch` must either be proven exhaustive or contain `default`. The checker precisely handles enums, enum classes and labels, `bool`, nullable types, unions, intersections, and closed tuples; it reports duplicate, unreachable, and redundant cases or defaults as warnings. Enabling it disables the old switch checks; the option still defaults to `false`. [be717c1223](https://github.com/hershel-theodore-layton/hhvm/commit/be717c12231dd446b8c27c5d0766d824046a72e0)
