# 2025-05-20

## Highlights

- `ReflectionClass::getName()` is now typed as `classname<mixed>` rather than plain `string`, preserving class-name information through reflection without changing the runtime string representation. [87ff635038](https://github.com/hershel-theodore-layton/hhvm/commit/87ff6350386bff400e826c072fe7f0ee92f09d07)

## Breaking Changes

- The checker no longer accepts dynamic static-method call syntax such as `$class::$method()` or `C::{expr}()`. Use a statically named method or the explicit `HH\dynamic_class_meth()` API. [458b089989](https://github.com/hershel-theodore-layton/hhvm/commit/458b0899896485f5e059d3c5909741c485f37bed) [f5759593e2](https://github.com/hershel-theodore-layton/hhvm/commit/f5759593e2f8a5ab4cbbbbbc48cf9c427b5d770d)
- The legacy `HH\ImplicitContext` abstract class and its private context-construction path have been removed; the `HH\ImplicitContext` namespace remains. Projects still using the class should migrate to the memo-sensitive or memo-agnostic API. [dc65144f44](https://github.com/hershel-theodore-layton/hhvm/commit/dc65144f44c2cfb3ecf339f249ab781ef47269b4)
- `HH\MemoAgnosticImplicitContext` and `HH\MemoSensitiveImplicitContext` are now sealed to their approved platform subclasses. Direct subclasses outside that hierarchy are no longer accepted. [529cf1661b](https://github.com/hershel-theodore-layton/hhvm/commit/529cf1661b4bf2fabd742eeab12c3abac85d73db)
