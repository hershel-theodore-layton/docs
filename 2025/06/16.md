# 2025-06-16

## Highlights

- The extract-method refactoring now leaves the original method's doc comment attached to that method instead of moving it to the newly extracted method. [3f0bf0852f](https://github.com/hershel-theodore-layton/hhvm/commit/3f0bf0852f367f5ab8420d6ad0a33449d0f83161)

## Breaking Changes

- Compiler-special functions without ordinary runtime definitions can no longer be captured with function-pointer syntax. Naming[2105] now rejects pointers to `HH\classname_to_class`, `exit`, `HH\ReifiedGenerics\get_class_from_type`, `HH\global_get`, `HH\global_set`, `HH\tag_provenance_here`, `HH\FIXME\UNSAFE_CAST`, and `HH\FIXME\UNSAFE_NONNULL_CAST`; direct calls remain supported. [87c01f69af](https://github.com/hershel-theodore-layton/hhvm/commit/87c01f69af89994a8b9877ccbc4f3ed768e40754)

## Future Changes

- Under unstable `no_disjoint_union`, type-constant access through union and intersection types now updates the dependent `this` type for each constituent. Fixpoint refinements consequently retain their precise projected types after these flows. [ede7843927](https://github.com/hershel-theodore-layton/hhvm/commit/ede7843927166a1e797f1a79794789f9e6a25a45)
