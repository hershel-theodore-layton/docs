# 2025-06-18

## Highlights

- The native `HH\Facts\subtypes()`, `transitive_subtypes()`, and `supertypes()` implementations now accept either class pointers or class names without raising string-to-class conversion notices. These APIs retain their explicit `[]` capability lists and therefore require no ambient capabilities from callers. [17a3032494](https://github.com/hershel-theodore-layton/hhvm/commit/17a3032494673f1e5d308fae7210b9ba58920476)
- Generated HHI declarations no longer need memoization-parameter annotations when a project enables `disallow_non_annotated_memoize`. This prevents bundled HSL declarations from causing `hh_server` to fail during startup; user source remains subject to the setting. [d7772b96df](https://github.com/hershel-theodore-layton/hhvm/commit/d7772b96df98098611e756f87da0aef933b6acea)

## Future Changes

- With `needs_concrete` checking enabled, calls to `__NeedsConcrete` methods through `self::` and `parent::` now account for their forwarding of the late-static receiver. Unsafe calls are rejected, while calls made from another `__NeedsConcrete` method are accepted when the receiver is known to be concrete. [95e848e66c](https://github.com/hershel-theodore-layton/hhvm/commit/95e848e66c183bfd9d800e15de30dcb3879373a2)
