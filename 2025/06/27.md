# 2025-06-27

## Highlights

- Redeclaring a non-const static property in a subclass now produces Warn[12021]. The declarations have separate runtime storage rather than overriding one another, so updates through the parent and child names do not share state. [0c9f90144e](https://github.com/hershel-theodore-layton/hhvm/commit/0c9f90144e0a9d470b05bc31071290e62757a5e8)
- `HH\serialize_with_options()` accepts `shape('keepClasses' => true)`. With the option enabled, class and lazy-class values are emitted with HHVM's `l:` representation and deserialize back to class values; the default remains string conversion. The function has no explicit capability list, so it continues to use the default capability set. [94e3085910](https://github.com/hershel-theodore-layton/hhvm/commit/94e3085910ce294c881768cb4f1aa3918b8dfda6)

## Future Changes

- Staged polymorphic function-pointer typing lets references such as `C::genericMethod<>` retain a rank-2 polymorphic function type instead of fixing fresh type variables after their first use. The extracted type accounts for method and class generics, `where` constraints, variance-sensitive `this`, and abstract type constants, allowing one reference to be used at multiple compatible instantiations. This typing is not yet the default. [2ff573c3b3](https://github.com/hershel-theodore-layton/hhvm/commit/2ff573c3b3e26515bd8661d1111cce3db593054e)
