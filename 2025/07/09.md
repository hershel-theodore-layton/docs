# 2025-07-09

## Security

- Hack's Rust dependency lockfile no longer transitively includes the vulnerable `owning_ref` crate affected by RUSTSEC-2022-0040. [b20fefa60c](https://github.com/hershel-theodore-layton/hhvm/commit/b20fefa60cd62383d1ead53d923c4482d4a32672)
- HHVM fixes a heap-use-after-free when mutating bespoke `LoggingArray` values by constructing the replacement before invalidating the old array. [2dbe10d8a1](https://github.com/hershel-theodore-layton/hhvm/commit/2dbe10d8a1921f7f28430155a8d096b99aa68c2e)

## Breaking Changes

- Four class-pointer migration settings—`class_pointer_ban_classname_new`, `_type_structure`, `_static_meth`, and `_class_const`—now take integer levels: `0` permits the operation, `1` emits Warn[12022], and `2` reports an error. Existing boolean values must be replaced with the corresponding integer. [e2bb8738e8](https://github.com/hershel-theodore-layton/hhvm/commit/e2bb8738e85bf847c2a4e7051ccc8ecde09fbe48)
- Static-property access through `classname<T>` is now an unconditional type error, and the former `class_pointer_ban_classname_static_prop` escape hatch has been removed. Migrate the receiver to `class<T>`. [e2bb8738e8](https://github.com/hershel-theodore-layton/hhvm/commit/e2bb8738e85bf847c2a4e7051ccc8ecde09fbe48)

## Future Changes

- Experimental `can_index` constraint solving now supports `Pair` and reports more precise string-index errors.
