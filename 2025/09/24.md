# 2025-09-24

## Highlights

- `type_structure($value, 'T')` now accepts a first argument of type `dynamic` instead of rejecting the call during its special type-constant validation. Its public signature retains `[]`, so callers need no ambient capabilities. [70d45071f4](https://github.com/hershel-theodore-layton/hhvm/commit/70d45071f40ce06a4737aa9b3d557c50febefd38)
- New `openssl_csr_get_dns_names(mixed): vec<string>` and `openssl_csr_get_upn(mixed): string` APIs read DNS subject-alt names and the Microsoft UPN otherName from a certificate-signing request. Both throw `OpenSSLException` for an unparseable CSR; the UPN API also throws when no valid UPN exists. Their omitted coeffect brackets mean `[defaults]`, so they are not callable from a pure `[]` context. [120ba485fd](https://github.com/hershel-theodore-layton/hhvm/commit/120ba485fd1ac285402b7385ca5641fd64c934a0) [b1691a9392](https://github.com/hershel-theodore-layton/hhvm/commit/b1691a9392c3b126fc40b47f5f162fcd59e53b59)
- HHVM now loads individual types in dependency order rather than repeatedly retrying whole units. Cross-file dependency chains that only looked cyclic because neither file could be loaded first can now autoload successfully. [d67fb09b37](https://github.com/hershel-theodore-layton/hhvm/commit/d67fb09b37197c71f29dcbccf15b251ba773e936)

## Future Changes

- Unstable named parameters now receive direct call-site checking for missing, extra, duplicate, and incorrectly typed names, plus autocomplete support. Required named parameters may follow optional parameters because their names remove positional ambiguity. Function-type subtyping and override checking do not yet compare parameter names; ordinary parameter contravariance and coeffect compatibility are unchanged.
