# 2025-10-03

## Highlights

- HHVM now provides `openssl_x509_get_upn(mixed): string` for extracting a Microsoft User Principal Name from an X.509 certificate's subject-alt names. It throws `OpenSSLException` when the certificate cannot be parsed or has no valid UPN; its omitted capability brackets mean `[defaults]`, and the public HHI follows on October 14. [fd5f758c2c](https://github.com/hershel-theodore-layton/hhvm/commit/fd5f758c2ccad8d7ccb1efdb02fcb4c95275e133)
- The x86 JIT now preserves native stack alignment while filling omitted default arguments, avoiding ABI-unsafe calls into the `uninitDefaultArgs` helper. [751e89833e](https://github.com/hershel-theodore-layton/hhvm/commit/751e89833eee3ce0a87c0f37141387111d5412dc)

## Breaking Changes

- The Watchman extension has removed `HH\watchman_query()`, `HH\watchman_subscribe()`, `HH\watchman_check_sub()`, `HH\watchman_sync_sub()`, and `HH\watchman_unsubscribe()`. Projects calling these APIs need to replace them; `HH\watchman_run()` and `HH\ext_watchman_version()` remain. [b61ee2ea1b](https://github.com/hershel-theodore-layton/hhvm/commit/b61ee2ea1b4eb89d90927f3f57b5118fdd783523)

## Future Changes

- Violating the staged `__NeedsConcrete` override rule now produces Warn[12027] instead of Typing[4487]. This permits hierarchy-by-hierarchy adoption while continuing to flag an override that imposes a stricter concreteness requirement than its parent. [9ec3de9342](https://github.com/hershel-theodore-layton/hhvm/commit/9ec3de934231c5d6e81db2e73b723443e2f4c400)
