# 2025-10-21

## Highlights

- `HH\FormatString<T>` now has an `as string` upper bound. Generic code can use ordinary string operations on a format string without typechecker special cases or a concatenation trick. [3da9793389](https://github.com/hershel-theodore-layton/hhvm/commit/3da9793389a595f18c6f875176ac09d8b6a398c7)

## Breaking Changes

- Strict string concatenation and interpolation are now unconditional, and the `.hhconfig` option `enable_strict_string_concat_interp` has been removed. `.`, interpolation, and `echo` accept only `string` and `int` (`arraykey`, plus `dynamic` under sound-dynamic typing); values such as `bool`, `float`, and `Stringish` must be explicitly converted. [73bb242fc6](https://github.com/hershel-theodore-layton/hhvm/commit/73bb242fc69cc50c56ccb018d4e71a41cdb16f29)

## Future Changes

- Staged polymorphic function subtyping now increases rank only when the supertype is universally quantified, avoiding needless rank changes when comparing ordinary callable types. [df5cd2852a](https://github.com/hershel-theodore-layton/hhvm/commit/df5cd2852ad7f204b5f77d2940083018764f7d33)
- Unstable type splats in method parameter lists must now be tuple types, matching the existing rule for functions. [02bf96e926](https://github.com/hershel-theodore-layton/hhvm/commit/02bf96e926338cd578d9167610363eeb7bdc0e5b)
