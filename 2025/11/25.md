# 2025-11-25

## Highlights

- The null-safe pipe operator `|?>` is fully released and no longer requires an unstable-feature opt-in. Hack also adds Warn[12031] when its left side cannot be null and Warn[12032] when it is always null. [9c1592aef2](https://github.com/hershel-theodore-layton/hhvm/commit/9c1592aef2c0404a305c1372e5d3b20f9c6dcd45) [49a01a024d](https://github.com/hershel-theodore-layton/hhvm/commit/49a01a024d301537552009cdc6fd5878581637e9)

## Breaking Changes

- Redundant `?->` checks have moved from lint codes 5633/5654 to Hack warnings 12029/12030. Update warning filters and suppressions accordingly; expression-tree lowering is excluded to avoid false positives. [41573b779d](https://github.com/hershel-theodore-layton/hhvm/commit/41573b779dbf18db87913112438c196208158ee1) [65841bca20](https://github.com/hershel-theodore-layton/hhvm/commit/65841bca20db834468ac590ad3776a9a5c9d6dd4)
- Exceptions thrown by Thrift adapter methods are now exposed to Hack as `TProtocolException` with `ERR_UNEXPECTED_EXCEPTION`, rather than leaking the original exception. Code that catches a particular adapter exception will need to catch the protocol exception instead. [ae27f8a1f0](https://github.com/hershel-theodore-layton/hhvm/commit/ae27f8a1f063871d2a9e4ec30609f15ea46e002e)

## Future Changes

- Type inference for immediately invoked lambdas now accounts for named arguments, fixing both missed errors and rejected valid calls under the unstable named-arguments feature. [d3ef01c111](https://github.com/hershel-theodore-layton/hhvm/commit/d3ef01c111f1f89c06239435088144fcbeef0a5e)
