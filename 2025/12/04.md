# 2025-12-04

## Highlights

- HHVM debugger listening sockets now use `SOCK_CLOEXEC`. Access-log processors and other subprocesses no longer inherit the descriptor and prevent the debugger server from reopening its socket after a client disconnects. [8e8e78c5ff](https://github.com/hershel-theodore-layton/hhvm/commit/8e8e78c5ff11884dfd2d5bc25dd6e367041b5e54)
- Access-log formats can use `%M` for the request's end time as a Unix timestamp in microseconds, providing finer resolution than the existing seconds-level time field. [c8a3b4f976](https://github.com/hershel-theodore-layton/hhvm/commit/c8a3b4f976e6543e5e4606acffe37e5986df75f7)

## Future Changes

- The still-configurable polymorphic function-pointer rollout is now enabled by default. References to generic declarations retain a rank-2 type instead of fixing their type arguments when the reference is created, allowing separate calls to choose separate valid instantiations. Declared parameter, return, and coeffect requirements remain part of the resulting `HH\FunctionRef`; projects needing a temporary escape hatch can set `poly_function_pointers=false`. [e4da608d51](https://github.com/hershel-theodore-layton/hhvm/commit/e4da608d51576bce1743a47abc0ee7bd5d80940e)
- The pre-release `__NeedsConcrete` override diagnostic now follows the default-false `needs_concrete` option, so disabling that option suppresses the override check along with the other `__NeedsConcrete` checks. [d729522778](https://github.com/hershel-theodore-layton/hhvm/commit/d729522778c452eceb3d742b954690f186d525cc)
- Staged type-constant lower bounds now participate in polymorphic function-pointer synthesis. For nested accesses, upper bounds are intersected and lower bounds are unioned so that every instantiation agrees on the projected type constant; ordinary callable parameter variance and coeffect compatibility remain enforced. [d80b10688e](https://github.com/hershel-theodore-layton/hhvm/commit/d80b10688e369870237568f408db2d17c94fc5aa)
