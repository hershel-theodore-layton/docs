# 2025-12-16

## Highlights

- HHBBC no longer performs quadratic dead-code elimination on long chains of array-element additions, reducing compile time for generated code and large literal-building sequences. [a2b1b96b4b](https://github.com/hershel-theodore-layton/hhvm/commit/a2b1b96b4bcc18f7beb3bf47aa878735835c353b)

## Breaking Changes

- The `.hhconfig` option `constraint_array_index` and the legacy array-read checker have been removed. Array reads now always use the constraint-based checker; the separate, default-false `constraint_array_index_assign` experiment for writes is unchanged. [e68fe7227a](https://github.com/hershel-theodore-layton/hhvm/commit/e68fe7227a62d718598a1db723e3dbacb499ffa0)

## Future Changes

- As part of the staged polymorphic function-pointer work, `meth_caller()` now erases reification on type parameters lifted from the receiver class. For `class C<reify T>`, an instance-method caller can have a rank-2 type such as `function<T>(C<T>, T): void` because the receiver already carries the runtime type structure; the method's declared capability requirements remain on the synthesized callable. [a17086df77](https://github.com/hershel-theodore-layton/hhvm/commit/a17086df772bf021b0a3c806248c3b165a0dc020)
- An opt-in `.hhconfig` setting, `ignore_string_methods=false`, exposes the experimental `HH\string::length(): int` method and its `HH\String\__primitive_length(string): int` implementation. Both omit explicit coeffect brackets and therefore use `[defaults]`; the default setting still hides them. [4e83e22176](https://github.com/hershel-theodore-layton/hhvm/commit/4e83e221764b3a73cb37f0a1cacf27542b046e33)
