# 2025-12-23

## Highlights

- New `HH\TypedFormatString<TFormatter, TArgs>` values carry the placeholder types as a tuple, allowing first-class helpers to pass a format string and its `...TArgs` without a FIXME. String literals are checked when a typed format string is expected, and concatenating two compatible typed format strings concatenates their argument tuples; the existing `HH\FormatString<T>` remains as a backward-compatible alias using `(mixed...)`. [12cbdcd02f](https://github.com/hershel-theodore-layton/hhvm/commit/12cbdcd02f83e46556aa875baf9ee09db26bfb47)
- `sprintf()`, `printf()`, `HH\invariant()`, and `HH\invariant_violation()` now connect the inferred format tuple to their variadic arguments. `sprintf()` and the invariant helpers retain `[]`; `printf()` still omits a bracket and therefore requires `[defaults]`, so the stronger typing does not grant callers any new capabilities. [12cbdcd02f](https://github.com/hershel-theodore-layton/hhvm/commit/12cbdcd02f83e46556aa875baf9ee09db26bfb47)

## Breaking Changes

- Each component of a concatenated typed format string must now be well formed. Constructions such as `"%" . "d"` are rejected even though the final plain string would spell a valid placeholder; concatenate complete format fragments instead. [12cbdcd02f](https://github.com/hershel-theodore-layton/hhvm/commit/12cbdcd02f83e46556aa875baf9ee09db26bfb47)
