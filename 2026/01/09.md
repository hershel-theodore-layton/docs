# 2026-01-09

## Highlights

- `HH\TypedFormatString<TFormatter, TArgs>` durably relanded after the January 6 rollback. Typed format strings can be passed through first-class helpers, string literals infer their placeholder tuple from the expected formatter, and concatenation combines compatible argument tuples. `HH\FormatString<T>` remains a compatibility alias using `(mixed...)`. [aeef5f7ec1](https://github.com/hershel-theodore-layton/hhvm/commit/aeef5f7ec176cff82dabe40912a9c276d446ca0e)
- `sprintf()`, `HH\invariant()`, and `HH\invariant_violation()` retain `[]` while gaining typed variadic arguments. `printf()` still omits a capability list and therefore requires `[defaults]`; the stronger format typing does not relax its caller requirement. [aeef5f7ec1](https://github.com/hershel-theodore-layton/hhvm/commit/aeef5f7ec176cff82dabe40912a9c276d446ca0e)

## Breaking Changes

- Components of a concatenated typed format string must each be valid format fragments. Expressions such as `"%" . "d"` are rejected even though the resulting plain string would form a valid placeholder. [aeef5f7ec1](https://github.com/hershel-theodore-layton/hhvm/commit/aeef5f7ec176cff82dabe40912a9c276d446ca0e)

## Future Changes

- Case-type refinement with shape predicates now supports optional fields and open shapes. The implementation deliberately favors a bounded-cost, less exhaustive split over combinatorial decomposition. [c2b9b24bf5](https://github.com/hershel-theodore-layton/hhvm/commit/c2b9b24bf5d7f30085a3b1a6d3b36dc2d7162036)
