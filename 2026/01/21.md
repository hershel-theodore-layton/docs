# 2026-01-21

## Highlights

- Package requirements are now modeled as declaration-level access requirements rather than as part of a callable's function type, fixing their interaction with polymorphism. New `<<__SoftRequirePackage('pkg')>>` support represents a requirement on a softly included package. [4762185971](https://github.com/hershel-theodore-layton/hhvm/commit/4762185971a6eafcae823aac90966fef515d9ecd)

## Breaking Changes

- Hack now validates package-requirement annotations against the declaring file's package and checks their relationships across overrides. A `<<__RequirePackage>>` or `<<__SoftRequirePackage>>` target must strictly include the declaring package; remove redundant same-package annotations and correct unrelated or only-soft-included targets. [4762185971](https://github.com/hershel-theodore-layton/hhvm/commit/4762185971a6eafcae823aac90966fef515d9ecd)

## Future Changes

- IDE hover text for an argument matched by a pre-stable type-splat parameter now includes the tuple index, such as `$args[1]`, instead of losing the parameter name after the first element. [a62607552a](https://github.com/hershel-theodore-layton/hhvm/commit/a62607552a9bf0c9655aa37ef2bd5c422c7955c9)
- Safe Abstract now rejects `<<__NeedsConcrete>>` on final classes, where the annotation would be ineffective or make the method unusable. This affects projects that explicitly enable the not-yet-released `needs_concrete` checks. [76c06fb06c](https://github.com/hershel-theodore-layton/hhvm/commit/76c06fb06cd3b9e6b743d4b4d86b37ae35f46641)
