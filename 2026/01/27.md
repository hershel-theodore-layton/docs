# 2026-01-27

## Highlights

- Hack's diagnostic engine now consistently distinguishes errors from warnings when backtracking and selecting type-checker paths. Enabling a warning can no longer suppress or manufacture a type error merely by changing that control flow. [561e592fd6](https://github.com/hershel-theodore-layton/hhvm/commit/561e592fd65abdddc3847b68757664b390ef7136)
- `FunctionCredential::pack()` and `FunctionCredential::unpack()` can transfer an authenticated function credential between threads in the same HHVM process. Packed values expire after five minutes and cannot be reused after a process restart or in another process; both methods require `[]`. [167e437347](https://github.com/hershel-theodore-layton/hhvm/commit/167e4373476a164c6ed23e6012739b855e4fbbd2)
- `HH\serialize_with_options()` accepts `disallowCollections => true`, causing serialization of `Map`, `Set`, `Vector`, and `Pair` values to throw while leaving Hack arrays and ordinary objects unaffected. [f999a274c0](https://github.com/hershel-theodore-layton/hhvm/commit/f999a274c079ad41e3d90c26c5225de7e647602d)

## Breaking Changes

- A concrete type constant inherited from a parent is now checked against an `<<__Enforceable>>` requirement introduced by an interface on the child. Previously this combination could accept an erased, non-enforceable type; it now reports error 4302. [548b917d91](https://github.com/hershel-theodore-layton/hhvm/commit/548b917d91b1bfb196261327b237d8579ec461a0)
