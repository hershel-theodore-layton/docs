# 2026-02-03

## Breaking Changes

- A type named in a `__Sealed` allowlist without being a subtype now produces warning 12035 rather than a lint or optional hard error. The `enforce_sealed_subclasses` setting has been removed, and the diagnostic now uses the correct `extend`, `implement`, or `use` relationship for each classish kind. [58d208a5ca](https://github.com/hershel-theodore-layton/hhvm/commit/58d208a5ca1585b976a0b9aa75ea68960319b849)
- Typedef well-formedness now follows aliases in the same way that runtime type-structure resolution does. Invalid cycles through an opaque newtype are rejected instead of being accepted by `hh` and potentially failing in HHVM; legal recursion through transparent aliases and an enabled recursive case type remains supported. [281bde125e](https://github.com/hershel-theodore-layton/hhvm/commit/281bde125ed68cc92ab5d3d6dca9f67fd025334c)

## Future Changes

- The unstable `shape_field_punning` feature adds `shape($foo)` as shorthand for `shape('foo' => $foo)` and permits punned and explicit fields in the same literal. It remains gated by `<<file:__EnableUnstableFeatures('shape_field_punning')>>`; missing-field diagnostics also now say where the field is required. [8aeb30361d](https://github.com/hershel-theodore-layton/hhvm/commit/8aeb30361d6a030c1c94bdf1f1ec743fa4fb30b0)
