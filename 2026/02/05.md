# 2026-02-05

## Highlights

- `HH\ImplicitContext`'s protected `runWith()` and `runWithAsync()` methods now require `[leak_safe, ctx $f]` instead of `[this::CRun, ctx $f]`. This narrows the fixed callee requirement to `leak_safe`, so callers no longer need to satisfy a subclass's potentially broader `CRun`; they must still provide a capability set that is a superset of both `[leak_safe]` and the callback's contextual requirement. [76abaa20a2](https://github.com/hershel-theodore-layton/hhvm/commit/76abaa20a21785724dc7ae75408614c88c74be60)
- Open-source HHVM builds now use Folly's symbolizer for crash reports and perf maps, replacing raw addresses with C++ symbols when the build provides libunwind. [c2909dc0ef](https://github.com/hershel-theodore-layton/hhvm/commit/c2909dc0efa055f557c8c2a39d76bb267209f8e7)

## Breaking Changes

- A class's `__Sealed` allowlist may no longer contain a trait. Such declarations now report `NastCheck[3108]`; traits can remain in allowlists on classish kinds where their relationship has defined semantics. [76df11f979](https://github.com/hershel-theodore-layton/hhvm/commit/76df11f97988d48629067f81cc867bf248ee41ff)

## Future Changes

- The named-parameter implementation can now carry named argument metadata from HackC into HHVM and execute basic calls with required named parameters in the interpreter. Written left-to-right argument evaluation is preserved even though named values are arranged before positional values on the VM stack; JIT, inlining, and HHBBC optimizations still deliberately fall back for these calls.
