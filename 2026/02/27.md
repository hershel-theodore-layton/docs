# 2026-02-27

## Highlights

- New `HH\ImplicitContext\PreparedContext` values let implicit-context subclasses prepare several assignments in pure code and apply them together with `runBatch()` or `runBatchAsync()`. The batch methods require `[leak_safe, ctx $f]`: callers must already have a capability set containing `leak_safe` and the callback's requirement; the list does not grant those capabilities. [3252eaa4eb](https://github.com/hershel-theodore-layton/hhvm/commit/3252eaa4eb536cbb997bff62b81d25b7f0a5d3ee)

## Breaking Changes

- Package checking is now always enabled, package and deployment inclusions are always checked for transitive closure, and `__RequirePackage` remains allowed on interface methods. The corresponding `check_packages`, `package_config_disable_transitivity_check`, and `allow_require_package_on_interface_methods` settings have been removed; delete stale overrides. [8d391cf433](https://github.com/hershel-theodore-layton/hhvm/commit/8d391cf4333468d223d84dbf572b10ffa926462e)

## Future Changes

- The JIT can now use the normal function-entry calling convention for direct named-argument calls whose named parameters are all required. It validates the argument names at translation time and otherwise generates the same happy-path call shape as positional arguments; optional and repacking cases still fall back. [d26c627ba8](https://github.com/hershel-theodore-layton/hhvm/commit/d26c627ba86e44153616cffb5425fad32ab18aa2)
