# 2026-03-18

## Breaking Changes

- Hack now emits Warn[12036] when an expression has a genuine unresolved `Tany` type that can silently pass as any type. `Tany` caused solely by a missing type in the hierarchy is excluded to avoid duplicating the underlying error. [bcbc39eec5](https://github.com/hershel-theodore-layton/hhvm/commit/bcbc39eec52ef59130e7282d76511cd7e5234f95)

## Future Changes

- Package-boundary checking can now cover types used by `as` and `?as`, which must be deployed because these expressions resolve a runtime type structure. The new `package_allow_as_expression_violations` carveout defaults to `true` for migration; setting it to `false` enables hard errors. [872d098c0d](https://github.com/hershel-theodore-layton/hhvm/commit/872d098c0de398eb0b258586ef8336440b2f21a4)
