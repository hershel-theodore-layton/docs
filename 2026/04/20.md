# 2026-04-20

## Breaking Changes

- Fileinfo, mailparse, and Async MySQL declarations now replace additional missing HHI types with concrete runtime signatures. [b10a40ecb8](https://github.com/hershel-theodore-layton/hhvm/commit/b10a40ecb8b69fb553ee739042aeec85ba6360cb) [750d2077d0](https://github.com/hershel-theodore-layton/hhvm/commit/750d2077d05cc4ac52ab8cf99a754d1b091f1bc4) [edf0a3bfbc](https://github.com/hershel-theodore-layton/hhvm/commit/edf0a3bfbc6f68004176c5c101c9cd01e50033cc)

- `is` expressions now validate their right-hand type even when the expression is not being used to refine the left-hand side. Invalid type hints that previously escaped localization now produce errors. [8b49bb1304](https://github.com/hershel-theodore-layton/hhvm/commit/8b49bb13047afc39fb08e3fc454e6b21b718b038)

- Inherited `class`, `classname`, and `string` return constraints now apply the same configuration-controlled warnings, errors, and class-to-string conversions as directly declared constraints. Projects relying on the previous inherited-constraint gap may see new runtime diagnostics or failures. [14aceb719a](https://github.com/hershel-theodore-layton/hhvm/commit/14aceb719a5200f777e6e66fcc44a5ae738f4172)

## Future Changes

- The experimental `TypeStructure` representation for refinements now correctly types `as` and `super` entries as `vec<mixed>`, since a refinement may carry multiple bounds. [7713c28719](https://github.com/hershel-theodore-layton/hhvm/commit/7713c28719bc82c612f7b348e9b81b4f16e3049d)
