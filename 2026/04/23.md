# 2026-04-23

## Highlights

- Runtime tests with an abstract `<<__Enforceable>>` type constant are now allowed even when its `as` bound is not itself enforceable; a concrete implementation can still provide an enforceable type. [edc62dc1c2](https://github.com/hershel-theodore-layton/hhvm/commit/edc62dc1c264998af992782f4db27677c93756bb)

- Nullable `?as` no longer triggers package-boundary diagnostics. Unlike `as`, a failed `?as` yields `null` rather than fatalling, so it does not require the asserted type to be available across the boundary. [13a5c1efc4](https://github.com/hershel-theodore-layton/hhvm/commit/13a5c1efc4e9147d5577f017ed3091a2403ef1d7)

## Breaking Changes

- Higher-rank generic validation now traverses nested types when looking for escaping type parameters. Invalid escapes that were hidden below the top level can now be reported. [653e481d9c](https://github.com/hershel-theodore-layton/hhvm/commit/653e481d9c2221a240087fe1ca9d2a60d2627b9e)

- Reflection declarations now expose concrete types for `Reflection::getModifierNames()`, `ReflectionFunction::isDisabled()`, and several `ReflectionProperty` queries. This improves inference and can reject callers that relied on the previous missing types. [64fd36da55](https://github.com/hershel-theodore-layton/hhvm/commit/64fd36da55be82a9700183e2ef073404fdfdc832)

## Future Changes

- The experimental type-alias refinement checker now looks through aliases when rejecting refinements in `is`, `as`, and reified-generic positions, closing a way to hide an unsupported refinement behind a typedef. [59f35936dd](https://github.com/hershel-theodore-layton/hhvm/commit/59f35936ddaa49337de608056456baca67fa3b09)
