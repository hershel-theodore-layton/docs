# 2026-04-29

## Breaking Changes

- Returning a value from a generator is now a parser error (`Parsing[1002]`) instead of a later NAST-check error. HHVM therefore rejects such code even when it is compiled without a full typecheck; generators always complete with `null`. [89a5c434fc](https://github.com/hershel-theodore-layton/hhvm/commit/89a5c434fcb5c1ece859aec99f72d84c201f1d1b) [32080e91f0](https://github.com/hershel-theodore-layton/hhvm/commit/32080e91f09bf1c39dbe563c029c8af894915c80)

## Future Changes

- Type-constant `super` bounds have moved from Preview to Ongoing Release. They no longer require per-file unstable-feature enablement, but remain pre-stable while the rollout continues. [81c412b911](https://github.com/hershel-theodore-layton/hhvm/commit/81c412b911054332d74bf6c97ce5440e5346d143)

- `RepresentableAs` has moved from Unstable to Preview. [451c9c875a](https://github.com/hershel-theodore-layton/hhvm/commit/451c9c875a0f9bec43b19058f465289a7908bb87)

- The manual now documents the experimental `named_parameters` feature, including that named parameter names are part of the API and must be preserved by overrides and function types. [75d958cfed](https://github.com/hershel-theodore-layton/hhvm/commit/75d958cfed2b18fde368df894bee521a7094d844)
