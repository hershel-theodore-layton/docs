# 2026-05-11

## Highlights

- Date/time runtime declarations now use more precise enforced types: `DateTime::add()`, `sub()`, and `setTimezone()` return `DateTime`; `diff()` returns `DateInterval`; `DateTimeZone::getOffset()` returns `int`; `date_add()` and `date_sub()` also return `DateTime`. The public HHI signatures are unchanged by this commit. [6d919856b8](https://github.com/hershel-theodore-layton/hhvm/commit/6d919856b8d02ae7d662eb9b4c5b796e326b1de8)

## Breaking Changes

- `DateTime::diff()` now enforces `DateTimeInterface` at runtime rather than accepting `mixed` and checking it inside the native implementation. Invalid arguments now fail native parameter enforcement instead of following the old warning-and-`false` path; the public HHI already required `DateTimeInterface`. [6d919856b8](https://github.com/hershel-theodore-layton/hhvm/commit/6d919856b8d02ae7d662eb9b4c5b796e326b1de8)

## Future Changes

- The runtime declaration of `DateTimeImmutable::createFromFormat()` now uses the pre-stable case type `BoolOrDateTimeImmutable`, accurately representing its `false` failure result without falling back to `mixed` in systemlib; its public HHI return type remains unchanged. [6d919856b8](https://github.com/hershel-theodore-layton/hhvm/commit/6d919856b8d02ae7d662eb9b4c5b796e326b1de8)
