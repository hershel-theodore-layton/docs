# 2026-05-26

## Highlights

- The Rust declaration provider received correctness fixes for class/type name collisions, trait `__Override` diagnostic positions, and descendant invalidation. In particular, unchanged shallow declarations are retained so stale remote declarations cannot suppress required fanout. [5f7f1b1004](https://github.com/hershel-theodore-layton/hhvm/commit/5f7f1b100402c8c534c0f06f52fdd4164ca5a2ae) [92a95e3bf4](https://github.com/hershel-theodore-layton/hhvm/commit/92a95e3bf4d3f9d7a49e65c6f5a491aa3c09cc82) [e40ada60a0](https://github.com/hershel-theodore-layton/hhvm/commit/e40ada60a014d77cd3ab1bd2e72b687f9f7ac7ca)

## Breaking Changes

- `hh_server`, `hh_single_type_check`, and `hh_single_decl` now use the Rust provider backend by default where supported. The positive `hh_single_type_check --rust-provider-backend` flag has been removed; use `hh_single_type_check --config rust_provider_backend=false` for a temporary shared-memory fallback, or `hh_single_decl --no-rust-provider-backend` for that tool. [a7830e409b](https://github.com/hershel-theodore-layton/hhvm/commit/a7830e409b58c8327566f23adbebe238406c7b66)
- Conditions are now always checked against `~bool`, and `check_bool_for_condition` has been removed. Projects that disabled the check or requested warning-only mode must migrate truthy values to explicit tests such as non-null, non-empty, or non-zero comparisons. [015f0e5ae7](https://github.com/hershel-theodore-layton/hhvm/commit/015f0e5ae7dfb3251de52c245950bca2cb8ae01b)
