# 2026-08-05

## Highlights

- HHVM now includes the original message from standard C++ exceptions in request failure diagnostics, improving errors such as Native Facts initialization failures. [4d451e6f58](https://github.com/hershel-theodore-layton/hhvm/commit/4d451e6f58667bcbb5efe72b6411d86a54c06e32)

- The typechecker now recognizes `HH\get_all_packages()` and `HH\get_all_deployments()`. Their declared shape return types now match the package and deployment metadata already returned at runtime. [9daedec5ab](https://github.com/hershel-theodore-layton/hhvm/commit/9daedec5ab91c78d5f9f48c378d5f03d9b3ed4ac)

## Future Changes

- The experimental `enable_implicit_packages` typechecker option now implements implicit package families: each direct child directory of a configured family path becomes a package without a separate `PACKAGES.toml` entry. The option is disabled by default. [f1d95b65bc](https://github.com/hershel-theodore-layton/hhvm/commit/f1d95b65bc55555c9ad4af2536412728df60df26)

- Experimental named variadic parameters in function, method, and lambda definitions now use an unnamed form such as `named int...`; the previous `named int ...$xs` spelling is rejected. The existing named-parameter and variadic-named-parameter gates still apply. [a3b29158ba](https://github.com/hershel-theodore-layton/hhvm/commit/a3b29158ba2881348b6d905ee5b6f8b19c070804)
