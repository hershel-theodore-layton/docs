# 2026-09-18

## Highlights

- The new `HH\BlobKV\Reader` and `HH\BlobKV\Writer` APIs read and write binary key/value data in Blob containers. Writers require explicit `finalize()`, enforce a single in-progress writer per output path, and are rejected in repo-authoritative mode; readers remain available there. [d3cbd3bacb](https://github.com/hershel-theodore-layton/hhvm/commit/d3cbd3bacb356f2387b2300496fae3d7d6576524)

## Breaking Changes

- Packages must opt into deployed-package checks with `allow_deployed_packages_checking=true` before code can use `package`, `__RequirePackage`, or `__SoftRequirePackage` for them. This flag cannot be combined with `enable_strict_isolation`. The separate prohibition based only on a soft-include edge is removed; ordinary strict-inclusion checks still apply. [55e411dea0](https://github.com/hershel-theodore-layton/hhvm/commit/55e411dea018a2ca14839ce78899f988bf4811b6) [5a43f0ec1f](https://github.com/hershel-theodore-layton/hhvm/commit/5a43f0ec1fb0bf41d3843743bf1d958787fc0470) [e5f9e4c461](https://github.com/hershel-theodore-layton/hhvm/commit/e5f9e4c4614ce94d3acfb2d7fde99e44d8a41009)

## Future Changes

- The typechecker temporarily rejects named parameters on `<<__Memoize>>` functions and `<<__Memoize>>`/`<<__MemoizeLSB>>` methods with `NastCheck[3113]`, because their generated wrappers can fail at runtime. Make the parameter positional or remove memoization. The restriction remains in HHVM 26.09.29 even after the runtime fix on September 22. [b74f9bcdca](https://github.com/hershel-theodore-layton/hhvm/commit/b74f9bcdcaf500203170fccabe8cf301fa9cc1a5)
