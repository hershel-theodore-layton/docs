Highlights

  • HH\ImplicitContext's protected runWith() and runWithAsync() methods now require [leak_safe, ctx $f] instead of [this::CRun, ctx $f]. This narrows the fixed callee requirement to leak_safe, so callers no longer need to satisfy a subclass's potentially broader CRun; they must still provide a capability set that is a superset of both [leak_safe] and the callback's contextual requirement. 76abaa20a2
  • Open-source HHVM builds now use Folly's symbolizer for crash reports and perf maps, replacing raw addresses with C++ symbols when the build provides libunwind. c2909dc0ef

Breaking Changes

  • A class's __Sealed allowlist may no longer contain a trait. Such declarations now report NastCheck[3108]; traits can remain in allowlists on classish kinds where their relationship has defined semantics. 76df11f979

Future Changes

  • The named-parameter implementation can now carry named argument metadata from HackC into HHVM and execute basic calls with required named parameters in the interpreter. Written left-to-right argument evaluation is preserved even though named values are arranged before positional values on the VM stack; JIT, inlining, and HHBBC optimizations still deliberately fall back for these calls. 792d13346d 0a27aa989f 3ca68328ff 7710d53043 b210576695
