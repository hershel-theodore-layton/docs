Thursday, April 23, 2026

5 noteworthy changes recorded on this day.

Highlights

  • Runtime tests with an abstract <<__Enforceable>> type constant are now allowed even when its as bound is not itself enforceable; a concrete implementation can still provide an enforceable type. edc62dc1c2
  • Nullable ?as no longer triggers package-boundary diagnostics. Unlike as, a failed ?as yields null rather than fatalling, so it does not require the asserted type to be available across the boundary. 13a5c1efc4

Breaking Changes

  • Higher-rank generic validation now traverses nested types when looking for escaping type parameters. Invalid escapes that were hidden below the top level can now be reported. 653e481d9c
  • Reflection declarations now expose concrete types for Reflection::getModifierNames(), ReflectionFunction::isDisabled(), and several ReflectionProperty queries. This improves inference and can reject callers that relied on the previous missing types. 64fd36da55

Future Changes

  • The experimental type-alias refinement checker now looks through aliases when rejecting refinements in is, as, and reified-generic positions, closing a way to hide an unsupported refinement behind a typedef. 59f35936dd
