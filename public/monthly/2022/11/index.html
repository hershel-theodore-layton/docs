58 noteworthy changes, organized by the source changelog sections.

Highlights

43 changes
  • W44 · Nov 1
    Module import and export rules now survive compilation and are exposed through reflection. Runtime enforcement is not enabled by this change. a2e15b83bd
  • W44 · Nov 1
    internal methods may now use <<__DynamicallyCallable>>; private and protected methods remain rejected. 235cd7a253
  • W44 · Nov 1
    The typechecker is more reliable when inferring disjunctive subtype constraints, and an internal error involving already-solved type variables has been fixed. e1e756b3f7 4500589618
  • W44 · Nov 1
    HH\execution_context() now declares [read_globals] instead of implicitly requiring [defaults]. A capability list is the callee's requirement, so this narrows the obligation on callers rather than granting the callee extra access: a caller that provides read_globals, or any superset such as defaults or globals, can call it. 0f776c17fd
  • W44 · Nov 2
    hh --remove-dead-fixmes no longer consumes the character immediately following an inline HH_FIXME. 92fd112e0e
  • W44 · Nov 2
    __toString() declarations in the bundled HHI files now explicitly return string. 700bee0a4f
  • W44 · Nov 2
    SplFileObject has more accurate iterator declarations: current() is a like-string because CSV mode and end-of-file can produce other values, while getChildren() is nullable. 1ab6c0cebd c4a85bee88
  • W44 · Nov 3
    Most previously untyped bundled HHI functions now have the transitional return type HH\FIXME\MISSING_RETURN_TYPE. This still behaves like Tany for compatibility, but is intended to become dynamic in the future. 7ecc475674
  • W44 · Nov 3
    Assignment through Map and Vector indexing no longer widens an already inferred element type. In particular, code that starts with an untyped empty collection may now need explicit generic arguments. a56d5cfefa
  • W44 · Nov 3
    In sound-dynamic mode, the result of a dynamic static method call such as ClassName::$method() is inferred as dynamic rather than the unsound Tany. 17f03a1a34
  • W44 · Nov 4
    Sound-dynamic checking now permits static calls through a value typed as string, matching the rule that string can flow to dynamic in this mode. 668b6893f5
  • W44 · Nov 4
    A typechecker soundness regression involving intersection types has been fixed. 1adee5934a
  • W44 · Nov 4
    Hack lint now reports redundant HH\FIXME\UNSAFE_CAST calls as lint 5647 and offers an autofix that replaces the cast with its input expression. d02adc3a29
  • W45 · Nov 7
    Redundant ?mixed and ?null type hints are now lint warnings (5008 and 5009) instead of type errors. 04b4d0f60b
  • W45 · Nov 7
    Type-alias expansion now detects cycles instead of repeatedly expanding a cyclic alias. 57491cc735
  • W45 · Nov 7
    Sound-dynamic checking handles partially enforced intersection return types and nullable-dynamic array operations more consistently. 17c37dd75a a7241d4077
  • W45 · Nov 7
    <<__MethodTraitDiamond>> is no longer gated as an experimental Hack feature. 7abe512898
  • W45 · Nov 8
    hhstc gained --remove-dead-unsafe-casts, which removes HH\FIXME\UNSAFE_CAST calls whose input already satisfies the destination type. 391d947075
  • W45 · Nov 8
    Bundled declarations now specify that Countable::count() returns int, and several ReflectionMethod predicates and modifier APIs now have concrete bool or int return types. ac1286cb39 9761e022e3
  • W45 · Nov 8
    Mutable collection clear() methods now return this, allowing their fluent behavior to be represented by the typechecker. 28e3aaa9cf
  • W45 · Nov 11
    Sound-dynamic pessimisation now handles abstract method return types and inherited intersection return types correctly, avoiding hierarchy errors in affected class trees. 7159fb5c86 e58ddaeeed
  • W46 · Nov 15
    Expression-tree type inference no longer passes pessimised like-types to makeTree when the virtual expression calls a pessimised function. 6f9d9ad3bc
  • W46 · Nov 15
    The bundled Set declarations now preserve their element type across iteration and common operations such as map, filter, values, and conversions. This should improve inference for projects using legacy Hack collections. f5ea07c6fa
  • W46 · Nov 15
    Dead HH\FIXME\UNSAFE_CAST removal is now integrated with hh_server, including repeated analysis until no further redundant casts can be removed. 097f3c19ad 6ebee6b689
  • W46 · Nov 15
    An internal type alias may now refer to another internal type from the same module. 61917d4bf0
  • W46 · Nov 15
    HH\classname_from_string_unsafe() is now declared in the HHI files. It converts a string to classname<mixed> without eager validity or module checks and is intended only for exceptional migration cases. 385ddd879a
  • W46 · Nov 16
    get_defined_functions() now preserves the declared capitalization of function names instead of lowercasing every result. Reflection calls with those names continue to work case-insensitively. e15e774b91
  • W46 · Nov 17
    Incremental typechecking now correctly fans out changes that add inherited XHP special attributes such as :aria-* and :data-*. Projects should see the same XHP attribute errors without needing a full typecheck. d615fbde45
  • W46 · Nov 17
    HHI global and class constants with an explicit type may now omit their placeholder value. Initializers have been removed from the bundled handwritten declarations and are no longer copied into generated HSL HHIs. This syntax is specific to HHI declaration files and does not change the constants' runtime values. 824ac81dc9 833f6d5fe7 0a1f30494a 80fb463a49 f5f90c7cad
  • W46 · Nov 17
    hh_server now tolerates duplicated and out-of-order Watchman state notifications during source-control updates, reducing the chance of an incorrect server state after an update or transaction. cea00244a1
  • W46 · Nov 17
    When code such as $object->$name attempts dynamic access on a non-dynamic value, naming error 2011 now explains the restriction and offers a quick-fix to ordinary property access such as $object->name. 82df50f9da
  • W47 · Nov 21
    Short enum-class labels such as #X can now be inferred when the expected parameter type is a nullable HH\EnumClass\Label. Invalid labels and labels with the wrong value type continue to produce the usual diagnostics. 153cf04a0d
  • W47 · Nov 22
    Sound Dynamic checking now preserves supportdyn when type_structure() examines a type constant bounded by an open shape. It also permits valid reads and appends through nullable containers while performing the additional __SupportDynamicType function-body check, avoiding false-positive errors in code that has already initialized or refined the container. e467b3f779 4f3e8fbfaa
  • W47 · Nov 22
    Hover text no longer mistakes class or namespace names beginning with HH_ for members of the HH namespace. A class named HH_FOO, for example, is now displayed without losing its prefix. 90d00b469a
  • W47 · Nov 23
    Sound Dynamic function-body checking now permits mutation after a value has been refined to AnyArray, including flows using HH\is_any_array(). These writes can be safely treated as an implicit upcast to dynamic. 3f1cef23f7
  • W47 · Nov 24
    hh_single_type_check --count-imprecise-types now emits a JSON summary of inferred mixed, nonnull, and dynamic expression types for each function and method in a file. This can help projects identify good starting points for type-precision migrations. 93c754fdb8
  • W47 · Nov 27
    A keyset literal in a context expecting mixed now retains the required arraykey element bound instead of being inferred as the invalid type keyset<mixed>. 2d1262a16e
  • W48 · Nov 28
    An experimental .hhconfig option, code_agnostic_fixme, makes an HH_FIXME suppress errors at its position regardless of the recorded error code. It is intended as a temporary aid for migrations such as Sound Dynamic pessimisation, where error codes may change; the default remains code-specific suppression. fe4f7ada87
  • W48 · Nov 28
    Generated hack.TypeInfo symbol facts now contain cross-references for common nested type hints such as Awaitable<?Foo> and vec<Foo>, rather than only for a bare class name. Consumers of symbol-info facts can use these links for more complete type navigation. 0c39bf8718
  • W48 · Nov 29
    Sound Dynamic enforceability checks now resolve this against the enclosing class when interpreting types such as this::T, improving the treatment of method returns, parameters, properties, and class constants that use type constants. 9beeec27c0
  • W48 · Nov 30
    Generic-arity errors are no longer redundantly produced during subtyping after the type has already been localized, reducing duplicate diagnostics. f9c1cb34c4
  • W48 · Nov 30
    Sound Dynamic inheritance checks now model runtime enforcement from a method's declaring signature rather than its instantiated inherited signature. This avoids treating a generic return such as T as runtime-enforced merely because a subclass inherits it as int. 7ff98a81d3
  • W48 · Nov 30
    Symbol-info export now always emits facts for namespace aliases defined in .hhconfig, even when gen_sym_hash is disabled. 59ea67ffd4

Future Changes

6 changes
  • W44 · Nov 2
    Untyped built-in declarations are beginning to use HH\FIXME\MISSING_RETURN_TYPE instead of the unsound internal Tany type. This is preparatory work toward treating such results as dynamic. 0c5aa56b30
  • W46 · Nov 16
    Lint 5624 no longer incorrectly labels generics used in pre-stable exact type refinements as redundant. 044f44601d
  • W47 · Nov 21
    Type constants in enum classes have moved from unstable to preview status. The syntax remains opt-in through <<file:__EnableUnstableFeatures('enum_class_type_constants')>>, but preview status permits explicitly enabled code to run in production. 810ea41057
  • W47 · Nov 23
    Enforceability analysis can now resolve type-constant accesses through concrete, abstract, and inherited definitions while safely terminating on cycles. This prepares Sound Dynamic signatures for future runtime enforcement of type constants. e92a9672ce
  • W48 · Nov 30
    Loose type refinements now participate in variance checking: as bounds are covariant, super bounds are contravariant, and exact refinements remain invariant. Code using preview type refinements may receive new variance diagnostics when a class type parameter appears in one of these bounds. 5a9139188b
  • W48 · Nov 30
    Autocomplete inside traits now suggests the preview require class constraint alongside require extends and require implements. 6052c0bcdf

Breaking Changes

9 changes
  • W45 · Nov 7
    Indexed assignment no longer widens inferred Hack array types. Code that builds a vec or dict from an empty value may need an explicit type annotation. 5143993e38
  • W45 · Nov 9
    Accessing a known-absent field on a nullable closed shape is now a type error even when using Shapes::idx() or ??. Previously, adding nullability could reduce this to a lint or suppress it. 9e49acc366
  • W45 · Nov 9
    SplPriorityQueue<T> is now declared as an iterator over ~T, reflecting that its extraction flags can make current() return a priority or a value/priority pair instead of T. 4110107aae
  • W46 · Nov 14
    Module boundary violations are now always enforced with exceptions; the Eval.EnforceModules switch and its disabled/warning modes have been removed. Soft-internal declarations continue to warn. 2b9440d421
  • W46 · Nov 15
    Class-level user attributes are typechecked outside the class context, so self is no longer available in their arguments. Module-internal names remain usable there when the attribute is evaluated inside the same module. a83ac0b2c2
  • W46 · Nov 15
    DirectoryIterator and FilesystemIterator now iterate over ~SplFileInfo, since extraction flags can make FilesystemIterator::current() return a string or the iterator itself. 7380211047
  • W46 · Nov 16
    Stale HHI declarations for runtime classes and class constants that do not exist have been removed. Several method declarations were also corrected, including ReflectionClass::getTraitAliases(), ReflectionFunctionAbstract::getStaticVariables(), and capitalization/finality mismatches in built-ins. Projects relying on the nonexistent declarations will now receive type errors. f4bc1485be 74f2d68eda 759eb8b13d
  • W48 · Nov 29
    Accessing $this where it is not defined now produces naming error 2050 instead of silently receiving an unconstrained type. This closes holes in enum-class member expressions and expression-tree contexts; affected code should pass or reference an explicit value instead. 8ca873e222
  • W48 · Nov 30
    The internal hphp_create_object() declaration has been removed from the bundled HHI files. Projects that called it directly will no longer typecheck and should use newv() instead. 0b947ff90f
