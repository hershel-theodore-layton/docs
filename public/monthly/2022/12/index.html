Highlights

29 changes
  • W48 · Dec 1
    Sound-dynamic checking now treats values captured by a <<__SupportDynamicType>> closure as like-types. This makes nested closures dynamically callable without repeatedly checking every nesting level, though hover and TAST output inside the closure may now show captured T values as ~T. 53d4897785
  • W48 · Dec 1
    The missing-<<__Override>> lint now offers a quick-fix, either adding a new attribute block or inserting __Override into an existing one. 624e58033f
  • W48 · Dec 1
    Go-to-definition and hover now distinguish a callable property from a method with the same name in expressions such as ($object->callback)(). 77fdfabcc6
  • W48 · Dec 1
    DOMElement::$attributes is no longer redeclared as non-null in the bundled HHI. It now inherits the nullable ?DOMNamedNodeMap<DOMAttr> declaration from DOMNode, so callers must handle null. d2bd42ae6c
  • W48 · Dec 2
    Invalid types encountered while localizing where constraints are now reported. This closes a type hole involving generic type-constant accesses and can reveal errors in signatures that previously passed. b614e9be2f
  • W48 · Dec 2
    Pair<T1, T2> is now typed as a ConstVector<T1 | T2>. Collection operations such as at(), map(), values(), and toImmMap() consequently preserve the union of the two element types instead of widening to mixed. dd7ca5fa24
  • W48 · Dec 3
    Bidirectional inference for keyset and dict literals now respects the arraykey bound when the expected type is (Keyed)Traversable or (Keyed)Container. Invalid expected key types no longer cause an out-of-bounds type to be inferred. 833436d8b6
  • W49 · Dec 5
    A type structure derived from an unbounded type constant no longer exposes class-specific fields such as classname. Add an appropriate classish bound before accessing those fields; an unbounded type constant is treated consistently with one bounded by mixed. ad69f94600
  • W49 · Dec 5
    Hovering over declarations now explains the class, interface, trait, enum, enum class, type, and newtype keywords. d079884920
  • W49 · Dec 6
    The bundled HHI now declares ThriftApplicationException, including its nullable-message constructor, so Hack code can refer to the exception without a local stub. aff8fbdb7e
  • W49 · Dec 7
    The typechecker now rejects trait composition that makes a static member overlap an instance member of the same name. Such code would already fatal in HHVM; the error is now caught during typechecking. 4f5f028f38
  • W49 · Dec 7
    Module names may now contain non-reserved keywords, matching the names accepted for classes. Reserved keywords and XHP-style names remain invalid. 669b93bd1b
  • W49 · Dec 7
    Deployments using native Facts can set Autoload.UpdateSuppressionPath to a sentinel file. While that file exists, Facts skips Watchman-driven updates; relative paths are resolved from the repository root. 5f4a1ae19b
  • W49 · Dec 8
    A new lint reports casts whose target type is already identical to the expression's inferred type. a070d39d1f
  • W49 · Dec 8
    When an enum declaration omits its base type, the parser error now offers a quick-fix that inserts : arraykey. c60763014e
  • W49 · Dec 8
    Reflection no longer converts enum-class labels found in arbitrary user-attribute arguments as though they were memoization metadata. The special conversion is now limited to memoization attributes. 8ba321326d
  • W50 · Dec 12
    Missing method visibility errors now offer a quick-fix that inserts a visibility modifier. 2b4eb0ad20
  • W50 · Dec 13
    Missing required-XHP-attribute errors now point to the attribute declaration rather than the containing XHP class. df7da6ed99
  • W50 · Dec 13
    An unbounded generic is now treated like a generic explicitly bounded by mixed when accessing type structures. Class-specific fields such as classname require a classish bound. eb806ee50a
  • W50 · Dec 13
    Several HH\TypeStructure fields have more accurate bundled declarations: return_type and value are mixed, while access_list is ?varray<string>. 7926fe9c9d
  • W50 · Dec 13
    Native Facts now coalesces simultaneous update requests behind an already-pending Watchman query instead of scheduling one query per caller. 3db59e7600
  • W50 · Dec 14
    HHVM's binary and compact Thrift serializers now apply parameterized type wrappers, including wrappers nested in container fields. Generated wrapped-field setters are used where nullable fields do not reveal the wrapper class at runtime. 2416be18d2
  • W50 · Dec 14
    The bundled HH\TypeStructure declaration now types param_types and elem_types as ?varray<mixed> instead of leaving their legacy-array generic arguments unspecified. 56002867f6 15721deb25
  • W50 · Dec 15
    Member find-references now narrows its dependency-graph search to descendants that can contain the named member. Results should be unchanged, with substantially less unrelated code searched in large hierarchies. aaf403a3e5
  • W50 · Dec 15
    Hover information is now available for keywords used inside classes, including static, use, and const type. b2e88973ff
  • W50 · Dec 15
    Experimental module-reference checking has been restored after fixing the module cache path that made it expensive. Projects using the feature once again receive its cross-module reference diagnostics. 9345a32382
  • W51 · Dec 22
    Errors for the PHP-style built-in aliases boolean and double now offer quick-fixes to Hack's bool and float types. 59dfa803f2
  • W52 · Dec 29
    hh_client --coverage and the corresponding single-file coverage/color modes now count dynamic and like-types as untyped coverage, aligning the metric with sound-dynamic code rather than only the legacy internal Tany type. 932ffc192a
  • W52 · Dec 29
    Return-type errors now point at the declared return type instead of the function name. 5439bf1e75

Future Changes

12 changes
  • W48 · Dec 2
    A trait and its required class may declare the same private property without producing a spurious ambiguous-access error in the pre-stable require class feature. In this case the declarations describe the same property rather than shadowing one another. 81231622de
  • W48 · Dec 2
    The unstable type-refinement implementation now supports loose as and super bounds, including their subtyping rules. Accessing a type member through an inexact refinement is rejected because the member is not known exactly. The feature still requires the type_refinements unstable-feature opt-in. 1eaa4bece4
  • W49 · Dec 5
    Unstable type refinements now use dedicated typing error codes: 4468 for access through an inexact refinement, 4469 for unsupported refinements, and 4470 for invalid class refinements. Suppressions written against the former generic error codes may need updating when adopting the feature. c50044fcc6
  • W49 · Dec 8
    Diagnostics for pre-stable type refinements now print refinement syntax with source-like spacing, making displayed types easier to read and copy. 418ef35a32
  • W49 · Dec 9
    The direct-declaration parser now retains pre-stable type-refinement members when they are wrapped as comma-separated list items. Incremental and full typechecking should consequently agree on refined type constants. 4528fb949c
  • W50 · Dec 12
    Type refinements are now accepted by HHVM itself. Source files still need <<file:__EnableUnstableFeatures('type_refinements')>>, but no separate HHVM-side feature gate is required. 32b5df2753
  • W50 · Dec 12
    Experimental module-reference checks were temporarily disabled because of their cost in projects using modules. They are restored on December 15 after the cache path was corrected. 694d3b9b2e
  • W50 · Dec 13
    Calling HH\autoload_set_paths() while native autoloading is active now raises a deprecation notice. Deployments can set Autoload.UserlandEnabled=false to turn such calls into InvalidOperationExceptions and find code that must migrate to native autoloading. 0e45a0afae
  • W50 · Dec 16
    Under everything_sdt, UNSAFE_CAST<TFrom, TTo> is now represented as an upcast to ~TTo, including in the TAST. Tools consuming the TAST should expect the like-type, which reflects that the cast does not provide a runtime guarantee. 90a13f5252
  • W50 · Dec 16
    Private methods in sound-dynamic classes are now checked as dynamically callable, just like non-private methods, because they can still be reached through dynamic or like-typed receivers. This can expose previously missed sound-dynamic errors. 822346b50c
  • W50 · Dec 16
    Implicit pessimisation no longer treats type constants as runtime-enforced by default. Projects experimenting with sound dynamic typing should not rely on a type-constant access alone to enforce the resulting value. f598a1f437
  • W51 · Dec 20
    A new disallow_static_constants_in_default_func_args project option can reject static::* in constant function-parameter defaults. It is off by default and applies alongside constant-default-argument checking, allowing projects to migrate before this late-static-bound form is removed. 962f77a960

Breaking Changes

5 changes
  • W48 · Dec 3
    Static properties must now declare public, protected, or private explicitly; Hack no longer silently treats a declaration such as static int $count as public. dc2a79087b
  • W49 · Dec 8
    Iterable::map() and KeyedIterable::mapWithKey() have been removed from their interfaces because their signatures were unsound. Calls through those interface types must use an appropriate concrete collection API or an HSL traversal function. 899d46019f
  • W50 · Dec 12
    Hack command-line tools now distinguish --error-format raw from the former plain-text rendering. Scripts that consume the old output from hh_single_type_check or related single-file tools should request the new --error-format plain; raw now consistently selects the structured raw formatter. d9f4bc6e0c
  • W51 · Dec 19
    SplPriorityQueue now takes separate value and priority type parameters: SplPriorityQueue<TValue, TPriority>. Its bundled HHI also gives concrete types to compare(), insert(), extract(), top(), and the iterator methods. Existing one-argument annotations must add the priority type. b55314d75a
  • W51 · Dec 19
    Constant-expression validation now recursively rejects static::* and parent::class inside collection and shape literals used for constants or property initializers. These accesses were already rejected at the top level; nesting them no longer bypasses the check. 3edc239bad
