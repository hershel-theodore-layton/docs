Highlights

33 changes
  • W35 · Sep 1
    Sound Dynamic joins now simplify unions and intersections through supportdyn wrappers, avoiding unnecessarily large or imprecise inferred unions after control-flow joins. 55f4a9ddff
  • W35 · Sep 1
    Soft-package class access no longer emits a duplicate deployment-boundary warning while resolving the class. 497854503a
  • W36 · Sep 4
    Enum-switch exhaustivity checking now recognizes pessimised enum types regardless of whether the enum bound appears before or after its like type in an intersection. This restores missing-case errors after awaiting an enum value and avoids treating intersections of unrelated enums as ordinary enum bounds. d755a2e87b
  • W36 · Sep 5
    Trait-diamond errors now suggest adding <<__EnableMethodTraitDiamond>> when that attribute is the intended migration. ce9619696c
  • W36 · Sep 6
    Projects can opt in to rejecting direct superglobal variables such as $_SERVER with disallow_direct_superglobals_refs=true; diagnostics direct callers to the corresponding HH\global_* APIs. The compatibility default remains disabled. 40a5ae7da0 491c65d3bf
  • W36 · Sep 6
    Package metadata now reaches hh_distc, and typechecker glob matching treats foo.* as matching both foo and its descendants while preferring the most specific exact match. 93d7c2a891 2933cd2759
  • W36 · Sep 7
    Repo-authoritative deployments now include soft packages so accesses can emit deployment-boundary warnings and continue, rather than failing with an undefined function or class. 1171062eb4
  • W36 · Sep 7
    Class expressions used as attribute arguments no longer trigger internal or cross-package visibility errors. This permits patterns such as sealing a trait to an internal class because the stored attribute value is only a class-name string. 1d2b48aecd
  • W36 · Sep 7
    The HHI declarations for HH\get_headers_secure() and HH\parse_cookies() no longer carry __PHPStdLib, restoring their intended treatment by Hack tooling. Their capability lists remain [read_globals] and [], respectively. d5ad640290 12d45c23a5
  • W36 · Sep 8
    Reified-generic checking now preserves the most informative type arguments across union receivers and looks through like-typed function signatures. This removes false missing-type-argument errors while restoring real errors for omitted reified arguments. c3045c650d ed0a6efdfd
  • W36 · Sep 8
    Implicit lazy-class-to-string notices for argument type hints now identify which argument and function triggered the conversion. e912bbb1e0
  • W37 · Sep 12
    Open-source HHVM builds once again parse and enforce PACKAGES.toml, and runtime package matching now agrees with the typechecker that foo.* includes foo itself while exact matches take precedence. a11552fc4f 5f0823ca7d
  • W37 · Sep 12
    IDE completion cards for top-level functions now include their parameter and return signatures. 78618a4c42
  • W37 · Sep 14
    HHVM's sodium extension adds Ed25519 point validation, addition, subtraction, and unclamped point scalar multiplication through sodium_crypto_core_ed25519_is_valid_point(), sodium_crypto_core_ed25519_add(), sodium_crypto_core_ed25519_sub(), and sodium_crypto_scalarmult_ed25519_noclamp(). 123c63cc3f
  • W37 · Sep 15
    Nested blocks inside finally are now flattened correctly during elaboration, preventing a typechecker crash. 2df376a2e3
  • W37 · Sep 15
    Native enum-class labels now retain their former opaque-resource serialization contract: JSON reports an unsupported type, memoization rejects labels, and serialize() throws an error identifying EnumClassLabel. 82316bc93d
  • W38 · Sep 18
    Corrected repo-authoritative support for soft deployments has relanded. Soft-package functions, classes, methods, and constants remain in the repo and emit boundary warnings rather than collapsing into undefined-symbol failures. d786fbef34
  • W38 · Sep 18
    hh_single_complete --resolve now exposes completion signatures, making the IDE's resolved completion data available to command-line tests and tooling. 8a7ff6c02c cc442823ec
  • W38 · Sep 19
    The IDE's “Inline method” refactor now emits a valid $res temporary for returned values instead of the invalid bare identifier res. 2e1dbf6572
  • W38 · Sep 19
    hh --rewrite-declarations can rename repeated declarations for notebook-style Hack input; the functionality has moved from a separately deployed binary into the standard client. 8e60519cb2
  • W38 · Sep 20
    Hack's HHI hover text and manual now explicitly deprecate collection classes in favor of Hack arrays: prefer vec to Vector, dict to Map, keyset to Set, and tuples to Pair. 0fbfe6867e
  • W38 · Sep 20
    Compiler-generated temporaries now have explicit block scope and are unset on both normal and exceptional exits. This also restores readonly checking for top-level await expressions inside concurrent blocks. 19d2d8a7af
  • W38 · Sep 21
    Runtime type-structure cache keys now include typevar_types, so distinct reified instantiations such as NT<int> and NT<float> no longer collide during resolution. 2784c2004f
  • W38 · Sep 22
    Errors for inaccessible or invalid attribute classes now point to the attribute use site, rather than manufacturing a source position from the attribute class declaration. 0a9d3a9db6
  • W39 · Sep 25
    HackC no longer constant-folds T::class when T is a reified generic; the emitted code resolves the runtime class supplied for T. 8068a8e3a6
  • W39 · Sep 25
    “Extract into method” now prints the real return type instead of _, including large and currently non-denotable types such as unions. “Add local type hint” likewise stops inserting type-printer fuel messages or truncated types into source. d37dcf933e f2bc2b88cb
  • W39 · Sep 26
    The typechecker and typed AST now retain concurrent blocks instead of first lowering them to generated awaitall code. This improves source positions and typed-local checks, and fixes “Extract into method” omitting async and Awaitable from methods extracted from a concurrent block. aef6da73ca
  • W39 · Sep 27
    The VS Code debugger now steps through async functions correctly with the JIT enabled, including stepping into and out of resumed async frames. 76c6770340
  • W39 · Sep 28
    preg_get_error_message_if_invalid(string $pattern): ?string is now available to typechecked Hack. It returns null for a valid regex or an error message for an invalid one without emitting malformed-pattern warnings. ed5c1a754e
  • W39 · Sep 28
    hh --find-refs now accepts Kind|Symbol, covering methods, properties, class constants, type constants, functions, classes, explicit classes, and global constants. ExplicitClass excludes references through self, static, and parent. 7beb2f1aa9
  • W39 · Sep 29
    IDE find-references requests can now be cancelled and immediately retried without leaving a stale shellout, and completion of the search reliably flushes its final streamed results. 6772812664 cbab9e45ea
  • W39 · Sep 29
    Invalid conversions of reified function pointers, reified class-method pointers, and enum-class labels now throw catchable InvalidOperationExceptions instead of terminating with an uncatchable fatal. Error text also uses Hack names such as “function,” “class method,” and “float.” fcca69ea4f
  • W39 · Sep 29
    ReflectionMethod::getCanonicalMethod() and getCanonicalClassname() can locate the trait that actually defines an inherited method in non-repo mode. They throw in repo-authoritative mode, where traits have already been flattened. 45c1f1f8e9

Breaking Changes

12 changes
  • W35 · Sep 1
    Sound Dynamic has backed out the all-dynamic fallback for calls through supportdyn function types. Calls that only typechecked after pessimising every parameter may now report argument errors. 349eca7fa1
  • W35 · Sep 1
    A property whose alias or newtype resolves to nothing is now rejected at class initialization with an invalid-property-type fatal, rather than slipping through runtime resolution. 57141c389a
  • W36 · Sep 6
    hh --search has been removed. IDE autocomplete and search no longer depend on hh_server's former SQLite symbol index. edd2b799c5
  • W36 · Sep 6
    The typechecker now supplies the built-in default module through HHI. Projects must not declare new module default {} themselves; package diagnostics can now point to this built-in declaration. be4229a0c4
  • W36 · Sep 8
    Enum-class labels now use a native runtime datatype by default instead of opaque resources. Dumps identify enum class label (#Name), equality compares label names, and relational comparisons throw InvalidOperationException; code that inspected labels as resources must migrate. d044eba3a1 353425f238 ab69809ede
  • W37 · Sep 12
    The repo-mode soft-package warning behavior from September 7 has been temporarily backed out. Repo builds once again omit soft packages and can fail with undefined-symbol errors until the corrected reland. 16c8aaf940
  • W37 · Sep 12
    The experimental hh --pause and hh --resume commands have been removed; file changes always trigger the normal full-check workflow. 3bd5161a2c
  • W37 · Sep 13
    Reflection's default-expression text for array access with a class constant, such as $items[C::class], is now emitted like the equivalent string-key expression. Invoking the function is unchanged, but reflective evaluation now follows the same failure behavior as $items["C"] instead of the old special case. e51ba0edb3
  • W37 · Sep 14
    HHVM's native PostgreSQL extension and its pg_* APIs have been removed, along with the libpq build dependency. Applications must use another database client. dabfb89185
  • W38 · Sep 18
    A source file may now contain at most one new module declaration. Projects that collected several module definitions into one file must split them into standalone files. 21f428203b
  • W38 · Sep 19
    hh_single_type_check --custom-hhi-path now requires --no-builtins, preventing concurrent invocations from truncating generated builtin files in the shared custom directory. 27e9b0384d
  • W38 · Sep 22
    Abstract methods and type constants inherited from traits no longer silently override concrete inherited members. The typechecker now reports the invalid redeclaration while preserving the correct primary source position. eb118e9546

Future Changes

    Opt-in strict switches now reject impossible case values and redundant defaults for nothing/noreturn scrutinees. 7497648c8c

    Experimental case-type overlap checking now uses require extends constraints on interfaces and traits to reason about their possible implementations. 21693db81f
  • W36 · Sep 7
    Opt-in strict switches now model null, nullable, nonnull, and negative types, diagnosing missing or repeated case null arms. 87922666c4

    Parser-schema and hackfmt groundwork lands for a future nameof C expression, but the typechecker still rejects the syntax at this stage. 55c68773cc

    Opt-in strict switches now understand boolean scrutinees and can require both true and false arms. 1e3bf333a0

    Runtime groundwork for case types now represents primitive and object unions in type constraints, supports properties in repo mode, and keeps property overrides nominal. Case types are still an opt-in language feature at this point. 32169a9ad6 a18b5577b7 808fb25912 ee67a83704
  • W37 · Sep 11

  • W37 · Sep 11
    The runtime implementation of preg_get_error_message_if_invalid() can validate a regex and return ?string without raising the usual malformed-pattern warning. Its HHI declaration has not landed yet, so typechecked projects cannot use it normally at this stage. 922ca33aa7
  • W37 · Sep 12
    Opt-in strict switches now recognize integer literals, require a default for the open-ended int domain, and report repeated literal arms. 1fa08641fe
  • W37 · Sep 13
    Opt-in strict switches now accept integer-valued class constants and transparent enum constants, and can diagnose repeated constants where their symbolic names match. d2a05fad8e
  • W37 · Sep 15
    Opt-in strict switches now require integer case literals to use a consistent base and provide better source locations when a case has the wrong type. 9e65ee8eec a2f0f8f4e0
  • W38 · Sep 19
    Strict-switch checking is now an explicitly unstable, per-function feature: opt in with <<file:__EnableUnstableFeatures('strict_switch')>>, then apply <<__StrictSwitch>> to a function or method. The old project-wide enable_strict_switch option is removed. String literals and string-valued class constants are also supported. dd6849b13b e172d60f7c 02bd9d5a82
  • W38 · Sep 21
    The unstable pipe_await lowering now uses properly scoped compiler temporaries for await on the right side of |>, preventing generated locals from leaking across the transformed statement. f908a5e42b
  • W38 · Sep 21
    Under implicit pessimisation, experimental case types are now correctly rejected as enum and enum-class base types instead of being hidden behind a like type. 38d5661170
  • W39 · Sep 26
    Unstable strict switches now classify arraykey-typed class constants as both possible integer and string cases, improving wrong-type and duplicate-case diagnostics. 39494259ec
  • W39 · Sep 27
    Case-type runtime checks now handle classname-to-string conversion warnings in the JIT instead of reaching an unimplemented path. 234bc7e5a5
  • W39 · Sep 27
    Case-type analysis now detects cycles through generic bounds, newtypes, sealed lists, requirements, and nested case types, making conservative approximations instead of looping or overflowing the typechecker stack. c49207358d
  • W39 · Sep 29
    Case types have moved from Unstable to Preview. They still require the case_types file-level opt-in, but Preview status permits opted-in code to run in production now that runtime enforcement is enabled. 942f1c5a74
