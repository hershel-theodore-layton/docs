50 noteworthy changes, organized by the source changelog sections.

Highlights

27 changes
  • W48 · Dec 1
    hh_single_type_check --root can now locate a downloaded naming table automatically and reads enable_sound_dynamic_type and everything_sdt from the project's .hhconfig, reducing differences from a normal hh run. 99c4e207d0
  • W48 · Dec 1
    The Hack manual now documents __AutocompleteSortText, which lets a declaration supply the sort key used for its IDE completion entry. 1785b081e2
  • W49 · Dec 4
    Best-effort notebook support now typechecks top-level statements as the body of a synthetic async function. This restores completions and ordinary type errors around top-level await, and initializes the same implicit capability locals as a function instead of reporting $#capability as undefined. Normal Hack files still receive the general error that top-level statements are unsupported. aa87ac15ee d5c48abf18
  • W49 · Dec 4
    debugger_dump() is now visible to typechecked notebook code. This removes only its __PHPStdLib restriction; its omitted capability list continues to mean [defaults]. 8c7dfdb58b
  • W49 · Dec 5
    A trait marked __ModuleLevelTrait may now use an ordinary trait. The runtime fatal has been removed because ordinary traits cannot themselves declare or access module-internal members. d1cfeadc32
  • W49 · Dec 6
    Enum-class-label completion now solves refinement-type constraints before filtering candidates, avoiding the fallback that suggested every label when only a constrained subset was valid. 3b57ad1701
  • W49 · Dec 6
    HH\FileDecls::getFile() now returns typedefs and modules under their proper keys instead of accidentally overwriting the file-attributes entry. 15c78d1216
  • W49 · Dec 7
    Enum-class-label completion no longer resolves a contravariant type variable prematurely to mixed or supportdyn<mixed>, allowing the IDE to retain the useful label candidates implied by narrower bounds. ee19abb9a3
  • W49 · Dec 7
    HHVM's sodium extension adds the missing Ristretto255 point operations: sodium_crypto_core_ristretto255_add(), sodium_crypto_core_ristretto255_sub(), sodium_crypto_core_ristretto255_is_valid_point(), and sodium_crypto_core_ristretto255_random(). ed0c96f189
  • W49 · Dec 8
    IDE completion signatures now print declared coeffects, including [], named contexts, and context-polymorphic requirements, instead of silently omitting them. This is a presentation fix: callee requirements and the rule that callers need a superset of those capabilities are unchanged. b1a1774b1f
  • W49 · Dec 8
    Override diagnostics now compare against and describe the instantiated parent member type, producing more useful explanations for failures inherited through generic parents and traits. 3c76b90da3
  • W49 · Dec 8
    The standard hash extension now supports unkeyed BLAKE3 through APIs such as hash('blake3', $data). d648c1cc26
  • W49 · Dec 8
    The HHI for debugger_dump() now gives its argument the real mixed type, so arbitrary values no longer need a missing-type workaround. 0c5f03837e
  • W49 · Dec 9
    meth_caller(nameof C, 'method') is now accepted as an alternative to meth_caller(C::class, 'method'). As before, the target must be a class rather than a trait. b10117f022
  • W50 · Dec 11
    nameof now accepts transparent and opaque type aliases and returns the alias's own name. For example, type T = int produces typename<int>, while an opaque newtype U produces typename<U>. 119ec37e14
  • W50 · Dec 14
    hh_single_complete --root can now locate a downloaded naming table automatically and load project settings from .hhconfig, matching the corresponding hh_single_type_check workflow. c1f8037cd1
  • W50 · Dec 14
    hackc verify compile can compile a set of Hack files solely to report parse, runtime, and compilation errors without retaining bytecode output. cb15edecd9
  • W50 · Dec 15
    An opt-in strict UTF-8 parser mode can reject source files containing invalid byte sequences. Hack uses strict_utf8=true; HHVM's Eval.StrictUtf8Mode remains off at 0, rejects source but permits eval input at 1, and rejects both at 2. 002372fd69
  • W51 · Dec 18
    HH\FileDecls::parsePath() is now implemented: it reads a Hack file from disk and returns the same declaration view as parseText(), throwing InvalidArgumentException when the path is missing or cannot be opened. de1dd54b17
  • W51 · Dec 18
    HH\class_to_classname() now retains dynamically constructed string inputs correctly, preventing its returned classname string from becoming invalid after the native wrapper releases the argument. f4402a8d7a
  • W51 · Dec 19
    Find-references, find-class-references, and refactor requests no longer restart their file iteration after cancellation polling, fixing searches that could run indefinitely. 6808aa6797
  • W51 · Dec 19
    LSP request cancellation is now enabled by default, so abandoned IDE work can stop rather than delaying the replacement request. 94342a995c
  • W51 · Dec 19
    Direct-declaration parsing with user attributes retained no longer drops heredoc, nowdoc, or parenthesized expressions. This prevents affected constants from degrading to an unknown type in downstream typechecking. 230809b98e
  • W51 · Dec 19
    Type errors that refer to expression-dependent types now print stable internal <expr#…> identifiers rather than renumbering them for display. The numbers may be larger or nonconsecutive, but repeated runs are deterministic. 65e011a6fd
  • W51 · Dec 20
    The Hack manual now includes a package guide covering package definitions, deployments, cross-package calls, and PACKAGES.toml configuration. 77eea71427
  • W51 · Dec 21
    The VS Code debugger now evaluates a request without an explicit frame ID in the frame selected by the most recent scopes request, when execution is paused. 9de19a803e
  • W51 · Dec 21
    Repo-authoritative optimization now converts type constraints back to unresolved form when their target class is later found to be missing or uninstantiable, avoiding stale resolved constraints against nonexistent classes. 6de1d23d18

Breaking Changes

12 changes
  • W48 · Dec 1
    hh_single_type_check no longer accepts the --like-type-hints switch and always enables like-type hints by default. Use --config like_type_hints=false when the legacy behavior is required. 12e71b4968
  • W48 · Dec 1
    The typechecker now rejects varray[...] and darray[...] initializer syntax. Migrate remaining initializers to vec[...] and dict[...]. 6e4f4cfed0
  • W48 · Dec 1
    A function marked __DynamicallyCallable and a class marked __DynamicallyReferenced are now implicitly treated as __SupportDynamicType. This removes the need to repeat the latter attribute, but it also checks those declarations under sound-dynamic assumptions and can expose new errors in their bodies or signatures. f84c931769 f81b17b454
  • W49 · Dec 6
    The declaration-inspection extension has moved its global FileDecls class, shapes, and constants into the HH namespace, and a new HHI makes the API available to the typechecker. Update calls to use HH\FileDecls and qualify associated types and constants. 5fe71bb694
  • W49 · Dec 6
    Converting a reified function pointer to bool now consistently produces true. The interpreter previously threw InvalidOperationException while JIT-compiled code already returned true. 327f2611e6
  • W49 · Dec 7
    Ancestor traversal now gives directly declared implements entries precedence over interfaces inherited through extends. For a type that reaches the same generic interface at several instantiations, this can change which instantiation wins and can expose type errors that the previous ordering hid. 23ac49c0fa
  • W49 · Dec 8
    When a class or interface reaches the same generic interface at multiple instantiations, the winning instantiation must now be a subtype of every ignored instantiation. Invalid hierarchies report Typing[4480]; __AllowMultipleInstantiations is available as an unsafe migration escape hatch. f61d456473
  • W50 · Dec 14
    The language's special handling for die has been removed. Replace remaining die(...) calls with exit(...). 85d879120e
  • W50 · Dec 15
    Constructors of __SupportDynamicType classes are now checked under dynamic assumptions, just like their other methods. Constructors that store or return values incompatible with dynamic construction can therefore gain new sound-dynamic errors. 9004eeeb25
  • W51 · Dec 18
    Support for meth_caller(nameof C, 'method'), introduced on December 9, has been backed out because the compiler lowering was unsound. Use meth_caller(C::class, 'method') again. 420490f6e1
  • W51 · Dec 20
    FixDefaultArgReflection now defaults to mode 2. If evaluating a parameter's default expression during reflection fails, HHVM emits a warning and reports the reflected default as null instead of exposing the evaluator's exception under the old mode. 6adc7b1655
  • W51 · Dec 21
    hh_single_type_check no longer accepts --math-new-code; the newer arithmetic-checking behavior is always enabled in the tool. 6c1dbdb71d

Future Changes

11 changes
  • W48 · Dec 1
    Typed local variables have moved from Unstable to Preview. They still require <<file:__EnableUnstableFeatures('typed_local_variables')>>, but the Preview status permits opted-in code to run in production. 466d390616
  • W48 · Dec 2
    nameof is being changed to bind like a prefix unary operator, so expressions such as nameof C . 'Suffix', nameof C is string, and nameof C |> f($$) apply the following operator outside nameof. The runtime compiler uses the new precedence immediately; the typechecker can opt in with nameof_precedence=true, but its default remains on the old parser behavior for this rollout stage. 3cc9a258bd
  • W49 · Dec 4
    A trait with the pre-stable require class C constraint may now call parent::; the call is checked against the required class's parent just as it is for require extends. c2149e9281
  • W49 · Dec 5
    IDE rename now handles Preview typed-local declarations, and typechecker errors point at the declared local rather than the entire let statement. Runtime enforcement failures are also prefixed with “Typed local assignment” to distinguish them from parameter and return-type failures. 1332c3ee42 a164327813
  • W49 · Dec 8
    The unstable function_references feature introduces invariant HH\FunctionRef<T> types for APIs that update a named function pointer. Named function pointers receive the wrapper type, lambdas do not, and the wrapper is erased before runtime. Where unstable features are allowed, opt in with <<file:__EnableUnstableFeatures('function_references')>>. 5bb1ca7dca
  • W50 · Dec 11
    Runtime type constraints now recognize the explicit HH\object type as “any object.” This is groundwork: no builtin or HHI declaration uses the new constraint yet. 93db8b6ada
  • W50 · Dec 13
    The unsafe escape hatch for repeated generic-interface instantiations is being renamed to __UNSAFE_AllowMultipleInstantiations. Both the old and new attribute names are accepted at this migration stage. 588f82b507
  • W50 · Dec 15
    Module-level traits have advanced from Preview to Ongoing Release. The runtime compiler can accept them during the rollout, while typechecked source still needs the module_level_traits file-level feature opt-in. 9cd2521478
  • W52 · Dec 27
    Package allow_directories restrictions can now be parsed from PACKAGES.toml, resolved relative to that file, and loaded into the typechecker's package information. Validation and enforcement are not implemented in this stack yet. 4f827c77b1 4d08d8fb03 337f4ebbce
  • W52 · Dec 27
    A gated IDE invalidation strategy now detects individual class-signature changes and invalidates that class plus cached descendants that depend on it, aiming to avoid both stale IDE errors and full-cache invalidation. The lsp_invalidation rollout flag remains off by default. 0f0bb7749a d0fc06c04c
  • W52 · Dec 28
    hh_single_type_check no longer suppresses package-configuration failures, allowing staged allow_directories errors such as nonexistent directories to be reported while that feature is developed. c70389e31b
