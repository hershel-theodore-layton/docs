Highlights

19 changes
  • W09 · Mar 1
    Under Sound Dynamic, calls through like-typed receivers and like-typed function values now produce like-typed results. For example, calling an int-returning method through ~C yields ~int, closing an unsound path that previously inferred plain int. 2b51ce34b0
  • W10 · Mar 4
    Sound Dynamic method calls can now use like-pushing to satisfy where constraints. A receiver such as ExpectObj<~vec<int>> can call a method constrained with T as Container<mixed>, with the result correctly remaining like-typed. e6dfdec1be
  • W10 · Mar 4
    The new pure HH\FileDecls::genParsePath(string)[]: Awaitable<HH\FileDecls> API supports non-blocking declaration parsing, including implementations backed by remote I/O-bound caches. b041842c13
  • W10 · Mar 4
    Type errors involving shapes reached through aliases now retain the alias definition position, so diagnostics such as error 4108 point to the declaration rather than a later hint. 7e07868621
  • W10 · Mar 4
    Image metadata detection gained AVIF and HEIC support through libheif, notably for getimagesize(). 80f15c3872
  • W10 · Mar 8
    The false branch of if ($x) no longer narrows $x to null: Hack now accounts for other falsy values such as false and the empty string, closing an unsound refinement. afee63e475
  • W11 · Mar 12
    A promoted variadic constructor parameter now declares its property as vec<T> rather than T in both parser paths. For example, private string ...$args produces a vec<string> property and no longer causes errors in the lowered constructor body. a9284326d6
  • W11 · Mar 12
    ReflectionFile::getModule()[]: ?string is now implemented, returning the module declared by the reflected file when it has one. 25639bc1f5
  • W11 · Mar 13
    The “add missing method stubs” quickfix now inserts generated methods at the end of the class instead of the beginning. ddfef7b4a5
  • W11 · Mar 13
    The new pure HH\Facts\files_and_attr_args_with_attribute(string)[]: vec<(string, ?string)> query returns every matching file and file-attribute argument in one call. Files with multiple arguments appear multiple times; integer arguments retain the Facts API's existing behavior of coming back as strings. bb3c74674d
  • W11 · Mar 14
    The new hphp_was_interrupted_by_debugger()[read_globals]: bool builtin reports whether the current request has been paused by the VS Code debugger, even if the debugger later disconnects. 0d9eca7e0f
  • W11 · Mar 14
    Promoted variadic constructor properties now carry their corrected vec<T> type into emitted property metadata, so runtime property-hint checks agree with the typechecker. c7e208f99e
  • W12 · Mar 19
    Autocomplete now recognizes namespace constant declarations, restoring completions at declaration sites inside namespaces. 62ec1f5201
  • W12 · Mar 19
    Type tests of the form if ($x is bool) now use constraint-based partitioning, improving true- and false-branch refinements for unions, intersections, and bounded abstract types. 769012223d 26fb5051ac 51ae0e53ef
  • W12 · Mar 20
    Hack's VS Code diagnostics can now render secondary quickfix locations as dotted gray underlines, and the same quickfix is available when the caret is on one of those hinted locations. d90eb57776 138bc45288 f1f9295614
  • W13 · Mar 26
    this is now considered fully runtime-enforced when it appears in a final, non-generic class, allowing Hack to reason more precisely about those type hints. ccc7a97603
  • W13 · Mar 26
    Immediately invoked lambdas with syntactically constant arguments no longer invalidate fake-member refinements. This supports expression-oriented patterns such as async blocks and expression-tree runtime expressions without unnecessary rechecks. d768a63db0
  • W13 · Mar 27
    The new unserialize_slice(string, int, int, darray = dict[])[defaults]: mixed builtin deserializes a byte range without first allocating a substring. Invalid offsets or non-positive lengths throw InvalidArgumentException. c3519b4365
  • W13 · Mar 27
    debugger_dump() now writes exclusively through debugger stdout hooks, so debug-display output reaches the debugger without also entering the application's ordinary output buffer. e5794da899

Future Changes

7 changes
  • W09 · Mar 1
    The experimental sound_enum_class_this_type feature now localizes this in enum-class member types against the enum class being accessed, rather than the surrounding class. 2d28f2b3ba
  • W10 · Mar 6
    HH\classname_to_class() and HH\class_to_classname() now accept preview readonly classname<T> arguments while remaining pure, allowing readonly class values to pass through the migration helpers without a mutable-value error. 03233e7456
  • W10 · Mar 6
    Function type hints in ongoing release now support the optional qualifier without a per-file opt-in. Types such as (function(int, optional int): void) can describe functions whose trailing parameter has a default, but the feature remains pre-stable. 6e9dfb645d
  • W11 · Mar 13
    Under the ongoing module_level_traits_extensions feature, a public <<__ModuleLevelTrait>> may now declare internal methods. Internal properties remain restricted to internal traits. 6cad9f87c5 f1bc12cf99
  • W12 · Mar 19
    Unstable expression trees can now contain keyed collection literals such as Dsl`Collection {'a' => 1}; DSLs receive them through visitKeyedCollection(). 8659f615d5
  • W12 · Mar 20
    Preview readonly checking now produces type errors for unary increment and decrement, matching its existing checks for compound assignments such as +=. d323321cd0
  • W12 · Mar 21
    Under the preview readonly feature, meth_caller() now produces a readonly function value because it captures no mutable state. A readonly target method also gives the generated callable a readonly receiver parameter, e.g. (readonly function(readonly C, int): bool). 34d1278fc9

Security

4 changes
  • W10 · Mar 5
    Internal type-constant projections inherited into public classes no longer degrade to any outside their module. They remain opaque and distinct, preventing invalid calls from bypassing the intended module boundary. 05db70051a
  • W10 · Mar 6
    Opaque representations of internal generic classes now preserve their type arguments across module boundaries. Distinct instantiations are no longer treated as compatible outside the defining module. 86f1847927
  • W11 · Mar 15
    The new off-by-default Eval.DisableRequestSuperglobal option prevents $_REQUEST from being created or populated, allowing deployments to avoid the superglobal's merged input surface. d6931f096c
  • W12 · Mar 24
    Hack now rejects meth_caller() for internal methods, even when the callable is created inside the defining module. Such a callable could escape and fail only when invoked outside the module boundary. 134b288fab

Breaking Changes

8 changes
  • W10 · Mar 8
    meth_caller() no longer accepts a class name as a string. Pass a class value such as C::class; stringly typed call sites should use dynamic_meth_caller() instead. 159e7c7744
  • W10 · Mar 9
    $this is now rejected as a parameter name, including in the unparenthesized callable syntax that previously escaped the check. 40495455d1
  • W11 · Mar 15
    The implicit class constant is now case-sensitive: only C::class, not spellings such as C::CLASS, receives the special class-name behavior. 07f75c18d1
  • W11 · Mar 15
    The runtime surface of meth_caller() now takes a classname value directly, completing the move away from class-name strings. Use C::class for statically known classes and dynamic_meth_caller() for dynamic strings. 16424edb7c
  • W12 · Mar 20
    Module existence checks now consistently use the pure HH\module_exists(string, bool = true)[]: bool API. The previous global module_exists() runtime spelling has been removed. f397bd3c97
  • W12 · Mar 22
    Hack source text must now be valid UTF-8. The compatibility configuration for non-strict source decoding has been removed. e768c25fcf
  • W13 · Mar 28
    Function names are now case-sensitive at runtime. Legacy mixed-case lookup, its compatibility configuration, and associated logging have been removed; call functions using their declared spelling. 39619a7250
  • W13 · Mar 29
    HackC now also compares function names with exact case, completing the case-sensitive function-name migration for compiled code. 351dd87969
