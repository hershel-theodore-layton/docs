April 2024

48 noteworthy changes, organized by the source changelog sections.

Highlights

26 changes
  • W14 · Apr 1
    Hack now permits global function declarations whose names differ only by case, matching the language's case-sensitive function lookup. Exact duplicate declarations remain invalid. bf677366a7
  • W14 · Apr 4
    HH\Facts\files_with_attribute_and_any_value() now uses the in-memory symbol map by default again, avoiding stale or incorrect DB-only results while files are changing. Deployments that need the old strategy can set Autoload.DB.UseSymbolMapForGetFilesWithAttributeAndAnyVal to false. 70bd28a835
  • W14 · Apr 5
    Lambda arity mismatches now produce TAST holes around the incompatible function value or lambda. Tools that consume typed ASTs can use the expected and actual function types to offer more precise migrations. 7eccda3526
  • W14 · Apr 5
    HH\get_executable_lines() no longer reports generated functions or abstract methods as executable. Coverage and debugger clients will no longer see interface methods or class-closing braces as spurious executable lines. 17236d2daf
  • W14 · Apr 5
    Constraint solving now retains the errors from all branches of a disjunction, improving explanations when no branch is valid—particularly for failures involving type-parameter constraints. 85d958bb73
  • W15 · Apr 8
    debugger_dump(null) is now a no-op instead of printing null. This also keeps null-valued notebook and debugger evaluations from producing a redundant display value. ced9997e21
  • W15 · Apr 8
    HHVM now agrees with the typechecker when a variadic method implements a variadic abstract method while declaring additional compatible non-variadic parameters. These implementations no longer fail at class loading. 743fc08410
  • W15 · Apr 8
    Repo-authoritative builds now stop on directory-open or file-stat errors instead of silently omitting affected Hack files from the compiled repository. 915842a0ce
  • W15 · Apr 9
    Str\replace_every_nonrecursive() is now declared with the empty capability list []. Its previous omitted list meant [defaults]; narrowing the callee requirement to [] is non-breaking and lets callers with any capability superset—including pure callers—use it. 62965cc890
  • W15 · Apr 10
    The typechecker now uses obvious argument types—such as locals and simple literals—to infer the parameter types of an immediately invoked lambda. This accepts more concise calls without requiring redundant lambda annotations. 725364297d
  • W15 · Apr 10
    nameof is now supported as an attribute argument by both the typechecker and runtime, completing the parser-side work from April 2. 5db8d278e2
  • W15 · Apr 11
    Repo-authoritative optimization no longer loops forever when a subclass-analysis split contains exactly 25,000 classes. 8c73cc33e2
  • W16 · Apr 16
    hackfmt now builds its line table tail-recursively, avoiding a stack overflow on unusually large source files. 88edd0b8ac
  • W16 · Apr 16
    hackfmt now keeps an empty module definition on one line as new module foo {}, matching other empty braced declarations. 0fff1574c6
  • W16 · Apr 19
    IDE rename now handles the $ prefix correctly for both static properties and the differing declaration/use spellings of instance properties. fb8c9ac5b1
  • W16 · Apr 19
    Repo-authoritative compilation accepts --vActiveDeployment=..., allowing a build invocation to set or override the active package deployment without editing build_config.hdf. 1dcd3f2216
  • W16 · Apr 20
    The SQLite3 extension now uses SQLite's 64-bit integer APIs consistently for returned values, bound parameters, and user-defined function results. Values outside the signed 32-bit range are no longer truncated on those paths. c9c52eab33
  • W17 · Apr 22
    hh --lint path/to/directory now reports that lint accepts files rather than crashing. Directory walking is still unsupported. 3d67603997
  • W17 · Apr 22
    ThriftAttributeSerializer now serializes a Thrift SET from the Hack array's keys rather than its values, fixing sets whose backing representation stores the member in the key. 366ea31781
  • W17 · Apr 23
    round() now handles precision values outside the meaningful range for a double directly: extremely high precision returns the input unchanged, while sufficiently low precision returns zero, avoiding invalid intermediate calculations. a6c87cb4c8
  • W17 · Apr 24
    TAST holes produced for invalid array access now retain the original outer type of a nullable or mixed base instead of incorrectly reporting its non-null inner type. Typed-AST consumers and codemods will see accurate actual types. be9a7af8b3
  • W17 · Apr 25
    Repo-authoritative optimization now models the concrete values written to memoization caches, avoiding incorrect bottom or return types for forwarded late-static-binding calls such as memoized methods inherited from traits. 9056a5bf64
  • W17 · Apr 25
    Top-level autocomplete backed by Glean now matches a declaration's autocomplete sort text as well as its name, allowing appropriately ranked declarations to appear for additional prefixes. 891e663ebc
  • W17 · Apr 26
    JSON diagnostics now include a top-level severity field. Consumers of hh --json can distinguish errors from the new warning severity without parsing rendered text. e19bd61dd0
  • W17 · Apr 26
    While VS Code debugging is paused, newly started request threads are no longer announced until execution resumes, keeping the stopped thread from being displaced in the debugger UI. e2849902e6
  • W17 · Apr 26
    The “override method” code action now inserts a multiline method body and places the cursor inside it, ready for implementation. 4f550b7331 2298871f36

Future Changes

15 changes
  • W14 · Apr 2
    The runtime parser now accepts nameof expressions as attribute arguments. This is only the runtime half of the change; typed Hack projects will continue to see a typechecker error until the matching support lands on April 10. 80415702c0
  • W14 · Apr 3
    HackC's expression-tree debug output now gives generated temporaries valid Hack variable names, so the lowered output can be passed through hackfmt. Expression trees remain experimental. adacdb6ddf
  • W14 · Apr 5
    Expression-tree collection literals moved from Preview to OngoingRelease as part of their staged rollout. Expression trees themselves remain experimental. eda3f8b79c
  • W15 · Apr 11
    JSON rendering of pre-stable function types, including hh --type-at-pos-batch, now preserves whether a parameter is optional. Consumers can distinguish (function(int, optional bool): int) from a function whose second parameter is required. 8fb398ec31
  • W15 · Apr 11
    Expression-tree lowering now passes XHP element names to visitXhp() using nameof, producing strings instead of the class-pointer values previously emitted with ::class. This affects experimental expression-tree DSLs that inspect those visitor arguments. 0f8bb1e8f8
  • W15 · Apr 11
    A disabled-by-default class_pointer_levels migration setting can lint or reject a direct C::class argument where a string parameter would trigger an implicit conversion, and offers nameof C as the fix. The first implementation is deliberately syntactic and does not follow the value through a local variable; it is groundwork for the future class<C> type. ffb5154a11
  • W16 · Apr 16
    Repo-authoritative optimization no longer asserts when a case-type union contains an unresolved member. The whole union is conservatively left unresolved, matching non-repo HHVM behavior; case types remain a staged feature. e01cd5e15a
  • W16 · Apr 17
    The typechecker gained internal flow-based provenance nodes for explaining how types move through variance and type constructors, together with a disabled-by-default extended-reasons option. This is groundwork only: the new reasons are not yet surfaced in ordinary project diagnostics. abd7cada5a 11e09fdacf
  • W16 · Apr 18
    Experimental expression-tree splices are now typechecked in the same lowered lambda shape used by code generation. An as refinement performed inside a splice no longer survives after the enclosing expression tree, and values used by splices are treated as captured variables and may be pessimised. de35277bac
  • W17 · Apr 23
    Collection literals inside opted-in expression trees no longer require the separate expression_tree_map unstable-feature attribute. The enclosing expression-tree feature remains staged. c13997fb6d
  • W17 · Apr 24
    The unstable expression_tree_nest feature allows an expression tree inside a splice. A nested tree inherits the enclosing DSL and therefore omits its own DSL prefix, except across an ordinary Hack lambda scope; nested trees cannot yet capture client variables from enclosing scopes. 8fd5211674
  • W17 · Apr 25
    A disabled-by-default hack_warnings project option introduces non-fatal Hack warnings. The first warns when ?X and ?Y are compared even though the non-null primitive types X and Y are disjoint. a5295f752a f5f47a9cc6
  • W17 · Apr 25
    Repo-authoritative optimization now handles enum members and unresolved object members in experimental case-type unions without misclassifying or asserting on the union. ba2eace20a
  • W17 · Apr 26
    When the opt-in Hack warning system is enabled, LSP diagnostics now reach editors with warning severity and are rendered as warnings rather than errors. 43370c7b5f
  • W18 · Apr 30
    A disabled-by-default strict_switch project option has been added as rollout plumbing for enabling strict switch checking globally. This commit only introduces and loads the option; it does not yet connect the setting to the strict-switch checker. b3f0c2a764

Breaking Changes

7 changes
  • W14 · Apr 4
    Variadic parameters must now have a capture variable. Replace bare ... in functions, methods, and lambdas with a named parameter such as ...$args; the runtime parser now rejects the unnamed form that the Hack typechecker already rejected in strict code. 64a98f185b
  • W16 · Apr 15
    where clauses may no longer project a type constant through a generic or abstract receiver, such as where U = T::TC. Express the relationship with a refinement such as T as Base with { type TC = U }. Context-polymorphic coeffect projections such as [$a::Ctx] and [T::Ctx] are explicitly exempt and remain supported. e9da5a4c6a
  • W16 · Apr 16
    Inside a module declaration, an imports block must now appear before an exports block. Reorder declarations that currently export first; the restriction prevents range-formatting from losing the original token order. 2f432af79a
  • W16 · Apr 18
    AsyncMysqlErrorResult::mysql_normalize_error() has been removed from the HHI and runtime extension. Migrate callers to the remaining error information, such as mysql_error(), mysql_errno(), or failureType(), as appropriate. 5a9a946d2d
  • W16 · Apr 19
    Accessing a private static member through an object expression, such as $object::method(), is now accepted only from that same class when it is final. Cross-class access that previously slipped through now reports that private members cannot be accessed dynamically; prefer self::method() for same-class calls. c17d4a0221
  • W16 · Apr 19
    DOMDocument::registerNodeClass() class mappings are now case-sensitive. The base-class spelling used during registration must exactly match the class name encountered when DOM objects are created. ecaf3474e9
  • W17 · Apr 25
    Hack's text diagnostic formats now encode severity. In particular, --error-format plain prefixes diagnostics with ERROR: or WARN:, and the raw, contextual, and highlighted renderers distinguish warnings too. Update scripts that parse the previous plain-text layout. 9bbf0bd8bd 4f788c05ab ac2791f216 3059d50fb7
