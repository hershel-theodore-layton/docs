May 2024

42 noteworthy changes, organized by the source changelog sections.

Highlights

23 changes
  • W18 · May 1
    “Add method stub” is now available when the cursor is on whitespace between class-body declarations, and inserts the selected inherited method at that position. 60ebc78364
  • W18 · May 1
    Typechecking cyclic generic upper bounds no longer recurses indefinitely while resolving type-member constraints. bcdba1ecd8
  • W18 · May 3
    Reified generic class values such as T::class no longer trigger the class-pointer migration lint or error; this spelling remains supported while nameof T is intentionally unavailable. e5353501f7
  • W19 · May 6
    HH\Facts\type_to_path_relative(string)[]: ?string now returns a type's path relative to the Facts repository root, avoiding caller-specific stripping of an absolute root. 41f678c119
  • W19 · May 7
    LSP textDocument/documentSymbol responses now include function and method signatures with parameter names, plus detail text for properties, class constants, and type constants. File outlines also include type aliases and global constants. Editors and coding assistants therefore receive a substantially richer structural view of each Hack file. 06ce20461a 31047fbe1b 9c05e9b175
  • W19 · May 9
    Relative-path variants are now available for every Facts symbol-to-path query: modules, types, type aliases, functions, constants, and the combined type-or-alias lookup. The existing absolute-path APIs remain available during migration. 7f90612b91
  • W20 · May 13
    Null checks written as is_null($value) or $value === null now use the same type-switch refinement as $value is null. 8d4f00adda d749ee3e5a
  • W20 · May 14
    Referencing $this inside an enum class now produces a direct parser error. HackC and syntax-only checks no longer panic later in compilation. 4f994c02df
  • W20 · May 14
    Shape-key validation now follows a missing field through further indexing on the left of ??; $shape['missing'][0] ?? null is no longer accepted when missing is absent. da7eb6cb73
  • W20 · May 14
    Under Sound Dynamic, the true branch of a null type test now refines precisely to null instead of the unhelpful ~null. 61db97555f
  • W20 · May 15
    The built-in constants TRUE, true, FALSE, false, NULL, and null are now declared in HHI files, so attempts to redefine them receive a naming error instead of surviving until HHVM's runtime fatal. 47c1ae0958
  • W20 · May 17
    Hack now reports top-level break or continue inside a finally block during typechecking, matching the fatal that HackC already emitted. cba8993c7c
  • W21 · May 20
    Class-pointer migration diagnostics now cover returning C::class from a string function and assigning it to a string property. Use a class-name type or convert explicitly with HH\class_to_classname(). a910b45d23
  • W21 · May 21
    Shapes::keyExists() and its negation now refine required, optional, and open shape fields more completely. The false branch knows an optional field is absent, and Hack reports accesses to that known-missing key. 2a66cd61b3 b37f5e1465
  • W21 · May 21
    Class-pointer migration diagnostics now also catch string concatenation with C::class; convert explicitly when a textual class name is required. e1f6f11a26
  • W21 · May 23
    The VS Code debugger now displays string variables and string constants in single quotes, making them visually distinct from names and non-string scalar values. d60b329ad4
  • W21 · May 24
    The hack_warnings configuration now accepts true/all, false/none, or a comma-separated allowlist of warning codes such as 12005,12006. Projects can enable a targeted warning migration without taking every warning at once. dbacc3fc0c
  • W22 · May 27
    IDE override navigation and hierarchy data now recognize methods inherited from traits as overridden methods, matching the typechecker's <<__Override>> behavior. d993b38446
  • W22 · May 28
    A new lint warns when code catches a broad exception and neither rethrows nor meaningfully uses the exception object, helping surface silently swallowed failures. Additional type-lie checks for HH_FIXME, UNSAFE_CAST, assertions, and explicit dynamic were added at disabled severity for later rollout. 0184f96d16 22b0ea2599
  • W22 · May 30
    extended_reasons=true is now available through .hhconfig and --config for hh and distributed typechecking. The diagnostic pipeline can retain contextual provenance through refinements and supportdyn, and shows the full file position for each context snippet. eb17a6a07a 297bdba569 5c7385ac80 3985711d5c
  • W22 · May 30
    hh --preexisting-warnings now includes warnings already present in the loaded saved-state baseline; without the flag, those baseline warnings remain filtered out. fb0ccfbed5
  • W22 · May 31
    Extended-reason debug output now renders a readable type-flow explanation alongside its JSON representation. f9538fd6bb
  • W22 · May 31
    Type-lie lints involving UNSAFE_CAST have been re-enabled at advisory severity rather than as errors, reducing noise while still exposing risky casts to lint consumers. 578070f438

Future Changes

11 changes
  • W18 · May 1
    The experimental strict switch checker is now selected project-wide by the strict_switch configuration. The per-switch <<__StrictSwitch>> attribute and its unstable-feature opt-in no longer select the implementation. e67c9a80f0
  • W19 · May 6
    Strict-switch diagnostics now handle negated type predicates directly. A subject described only as “not primitive” still requires default, but no longer produces a misleading exhaustiveness explanation. b04e4a7bc5
  • W19 · May 9
    Nested expression trees have moved from unstable to preview status. They remain pre-stable and continue to require the expression_tree_nest feature where preview features are not enabled. 0d9f8f88ad
  • W19 · May 11
    In the staged module-level trait work, public module-level traits may declare internal methods without separately enabling module_level_traits_extensions. Internal properties on public traits remain invalid. 2b00d0ec8b
  • W20 · May 16
    Package-v2 groundwork adds the package_v2 option, parsing for path-based include_paths, and an unstable <<file:__PackageOverride(...)>> attribute. The override is syntax-only at this stage; enforcement work follows later. 405a8e27b8 f791873cdd 8bd22d74db
  • W21 · May 22
    When hh_single_type_check receives --packages-config-path, it now treats that configuration file's directory as the project root. Experimental path-based package definitions therefore resolve test files relative to the same location as the package config. 661620fadc
  • W21 · May 23
    Every nested expression tree must now repeat its DSL name, and that name must match the enclosing tree. The earlier shorthand that inherited the outer DSL is rejected. c610bf057f
  • W21 · May 24
    Under implicit pessimisation, is this and as this now refine to ~this where an exact this result would be unsound. 2e1a710c6b
  • W21 · May 24
    Enum refinements nested inside nullable and tuple-like types now preserve the enum's stringish or intish weakening instead of unsoundly producing an exact enum type. 9235b6c767
  • W22 · May 28
    With experimental package_v2 enabled, the typechecker now maps files to the most specific matching include_paths entry and enforces path-based package access for public symbols. Internal-symbol enforcement and __PackageOverride support are not included yet. 6cfa1c710a e837faa0c8
  • W22 · May 28
    The experimental sealed_methods feature allows <<__Sealed(C1::class, ...)>> on a method to restrict which classes may override it. Functions cannot use the attribute. 7e28a90a65

Breaking Changes

8 changes
  • W19 · May 11
    HH\ImplicitContext\soft_run_with() and soft_run_with_async() no longer create a soft implicit-context state from their $key; they now invoke the callback without changing context. Code that depended on the key creating separate memoization context should migrate to an explicit implicit-context API. 9461b78f48
  • W20 · May 15
    __clone() must declare a void return type. Returned values were always discarded; implementations that returned this or another value must remove the return value and keep mutation in the method body. 50376266b5
  • W20 · May 16
    hh_single_type_check now enables everything_sdt by default and has removed the --everything-sdt flag. Tests that need the legacy mode should pass --config everything_sdt=false. 50f7db53c0
  • W20 · May 16
    Comparison typechecking now constrains both operands even when one begins as an unresolved type variable. Unconstrained generic or nullable comparisons that could resolve outside int, string, DateTime, or DateTimeImmutable may now report errors. d45b3df95f
  • W20 · May 17
    The erased UNSAFE_CAST pseudo-function may no longer be captured as a first-class function pointer with UNSAFE_CAST<>. Direct HH\FIXME\UNSAFE_CAST(...) migration calls remain available. 080efb3351
  • W20 · May 18
    Trait names are no longer considered runtime-enforceable types. They cannot be supplied to an <<__Enforceable>> reified parameter or used as the target of is and as; use an interface or concrete class for runtime checks. 9001bd2d40
  • W21 · May 20
    Namespace names in use declarations may no longer contain :. XHP-style names are not valid namespaces and now produce a parser error. 092c46226a
  • W21 · May 23
    Namespace names and aliases in use declarations may no longer contain XHP-style : or - characters. This completes the namespace validation introduced on May 20. 15efb0012e
