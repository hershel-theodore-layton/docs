July 2024

41 noteworthy changes, organized by the source changelog sections.

Highlights

18 changes
  • W27 · Jul 1
    HH\FileDecls::getShapeKeys() now returns the keys of a shape type alias without recursively expanding nested aliases. Class-constant keys retain their Class::CONSTANT spelling. The pure [] API is useful to source-analysis tools that need the declaration's written shape rather than a normalized type. b48159fb69
  • W27 · Jul 3
    Autocomplete now correctly applies where constraints when a function type's return type has been pessimised to a like type. This restores valid suggestions whose availability depends on the callback return type. 3ba7478771
  • W27 · Jul 4
    Type errors now retain explanations from every disjunct considered while checking generic upper and lower bounds, making failures involving constrained generics less likely to lose the useful branch. Traversability errors also point at the subtype that failed the check rather than the expected supertype. bfea95c5c1 402a8d51e4 6edbff137a
  • W28 · Jul 8
    Samples returned by HH\xenon_get_data() may now include optional PageletWorkers, XboxWorkers, HttpWorkers, and CliWorkers fields in HH\XenonSample. Consumers should continue treating these worker-category counts as optional. a5a47241f9
  • W28 · Jul 10
    Vec\intersect() now materializes a forward-only first Traversable before processing it. Passing a Generator as the first argument no longer attempts to rewind it and throw. The function remains pure ([]). ed1ef19ce5
  • W28 · Jul 10
    The Dict\from_keys() documentation now links to the actual asynchronous counterpart, Dict\from_keys_async(). 3c80238bdc
  • W29 · Jul 15
    Calls with explicit or empty type arguments now associate correctly inside subtraction expressions. For example, 10 - f<int>(1) - 1 is evaluated left-to-right instead of being misparsed into an expression that evaluates to 10. 7d30230a5b
  • W29 · Jul 16
    A method may use <<__Overlapping('T1', 'T2', ...)>> to tell the disjointness lint which class- and method-level generic parameters are intended to overlap. This lets the lint identify calls whose instantiated types make comparisons or membership checks constant without adding API-shaping where constraints. c94a1e968d
  • W29 · Jul 16
    Source-analysis tools can query a file's declared module through the pure HH\FileDecls::getFileModuleMembership() and HH\Facts\path_to_module_membership() APIs when module-membership facts are collected and available. The latter accepts a source path and returns the module name, if any. ad00e88510
  • W29 · Jul 17
    Standard collection declarations now annotate contains(), containsKey(), and linearSearch() with __Overlapping. hh --lint can consequently report calls whose inferred argument and element/key types are disjoint and whose result is always the same. ac1433f124
  • W29 · Jul 17
    Find-references output from the default parser now uses source XHP spelling such as :xhp:foo-element instead of the internal mangled spelling xhp\foo-element. c6db057c8e
  • W29 · Jul 19
    hackfmt --linttool now emits JSON lint replacements for files named on the command line or supplied through an @pathsfile. --linttool-severity controls the emitted severity. 54fd999ce3 8fdcb93335
  • W30 · Jul 24
    When hh is invoked with --from, an explicit --error-format now takes precedence instead of being silently replaced with plain output. 392e317d12
  • W30 · Jul 26
    HHVM now registers ARM JIT trap fixups correctly, preventing trap metadata from taking precedence over the intended fixup and breaking stack unwinding. dec8107878
  • W30 · Jul 26
    HSL sorting documentation now states the comparator contract consistently: return a negative value, zero, or a positive value when the first argument sorts before, equal to, or after the second, respectively, as with <=>. b3a1874c44
  • W31 · Jul 29
    When the VS Code debugger is attached to a server, only explicit evaluation output is now sent to the debugger's stdout stream. This avoids unrelated request output flooding the debug console and makes evaluation output consistent. 723c132357 783f6ccf7a
  • W31 · Jul 31
    HackToThrift symbol indexing now includes enum declarations and their enumerators in generated facts and cross-references. ed5d8b036e
  • W31 · Jul 31
    Sound-dynamic inference now partially solves type-variable lower bounds while removing dynamic components. This recognizes like types hidden behind variables and accepts more valid relationships of the form C<~T> <: ~C<T>. bce6c1e3a6

Future Changes

15 changes
  • W27 · Jul 2
    Package v2 no longer reports package-access errors for types used only in erased generic arguments or generic parameter constraints, including constructor and function calls. Reified generic arguments remain runtime-visible and are still subject to package checks. aa82f3b408
  • W27 · Jul 4
    The opt-in extended type-error explanations now simplify paths through type structure, correctly describe missing shape fields and pessimised returns, and suppress unhelpful implicit supportdyn details. 7a802e4b40 c15dfa75a1 8512b74515
  • W27 · Jul 5
    Identify-symbol and go-to-definition now resolve enum-class labels through dependent, nullable, and pre-stable case types. 929a95c5b8
  • W28 · Jul 9
    The opt-in warning formerly reported as code 12002 is now divided into 12009 (is always true), 12010 (is always false), 12011 (as always succeeds), and 12012 (as always fails). Projects that enable these warnings should update warning-code suppressions and tooling. d6e5153e6c
  • W28 · Jul 11
    .hhconfig gained an enable_experimental_stx_features JSON map as the new configuration path for experimental syntax-tree features. At this stage, configured statuses must agree with the compiler's hardcoded feature statuses; the option is rollout plumbing rather than a way to enable arbitrary syntax. 25411fc714
  • W29 · Jul 15
    Package v2 now enforces package access for reified generic arguments to functions and classes. Erased generic arguments remain exempt because their types do not survive at runtime. 92ed59910e
  • W29 · Jul 17
    Opt-in extended type-error explanations can now describe nullable-type decomposition and point to the declarations of classes, type aliases, and newtypes involved in an error. b4eefe87a3 bad36007e0
  • W29 · Jul 18
    With .hhconfig option enable_abstract_method_optional_parameters=true, interface and abstract-method declarations may mark a parameter optional without supplying a default. Implementations must provide a default value; optional is rejected on concrete methods and on inout or variadic parameters. Reflection reports these parameters as optional. 64be82990a
  • W29 · Jul 18
    Runtime optimization of experimental case types no longer crashes when resolving an alias that combines an enum with another member type. 9971c4deb3
  • W29 · Jul 19
    Package v2 no longer reports package-access errors for type references nested inside shapes, vec, dict, or function types, nor for attributes, interfaces, HHIs, and same-file references that do not require a runtime package check. 319dcfe9a3 5011d0f10d
  • W29 · Jul 19
    The configuration switch for experimental class-level where clauses has been removed. The syntax itself is removed a few days later; projects experimenting with it should migrate toward type refinements. 361365bd93
  • W30 · Jul 22
    Experimental class-level where clauses have been removed from the language. They were never enabled as a supported feature; use type refinements for constraints on associated types. 46632da404
  • W30 · Jul 24
    The disabled-by-default .hhconfig option type_refinement_partition_shapes=true enables constraint-based is refinements for closed shapes with required fields. Open shapes and shapes with optional fields are not yet handled by this path. e99ed3d046
  • W31 · Jul 29
    An experimental set_oom_multiplier(int): bool API lets a critical request raise its out-of-memory termination threshold by a multiplier of at most 100. The implementation notes that future cost attribution work is still required, so this is not yet a general-purpose memory-management API. 8ec4a3eead
  • W31 · Jul 29
    Experimental case-type expansion now preserves the typing environment while simplifying members, avoiding dangling type variables and parameters in later checks. 19275f0ab4

Breaking Changes

8 changes
  • W27 · Jul 3
    Enum-class labels may no longer refer to type constants. Expressions such as E#T or #T now produce a type error when T is a type constant rather than an enum-class member. 3c9a2a4a23
  • W27 · Jul 3
    HH\ImplicitContext gained an abstract boolean constant named IS_MEMO_SENSITIVE. Subclasses must choose true for memo-sensitive contexts or false for memo-agnostic contexts. This systemlib change precedes the matching HHI declaration added later in the month. 9fbef64f53
  • W27 · Jul 5
    HH\FileDecls now preserves the exact source spelling of string values, including quote style and escapes, instead of normalizing them to single-quoted strings. Source-analysis tools that compare or parse the former normalized output need to accept raw snippets. a3e0167a71
  • W28 · Jul 12
    HH\ImplicitContext gained an abstract context constant, CRun. Its base runWith(), runWithAsync(), get(), and exists() methods now require [this::CRun] instead of a fixed [zoned] capability, and subclasses must choose a concrete requirement such as const ctx CRun = [zoned]. This annotation does not grant the listed capability: it is a requirement on the callee, so a caller must have a capability set that contains the subclass's chosen CRun. Both runWith() and runWithAsync() additionally require the callback's context through ctx $f. Choosing a narrower CRun relaxes the requirement on callers. The matching HHI declaration follows later in the month. d36ec6e832
  • W30 · Jul 22
    ConstIndexAccess and IndexAccess now constrain their key type parameter with as arraykey; collection contains() and containsKey() declarations received the same constraint. Custom implementations and calls that explicitly supplied an unconstrained, non-arraykey type argument may now fail type checking. 716478479e
  • W30 · Jul 24
    The HHI for HH\ImplicitContext now exposes the abstract IS_MEMO_SENSITIVE boolean and CRun context constant introduced in systemlib earlier this month, so typed subclasses must define both. Calls to runWith(), runWithAsync(), get(), and exists() must provide a capability set that is a superset of the subclass's selected CRun; [this::CRun] states a callee requirement and does not grant that capability to the caller. Both runWith() and runWithAsync() additionally carry the callback's contextual requirement through ctx $f. 0746e19f3f
  • W30 · Jul 24
    The hh --xhp-autocomplete-snippet command-line option has been removed. ac67a519c5
  • W31 · Jul 29
    The disallow_direct_superglobals_refs configuration option has been removed. Direct references to superglobals such as $_GET and $_SERVER remain parse errors; use HH\global_get() and HH\global_set() instead. 351be32993
