21 noteworthy changes, organized by the source changelog sections.

Highlights

13 changes
  • W49 · Dec 2
    Extended Hack diagnostics can now render source context for positions inside HHI files instead of falling back to “No source found.” This makes errors that point into built-in declarations substantially easier to interpret. ddb28b2550
  • W49 · Dec 6
    HH\get_class_from_object(readonly object)[]: class<mixed> returns an object's class pointer, while HH\get_parent_class_from_class(readonly class<mixed>)[]: ?class<mixed> returns its parent or null. Both APIs have an explicit empty capability list [], so callers need no ambient capabilities. c4650b12f7
  • W49 · Dec 6
    Diagnostics involving implicitly pessimised properties and returns now explain why the like type was introduced—for example, an unenforced generic argument, type constant, function type, or call on a dynamic value. 0d45f2066c
  • W50 · Dec 9
    With error streaming enabled, hh --error-format raw once again prints No errors! when the check succeeds. 2cb35690cd
  • W50 · Dec 9
    Sound-dynamic error reasons now retain the provenance of a like type as it passes through a function that supports dynamic calling. d7ae8d1528
  • W50 · Dec 11
    A top-level generic function pointer now retains a universally quantified function type. A reference such as identity<> can therefore instantiate independently as (function(int): int) and (function(string): string) at different uses, while respecting its generic bounds and where-constraints. 98103efcd3
  • W50 · Dec 12
    Initial warning suppression is now applied before errors are streamed, preventing baseline warnings from being sent to the client before the end-of-check filter can remove them. e93229f61e
  • W50 · Dec 12
    HH\TypeStructureKind now exposes OF_CLASS_PTR and OF_CLASS_OR_CLASSNAME, matching the kind values returned by type_structure() and ReflectionTypeConstant::getTypeStructure() for class<T> and transitional class-or-classname types. 14a113c6d0
  • W50 · Dec 13
    The Hack manual now documents class<C> as the type for class references used in construction and static member access, and distinguishes it from the string-compatible classname<C> type. 006861e2fa
  • W51 · Dec 17
    Hack now discards every warning from the initial typecheck when the merge base has no matching saved state, rather than doing so only on a clean public revision. This favors hiding a stale warning over showing one unrelated to the user's changes. b3432de375
  • W52 · Dec 23
    The built-in declarations now include thrift_protocol_write_compact_struct() and thrift_protocol_write_binary_struct(). Their signatures omit a capability list, so callers require [defaults]. 4690549348
  • W01 · Dec 30
    HH\XReqSync provides named, cross-request asynchronous locks in non-authoritative mode. get() obtains a named lock object, genLock() waits with an optional millisecond timeout and resolves to whether the lock was acquired, and unlock() releases it; destruction also releases a held lock. All three public methods explicitly declare [], so callers need no ambient capabilities. 9220fd6076
  • W01 · Dec 30
    Sound-dynamic diagnostics now retain like-type provenance when a dynamic or like-typed value is used as the receiver of a method call. ed7dbea12d

Future Changes

7 changes
  • W49 · Dec 6
    The unstable expression-tree implementation now preserves the enclosing async state through generated and explicit client lambdas, so await inside nested splices is lowered correctly. Unsupported yield expressions also receive a direct diagnostic. fa0ef516d2 033b634564
  • W50 · Dec 9
    Pre-stable function references are now enabled by default. A pointer such as foo<> is typed as HH\FunctionRef<(readonly function(...): ...)> rather than only as its underlying function type; the wrapped signature retains the function's declared capability list. Projects can temporarily restore the previous typing with enable_function_references=false. 76890b5a62
  • W50 · Dec 9
    The staged package-v2 checker accepts package_v2_exclude_patterns as a comma-separated list of path regexes. Matching source or target files are exempt from package-boundary checks; the initial default excludes .*/__tests__/.*. bf5b18d2dc
  • W50 · Dec 9
    Package-v2 boundary errors now point separately to the illegal reference, each file's package membership source, and the relevant PACKAGES.toml relationship. d5bbd48c44
  • W51 · Dec 16
    Package-v2 runtime metadata now stores input_paths relative to Server.SourceRoot and matches those relative paths when selecting an active deployment. This fixes deployment filtering when a repository is built under a different absolute root, such as a remote-execution worker. 1bda185dc6
  • W51 · Dec 18
    The configurable class-pointer migration check now follows values already typed as class<T> into dict, keyset, indexed-access, and collection-key positions. Setting the arraykey entry in class_pointer_levels to 3 emits warning 12013; level 4 makes it an error. Convert deliberately with HH\class_to_classname() when a string key is intended. 36e5e97a95
  • W51 · Dec 20
    The unstable require_constraint feature adds require this as C; to traits. It gives the trait body a this <: C assumption without requiring C to be final, and—unlike require extends C—also permits the using class to be exactly C. Enable it with <<file: __EnableUnstableFeatures('require_constraint')>>. aabd163a85

Breaking Changes

1 change
  • W50 · Dec 9
    class<C> no longer satisfies a generic string or arraykey bound merely through the transitional class<C> <: classname<C> relation. Type hints such as dict<class<C>, V> are rejected at the generic boundary; use classname<C> for string keys, or keep class pointers out of array-key positions. bb07c68abe
