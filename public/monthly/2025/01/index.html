January 2025

32 noteworthy changes, organized by the source changelog sections.

Highlights

18 changes
  • W01 · Jan 2
    The new HH\is_cli_server_mode() builtin reports whether the current request is proxying filesystem and system calls through HHVM's CLI-server protocol. e8893477e1
  • W01 · Jan 3
    The redundant-generics check no longer reports parameters whose replacement would require a non-denotable intersection type, including intersections hidden beneath supportdyn. caec562dfd
  • W02 · Jan 9
    HH\XReqSync now records the next waiter as a mutex's owner before waking it, fixing lock handoff failures when several requests contend for the same mutex. 9e251bb7ae
  • W02 · Jan 10
    "Extract into method" now strips implicit like types throughout generated parameter and return types, avoiding suggestions containing source-level ~T hints that users did not write. ae9f4200f3
  • W03 · Jan 13
    Non-repo-authoritative HHVM gained HH\SimpleLock, a named cross-request mutex API with asynchronous lock(), immediate try_lock(), unlock(), and a timeout helper. Locks abandoned at request shutdown are released automatically. ea44027434
  • W03 · Jan 17
    The new HH\gc_is_conservative() builtin reports whether HHVM's garbage collector is operating without any conservative type scanners. 3f6dfef71e
  • W04 · Jan 20
    Hack's language server now implements the standard $/setTrace notification in addition to VS Code's older $/setTraceNotification, allowing clients to toggle verbose protocol tracing without receiving a method-not-found response. 6ff6878cbd
  • W04 · Jan 20
    The Hack server gained an exhaustive folded-declaration invalidation mode for saved files, favoring correctness when stale folded declarations would otherwise make IDE results disagree with the CLI. 7ef8817196
  • W04 · Jan 21
    Timezone data was updated to the 2025a release, including newly added historical transitions that can change results for old timestamps. e49a2d45dc
  • W04 · Jan 21
    Overrides of ordinary class methods marked <<__NoAutoLikes>> now inherit that behavior automatically, so their return types are not implicitly widened to like types. Interface implementations still need their own annotation. 7a353344ec
  • W04 · Jan 23
    Classes using the same trait through many branches of a trait diamond no longer count duplicate imported methods toward HHVM's 65,535-method limit, avoiding a false "Class has more than 65,535 methods" failure. 2566b4e7d8
  • W04 · Jan 24
    HHVM now reports a clear error when a non-default Eval.PackagesTomlFileName cannot be opened instead of silently continuing with an empty package specification. f9035ba600
  • W04 · Jan 24
    The unsurfaced-exception lint no longer produces false positives for exception variables captured by lambdas during the dynamic TAST pass. 527a1dc8e7
  • W04 · Jan 24
    HH\SimpleLock\is_held() reports whether any request currently holds a named SimpleLock. a2466c5ee3
  • W04 · Jan 24
    The new #ICInaccessibleSpecialCase memoization option allows specialized functions to read implicit context without sharding their memo cache by it. Like #MakeICInaccessible, it is restricted to defaults, leak_safe_shallow, or leak_safe_local contexts. 2e164dc8db
  • W05 · Jan 28
    HHVM now carries complete property type-constraint intersections through runtime enforcement and JIT analysis, so generic upper bounds are considered consistently—including for compound property assignments—instead of consulting only the primary hint. 4e1ae2c191 938742f7ec 0e0fd266cf e95d7acaf4
  • W05 · Jan 29
    Warning filtering works again when error streaming delegates a full check to hh_distc; streamed worker batches are now filtered as they arrive and carry the updated warning saved state through the distributed check. 732a576117
  • W05 · Jan 30
    The VS Code debugger now sets breakpoints on every non-contiguous bytecode block mapped to a source line, fixing missed stops when compiler optimizations duplicate a loop body. Some multiline expressions can consequently produce more than one breakpoint. 2b8ada7314

Breaking Changes

2 changes
  • W02 · Jan 7
    DateTimeZone::listIdentifiers() and DateTimeZone::listAbbreviations() now use the default impure context instead of []. This corrects their dependence on external timezone data, but means they can no longer be called from a pure context. f073bea3f4
  • W05 · Jan 31
    The report_pos_from_reason typechecker option has been removed. Diagnostics no longer append [FROM REASON INFO], and positions derived from type reasons no longer receive special treatment that prevented HH_FIXME or HH_IGNORE_ERROR suppression. 485b19043a

Future Changes

11 changes
  • W02 · Jan 9
    Experimental recursive case types can now satisfy recursively structured as bounds such as shape(?'a' => nonnull) without the cycle detector prematurely replacing the type with mixed. 72b236ce34
  • W03 · Jan 13
    Packages v2 now requires every package's includes and soft_includes sets to contain their full transitive closure, and reports all missing nested packages in one configuration error. 1f4c78a1a3
  • W03 · Jan 16
    Open tuple hints with optional, variadic, or splat elements are now rejected in is and as expressions because HHVM does not yet support enforcing those runtime checks. 591fe0ae72
  • W03 · Jan 17
    Runtime type structures for open tuples now preserve required elements in elem_types, optional elements in optional_elem_types, and a variadic tail in variadic_type. Absent optional or variadic parts omit their corresponding fields. 4c9affb24d
  • W03 · Jan 17
    A type used after the experimental splat operator must now be known to be a tuple—typically through a bound such as T as (mixed...). Unconstrained generics used in tuple or function-type splats now produce a constraint error. 700abe325e
  • W03 · Jan 17
    Recursive case-type runtime handling now preserves generic arguments, resolves cycles involving aliases more reliably, and refuses recursive is/as enforcement that could recurse without bound. 0d7f21793a
  • W04 · Jan 21
    Expression-tree lambdas now reject a bare nested splice such as ${$x ==> ${$x}}; splicing is only valid while the parser is directly inside an expression-tree literal. d796173ae4
  • W04 · Jan 23
    JSON-encoded type information for open tuples now carries optional_args, variadic_arg, or splat_arg instead of collapsing every open tail into fields_known: false. This improves structured type-error and IDE consumers. ade6c78117
  • W05 · Jan 28
    Trait require class and experimental require this as declarations now share one constraint representation. Checks that previously considered only require class now also honor require this as, including inherited constraint handling. 0a38aa99be
  • W05 · Jan 30
    Expression trees gained Preview support for shape literals and shape-typed parameters behind expression_tree_shape_creation. DSLs can virtualize shape construction with proper required, optional, open-field, and nested-shape checking, but shape reads and writes are not included yet. 0783044e49 5f4cd41fcf
  • W05 · Jan 30
    Hack's TypeStructure<T> shape now exposes optional optional_elem_types and variadic_type fields for tuple types, matching the runtime representation added earlier in the month. 84b51c4165

Security

1 change
  • W02 · Jan 10
    Async MySQL certificate callbacks now hold a weak reference to their operation and fail safely if a cancelled or timed-out connection has already released it, preventing a use-after-free during certificate validation. 693eb7f80e
