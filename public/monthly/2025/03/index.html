Highlights

15 changes
  • W10 · Mar 3
    Type printers now collapse nested nullable wrappers, so TAST and diagnostic-oriented tooling displays types such as ~?int instead of the invalid-looking ~??int. 6acb549bd8
  • W10 · Mar 7
    Truthiness analysis no longer strips the like-type wrapper from ~null. This avoids false-positive “always truthy” warnings for nullable values commonly produced by operations such as idx() on dynamic data. a59544983a
  • W10 · Mar 7
    The bundled classname<T> documentation and IDE hover text now describe class-name strings using the nameof C spelling. 0a174765d9
  • W11 · Mar 11
    The missing-method-visibility diagnostic now lists internal as a valid choice and offers a quick-fix that inserts it. c2ab98a8ad
  • W11 · Mar 12
    Intersections of covariant class-name strings now simplify from classname<U> & classname<V> to classname<U & V>, improving narrowing after equality tests. b430a5cf86
  • W11 · Mar 14
    After a file is saved, the language server may now replace its standalone diagnostics with fresher hh_server diagnostics even while the file remains open. Server diagnostics are still ignored while the editor buffer has unsaved changes. 1858e721fb
  • W11 · Mar 14
    HH\Lib\Regex\Pattern<T> now exposes its as string bound in the bundled HHI, matching the typechecker's underlying declaration and allowing APIs constrained to string to recognize a pattern value. e718944d9c
  • W12 · Mar 18
    Async functions and methods may use <<__AsioLowPri>> to suspend eager execution immediately into a low-priority awaitable. Runtime option Eval.EnableLowPriorityAwaitables defaults to true; disabling it leaves the emitted bytecode in place but makes the initial suspension a no-op. 08153b56f7
  • W12 · Mar 19
    Low-priority async wait handles no longer crash when scheduler cleanup examines a ready handle that does not yet have a child. 046529dc2e
  • W12 · Mar 20
    IDE and CLI file-change handling now invalidates folded declarations through the in-memory dependency graph, including descendants reached through inheritance edges. This precise behavior is always enabled, reducing stale errors after editing a parent class without invalidating every folded declaration. 53cb992bd3
  • W12 · Mar 20
    HH\asio_get_current_context_depth(): int returns the current scheduler-context nesting depth, or zero outside a scheduler context, and supersedes HH\asio_get_current_context_idx(). The declaration has no explicit context list, so it uses the default context rather than []. d3b7081039
  • W13 · Mar 27
    Errors for abstract type constants now suggest the corresponding this::TConst form when that is likely what the author intended. 9033b41694
  • W13 · Mar 28
    HH\mangle_unit_sha1(string $sha1 = '', string $ext = '.php', ?string $repo = null): string and the convenience wrapper HH\unit_schema(?string $repo = null): string are now available to Hack. Both declarations omit an explicit context list and therefore use the default context. 2bb86e7bf2
  • W13 · Mar 29
    Switch cases whose values are disjoint from the scrutinee now produce warning 12007 explaining that the case can never match. This check is part of ordinary typechecking and is not limited to the staged exhaustivity checker. 8ccb15e063
  • W14 · Mar 31
    A missing or unreadable PACKAGES.toml, including exceptions raised while opening it, now logs a warning and falls back to an empty package specification instead of terminating ungracefully. Parse errors in a file that was successfully opened remain fatal configuration errors. 01d32e26ad

Security

1 change
  • W10 · Mar 3
    gmp_pow() now rejects exponents greater than UINT32_MAX, raises a warning, and returns false. This prevents unbounded allocations inside GMP that are not charged to HHVM's request heap. 94defb1921

Breaking Changes

8 changes
  • W10 · Mar 3
    Transparent type aliases may no longer put constraints on their type parameters. A declaration such as type T<X as Foo> = ... is now a parse error; use newtype when the constraint is part of the abstraction, or remove the constraint. fb39956d48
  • W11 · Mar 11
    Runtime-enforceable hint validation now resets its “inside reified argument” state between sibling generic arguments. Invalid is hints containing erased arguments after a reified argument are no longer accidentally accepted. 28716a94fb
  • W11 · Mar 12
    Improved IDE hover output is now unconditional, and the improved_hover configuration option has been removed. Hover for a referenced function reports its declaration-shaped signature rather than only its result type. e55c1b27ad
  • W12 · Mar 18
    The second argument of callbacks registered through ResumableWaitHandle::setOnCreateCallback() is now ?WaitableWaitHandle<mixed>, because a newly created low-priority async wait handle has no child yet. Existing callbacks that require a non-null second argument must accept and handle null. The HHI method and callback types have no explicit context lists, so they retain the usual default context rather than declaring []. 08153b56f7
  • W12 · Mar 19
    Non-null refinement now intersects a type with nonnull instead of rewriting the concrete bounds of abstract types. This closes an unsoundness affecting nullsafe calls, shape access, truthiness checks, and related refinements; code that previously smuggled nullable or mixed members into a non-null return type may now fail typechecking. f4b5b94a09
  • W13 · Mar 27
    The .hhconfig options strict_wellformedness and enable_strict_const_semantics have been removed after their strongest levels were fully rolled out. Well-formedness checks on requirements and type localization, and strict inherited type-constant semantics, are now unconditional. 0ae558f29a 2deb722ba4
  • W13 · Mar 29
    The legacy typed switch linter has been removed. Its impossible-case check is now warning 12007, while replacement exhaustivity behavior is provided by the staged checker described below. Tooling that depended on lint codes 5607, 5614, or 5640 should migrate to the new warning and typechecker diagnostics rather than expecting a one-to-one lint-code replacement. 7585768d07
  • W14 · Mar 31
    The HHVM repository compiler has removed --repo-options-dir. It now reads .hhvmconfig.hdf and PACKAGES.toml relative to --input-dir, so build scripts that kept source input and repository options in different roots must align or stage those files first. cbff84ff23

Future Changes

19 changes
  • W10 · Mar 3
    With .hhconfig option safe_abstract=true, accessing an abstract class constant through a receiver that may denote an abstract class now produces warning 12018. Concrete constants remain safe. 280387469b
  • W10 · Mar 7
    Experimental nested expression-tree bindings are now typechecked across splices: a nested expression tree may capture locals from the enclosing splice, and those captured types are tracked through control-flow joins. This requires the staged expression_tree_nested_bindings feature. b1fb7f1d52
  • W10 · Mar 7
    IDE hover for the staged class<T> type now distinguishes class pointers from classname<T> strings and explains the operations supported by each. 0a174765d9
  • W11 · Mar 10
    Experimental __NoDisjointUnion checking now looks through nullable wrappers, so an inferred ?(A | B) is checked like A | B. Warning 12017 now points separately to each disjoint member and to the annotated type parameter, instead of presenting only a flattened inferred type. The feature remains gated by no_disjoint_union. 4e1e9e9cce 64fd9a76e4
  • W11 · Mar 11
    Safe-abstract typing replaces the special-purpose concreteclassname<T> with the general covariant wrapper concrete<T>. This supports both concrete<classname<T>> and, with class-pointer typing enabled, concrete<class<T>>; the feature remains controlled by safe_abstract, which defaults to false. f3468eb107
  • W11 · Mar 11
    Class-pointer intersection simplification now reduces class<U> & class<V> to class<U & V> and, when class<T> is configured as a subtype of classname<T>, reduces class<U> & classname<V> to classname<U & V>. This gives equality refinement a denotable result instead of retaining an opaque intersection. def2bf2676
  • W11 · Mar 12
    Lambdas checked against a pre-stable polymorphic function type no longer instantiate the expected type too early. Valid implementations are accepted, while implementations that only satisfy one instantiation correctly fail subtyping. ad85396a28
  • W11 · Mar 12
    Pre-stable case-type variants are now validated under their own where constraints. A constraint can justify that variant's type arguments and bounds, but its assumptions do not leak into sibling variants. 6e65d7f43b
  • W11 · Mar 12
    Safe-abstract analysis now understands class<T> receivers as well as classname<T>, including unions and intersections. Under safe_abstract=true, unsafe construction, static calls, and abstract-constant access through class pointers produce the corresponding warnings. 3bd3fcbce1
  • W11 · Mar 12
    A new .hhconfig option, allow_class_string_cast, controls whether (string)$class is accepted when $class has type class<T>. It defaults to true; projects preparing for stricter class-pointer separation can set it to false. 29b5728cd6
  • W11 · Mar 13
    Expression-tree DSLs can provide specially typed static shapeAt, shapePut, and shapeIdx methods. Inside staged expression-tree syntax, the typechecker gives these the field-reading and field-writing semantics of Shapes::at(), Shapes::put(), and Shapes::idx() while generated code still calls the DSL's implementation. Shape creation and expression trees must be enabled, and each DSL remains responsible for the runtime methods. e222eed11d 29ff1adc01 dd0875d10a
  • W11 · Mar 14
    During the staged class-pointer migration, the runtime notice for loading an unannotated class from a string now says that the class is missing __DynamicallyReferenced. Class resolution and module checks run before string-to-class or missing-attribute notices, so a nonexistent or inaccessible class no longer produces a misleading conversion notice first. 7546273528 fa6aa63ebd
  • W12 · Mar 17
    During the staged class-pointer migration, __DynamicallyReferenced accepts an optional integer literal for additional notice sampling. When HHVM's global dynamically-referenced notice sampling selects a string-based class load, <<__DynamicallyReferenced(N)>> applies a further roughly 1-in-N check; 0 suppresses the soft notice. The argument must be a single integer literal, while the argument-free attribute retains its normal fully opted-in behavior. 74e1b401c2
  • W13 · Mar 25
    The staged polymorphic_function_hints feature adds denotable generic function types such as (function<T as C>(T): T). Hint-local type parameters may have upper and lower bounds and parameterless attributes, but may not be variant, reified, higher-kinded, shadow an enclosing type parameter, or use attributes with arguments. Existing polymorphic subtyping rules apply; the change adds syntax rather than a new subtyping relation. d5532224da
  • W13 · Mar 27
    parent:: inside a trait now resolves against the parent of the class named by the pre-stable require class or require this as constraint, rather than against the required class itself. The typechecker rejects parent:: when that class has no parent and points back to the requirement. 05e9f87a89
  • W13 · Mar 28
    Experimental expression-tree splices now evaluate eagerly and pass every spliced expression through the DSL's static lift() method before checking it as Spliceable. Nested-binding splices use the ordinary splice() visitor method with captured variable names as an optional fourth argument; the short-lived macroSplice() and asyncMacroSplice() protocol is no longer used. A capability-free DSL implementation can declare a helper such as public static function lift<T>(DslExpression<T> $x)[]: DslExpression<T>. f0b3d5104b
  • W13 · Mar 28
    Preview __SimpliHack IDE code actions are gated by the corrected feature name simpli_hack. The attribute may take a prompt string directly instead of a promptlet class pointer; clients must still implement the generated inline-chat command. 33e4701f2e c6d59c6834
  • W13 · Mar 28
    Class-pointer subtyping now clears stale this and like-type state while simplifying covariant class<T> propositions, avoiding spurious unsimplified unions and downstream diagnostics under sound dynamic. 733c16a23c
  • W13 · Mar 29
    With .hhconfig option new_exhaustivity_check=true, every switch must either be proven exhaustive or contain default. The checker precisely handles enums, enum classes and labels, bool, nullable types, unions, intersections, and closed tuples; it reports duplicate, unreachable, and redundant cases or defaults as warnings. Enabling it disables the old switch checks; the option still defaults to false. be717c1223
