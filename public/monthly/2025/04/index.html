Highlights

19 changes
  • W14 · Apr 1
    Redundant or impossible is and as checks are now detected after stripping the dynamic part of most like types, revealing more always-true and always-false checks without producing false positives for ~null. cb98bf2069
  • W14 · Apr 2
    Constructor arguments are typechecked even when resolving the constructed class yields only dynamic, so errors inside those arguments are no longer missed. b650999cb7
  • W14 · Apr 2
    Changes to enum members now correctly fan out to files whose switch exhaustivity depends on that enum. 4a25a14787
  • W14 · Apr 4
    Plain <<__Memoize>> functions with contexts such as [leak_safe] are no longer rejected merely because memoize-policy configuration is enabled. The parser now applies or requires #KeyedByIC only when the function's context can actually access implicit context. a278d85633 6d7717e2e1
  • W15 · Apr 8
    Type errors now describe classname<T> and typename<T> values with their inner type, for example “a classname string for C,” instead of dropping that useful detail. 2df9627226
  • W15 · Apr 10
    The compact Thrift helpers thrift_protocol_write_compact_struct_to_string and thrift_protocol_read_compact_struct_from_string are now declared in the HHI, along with more precise void return types for several existing write helpers. 6532008ee1
  • W15 · Apr 10
    asio_get_current_context_depth is now autoimported and can be called without the HH\ prefix. 1c46f2565e
  • W15 · Apr 11
    Constructing a value through a like-typed generic classname now preserves the generic type instead of falling back to dynamic, restoring useful return-type errors at the call site. a19c19574d
  • W16 · Apr 16
    HSL's OS exception dispatch no longer uses class pointers as keyset string keys, eliminating a burst of implicit class-to-string notices when an OS operation throws. a0698adb2a
  • W17 · Apr 21
    <<__Reifiable>> abstract type constants are no longer rejected because their as or super bounds contain non-reifiable types; only the constant's default or concrete value is relevant. ef204df70b
  • W17 · Apr 21
    HH\IPureMemoizeParam provides a pure getInstanceKey()[], and the new MemoAgnosticImplicitContext and MemoSensitiveImplicitContext base classes separate the two implicit-context behaviors. Their runWith methods require the context capability plus the callback's capability through [this::CRun, ctx $f]. a45c285415 13fa7c975b
  • W17 · Apr 22
    Async functions marked <<__AsioLowPri>> now run through a separate scheduler queue. Regular runnable awaitables are drained before low-priority work, while awaiting a child still lifts it into its parent's context. 8b9ebdb953
  • W17 · Apr 22
    Repeated IDE find-references requests no longer return progressively fewer class-member references as result files become open in the client. db5c895462
  • W17 · Apr 22
    Native <<__OutOnly>> parameters now expose their actual output type in the normal inout type position, and HHVM no longer enforces that type against the ignored incoming value. 794f98a7f4 3644d5ed99 be95fc5529 f4024e274f
  • W17 · Apr 23
    ReflectionFunctionAbstract::getParamTypeVarNames() returns the type-variable names used by a function or method's parameter hints. 98684268f3
  • W17 · Apr 23
    The new implicit-context base classes' private context constructors now require [leak_safe] rather than implicit [defaults]. This weakens their caller requirement, so they can be called from the base class's leak-safe context. 724940306c
  • W18 · Apr 28
    String interpolation with more than two pieces now emits a single concatN operation, reducing generated bytecode. e52b893890
  • W18 · Apr 28
    BuiltinEnum::coerce() now converts class inputs to classname strings consistently instead of returning a class value through a declared ?arraykey result, fixing a crash and disabling the invalid JIT fast path. bdfd541010
  • W18 · Apr 29
    <<__Memoize(#MakeICInaccessible)>> is now accepted on functions requiring zoned or newctx capabilities. The special parser ban was removed without changing the function's declared context requirement. 1a7cebca38

Future Changes

21 changes
  • W14 · Apr 1

  • W14 · Apr 2
    Packages v2 repo builds can now select files from an active deployment, symbol references, or both. --exclude-file and --exclude-pattern remain absolute exclusions, while package rules or symbol references may pull files back from --exclude-dir. 5bd4e8173b
  • W14 · Apr 3
    Packages v2 repo builds accept --report-files-in-build=<file> to write an exhaustive list of included source files, including files selected without a symbol-reference edge. e23a4e9c4c
  • W14 · Apr 4
    The staged __NeedsConcrete checker now enforces that calls to marked methods have a concrete late-static receiver, while permitting abstract-member access through static inside a __NeedsConcrete method. 8230cf15b4
  • W14 · Apr 4
    Reflection type-structure kinds now include OF_UNION and OF_RECURSIVE_UNION for case types. 0ab406eaf4
  • W15 · Apr 7
    __SimpliHack now accepts nonliteral arguments, and its interpreter can evaluate method calls and top-level function calls used to construct a prompt. ae6e86565e 0fecd7e618 042ac9fff0
  • W15 · Apr 9
    Hack code can now name the case-type reflection kinds TypeStructureKind::OF_UNION and TypeStructureKind::OF_RECURSIVE_UNION. e620c21119
  • W15 · Apr 10
    The direct-declaration parser no longer crashes on type splats in tuple bounds such as TExtra as (int, ...T). ae8c68cd2b
  • W15 · Apr 10
    Case-type refinement now carries variant where constraints into both true and false branches, including the final branch of an exhaustive chain of type tests. aadc7f921c
  • W16 · Apr 14
    Packages v2 is tightening boundary checks around class-pointer migration. New compatibility flags can temporarily allow violations from ::class, reifiable type constants, reified or erased generics, and all type constants; strict configurations can now check each of those positions. 5fa8eae5c6 a5c3b02b55 cd924b79dd f11e6f2900 cec831da05
  • W16 · Apr 15
    A type and a tuple containing only that type as a splat are now treated as equivalent: (...T) <: T and T <: (...T). 399bc551e2
  • W16 · Apr 17
    Calls to functions with a type-splat parameter can now pass an expression splat. For example, a final ...$args is checked by comparing the actual tuple, including its splat tail, with the parameter tuple. 830f0a4d73
  • W17 · Apr 21
    The unstable class-pointer API adds HH\get_class_from_object, HH\get_parent_class_from_class, and HH\ReifiedGenerics\get_class_from_type. 048e19045c
  • W17 · Apr 21
    SimpliHack promptlets can use HH\SimpliHack\file() to read a file relative to the .hhconfig root. The callee requires the new HH\SimpliHack context; its as [write_props] bound means that context requires at least write_props, rather than granting property-write access to a caller. 76ebbfc28a
  • W17 · Apr 22
    Packages v2 no longer checks the right-hand side of where constraints for package access, matching symbol-reference build behavior. c28fd84875
  • W17 · Apr 25
    Pre-stable require class constraints now propagate transitively through trait use relationships, allowing a using trait to rely on members guaranteed by an inherited requirement. 62494cfe06
  • W17 · Apr 25
    The staged require this as constraint now also propagates transitively through trait use relationships. 62494cfe06
  • W17 · Apr 25
    Nested expression trees no longer leak macro-splice variables into surrounding Hack expressions or retain them after leaving the tree. 373083a98f
  • W18 · Apr 28
    Staged polymorphic function hints are no longer allowed as type-constant definitions because their type parameters and bounds cannot be represented in runtime type structures. af7eae2a87
  • W18 · Apr 29
    The experimental Hack.Lang.CheckedUnsafeCast mode inserts a deep VerifyTypeTS check for HH\FIXME\UNSAFE_CAST<_, T>, warning by default when the runtime value does not match T and optionally making the mismatch fatal. 6bee4c575e
  • W18 · Apr 30
    Experimental higher-kinded type support is being removed. The checker no longer retains an unapplied type alias as a special Tunapplied_alias type, and the higher-kinded localization path and its tests have been deleted. 2bc12687aa fe83e883a0 5bda2a9975

Breaking Changes

10 changes
  • W15 · Apr 7
    Strict switch exhaustivity checking is now the default. Switches over types the checker cannot prove finite, such as int or dynamic, require a default; duplicate cases are errors, while redundant defaults on exhaustive finite switches are warnings. ab72191e86
  • W15 · Apr 9
    C::class is now typed as class<C> rather than classname<C> by default. Code that stores class constants as strings must convert explicitly with HH\class_to_classname. 6afb873297
  • W15 · Apr 9
    ReflectionParameter::$info is now private, and the undeclared ReflectionParameter::$paramTypeInfo field has been removed. Use the public reflection methods instead of inspecting these implementation fields dynamically. 2b92c03aec
  • W15 · Apr 11
    The legacy switch checker and the new_exhaustivity_check configuration option have been removed. Strict switch exhaustivity can no longer be disabled through .hhconfig. 434b2af668
  • W16 · Apr 16
    The runtime implementation of reflection's getAttributeClass now expects a class<mixed> and performs its own explicit classname conversion, beginning the migration away from accepting classname strings. 7a0f146cd3
  • W16 · Apr 18
    The deprecated HH\asio_get_current_context_idx and HH\asio_get_running_in_context functions have been removed from the HHI and autoimports. Use HH\asio_get_current_context_depth and HH\asio_get_running instead. 13c7313fb1
  • W16 · Apr 19
    The runtime implementations of the deprecated HH\asio_get_current_context_idx and HH\asio_get_running_in_context functions have now been removed as well. bb54bd8f99
  • W17 · Apr 23
    Reflection getAttributeClass methods now accept class<T> rather than classname<T> in the public HHI. Pass MyAttribute::class, not a classname string. 59ef42483e
  • W17 · Apr 23
    HH\dynamic_class_meth and HH\dynamic_class_meth_force now accept class pointers directly; passing a string remains supported through class_or_classname but raises an implicit string-to-class notice. 3ab00621de
  • W17 · Apr 24
    Reading an implicit-context value while that context is inaccessible now returns null instead of throwing InvalidOperationException. Wrappers should expose a nullable return type and callers should stop relying on the exception. f1de1267ab
