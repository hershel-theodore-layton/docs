Highlights

21 changes
  • W23 · Jun 2
    Streaming hh checks now pass a configured watchman_sockname to both watch-project and the Watchman client, avoiding a split where the server and client observe different Watchman instances. 45d6473b90
  • W23 · Jun 5
    Notebook-to-Hack conversion now repairs a missing semicolon at the end of a top-level cell, but only when that single edit reduces exactly one parse error to none. Other malformed cells are left unchanged for normal tooling to diagnose. d82928deeb
  • W24 · Jun 10
    Distributed hh checks avoid repeatedly merging large streamed error sets and instead filter the final result. This substantially reduces completion time on warning-heavy repositories. 708f72be89
  • W24 · Jun 10
    Legacy non-Hack notebook cells no longer lose their first character during conversion back from Hack. Wrapper removal now recognizes the complete comment form rather than blindly trimming the cell. be786e4c21
  • W24 · Jun 10
    A new print_debug_display(mixed $value, bool $ret = false): mixed built-in formats values with the debugger serializer and honors objects' __toDebugDisplay() methods. It has no explicit capability list and therefore uses the default capability set. 3ff25b1dfc
  • W24 · Jun 11
    HH\Lib\Async\LowPri<void> now works: run() no longer assumes that the awaited result is nonnull. Its capability remains [ctx $action, write_props], so callers still need the action's capabilities plus property-write access. 12fc967b7d
  • W24 · Jun 12
    XHP attributes declared as class<C> now compile and receive the same runtime attribute validation treatment as classname<C> attributes. This emitter fix does not introduce a new general subtype relationship between the two types. 72056a5eef
  • W24 · Jun 12
    hphpd -m notebook adds a continuation-free notebook mode in which each evaluation streams its output, allowing multiline commands without debugger continuation prompts leaking into notebook output. cbd1d4510d
  • W24 · Jun 14
    APC and HHVM-internal serialization now preserve class pointers as lazy-class l: values instead of turning them into strings, including when nested in Pair, Map, or dict values. Ordinary user-facing serialize() remains string-based by default. 159314f561
  • W25 · Jun 16
    The extract-method refactoring now leaves the original method's doc comment attached to that method instead of moving it to the newly extracted method. 3f0bf0852f
  • W25 · Jun 17
    hh_server no longer crashes when an Eden-backed watcher observes a directory rename in a repository root below the Eden mount point. The watcher now issues the correct relative glob and the test suite verifies that the server did not silently restart. d3f1c8d92c
  • W25 · Jun 18
    The native HH\Facts\subtypes(), transitive_subtypes(), and supertypes() implementations now accept either class pointers or class names without raising string-to-class conversion notices. These APIs retain their explicit [] capability lists and therefore require no ambient capabilities from callers. 17a3032494
  • W25 · Jun 18
    Generated HHI declarations no longer need memoization-parameter annotations when a project enables disallow_non_annotated_memoize. This prevents bundled HSL declarations from causing hh_server to fail during startup; user source remains subject to the setting. d7772b96df
  • W25 · Jun 19
    Generic inference now expands type variables before removing covariant like types. Valid calls involving refined generic settings and nested shape, vec, or dict values no longer produce false subtyping errors under sound-dynamic checking. f784cde712
  • W25 · Jun 20
    Direct static method calls on a trait now produce Warn[12020]. Call the method through a using class, or use self::/static:: inside the trait, to avoid accessing the trait's separate runtime state. b3cc106aee
  • W26 · Jun 23
    Package-boundary checking no longer reports violations for an enum or enum-class base type or constraint type, matching the fact that those hints do not create symbol-reference dependencies. d238628006
  • W26 · Jun 24
    Class-pointer results from HH\Facts\subtypes(), transitive_subtypes(), and supertypes() are now sorted before being returned, producing deterministic ordering in both interpreter and JIT modes. ca7697d710
  • W26 · Jun 25
    Notebook-to-Hack conversion no longer generates an empty async entry-point function when the notebook has no top-level statements. 9a43d12c8d
  • W26 · Jun 25
    Development builds of HHVM no longer abort during process shutdown after asynchronous writes through HSL's standard file descriptors. Descriptor sweeping is now a no-op because request shutdown already closes the underlying built-in files. f32e4281d8
  • W26 · Jun 27
    Redeclaring a non-const static property in a subclass now produces Warn[12021]. The declarations have separate runtime storage rather than overriding one another, so updates through the parent and child names do not share state. 0c9f90144e
  • W26 · Jun 27
    HH\serialize_with_options() accepts shape('keepClasses' => true). With the option enabled, class and lazy-class values are emitted with HHVM's l: representation and deserialize back to class values; the default remains string conversion. The function has no explicit capability list, so it continues to use the default capability set. 94e3085910

Breaking Changes

9 changes
  • W23 · Jun 2
    type_structure($class_name, ...) now participates in implicit string-to-class conversion notices when its class argument is a string. Class pointers, lazy classes, and objects do not raise this notice. Projects using Eval.RaiseClassConversionNoticeSampleRate can use the signal to find classes that need <<__DynamicallyReferenced>> or callers that should pass a class pointer. b028e13e25
  • W23 · Jun 4
    The legacy resource-backed representation of enum-class labels and the Eval.EmitNativeEnumClassLabels=false configuration have been removed; labels are now always native values. Public coeffects are unchanged: nameOf() remains [], while valueOf() remains [write_props]. ff50cab0ba
  • W23 · Jun 7
    Reifying the late-static-bound this type is now permitted only when its lexical class is final and has no type parameters. A final C<T> can no longer hide a non-reified T inside a reified type constant through this; the typechecker reports Typing[4305]. 9b7f7a647c
  • W24 · Jun 10
    The JSON-valued .hhconfig setting class_pointer_levels has been replaced by six default-false booleans: class_pointer_ban_classname_new, class_pointer_ban_classname_type_structure, class_pointer_ban_classname_static_prop, class_pointer_ban_classname_static_meth, class_pointer_ban_classname_class_const, and class_pointer_ban_class_array_key. Literal C::class values in string or array-key positions are now errors rather than configurable warnings; use nameof C or HH\class_to_classname() when a name is intended. af60977aab
  • W25 · Jun 16
    Compiler-special functions without ordinary runtime definitions can no longer be captured with function-pointer syntax. Naming[2105] now rejects pointers to HH\classname_to_class, exit, HH\ReifiedGenerics\get_class_from_type, HH\global_get, HH\global_set, HH\tag_provenance_here, HH\FIXME\UNSAFE_CAST, and HH\FIXME\UNSAFE_NONNULL_CAST; direct calls remain supported. 87c01f69af
  • W25 · Jun 20
    HH\Facts\subtypes(), transitive_subtypes(), and supertypes() now return class-pointer values instead of bare strings, avoiding dynamic class loads when their results are used as classes. All three functions retain []; code that stores, concatenates, or serializes the returned values as strings must convert them deliberately. 4b4b297617
  • W26 · Jun 23
    Direct static property access through a trait name is now rejected with Typing[4497]. A trait and each class that uses it have distinct static storage, so access the property through the using class or through self::/static:: as appropriate. 4efd0792f2
  • W26 · Jun 25
    The HHI signatures for HH\Facts\subtypes<T>() and transitive_subtypes<T>() now return vec<class<T>>; supertypes() returns vec<class<mixed>>. This exposes the class-pointer runtime change to static typing while preserving subtype information and the APIs' [] capability lists. d81dc7b2f9
  • W26 · Jun 26
    The unused .hhconfig key log_exhaustivity_check has been removed. Deleting it does not change switch-exhaustiveness checking because the option had no effect. cd143bb3eb

Future Changes

15 changes
  • W23 · Jun 2
    Preview type-splat declarations no longer confuse a type-splat parameter with a variadic capture during runtime method-override checks. After T is instantiated as (int, string), a method with parameters (int, string) can implement one declared with ...T; ordinary return-type, coeffect, and parameter checks still apply. 23b2e8bd5e
  • W23 · Jun 4
    Under the unstable no_disjoint_union feature, fixpoint class refinements such as this::TNext bounded by I with { type TNext = this::TNext } now retain their dependent projected type instead of collapsing to TAny. ac0e6a103f
  • W23 · Jun 6
    Enabling Packages V2 now forcibly disables Eval.EnforceDeployment. The initial Packages V2 implementation therefore does not provide Packages V1's runtime deployment-boundary enforcement; projects must rely on static package checks. 6f6ee77b3d
  • W24 · Jun 10
    Expression-tree operation typing now passes the left or unary operand through Dsl::operationType() before dispatching operator and implicit-boolean methods. This lets a DSL map virtual values such as null onto an object that defines the operation. DSLs using the unstable feature must add the static method; a pure identity implementation should declare [] so it does not add a caller capability requirement. 77f1b1105e
  • W24 · Jun 10
    With unstable case-type where clauses, a direct or indirect reference from a case type's own where clause is now rejected with Typing[4485]. The invalid clause is excluded from checking to prevent infinite recursion in constraint solving and subtyping. f696b2fb30
  • W24 · Jun 11
    Preview SimpliHack expressions can request a class's constructor, instance and static methods, or instance and static fields through HH\SimpliHack\constructor(), methods(), static_methods(), fields(), and static_fields(). Each takes classname<mixed>, returns string, and requires the [HH\SimpliHack] capability. 277597ae53
  • W24 · Jun 13
    Open tuples and type splats have moved from Preview to OngoingRelease. This staged rollout enables them without a file-level unstable-feature opt-in, including arity-polymorphic forms such as TArgs as (mixed...) and ...TArgs, but they are not yet fully released. 4d0ce07626
  • W25 · Jun 16
    Under unstable no_disjoint_union, type-constant access through union and intersection types now updates the dependent this type for each constituent. Fixpoint refinements consequently retain their precise projected types after these flows. ede7843927
  • W25 · Jun 18
    With needs_concrete checking enabled, calls to __NeedsConcrete methods through self:: and parent:: now account for their forwarding of the late-static receiver. Unsafe calls are rejected, while calls made from another __NeedsConcrete method are accepted when the receiver is known to be concrete. 95e848e66c
  • W25 · Jun 20
    Within an unstable polymorphic lambda's body, wildcard hints are now allowed in refinements such as $x is A<_>. Wildcards remain forbidden in the lambda's parameter and return types, including nested lambda signatures. 7c45cf525e
  • W26 · Jun 24
    The protected internal member visibility has moved from Unstable to Preview, and HackC now preserves it through bytecode IR and assembly. It remains a staged feature rather than a generally released visibility mode. e83acda317 346b857de9
  • W26 · Jun 27
    Staged polymorphic function-pointer typing lets references such as C::genericMethod<> retain a rank-2 polymorphic function type instead of fixing fresh type variables after their first use. The extracted type accounts for method and class generics, where constraints, variance-sensitive this, and abstract type constants, allowing one reference to be used at multiple compatible instantiations. This typing is not yet the default. 2ff573c3b3
  • W26 · Jun 28
    Under the staged polymorphic function-pointer typing, meth_caller() gives polymorphic instance methods a rank-2 polymorphic function type, including an implicit first parameter representing the receiver's this type. This prevents one use from prematurely fixing method or receiver type variables and removes false errors when the same caller is used at compatible instantiations. This typing is not yet the default. b3fb0d6924
  • W27 · Jun 30
    When the experimental EdenFS-backed file watcher cannot initialize, hh_server now falls back to the next enabled notifier—normally Watchman—instead of failing outright. 6d4cfd4936
  • W27 · Jun 30
    Nested type-parameter declarations used for experimental higher-kinded types, such as class Foo<TC<TX>> {}, are no longer part of Hack's grammar. The --enable-higher-kinded-types single-file checker flag and its internal option have also been removed; projects must express abstractions with supported ordinary generics. b0f3ed5c9c 60adf9a9fb
