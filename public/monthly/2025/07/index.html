Breaking Changes

11 changes
  • W27 · Jul 3
    The legacy apache_request_headers() and getallheaders() declarations have been removed from the HHI, so typechecked Hack code can no longer call either API. The removed getallheaders() declaration required [read_globals]; this is an API removal, not a narrowing of that capability requirement. fdbee7ee64
  • W27 · Jul 5
    Distributed typechecking configuration now uses hh_distc_fanout_threshold as the lower activation threshold and replaces hh_distc_fanout_aware_threshold with hh_distc_fanout_full_init_threshold. Fanout-aware mode also requires the new default-false enable_fanout_aware_distc switch, so deployments using the old key must update their server-local configuration. 0617ce8382
  • W28 · Jul 9
    Four class-pointer migration settings—class_pointer_ban_classname_new, _type_structure, _static_meth, and _class_const—now take integer levels: 0 permits the operation, 1 emits Warn[12022], and 2 reports an error. Existing boolean values must be replaced with the corresponding integer. e2bb8738e8
  • W28 · Jul 9
    Static-property access through classname<T> is now an unconditional type error, and the former class_pointer_ban_classname_static_prop escape hatch has been removed. Migrate the receiver to class<T>. e2bb8738e8
  • W28 · Jul 10
    Eval.ForbidDynamicCallsToFunc now defaults to level 2. Dynamically calling a top-level function that lacks <<__DynamicallyCallable>> throws, while raw string call sites still warn; migrate ordinary calls to function pointers and use HH\dynamic_fun() only for deliberately opted-in dynamic targets. 77763d0b69 950e7c8257
  • W28 · Jul 11
    ReflectionFunction::invoke() and invokeArgs() now throw ReflectionException for named top-level functions. Invocation through a reflection object remains supported for closures. 6e46037c92
  • W28 · Jul 11
    Eval.ForbidDynamicCallsToFunc now defaults to level 3, so raw-string top-level function calls throw even when the target has <<__DynamicallyCallable>>. Use a function pointer, or resolve an explicitly dynamic target through HH\dynamic_fun(). ee7d2b14b1
  • W28 · Jul 12
    HH\dynamic_fun() now resolves its target in the caller's context, so enabled module and package-deployment boundary checks can reject dynamic calls that previously bypassed enforcement. 4231b683b5
  • W29 · Jul 14
    Constructor analysis now checks every reachable use of $this instead of short-circuiting after the first control-flow result. Premature uses in loop conditions, increments, and thrown expressions can now produce initialization errors that were previously missed. 32d174351d
  • W30 · Jul 25
    SoapServer::addFunction() now throws SoapException when passed a single function-name string. Code using string registration must move to one of the API's supported non-string registration forms or redesign the dispatch path. eebe7d5a17
  • W31 · Jul 31
    HPHPD no longer supports creating, listing, clearing, enabling, or disabling breakpoints. Projects that still use HPHPD for debugging should migrate breakpoint workflows to the VS Code debugger. 4b5791d1ba

Highlights

23 changes
  • W28 · Jul 7
    HHVM's reflection runtime adds getTypeVarNames()[] to ReflectionClass and ReflectionFunctionAbstract, reporting every declared type parameter rather than only parameters appearing in the callable signature. The runtime signature requires no capabilities, but the public HHI does not expose the methods until later in the month. 844b86e849
  • W28 · Jul 8
    Truthiness analysis now recognizes closures, function references, and class<T> values as always truthy, while vec_or_dict remains potentially empty. Conditions such as if ($closure) can consequently produce the intended always-truthy warning. 0bf71d4a41
  • W28 · Jul 11
    LSP document-symbol ranges now begin at the symbol's name rather than at the start of its line, improving outline navigation and symbol selection. 0c2b5109ff
  • W28 · Jul 11
    ReflectionTypeConstant::getCanonicalClassname()[] reports the class or trait that actually defines a type constant in non-repo-authoritative mode. Repo-authoritative builds flatten traits and therefore throw when that distinction cannot be recovered; the explicit [] adds no caller capability requirement. db653f14e1
  • W28 · Jul 12
    Switch exhaustiveness analysis now strips supportdyn wrappers, avoiding unnecessary default branches when all underlying cases are covered. 7036122c9a
  • W29 · Jul 14
    Constructor initialization checking no longer reports a false read-before-write error when an inherited property is initialized by a child's default value. 25fc487bb9
  • W29 · Jul 15
    Implicit string-to-class conversion notices now identify whether the conversion came from an expression, a static-method call, type_structure(), or HH\dynamic_class_meth(), making class-pointer migrations easier to triage. d6f352bc64
  • W29 · Jul 15
    The compact-protocol readers now accept an optional trailing int $version = 2 at runtime, and the public HHI exposes it on thrift_protocol_read_compact_struct_from_string(). Its omitted capability list remains implicit [defaults]. c292d2c41e
  • W29 · Jul 16
    Hack now gives each built-in pseudoconstant—such as __FILE__, __CLASS__, and __METHOD__—a distinct bounded newtype. Existing string and integer uses remain valid, while APIs can distinguish the pseudoconstant's origin in their signatures. 4b2d2f26d9
  • W29 · Jul 16
    Type-switch refinement now preserves the scrutinee's generic upper bound in both true and false branches, and sealed-interface knowledge is used more consistently when proving types disjoint. 57c703bbf5 e76d7a2c00
  • W29 · Jul 17
    Type errors caused by generic or newtype upper bounds now point to the value's origin and explain the relevant bound definition instead of attributing the mismatch to an opaque solver type. f53441eb8b
  • W29 · Jul 18
    User-facing type errors now treat e1[e2] as a local flow source, so an invalid indexed value is attributed to the subscript expression rather than only to the distant origin of the container's type. b591ddd593 1249826f24
  • W29 · Jul 18
    The public HHI now exposes getTypeVarNames()[] on ReflectionClass and ReflectionFunctionAbstract, completing the runtime API added earlier in the month. Its empty capability list means any caller context can invoke it. 9786b22b25
  • W30 · Jul 21
    Type refinements for runtime generic-class tests now instantiate wildcard arguments existentially. Checks such as $x is C<_> can therefore partition and refine generic values without inventing a concrete wildcard type. a2835215c6 215bdd8e7e
  • W30 · Jul 22
    Runtime is checks and type verification now treat <<__Soft>> constraints as mixed, matching the textual bytecode backend and preventing a soft annotation from being accidentally enforced as a hard type. 32c03fcd51
  • W31 · Jul 28
    HH\FileDecls::getPublicApiForClass(string $name)[] returns a source-like rendering of a class's public methods, constants, type constants, inheritance, and implemented interfaces. Its explicit [] means tooling can call it from any capability context. 920bfa05ee
  • W31 · Jul 29
    --report-files-in-build now works for legacy non-Packages-V2 repo builds, and build reports identify why each file was included—for example through package selection, symbol references, autoload roots, or explicit include paths. 40aa523fd5 f4df5c5e47
  • W31 · Jul 29
    HHVM now defines the built-in pseudoconstant newtypes in systemlib as well as in the HHI, preventing values such as __METHOD__ from being mistaken for class names at runtime. 49f2d63ded
  • W31 · Jul 29
    Public-API rendering through HH\FileDecls now includes constructors. d6cd4b01f2
  • W31 · Jul 30
    The Rust full-fidelity syntax tree now computes parentage offsets from each child node's width rather than the parent's width, fixing offset-based parser and IDE queries. 90d676478f
  • W31 · Jul 30

  • W31 · Jul 31
