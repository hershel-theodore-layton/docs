Breaking Changes

7 changes
  • W36 · Sep 1
    Objprof now visits each reachable object or array value only once per root, preventing exponentially slow heap scans when a value is reachable through many paths. As a consequence, objprof_get_paths() reports one representative path rather than attempting to enumerate every path to the same value. 6f2a571385
  • W36 · Sep 3
    Constraint-based array-index inference is now enabled by default through constraint_array_index=true. This improves inference when the container or key is generic, but can change accepted programs and diagnostics—for example, some specialized index errors become ordinary Typing[4110] subtype errors. Projects can temporarily set the option to false while migrating. cb6c796386
  • W36 · Sep 4
    The optional HH\ExtDeclSignature shape field 'cross_package' has been renamed to 'require_package', reflecting the replacement of <<__CrossPackage>> with <<__RequirePackage>>. Tools consuming the ExtDecl API must read the new field name. 5b56df5697
  • W37 · Sep 9
    Legacy dynamic typing has been removed. The .hhconfig option enable_sound_dynamic_type no longer exists, and Hack now always uses sound-dynamic coercion, subtyping, and TAST generation. 0eb895abd4
  • W37 · Sep 10
    Packages v1 and <<__CrossPackage>> have been removed. The Eval.PackageV2, Eval.EnforceDeployment, and .hhconfig package_v2 switches are gone, and migration options formerly prefixed package_v2_ have been renamed to package_ equivalents, such as package_exclude_patterns. 4ed554f36f
  • W37 · Sep 10
    hh_server no longer verifies by default that every PACKAGES.toml include path exists on the local filesystem. Malformed paths and paths assigned to multiple packages remain configuration errors. 1b6a11ff14
  • W38 · Sep 15
    HHVM now raises a runtime notice when a non-async method overrides an async parent method, even if the overriding method returns an Awaitable. This is a notice rather than the hard rejection that was previously backed out, but it may affect logs and user error handlers. b194537329

Highlights

21 changes
  • W36 · Sep 2
    A reified generic marked <<__Newable>> may now make a static call such as T::f() even when the method is abstract on T's upper bound. Newability proves that the runtime class is concrete; the called method's ordinary parameter, return, and coeffect checks still apply. fe174ae69f
  • W36 · Sep 2
    CUSTOM_ERRORS.json rules can now match missing-member errors by static versus instance access, member kind, class name, member name, and visibility. This covers methods, properties, class constants, and type constants. b7d5fc5c01
  • W36 · Sep 5
    Facts/autoload configuration now supports the Eden-compatible Autoload.IncludePaths, Autoload.ExcludePaths, and Autoload.FileExtensions lists, plus Autoload.UseEden. When the path and extension lists are present, HHVM also derives an equivalent Watchman query for backward compatibility; these lists take precedence over Autoload.Query. f71b97f6d9
  • W37 · Sep 9
    HEIF and AVIF decoding through the GD extension now reports whether a requested read position is available, beyond end-of-file, or failed, while restoring the stream cursor after checking. This fixes decoding behavior needed by newer libheif releases. 98c14764fe
  • W37 · Sep 10
    Packages v2 is now Hack and HHVM's only package model and no longer requires an unstable-feature opt-in. <<__RequirePackage>> is the released attribute for declaring a function or method's package requirement. 4ed554f36f
  • W37 · Sep 12
    Custom-error schema version 2 can match naming errors as well as typing errors. Its first naming pattern, Unbound_name, can restrict matches by the missing name and by contexts such as function, constant, module, package, class, trait, or other type; version 1 typing-error rules remain supported. 0fedc4eba4
  • W38 · Sep 16
    Redundant and impossible is/as analysis no longer produces false positives from wildcard tests or unsolved constrained types. Nullable ?as assertions now receive the same always-succeeds or always-fails warnings as ordinary as assertions. 9374196892 0b4c942af5
  • W38 · Sep 16
    meth_caller() no longer wraps references to methods without __SupportDynamicType in supportdyn. The resulting callable now reflects the method's actual dynamic support while retaining its declared parameter, return, and coeffect information. 3788c4ad24
  • W38 · Sep 16
    hphpd print-expression commands now permit assignments, so expressions such as = $value = compute() can update a debugger variable and display the result in one command. 6b677a3e2c
  • W38 · Sep 17
    hh --find-my-tests accepts one or more method names and returns referencing files under __tests__ directories. It can also walk callers backward through the call graph up to a requested maximum distance, finding tests that exercise a method indirectly. c0adb1229d 83dbfa02c7
  • W38 · Sep 18
    PHP\pack() and PHP\unpack() now support g/G for little-/big-endian floats and e/E for little-/big-endian doubles, matching the formats added in PHP 7.2. f855f97526
  • W39 · Sep 22
    hh --tast-holes now preserves like types in its JSON rendering of actual and expected types, giving unsafe-cast codemods the precision needed to retain sound-dynamic boundaries. 01c2d1d968
  • W39 · Sep 22
    A parameter declared as dynamic now remains dynamic inside the function even when its default expression has a narrower like type. Defaults no longer cause false downstream errors when that parameter is passed to other dynamic-aware code. f3a9352a5a
  • W39 · Sep 22
    Sound-dynamic subtyping can now push like types through contravariant positions nested beneath invariant types. Valid relationships such as Box<Contra<~int>> <: ~Box<Contra<int>> no longer fail because like-pushing happened at the wrong variance. b90d86fd9a
  • W39 · Sep 24
    type_structure($value, 'T') now accepts a first argument of type dynamic instead of rejecting the call during its special type-constant validation. Its public signature retains [], so callers need no ambient capabilities. 70d45071f4
  • W39 · Sep 24
    New openssl_csr_get_dns_names(mixed): vec<string> and openssl_csr_get_upn(mixed): string APIs read DNS subject-alt names and the Microsoft UPN otherName from a certificate-signing request. Both throw OpenSSLException for an unparseable CSR; the UPN API also throws when no valid UPN exists. Their omitted coeffect brackets mean [defaults], so they are not callable from a pure [] context. 120ba485fd b1691a9392
  • W39 · Sep 24
    HHVM now loads individual types in dependency order rather than repeatedly retrying whole units. Cross-file dependency chains that only looked cyclic because neither file could be loaded first can now autoload successfully. d67fb09b37
  • W39 · Sep 25
    GADT-style is refinements now preserve class type-constant refinements while learning constraints on an enclosing generic. Checks such as $x is IChild<_> can refine both an inherited generic and with { type T = ... } information without producing false errors. 3ce3fe0a57
  • W40 · Sep 29
    Sound-dynamic inference now carries supportdyn through indexed container element types and through intersections whose type variables have dynamic-supporting upper bounds. This removes false errors around generic array access and constraints such as CanTraverse. 6dbec9f7df 679954de6d
  • W40 · Sep 29
    With checked unsafe casts disabled, HH\FIXME\UNSAFE_CAST<TFrom, TTo>(await $value) now goes through the same await-lifting path as a bare await $value. Unsafe-cast unwrapping happens during AST elaboration, avoiding bytecode differences caused by a later compiler pass. 9e9c5e8ba1
  • W40 · Sep 29
    The new per-type autoload ordering correctly handles re-entry from a user error handler while loading a unit, preventing the handler's own class loads from observing a paused autoloader. 24a6049013

Future Changes

12 changes
  • W36 · Sep 2
    Packages v2's unstable <<__RequirePackage('foo')>> attribute is now enforced at runtime when an active deployment is configured. Entering an annotated function or method fatals if the required package is not deployed; without an active deployment, the check is not enforced. d19f80681a
  • W36 · Sep 2
    A PACKAGES.toml include path may belong to only one package. Duplicate include_paths now produce a configuration error rather than making file-to-package assignment depend on package order. 1dec51cc16
  • W37 · Sep 9
    Opt-in constraint_array_index_assign inference now understands writes through dynamic containers and string offsets, extending the constraint-based read path to more indexed assignments. The option remains disabled by default. 2aaede9d97 bae68aa2ae
  • W37 · Sep 9
    Experimental <<__Const>> may no longer annotate an entire class, interface, trait, or enum. The staged const-object work is narrowing to explicitly const properties instead of implicitly making every property const. ee81f08f04
  • W37 · Sep 11
    The expression-tree ?? and ?-> subfeatures have moved to OngoingRelease. DSLs can use null coalescing and null-safe member access without those individual opt-ins, though expression trees themselves remain experimental. d34f379825
  • W38 · Sep 18
    Under staged poly_function_pointers, a static method pointer no longer quantifies over an unused class-level generic, even when that generic is reified. For example, a static method that does not mention Wibble<reify T>'s T can produce an ordinary HH\FunctionRef<(readonly function(): TResult)>; its declared coeffect bracket is preserved. dd7e7c2480
  • W38 · Sep 18
    Experimental recursive case types now report Typing[4498] instead of the general cyclic-alias Typing[4014]. Update targeted suppressions or diagnostic tooling that distinguishes these errors by code. 655c4925aa
  • W39 · Sep 24
    Unstable named parameters now receive direct call-site checking for missing, extra, duplicate, and incorrectly typed names, plus autocomplete support. Required named parameters may follow optional parameters because their names remove positional ambiguity. Function-type subtyping and override checking do not yet compare parameter names; ordinary parameter contravariance and coeffect compatibility are unchanged. 6ff9985d4d c345859fc2 4427b17a5e
  • W39 · Sep 25
    Increment and decrement operations on an experimental <<__Const>> property now produce Typing[4196], matching direct assignment. The check currently applies at a mutating helper method's declaration; moving it to calls made outside construction is follow-up work. 8adb7b6e42
  • W40 · Sep 29
    Experimental expression trees can reference enum members and named class constants directly, desugaring them through the DSL's new visitClassConstant() hook instead of requiring ${...} splices. Dynamic class names remain unsupported; the hook's declared coeffects participate in normal caller-superset checking and are not implicitly granted. 1ad2b8920b
  • W40 · Sep 29
    Opt-in constraint_method_call=true uses function-type parameter contravariance to infer simple instance calls, including previously underconstrained lambda parameters. The path currently excludes explicit type arguments and unpacked arguments and synthesizes a [defaults] callable target; callers must therefore provide the default capability set, even if the concrete method is purer. Diagnostics now point to the missing method or mismatched argument rather than the whole call. 75142ebf79 eab5021b17
  • W40 · Sep 30
    Unsupported expression-tree forms now receive specific Parsing[1002] explanations instead of a generic syntax error. Diagnostics distinguish await, new, string interpolation, global constants, and [] indexing, making DSL migrations more actionable. ee1a3a88e8
