Highlights

25 changes
  • W40 · Oct 1
    The required-shape-field lint no longer recommends direct indexing when the shape itself is optional. Calls such as Shapes::idx($optional_shape, 'field') no longer receive a false Lint[5005]. 65985eea5e
  • W40 · Oct 1
    enum<T> hints now validate the enum's base type instead of treating T as a class name. Valid generic enum hints no longer receive Typing[4148], while incompatible enum bases receive the ordinary subtype error. 2e533742f9
  • W40 · Oct 2
    Typing[4104] and Typing[4105] now say "too few positional arguments" and "too many positional arguments." Named-argument arity has separate diagnostics, so the revised wording identifies the part of a call that is actually wrong. 9a285f64ab
  • W40 · Oct 3
    HHVM now provides openssl_x509_get_upn(mixed): string for extracting a Microsoft User Principal Name from an X.509 certificate's subject-alt names. It throws OpenSSLException when the certificate cannot be parsed or has no valid UPN; its omitted capability brackets mean [defaults], and the public HHI follows on October 14. fd5f758c2c
  • W40 · Oct 3
    The x86 JIT now preserves native stack alignment while filling omitted default arguments, avoiding ABI-unsafe calls into the uninitDefaultArgs helper. 751e89833e
  • W41 · Oct 6
    Sound-dynamic typing for integer operations is more precise. Binary &, |, and ^ return ~int only when both operands may hide strings; %, <<, and >> accept like/dynamic integer operands but return int; unary ~ over a like/dynamic integer returns ~int. Invalid operands now receive Typing[4110]. 8b0a654ad2 cb891dba1b 8ad57d6c36
  • W41 · Oct 6
    Eval.WarnOnBitwiseOpInvalidType provides a migration path away from runtime bitwise operations on strings. The default 0 preserves them, 1 raises a warning, and 2 raises an error. 0d19dfbb13
  • W41 · Oct 7
    A property-assignment type mismatch now highlights the incompatible right-hand-side expression rather than the entire assignment statement, making Typing[4110] errors substantially easier to locate. db5d63a7fa
  • W41 · Oct 8
    CUSTOM_ERRORS.json rules can now match Module_cross_package_access by the use, declaration, module, and package files and by the current and target module/package names. File patterns support path segments, filename/extension matching, wildcards, and captures. 9243b11d8a
  • W41 · Oct 8
    Bad array-index diagnostics now point at the index expression, and Lint[5654] flags ?-> when the receiver is statically exactly null. 9b6a914f00 a9a26055e5
  • W41 · Oct 8
    HackC unit-compilation exceptions crossing the Rust/C++ boundary are now rendered as meaningful emitter errors instead of opaque bridge-class failures. c776cb5c3a
  • W41 · Oct 8
    Thrift streaming now credits a request when response payload memory is freed on its I/O thread, reducing false per-request out-of-memory failures. Credit is applied when control next returns to the request thread, so several in-flight payloads must still fit within the limit. 6f2c4027de
  • W41 · Oct 9
    protected internal visibility is released and no longer requires <<file: __EnableUnstableFeatures('protected_internal')>>. The old unstable-feature name has been removed. 3b6cd30fac
  • W41 · Oct 9
    Compact Thrift string serialization and deserialization now rethrow Hack exception objects unchanged. User exceptions retain their original class and message instead of being wrapped as a generic Thrift error. 5ba682b8b8
  • W42 · Oct 14
    Hack's public HHI now declares OpenSSLException, openssl_csr_get_dns_names(), openssl_csr_get_upn(), and openssl_x509_get_upn(). These runtime APIs from September 24 and October 3 are now directly typecheckable; omitted capability brackets mean [defaults], so they are not callable from a pure [] context. 5c0196ca81
  • W43 · Oct 21
    HH\FormatString<T> now has an as string upper bound. Generic code can use ordinary string operations on a format string without typechecker special cases or a concatenation trick. 3da9793389
  • W43 · Oct 22
    New HH\Facts\path_to_package(string)[]: ?string returns a known file's package. A per-file package override wins; otherwise Facts chooses the package with the longest matching include_paths prefix. The explicit [] means callers need no ambient capabilities. e1415fca71
  • W43 · Oct 22
    Moving only a package override's source position no longer makes the file's declarations appear to have changed, avoiding unnecessary incremental rechecks after whitespace edits. 08cd63f125
  • W43 · Oct 23
    Refining a generic wildcard now retains the generic parameter's substituted bounds. Valid refinements—especially under implicit pessimization—no longer fail because an upper or lower bound disappeared during localization. fab431c150
  • W44 · Oct 27
    New auto-imported objprof_get_data_with_graph_stats(), objprof_get_data_extended_with_graph_stats(), and objprof_get_paths_with_graph_stats() can bound traversal with max_depth and max_visits. They return the usual object statistics plus nodes_visited and max_depth_seen; omitted capability brackets mean [defaults]. b8a2b2c9d7 5b20747174 6663dc9b4e
  • W44 · Oct 27
    CUSTOM_ERRORS.json can now match Cross_pkg_access and Cross_pkg_access_with_requirepackage by use and declaration file. Missing-member class patterns are also namespace-aware, so top-level names no longer require a leading backslash in a plain string pattern. bc740ac7e2 5b894225af
  • W44 · Oct 28
    The VS Code debugger's stepIn request now records the current stack depth before resuming, fixing cases where stepping entered the wrong function. b991fdf189
  • W44 · Oct 30
    Default-parameter initializer bytecode now uses the parameter's source location. Runtime type errors point to the parameter declaration rather than the function's closing brace, and default-value funclets are excluded from executable-line and coverage results. 3e366bf718
  • W44 · Oct 31
    Implicit pessimization is more precise for single-parameter functions with enforced return types and for non-overridable methods: top-level functions, non-trait private methods, final methods, and methods in final classes. They accept a like/dynamic argument while retaining the exact enforced return type instead of unnecessarily returning a like type. a4a706bc7a
  • W44 · Oct 31
    Custom-error rules can now capture files from package-primary patterns and member names from missing-member patterns. Custom messages render Markdown styling in terminal and LSP output, and a malformed class name now makes a rule fail to match instead of crashing evaluation. 3787483015 8e501c4a0b b0aa1b2428 32524cb34f

Future Changes

20 changes
  • W40 · Oct 1
    Under the preview readonly feature, HHVM's runtime declaration of HH\legacy_is_truthy() now accepts readonly mixed, allowing readonly values to be inspected without a cast. Its explicit [] capability list is unchanged, so callers still need no ambient capabilities; the public HHI follows on October 20. 3df24d5bf5
  • W40 · Oct 1
    Nested experimental expression trees no longer have a separate expression_tree_nested_bindings gate. They may capture bindings from an outer expression tree once expression trees themselves are enabled. 5b90e946d6
  • W40 · Oct 2
    Unstable named parameters now participate in function-type subtyping and override arity checks. A subtype must accept every named parameter promised by its supertype and may not make an optional named parameter required. a354304453
  • W40 · Oct 3
    Violating the staged __NeedsConcrete override rule now produces Warn[12027] instead of Typing[4487]. This permits hierarchy-by-hierarchy adoption while continuing to flag an override that imposes a stricter concreteness requirement than its parent. 9ec3de9342
  • W41 · Oct 6
    Unstable named parameters are now parsed in lambdas and function-type hints, compared by name during function subtyping, and supported after one splatted argument. Diagnostics distinguish missing named markers and multiple splats, with quickfixes and narrower source positions. 0dca1d44ca f4ef532fa8 363a3b9bf4 dc806083d8 f3fdea9f10 e6e42516c3
  • W41 · Oct 9
    Opt-in constraint_method_call inference now compares a method's required capabilities with the caller's actual provided capability instead of a synthesized [defaults]. Capability requirements are caller obligations and function capabilities are contravariant: the method may require the same or a smaller set than the caller provides, while a requirement outside that set is rejected. ee31ebee65
  • W41 · Oct 9
    Experimental case-type disjointness now expands sealed classes as well as sealed interfaces. This admits unions such as I | Awaitable<I> when the sealed Awaitable hierarchy proves that the variants cannot overlap. 707dd89d81
  • W41 · Oct 10
    The staged null-safe pipe operator |?> evaluates its right-hand side only when the left-hand side is non-null. Within the right-hand side $$ is narrowed to non-null, and the whole expression remains nullable. 1ba856e4ee
  • W42 · Oct 16
    Experimental constraint-based method-call inference now updates argument positions as it descends through function subtyping. Errors identify the particular incompatible argument instead of inheriting a stale position from an earlier constraint. abcf4835b6
  • W43 · Oct 20
    Under the preview readonly feature, Hack's public declaration of HH\legacy_is_truthy() now accepts readonly mixed, completing the runtime change from October 1. The change widens the accepted parameter type; its [] capability requirement remains unchanged. ba5dfba433
  • W43 · Oct 20
    Opt-in constraint-based method-call inference now preserves readonly receivers and arguments and a surrounding readonly return context. It can require a readonly method for a readonly receiver while accepting readonly parameters or returns where function subtyping permits them. 7b1fa8acc1
  • W43 · Oct 21
    Staged polymorphic function subtyping now increases rank only when the supertype is universally quantified, avoiding needless rank changes when comparing ordinary callable types. df5cd2852a
  • W43 · Oct 21
    Unstable type splats in method parameter lists must now be tuple types, matching the existing rule for functions. 02bf96e926
  • W43 · Oct 22
    Experimental expression trees can now lower static:: class constants and static method calls where the corresponding late-bound reference is valid. self:: and parent:: remain unsupported in these forms. f1f2029527
  • W43 · Oct 22
    The default-off fanout_strip_class_location rollout option treats a class moved within the same file as unchanged when comparing declaration order inputs. Moving the class to another file still triggers fanout. 08cd63f125 76b64bc6f8
  • W43 · Oct 23
    With checked unsafe casts enabled, nested HH\FIXME\UNSAFE_CAST() and UNSAFE_NONNULL_CAST() expressions are now all traversed. Runtime checks are no longer skipped merely because one unsafe cast is nested inside another. 3fb517842f
  • W43 · Oct 24
    When experimental expression-tree lowering produces a top-level function or static-method pointer, staged polymorphic pointer types are now instantiated before the DSL visitor sees them. This preserves the earlier monomorphic inference behavior inside expression trees. d17f9d9fe2
  • W44 · Oct 27
    A generic Watcher runtime abstraction has landed as explicit work in progress toward Watchman and Eden backends. It currently has no typechecker HHI, supports only Watchman, and does not yet return its specified output format, so projects should not adopt it yet. cdce35b437
  • W44 · Oct 28
    Experimental recursive case-type localization now carries cycle detection across multiple generic upper bounds, preventing infinite recursion when mutually recursive aliases are reached through more than one bound. 2a02549225
  • W44 · Oct 30
    Experimental expression trees no longer support XHP syntax. DSLs using staged expression trees must splice or otherwise construct XHP outside the tree. 576aa124fa

Breaking Changes

4 changes
  • W40 · Oct 3
    The Watchman extension has removed HH\watchman_query(), HH\watchman_subscribe(), HH\watchman_check_sub(), HH\watchman_sync_sub(), and HH\watchman_unsubscribe(). Projects calling these APIs need to replace them; HH\watchman_run() and HH\ext_watchman_version() remain. b61ee2ea1b
  • W41 · Oct 8
    The .hhconfig option disallow_invalid_arraykey has been removed. Hack has enforced this behavior unconditionally for years, so removing the stale setting does not relax invalid array-key checks, but project configuration must stop declaring it. 642bb4521d
  • W43 · Oct 21
    Strict string concatenation and interpolation are now unconditional, and the .hhconfig option enable_strict_string_concat_interp has been removed. ., interpolation, and echo accept only string and int (arraykey, plus dynamic under sound-dynamic typing); values such as bool, float, and Stringish must be explicitly converted. 73bb242fc6
  • W44 · Oct 30
    Eval.EnableCodeCoveragePerBytecode now defaults to true, so coverage and HH\get_executable_lines() count only bytecodes representing meaningful actions such as calls, branches, assignments, and returns. Reports may contain fewer executable or covered lines; set it to false temporarily for the legacy all-bytecode behavior. 23b107df3e

Security

2 changes
  • W41 · Oct 10
    Servers can set Server.AllowExec=false to disable process-launching APIs. HHVM then throws for shell_exec(), exec(), passthru(), system(), proc_open(), pcntl_exec(), and HSL's OS\fork_and_execve(); the default remains true. 5a71f2f16a
  • W43 · Oct 23
    Package checking now exempts top-level function-pointer expressions by default, matching SymbolRefs' behavior of not following those pointers. Set .hhconfig package_allow_function_pointers_violations=false to enforce package boundaries at these expressions. 5c26f88816
