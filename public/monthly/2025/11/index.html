40 noteworthy changes, organized by the source changelog sections.

Highlights

20 changes
  • W45 · Nov 3
    Declared-type hovers now omit like types (~T) introduced by pessimization. Hovering a call therefore shows the API's source-level declaration instead of the type checker's sound-dynamic implementation detail. d1ed3e8f71
  • W45 · Nov 4
    A new hh --package-lint FILE command finds references to definitions in a file, providing a targeted way to estimate the impact of moving that file across package boundaries. Its initial JSON response includes each definition and its references. 572e5972c8
  • W45 · Nov 5
    Higher-rank type-parameter escape diagnostics now explain that a generic parameter may be escaping its defining scope, instead of asserting that it definitely did. 801396cf42
  • W45 · Nov 6
    Custom-error file patterns now support a ** globstar suffix, which matches zero or more path segments after a fixed prefix, and optional path segments. This makes a single custom-error rule usable across nested or partially optional directory layouts. de62e41f78
  • W45 · Nov 6
    get_executable_lines() no longer repeatedly replaces its line-table cache while walking bytecode offsets, fixing a potentially large per-request memory leak. 80fec6c413
  • W46 · Nov 10
    Awaiting a static method call or class-constant access inside a pipe no longer leaves an unreplaced $$ for the emitter. Expressions such as $value |> await $$::method() now compile correctly. 533fc364b1
  • W46 · Nov 11
    Function pointers to <<__Native>> functions using <<__TrivialHHVMBuiltinWrapper>> now resolve to the wrapper's target in the interpreter, matching ordinary calls and JIT execution. 594c8fb627
  • W46 · Nov 11
    The Hack client adds hh --log-errors, an asynchronous mode that type-checks a supplied file list and logs its diagnostics after returning immediately. --log-to-file PATH writes those diagnostics to a file, and the mode honors the usual error and warning filters. 78608b1f95
  • W46 · Nov 14
    Custom-error configuration now validates repeated bindings across all supported pattern kinds, preventing valid rules from being rejected—or incompatible bindings from being accepted—when they use newer pattern types. 44ec7ad20c
  • W46 · Nov 14
    Vec\map_with_key_async() no longer constrains input keys to arraykey; it now accepts any KeyedTraversable<Tk, Tv>. The callback coeffect remains [ctx $value_func]. 171f7923fa
  • W46 · Nov 14
    HHVM's unit cache now records a changed repository-options hash even when recompilation produces identical bytecode. Updating .hhvmconfig.hdf or PACKAGES.toml therefore no longer makes unchanged files recompile on every request. 506ac2d22c
  • W47 · Nov 17
    Reified type-structure interning now compares semantically equal type structures without depending on dictionary key order, avoiding debug-build assertions for structures assembled through different inheritance and constraint paths. 3688b57f82
  • W47 · Nov 17
    The JIT no longer applies an unsafe dict/keyset offset optimization when a container may be empty or contain tombstones, preventing incorrect optimized execution. 90a4d19894
  • W47 · Nov 19
    HHBBC no longer performs stack-rewinding or stack-shape-changing reductions while speculating through a block, fixing a path that could incorrectly optimize bytecode. 58b4eb518a
  • W47 · Nov 20
    The debugger no longer sends a DAP thread exited event for a thread whose corresponding thread started event was never sent, keeping client thread state balanced. 9cd2be99d3
  • W47 · Nov 23
    HHBBC now preserves the known staticness of nested dict/keyset keys and values when modeling copy-on-write on an otherwise static array, fixing an optimizer monotonicity bug. 3a858a7274
  • W48 · Nov 24
    <<__RequirePackage>> on interface and abstract methods no longer makes hackc try to insert a runtime assertion body where no method body can exist, fixing compilation of these declarations. 7850ed7b86
  • W48 · Nov 25
    The null-safe pipe operator |?> is fully released and no longer requires an unstable-feature opt-in. Hack also adds Warn[12031] when its left side cannot be null and Warn[12032] when it is always null. 9c1592aef2 49a01a024d
  • W48 · Nov 26
    Custom-error ** file-prefix patterns no longer swallow a failed required path segment and match an unintended file. Exact and prefix patterns now share the corrected segment matcher. 95025e2a47
  • W48 · Nov 28
    When a generic type is supplied the wrong number of arguments, Hack now stops after the arity error instead of inventing Tany arguments and producing misleading follow-on constraint errors. db68c7eef3

Breaking Changes

8 changes
  • W45 · Nov 5
    DOMElement::getAttribute() is now declared to return string instead of an untyped result, matching its runtime behavior. Code that null-checks the result or relies on implicit conversion from it may now produce type errors. bc373ee080
  • W46 · Nov 12
    hh --package-lint FILE now uses naming and dependency tables instead of fully type-checking reference files. Its JSON output changes from per-definition reference records to a simple array of absolute paths for files that may be affected by moving the input file. 648d385bc7
  • W47 · Nov 18
    parent::__construct(...) is now checked as an ordinary method call. This correctly supports constructors with <<__SupportDynamicType>>, but also reports an error when the parent class has no constructor instead of silently accepting the call. b1f24f75dd
  • W47 · Nov 18
    With an active deployment, package foo and HH\package_exists('foo') now return false when foo is only softly deployed. This also changes whether <<__RequirePackage('foo')>> requirements are satisfied. 32f696c3e9
  • W47 · Nov 19
    The runtime functions apache_request_headers() and its alias getallheaders() have been removed. Their declarations had already been removed from the standard-library HHI files. be51b361e8
  • W48 · Nov 25
    Redundant ?-> checks have moved from lint codes 5633/5654 to Hack warnings 12029/12030. Update warning filters and suppressions accordingly; expression-tree lowering is excluded to avoid false positives. 41573b779d 65841bca20
  • W48 · Nov 25
    Exceptions thrown by Thrift adapter methods are now exposed to Hack as TProtocolException with ERR_UNEXPECTED_EXCEPTION, rather than leaking the original exception. Code that catches a particular adapter exception will need to catch the protocol exception instead. ae27f8a1f0
  • W48 · Nov 26
    HH\Facts\types_with_attribute() now returns lazy-class values instead of raw strings, statically changing from vec<string> to vec<classname<nonnull>>. Its attribute parameter changes from string to class_or_classname<ClassLikeAttribute>, so callers holding an unrefined string may need to supply a typed class name. Type aliases remain excluded, and the function remains capability-free ([]). 22eba707f3

Future Changes

10 changes
  • W45 · Nov 5
    Expression trees now accept late-static-bound method calls and class constants written with static::; self::, parent::, and dynamically selected classes remain unsupported. Expression trees are still an ongoing-release feature. 5699d743ec
  • W45 · Nov 7
    First-class polymorphism now rejects higher-rank type variables that escape their defining scope, closing a case previously missed by the rank check. This applies to the still-experimental polymorphic-function-hint work. 520dda036c
  • W45 · Nov 9
    Custom-error v2 rules can now match the expression-tree "unsupported operator" diagnostic, including the affected DSL class and operator member. Expression trees remain an ongoing-release feature. da440e2b51
  • W46 · Nov 12
    The ongoing-release sealed_methods feature adds method-level <<__Sealed(...)>>. Its allowlist restricts which classes or traits may directly override a method; constructors, private methods, and interface methods cannot use the attribute. 83a0b8478c
  • W46 · Nov 12
    The new unstable xhp_type_constants feature permits type constants such as A::T and this::TData in XHP attribute declarations. Runtime XHP metadata currently represents these attributes as mixed, so the feature still requires __EnableUnstableFeatures. acca24cbe1
  • W46 · Nov 13
    Preview readonly checking now treats $condition ?: $fallback as readonly when the returned left-hand value or fallback is readonly. Mutating or returning the result in a mutable position can therefore reveal errors that the previous analysis missed. b2a2b3ea0f
  • W46 · Nov 13
    Under the experimental dynamic-assumptions mode (everything_sdt=false), indexing an unknown field of an open shape refined from dynamic no longer produces a false error after Shapes::keyExists(). 9cef9e19bf
  • W47 · Nov 19
    .hhconfig gains check_bool_for_condition: 0 keeps existing truthiness behavior, 1 emits Warn[12028], and 2 emits Typing[4504] unless conditions are subtypes of ~bool. The opt-in check covers control-flow conditions, !, &&, ||, and ternaries. f2102bc763
  • W48 · Nov 24
    Named-argument completion snippets now keep parameter_name= outside the editable placeholder, so typing the value no longer deletes the parameter name. Optional parameters remain omitted from call completions. Named arguments are still unstable. c2d246ec9d
  • W48 · Nov 25
    Type inference for immediately invoked lambdas now accounts for named arguments, fixing both missed errors and rejected valid calls under the unstable named-arguments feature. d3ef01c111

Security

2 changes
  • W46 · Nov 12
    Package boundary checks now cover global constants. Accessing a constant from another package without a permitted dependency produces Typing[4472], closing a gap in package access enforcement. fcd7b5c771
  • W47 · Nov 20
    HHVM can now enforce Server.RequestFanoutLimit for recursively spawned Xbox requests. With the new Server.EnforceRequestFanout=true setting, exceeding the limit rolls back the counter and throws RequestFanoutLimitExceededException; enforcement is off by default. a96d874cb8
