49 noteworthy changes, organized by the source changelog sections.

Highlights

25 changes
  • W49 · Dec 1
    A successful if (package foo) refinement or <<__RequirePackage('foo')>> guarantee now also marks every package transitively included by foo as loaded. Code inside the guarded function or branch can therefore access symbols from those included packages without redundant package checks. 57290fa827
  • W49 · Dec 1
    The performance regression affecting fresh hh --no-load checks has been fixed. 5edcde7241
  • W49 · Dec 2
    The Thrift extension now provides thrift_protocol_write_binary_struct_to_string() and thrift_protocol_read_binary_struct_from_string(). They serialize Binary-protocol structs directly to and from strings, avoiding repeated calls into Hack through TMemoryBuffer; both omit explicit capability brackets and therefore require [defaults]. 956620c50f
  • W49 · Dec 3
    HH\is_any_array($value) now refines types like $value is HH\AnyArray<_, _>. In particular, false branches no longer produce spurious AnyArray arity errors. 37cae09f34
  • W49 · Dec 3
    The global, final RequestFanoutLimitExceededException is now declared in the bundled HHI files, so Hack code can name and catch the runtime exception without supplying a local stub. fe93d4bbde
  • W49 · Dec 4
    HHVM debugger listening sockets now use SOCK_CLOEXEC. Access-log processors and other subprocesses no longer inherit the descriptor and prevent the debugger server from reopening its socket after a client disconnects. 8e8e78c5ff
  • W49 · Dec 4
    Access-log formats can use %M for the request's end time as a Unix timestamp in microseconds, providing finer resolution than the existing seconds-level time field. c8a3b4f976
  • W49 · Dec 5
    New <<__SoftRequirePackage('pkg', 100)>> annotations let functions and concrete methods observe missing deployment requirements without failing the call. The package name and optional sample rate must be literals. A missing package emits a sampled notice identifying the callable; the rate defaults to 1, while 0 suppresses logging. 233ada2c6f
  • W50 · Dec 8
    Hack's line-break map now handles CRLF, LF, and a trailing bare CR without an off-by-one access, improving source positions in tools that consume the map. b09e3f9d1c
  • W50 · Dec 8
    Eden-backed hh_server file enumeration no longer discards changes that were waiting to be consumed, preventing a full-file query from making subsequent incremental checks miss an edit. 44760b5d3e
  • W50 · Dec 9
    Fresh generic parameters that still occur in local-variable types are no longer discarded from the typing environment during refinement and control-flow analysis. This fixes false errors in code that refines generic predicates and then joins values from the resulting branches. 2ec0bc4566
  • W50 · Dec 10
    The parser now processes long else if chains iteratively, avoiding stack growth proportional to the number of branches while preserving the same syntax tree. 794dce91c0
  • W50 · Dec 10
    Tools converting Hack's JSON type representation back into local types now map the primitive string entry to HH\string rather than a class literally named string. 0e9e24f115
  • W50 · Dec 11
    The open-source implicit_context.hhi no longer seals MemoSensitiveImplicitContext to an internal-only subclass, preventing bundled HHI declarations from producing an impossible subclass error in OSS projects. a455f079d5
  • W50 · Dec 12
    Disjoint-type checking now builds substitutions from the class being instantiated rather than the declaration where a member originated, avoiding an assertion when inherited generic arities differ. e4a5ef9f93
  • W50 · Dec 13
    AsyncMysqlQueryResult now exposes mysqlInfo(): ?string, rowsMatched(): ?int, and warningsCount(): int. These distinguish rows matched from rows actually changed by an update and expose server warning metadata; their omitted coeffect brackets mean [defaults], so they are not callable from a pure [] context. aef4881eab
  • W51 · Dec 15
    The Hack manual now documents package inclusion and cross-package calls in greater depth and adds a migration guide covering __PackageOverride, __RequirePackage, and the new __SoftRequirePackage workflow. abb3833a49
  • W51 · Dec 16
    HHBBC no longer performs quadratic dead-code elimination on long chains of array-element additions, reducing compile time for generated code and large literal-building sequences. a2b1b96b4b
  • W51 · Dec 17
    A fatal caused by throwing a value that does not implement Throwable now includes the value's actual runtime type, making boundary and deserialization failures substantially easier to diagnose. 94bd1abfe1
  • W51 · Dec 18
    HHVM avoids building an expensive JIT region context after losing a translation lease, reducing extreme CPU use when many requests contend to translate the same large function. 5a202ad779
  • W51 · Dec 19
    CLI-server deployments can set Eval.UnixServerNotifySystemd=true to send READY=1 after the Unix server has started accepting connections. fa336b0021
  • W52 · Dec 23
    New HH\TypedFormatString<TFormatter, TArgs> values carry the placeholder types as a tuple, allowing first-class helpers to pass a format string and its ...TArgs without a FIXME. String literals are checked when a typed format string is expected, and concatenating two compatible typed format strings concatenates their argument tuples; the existing HH\FormatString<T> remains as a backward-compatible alias using (mixed...). 12cbdcd02f
  • W52 · Dec 23
    sprintf(), printf(), HH\invariant(), and HH\invariant_violation() now connect the inferred format tuple to their variadic arguments. sprintf() and the invariant helpers retain []; printf() still omits a bracket and therefore requires [defaults], so the stronger typing does not grant callers any new capabilities. 12cbdcd02f
  • W52 · Dec 25
    Nullable ?as expressions no longer leave compiler-generated locals initialized on a failed check or on an exception raised while resolving a type structure. This prevents later control flow, including loops in a surrounding catch, from observing dangling temporary state. 998c829efb
  • W01 · Dec 29
    JIT recovery now selects the oldest worker for termination and stack capture when the main retranslate-all thread is stuck, even if that worker has not independently exceeded the timeout. A larger initial profiling-prologue table also reduces contention during heavily profiled workloads. 8a64b59275 1050ba1a55

Breaking Changes

8 changes
  • W49 · Dec 3
    The void-use check now looks through supportdyn, so consuming an expression typed as supportdyn<void> is rejected just like consuming void. This can reveal previously missed errors in sound-dynamic code. 26e025e493
  • W49 · Dec 5
    The HHI model of HH\string is now final. User classes can no longer extend the primitive's synthetic class, while types such as classname<C> remain meaningful subtypes of string. e71a41b2ba
  • W50 · Dec 9
    The global boolval() function has been removed from Hack's HHI files and HHVM's standard extension. Replace calls with HH\legacy_is_truthy(), which preserves the legacy conversion behavior and, like the removed function, requires no capabilities ([]). 27465dc29d
  • W51 · Dec 15
    Null-safe pipe syntax has completed its rollout and nullsafe_pipe has been removed from the experimental-feature registry. The syntax remains available by default, but projects should remove stale <<file:__EnableUnstableFeatures('nullsafe_pipe')>> declarations. 99ff43dd3d
  • W51 · Dec 16
    The .hhconfig option constraint_array_index and the legacy array-read checker have been removed. Array reads now always use the constraint-based checker; the separate, default-false constraint_array_index_assign experiment for writes is unchanged. e68fe7227a
  • W51 · Dec 18
    The direct-to-string Binary Thrift APIs added on December 2, thrift_protocol_write_binary_struct_to_string() and thrift_protocol_read_binary_struct_from_string(), have been removed. The implementation was rolled back because a backend could identify a result as a Thrift exception while supplying a class that was not throwable. 773f486d40
  • W52 · Dec 22
    zip_entry_read() now takes only its resource $zip_entry argument and always reads up to 1024 bytes. Remove the optional $length argument from callers. The HHI return type remains string, and the omitted coeffect brackets mean [defaults]. 8fca72ab98
  • W52 · Dec 23
    Each component of a concatenated typed format string must now be well formed. Constructions such as "%" . "d" are rejected even though the final plain string would spell a valid placeholder; concatenate complete format fragments instead. 12cbdcd02f

Future Changes

16 changes
  • W49 · Dec 4
    The still-configurable polymorphic function-pointer rollout is now enabled by default. References to generic declarations retain a rank-2 type instead of fixing their type arguments when the reference is created, allowing separate calls to choose separate valid instantiations. Declared parameter, return, and coeffect requirements remain part of the resulting HH\FunctionRef; projects needing a temporary escape hatch can set poly_function_pointers=false. e4da608d51
  • W49 · Dec 4
    The pre-release __NeedsConcrete override diagnostic now follows the default-false needs_concrete option, so disabling that option suppresses the override check along with the other __NeedsConcrete checks. d729522778
  • W49 · Dec 4
    Staged type-constant lower bounds now participate in polymorphic function-pointer synthesis. For nested accesses, upper bounds are intersected and lower bounds are unioned so that every instantiation agrees on the projected type constant; ordinary callable parameter variance and coeffect compatibility remain enforced. d80b10688e
  • W49 · Dec 5
    XHP type constants have moved to OngoingRelease. XHP attributes may use declarations such as attribute MyClass::TMyType attr without a file-level unstable-feature opt-in, but the feature remains pre-stable. 19d0a58e2e
  • W50 · Dec 8
    Diagnostics for pre-stable optional function parameters now suggest marking an extra lambda parameter optional when a callable supplies too many mandatory positional parameters for the expected function type. This is guidance for the existing contravariant callable check; parameter variance and coeffect compatibility are unchanged. a9f0befdc6
  • W50 · Dec 9
    Type-constant super bounds have moved from Unstable to Preview. The staged syntax permits lower bounds alongside as upper bounds on abstract type constants; it is not yet an OngoingRelease feature. 913a25ea19
  • W50 · Dec 10
    During the null-safe pipe's OngoingRelease phase, await is no longer allowed on the right-hand side of |?>, because that branch is conditionally executed. Await the value before the pipe or move the asynchronous operation into explicit control flow. 67afb72ad7
  • W50 · Dec 10
    With the pre-stable open_tuples and type_splat features enabled, a vec<mixed> can now be unpacked into a function declared with ...(mixed...) or a generic ...TArgs. Subtyping treats the unknown-length vec as a variadic sequence rather than a single tuple slot; the callee's capability requirements still undergo the normal caller-superset check. 9dd3259bf2
  • W50 · Dec 11
    Diagnostics for pre-stable optional function parameters now call out when a supplied callable accepts too few positional arguments for the expected function type. This makes the accepted-call-set mismatch clearer without changing parameter contravariance or coeffect subtyping. 65a2637417
  • W50 · Dec 12
    HHBBC now preserves type variables when resolving Preview case-type type structures, matching live HHVM resolution and preventing repo-authoritative builds from silently losing generic information. 6ab86e1f68
  • W51 · Dec 16
    As part of the staged polymorphic function-pointer work, meth_caller() now erases reification on type parameters lifted from the receiver class. For class C<reify T>, an instance-method caller can have a rank-2 type such as function<T>(C<T>, T): void because the receiver already carries the runtime type structure; the method's declared capability requirements remain on the synthesized callable. a17086df77
  • W51 · Dec 16
    An opt-in .hhconfig setting, ignore_string_methods=false, exposes the experimental HH\string::length(): int method and its HH\String\__primitive_length(string): int implementation. Both omit explicit coeffect brackets and therefore use [defaults]; the default setting still hides them. 4e83e22176
  • W51 · Dec 17
    Pre-stable open-tuple checking now handles projection from tuples with optional elements before a splat. It also reports Typing[4116] when null-coalescing access requests an index that can never exist. 5538c39818
  • W51 · Dec 17
    Unstable named-parameter function types now recognize function(optional named bool $b): void as a subtype of function(): void. The former accepts a superset of the calls permitted by the latter, which is the contravariant relationship required for parameters; return types and coeffect brackets must still satisfy their ordinary subtype rules. 8039d96fed
  • W51 · Dec 18
    Runtime arity errors now say that a callable expects a number of positional parameters. This keeps the message accurate for callables that also define named parameters. 7db2c19473
  • W51 · Dec 19
    Staged __NeedsConcrete checking now has two independent, default-false controls: needs_concrete enables call-site and related checks, while needs_concrete_override_check enables the warning for a __NeedsConcrete method overriding an unannotated method. Enabling one does not imply the other. 9027820d96
