Security

3 changes
  • W10 · Mar 2
    HHVM operators can set Eval.AllowUngatedExec=false to reject shell_exec(), exec(), passthru(), system(), pcntl_exec(), and HH\Lib\OS\fork_and_execve(). proc_open() can remain available to exact function or Class::method names listed in Eval.ProcOpenGatedApprovedCallers. 3f00bd113d
  • W10 · Mar 3
    Hack's string unescaper no longer attempts an out-of-bounds index when a single-quoted, nowdoc, or long string ends with a bare backslash. Malformed input now returns an error instead of panicking the compiler. 7be063f2ff
  • W13 · Mar 25
    HackC no longer constructs invalid Rust strings from binary Hack literals while emitting shape keys, dynamic method names, or enum-class labels. Invalid UTF-8 bytes are replaced lossily instead of causing undefined behavior in later string operations. 8d729a6bfc

Breaking Changes

14 changes
  • W10 · Mar 2
    The DateInterval HHI is more precise: $days is now int, createFromDateString() returns DateInterval, and format() returns string. Code that relied on these APIs producing mixed may now expose type errors. f551f0f9fc
  • W10 · Mar 4
    An if (package p) expression is now rejected unless package p includes the package containing the current file, matching the well-formedness rule for __RequirePackage. 4986189361
  • W10 · Mar 4
    The cross-package migration linter now tracks C::class references when package_allow_classconst_violations=true; projects using that temporary carveout may see new lint 5656 diagnostics for undeclared package dependencies. 6671f217e0
  • W10 · Mar 5
    Cyclic abstract type-constant bounds such as abstract const type T as this::T no longer introduce an unsound Tany bound. The cycle is treated as an absent upper bound (mixed) or lower bound (nothing), so invalid uses that previously passed through Tany can now produce type errors. 97d482d027
  • W11 · Mar 11
    The built-in date/time HHI now gives many formerly untyped APIs concrete parameter and return types, including checkdate(): bool, timezone getters and setters, DateTime mutators returning this, and typed DateTime/DateInterval parameters. Calls that previously flowed through missing HHI types may now report type errors. 7e8a8d7133
  • W11 · Mar 12
    Misspelled script markers such as <?h, <?hx, or <?h h are no longer mistaken for PHP and silently skipped. Hack treats them as source files and reports a parse error directing authors to <?hh; valid <?php and bare <? PHP markers remain skipped. cffabe0510 b0addbd6a3
  • W11 · Mar 12
    Legacy @T soft type hints are now unconditionally rejected; the already-default-on disable_legacy_soft_typehints setting and CLI flags were removed. Use <<__Soft>> T and delete stale configuration overrides. 28379910d0
  • W11 · Mar 13
    Date/time declarations were tightened further: procedural functions such as date_diff(), date_format(), and date_sub() now have concrete date/time parameters and returns; DateTime mutators return this, diff() returns DateInterval, and DateTimeZone::getOffset() returns int. Invalid calls and assumptions previously hidden by missing HHI types can now fail typechecking. 9b933e837e
  • W12 · Mar 18
    Hack now emits Warn[12036] when an expression has a genuine unresolved Tany type that can silently pass as any type. Tany caused solely by a missing type in the hierarchy is excluded to avoid duplicating the underlying error. bcbc39eec5
  • W12 · Mar 19
    Conflicting trait-method detection now catches a method re-imported through both a parent class and multiple traits. Hack follows HHVM's trait flattening and reports the ambiguous trait definitions instead of incorrectly retaining the inherited class method. f316fd38e6
  • W12 · Mar 20
    method_trait_diamond and require_class completed their release and were removed from the experimental-feature registry. Their syntax is available without __EnableUnstableFeatures; remove those now-stale feature names from file attributes and experimental-feature configuration. 25c20acf30 775769c0e6
  • W13 · Mar 27
    Lint 5655 now reports __PackageOverride dependencies introduced through as/?as, reifiable type constants, and explicit generic arguments even while their package-boundary carveout settings remain enabled. 90c5cd1df9
  • W13 · Mar 29
    Lint 5656 now checks C::class references from a file with __PackageOverride when the target lacks the same override. These cross-boundary class-pointer dependencies were previously skipped altogether. 5c9c5a3178
  • W14 · Mar 31
    HH\FunctionRef is fully released: the enable_function_references setting and function_references unstable-feature name were removed. Function references remain enabled; delete stale configuration and __EnableUnstableFeatures('function_references') entries. 020e9dd575

Highlights

19 changes
  • W10 · Mar 4
    hh --help now shows a curated everyday command set instead of roughly 70 rarely used flags; hh --ultrahelp retains the complete option list. 300f886607
  • W10 · Mar 5
    HackC no longer crashes while reporting invalid constant initializers that contain local-variable list expressions; it now points the constant-expression error at the offending expression. de71cec1a5
  • W10 · Mar 6
    HH\type_structure_classname() is now understood specially by the typechecker: it resolves the named type constant and returns the corresponding classname<T> when the type is classish or an enum, while rejecting non-classish type constants. 9b14e5db5d
  • W10 · Mar 6
    apc_add(), apc_store(), and their with_pure_sleep variants gained a final $guaranteed_acyclic argument. Setting it to true skips APC's cycle-detection walk when the caller can guarantee the stored value contains no cycles. 7fa443e8fa
  • W11 · Mar 9
    Exhaustiveness checking now follows a user-defined newtype's upper bound when that bound is an enum. A complete switch over newtype Wrapped as MyEnum = MyEnum no longer needs a redundant default case. 7849dd4079
  • W11 · Mar 12
    Lambda type-parameter exposure now removes expression-dependent variables from recursive refined builder types instead of retaining them across later lambdas. This avoids cubic typechecking behavior in fluent-builder code with class refinements. db5234971c
  • W11 · Mar 12
    The persistent Hack server no longer gets stuck or returns stale results when one file changes while an earlier recheck is being interrupted. Files left in disk_needs_parsing now trigger another typecheck even when no additional filesystem event arrives. 6bfec3705a
  • W11 · Mar 14
    hh --outline-for-agents FILE emits a compact list of a Hack file's declarations and line ranges while hiding private members. It gives coding tools a cheap map of large or generated files before they read the relevant ranges. a52d4298ea
  • W12 · Mar 17
    hh --find-refs and symbol-indexing cross-references no longer lose class receivers when a union also contains dynamic or Tany. Method references remain discoverable after repeated is refinements that introduce like types. e2490020de
  • W12 · Mar 19
    Concurrent use of the LMDB extension no longer races while closing environments or cursors, corrupting its handle map and crashing HHVM. LMDB handles are now tracked per request thread. 4a781cffc4
  • W13 · Mar 24
    Deleting, renaming, or moving a file during typechecking now restarts the full initialization cycle instead of swallowing File_provider_stale and reporting a spurious internal diagnostic. 654061e2d8
  • W13 · Mar 25
    Typechecking functions that conditionally add many fields to a closed shape is substantially faster. Closed-shape unions now bypass subtype checks that cannot succeed, and branch joins reuse physically shared fields instead of repeatedly processing the entire growing shape. ce7e826544 487491f877
  • W13 · Mar 25
    Open-source HHBBC compilation no longer deadlocks when its subprocess scheduler is saturated; a worker waiting for capacity no longer holds the lock needed to register and release other subprocesses. 7215c6d4ae
  • W13 · Mar 26
    date_diff() once again accepts any DateTimeInterface as its first argument, correcting the overly narrow DateTime HHI introduced earlier in the month. c869f6c13d
  • W13 · Mar 27
    Async lambdas checked against a like-wrapped Awaitable<T> return now reuse the expected T instead of inventing a fresh return type variable. This improves inference when passing async lambdas into dynamically callable APIs. 05f87d6706
  • W13 · Mar 27
    HHBBC no longer takes quadratic time when folding large keyset literals; it now applies the same efficient element-chain handling already used for dicts. edd801ed44
  • W14 · Mar 30
    HackLint 5644's quick fix now preserves semantics for always-true and always-false boolean expressions: expr || true becomes true, and expr && false becomes false, rather than incorrectly dropping the literal and keeping expr. 2961c64c7b
  • W14 · Mar 30
    Warn[12026] for calling new static() through an uninstantiable class now recommends <<__NeedsConcrete>> on the containing method and offers a quick fix to add it. 4606faa9c0
  • W14 · Mar 31
    Unrecognized hh --config key=value keys are now recorded in the client log, with a spelling suggestion when available. The command remains non-fatal to tolerate mixed-version releases and rollbacks. 1b40943644

Future Changes

12 changes
  • W10 · Mar 4
    Symbol information now retains the pre-stable named and readonly parameter modifiers when rendering function type hints, so tools consuming displayType no longer erase them from the displayed function type. d927c424f2
  • W10 · Mar 4
    The pre-stable extended-await implementation now supports conditional and sequential awaits inside concurrent blocks, preserves using statement lifetime correctly, and evaluates for initializer and iterator expression lists in source order. 31f3c8b933 4b74fe53e8 de3ebf325f
  • W10 · Mar 4
    The pre-stable delay operator explicitly leaves an Awaitable<T> un-awaited while preserving its type. It is a runtime no-op, is permitted only in async functions, and is intended to distinguish deliberate delayed awaiting from accidentally discarded awaitables. 5872d7ec97
  • W10 · Mar 4
    Runtime type structures can now represent exact, upper-bound, lower-bound, and context-constant refinements such as I with { type T = int }. This is groundwork for using pre-stable class refinements on the right-hand side of type aliases and type constants. b05c47edf3
  • W10 · Mar 4
    Setting disallow_bool_cast=true now makes (bool) casts a parse error, providing an opt-in migration path away from implicit truthiness conversions. 6479cd2461
  • W11 · Mar 10
    Mutually recursive pre-stable case-type bounds no longer send the typechecker into an infinite loop; upper-bound localization now avoids recursively simplifying intersections. 7e5b31d920
  • W11 · Mar 13
    With strict_consistent_construct=true, an abstract class may no longer extend a non-abstract <<__ConsistentConstruct>> class. The opt-in rule prevents new static() from resolving to an uninstantiable intermediate class. 8c7ea12399
  • W12 · Mar 18
    Package-boundary checking can now cover types used by as and ?as, which must be deployed because these expressions resolve a runtime type structure. The new package_allow_as_expression_violations carveout defaults to true for migration; setting it to false enables hard errors. 872d098c0d
  • W13 · Mar 26
    The pre-stable HH\Runtime\RepresentableAs<T> type now exists in HHVM's runtime systemlib as well as the typechecker HHI. HH\Runtime\reveal<T>() safely unwraps it to T; the operation is an identity at runtime because the newtype's representation is already T. 4b854c96a6
  • W14 · Mar 30
    The pre-stable typed-local declaration syntax was removed from the parser, HackC, typechecker, IDE actions, and experimental-feature registry. Projects experimenting with let T $x must return to ordinary local assignments. 599dea0aa0 68b41e1558
  • W14 · Mar 30
    The opt-in stricter __ConsistentConstruct rollout now warns on abstract-final classes, which cannot be instantiated through new static(). ae16b6ede2
  • W14 · Mar 31
    Calls using pre-stable named arguments no longer need a file-level feature attribute, although defining named parameters still does. This reduces call-site migration friction without completing the feature's rollout. 81144c312a
