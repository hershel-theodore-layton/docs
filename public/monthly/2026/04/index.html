Highlights

8 changes
  • W14 · Apr 1
    Type errors involving UNSAFE_CAST now retain the original expression's provenance while still identifying the cast, improving diagnostics without walking the full reason chain. 51fa340ff1
  • W16 · Apr 14
    hh_client and hh_single_type_check now support --enforcement-at-pos-batch, which reports whether HHVM enforces the type at each requested source position and returns the concrete enforced bounds where applicable. It covers declarations as well as call arguments, returns, property assignments, constructors, and array indices. 985a6cb528
  • W17 · Apr 21
    Go-to-definition on nameof SomeTypeAlias now navigates to the alias declaration instead of incorrectly resolving through typename to the HH\string HHI declaration. f0c1da1d2a
  • W17 · Apr 23
    Runtime tests with an abstract <<__Enforceable>> type constant are now allowed even when its as bound is not itself enforceable; a concrete implementation can still provide an enforceable type. edc62dc1c2
  • W17 · Apr 23
    Nullable ?as no longer triggers package-boundary diagnostics. Unlike as, a failed ?as yields null rather than fatalling, so it does not require the asserted type to be available across the boundary. 13a5c1efc4
  • W18 · Apr 27
    The contexts and capabilities manual now states the key calling rule explicitly: a context list describes the callee's requirements, and the caller must provide a capability set containing them. An omitted list means [defaults]; [globals, ctx $f] requires both globals and whatever the callback requires rather than granting either capability. 7ee1c54c3c ace7b77acc
  • W18 · Apr 27
    The manual now documents how enforceable generic upper bounds affect runtime checking, including when several enforceable bounds contribute to the check. 63fa7dabb5
  • W18 · Apr 28
    The revised coeffects manual now explains capability subtyping in the correct direction: a callable requiring fewer capabilities is usable where one requiring more was accepted. For example, a function requiring [read_globals] or [] can stand in for (function()[globals]: void), because callers prepared to supply globals can satisfy the narrower requirement. af05be4b70

Breaking Changes

14 changes
  • W14 · Apr 1
    The enable_abstract_method_optional_parameters option has been removed after the feature's rollout. optional parameters on abstract methods are now accepted unconditionally; remove the obsolete setting from project configuration. 404b18c259
  • W16 · Apr 13
    More standard-library declarations now use their concrete runtime types instead of HH\FIXME\MISSING_*_TYPE: apache_setenv() returns bool, and a large set of Intl functions now have concrete return types. Code that relied on these APIs being effectively untyped may gain type errors. 2531f61026 85b373a37f
  • W16 · Apr 14
    Built-in declarations for ICU, IntervalTimer, OpenSSL, and file APIs now replace many missing parameter and return annotations with concrete types matching their implementations. This improves inference but can expose calls that previously flowed through an effectively untyped signature. a6c59630b8 4b503a24a7 9e5cfbd2ba 9e2dfa95ca
  • W16 · Apr 15
    The standard-library HHI cleanup now gives concrete types to process, POSIX, zlib, bzip2, math, cURL, APC, array, output-buffering, multibyte-string, and network APIs. Expect stronger return inference and possible errors where callers passed values that the old HH\FIXME\MISSING_*_TYPE placeholders accepted. 3c04556fba 0272e4b014 f046e9836b 2a767b8e7c 1cdffbf5a7 250c92cb6d 25c06b37a8 0422f445b7 ac3aeb093e ea542c231f 08104dcc6d
  • W16 · Apr 16
    Intl HHI declarations now give concrete parameter types to Collator, date formatter, message formatter, number formatter, resource bundle, calendar, timezone, grapheme, and break-iterator APIs. Calls that depended on the previous missing parameter types may now fail type checking. 7a015e0bdb
  • W17 · Apr 20
    Fileinfo, mailparse, and Async MySQL declarations now replace additional missing HHI types with concrete runtime signatures. b10a40ecb8 750d2077d0 edf0a3bfbc
  • W17 · Apr 20
    is expressions now validate their right-hand type even when the expression is not being used to refine the left-hand side. Invalid type hints that previously escaped localization now produce errors. 8b49bb1304
  • W17 · Apr 20
    Inherited class, classname, and string return constraints now apply the same configuration-controlled warnings, errors, and class-to-string conversions as directly declared constraints. Projects relying on the previous inherited-constraint gap may see new runtime diagnostics or failures. 14aceb719a
  • W17 · Apr 22
    Memcached HHI declarations now give concrete types to 27 methods, including boolean operation results, getResultCode(): int, getResultMessage(): string, and a nullable-string constructor argument. 3b7f6b9fb4
  • W17 · Apr 22
    A new Warn[12042] reports property access through dynamic, including dynamic intersections and supportdyn wrappers. This mirrors the existing warning for dynamic method calls and may affect projects that promote warnings to failures. faa70e09f3
  • W17 · Apr 23
    Higher-rank generic validation now traverses nested types when looking for escaping type parameters. Invalid escapes that were hidden below the top level can now be reported. 653e481d9c
  • W17 · Apr 23
    Reflection declarations now expose concrete types for Reflection::getModifierNames(), ReflectionFunction::isDisabled(), and several ReflectionProperty queries. This improves inference and can reject callers that relied on the previous missing types. 64fd36da55
  • W18 · Apr 29
    Returning a value from a generator is now a parser error (Parsing[1002]) instead of a later NAST-check error. HHVM therefore rejects such code even when it is compiled without a full typecheck; generators always complete with null. 89a5c434fc 32080e91f0
  • W18 · Apr 30
    Package-boundary checking for non-null as expressions now descends into shape field types, including nested shapes and shapes inside tuples. Strict package configurations can therefore report cross-package asserted types that were previously missed; nullable ?as remains exempt. 879b436c9d

Future Changes

13 changes
  • W15 · Apr 12
    Under the preview readonly feature, HH\Readonly\as_mut() checking now recursively applies the same value-type rules as HH\Readonly\is_value_type(). Nested structures containing non-value data, such as a shape containing a closure, are rejected statically instead of passing Hack and failing at runtime. f271a6466c
  • W16 · Apr 15
    The experimental with_refinement_alias feature now permits I with { type T = ... } on the right-hand side of type aliases and type constants. It remains pre-stable and still disallows such refinements in is and as expressions. 23e4d7e770
  • W16 · Apr 17
    HH\TypeStructure now declares the optional with_refinements field produced for refined types, including whether each refinement is a context and its equality, upper-bound, or lower-bound data. This accompanies the still-experimental type-alias refinement work. 10b493a51a
  • W17 · Apr 20
    The experimental TypeStructure representation for refinements now correctly types as and super entries as vec<mixed>, since a refinement may carry multiple bounds. 7713c28719
  • W17 · Apr 21
    Parser and AST support has landed for unstable class and interface aliases such as class C = D; and interface I = D;, including generic syntax. The feature is gated by class_aliases_everywhere and is not yet stable for production use. 314b03ace4 0150d9ae67
  • W17 · Apr 22
    The manual now documents Preview-stage recursive case types, including guarded and mutual recursion and the current limitation around single-variant shape definitions. e2f872bce4
  • W17 · Apr 23
    The experimental type-alias refinement checker now looks through aliases when rejecting refinements in is, as, and reified-generic positions, closing a way to hide an unsupported refinement behind a typedef. 59f35936dd
  • W18 · Apr 28
    The unstable class-alias pipeline now reaches HackC: aliases are emitted as .class_alias Alias = Original; records with a corresponding class reference. Generic arguments are parsed but are not propagated to HHVM; only class or interface renaming is supported. 32dff62192
  • W18 · Apr 28
    The manual now includes an initial guide for the experimental require this as trait constraint. 742d1cba0d
  • W18 · Apr 29
    Type-constant super bounds have moved from Preview to Ongoing Release. They no longer require per-file unstable-feature enablement, but remain pre-stable while the rollout continues. 81c412b911
  • W18 · Apr 29
    RepresentableAs has moved from Unstable to Preview. 451c9c875a
  • W18 · Apr 29
    The manual now documents the experimental named_parameters feature, including that named parameter names are part of the API and must be preserved by overrides and function types. 75d958cfed
  • W18 · Apr 30
    A staged package check can now diagnose cross-package type aliases used at runtime-enforced positions such as parameters, returns, properties, regular enum bases, and generic upper bounds. The main package_allow_enforceable_type_alias_violations switch still defaults to allowing these uses, so this is rollout groundwork; a secondary relief switch can exempt aliases that resolve to class-like types if needed. bfa29842f8 2433ee724c

Security

4 changes
  • W16 · Apr 13
    EXIF parsing now clears stale allocation state after an out-of-memory failure, preventing the cleanup-time use-after-free tracked as CVE-2026-23867. The same resynchronization also fixes overflow and pointer-lifetime bugs in Vector::splice(), Memcache Unix sockets, IPv6 socket scopes, and stream socket peer addresses. 4242fe4f88
  • W17 · Apr 22
    popen() and pclose() now obey the same AllowExec and AllowUngatedExec process-execution gates as exec(), system(), and proc_open(). Deployments that disable either gate will now reject these shell-pipe APIs too. d33c8c0de0
  • W18 · Apr 28
    ZipArchive::getFromName() and getFromIndex() now reject requested lengths and stored entry sizes above the signed 32-bit range before passing them to a 32-bit string buffer, preventing truncation from becoming a buffer overflow. Oversized reads return an empty string. d27c559a44
  • W18 · Apr 30
    HHVM's reference-count optimizer now models the reified-generics vec passed to NewRClsMeth and NewRFunc as an ownership transfer. This prevents it from deleting a required increment and causing a use-after-free when the resulting callable is released before another use of the same generics vector. 24fd5d8e9b
