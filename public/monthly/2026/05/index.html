Highlights

11 changes
  • W18 · May 1
    Redundant __PackageOverride analysis can now verify dependency-graph candidates against their typed syntax, excluding references such as nameof, ::class, and attributes that do not affect the production build. This makes package-override linting less prone to conservative false positives. f41333f091
  • W18 · May 3
    The Hack manual now documents null-safe pipes, tuple splatting in function calls, and the distinct read, append, update, and out-of-bounds behavior of keyset subscripts. 9413aef365 b47447cf10 646cd890cf
  • W19 · May 4
    The class manual now gives a consolidated account of public, protected, private, internal, and protected internal, including constructor-promoted properties and visibility rules for overrides. e750dcbdf6
  • W20 · May 11
    Date/time APIs now expose substantially more precise types: DateTime::add(), sub(), and setTimezone() return DateTime; diff() returns DateInterval; DateTimeZone::getOffset() returns int; and the corresponding procedural helpers no longer return mixed. 6d919856b8
  • W20 · May 13
    Package lints 5655 and 5656 now report cross-boundary references even when the caller has __SoftRequirePackage for the target's original package. Soft loading does not make an override edge or class-pointer edge structurally valid. 34397692a5
  • W20 · May 13
    AsyncMysqlConnection::getSslVersion() returns the TLS version negotiated for the connection, or an empty string when unavailable. Its declaration omits a capability list and therefore requires [defaults]. 6d84b0bce8
  • W20 · May 14
    When a foreach target attempts to reassign a variable used by a dependent capability such as [$v::C], error 4404 now points at the offending target variable rather than the entire foreach expression. This is a position fix; it does not change the capability requirement. 584dc969b8
  • W21 · May 19
    hh --infer-dynamic FUNCTION and hh --infer-dynamic-as-data FUNCTION infer candidate types for local dynamic values from how they are called, indexed, traversed, awaited, and refined. The server returns JSON solutions; the as-data form favors shapes and vectors for data-like access patterns. e3ecb1cc09 5e30b94a43 4268ce9b9a e766c827f9
  • W21 · May 20
    The VS Code debugger now loads its startup document while the sandbox source root is active. Debugger REPL expressions can therefore resolve classes and class constants from the local checkout instead of accidentally initializing the autoloader against the deployed tree. 1111b878a7
  • W22 · May 26
    The Rust declaration provider received correctness fixes for class/type name collisions, trait __Override diagnostic positions, and descendant invalidation. In particular, unchanged shallow declarations are retained so stale remote declarations cannot suppress required fanout. 5f7f1b1004 92a95e3bf4 e40ada60a0
  • W22 · May 27
    Symbol indexing no longer drops static-property references such as Class::$property, self::$property, and static::$property. Target-use queries and tools backed by the Hack index can now find those xrefs. 85d45051d3

Future Changes

17 changes
  • W18 · May 1
    Preview HH\Runtime\reveal() is now explicitly pure ([]). This narrows its caller requirement from omitted brackets—which mean [defaults]—to no capabilities, so it can be called from pure code; representable_as itself remains in Preview. 6cbf331237
  • W18 · May 3
    Shape-field punning now has manual examples, including shorthand construction and pattern-like field reuse. The shape_field_punning language feature remains Unstable. 358b5ca388
  • W19 · May 5
    Preview expression trees can now desugar vec[...], dict[...], and keyset[...] literals through visitVec, visitDict, and visitKeyset. The support is gated by expression_tree_hack_arrays. b8379a88ac
  • W19 · May 5
    The staged named-parameter runtime now has dedicated function entries for optional named parameters and can initialize their defaults consistently in the interpreter and JIT, including coeffect checks after initialization. Named parameters are not yet Released. 4214c0a6a3 e313bccd11 585ae3ac58 ff5c55a8d2
  • W19 · May 6
    Sealed methods no longer require an unstable-feature declaration at their use site. The feature is still classified as OngoingRelease rather than Released, so projects should continue to treat it as pre-stable. 2017c9b602
  • W19 · May 6
    Named parameters moved from Unstable to Preview in Hack's feature registry. This broadens the intended testing audience but does not make their syntax or behavior stable. 8d1b4f3f5d
  • W20 · May 11
    DateTimeImmutable::createFromFormat() is now typed as the pre-stable case type BoolOrDateTimeImmutable, accurately representing its false failure result without falling back to mixed. 6d919856b8
  • W20 · May 12
    Experimental constraint-based method-call inference now honors <<__IgnoreReadonlyError>> on callable parameters, including nested lambda return comparisons. 108d91d898
  • W20 · May 12
    Unstable shape and tuple destructuring now has dedicated parser and AST nodes for patterns such as shape('x' => $x) = $value and tuple($x, $y) = $value. Typing and emission were still landing separately. 3f5a8d867a
  • W20 · May 13
    The accepted named-parameters HIP is now published with the proposed syntax, ordering and compatibility rules, reflection model, and rationale. Named parameters remain in Preview. c9337aa404
  • W20 · May 13
    Unstable shape and tuple destructuring can now be typechecked, including its interactions with subtyping, dynamic, and like types. Runtime emission was still pending on this date. 4343f5bcae
  • W20 · May 14
    The __NeedsConcrete HIP is now published, documenting the proposed Safe Abstract contract for static methods that may only be called through a concrete class. The checks still require needs_concrete=true. 75d4d868bb
  • W20 · May 15
    The shape-and-tuple-destructuring HIP is now published, covering pattern syntax, typing, runtime behavior, evaluation-order constraints, and the intended migration away from permissive list(...) destructuring. The feature remains Unstable. defc97a3eb
  • W21 · May 19
    HackC can now emit bytecode for unstable shape and tuple destructuring. Together with the parser and typechecker work from earlier in the month, the basic staged implementation now spans the frontend and runtime. 4c20e78881
  • W21 · May 22
    Preview RepresentableAs now refines case-type variants correctly across files and accepts structurally compatible generic and dependent types through their bounds. This fixes cases where RepresentableAs<int> or tuple-backed variants previously degraded to mixed or failed subtyping. 0626e4c354 d1836b6ae6
  • W21 · May 23
    ReflectionParameter::isNamed()[] reports whether a parameter uses Preview named-parameter syntax. Positional parameters return false; named parameters, including optional ones, return true. a53d527ec7
  • W22 · May 28
    Hack declarations now expose the pre-stable case types HH\Runtime\BoolOrInt, BoolOrString, BoolOrFloat, and BoolOrNum for accurately typing legacy PHP APIs that return false on failure. f24aafecb8

Breaking Changes

11 changes
  • W18 · May 3
    The typechecker no longer gives HH_FIXME\MISSING_TYPE_IN_HIERARCHY special Tany treatment. Remove remaining uses of this obsolete migration type and replace them with accurate declarations; a project-defined alias with that name now behaves like an ordinary alias. 0a3657f7e7
  • W19 · May 5
    ReflectionMethod::invoke() and invokeArgs() are now deprecated in Hack declarations. Migrate reflective call sites to HH_FIXME::reflectionMethodInvokeForCallsite() and HH_FIXME::reflectionMethodInvokeArgsForCallsite() while removing avoidable reflection. 5d4b0335e7
  • W19 · May 7
    __AutocompleteSortText and its rollout configuration have been removed. The attribute no longer influences IDE completion ordering, and projects should delete it rather than relying on custom sort prefixes. 912edca7b3
  • W20 · May 11
    DateTime::diff() now accepts DateTimeInterface rather than mixed. Calls whose argument is still statically mixed must refine or validate it before calling; this aligns Hack's signature with the runtime check that already existed. 6d919856b8
  • W20 · May 13
    The package_allow_reifiable_tconst_violations and package_allow_all_generics_violations configuration escape hatches have been removed. Reified type-constant and generic package-boundary violations are now always hard errors. 8a12a927f2
  • W20 · May 14
    package_allow_typedef_violations has been removed. Transparent type aliases that cross an unavailable package boundary now always produce a hard error, and their referenced symbols count as production-affecting edges. b96d110f20
  • W22 · May 26
    hh_server, hh_single_type_check, and hh_single_decl now use the Rust provider backend by default where supported. The positive hh_single_type_check --rust-provider-backend flag has been removed; use hh_single_type_check --config rust_provider_backend=false for a temporary shared-memory fallback, or hh_single_decl --no-rust-provider-backend for that tool. a7830e409b
  • W22 · May 26
    Conditions are now always checked against ~bool, and check_bool_for_condition has been removed. Projects that disabled the check or requested warning-only mode must migrate truthy values to explicit tests such as non-null, non-empty, or non-zero comparisons. 015f0e5ae7
  • W22 · May 27
    ReflectionParameter::isArray() has been removed. Inspect getType() or getTypeText() instead; the old predicate discarded generics and other source-level type information. 0dc0df841c
  • W22 · May 28
    ReflectionClass::newInstance() is now deprecated in Hack declarations. Migrate unavoidable reflective construction to HH_FIXME::reflectionClassNewInstanceForCallsite() and prefer direct constructors where possible. 0eaf6710f2
  • W22 · May 29
    ReflectionParameter::getClass() has been removed because it inferred only a partial view of the parameter type and ignored upper bounds. Use getType() or parse getTypeText() when source-level type syntax is required. 2d70a67585
