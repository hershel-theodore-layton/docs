Highlights

22 changes
  • W27 · Jul 2
    Open-source HHVM no longer collects its low-level per-request JIT and interpreter timing measurements. On platforms where reading current-thread CPU time requires clock_gettime(), collecting these measurements consumed about 37% of CPU time during JIT warmup; removing them avoids that overhead. e412a40b27
  • W28 · Jul 8
    Hershel's HHVM now includes a Ubuntu 24.04 Noble build script. The repository now includes a clean-container build entry point and Debian metadata for regular, nightly, debug-symbol, and development packages; this package build identifies the runtime as HHVM 26.6.5. e8b37975a0
  • W28 · Jul 8
    Hack enum hints now participate in predicate-based is/as refinement, including the legacy numeric-string behavior of enum checks and sound-dynamic builtin pessimization. 99592e454f
  • W28 · Jul 9
    Build support has landed in Hershel's HHVM for Ubuntu 26.04 Resolute. ./build.sh --ubuntu-26.04 selects it, with bundled PCRE and libdwarf compatibility work for the newer distribution; Ubuntu 24.04 remains the default. 0a1acba1cb
  • W28 · Jul 9
    Incremental typechecking now rechecks descendant classes when a parent member gains or loses __TestsBypassVisibility, keeping override and private-shadowing diagnostics up to date. 2d646e5e23
  • W29 · Jul 14
    HHBBC no longer removes unused increment or decrement operations that can throw, such as incrementing a null value, preserving exceptions in optimized repositories. 3233b87b44
  • W29 · Jul 15
    HHBBC preserves unused compound arithmetic operations that can throw, including division or modulo by zero and non-numeric operands. A fractional modulo divisor that truncates to zero is also handled safely. 057bffc3ee
  • W29 · Jul 17
    Case types may combine an object variant with class<T>: the typechecker now recognizes class pointers as disjoint from objects. Class-pointer variants still overlap strings during the ongoing class-pointer migration. 9067cd722c
  • W30 · Jul 20
    DNS response parsing now bounds compressed-name expansion by the actual response length, fixing an uninitialized-memory disclosure when processing malformed DNS records. 43a1cce7f4
  • W30 · Jul 22
    Packages can opt into stronger boundaries with enable_strict_isolation=true in PACKAGES.toml. Dynamic package observation through package expressions and __RequirePackage/__SoftRequirePackage is rejected for these packages. aae1d23bb6
  • W30 · Jul 22
    Strict-isolation packages enforce their boundaries even for paths covered by package_exclude_patterns. Non-excluded code also cannot reference excluded-path code inside the strict package. 8466c8e6b6
  • W30 · Jul 22
    User attribute classes from strict-isolation packages now receive cross-package access checks, including attributes on functions whose effective package must be established before checking them. cb537175eb
  • W30 · Jul 23
    Hershel's HHVM has optimized the implementation of HH\Lib\Vec\slice, a hot function in portable-hack-ast-linters. This reduces whole project lint latency by ~30%. Improvements scale more than linearly with the size of the file being linted. Projects with larger files may see a greater improvement. This change is included in hersheltheodorelayton/hhvm-full:26.06.05. See also HHVM issue for perf on the hhvm repo. b983bd51b1
  • W30 · Jul 23
    Strict-isolation package boundaries now apply to class and alias references throughout type hints, including nested type arguments and inheritance declarations. acdcb7f349
  • W30 · Jul 23
    C::class references into strict-isolation packages now produce hard package-boundary errors instead of only migration lints. 1d9d645d5f
  • W30 · Jul 23
    nameof C and exception-class references in catch now respect strict-isolation package boundaries, including excluded-path restrictions. f39c87984b
  • W30 · Jul 23
    Predicate-based refinement now understands runtime-checkable reified type parameters, enforceable abstract type constants such as this::TC, and this itself. 6c2e8cda7f
  • W30 · Jul 23
    HH\class_or_classname<T> is now a covariant opaque type accepting both class<T> and classname<T>. Related Facts APIs use it so callers can pass either representation. e9914ef5cf
  • W31 · Jul 28
    HHVM publishes profiling prologues only after their translation metadata has been installed, fixing crashes during profile-guided prologue regeneration. b679ec1fff
  • W31 · Jul 29
    The bundled libgd GIF decoder initializes its LZW tables correctly, fixing an uninitialized-memory disclosure associated with CVE-2017-7890. 23cfa7784a
  • W31 · Jul 31
    The native saved-state loader now detects incomplete cached states, removes the incomplete cache entry, and downloads a fresh copy instead of failing when a required artifact is missing. d425de3a08
  • W31 · Jul 31
    HH_TMPDIR now controls the native saved-state cache location, consistently with the typechecker's other temporary files. 08797dc741

Breaking Changes

12 changes
  • W27 · Jul 2
    wordwrap() now throws InvalidArgumentException for an empty break string or a zero width with forced cutting, instead of emitting a warning and returning false. 34e33d25f6
  • W28 · Jul 9
    The $_REQUEST superglobal has been removed, together with Eval.DisableRequestSuperglobal. Read request parameters from $_GET and $_POST as appropriate. e9cb94b3ae
  • W28 · Jul 9
    The $_COOKIE superglobal and automatic Cookie-header parsing into it have been removed, together with Eval.DisableParsedCookies. The raw request header and parse_cookies() remain available. e6ac19eb7a
  • W28 · Jul 9
    Storing a meth_caller in APC now always throws, including when nested in a container. Eval.ForbidMethCallerAPCSerialize no longer permits a warning-only or permissive mode. 87298f974e
  • W28 · Jul 9
    HH\dynamic_fun() now always throws InvalidArgumentException when its target lacks <<__DynamicallyCallable>>; Eval.DynamicFunLevel no longer permits the call or reduces it to a warning. 70fc6271ce
  • W28 · Jul 10
    String concatenation now always throws on disallowed implicit string coercions instead of permitting warning-only or permissive behavior through Eval.NoticeOnCoerceForStrConcat. Integers and strings remain supported. eda918a5d9
  • W28 · Jul 10
    The left operand of .= now always throws on disallowed string coercion; the Eval.NoticeOnCoerceForStrConcat2 rollout option has been removed. 92c8ae13c2
  • W28 · Jul 10
    Implicit conversion of an object to a string no longer invokes its __toString() method; HHVM throws TypecastException instead. Call __toString() explicitly when that conversion is intended. ba521c3324
  • W29 · Jul 13
    Assignments cannot be used as expressions, and Hack.Lang.DisableLvalAsAnExpression can no longer restore that syntax. The parser reports Assignments can no longer be used as expressions. 04ed8194b9
  • W29 · Jul 15
    Numeric literals containing underscore separators, such as 1_000, are no longer accepted. Remove separators from integer and floating-point literals. e05fa0d5ca
  • W30 · Jul 21
    HH\is_vec_or_varray() and HH\is_dict_or_darray() have been removed. Their direct replacements are HH\is_vec() and HH\is_dict(). 911cd41801
  • W30 · Jul 23
    Case-type disjointness now treats Hack enums as arraykey, rejecting combinations with other integer or string variants that enum is checks cannot reliably distinguish. c38b6f7d06

Future Changes

2 changes
  • W28 · Jul 7
    Function type hints can describe variadic named arguments using syntax such as (function(int, named string...): void). The initial implementation requires named_variadic_type=true; call checking and subtyping support follow later in the release cycle. 4315b4c024
  • W30 · Jul 21
    Opt-in variadic named parameter types now support call checking and function subtyping. Unexpected argument labels can be absorbed by a named variadic, whose element type is checked, rather than causing spurious missing-argument errors or internal typechecker errors. adc7faffa3
