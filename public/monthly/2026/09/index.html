Highlights

20 changes
  • W36 · Sep 1
    HHVM avoids a crash when an external-thread task result invokes HH\Asio\join() on that same task during deserialization, such as from __wakeup(). A task already being processed cannot be re-entered or cancelled as though it were still waiting. fe5bf06c3c
  • W36 · Sep 1
    Facts symbol-to-file lookups avoid constructing an unnecessary filesystem path before returning the resolved filename. 1e7673c9fb
  • W36 · Sep 2
    Uncaught internal failures in hh_client now use exit status 221 rather than the type-error status 2. Malformed key-value command-line arguments use status 64 and no longer print a backtrace. bab52cef3d 3148255d19
  • W36 · Sep 3
    If a saved-state dependency graph disappears before a worker opens it, hh_server reports an unavailable graph and the monitor can restart it to restore the graph, instead of panicking through the dependency-query FFI. 838b5ecfe8
  • W36 · Sep 4
    The analysis command --find-isolatable-clusters discovers seed files with no incoming references; --json exposes the seed paths and count for scripts. This initial discovery does not yet compute complete movable clusters. ee4c52b940 fa20924e45
  • W37 · Sep 9
    Setting Eval.AllowManualGC=false makes gc_collect_cycles() skip collection. Manual collection remains enabled by default. bb180afe2e
  • W37 · Sep 10
    The typed AST now records the correct classname<T> or class<T> result on HH\type_structure_classname() and HH\type_structure_class() calls, avoiding spurious invalid-comparison warnings from checks that read the expression annotation. b9e0ca8265
  • W37 · Sep 11
    Outside repo-authoritative mode, inherited private properties annotated with <<__TestsBypassVisibility>> can now resolve correctly on subclass instances when the calling test context is authorized to bypass visibility. 55d22e2551
  • W38 · Sep 14
    serialize() accepts an options dictionary, including zstd=true; HH\serialize_with_options() and unserialize() also support streaming zstd compression or decompression. This avoids materializing the full uncompressed serialized string at once. 35e214ff7a
  • W38 · Sep 14
    HH\ImplicitContext\PreparedContext::runBatch() and runBatchAsync() no longer fail with a coeffect violation before running callbacks with [] or [zoned_shallow] contexts. Their shared preparation helper now declares [leak_safe]. 1d894fd5cc
  • W38 · Sep 18
    The new HH\BlobKV\Reader and HH\BlobKV\Writer APIs read and write binary key/value data in Blob containers. Writers require explicit finalize(), enforce a single in-progress writer per output path, and are rejected in repo-authoritative mode; readers remain available there. d3cbd3bacb
  • W39 · Sep 21
    HHVM fixes an allocation/free size mismatch for shared logging arrays wrapping arrays with a string-key table, which could pass an interior pointer and incorrect allocation size to jemalloc. 3514f777ed
  • W39 · Sep 25
    Under implicit pessimization, functions and non-overridable methods returning vec<mixed>, dict<arraykey, mixed>, vec_or_dict<arraykey, mixed>, or keyset<arraykey> can retain those exact return types as fully runtime-enforced top container types. Overridable methods retain pessimization so narrower element-type overrides remain sound. 1a3b9802b4
  • W39 · Sep 25
    Explicit reified type arguments on parent instance-method calls such as parent::method<int>() are now preserved by the typechecker, avoiding false missing-type-argument errors. ee3fbe441c
  • W40 · Sep 28
    Typed open shapes are now enabled by default through typed_open_shapes=true. Normalizing supportdyn over open shape tails also correctly distributes union tails. b60a3f7001 5ba371e121
  • W40 · Sep 28
    A new warning detects expressions typed dynamic returned through an explicitly declared return type that is not fully enforced at runtime. Fully enforced and like-typed return positions, including async return-value enforcement, are exempt. 64f7043e62
  • W40 · Sep 28
    --validate-isolation <file> checks a candidate list of repo-relative file paths against a temporary strict package and reports boundary violations. Exit statuses distinguish a successful check (0), violations (2), and unknown or overridden input paths (10); --json provides structured output. b3a8b8384f
  • W40 · Sep 29
    Hershel's HHVM 26.09.29 build now passes the selected JOBS limit through dependency builds, Cargo, OPAM, CMake, and the Hack Dune build. The runtime and Debian package version are reported as 26.9.29. d647defffa8 1467c534ea
  • W40 · Sep 29
    Debian package builds can preserve the existing build tree with HHVM_INCREMENTAL_BUILD=1, avoiding the normal clean step. d51b53256c 673255ed70
  • W40 · Sep 29
    The Ubuntu build script pins Rust to nightly-2026-08-24, and the Debian rules resolve the compiler through rustup, keeping the Hack build on a toolchain that supports its box patterns. Source dependency builds also set the CMake policy minimum to 3.5 for compatibility with CMake 4. 2530b1b13e 6da7c58a96

Future Changes

    A draft proposal documents limited variadic named parameters for typed mocking, including accepting additional named arguments without exposing them in the function body. This commit changes the proposal only; the prototype remains behind the default-off named_variadic_type and variadic_named_parameters typechecker options. 46a19fe934
  • W36 · Sep 2
    Function-type displays now print optional named in the order accepted by the parser, making displayed hints easier to copy into source. c66ce9b3dc
  • W36 · Sep 3

  • W36 · Sep 3
    The variadic-named-parameter proposal now specifies contravariant argument acceptance correctly and documents its memoization and readonly restrictions. These are proposal edits, not newly enabled language features. b5adffd627 0044eee66e
  • W36 · Sep 3
    Experimental named-variadic subtyping now checks an explicit optional parameter against the expected named-variadic type when that parameter shadows the implementation’s variadic, preventing incompatible functions from being accepted. e41f9dc708
  • W36 · Sep 4
    IDE autocomplete now suggests unused optional named argument labels as well as required ones, ordering required labels first and preserving declaration order within each group. a6237234b5

  • W37 · Sep 9

The class_pointer_array_literal_keys and class_pointer_array_write_keys rollout levels remain zero by default. 2f116d635b 0f74e9d033
  • W38 · Sep 16

  • W38 · Sep 16
    The runtime and typechecker expose HH\implicit_package_family_exists() and HH\get_all_implicit_package_families() for configured implicit package families. Family availability follows hard deployment membership, while enumeration returns declared family paths and dependencies without materializing member packages. 1ae3ff4005
  • W38 · Sep 18
    The typechecker temporarily rejects named parameters on <<__Memoize>> functions and <<__Memoize>>/<<__MemoizeLSB>> methods with NastCheck[3113], because their generated wrappers can fail at runtime. Make the parameter positional or remove memoization. The restriction remains in HHVM 26.09.29 even after the runtime fix on September 22. b74f9bcdca
  • W39 · Sep 21
    Named callback arguments now participate in the same staged lambda-inference passes as positional arguments, removing inference failures that depended on argument order. Function subtyping also keeps named parameters out of positional variadic and type-splat tails. e620163247 d708f251ce
  • W39 · Sep 21
    HHVM now compares named method parameters by label and optionality separately from positional parameters. This accepts implementations with extra optional named parameters and rejects missing parameters or incompatible inout positions that combined slot counts could conceal. 7cb12ea0ef
  • W39 · Sep 21
    Runtime checks now keep reordered named parameters paired with their original type hints and defaults. Readonly checks also bind passed arguments to the correct parameter when optional named arguments are omitted, fixing both false rejections and missed violations in the interpreter and JIT. d9825e5b77 9fed0ff97f
  • W39 · Sep 22
    Explicit null supplied to an optional named parameter is now preserved instead of being replaced by its default, including under repo-authoritative optimization. 3255cabee6
  • W39 · Sep 22
    Readonly argument flags now follow the same reordering as named argument values, including constructor calls, fixing incorrect acceptance and rejection of calls. 3dac710c75
  • W39 · Sep 22
    Memoization wrappers now order and forward named parameters correctly, fixing runtime failures for memoized functions and methods. The temporary typechecker restriction from September 18 remains active; this commit does not yet make the combination available to normally typechecked code. d3597e3fe5

  • W39 · Sep 24

  • W39 · Sep 24

Breaking Changes

5 changes
  • W37 · Sep 7
    Computed property and method access now requires a receiver that is a subtype of dynamic under ordinary subtyping. A concrete value merely compatible with dynamic no longer suffices. Nullsafe access permits the nullable arm while checking the non-null receiver; failures use Typing[4524] instead of Naming[2011]. dea7d004c3
  • W38 · Sep 14
    Files assigned to implicit packages by their paths may no longer use __PackageOverride to escape that membership. 51094a61e4
  • W38 · Sep 18
    Packages must opt into deployed-package checks with allow_deployed_packages_checking=true before code can use package, __RequirePackage, or __SoftRequirePackage for them. This flag cannot be combined with enable_strict_isolation. The separate prohibition based only on a soft-include edge is removed; ordinary strict-inclusion checks still apply. 55e411dea0 5a43f0ec1f e5f9e4c461
  • W39 · Sep 21
    __PackageOverride is also rejected when a file physically belongs to an explicit package with strict isolation, closing the same escape route already blocked for implicit packages. e48e4b7856
  • W39 · Sep 23
    Dynamic string-to-class references to classes in strict packages now receive an independent strict-package check in the interpreter, JIT, and native class APIs. raise_dynamic_class_load_error defaults to true for strict packages; explicit false selects sampled notices. __DynamicallyReferenced does not bypass this policy. cb6bca1916 8eecec3bf1 9495634c20 aaef0e6260
