Week 46: Nov 14–Nov 20, 2022

15 noteworthy changes, organized by the source changelog sections.

DayWeekMonth

Breaking Changes

4 changes
  • Mon, Nov 14
    Module boundary violations are now always enforced with exceptions; the Eval.EnforceModules switch and its disabled/warning modes have been removed. Soft-internal declarations continue to warn. 2b9440d421
  • Tue, Nov 15
    Class-level user attributes are typechecked outside the class context, so self is no longer available in their arguments. Module-internal names remain usable there when the attribute is evaluated inside the same module. a83ac0b2c2
  • Tue, Nov 15
    DirectoryIterator and FilesystemIterator now iterate over ~SplFileInfo, since extraction flags can make FilesystemIterator::current() return a string or the iterator itself. 7380211047
  • Wed, Nov 16
    Stale HHI declarations for runtime classes and class constants that do not exist have been removed. Several method declarations were also corrected, including ReflectionClass::getTraitAliases(), ReflectionFunctionAbstract::getStaticVariables(), and capitalization/finality mismatches in built-ins. Projects relying on the nonexistent declarations will now receive type errors. f4bc1485be 74f2d68eda 759eb8b13d

Highlights

10 changes
  • Tue, Nov 15
    Expression-tree type inference no longer passes pessimised like-types to makeTree when the virtual expression calls a pessimised function. 6f9d9ad3bc
  • Tue, Nov 15
    The bundled Set declarations now preserve their element type across iteration and common operations such as map, filter, values, and conversions. This should improve inference for projects using legacy Hack collections. f5ea07c6fa
  • Tue, Nov 15
    Dead HH\FIXME\UNSAFE_CAST removal is now integrated with hh_server, including repeated analysis until no further redundant casts can be removed. 097f3c19ad 6ebee6b689
  • Tue, Nov 15
    An internal type alias may now refer to another internal type from the same module. 61917d4bf0
  • Tue, Nov 15
    HH\classname_from_string_unsafe() is now declared in the HHI files. It converts a string to classname<mixed> without eager validity or module checks and is intended only for exceptional migration cases. 385ddd879a
  • Wed, Nov 16
    get_defined_functions() now preserves the declared capitalization of function names instead of lowercasing every result. Reflection calls with those names continue to work case-insensitively. e15e774b91
  • Thu, Nov 17
    Incremental typechecking now correctly fans out changes that add inherited XHP special attributes such as :aria-* and :data-*. Projects should see the same XHP attribute errors without needing a full typecheck. d615fbde45
  • Thu, Nov 17
    HHI global and class constants with an explicit type may now omit their placeholder value. Initializers have been removed from the bundled handwritten declarations and are no longer copied into generated HSL HHIs. This syntax is specific to HHI declaration files and does not change the constants' runtime values. 824ac81dc9 833f6d5fe7 0a1f30494a 80fb463a49 f5f90c7cad
  • Thu, Nov 17
    hh_server now tolerates duplicated and out-of-order Watchman state notifications during source-control updates, reducing the chance of an incorrect server state after an update or transaction. cea00244a1
  • Thu, Nov 17
    When code such as $object->$name attempts dynamic access on a non-dynamic value, naming error 2011 now explains the restriction and offers a quick-fix to ordinary property access such as $object->name. 82df50f9da

Future Changes

1 change
  • Wed, Nov 16
    Lint 5624 no longer incorrectly labels generics used in pre-stable exact type refinements as redundant. 044f44601d
