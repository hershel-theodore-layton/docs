Week 48: Nov 28–Dec 4, 2022

20 noteworthy changes, organized by the source changelog sections.

DayWeekMonth
←Previous week→Next week

Highlights

13 changes
  • Mon, Nov 28
    An experimental .hhconfig option, code_agnostic_fixme, makes an HH_FIXME suppress errors at its position regardless of the recorded error code. It is intended as a temporary aid for migrations such as Sound Dynamic pessimisation, where error codes may change; the default remains code-specific suppression. fe4f7ada87
  • Mon, Nov 28
    Generated hack.TypeInfo symbol facts now contain cross-references for common nested type hints such as Awaitable<?Foo> and vec<Foo>, rather than only for a bare class name. Consumers of symbol-info facts can use these links for more complete type navigation. 0c39bf8718
  • Tue, Nov 29
    Sound Dynamic enforceability checks now resolve this against the enclosing class when interpreting types such as this::T, improving the treatment of method returns, parameters, properties, and class constants that use type constants. 9beeec27c0
  • Wed, Nov 30
    Generic-arity errors are no longer redundantly produced during subtyping after the type has already been localized, reducing duplicate diagnostics. f9c1cb34c4
  • Wed, Nov 30
    Sound Dynamic inheritance checks now model runtime enforcement from a method's declaring signature rather than its instantiated inherited signature. This avoids treating a generic return such as T as runtime-enforced merely because a subclass inherits it as int. 7ff98a81d3
  • Wed, Nov 30
    Symbol-info export now always emits facts for namespace aliases defined in .hhconfig, even when gen_sym_hash is disabled. 59ea67ffd4
  • Thu, Dec 1
    Sound-dynamic checking now treats values captured by a <<__SupportDynamicType>> closure as like-types. This makes nested closures dynamically callable without repeatedly checking every nesting level, though hover and TAST output inside the closure may now show captured T values as ~T. 53d4897785
  • Thu, Dec 1
    The missing-<<__Override>> lint now offers a quick-fix, either adding a new attribute block or inserting __Override into an existing one. 624e58033f
  • Thu, Dec 1
    Go-to-definition and hover now distinguish a callable property from a method with the same name in expressions such as ($object->callback)(). 77fdfabcc6
  • Thu, Dec 1
    DOMElement::$attributes is no longer redeclared as non-null in the bundled HHI. It now inherits the nullable ?DOMNamedNodeMap<DOMAttr> declaration from DOMNode, so callers must handle null. d2bd42ae6c
  • Fri, Dec 2
    Invalid types encountered while localizing where constraints are now reported. This closes a type hole involving generic type-constant accesses and can reveal errors in signatures that previously passed. b614e9be2f
  • Fri, Dec 2
    Pair<T1, T2> is now typed as a ConstVector<T1 | T2>. Collection operations such as at(), map(), values(), and toImmMap() consequently preserve the union of the two element types instead of widening to mixed. dd7ca5fa24
  • Sat, Dec 3
    Bidirectional inference for keyset and dict literals now respects the arraykey bound when the expected type is (Keyed)Traversable or (Keyed)Container. Invalid expected key types no longer cause an out-of-bounds type to be inferred. 833436d8b6

Breaking Changes

3 changes
  • Tue, Nov 29
    Accessing $this where it is not defined now produces naming error 2050 instead of silently receiving an unconstrained type. This closes holes in enum-class member expressions and expression-tree contexts; affected code should pass or reference an explicit value instead. 8ca873e222
  • Wed, Nov 30
    The internal hphp_create_object() declaration has been removed from the bundled HHI files. Projects that called it directly will no longer typecheck and should use newv() instead. 0b947ff90f
  • Sat, Dec 3
    Static properties must now declare public, protected, or private explicitly; Hack no longer silently treats a declaration such as static int $count as public. dc2a79087b

Future Changes

4 changes
  • Wed, Nov 30
    Loose type refinements now participate in variance checking: as bounds are covariant, super bounds are contravariant, and exact refinements remain invariant. Code using preview type refinements may receive new variance diagnostics when a class type parameter appears in one of these bounds. 5a9139188b
  • Wed, Nov 30
    Autocomplete inside traits now suggests the preview require class constraint alongside require extends and require implements. 6052c0bcdf
  • Fri, Dec 2
    A trait and its required class may declare the same private property without producing a spurious ambiguous-access error in the pre-stable require class feature. In this case the declarations describe the same property rather than shadowing one another. 81231622de
  • Fri, Dec 2
    The unstable type-refinement implementation now supports loose as and super bounds, including their subtyping rules. Accessing a type member through an inexact refinement is rejected because the member is not known exactly. The feature still requires the type_refinements unstable-feature opt-in. 1eaa4bece4
