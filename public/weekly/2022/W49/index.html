Week 49: Dec 5–Dec 11, 2022

13 noteworthy changes, organized by the source changelog sections.

DayWeekMonth
←Previous week→Next week

Highlights

9 changes
  • Mon, Dec 5
    A type structure derived from an unbounded type constant no longer exposes class-specific fields such as classname. Add an appropriate classish bound before accessing those fields; an unbounded type constant is treated consistently with one bounded by mixed. ad69f94600
  • Mon, Dec 5
    Hovering over declarations now explains the class, interface, trait, enum, enum class, type, and newtype keywords. d079884920
  • Tue, Dec 6
    The bundled HHI now declares ThriftApplicationException, including its nullable-message constructor, so Hack code can refer to the exception without a local stub. aff8fbdb7e
  • Wed, Dec 7
    The typechecker now rejects trait composition that makes a static member overlap an instance member of the same name. Such code would already fatal in HHVM; the error is now caught during typechecking. 4f5f028f38
  • Wed, Dec 7
    Module names may now contain non-reserved keywords, matching the names accepted for classes. Reserved keywords and XHP-style names remain invalid. 669b93bd1b
  • Wed, Dec 7
    Deployments using native Facts can set Autoload.UpdateSuppressionPath to a sentinel file. While that file exists, Facts skips Watchman-driven updates; relative paths are resolved from the repository root. 5f4a1ae19b
  • Thu, Dec 8
    A new lint reports casts whose target type is already identical to the expression's inferred type. a070d39d1f
  • Thu, Dec 8
    When an enum declaration omits its base type, the parser error now offers a quick-fix that inserts : arraykey. c60763014e
  • Thu, Dec 8
    Reflection no longer converts enum-class labels found in arbitrary user-attribute arguments as though they were memoization metadata. The special conversion is now limited to memoization attributes. 8ba321326d

Future Changes

3 changes
  • Mon, Dec 5
    Unstable type refinements now use dedicated typing error codes: 4468 for access through an inexact refinement, 4469 for unsupported refinements, and 4470 for invalid class refinements. Suppressions written against the former generic error codes may need updating when adopting the feature. c50044fcc6
  • Thu, Dec 8
    Diagnostics for pre-stable type refinements now print refinement syntax with source-like spacing, making displayed types easier to read and copy. 418ef35a32
  • Fri, Dec 9
    The direct-declaration parser now retains pre-stable type-refinement members when they are wrapped as comma-separated list items. Incremental and full typechecking should consequently agree on refined type constants. 4528fb949c

Breaking Changes

1 change
  • Thu, Dec 8
    Iterable::map() and KeyedIterable::mapWithKey() have been removed from their interfaces because their signatures were unsound. Calls through those interface types must use an appropriate concrete collection API or an HSL traversal function. 899d46019f
