Week 50: Dec 12–Dec 18, 2022

17 noteworthy changes, organized by the source changelog sections.

DayWeekMonth
←Previous week→Next week

Highlights

10 changes
  • Mon, Dec 12
    Missing method visibility errors now offer a quick-fix that inserts a visibility modifier. 2b4eb0ad20
  • Tue, Dec 13
    Missing required-XHP-attribute errors now point to the attribute declaration rather than the containing XHP class. df7da6ed99
  • Tue, Dec 13
    An unbounded generic is now treated like a generic explicitly bounded by mixed when accessing type structures. Class-specific fields such as classname require a classish bound. eb806ee50a
  • Tue, Dec 13
    Several HH\TypeStructure fields have more accurate bundled declarations: return_type and value are mixed, while access_list is ?varray<string>. 7926fe9c9d
  • Tue, Dec 13
    Native Facts now coalesces simultaneous update requests behind an already-pending Watchman query instead of scheduling one query per caller. 3db59e7600
  • Wed, Dec 14
    HHVM's binary and compact Thrift serializers now apply parameterized type wrappers, including wrappers nested in container fields. Generated wrapped-field setters are used where nullable fields do not reveal the wrapper class at runtime. 2416be18d2
  • Wed, Dec 14
    The bundled HH\TypeStructure declaration now types param_types and elem_types as ?varray<mixed> instead of leaving their legacy-array generic arguments unspecified. 56002867f6 15721deb25
  • Thu, Dec 15
    Member find-references now narrows its dependency-graph search to descendants that can contain the named member. Results should be unchanged, with substantially less unrelated code searched in large hierarchies. aaf403a3e5
  • Thu, Dec 15
    Hover information is now available for keywords used inside classes, including static, use, and const type. b2e88973ff
  • Thu, Dec 15
    Experimental module-reference checking has been restored after fixing the module cache path that made it expensive. Projects using the feature once again receive its cross-module reference diagnostics. 9345a32382

Breaking Changes

1 change
  • Mon, Dec 12
    Hack command-line tools now distinguish --error-format raw from the former plain-text rendering. Scripts that consume the old output from hh_single_type_check or related single-file tools should request the new --error-format plain; raw now consistently selects the structured raw formatter. d9f4bc6e0c

Future Changes

6 changes
  • Mon, Dec 12
    Type refinements are now accepted by HHVM itself. Source files still need <<file:__EnableUnstableFeatures('type_refinements')>>, but no separate HHVM-side feature gate is required. 32b5df2753
  • Mon, Dec 12
    Experimental module-reference checks were temporarily disabled because of their cost in projects using modules. They are restored on December 15 after the cache path was corrected. 694d3b9b2e
  • Tue, Dec 13
    Calling HH\autoload_set_paths() while native autoloading is active now raises a deprecation notice. Deployments can set Autoload.UserlandEnabled=false to turn such calls into InvalidOperationExceptions and find code that must migrate to native autoloading. 0e45a0afae
  • Fri, Dec 16
    Under everything_sdt, UNSAFE_CAST<TFrom, TTo> is now represented as an upcast to ~TTo, including in the TAST. Tools consuming the TAST should expect the like-type, which reflects that the cast does not provide a runtime guarantee. 90a13f5252
  • Fri, Dec 16
    Private methods in sound-dynamic classes are now checked as dynamically callable, just like non-private methods, because they can still be reached through dynamic or like-typed receivers. This can expose previously missed sound-dynamic errors. 822346b50c
  • Fri, Dec 16
    Implicit pessimisation no longer treats type constants as runtime-enforced by default. Projects experimenting with sound dynamic typing should not rely on a type-constant access alone to enforce the resulting value. f598a1f437
