Week 3: Jan 16–Jan 22, 2023

8 noteworthy changes, organized by the source changelog sections.

DayWeekMonth

Highlights

6 changes
  • Tue, Jan 17
    Several standard-library HHI output parameters now have concrete nullable types. APC success outputs are inout ?bool, while the error-code outputs of msg_send() and msg_receive() are inout ?int. Variables passed to these functions should use the corresponding nullable type and be checked after the call. ff9df89621
  • Wed, Jan 18
    Expression-tree lambdas are now fully inferred during sound-dynamic checking. This fixes spurious constraint errors on expression trees whose inferred type parameter cannot be dynamic. e6189ec286
  • Wed, Jan 18
    More HHI output parameters now describe their results: pcntl_wait() uses ?int, exec() and preg_match_with_error() use dynamic, and the resource collections used by proc_open() and stream_select() are nullable vec_or_dict<resource>. Existing variables passed by inout may need matching annotations. 14b294fef6
  • Fri, Jan 20
    Array-access errors now retain the actual base and index types in typed-AST holes, and inferred KeyedContainer key types are constrained to arraykey. IDE fixes and type-error explanations should no longer suggest impossible types such as KeyedContainer<bool, nothing>. 5519413eb5 01bddda586 59a15c7f27
  • Fri, Jan 20
    The dead-UNSAFE_CAST codemod now omits redundant parentheses for expressions that cannot be captured by surrounding syntax, producing smaller and more idiomatic patches. 952e984837
  • Sun, Jan 22
    Expressions involving a missing class now receive type nothing instead of an unconstrained fresh type variable. This avoids large, misleading inferred unions and reflects that executing the unresolved class reference will fatal, even if its naming error was suppressed. 1a16e3c578

Breaking Changes

2 changes
  • Thu, Jan 19
    HHI declarations must now provide explicit parameter, return, method, and property types. Authors of project-specific HHIs should add real types where known and use an appropriate placeholder only where the declaration truly cannot be typed. 96f6e5b16f
  • Fri, Jan 20
    tls:// stream sockets no longer negotiate TLS 1.0 and instead use the modern TLS client or server method. Connections to endpoints that only support TLS 1.0 will now fail and should be migrated to a current protocol. 083f5ffdee
