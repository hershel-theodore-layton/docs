Week 5: Jan 30–Feb 5, 2023

9 noteworthy changes, organized by the source changelog sections.

DayWeekMonth
←Previous week→Next week

Highlights

8 changes
  • Mon, Jan 30
    The bundled implicit-context HHI now exposes HH\MemoizeOption#Uncategorized, completing typechecker support for the memoization category added earlier in the month. 6593d8379b
  • Tue, Jan 31
    Sound-dynamic hierarchy checks now consider all ancestors, including interfaces inherited through used traits. A class that transitively acquires an SDT interface requirement must itself support dynamic. 810c57c82f
  • Tue, Jan 31
    A trait is now considered to support dynamic only when it is marked <<__SupportDynamicType>> and one of its requirements restricts it to SDT classes. This fixes both false acceptance and false rejection around SDT traits and their consumers. c07151edf9
  • Wed, Feb 1
    Several APC declarations now have narrower capability requirements than their former implicit [defaults]: read operations such as apc_exists() require [read_globals], mutations require [globals], and apc_sma_info() is pure. This allows callers with correspondingly restricted contexts to use these APIs. 2aaa02ccf6
  • Wed, Feb 1
    The Rust .hhconfig reader now recognizes union_intersection_type_hints, so projects using that parser can enable union and intersection type-hint syntax consistently. 229121c557
  • Fri, Feb 3
    Sound Dynamic pessimisation now honors <<__NoAutoDynamic>> on top-level functions and no longer adds inappropriate dynamic bounds to classname<T>, typename<T>, or common generic container declarations. Types such as Vector<string> can therefore support dynamic without requiring their type argument to be exactly dynamic. a51c285635 936f37edee 0ceb0b7ce4
  • Fri, Feb 3
    cpu_get_count() and cpu_get_model() now require only [read_globals] rather than implicit [defaults], making them callable from functions with a narrower capability set. 26cae71480
  • Sun, Feb 5
    The Rust .hhconfig reader now warns about unrecognized options instead of silently ignoring them. This should expose misspellings and configuration options that are unavailable in the selected typechecker implementation. a19a617ce9

Breaking Changes

1 change
  • Thu, Feb 2
    The experimental BigCode autocomplete path and the corresponding hh_client --bigcode option have been removed. Tooling that still passes the option should stop doing so and use the standard autocomplete service. af637e05a1 cdabde25c1
