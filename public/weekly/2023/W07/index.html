Week 7: Feb 13–Feb 19, 2023

19 noteworthy changes, organized by the source changelog sections.

Highlights

9 changes
  • Mon, Feb 13
    Enum-class labels in attribute arguments are now preserved through naming, enabling typechecking, hover, and completion for forms such as <<__Memoize(#Key)>>. b9dd041059
  • Mon, Feb 13
    In --everything-sdt mode, method return expressions are now checked against a supportdyn-wrapped return type, matching explicitly Sound Dynamic methods. 82c7fcccc7
  • Tue, Feb 14
    hh --tast-holes-batch accepts a newline-separated list of source files and reports TAST holes across the batch, making type-precision analysis easier to automate. c41d55d42c
  • Tue, Feb 14
    Invalid __Memoize arguments now distinguish wrong arity from an invalid option and report the expected number of arguments. fa4f4eb1ef
  • Tue, Feb 14
    Partially written methods are lowered far enough for IDE features to work, __Override diagnostics retain complete positions, and autocomplete can suggest overridden method names after an incomplete <<__Override>> declaration. 80775a8a36 f25f7d4b3e dabbec63a9
  • Thu, Feb 16
    The command form hh --json check . works again after an argument-parsing regression. dd5ab56163
  • Fri, Feb 17
    Sound Dynamic subtyping can now push supportdyn through built-in containers and through safe promotions to Traversable, while expected-type inference retains more useful like-type information. This removes several false-positive errors around refined and nested container types. f9fe075c21 972106d560 61ab0e31c7
  • Fri, Feb 17
    Autocomplete now works in generic type-argument positions such as vec<string> without mistaking the angle brackets for XHP syntax. 480b384688
  • Fri, Feb 17
    hh_single_type_check --sdt-analysis can now identify top-level functions that need __SupportDynamicType, including dynamically callable functions and call sites that require dynamic-aware checking. 0ae3969f18 582b596f55

Breaking Changes

7 changes
  • Mon, Feb 13
    The fun(), class_meth(), and inst_meth() pseudo-function-pointer forms are now rejected by default. Migrate to first-class pointers such as function_name<>, ClassName::method<>, and $object->method<>. 4c7ba8532f
  • Mon, Feb 13
    Unimplemented and obsolete STREAM_CRYPTO_METHOD_* constants have been removed, including the protocol-version-specific TLS and legacy SSL constants. Use STREAM_CRYPTO_METHOD_TLS_CLIENT, STREAM_CRYPTO_METHOD_TLS_SERVER, or the corresponding ANY constants. a5ce6b07f0
  • Mon, Feb 13
    String arguments such as <<__Memoize("foo")>> are now rejected where a memoize option enum-class label is required. Use the appropriate label syntax instead. b9dd041059
  • Wed, Feb 15
    HHVM now defaults Autoload.Enabled to true. Deployments that need the previous behavior should explicitly set Autoload.Enabled = false. a714af2744
  • Wed, Feb 15
    Thrift stream and sink failures are now delivered as ThriftApplicationException rather than TApplicationException. Code catching the older concrete class should catch the new exception or a shared base such as Exception. 0e2f06e781
  • Thu, Feb 16
    Hack now rejects prohibited uses of this in class type parameters, class-variable hints, extends, and require extends. Type accesses rooted at this, such as this::T, remain available; affected declarations should otherwise use an explicit class or type parameter. 150429e923
  • Thu, Feb 16
    ZipArchive::getFromIndex() now returns null, rather than false, on failure and is typed as ?string. Callers checking strictly for false must migrate to a null check. 8ac98e8a21

Future Changes

3 changes
  • Tue, Feb 14
    The experimental packages work now lowers package declarations containing module patterns and included packages, and hh_server can load a repository-level __PACKAGES__.php into its package map. The syntax remains gated by the unstable packages feature. 135540312d 32f3dab867
  • Thu, Feb 16
    Opt-in expression-tree blocks allow statements directly inside Code`{ ... }` syntax and lower them to an immediately invoked lambda. The ongoing-release feature currently requires <<file:__EnableUnstableFeatures('expression_tree_blocks')>> for typechecking. 60a7b62d04
  • Fri, Feb 17
    Type constants in enum classes have entered ongoing release. The typechecker still requires the enum_class_type_constants opt-in while the runtime rollout completes. 2557874291
