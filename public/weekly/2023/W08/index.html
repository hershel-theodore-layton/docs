Week 8: Feb 20–Feb 26, 2023

17 noteworthy changes, organized by the source changelog sections.

DayWeekMonth
←Previous week→Next week

Highlights

14 changes
  • Mon, Feb 20
    Sound Dynamic union, intersection, and subtype processing no longer accumulates recursive supportdyn wrappers that can overflow the typechecker's stack, and it now retains the wrapper while comparing two supportdyn types. 0e60e722c7 de66255762
  • Mon, Feb 20
    Hover in Sound Dynamic projects can show an expression's type under dynamic assumptions when it differs from the ordinary type. The additional TAST is generated on demand for hover rather than for every typecheck. f0ad1da10f bdad09d3c0
  • Mon, Feb 20
    Sound Dynamic generic inference now removes like-types in safe covariant positions before solving a type variable, and tuple reads and writes are no longer unnecessarily pessimised. 4d6992a5db 76d4a7b435
  • Mon, Feb 20
    The experimental SDT analyzer now propagates NeedsSDT constraints from dynamic instance and static method calls to classes. da198e2d89
  • Tue, Feb 21
    <<__NoAutoDynamic>> is now honored on interfaces by the direct-declaration parser. Implicit pessimisation no longer treats an opted-out interface as Sound Dynamic. fd5a47c16b
  • Wed, Feb 22
    Runtime module-boundary errors now correctly describe an internal top-level function called from a method, rather than misreporting it as a method on the caller's class. 3d6bddce49
  • Wed, Feb 22
    Sound Dynamic checking avoids another stack overflow while solving supportdyn bounds, supplies dynamic bounds for class-level generics during the additional method-body check, and correctly wraps methods fetched through intersection receivers. 4de931af81 12856381c5 46a1c1580b
  • Wed, Feb 22
    Redundant-cast lints now warn that removing a runtime cast can change behavior, instead of presenting removal as unconditionally safe. 30abe736a4
  • Wed, Feb 22
    Optimized code no longer assumes that a value checked by a soft return-type constraint is non-null, preserving the runtime semantics of soft type hints. 7dccf227c0
  • Thu, Feb 23
    Implicit Sound Dynamic mode now pessimises inout parameters as both inputs and outputs. Declarations always receive a like-type, while definitions add it when the parameter type is not runtime-enforced. 5c70475d3d
  • Fri, Feb 24
    hh --json --prefer-stdout sends JSON results to standard output instead of mixing them with diagnostic output on standard error, simplifying scripted use. 69c5614feb
  • Fri, Feb 24
    Autocomplete now offers accessible type constants after SomeClass:: and this:: in type positions, including chained abstract and concrete accesses. 86d5445582
  • Fri, Feb 24
    When HH_SERVER_PATH is set, hh_client launches exactly that hh_server binary instead of relying on a sibling binary or $PATH. This provides deterministic pairing for custom builds, wrappers, and test environments. edcc11a69a
  • Sun, Feb 26
    The VS Code debugger now understands lazy-class values such as Foo::class instead of displaying an unexpected-variable-type error. abd73aac74

Breaking Changes

2 changes
  • Wed, Feb 22
    Deprecated AwaitAllWaitHandle::fromVector(), fromMap(), and fromContainer() have been removed. Use fromVec() or fromDict() after an appropriate constant-time collection cast. e0d354d015
  • Wed, Feb 22
    AwaitAllWaitHandle::setOnCreateCallback() now passes a vec rather than a Vector. Callbacks that only iterate can accept Traversable<Awaitable<mixed>> to remain compatible. 75f849cc74

Future Changes

1 change
  • Wed, Feb 22
    Initial TOML parsing support has landed for package configuration, including source spans that later diagnostics can map to line numbers. The active package integration remains experimental. 00899f4f76
