Week 11: Mar 13–Mar 19, 2023

11 noteworthy changes, organized by the source changelog sections.

Highlights

11 changes
  • Mon, Mar 13
    Invalid PACKAGES.toml relationships now produce parsing error 1009. The checker reports references to undefined packages and module globs assigned to more than one package. fbc8e0d7bb
  • Mon, Mar 13
    Implicit pessimization of an async function returning an enforced enum now applies the enum's base-type intersection inside Awaitable<...>, rather than intersecting the awaitable itself down to nothing. 95dae7a057
  • Mon, Mar 13
    Enum classes may now carry the internal SDT marker used by implicit sound-dynamic mode, avoiding recursive subtype failures for pessimised enum classes. 4ff56661ca
  • Tue, Mar 14
    hh progress is now tracked per repository rather than per server PID, allowing clients to show monitor and server status before connecting. Stale progress from a dead process is ignored, idle servers report ready, and long fanout/typecheck phases provide earlier and more accurate status messages. 98658279b8 8550b0f635 0cd7ddd10c
  • Wed, Mar 15
    Type constants in enum classes are now generally available and no longer require the enum_class_type_constants unstable-feature opt-in. bd5838a61b
  • Thu, Mar 16
    A new quick-fix application tool consumes hh --lint --json output from standard input or --input-file. It prints patched source by default and can update files with --overwrite; overlapping, stale, or otherwise unsafe fixes are dropped. 58c5e14cc8
  • Thu, Mar 16
    Package configuration validation now reports every cycle in the includes graph. 6c97dac720
  • Fri, Mar 17
    hackfmt now keeps expression-tree block braces next to their backticks, formatting them as Dsl`{ ... }` rather than separating the backtick and brace. a665b6d472
  • Fri, Mar 17
    The March 10 default requiring constant function and lambda default arguments has been reverted. Nonconstant defaults are accepted again unless the stricter options are explicitly enabled. 04b49bbdfe
  • Sat, Mar 18
    The redundant-cast linter now reports a cast in sound-dynamic code only when it is redundant under both normal and dynamic assumptions, reducing unsafe suggestions at dynamic boundaries. 13baee84fc cb5f9f9236
  • Sun, Mar 19
    Quick-fixes for redundant casts now preserve expression precedence, adding parentheses when removing a cast would otherwise let an enclosing operator capture part of the expression. a07d4e824a
