Week 14: Apr 3–Apr 9, 2023

20 noteworthy changes, organized by the source changelog sections.

Highlights

13 changes
  • Mon, Apr 3
    A new lint reports casts such as (int) new C() where a non-primitive value is cast to a primitive in a way that is unlikely to be meaningful. 593f41db78
  • Mon, Apr 3
    Nested type parameters in higher-kinded types no longer produce a false naming error for not beginning with T. 9b5699d6ee
  • Mon, Apr 3
    Watchman-backed status checks now qualify root-relative filenames correctly and keep the server's Watchman clock current. This fixes stale “No errors” results and indefinite hh_server sync waits after a file changes. a084e13751 a3f47f498e
  • Mon, Apr 3
    The missing-method diagnostic now offers one quick-fix that generates all required method stubs, rather than a separate fix for each method. 8dfff9994e
  • Mon, Apr 3
    Invalid expression-tree splices now describe the DSL, the expected splice type, the actual Hack value, and the DSL's documentation link instead of reporting only generic expression-tree terminology. 833661e119
  • Tue, Apr 4
    Failed nullsafe property access now prefers the actual missing or inaccessible-member error instead of the misleading message that a non-null receiver was expected to be null. 21cd44f60c
  • Tue, Apr 4
    Sound-dynamic subtyping now accepts compatible open shapes on both sides of supportdyn, including when the right-hand shape adds optional fields. 6886c8cb21
  • Wed, Apr 5
    XHP completion now inserts required attributes, with snippet placeholders when the client supports them. 65e5432943
  • Wed, Apr 5
    “Extract into variable” is no longer offered for expression selections that cannot be extracted safely. 355e174dce
  • Wed, Apr 5
    Referencing an outer local directly inside an expression tree now produces a contextual diagnostic and a quick-fix that splices the variable into the tree. 2635c40267
  • Wed, Apr 5
    Soft-package and soft-deployment validation now follows transitive soft relationships and reports invalid configurations more precisely. 657f4986f1
  • Thu, Apr 6
    A lambda nested inside a finally block may return normally; it is no longer treated as though its own body were part of the enclosing finally. 52c136dd3a
  • Thu, Apr 6
    Rust elaboration now reports more accurate positions and error kinds for reading from [], invalid <<__Deprecated>> strings, generic entry points, duplicate class constants, and wildcard type parameters. e25f032cde a0b5a2c4a4 c681a172f8 93930d39c8 fcab758a8c

Breaking Changes

1 change
  • Mon, Apr 3
    HH\autoload_set_paths() now always throws, as part of the migration to native autoloading. This change is backed out on April 10 while remaining callers are migrated. d419828855

Future Changes

6 changes
  • Tue, Apr 4
    Package-existence conditions now refine the typechecking environment. if (package foo && package bar) treats both packages as loaded inside the branch, while invariant(package foo, ...) treats the package as loaded for the rest of the block. 01178c77bd 0b7729bf54
  • Tue, Apr 4
    PACKAGES.toml can now parse soft deployments. This initial change only establishes the configuration representation; application and runtime support follows in later commits. 0cc3871280
  • Wed, Apr 5
    Under implicit pessimisation, inout parameters in function-type and lambda hints now receive like-types even when their runtime types are unenforced. 3be0d658a1
  • Wed, Apr 5
    Abstract context constants no longer receive an implicit as supportdyn<mixed> bound. An unbounded context constant can therefore still be instantiated with [], which is the context equivalent of mixed. 639c0f130a
  • Thu, Apr 6
    Implicit pessimisation now rejects a bare or implicit return from a function whose declared return type is non-void; it no longer accepts the missing value through dynamic. 6f9c0e2cb3
  • Thu, Apr 6
    The experimental newtype_super_bounds feature now honors class-typed lower bounds such as newtype T super C = mixed. b87d8ce093
