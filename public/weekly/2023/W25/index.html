Week 25: Jun 19–Jun 25, 2023

12 noteworthy changes, organized by the source changelog sections.

DayWeekMonth
←Previous week→Next week

Highlights

5 changes
  • Tue, Jun 20
    Documentation comments on type and newtype declarations are now retained in the AST and symbol index, making them available to code browsers and other indexing consumers. f0d2510328 4ce540d910
  • Tue, Jun 20
    The bundled HHI now exposes record_visited_files(): void and get_visited_files(): keyset<string> for applications that need to record which source files a request loads. 46bee8cf1e
  • Wed, Jun 21
    Go-to-implementation now accounts for unsaved editor contents, so results reflect dirty files rather than only the last versions on disk. 9e911b1aaf
  • Thu, Jun 22
    The IDE now loads its naming table from disk by default, allowing standalone features to become useful sooner after startup. 1ddca58a12
  • Sun, Jun 25
    Custom-error configuration now carries an explicit schema version so the format can evolve without tying configuration migrations to an HHVM release. A malformed CUSTOM_ERRORS.json now terminates hh_server with a configuration error instead of being silently ignored. d26d33e721 57f963ad90

Future Changes

6 changes
  • Tue, Jun 20
    Typed-local errors at control-flow joins now point to the join that caused the incompatible assignment and retain the flow-sensitive type after reporting the violation. 1ff3f090d7 1d8e65640a
  • Wed, Jun 21
    Refining a vec<T> to a tuple now preserves both the tuple element intersections and the original vec<T> constraint. This retains supportdyn information during tuple destructuring. 5eed6b73d3
  • Wed, Jun 21
    Case-type well-formedness now expands nested case types to their actual variants, so a definition such as case type B = A | bool is accepted when A itself has a disjoint variant such as int. Case types also work correctly as upper bounds on generic parameters. a23680767d c4f5f83241
  • Thu, Jun 22
    The explicit sound-dynamic pessimiser now understands case-type declarations and pessimises them using the same rules as opaque newtype declarations. c037d9ebc0
  • Sun, Jun 25
    In everything_sdt mode, <<__NoAutoLikes>> can suppress automatically introduced like-types on function and method returns, inout parameters, properties, lambdas, and promoted constructor properties. It does not disable supportdyn bounds or dynamic-callability checking. fbf8d8aa22
  • Sun, Jun 25
    Like-type pushing now resolves type variables with identical upper and lower equality bounds, improving inference around where type constraints and type constants. be102b4bae

Breaking Changes

1 change
  • Thu, Jun 22
    Autoload.Enabled has been removed because native autoloading is always enabled. Configuration that still sets the option should remove it; it no longer controls runtime behavior. 7e2baa2a3d
