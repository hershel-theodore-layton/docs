Week 26: Jun 26–Jul 2, 2023

14 noteworthy changes, organized by the source changelog sections.

DayWeekMonth
←Previous week→Next week

Highlights

7 changes
  • Mon, Jun 26
    Runtime deployment enforcement now distinguishes soft packages. Accessing a symbol from a soft package outside the hard deployment emits a warning in non-repository mode; hard-package violations still throw. Repository-authoritative builds continue to reject the access because soft-package files are not loaded. 08f82a6cb4
  • Mon, Jun 26
    Standalone IDE services and batched change processing now default on in configurations without rollout overrides, bringing open-source and direct-build configurations closer to the current IDE path. e433190c9e
  • Tue, Jun 27
    An async function containing only yield break is now recognized as an AsyncGenerator, matching functions that yield an actual value. 7e52671c4e
  • Wed, Jun 28
    “Extract shape type” now includes the missing semicolon in generated aliases, so its edits produce syntactically valid Hack. d996877551
  • Wed, Jun 28
    Indexed signatures with polymorphic contexts such as [ctx $callback] no longer expose the synthetic type parameter used internally to represent that context. 572b101e53
  • Thu, Jun 29
    The systemlib definitions of HH\stdin(), HH\stdout(), HH\stderr() and their nullable try_* variants now use [], matching their existing HHI declarations; the HHI also gains documentation for script and web-request behavior. Moving the implementations from implicit [defaults] to [] narrows their capability requirement and is not a caller break. Obtaining a stream handle is pure, while performing I/O still requires the appropriate capability. 77b6d77442
  • Fri, Jun 30
    “Inline method” now handles empty method bodies instead of crashing on their positionless AST placeholder. f9709918c4

Breaking Changes

1 change
  • Tue, Jun 27
    Dynamic property access such as $object->{$name} now requires the receiver to support dynamic, and the access result is always dynamic. Using it on an ordinary statically typed object is rejected; accidental $ insertion still receives the existing quick-fix to normal property access. aade1260bd

Future Changes

6 changes
  • Tue, Jun 27
    require class trait requirements have advanced to ongoing release and no longer require the require_class unstable-feature opt-in. 39ac898932
  • Tue, Jun 27
    Runtime-datatype information is now used when refining case types, allowing assertions such as $value as vec<_> to select and preserve the compatible vec<T> variant. 47e0a54653
  • Wed, Jun 28
    <<__NoAutoBound>> on a generic parameter disables the automatic as supportdyn<mixed> bound under implicit or explicit pessimisation without opting the surrounding declaration out of other sound-dynamic transformations. 581ae77b8d
  • Thu, Jun 29
    The “Add local type hint” action is now offered only when the selection covers the assignment's left-hand variable or the complete assignment, avoiding unrelated suggestions when selecting part of the right-hand expression. 8c74b8200c
  • Fri, Jun 30
    Readonly method-call checking now handles function types wrapped with dynamic by implicit pessimisation, avoiding false readonly errors and invariant failures. ab343625af
  • Sat, Jul 1
    HHVM gains the first runtime implementation for checking case types in parameter and return positions. Default builds still treat case types as mixed while the rest of runtime enforcement is completed, so this commit is groundwork rather than an immediate behavior change. 7d8e1d9dba
