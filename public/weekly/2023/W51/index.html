Week 51: Dec 18–Dec 24, 2023

12 noteworthy changes, organized by the source changelog sections.

DayWeekMonth
←Previous week→Next week

Highlights

9 changes
  • Mon, Dec 18
    HH\FileDecls::parsePath() is now implemented: it reads a Hack file from disk and returns the same declaration view as parseText(), throwing InvalidArgumentException when the path is missing or cannot be opened. de1dd54b17
  • Mon, Dec 18
    HH\class_to_classname() now retains dynamically constructed string inputs correctly, preventing its returned classname string from becoming invalid after the native wrapper releases the argument. f4402a8d7a
  • Tue, Dec 19
    Find-references, find-class-references, and refactor requests no longer restart their file iteration after cancellation polling, fixing searches that could run indefinitely. 6808aa6797
  • Tue, Dec 19
    LSP request cancellation is now enabled by default, so abandoned IDE work can stop rather than delaying the replacement request. 94342a995c
  • Tue, Dec 19
    Direct-declaration parsing with user attributes retained no longer drops heredoc, nowdoc, or parenthesized expressions. This prevents affected constants from degrading to an unknown type in downstream typechecking. 230809b98e
  • Tue, Dec 19
    Type errors that refer to expression-dependent types now print stable internal <expr#…> identifiers rather than renumbering them for display. The numbers may be larger or nonconsecutive, but repeated runs are deterministic. 65e011a6fd
  • Wed, Dec 20
    The Hack manual now includes a package guide covering package definitions, deployments, cross-package calls, and PACKAGES.toml configuration. 77eea71427
  • Thu, Dec 21
    The VS Code debugger now evaluates a request without an explicit frame ID in the frame selected by the most recent scopes request, when execution is paused. 9de19a803e
  • Thu, Dec 21
    Repo-authoritative optimization now converts type constraints back to unresolved form when their target class is later found to be missing or uninstantiable, avoiding stale resolved constraints against nonexistent classes. 6de1d23d18

Breaking Changes

3 changes
  • Mon, Dec 18
    Support for meth_caller(nameof C, 'method'), introduced on December 9, has been backed out because the compiler lowering was unsound. Use meth_caller(C::class, 'method') again. 420490f6e1
  • Wed, Dec 20
    FixDefaultArgReflection now defaults to mode 2. If evaluating a parameter's default expression during reflection fails, HHVM emits a warning and reports the reflected default as null instead of exposing the evaluator's exception under the old mode. 6adc7b1655
  • Thu, Dec 21
    hh_single_type_check no longer accepts --math-new-code; the newer arithmetic-checking behavior is always enabled in the tool. 6c1dbdb71d
