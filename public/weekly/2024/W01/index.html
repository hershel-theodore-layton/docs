Week 1: Jan 1–Jan 7, 2024

9 noteworthy changes, organized by the source changelog sections.

DayWeekMonth
←Previous week→Next week

Highlights

6 changes
  • Tue, Jan 2
    XHP required-attribute checking now combines requirements from every side of an intersection type, avoiding false “missing required attribute” errors. 47b213ac59
  • Tue, Jan 2
    The language server now invalidates cached typed ASTs and errors in additional file-change scenarios, preventing stale diagnostics after open files or their dependencies change. 1e8217ee0a
  • Wed, Jan 3
    The new HH\autoload_type_or_type_alias_to_path(string)[defaults]: ?string performs one autoload-map lookup for a name that may denote either a class-like type or a type alias. a35c775051
  • Wed, Jan 3
    Hack's bundled declarations now expose the existing pure Facts API HH\Facts\module_to_path(string)[]: ?string. 17446e19ae
  • Fri, Jan 5
    Separate Hack notebook kernels can now define declarations with the same source names without colliding, and top-level notebook statements now respect the repository's auto-namespace map. 3475febb1c 33f41836a4
  • Fri, Jan 5
    The new pure HH\FileDecls::parseTypeExpression(string)[] API parses a standalone type expression into a recursive declaration structure without the cost of runtime type_structure(). 96ee1ec4c5

Security

1 change
  • Fri, Jan 5
    The fb303 server can now check and enforce access-control lists using Fb303Server.EnableAclChecks, Fb303Server.EnforceAclChecks, and Fb303Server.Identity. The feature is disabled by default. de71bf51b0

Breaking Changes

2 changes
  • Fri, Jan 5
    Built-in declarations that accidentally used the nonexistent object type now use concrete DOM types or HH\object. In particular, XSLTProcessor::importStylesheet() now accepts DOMDocument, not SimpleXMLElement. 3c1e77a511
  • Fri, Jan 5
    The legacy fb_set_post_autoload_handler() API has been removed. 8f0646db1f
