Week 4: Jan 22–Jan 28, 2024

7 noteworthy changes, organized by the source changelog sections.

DayWeekMonth
←Previous week→Next week

Highlights

4 changes
  • Mon, Jan 22
    HH\package_exists() now returns true for soft-deployed packages, matching their status as loaded packages whose boundary violations warn rather than throw. a7f1122c6e
  • Mon, Jan 22
    Virtual lambdas synthesized for expression trees are now pure, so expression trees containing virtualized effects can be constructed inside [] functions. Property writes are checked inside an uncalled lambda with the required capability and no longer refine the runtime property. 9abcdf6c65
  • Wed, Jan 24
    The date_format() declaration now accepts DateTimeInterface, matching the runtime and allowing immutable or alternative implementations without a type error. c14b15ffd2
  • Thu, Jan 25
    When a package defines allow_directories, the typechecker now rejects module foo; declarations in files outside those directories. 14b0127365

Breaking Changes

2 changes
  • Mon, Jan 22
    Runtime upper bounds on generic types are now always fully enforced, and the non-default modes of Eval.EnforceGenericsUB have been removed. Code that relied on warning-only or disabled upper-bound checks can now receive catchable fatals. 772702fa69
  • Tue, Jan 23
    Standard runtime parameter type checking for C++ builtins is now enabled in soft mode by default through Eval.CheckBuiltinParamTypeHints=1. Invalid arguments can emit new type-hint warnings; deployments may use 0 to disable checks or 2 for hard enforcement. cdc7f67f91

Security

1 change
  • Tue, Jan 23
    A function or method carrying <<__CrossPackage("pkg")>> now begins with an invariant that the named package is actually loaded. Misconfigured cross-package access fails immediately instead of continuing into boundary violations. b6593e555d
