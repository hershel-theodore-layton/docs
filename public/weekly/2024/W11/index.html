Week 11: Mar 11–Mar 17, 2024

10 noteworthy changes, organized by the source changelog sections.

DayWeekMonth
←Previous week→Next week

Highlights

6 changes
  • Tue, Mar 12
    A promoted variadic constructor parameter now declares its property as vec<T> rather than T in both parser paths. For example, private string ...$args produces a vec<string> property and no longer causes errors in the lowered constructor body. a9284326d6
  • Tue, Mar 12
    ReflectionFile::getModule()[]: ?string is now implemented, returning the module declared by the reflected file when it has one. 25639bc1f5
  • Wed, Mar 13
    The “add missing method stubs” quickfix now inserts generated methods at the end of the class instead of the beginning. ddfef7b4a5
  • Wed, Mar 13
    The new pure HH\Facts\files_and_attr_args_with_attribute(string)[]: vec<(string, ?string)> query returns every matching file and file-attribute argument in one call. Files with multiple arguments appear multiple times; integer arguments retain the Facts API's existing behavior of coming back as strings. bb3c74674d
  • Thu, Mar 14
    The new hphp_was_interrupted_by_debugger()[read_globals]: bool builtin reports whether the current request has been paused by the VS Code debugger, even if the debugger later disconnects. 0d9eca7e0f
  • Thu, Mar 14
    Promoted variadic constructor properties now carry their corrected vec<T> type into emitted property metadata, so runtime property-hint checks agree with the typechecker. c7e208f99e

Future Changes

1 change
  • Wed, Mar 13
    Under the ongoing module_level_traits_extensions feature, a public <<__ModuleLevelTrait>> may now declare internal methods. Internal properties remain restricted to internal traits. 6cad9f87c5 f1bc12cf99

Security

1 change
  • Fri, Mar 15
    The new off-by-default Eval.DisableRequestSuperglobal option prevents $_REQUEST from being created or populated, allowing deployments to avoid the superglobal's merged input surface. d6931f096c

Breaking Changes

2 changes
  • Fri, Mar 15
    The implicit class constant is now case-sensitive: only C::class, not spellings such as C::CLASS, receives the special class-name behavior. 07f75c18d1
  • Fri, Mar 15
    The runtime surface of meth_caller() now takes a classname value directly, completing the move away from class-name strings. Use C::class for statically known classes and dynamic_meth_caller() for dynamic strings. 16424edb7c
