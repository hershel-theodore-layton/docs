Week 16: Apr 15–Apr 21, 2024

13 noteworthy changes, organized by the source changelog sections.

Breaking Changes

5 changes
  • Mon, Apr 15
    where clauses may no longer project a type constant through a generic or abstract receiver, such as where U = T::TC. Express the relationship with a refinement such as T as Base with { type TC = U }. Context-polymorphic coeffect projections such as [$a::Ctx] and [T::Ctx] are explicitly exempt and remain supported. e9da5a4c6a
  • Tue, Apr 16
    Inside a module declaration, an imports block must now appear before an exports block. Reorder declarations that currently export first; the restriction prevents range-formatting from losing the original token order. 2f432af79a
  • Thu, Apr 18
    AsyncMysqlErrorResult::mysql_normalize_error() has been removed from the HHI and runtime extension. Migrate callers to the remaining error information, such as mysql_error(), mysql_errno(), or failureType(), as appropriate. 5a9a946d2d
  • Fri, Apr 19
    Accessing a private static member through an object expression, such as $object::method(), is now accepted only from that same class when it is final. Cross-class access that previously slipped through now reports that private members cannot be accessed dynamically; prefer self::method() for same-class calls. c17d4a0221
  • Fri, Apr 19
    DOMDocument::registerNodeClass() class mappings are now case-sensitive. The base-class spelling used during registration must exactly match the class name encountered when DOM objects are created. ecaf3474e9

Highlights

5 changes
  • Tue, Apr 16
    hackfmt now builds its line table tail-recursively, avoiding a stack overflow on unusually large source files. 88edd0b8ac
  • Tue, Apr 16
    hackfmt now keeps an empty module definition on one line as new module foo {}, matching other empty braced declarations. 0fff1574c6
  • Fri, Apr 19
    IDE rename now handles the $ prefix correctly for both static properties and the differing declaration/use spellings of instance properties. fb8c9ac5b1
  • Fri, Apr 19
    Repo-authoritative compilation accepts --vActiveDeployment=..., allowing a build invocation to set or override the active package deployment without editing build_config.hdf. 1dcd3f2216
  • Sat, Apr 20
    The SQLite3 extension now uses SQLite's 64-bit integer APIs consistently for returned values, bound parameters, and user-defined function results. Values outside the signed 32-bit range are no longer truncated on those paths. c9c52eab33

Future Changes

3 changes
  • Tue, Apr 16
    Repo-authoritative optimization no longer asserts when a case-type union contains an unresolved member. The whole union is conservatively left unresolved, matching non-repo HHVM behavior; case types remain a staged feature. e01cd5e15a
  • Wed, Apr 17
    The typechecker gained internal flow-based provenance nodes for explaining how types move through variance and type constructors, together with a disabled-by-default extended-reasons option. This is groundwork only: the new reasons are not yet surfaced in ordinary project diagnostics. abd7cada5a 11e09fdacf
  • Thu, Apr 18
    Experimental expression-tree splices are now typechecked in the same lowered lambda shape used by code generation. An as refinement performed inside a splice no longer survives after the enclosing expression tree, and values used by splices are treated as captured variables and may be pessimised. de35277bac
