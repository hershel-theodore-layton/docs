Week 17: Apr 22–Apr 28, 2024

15 noteworthy changes, organized by the source changelog sections.

Highlights

9 changes
  • Mon, Apr 22
    hh --lint path/to/directory now reports that lint accepts files rather than crashing. Directory walking is still unsupported. 3d67603997
  • Mon, Apr 22
    ThriftAttributeSerializer now serializes a Thrift SET from the Hack array's keys rather than its values, fixing sets whose backing representation stores the member in the key. 366ea31781
  • Tue, Apr 23
    round() now handles precision values outside the meaningful range for a double directly: extremely high precision returns the input unchanged, while sufficiently low precision returns zero, avoiding invalid intermediate calculations. a6c87cb4c8
  • Wed, Apr 24
    TAST holes produced for invalid array access now retain the original outer type of a nullable or mixed base instead of incorrectly reporting its non-null inner type. Typed-AST consumers and codemods will see accurate actual types. be9a7af8b3
  • Thu, Apr 25
    Repo-authoritative optimization now models the concrete values written to memoization caches, avoiding incorrect bottom or return types for forwarded late-static-binding calls such as memoized methods inherited from traits. 9056a5bf64
  • Thu, Apr 25
    Top-level autocomplete backed by Glean now matches a declaration's autocomplete sort text as well as its name, allowing appropriately ranked declarations to appear for additional prefixes. 891e663ebc
  • Fri, Apr 26
    JSON diagnostics now include a top-level severity field. Consumers of hh --json can distinguish errors from the new warning severity without parsing rendered text. e19bd61dd0
  • Fri, Apr 26
    While VS Code debugging is paused, newly started request threads are no longer announced until execution resumes, keeping the stopped thread from being displaced in the debugger UI. e2849902e6
  • Fri, Apr 26
    The “override method” code action now inserts a multiline method body and places the cursor inside it, ready for implementation. 4f550b7331 2298871f36

Future Changes

5 changes
  • Tue, Apr 23
    Collection literals inside opted-in expression trees no longer require the separate expression_tree_map unstable-feature attribute. The enclosing expression-tree feature remains staged. c13997fb6d
  • Wed, Apr 24
    The unstable expression_tree_nest feature allows an expression tree inside a splice. A nested tree inherits the enclosing DSL and therefore omits its own DSL prefix, except across an ordinary Hack lambda scope; nested trees cannot yet capture client variables from enclosing scopes. 8fd5211674
  • Thu, Apr 25
    A disabled-by-default hack_warnings project option introduces non-fatal Hack warnings. The first warns when ?X and ?Y are compared even though the non-null primitive types X and Y are disjoint. a5295f752a f5f47a9cc6
  • Thu, Apr 25
    Repo-authoritative optimization now handles enum members and unresolved object members in experimental case-type unions without misclassifying or asserting on the union. ba2eace20a
  • Fri, Apr 26
    When the opt-in Hack warning system is enabled, LSP diagnostics now reach editors with warning severity and are rendered as warnings rather than errors. 43370c7b5f

Breaking Changes

1 change
  • Thu, Apr 25
    Hack's text diagnostic formats now encode severity. In particular, --error-format plain prefixes diagnostics with ERROR: or WARN:, and the raw, contextual, and highlighted renderers distinguish warnings too. Update scripts that parse the previous plain-text layout. 9bbf0bd8bd 4f788c05ab ac2791f216 3059d50fb7
