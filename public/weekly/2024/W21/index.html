Week 21: May 20–May 26, 2024

11 noteworthy changes, organized by the source changelog sections.

DayWeekMonth
←Previous week→Next week

Highlights

5 changes
  • Mon, May 20
    Class-pointer migration diagnostics now cover returning C::class from a string function and assigning it to a string property. Use a class-name type or convert explicitly with HH\class_to_classname(). a910b45d23
  • Tue, May 21
    Shapes::keyExists() and its negation now refine required, optional, and open shape fields more completely. The false branch knows an optional field is absent, and Hack reports accesses to that known-missing key. 2a66cd61b3 b37f5e1465
  • Tue, May 21
    Class-pointer migration diagnostics now also catch string concatenation with C::class; convert explicitly when a textual class name is required. e1f6f11a26
  • Thu, May 23
    The VS Code debugger now displays string variables and string constants in single quotes, making them visually distinct from names and non-string scalar values. d60b329ad4
  • Fri, May 24
    The hack_warnings configuration now accepts true/all, false/none, or a comma-separated allowlist of warning codes such as 12005,12006. Projects can enable a targeted warning migration without taking every warning at once. dbacc3fc0c

Breaking Changes

2 changes
  • Mon, May 20
    Namespace names in use declarations may no longer contain :. XHP-style names are not valid namespaces and now produce a parser error. 092c46226a
  • Thu, May 23
    Namespace names and aliases in use declarations may no longer contain XHP-style : or - characters. This completes the namespace validation introduced on May 20. 15efb0012e

Future Changes

4 changes
  • Wed, May 22
    When hh_single_type_check receives --packages-config-path, it now treats that configuration file's directory as the project root. Experimental path-based package definitions therefore resolve test files relative to the same location as the package config. 661620fadc
  • Thu, May 23
    Every nested expression tree must now repeat its DSL name, and that name must match the enclosing tree. The earlier shorthand that inherited the outer DSL is rejected. c610bf057f
  • Fri, May 24
    Under implicit pessimisation, is this and as this now refine to ~this where an exact this result would be unsound. 2e1a710c6b
  • Fri, May 24
    Enum refinements nested inside nullable and tuple-like types now preserve the enum's stringish or intish weakening instead of unsoundly producing an exact enum type. 9235b6c767
