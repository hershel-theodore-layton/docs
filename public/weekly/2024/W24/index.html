Week 24: Jun 10–Jun 16, 2024

9 noteworthy changes, organized by the source changelog sections.

DayWeekMonth
←Previous week→Next week

Highlights

6 changes
  • Mon, Jun 10
    Extended type errors now include the primary claim's source snippet and position, including for constructor calls. When combined with JSON output, --error-format extended also supplies a human-readable rendering of the error. 67328c1ec9 e7a9c060ca 59443d6edd
  • Wed, Jun 12
    debug_backtrace()[defaults] now returns HH\StackTrace, a vec of open HH\StackFrame shapes whose fields are explicitly optional. This makes code account for fields such as 'args', 'file', and 'function' being absent. df840cc4bc
  • Wed, Jun 12
    In repo-authoritative mode, equality and conditional branching now agree when comparing lazy class values with class pointers. A true $lazy_class === $class_pointer comparison can no longer be optimized into an unreachable branch. 9884cdfbf2
  • Thu, Jun 13
    Active implicit contexts are now refcounted correctly while entering and resuming calls, async functions, and wait handles, avoiding lifetime errors when context switching replaces the active object. c6f02fdab1
  • Fri, Jun 14
    JIT-compiled is_a() and is_subclass_of() now honor the $allow_string argument and reject trait targets, matching interpreter behavior for class pointers. c3c428aa95
  • Sat, Jun 15
    Subclasses of HH\ImplicitContext can now call the inherited protected exists()[zoned]: bool helper to test whether their keyed context is present without reading its value. 9e3108de07

Breaking Changes

1 change
  • Tue, Jun 11
    get_class() and get_parent_class() now require an explicit argument; the implicit current-class form has been removed. get_class() also enforces an object argument through its builtin type hint and returns a classname rather than mixed. aa31bd583b

Security

1 change
  • Wed, Jun 12
    Public classes and interfaces may no longer extend internal types. This restores a firm module boundary and prevents public APIs from exposing a base type that callers outside the module cannot name. f971a6634f

Future Changes

1 change
  • Fri, Jun 14
    With Packages v2 enabled, <<file: __PackageOverride('name')>> no longer needs an __EnableUnstableFeatures declaration. The attribute lets a file opt into the named package for access checking. ff5b55092b
