Highlights

3 changes
  • Mon, Jul 8
    Samples returned by HH\xenon_get_data() may now include optional PageletWorkers, XboxWorkers, HttpWorkers, and CliWorkers fields in HH\XenonSample. Consumers should continue treating these worker-category counts as optional. a5a47241f9
  • Wed, Jul 10
    Vec\intersect() now materializes a forward-only first Traversable before processing it. Passing a Generator as the first argument no longer attempts to rewind it and throw. The function remains pure ([]). ed1ef19ce5
  • Wed, Jul 10
    The Dict\from_keys() documentation now links to the actual asynchronous counterpart, Dict\from_keys_async(). 3c80238bdc

Future Changes

2 changes
  • Tue, Jul 9
    The opt-in warning formerly reported as code 12002 is now divided into 12009 (is always true), 12010 (is always false), 12011 (as always succeeds), and 12012 (as always fails). Projects that enable these warnings should update warning-code suppressions and tooling. d6e5153e6c
  • Thu, Jul 11
    .hhconfig gained an enable_experimental_stx_features JSON map as the new configuration path for experimental syntax-tree features. At this stage, configured statuses must agree with the compiler's hardcoded feature statuses; the option is rollout plumbing rather than a way to enable arbitrary syntax. 25411fc714

Breaking Changes

1 change
  • Fri, Jul 12
    HH\ImplicitContext gained an abstract context constant, CRun. Its base runWith(), runWithAsync(), get(), and exists() methods now require [this::CRun] instead of a fixed [zoned] capability, and subclasses must choose a concrete requirement such as const ctx CRun = [zoned]. This annotation does not grant the listed capability: it is a requirement on the callee, so a caller must have a capability set that contains the subclass's chosen CRun. Both runWith() and runWithAsync() additionally require the callback's context through ctx $f. Choosing a narrower CRun relaxes the requirement on callers. The matching HHI declaration follows later in the month. d36ec6e832
