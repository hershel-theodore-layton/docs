Week 38: Sep 16–Sep 22, 2024

15 noteworthy changes, organized by the source changelog sections.

Highlights

7 changes
  • Mon, Sep 16
    Lambdas may reuse the discard parameter name with different annotations, as in (int $_, string $_) ==> {}; Hack no longer compares the discarded parameters with one another and reports a spurious coercion error. 0b59874dd4
  • Mon, Sep 16
    Direct references to constants and type constants declared by a trait now initialize against the trait's own class object, fixing failures for expressions such as TMyTrait::MY_CONSTANT. 4752658e59
  • Mon, Sep 16
    Method hovers selected through an enum-class label now show the label's singleton type. Dead-suppression cleanup also removes unused HH_IGNORE comments alongside unused HH_FIXME comments. 9fc76eee71 9ba137b426
  • Tue, Sep 17
    hh_single_type_check --config hack_warnings=false can now disable warnings for one-off checks; true enables the full warning set. d7fb8b6b4c
  • Wed, Sep 18
    Hack LSP accepts --disable-format-on-save, which stops advertising textDocument/willSaveWaitUntil while leaving explicit document and range formatting available. 77c22fb8c6
  • Wed, Sep 18
    The HH\lmdb API now exposes typed enums for LMDB environment, database, put, copy, and cursor-operation flags. 73bc12842a
  • Fri, Sep 20
    A literal nameof C used as an array key is now folded directly into the member key, matching literal-string access and avoiding the generic expression path. b6fc70430d

Future Changes

6 changes
  • Mon, Sep 16
    Staged package-v2 checking now permits a function pointer to a static method in another package, matching the symbol-reference traversal used for deployment boundaries. 38d78565b8
  • Mon, Sep 16
    Work on recursive_case_types now models newtype bounds, enum bounds, and function-type variants when checking recursive case definitions. 99e7aa8229 c8b31f79f2 d34c456b07
  • Wed, Sep 18
    The configurable class-pointer migration check now covers C::class values used as enum members through the enum key in class_pointer_levels, recommending nameof C before implicit class-to-string conversion is removed. dc08ae9cb2
  • Thu, Sep 19
    The unstable open_tuples feature now parses, represents, and subtype-checks tuples with optional elements and variadic tails, such as (int, optional string, arraykey...). Null-coalescing access also understands optional and variadic positions. 084c06ee9f 4cf74b6739 f67f3046ad 7d7f1af223 812d981b81
  • Thu, Sep 19
    The class-pointer migration check's arraykey level now diagnoses C::class when used as a dict, keyset, or collection key, or in indexed access, and recommends nameof C. f34b115e5c
  • Fri, Sep 20
    Recursive case-type checking no longer loops while intersecting recursive variants. With recursive_case_types enabled, case definitions are also exempt from the legacy blanket cyclic-type-alias rejection so valid recursive lists and trees can be checked structurally. 6228f4218f 781cdb1af5

Breaking Changes

2 changes
  • Tue, Sep 17
    HH\ImplicitContext\is_inaccessible()[zoned] has been removed. d87f330ce2
  • Sun, Sep 22
    Deprecated implicit-context states and memoization options have been removed. The NULL, SOFT_SET, and SOFT_INACCESSIBLE state members and the SoftMakeICInaccessible and Uncategorized memoization options are no longer available; use the remaining VALUE / INACCESSIBLE states and KeyedByIC / MakeICInaccessible options. 23faf7f107 efdf82e1d3
