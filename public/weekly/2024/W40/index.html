Week 40: Sep 30–Oct 6, 2024

14 noteworthy changes, organized by the source changelog sections.

DayWeekMonth
←Previous week→Next week

Highlights

8 changes
  • Mon, Sep 30
    --ignore-hh-version can now initialize from a saved state even when .hhconfig has changed, by requesting a state without constraining its project metadata. 788b1c1349
  • Mon, Sep 30
    User-profiler callbacks now retain the current implicit-context value instead of running with that value cleared. a4a17fac22
  • Mon, Sep 30
    Subtyping can now solve an unsolved type variable against a like type instead of prematurely rejecting that branch, fixing valid generic inference under sound dynamic. cf76be167a
  • Tue, Oct 1
    The Hack manual now documents optional parameters on interface and abstract methods: the declaration omits a default, while each concrete implementation supplies the default its callers will use. 88468f2192
  • Wed, Oct 2
    Hack's subprocess timeout handling now closes its streams after both timeouts and exceptions; the select-based implementation also terminates the child, reducing leaked processes and file descriptors in long-running tooling. 62da22e7c8
  • Wed, Oct 2
    hh_single_type_check --get-some-file-deps --root ... can now derive its naming table from the repository root; --naming-table is no longer mandatory for this mode. bdf41c6516
  • Fri, Oct 4
    Warning filtering now tolerates failures from its Mercurial queries instead of allowing an external VCS error to abort the typecheck. 9b5597b79f
  • Fri, Oct 4
    At positive typing-log levels, hh_show() output now includes numbered type variables such as #1, which makes unresolved relationships easier to follow. ca6767e0a1

Future Changes

5 changes
  • Mon, Sep 30
    Staged package-v2 checks now deliberately ignore types referenced only on the right-hand side of is expressions or as generic type arguments, matching the deployment symbol-reference traversal. 10efc91d0b 52e2d3811b
  • Mon, Sep 30
    Experimental type splats are now typechecked and participate in subtyping, including fixed, optional, and variadic open-tuple components. This makes arity-polymorphic wrappers such as function call<TArgs as (mixed...)>((function(...TArgs): void) $f, ...TArgs $args) type-safe. 58d6aa941e 6b5ac89089
  • Tue, Oct 1
    Open tuples and type splats moved to Preview status in HHVM's feature configuration, making them available for broader experimentation. a0e6574d02
  • Fri, Oct 4
    Packages v2 include_paths now use repository-rooted paths beginning with //; directory entries end in /, exact-file entries do not, and ./ or ../ segments are rejected. 9bcaba8f44
  • Fri, Oct 4
    The experimental type-splat syntax can now appear at the end of tuple hints, for example (float, ...T). A tuple may have only one variadic or splat tail, and a splat cannot follow an optional element. 03ed3cc3d6

Breaking Changes

1 change
  • Thu, Oct 3
    Runtime enforcement of builtin parameter type hints can no longer be disabled with Eval.CheckBuiltinParamTypeHints; builtins now consistently use the strict enforcement behavior that was previously level 2. c2c0564ce9
