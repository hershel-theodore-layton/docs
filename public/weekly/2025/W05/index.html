Week 5: Jan 27–Feb 2, 2025

7 noteworthy changes, organized by the source changelog sections.

DayWeekMonth
←Previous week→Next week

Highlights

3 changes
  • Tue, Jan 28
    HHVM now carries complete property type-constraint intersections through runtime enforcement and JIT analysis, so generic upper bounds are considered consistently—including for compound property assignments—instead of consulting only the primary hint. 4e1ae2c191 938742f7ec 0e0fd266cf e95d7acaf4
  • Wed, Jan 29
    Warning filtering works again when error streaming delegates a full check to hh_distc; streamed worker batches are now filtered as they arrive and carry the updated warning saved state through the distributed check. 732a576117
  • Thu, Jan 30
    The VS Code debugger now sets breakpoints on every non-contiguous bytecode block mapped to a source line, fixing missed stops when compiler optimizations duplicate a loop body. Some multiline expressions can consequently produce more than one breakpoint. 2b8ada7314

Future Changes

3 changes
  • Tue, Jan 28
    Trait require class and experimental require this as declarations now share one constraint representation. Checks that previously considered only require class now also honor require this as, including inherited constraint handling. 0a38aa99be
  • Thu, Jan 30
    Expression trees gained Preview support for shape literals and shape-typed parameters behind expression_tree_shape_creation. DSLs can virtualize shape construction with proper required, optional, open-field, and nested-shape checking, but shape reads and writes are not included yet. 0783044e49 5f4cd41fcf
  • Thu, Jan 30
    Hack's TypeStructure<T> shape now exposes optional optional_elem_types and variadic_type fields for tuple types, matching the runtime representation added earlier in the month. 84b51c4165

Breaking Changes

1 change
  • Fri, Jan 31
    The report_pos_from_reason typechecker option has been removed. Diagnostics no longer append [FROM REASON INFO], and positions derived from type reasons no longer receive special treatment that prevented HH_FIXME or HH_IGNORE_ERROR suppression. 485b19043a
