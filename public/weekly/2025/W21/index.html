Week 21: May 19–May 25, 2025

16 noteworthy changes, organized by the source changelog sections.

Future Changes

4 changes
  • Mon, May 19
    Declarations using the unstable type-splat syntax are now checked to ensure the splatted parameter type is a subtype of (mixed...). Generic splats therefore need an appropriate tuple bound instead of remaining unchecked at declaration time. 768846af7b
  • Wed, May 21
    Nested expression-tree lowering now orders captured free variables deterministically, preventing run-to-run changes in generated lambda parameters and bytecode while the nested-binding implementation evolves. 359704caf9
  • Thu, May 22
    Class-pointer diagnostics for dynamic static calls now include the type's definition site, and the unstable HH\ReifiedGenerics\get_class_from_type() intrinsic accepts abstract type constants without <<__Reifiable>> because it consumes their type structure rather than preserving a reification witness. 497d071296 b2082d530e
  • Thu, May 22
    The unstable polymorphic-lambda feature now supports both function<T>(T $x): T ==> $x and generic legacy anonymous functions. Parameters and returns must be explicitly typed, and reified, variant, higher-kinded, and shadowing type parameters remain disallowed. bb4279c923 3e1031ad4c

Highlights

8 changes
  • Tue, May 20
    ReflectionClass::getName() is now typed as classname<mixed> rather than plain string, preserving class-name information through reflection without changing the runtime string representation. 87ff635038
  • Wed, May 21
    HH\PriorityBridgeWaitHandle can wrap an awaitable so its child continues at lower priority instead of being promoted by the waiting context, and prioritize() can later lift it. create() requires []; the initial HHI for prioritize() omits a bracket list, so callers initially need the implicit [defaults] capability. ab939a7f4a 287b567685
  • Wed, May 21
    The class_overrides_all_trait_methods linter now ignores abstract trait methods that exist to carry user-defined semantic attributes, while continuing to report genuinely dead overrides. 4794a8c906
  • Wed, May 21
    HH\dynamic_class_meth() and HH\dynamic_meth_caller() now accept class_or_classname<mixed> instead of only string, adding class-pointer arguments without rejecting existing classname strings. 9da64160bd
  • Thu, May 22
    Calling PriorityBridgeWaitHandle::prioritize() after the wrapped wait handle has already finished is now a no-op instead of crashing. dd5cdaf7a4
  • Fri, May 23
    Repo-authoritative builds can use repeatable --static-pattern glob options to include only selected files in file.cache; this mode cannot be combined with --cdir or --cfile. 51c53a7882 bd70a8f60a
  • Fri, May 23
    HSL adds HH\Lib\Async\LowPri<T> for starting non-critical async work at low priority and promoting it later. run() has callee requirements [ctx $action, write_props], and prioritize() requires [write_props], so their callers must provide at least those capabilities. b90e9d07ac
  • Fri, May 23
    The HHI for PriorityBridgeWaitHandle::prioritize() now explicitly uses [] instead of omitted brackets. This weakens its callee requirement from implicit [defaults] to no capabilities and is therefore non-breaking for callers. b90e9d07ac

Breaking Changes

4 changes
  • Tue, May 20
    The checker no longer accepts dynamic static-method call syntax such as $class::$method() or C::{expr}(). Use a statically named method or the explicit HH\dynamic_class_meth() API. 458b089989 f5759593e2
  • Tue, May 20
    The legacy HH\ImplicitContext abstract class and its private context-construction path have been removed; the HH\ImplicitContext namespace remains. Projects still using the class should migrate to the memo-sensitive or memo-agnostic API. dc65144f44
  • Tue, May 20
    HH\MemoAgnosticImplicitContext and HH\MemoSensitiveImplicitContext are now sealed to their approved platform subclasses. Direct subclasses outside that hierarchy are no longer accepted. 529cf1661b
  • Wed, May 21
    HH\meth_caller() now requires class<mixed> rather than classname<mixed>. Pass a class pointer such as C::class; classname strings and variables no longer satisfy the public signature. 880710ad0c
