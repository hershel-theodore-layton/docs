Week 40: Sep 29–Oct 5, 2025

16 noteworthy changes, organized by the source changelog sections.

Highlights

8 changes
  • Mon, Sep 29
    Sound-dynamic inference now carries supportdyn through indexed container element types and through intersections whose type variables have dynamic-supporting upper bounds. This removes false errors around generic array access and constraints such as CanTraverse. 6dbec9f7df 679954de6d
  • Mon, Sep 29
    With checked unsafe casts disabled, HH\FIXME\UNSAFE_CAST<TFrom, TTo>(await $value) now goes through the same await-lifting path as a bare await $value. Unsafe-cast unwrapping happens during AST elaboration, avoiding bytecode differences caused by a later compiler pass. 9e9c5e8ba1
  • Mon, Sep 29
    The new per-type autoload ordering correctly handles re-entry from a user error handler while loading a unit, preventing the handler's own class loads from observing a paused autoloader. 24a6049013
  • Wed, Oct 1
    The required-shape-field lint no longer recommends direct indexing when the shape itself is optional. Calls such as Shapes::idx($optional_shape, 'field') no longer receive a false Lint[5005]. 65985eea5e
  • Wed, Oct 1
    enum<T> hints now validate the enum's base type instead of treating T as a class name. Valid generic enum hints no longer receive Typing[4148], while incompatible enum bases receive the ordinary subtype error. 2e533742f9
  • Thu, Oct 2
    Typing[4104] and Typing[4105] now say "too few positional arguments" and "too many positional arguments." Named-argument arity has separate diagnostics, so the revised wording identifies the part of a call that is actually wrong. 9a285f64ab
  • Fri, Oct 3
    HHVM now provides openssl_x509_get_upn(mixed): string for extracting a Microsoft User Principal Name from an X.509 certificate's subject-alt names. It throws OpenSSLException when the certificate cannot be parsed or has no valid UPN; its omitted capability brackets mean [defaults], and the public HHI follows on October 14. fd5f758c2c
  • Fri, Oct 3
    The x86 JIT now preserves native stack alignment while filling omitted default arguments, avoiding ABI-unsafe calls into the uninitDefaultArgs helper. 751e89833e

Future Changes

7 changes
  • Mon, Sep 29
    Experimental expression trees can reference enum members and named class constants directly, desugaring them through the DSL's new visitClassConstant() hook instead of requiring ${...} splices. Dynamic class names remain unsupported; the hook's declared coeffects participate in normal caller-superset checking and are not implicitly granted. 1ad2b8920b
  • Mon, Sep 29
    Opt-in constraint_method_call=true uses function-type parameter contravariance to infer simple instance calls, including previously underconstrained lambda parameters. The path currently excludes explicit type arguments and unpacked arguments and synthesizes a [defaults] callable target; callers must therefore provide the default capability set, even if the concrete method is purer. Diagnostics now point to the missing method or mismatched argument rather than the whole call. 75142ebf79 eab5021b17
  • Tue, Sep 30
    Unsupported expression-tree forms now receive specific Parsing[1002] explanations instead of a generic syntax error. Diagnostics distinguish await, new, string interpolation, global constants, and [] indexing, making DSL migrations more actionable. ee1a3a88e8
  • Wed, Oct 1
    Under the preview readonly feature, HHVM's runtime declaration of HH\legacy_is_truthy() now accepts readonly mixed, allowing readonly values to be inspected without a cast. Its explicit [] capability list is unchanged, so callers still need no ambient capabilities; the public HHI follows on October 20. 3df24d5bf5
  • Wed, Oct 1
    Nested experimental expression trees no longer have a separate expression_tree_nested_bindings gate. They may capture bindings from an outer expression tree once expression trees themselves are enabled. 5b90e946d6
  • Thu, Oct 2
    Unstable named parameters now participate in function-type subtyping and override arity checks. A subtype must accept every named parameter promised by its supertype and may not make an optional named parameter required. a354304453
  • Fri, Oct 3
    Violating the staged __NeedsConcrete override rule now produces Warn[12027] instead of Typing[4487]. This permits hierarchy-by-hierarchy adoption while continuing to flag an override that imposes a stricter concreteness requirement than its parent. 9ec3de9342

Breaking Changes

1 change
  • Fri, Oct 3
    The Watchman extension has removed HH\watchman_query(), HH\watchman_subscribe(), HH\watchman_check_sub(), HH\watchman_sync_sub(), and HH\watchman_unsubscribe(). Projects calling these APIs need to replace them; HH\watchman_run() and HH\ext_watchman_version() remain. b61ee2ea1b
