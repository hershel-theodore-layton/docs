Week 45: Nov 3–Nov 9, 2025

9 noteworthy changes, organized by the source changelog sections.

DayWeekMonth
←Previous week→Next week

Highlights

5 changes
  • Mon, Nov 3
    Declared-type hovers now omit like types (~T) introduced by pessimization. Hovering a call therefore shows the API's source-level declaration instead of the type checker's sound-dynamic implementation detail. d1ed3e8f71
  • Tue, Nov 4
    A new hh --package-lint FILE command finds references to definitions in a file, providing a targeted way to estimate the impact of moving that file across package boundaries. Its initial JSON response includes each definition and its references. 572e5972c8
  • Wed, Nov 5
    Higher-rank type-parameter escape diagnostics now explain that a generic parameter may be escaping its defining scope, instead of asserting that it definitely did. 801396cf42
  • Thu, Nov 6
    Custom-error file patterns now support a ** globstar suffix, which matches zero or more path segments after a fixed prefix, and optional path segments. This makes a single custom-error rule usable across nested or partially optional directory layouts. de62e41f78
  • Thu, Nov 6
    get_executable_lines() no longer repeatedly replaces its line-table cache while walking bytecode offsets, fixing a potentially large per-request memory leak. 80fec6c413

Breaking Changes

1 change
  • Wed, Nov 5
    DOMElement::getAttribute() is now declared to return string instead of an untyped result, matching its runtime behavior. Code that null-checks the result or relies on implicit conversion from it may now produce type errors. bc373ee080

Future Changes

3 changes
  • Wed, Nov 5
    Expression trees now accept late-static-bound method calls and class constants written with static::; self::, parent::, and dynamically selected classes remain unsupported. Expression trees are still an ongoing-release feature. 5699d743ec
  • Fri, Nov 7
    First-class polymorphism now rejects higher-rank type variables that escape their defining scope, closing a case previously missed by the rank check. This applies to the still-experimental polymorphic-function-hint work. 520dda036c
  • Sun, Nov 9
    Custom-error v2 rules can now match the expression-tree "unsupported operator" diagnostic, including the affected DSL class and operator member. Expression trees remain an ongoing-release feature. da440e2b51
