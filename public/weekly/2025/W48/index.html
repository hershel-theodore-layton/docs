Week 48: Nov 24–Nov 30, 2025

9 noteworthy changes, organized by the source changelog sections.

DayWeekMonth
←Previous week→Next week

Highlights

4 changes
  • Mon, Nov 24
    <<__RequirePackage>> on interface and abstract methods no longer makes hackc try to insert a runtime assertion body where no method body can exist, fixing compilation of these declarations. 7850ed7b86
  • Tue, Nov 25
    The null-safe pipe operator |?> is fully released and no longer requires an unstable-feature opt-in. Hack also adds Warn[12031] when its left side cannot be null and Warn[12032] when it is always null. 9c1592aef2 49a01a024d
  • Wed, Nov 26
    Custom-error ** file-prefix patterns no longer swallow a failed required path segment and match an unintended file. Exact and prefix patterns now share the corrected segment matcher. 95025e2a47
  • Fri, Nov 28
    When a generic type is supplied the wrong number of arguments, Hack now stops after the arity error instead of inventing Tany arguments and producing misleading follow-on constraint errors. db68c7eef3

Future Changes

2 changes
  • Mon, Nov 24
    Named-argument completion snippets now keep parameter_name= outside the editable placeholder, so typing the value no longer deletes the parameter name. Optional parameters remain omitted from call completions. Named arguments are still unstable. c2d246ec9d
  • Tue, Nov 25
    Type inference for immediately invoked lambdas now accounts for named arguments, fixing both missed errors and rejected valid calls under the unstable named-arguments feature. d3ef01c111

Breaking Changes

3 changes
  • Tue, Nov 25
    Redundant ?-> checks have moved from lint codes 5633/5654 to Hack warnings 12029/12030. Update warning filters and suppressions accordingly; expression-tree lowering is excluded to avoid false positives. 41573b779d 65841bca20
  • Tue, Nov 25
    Exceptions thrown by Thrift adapter methods are now exposed to Hack as TProtocolException with ERR_UNEXPECTED_EXCEPTION, rather than leaking the original exception. Code that catches a particular adapter exception will need to catch the protocol exception instead. ae27f8a1f0
  • Wed, Nov 26
    HH\Facts\types_with_attribute() now returns lazy-class values instead of raw strings, statically changing from vec<string> to vec<classname<nonnull>>. Its attribute parameter changes from string to class_or_classname<ClassLikeAttribute>, so callers holding an unrefined string may need to supply a typed class name. Type aliases remain excluded, and the function remains capability-free ([]). 22eba707f3
