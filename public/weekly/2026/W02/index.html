Future Changes

5 changes
  • Mon, Jan 5
    Runtime refinements now understand nullable predicates such as $x is ?T, including while decomposing variants that use the pre-stable case-type where-clause feature. abdfbd2d1e
  • Mon, Jan 5
    Optional parameters and parameters with defaults may now precede a type-splat parameter such as ...Targs. This supports typed-format helpers whose optional format argument is followed by the format tuple. 1128e6a255
  • Mon, Jan 5
    Experimental constraint-based method-call inference can defer resolving an underconstrained receiver inside expression trees. It is gated by try_constraint_method_inference; support for several method features and polished diagnostics is still incomplete. 0000cf2e3e
  • Tue, Jan 6
    Case types moved from Preview to OngoingRelease, so ordinary case-type declarations no longer need __EnableUnstableFeatures('case_types'). Case-type where clauses remain in Preview, and recursive case types are not part of this pre-stable release. a5022daa7c
  • Fri, Jan 9
    Case-type refinement with shape predicates now supports optional fields and open shapes. The implementation deliberately favors a bounded-cost, less exhaustive split over combinatorial decomposition. c2b9b24bf5

Highlights

4 changes
  • Tue, Jan 6
    The strongly typed HH\TypedFormatString implementation introduced on December 23 was temporarily reverted while a memory regression was investigated. This rollback lasted until the corrected reland on January 9. 5b0e3057c1
  • Wed, Jan 7
    Hack now provides declarations for HH\watcher_query(), HH\watcher_get_clock(), HH\ext_watcher_version(), and the watcher option/result shapes, eliminating unbound-name errors for the existing watcher extension API. These functions omit coeffect brackets and therefore require [defaults]. 6aab9d86c4
  • Fri, Jan 9
    HH\TypedFormatString<TFormatter, TArgs> durably relanded after the January 6 rollback. Typed format strings can be passed through first-class helpers, string literals infer their placeholder tuple from the expected formatter, and concatenation combines compatible argument tuples. HH\FormatString<T> remains a compatibility alias using (mixed...). aeef5f7ec1
  • Fri, Jan 9
    sprintf(), HH\invariant(), and HH\invariant_violation() retain [] while gaining typed variadic arguments. printf() still omits a capability list and therefore requires [defaults]; the stronger format typing does not relax its caller requirement. aeef5f7ec1

Breaking Changes

1 change
  • Fri, Jan 9
    Components of a concatenated typed format string must each be valid format fragments. Expressions such as "%" . "d" are rejected even though the resulting plain string would form a valid placeholder. aeef5f7ec1
