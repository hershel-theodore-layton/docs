Week 4: Jan 19–Jan 25, 2026

14 noteworthy changes, organized by the source changelog sections.

Highlights

5 changes
  • Mon, Jan 19
    HH\Lib\Str\format() and format_l() now preserve a HH\TypedFormatString<SprintfFormat, Targs> placeholder tuple through their ...Targs arguments, so first-class wrappers retain format-argument types without a FIXME. Both functions remain []. 60d4799e1f
  • Mon, Jan 19
    The runtime definition of HH\TypedFormatString is now present alongside its HHI declaration, so runtime type structures and aliases agree with Hack's typechecker. e0e9fe6410
  • Tue, Jan 20
    Prefixed string literals such as re'/foo/' are now accepted by both the runtime parser and typechecker in constant positions, including class constants, enum values, and default parameters. d7b2ba9381
  • Wed, Jan 21
    Package requirements are now modeled as declaration-level access requirements rather than as part of a callable's function type, fixing their interaction with polymorphism. New <<__SoftRequirePackage('pkg')>> support represents a requirement on a softly included package. 4762185971
  • Fri, Jan 23
    Document formatting no longer consumes the last nonblank line when the only required edit is removing trailing newlines. 21784c07ad

Breaking Changes

3 changes
  • Mon, Jan 19
    Calls to Str\format() and Str\format_l() now type-check variadic arguments against literal placeholders instead of accepting arbitrary mixed arguments. Fix newly reported calls by matching each placeholder's required type or by correcting the format string. 60d4799e1f
  • Tue, Jan 20
    hh_client --save-state, hh_server --save-state, and --gen-saved-ignore-type-errors have been removed, along with the corresponding server RPC. Generate saved states with hh_distc, which can also run locally. f6cc06f5b6
  • Wed, Jan 21
    Hack now validates package-requirement annotations against the declaring file's package and checks their relationships across overrides. A <<__RequirePackage>> or <<__SoftRequirePackage>> target must strictly include the declaring package; remove redundant same-package annotations and correct unrelated or only-soft-included targets. 4762185971

Future Changes

6 changes
  • Tue, Jan 20
    In the pre-stable readonly feature, <<__IgnoreReadonlyError>> on a callable parameter now applies to the callback's return coercion and propagates through nested, bidirectionally typed lambdas. Readonly-returning callbacks no longer produce the suppressed mismatch at either level. cb714a6040 2409334bab
  • Tue, Jan 20
    Safe Abstract and __NeedsConcrete now have user-facing documentation and tested warning examples ahead of the needs_concrete configuration's release. a50aed61a0
  • Wed, Jan 21
    IDE hover text for an argument matched by a pre-stable type-splat parameter now includes the tuple index, such as $args[1], instead of losing the parameter name after the first element. a62607552a
  • Wed, Jan 21
    Safe Abstract now rejects <<__NeedsConcrete>> on final classes, where the annotation would be ineffective or make the method unusable. This affects projects that explicitly enable the not-yet-released needs_concrete checks. 76c06fb06c
  • Thu, Jan 22
    Safe Abstract now rejects <<__NeedsConcrete>> on instance methods and constructors. Such members already require an instantiated—and therefore concrete—class, so the annotation is redundant. 5e8effe259
  • Fri, Jan 23
    For the pre-stable type-splat feature, IDE signature help and autocomplete now expand an instantiated parameter such as ...(int, int) $args into indexed arguments, restoring parameter hints and enum completions for generic splat APIs. a264781a6a
