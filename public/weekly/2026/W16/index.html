Week 16: Apr 13–Apr 19, 2026

8 noteworthy changes, organized by the source changelog sections.

Security

1 change
  • Mon, Apr 13
    EXIF parsing now clears stale allocation state after an out-of-memory failure, preventing the cleanup-time use-after-free tracked as CVE-2026-23867. The same resynchronization also fixes overflow and pointer-lifetime bugs in Vector::splice(), Memcache Unix sockets, IPv6 socket scopes, and stream socket peer addresses. 4242fe4f88

Breaking Changes

4 changes
  • Mon, Apr 13
    More standard-library declarations now use their concrete runtime types instead of HH\FIXME\MISSING_*_TYPE: apache_setenv() returns bool, and a large set of Intl functions now have concrete return types. Code that relied on these APIs being effectively untyped may gain type errors. 2531f61026 85b373a37f
  • Tue, Apr 14
    Built-in declarations for ICU, IntervalTimer, OpenSSL, and file APIs now replace many missing parameter and return annotations with concrete types matching their implementations. This improves inference but can expose calls that previously flowed through an effectively untyped signature. a6c59630b8 4b503a24a7 9e5cfbd2ba 9e2dfa95ca
  • Wed, Apr 15
    The standard-library HHI cleanup now gives concrete types to process, POSIX, zlib, bzip2, math, cURL, APC, array, output-buffering, multibyte-string, and network APIs. Expect stronger return inference and possible errors where callers passed values that the old HH\FIXME\MISSING_*_TYPE placeholders accepted. 3c04556fba 0272e4b014 f046e9836b 2a767b8e7c 1cdffbf5a7 250c92cb6d 25c06b37a8 0422f445b7 ac3aeb093e ea542c231f 08104dcc6d
  • Thu, Apr 16
    Intl HHI declarations now give concrete parameter types to Collator, date formatter, message formatter, number formatter, resource bundle, calendar, timezone, grapheme, and break-iterator APIs. Calls that depended on the previous missing parameter types may now fail type checking. 7a015e0bdb

Highlights

1 change
  • Tue, Apr 14
    hh_client and hh_single_type_check now support --enforcement-at-pos-batch, which reports whether HHVM enforces the type at each requested source position and returns the concrete enforced bounds where applicable. It covers declarations as well as call arguments, returns, property assignments, constructors, and array indices. 985a6cb528

Future Changes

2 changes
  • Wed, Apr 15
    The experimental with_refinement_alias feature now permits I with { type T = ... } on the right-hand side of type aliases and type constants. It remains pre-stable and still disallows such refinements in is and as expressions. 23e4d7e770
  • Fri, Apr 17
    HH\TypeStructure now declares the optional with_refinements field produced for refined types, including whether each refinement is a context and its equality, upper-bound, or lower-bound data. This accompanies the still-experimental type-alias refinement work. 10b493a51a
