15 noteworthy changes, organized by the source changelog sections.

Breaking Changes

7 changes
  • Mon, Apr 20
    Fileinfo, mailparse, and Async MySQL declarations now replace additional missing HHI types with concrete runtime signatures. b10a40ecb8 750d2077d0 edf0a3bfbc
  • Mon, Apr 20
    is expressions now validate their right-hand type even when the expression is not being used to refine the left-hand side. Invalid type hints that previously escaped localization now produce errors. 8b49bb1304
  • Mon, Apr 20
    Inherited class, classname, and string return constraints now apply the same configuration-controlled warnings, errors, and class-to-string conversions as directly declared constraints. Projects relying on the previous inherited-constraint gap may see new runtime diagnostics or failures. 14aceb719a
  • Wed, Apr 22
    Memcached HHI declarations now give concrete types to 27 methods, including boolean operation results, getResultCode(): int, getResultMessage(): string, and a nullable-string constructor argument. 3b7f6b9fb4
  • Wed, Apr 22
    A new Warn[12042] reports property access through dynamic, including dynamic intersections and supportdyn wrappers. This mirrors the existing warning for dynamic method calls and may affect projects that promote warnings to failures. faa70e09f3
  • Thu, Apr 23
    Higher-rank generic validation now traverses nested types when looking for escaping type parameters. Invalid escapes that were hidden below the top level can now be reported. 653e481d9c
  • Thu, Apr 23
    Reflection declarations now expose concrete types for Reflection::getModifierNames(), ReflectionFunction::isDisabled(), and several ReflectionProperty queries. This improves inference and can reject callers that relied on the previous missing types. 64fd36da55

Future Changes

4 changes
  • Mon, Apr 20
    The experimental TypeStructure representation for refinements now correctly types as and super entries as vec<mixed>, since a refinement may carry multiple bounds. 7713c28719
  • Tue, Apr 21
    Parser and AST support has landed for unstable class and interface aliases such as class C = D; and interface I = D;, including generic syntax. The feature is gated by class_aliases_everywhere and is not yet stable for production use. 314b03ace4 0150d9ae67
  • Wed, Apr 22
    The manual now documents Preview-stage recursive case types, including guarded and mutual recursion and the current limitation around single-variant shape definitions. e2f872bce4
  • Thu, Apr 23
    The experimental type-alias refinement checker now looks through aliases when rejecting refinements in is, as, and reified-generic positions, closing a way to hide an unsupported refinement behind a typedef. 59f35936dd

Highlights

3 changes
  • Tue, Apr 21
    Go-to-definition on nameof SomeTypeAlias now navigates to the alias declaration instead of incorrectly resolving through typename to the HH\string HHI declaration. f0c1da1d2a
  • Thu, Apr 23
    Runtime tests with an abstract <<__Enforceable>> type constant are now allowed even when its as bound is not itself enforceable; a concrete implementation can still provide an enforceable type. edc62dc1c2
  • Thu, Apr 23
    Nullable ?as no longer triggers package-boundary diagnostics. Unlike as, a failed ?as yields null rather than fatalling, so it does not require the asserted type to be available across the boundary. 13a5c1efc4

Security

1 change
  • Wed, Apr 22
    popen() and pclose() now obey the same AllowExec and AllowUngatedExec process-execution gates as exec(), system(), and proc_open(). Deployments that disable either gate will now reject these shell-pipe APIs too. d33c8c0de0
