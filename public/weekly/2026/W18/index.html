Week 18: Apr 27–May 3, 2026

18 noteworthy changes, organized by the source changelog sections.

Highlights

5 changes
  • Mon, Apr 27
    The contexts and capabilities manual now states the key calling rule explicitly: a context list describes the callee's requirements, and the caller must provide a capability set containing them. An omitted list means [defaults]; [globals, ctx $f] requires both globals and whatever the callback requires rather than granting either capability. 7ee1c54c3c ace7b77acc
  • Mon, Apr 27
    The manual now documents how enforceable generic upper bounds affect runtime checking, including when several enforceable bounds contribute to the check. 63fa7dabb5
  • Tue, Apr 28
    The revised coeffects manual now explains capability subtyping in the correct direction: a callable requiring fewer capabilities is usable where one requiring more was accepted. For example, a function requiring [read_globals] or [] can stand in for (function()[globals]: void), because callers prepared to supply globals can satisfy the narrower requirement. af05be4b70
  • Fri, May 1
    Redundant __PackageOverride analysis can now verify dependency-graph candidates against their typed syntax, excluding references such as nameof, ::class, and attributes that do not affect the production build. This makes package-override linting less prone to conservative false positives. f41333f091
  • Sun, May 3
    The Hack manual now documents null-safe pipes, tuple splatting in function calls, and the distinct read, append, update, and out-of-bounds behavior of keyset subscripts. 9413aef365 b47447cf10 646cd890cf

Security

2 changes
  • Tue, Apr 28
    ZipArchive::getFromName() and getFromIndex() now reject requested lengths and stored entry sizes above the signed 32-bit range before passing them to a 32-bit string buffer, preventing truncation from becoming a buffer overflow. Oversized reads return an empty string. d27c559a44
  • Thu, Apr 30
    HHVM's reference-count optimizer now models the reified-generics vec passed to NewRClsMeth and NewRFunc as an ownership transfer. This prevents it from deleting a required increment and causing a use-after-free when the resulting callable is released before another use of the same generics vector. 24fd5d8e9b

Future Changes

8 changes
  • Tue, Apr 28
    The unstable class-alias pipeline now reaches HackC: aliases are emitted as .class_alias Alias = Original; records with a corresponding class reference. Generic arguments are parsed but are not propagated to HHVM; only class or interface renaming is supported. 32dff62192
  • Tue, Apr 28
    The manual now includes an initial guide for the experimental require this as trait constraint. 742d1cba0d
  • Wed, Apr 29
    Type-constant super bounds have moved from Preview to Ongoing Release. They no longer require per-file unstable-feature enablement, but remain pre-stable while the rollout continues. 81c412b911
  • Wed, Apr 29
    RepresentableAs has moved from Unstable to Preview. 451c9c875a
  • Wed, Apr 29
    The manual now documents the experimental named_parameters feature, including that named parameter names are part of the API and must be preserved by overrides and function types. 75d958cfed
  • Thu, Apr 30
    A staged package check can now diagnose cross-package type aliases used at runtime-enforced positions such as parameters, returns, properties, regular enum bases, and generic upper bounds. The main package_allow_enforceable_type_alias_violations switch still defaults to allowing these uses, so this is rollout groundwork; a secondary relief switch can exempt aliases that resolve to class-like types if needed. bfa29842f8 2433ee724c
  • Fri, May 1
    Preview HH\Runtime\reveal() is now explicitly pure ([]). This narrows its caller requirement from omitted brackets—which mean [defaults]—to no capabilities, so it can be called from pure code; representable_as itself remains in Preview. 6cbf331237
  • Sun, May 3
    Shape-field punning now has manual examples, including shorthand construction and pattern-like field reuse. The shape_field_punning language feature remains Unstable. 358b5ca388

Breaking Changes

3 changes
  • Wed, Apr 29
    Returning a value from a generator is now a parser error (Parsing[1002]) instead of a later NAST-check error. HHVM therefore rejects such code even when it is compiled without a full typecheck; generators always complete with null. 89a5c434fc 32080e91f0
  • Thu, Apr 30
    Package-boundary checking for non-null as expressions now descends into shape field types, including nested shapes and shapes inside tuples. Strict package configurations can therefore report cross-package asserted types that were previously missed; nullable ?as remains exempt. 879b436c9d
  • Sun, May 3
    The typechecker no longer gives HH_FIXME\MISSING_TYPE_IN_HIERARCHY special Tany treatment. Remove remaining uses of this obsolete migration type and replace them with accurate declarations; a project-defined alias with that name now behaves like an ordinary alias. 0a3657f7e7
