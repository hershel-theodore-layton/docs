Week 20: May 11–May 17, 2026

14 noteworthy changes, organized by the source changelog sections.

DayWeekMonth

Highlights

4 changes
  • Mon, May 11
    Date/time APIs now expose substantially more precise types: DateTime::add(), sub(), and setTimezone() return DateTime; diff() returns DateInterval; DateTimeZone::getOffset() returns int; and the corresponding procedural helpers no longer return mixed. 6d919856b8
  • Wed, May 13
    Package lints 5655 and 5656 now report cross-boundary references even when the caller has __SoftRequirePackage for the target's original package. Soft loading does not make an override edge or class-pointer edge structurally valid. 34397692a5
  • Wed, May 13
    AsyncMysqlConnection::getSslVersion() returns the TLS version negotiated for the connection, or an empty string when unavailable. Its declaration omits a capability list and therefore requires [defaults]. 6d84b0bce8
  • Thu, May 14
    When a foreach target attempts to reassign a variable used by a dependent capability such as [$v::C], error 4404 now points at the offending target variable rather than the entire foreach expression. This is a position fix; it does not change the capability requirement. 584dc969b8

Breaking Changes

3 changes
  • Mon, May 11
    DateTime::diff() now accepts DateTimeInterface rather than mixed. Calls whose argument is still statically mixed must refine or validate it before calling; this aligns Hack's signature with the runtime check that already existed. 6d919856b8
  • Wed, May 13
    The package_allow_reifiable_tconst_violations and package_allow_all_generics_violations configuration escape hatches have been removed. Reified type-constant and generic package-boundary violations are now always hard errors. 8a12a927f2
  • Thu, May 14
    package_allow_typedef_violations has been removed. Transparent type aliases that cross an unavailable package boundary now always produce a hard error, and their referenced symbols count as production-affecting edges. b96d110f20

Future Changes

7 changes
  • Mon, May 11
    DateTimeImmutable::createFromFormat() is now typed as the pre-stable case type BoolOrDateTimeImmutable, accurately representing its false failure result without falling back to mixed. 6d919856b8
  • Tue, May 12
    Experimental constraint-based method-call inference now honors <<__IgnoreReadonlyError>> on callable parameters, including nested lambda return comparisons. 108d91d898
  • Tue, May 12
    Unstable shape and tuple destructuring now has dedicated parser and AST nodes for patterns such as shape('x' => $x) = $value and tuple($x, $y) = $value. Typing and emission were still landing separately. 3f5a8d867a
  • Wed, May 13
    The accepted named-parameters HIP is now published with the proposed syntax, ordering and compatibility rules, reflection model, and rationale. Named parameters remain in Preview. c9337aa404
  • Wed, May 13
    Unstable shape and tuple destructuring can now be typechecked, including its interactions with subtyping, dynamic, and like types. Runtime emission was still pending on this date. 4343f5bcae
  • Thu, May 14
    The __NeedsConcrete HIP is now published, documenting the proposed Safe Abstract contract for static methods that may only be called through a concrete class. The checks still require needs_concrete=true. 75d4d868bb
  • Fri, May 15
    The shape-and-tuple-destructuring HIP is now published, covering pattern syntax, typing, runtime behavior, evaluation-order constraints, and the intended migration away from permissive list(...) destructuring. The feature remains Unstable. defc97a3eb
