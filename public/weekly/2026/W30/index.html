Week 30: Jul 20–Jul 26, 2026

13 noteworthy changes, organized by the source changelog sections.

Highlights

10 changes
  • Mon, Jul 20
    DNS response parsing now bounds compressed-name expansion by the actual response length, fixing an uninitialized-memory disclosure when processing malformed DNS records. 43a1cce7f4
  • Wed, Jul 22
    Packages can opt into stronger boundaries with enable_strict_isolation=true in PACKAGES.toml. Dynamic package observation through package expressions and __RequirePackage/__SoftRequirePackage is rejected for these packages. aae1d23bb6
  • Wed, Jul 22
    Strict-isolation packages enforce their boundaries even for paths covered by package_exclude_patterns. Non-excluded code also cannot reference excluded-path code inside the strict package. 8466c8e6b6
  • Wed, Jul 22
    User attribute classes from strict-isolation packages now receive cross-package access checks, including attributes on functions whose effective package must be established before checking them. cb537175eb
  • Thu, Jul 23
    Hershel's HHVM has optimized the implementation of HH\Lib\Vec\slice, a hot function in portable-hack-ast-linters. This reduces whole project lint latency by ~30%. Improvements scale more than linearly with the size of the file being linted. Projects with larger files may see a greater improvement. This change is included in hersheltheodorelayton/hhvm-full:26.06.05. See also HHVM issue for perf on the hhvm repo. b983bd51b1
  • Thu, Jul 23
    Strict-isolation package boundaries now apply to class and alias references throughout type hints, including nested type arguments and inheritance declarations. acdcb7f349
  • Thu, Jul 23
    C::class references into strict-isolation packages now produce hard package-boundary errors instead of only migration lints. 1d9d645d5f
  • Thu, Jul 23
    nameof C and exception-class references in catch now respect strict-isolation package boundaries, including excluded-path restrictions. f39c87984b
  • Thu, Jul 23
    Predicate-based refinement now understands runtime-checkable reified type parameters, enforceable abstract type constants such as this::TC, and this itself. 6c2e8cda7f
  • Thu, Jul 23
    HH\class_or_classname<T> is now a covariant opaque type accepting both class<T> and classname<T>. Related Facts APIs use it so callers can pass either representation. e9914ef5cf

Breaking Changes

2 changes
  • Tue, Jul 21
    HH\is_vec_or_varray() and HH\is_dict_or_darray() have been removed. Their direct replacements are HH\is_vec() and HH\is_dict(). 911cd41801
  • Thu, Jul 23
    Case-type disjointness now treats Hack enums as arraykey, rejecting combinations with other integer or string variants that enum is checks cannot reliably distinguish. c38b6f7d06

Future Changes

1 change
  • Tue, Jul 21
    Opt-in variadic named parameter types now support call checking and function subtyping. Unexpected argument labels can be absorbed by a named variadic, whose element type is checked, rather than causing spurious missing-argument errors or internal typechecker errors. adc7faffa3
