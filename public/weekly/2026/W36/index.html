Week 36: Aug 31–Sep 6, 2026

15 noteworthy changes, organized by the source changelog sections.

Highlights

7 changes
  • Mon, Aug 31
    The JIT now resumes named-parameter function entries with the correct calling convention when translation is disabled. a105247ec2
  • Mon, Aug 31
    Fileinfo no longer calls qsort() on an empty magic-rule set, avoiding an undefined-behavior sanitizer abort for magic files without named rules. b9c8a5d593
  • Tue, Sep 1
    HHVM avoids a crash when an external-thread task result invokes HH\Asio\join() on that same task during deserialization, such as from __wakeup(). A task already being processed cannot be re-entered or cancelled as though it were still waiting. fe5bf06c3c
  • Tue, Sep 1
    Facts symbol-to-file lookups avoid constructing an unnecessary filesystem path before returning the resolved filename. 1e7673c9fb
  • Wed, Sep 2
    Uncaught internal failures in hh_client now use exit status 221 rather than the type-error status 2. Malformed key-value command-line arguments use status 64 and no longer print a backtrace. bab52cef3d 3148255d19
  • Thu, Sep 3
    If a saved-state dependency graph disappears before a worker opens it, hh_server reports an unavailable graph and the monitor can restart it to restore the graph, instead of panicking through the dependency-query FFI. 838b5ecfe8
  • Fri, Sep 4
    The analysis command --find-isolatable-clusters discovers seed files with no incoming references; --json exposes the seed paths and count for scripts. This initial discovery does not yet compute complete movable clusters. ee4c52b940 fa20924e45

Future Changes

8 changes
  • Tue, Sep 1
    Experimental named parameters may now be optional before required parameters in function-type hints, matching function declarations. Optional positional parameters must still follow required positional parameters. 3e8b127f49
  • Wed, Sep 2
    A draft proposal documents limited variadic named parameters for typed mocking, including accepting additional named arguments without exposing them in the function body. This commit changes the proposal only; the prototype remains behind the default-off named_variadic_type and variadic_named_parameters typechecker options. 46a19fe934
  • Wed, Sep 2
    Function-type displays now print optional named in the order accepted by the parser, making displayed hints easier to copy into source. c66ce9b3dc
  • Thu, Sep 3
    The default-off reject_promoted_property_redeclaration option adds a typechecker diagnostic for constructor parameters that re-promote inherited properties. Private non-LSB ancestor properties remain legal to shadow. 56beee3a0a
  • Thu, Sep 3
    The variadic-named-parameter proposal now specifies contravariant argument acceptance correctly and documents its memoization and readonly restrictions. These are proposal edits, not newly enabled language features. b5adffd627 0044eee66e
  • Thu, Sep 3
    Experimental named-variadic subtyping now checks an explicit optional parameter against the expected named-variadic type when that parameter shadows the implementation’s variadic, preventing incompatible functions from being accepted. e41f9dc708
  • Fri, Sep 4
    IDE autocomplete now suggests unused optional named argument labels as well as required ones, ordering required labels first and preserving declaration order within each group. a6237234b5
  • Fri, Sep 4
    Experimental named-variadic method overrides now track positional and named variadics separately, avoiding incorrect arity and compatibility results. 39180f36f8
