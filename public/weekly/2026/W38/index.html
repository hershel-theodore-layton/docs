Week 38: Sep 14–Sep 20, 2026

8 noteworthy changes, organized by the source changelog sections.

Highlights

3 changes
  • Mon, Sep 14
    serialize() accepts an options dictionary, including zstd=true; HH\serialize_with_options() and unserialize() also support streaming zstd compression or decompression. This avoids materializing the full uncompressed serialized string at once. 35e214ff7a
  • Mon, Sep 14
    HH\ImplicitContext\PreparedContext::runBatch() and runBatchAsync() no longer fail with a coeffect violation before running callbacks with [] or [zoned_shallow] contexts. Their shared preparation helper now declares [leak_safe]. 1d894fd5cc
  • Fri, Sep 18
    The new HH\BlobKV\Reader and HH\BlobKV\Writer APIs read and write binary key/value data in Blob containers. Writers require explicit finalize(), enforce a single in-progress writer per output path, and are rejected in repo-authoritative mode; readers remain available there. d3cbd3bacb

Breaking Changes

2 changes
  • Mon, Sep 14
    Files assigned to implicit packages by their paths may no longer use __PackageOverride to escape that membership. 51094a61e4
  • Fri, Sep 18
    Packages must opt into deployed-package checks with allow_deployed_packages_checking=true before code can use package, __RequirePackage, or __SoftRequirePackage for them. This flag cannot be combined with enable_strict_isolation. The separate prohibition based only on a soft-include edge is removed; ordinary strict-inclusion checks still apply. 55e411dea0 5a43f0ec1f e5f9e4c461

Future Changes

3 changes
  • Wed, Sep 16
    With the default-off use_module_error_for_member_access option enabled, member-level module boundary violations use Typing[4444] instead of the general visibility code 4112. Protected-internal members receive separate module and protected-visibility checks. 38c3759cf4
  • Wed, Sep 16
    The runtime and typechecker expose HH\implicit_package_family_exists() and HH\get_all_implicit_package_families() for configured implicit package families. Family availability follows hard deployment membership, while enumeration returns declared family paths and dependencies without materializing member packages. 1ae3ff4005
  • Fri, Sep 18
    The typechecker temporarily rejects named parameters on <<__Memoize>> functions and <<__Memoize>>/<<__MemoizeLSB>> methods with NastCheck[3113], because their generated wrappers can fail at runtime. Make the parameter positional or remove memoization. The restriction remains in HHVM 26.09.29 even after the runtime fix on September 22. b74f9bcdca
