Week 39: Sep 21–Sep 27, 2026

21 noteworthy changes, organized by the source changelog sections.

Highlights

3 changes
  • Mon, Sep 21
    HHVM fixes an allocation/free size mismatch for shared logging arrays wrapping arrays with a string-key table, which could pass an interior pointer and incorrect allocation size to jemalloc. 3514f777ed
  • Fri, Sep 25
    Under implicit pessimization, functions and non-overridable methods returning vec<mixed>, dict<arraykey, mixed>, vec_or_dict<arraykey, mixed>, or keyset<arraykey> can retain those exact return types as fully runtime-enforced top container types. Overridable methods retain pessimization so narrower element-type overrides remain sound. 1a3b9802b4
  • Fri, Sep 25
    Explicit reified type arguments on parent instance-method calls such as parent::method<int>() are now preserved by the typechecker, avoiding false missing-type-argument errors. ee3fbe441c

Breaking Changes

2 changes
  • Mon, Sep 21
    __PackageOverride is also rejected when a file physically belongs to an explicit package with strict isolation, closing the same escape route already blocked for implicit packages. e48e4b7856
  • Wed, Sep 23
    Dynamic string-to-class references to classes in strict packages now receive an independent strict-package check in the interpreter, JIT, and native class APIs. raise_dynamic_class_load_error defaults to true for strict packages; explicit false selects sampled notices. __DynamicallyReferenced does not bypass this policy. cb6bca1916 8eecec3bf1 9495634c20 aaef0e6260

Future Changes

16 changes
  • Mon, Sep 21
    Named callback arguments now participate in the same staged lambda-inference passes as positional arguments, removing inference failures that depended on argument order. Function subtyping also keeps named parameters out of positional variadic and type-splat tails. e620163247 d708f251ce
  • Mon, Sep 21
    HHVM now compares named method parameters by label and optionality separately from positional parameters. This accepts implementations with extra optional named parameters and rejects missing parameters or incompatible inout positions that combined slot counts could conceal. 7cb12ea0ef
  • Mon, Sep 21
    Runtime checks now keep reordered named parameters paired with their original type hints and defaults. Readonly checks also bind passed arguments to the correct parameter when optional named arguments are omitted, fixing both false rejections and missed violations in the interpreter and JIT. d9825e5b77 9fed0ff97f
  • Tue, Sep 22
    Explicit null supplied to an optional named parameter is now preserved instead of being replaced by its default, including under repo-authoritative optimization. 3255cabee6
  • Tue, Sep 22
    Readonly argument flags now follow the same reordering as named argument values, including constructor calls, fixing incorrect acceptance and rejection of calls. 3dac710c75
  • Tue, Sep 22
    Memoization wrappers now order and forward named parameters correctly, fixing runtime failures for memoized functions and methods. The temporary typechecker restriction from September 18 remains active; this commit does not yet make the combination available to normally typechecked code. d3597e3fe5
  • Wed, Sep 23
    Renaming a named parameter now counts as a declaration change during saved-state initialization, ensuring callers are rechecked for missing or unexpected argument labels. Positional parameter names remain irrelevant to that comparison. 7ce004b6be
  • Thu, Sep 24
    Opt-in class-pointer bound widening can infer classname<T> when generic constraints coerce a class<T> value into a string-like type, preventing overly narrow inferred types. The lower- and upper-bound rollout levels remain zero by default. d0bdd39d7f
  • Thu, Sep 24
    Readonly values may now be passed as named arguments when the corresponding parameter accepts readonly values. The typechecker binds readonly checks by label, fixing errors caused by omitted or reordered named arguments. 45fa38f59c 3e1ffa6122
  • Thu, Sep 24
    Argument-unpacking checks now count only positional parameters and arguments, fixing spurious arity errors around optional named parameters. Positional variadics followed by named parameters are also identified correctly during lambda checking. 0cf2a094cf 626c5ea848
  • Thu, Sep 24
    --infer-dynamic now preserves named labels in suggested callback types; a call such as $f(n=1) produces (function(named int $n): mixed) instead of a positional function type. c7a7d272a9
  • Thu, Sep 24
    meth_caller now rejects methods with named parameters, including named variadics, with Typing[4527] because the runtime cannot call those methods through that helper. 4b05630dab
  • Thu, Sep 24
    Repo-authoritative analysis no longer assigns argument types to incorrect parameter slots when named arguments are omitted, preventing an HHBBC invariant failure. Compiler-generated coeffect rules also skip unemitted nameless variadics when calculating parameter indexes. 1c03d83d74 b32892d482
  • Sat, Sep 26
    --enforcement-at-pos and --enforcement-at-pos-batch now match named arguments by label and count positional arguments separately, restoring correct enforcement information for reordered calls, constructors, and variadics. 47ddda6381
  • Sun, Sep 27
    Experimental shape-splat is refinement now resolves splatted type-parameter bounds into a shape view, so impossible shape tests can refine the true branch to nothing. This refines the tested value, not the type parameter; as casts are unchanged. 9be68998a0
  • Sun, Sep 27
    Experimental shape-splat normalization avoids repeated map insertion, optional-field widening, and repeated merging that could cause quadratic work on large splats. 3020a207bd faa6de4b64 d2f0bd921a 9cff0cce34
