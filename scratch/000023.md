Commit title: Specialize thawing of ordered maps which have a constructor accepting a presorted container
Commit body:
Summary:
[Looking at the relevant Strobelight profile](https://fburl.com/strobelight/5d51zejs), it looks like the choice to use `reserve_if_possible` and insert with the hinted iterator for thawing `folly::sorted_vector_map` was not the best move for performance. A benchmark I slapped together locally shows that building up from `T::container_type` and constructing from that with `folly::sorted_unique_t()` is substantially faster. Given that this function is taking up [0.38% of CPU in AdRanker](https://fburl.com/strobelight/dcjug8ob), I think this is well-worth specializing, in line [with ot's comment on the original diff](https://www.internalfb.com/diff/D40159640 (https://github.com/facebook/hhvm/commit/8b040eb2d4f46ea861f826907406e923fbb9ee4a)?dst_version_fbid=435609285355473&transaction_fbid=1152456575347929):

> We should explore specialization only if it is a measurable improvement on top of that.
