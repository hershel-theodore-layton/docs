Commit title: Don't widen Map and Vector for array assignment
Commit body:
Summary:
Type inference replaces the inner types of various arrays and containers with type variables when typing an expression `e1[e2] = e3`. For Hack arrays (`vec`, `dict`) this makes sense since they're copy-on-write and users expect to be able widen their types by inserting new things.

For Hack collections, users generally expect the types to stay fixed (when you're not building up from an empty) Map, and the key and value types are invariant because collections are mutable, so it doesn't really make sense to widen for every assignment. Further, the widening was causing exponential behavior under sound dynamic because none of the intermediate `Map<#N, #M>` types unify with each other (even though the type variables were solved!), so you get ever growing unions.
