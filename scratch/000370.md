Commit title: Simplify Rust Thrift service log lines
Commit body:
Summary:
Current Rust thrift service log lines are very long with repetitive information.

This makes using them difficult, which makes debugging and writing Rust services difficult.  I have a 32" 4k monitor and I cannot split my screen in half without getting line wrapping in my terminal, and I don't really care about the information that's presented.

I'd like to see us roll a "standard FB logging" fitler, maybe with some options, but for now I'd like to tweak the service logs to make it easier to leverage tracing_subscriber::filter::dynanmic_filter_fns to handles this on a per-service basis.

This diff:
* changes the span name of the handler from per-method to a single `handler` span so we can easily drop that span's fields from log lines if desired
* Removes the nested `service_handler` span which IMO doesn't provide much value given our top level span
* Removes `method` from `success` and failure messages because the top level span already has that
* Moves the error from a field to the message payload because I personally find an event with no payload a bit harder to read.

Let me know if you have any strong opinons on this.
