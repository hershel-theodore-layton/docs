Commit body:
Summary:
This diff combines a bugfix to make hh_distc's naming table builder compatible with
hh_naming_table_builder, and some refactoring to ensure the bugfix does not cause
a regression.

Unfortunately, naming tables contain entropy that prevents bitwise comparison.
Instead we diff the results of `sqlite3 naming.sql .dump`.

The bugfixes:
* FileDeclHash must be computed before php stdlib decls are removed, and must
be computed over the decls in reverse file order (the hash is order sensitive).
* Naming table entries (RelativePath, FileSummary) pairs must be sorted by RelativePath
before insertion.

Refactoring:
* use par_sort_by() to sort naming table pairs before insertion (saves 1/2 sec)
* HhServerProviderBackend::parse_and_cache_decls() reversed the decls twice,
now it does not reverse them at all, but uses iter().rev() to visit them in forward file order.
* FileSummary::from_hashed_decls() was split so DeclParser::parse_and_summarize()
could avoid filtering php stdlib functions twice, and avoid cloning ParsedFileWithHashes.
* added naming_sqlite::Names::close(), so callers of build_at_path() can handle close errors.
* converted various Vec::from_iter(...) to collect() to clean up code.
