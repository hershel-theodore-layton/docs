Commit title: service: add an on-demand GC for Windows
Commit body:
Summary:
One of the major issue for EdenFS on Windows is its inability to shrink the
working copy: once a directory is a placeholder on disk, the only way to remove
it is to remove all of its childrens. This is usually only achieved when that
directory is removed from the repository and the user updates past the commit
that performs the removal, suffice to say, this is a rare event.

In order for EdenFS to thus shrink the working copy, we need a mechanism that
would proactively scan the repository and delete bits that haven't been used in
a while. As a first step, we can provide a Thrift API to do this on the
entirety of the repository with no regards to how recently files/directories
were accessed.

Future diffs will add an automatic background GC, as well as running this in
doctor for repositories with very large working copy (>1M files).
