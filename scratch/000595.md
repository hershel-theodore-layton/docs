Summary:
This diff changes ParsedFilesWithHashes:
1. It's now immutable.
2. The moment of construction is when you decide whether to respect deregister_php_stdlib (rather than being left as an easily-forgotten mutating afterthought)
3. Its iter() and into_iter() methods return DoubleEndedIterator so you can decide at the callsite whether you want to iterate in forward or reverse lexical order (rather than this being an implication of whether you happened to reverse it earlier)
4. It preserves the previous diff's behavior, that decl-hashes reflect the result of deregister_php_stdlib
5. For FFI serializing, the type `OcamlReverseParsedFileWithHashes` indicates clearly that the ocaml list is going to have decls in reverse order.
   1. There are also a few places which use what I call `OcamlReverseUnfilteredParsedFileWithHashes`, i.e. they haven't undergoing filtering by deregister_php_stdlib. I'm sure this is a bug, but I left it in because this diff preserves all existing behavior.
6. `FileSummary` no longer does any deregistering or reversing itself. That has all been moved into ParsedFileWithHashes.

This diff doesn't change any behavior. It merely expresses the existing behavior, but now with non-mutating code.

## How to review this diff

1. Read **direct_decl_parser.rs**. This introduces the types, and has comments explaining what they're for.
2. Read **summary.rs**. The deregistering behavior has been moved out of `FileSummary` here, into `ParsedFileWithHashes` constructor.
3. Read **rust_decl_ffi.rs**. This shows how the type `OcamlReverseParsedFileWithHashes` explains, through type-name, what content the ffi'd list on the ocaml side will have
4. Read **hackrs/decl_parser/decl_parser.rs**. This also showcases how the new `ParsedFileWithHashes` makes it easier for consumers.
5. Read **full_fidelity_ast.ml**. I pushed up through the callstack my concerns about functions that don't deregister php_std_lib in the way you'd expect them to.
6. All other files are just straightforward consequences of the change.
