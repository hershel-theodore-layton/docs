Commit title: Give AtomicCoreCachedSharedPtr slightly stronger reclamation guarantees
Commit body:
Summary:
`AtomicCoreCachedSharedPtr` uses hazard pointers to manage the `shared_ptr` cache, so on `reset()` the old references are released in background threads. Releasing them synchronously (waiting for any outstanding readers) would be expensive due to the design of hazard pointers, but we can at least ensure that they are all released when `AtomicCoreCachedSharedPtr` is destroyed.

See for example in the changed test how this makes the semantics a bit more deterministic.
