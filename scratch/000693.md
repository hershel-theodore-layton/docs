Summary:
## What

1. Create infra for (un)marshalling constraints and *then* solving. Use this infra in our tests.

2. We also add a command that is useful for playing around in development:

`dump-marshalled:$mode:$constraints_dir`

where:
-  `$mode` is 'local' or 'global' (just like for our other args)
- `$constraints_dir` is the directory in which to dump constraints

**This diff is a noop change aside from adding a new command**. The infra is used later in the stack

## Why

Later in the stack, the marshal/un-marshal infra is used from shape_analysis_logger behind a flag.

The benefits of storing constraints on the file system are:
- Faster development cycle, since we don't have to wait for re-generating constraints every time we want to iterate on the logic for reading and solving constraints (including experimenting with granularity). (details in FB section below)
- When solving, we don't compete with the rest of hh for memory, which gives us more headroom
- While the short-term goal is to do file-level solving, we need in the near future to do repo-level solving:
    - I doubt we can achieve repo-level solving without pulling constraint-solving out of hh. There's some precedent for the approach here on global constraint solving for generic type arguments  persisted to disk.
    - I want to leave the door open for incremental analysis in future: "saved state" for shape analysis/HIPS. While I doubt we need incrementality for file-level granularity, I am hoping to not close off technical opportunities for repo-level granularity (all else being equal)

## Details

We solve constraints to disk and read them back in `shape_analysis.ml`. This is used with `hh_single_typecheck` in tests.

What made marshalling types to disk interesting is that we need to *either* use the `Marshal.Closures` flag or remove al closures from types before persisting. I chose the latter option because later in the stack we read constraints from disk using a different binary than the one that created the constraints. Closures can't be unmarshalled using a distinct binary.

Closures are removed from types by wiping type reasons, using code borrowed from madgen in wipe_type_reason.ml
