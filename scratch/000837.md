Commit title: Separate hint elaboration
Commit body:
Summary:
The current naming phases couples several different elaboration and validation passes. Furthermore, some of these passes should be visible to both hh and hackc whilst some are solely typechecking concerns.

This diff separates hint elaboration as first step in decoupling the hh naming phase. It introduces a number of explicit passes that were previously intertwined:
- `naming_elab_hints` transforms hints into their canonical form and replaces malformed hints with `Herr` markers
- `naming_elab_everything_sdt` performs pessimisation of hints under the `--everything-sdt` typechecker flag
- `naming_elab_soft` performs elaboration / removal of soft hints under the `--soft-types-as-like-types` typechecker flag
- `naming_elab_hkt` performs removal of higher kind types under the `--higher-kinded-types` typechecker flag
- `naming_validate_builtin_enum` checks for restricted use of internal classes before enum class elaboration
- `naming_validate_supportdyn` checks for restricted use of the `SupportDynamic` class, under the `--enable-supportdyn-hint` typechecker flag
- `naming_validate_xhp` checks for common mistakes when referencing xhp classes

The remaining elaboration steps (for enum classes, xhp, invalid expression, typechecker option driven elaboration and expression invalidation) will be separated in subsequent diffs.

Note that some of the validation phases will ultimately be rephrased as NAST checks to reduce the number of AST traversals required.
