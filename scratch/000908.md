Summary:
Fix a handful of bugs discovered while comparing .hhdg depgraphs between `hh_distc`
and `hh`:

`hhdg::DependencyName::Const()` was missing the `type` field, since it represents
class constants and type constants.

`ConstName` was incorrectly converting to `DependencyName::Const` - it should be `GConst`.

`DependencyHash::of_class()` and `of_member()` were incorrectly converting `ToplevelSymbolHash`
to big endian bytes and hashing them as if they were a symbol; instead they should be
using the u64 directly.

fix `DependencyHash::of_member()` by passing the underlying u64 to `hash2()`.

Made `Dep.make` and `Dep.make_member_dep_from_type_dep` consistent by using
`hash2(kConstructor, type_hash, "")` for both, similar to the AllMembers encoding,
and fixed facebook/hh_fanout/member.rs to use the same hash2() for constructors.

`DependencyHash::of_class()` is not fixable in its current form, so delete it. It was called in two places:
* `DeclComparer::go_class_constants()` in decl_comparer.rs was attempting to create
an AllMembers hash; it should have been using `of_member()` with `""` as the member name.
(see Dep.make in typing_deps.ml)
* `Constructor::make_dep_hash()` in member.rs should use of_member() for constructor hashes.

`hash2_ocaml()` did not clear the MSB when converting ocaml `int` to Rust `u64`, resulting
in different hashes for hash2-style dependencies when computed in Rust. Fixed by clearing the MSB.
This was already fixed in FromOcamlRep for depgraph/dep::Dep, we just missed the
other code path.
