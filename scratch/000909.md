Commit title: Create dep edges with --save-64bit
Commit body:
Summary:
For saved state generation, `hh_distc typecheck` needs to generate dep edges.
This diff adds options to do it:
* --save-64bit <dir> (like the hh option) generates raw edge files into the
given dir. Unlike hh, these are in .hhdg_delta format, which are about 2x smaller
than raw .bin edge files produced by hh. `hh_fanout build` already supports both
formats, so why not use the more compact one?
* --save-human-readable-64bit-dep-map <dir> (like the hh option) generates
human readable (hash, DepType, symbol) triples in `batch-N.txt` files used for debugging,
but only for edges we get from FoldedDeclProvider.

The detailed flow for each batch:
* when folding decls in a batch, capture all edges produced by FoldedDeclProvider, then group
them by file (the file that declared the dependent side of each edge). This naturally
discards hhi->hhi edges since we never typecheck hhi files. It also de-duplicates
edges discovered while folding transitive ancestor classes, which would otherwise appear
in many batches.
* when folding a single file, capture all edges from the type checker and discard all
edges produced by FoldedDeclProvider. The latter are probably more truthful but
do not have parity with the type checker.
* how do we get edges from the ocaml typechecker to rust? we use InMemoryMode,
then call Typing_deps.register_discovered_dep_edges, which moves the discovered
edges into a Rust DepGraphDelta. We then send that delta to the main worker process
in a WorkResult along with missing symbols.
* for each batch produce one DepGraphDelta for finished files, and another for pending
files. They will be merged later.

and in hh_distc:
* when each batch completes, merge all finished DepGraphDeltas and write a single
batch-N.hhdg_delta. These .hhdg_delta files are about 2x smaller than raw .bin files
because they group edges by dependency.
