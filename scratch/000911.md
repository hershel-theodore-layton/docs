Summary:
I recently dug deeper into direct_decl_parser::parse_file_for_typechecking D41439789 (https://github.com/facebook/hhvm/commit/15013efb97e0d2d0d3fa4ae47371d42604c3a42a). What I discovered:
1. If you just call `parse_file_for_typechecking` it will probably do the wrong thing because that function doesn't respect .hhconfig `deregister_php_stdlib`. (In this current hh_decl diffstack, it was manifest as a few symbols being defined in both HHI and in WWW)
2. I rewrote functions around that so that ParsedFileWithHashes is now the definitive API for taking into account that .hhconfig flag. (It has the added property of calculating decl-hashes).

This diff therefore changes hh_decl to (1) use ParsedFileWithHashes, (2) use decl-hashes that it obtained from ParsedFileWithHashes rather than recalculating them itself.

This is doubly nice because I can remove names::hash_decl and names::hash_decls -- all decl-hashing is now done solely inside ParsedFilesWithHashes.
