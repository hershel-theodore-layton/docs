Commit title: Change union `ensure` semantics
Commit body:
Summary:
Previously, merging two union patches would ignore the second patch if the second patch `ensure`'d a different member than the first patch. That is:

```
fooPatch = myUnionPatch.ensure({foo: {}}).patch({foo: ...})
barPatch = myUnionPatch.ensure({bar: {}}).patch({bar: ...})

fooPatch.merge(barPatch) // barPatch will be effectively ignored, since the union already has a set member
```

The problem with this is that now, the behavior of `merge` differs from the behavior of applying the two patches sequentially; that is,

```
fooPatch.merge(barPatch);
fooPatch.apply(myUnion);
```

gives a different result from:

```
fooPatch.apply(myUnion);
barPatch.apply(myUnion);
```

The second result should be the desired behavior (where `barPatch` overrides the currently set union member).

This diff modifies the `merge` function for `UnionPatch` to better match the expected behavior such that the `ensure` field on the subsequent patch is taken into account.
