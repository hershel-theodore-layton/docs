Commit title: introduce --error-format plain to de-overload --error-format raw
Commit body:
Summary:
After some light experimentation, I discovered that `hh` and `hh_single_type_check`
format Errors.Raw differently. `hh` (and its cousins) use Raw_error_formatter, while
`hh_single_type_check` (and its cousins) use Errors.to_string.

Why do we have two raw formats? This looks like a migraiton to introduce
a new format that stalled when it encountered our test suite.

1. Extend Errors.format with a new variant: Errors.Plain, which *all* tools implement with Errors.to_string.
2. Modify the `hh_single_*` tools to use Raw_error_formatter for Errors.Raw
3. Update test suites to pass `--error-format plain` to `hh_single_*` tools, to preserve the existing formatting.
4. In Rust, rename Errors::display_raw() to display_plain() to align terminology.
5. Update CLI help to say what the default error format is.
