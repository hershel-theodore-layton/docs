Commit title: Don't schedule another Watchman query if we have a pending query in flight already
Commit body:
Summary:
When you call `update()`, Facts promises you a future that will complete after at least one Watchman query has both started and completed since you called `update()`.

Today, we accomplish this by always scheduling a Watchman query when you call `update()`. While this guarantees that there will be a query that starts and finishes after you call `update()`, this does mean that we'll dogpile Watchman if we have many simultaneous calls to `update()`.

I'm proposing this optimization/fix: we track the number of queries that haven't yet been issued by keeping a queue length variable. If the queue length is greater than 0, then there is already a Watchman query which hasn't started yet, and in that case, we don't need to schedule another Watchman query.
