Commit title: Source worker count from JK instead of PRCB. Reduce worker count per group.
Commit body:
Summary:
Currently, the worker thread configuration is thrift based and is written out by PRCB. I wanted to test setting different number of worker threads per stacked group. [Canarying these changes with PRCB was problematic](https://fb.workplace.com/groups/1767122506698877/posts/5681520835259005), so I moved this configuration to [this new JK](https://www.internalfb.com/intern/justknobs/?name=revproxy%2Fknobs#worker_thread_count).

The current ATL3-specific JK configuration is reducing the number of threads to allow each group handle at least 2x its peak volume without a regression in penalty. Ideally, this would be something updatable dynamically, but we don't currently support dynamic scaling of thread pools, so for changes to be enacted a (hotswap) restart is required.

Based on testing so far, the worker pool reduction reduces the context switches to the pre-stacked level and wins back about half of the efficience loss from stacking.
