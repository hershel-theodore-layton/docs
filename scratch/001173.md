Commit title: Check for repoOptions with an empty path
Commit body:
Summary:
Native Facts and native autoloading only works inside of a directory containing `.hhvmconfig.hdf`. We determine the root of your project by starting at the script you're running, and then looking for this file in parent directories.

Today, if you attempt to run HHVM with native autoloading outside of a directory that has a `.hhvmconfig.hdf` file, you'll get a cryptic mangled `std::filesystem::filesystem_error`:

```
[jhemphill@devbig351.ftw3 /tmp/q]$ cat q.php
<?hh

<<__EntryPoint>>
function q(): void {
  var_dump(HH\Facts\enabled());
}

[jhemphill@devbig351.ftw3 /tmp/q]$ /usr/local/hphpi/bin/hhvm --config /usr/local/hphpi/cli.hdf -v Autoload.Enabled=true -m run  q.php
Fatal error: unexpected NSt10filesystem7__cxx1116filesystem_errorE: filesystem error: cannot make canonical path: Invalid argument []
```

Apparently, if you run HHVM outside of a repo with `.hhvmconfig.hdf`, `getRepoOptionsForRequest` will return a `HPHP::RepoOptions` with an empty string path. If we get an empty string path, I opt to say that we aren't in a directory that supports autoloading at all, and we should just run with autoloading disabled.
