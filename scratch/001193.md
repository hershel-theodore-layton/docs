Commit title: Switch DepGraphDelta byte ordering and tagging
Commit body:
Summary:
DepGraphDelta stores its values in files in big-endian byte order (x86 is
little endian), and sets a tag bit on every dependent to distinguish it
from a dependency, rather than the other way around.

These two facts prevent us from simply pointing into a memory mapped
file to produce a `&[Dep]` for the dependents, so reverse both conventions.

.hhdg files already use native endian values so any theoretical portability
issue mixing machines of different endiannesses is pretty weak.
