Commit title: Unify and extend checks around `static::*` in constant expression positions
Commit body:
Summary:
Our checking around invalid constant values at parse time is haphazard and somewhat bit-rotted.
* We have a superglobals check that has been subsumed by a general "superglobals are banned" check
* Checks for `static::*` and `parent::class` would only check the top level:
```
const mixed FOO = parent::class; // Bad!
const mixed BAR = vec[parent::class]; // Totally OK!
```
* For the forthcoming `const_default_func_args` option, we didn't even consider `static::*` to be non-constant.

This fixes all issues by folding these errors together into a single error. The error messaging has degraded somewhat, but we now properly highlight the illegal constants at parse time. The next diff adds an option to fix the last bullet: for now the default is to allow it.
