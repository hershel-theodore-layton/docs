Summary:
`ShardAlloc` manages memory in chunks. It has a global control data keeping track of 3 values
1. `current_start` is the start of the current chunk
2. `current_end` is the end of the current chunk
2. `current_next` is the pointer to the next available space within the current chunk

In `ShardAlloc`'s implementation of the `Allocator` method `allocate`, we
1. calculate the amount of space needed to allocate a new blob
2. check that the space is within bounds of the current chunk (< current_end). If so, put it there; if not,
3. we call `extend` to 1) allocate another chunk, and 2) try fitting the blob within this new chunk by repeating steps 1 & 2

This diff refactors the logic in `allocate` by
- adding a function `alloc_blob`: does steps 1 + 2, returning an option indicating success or failure
- renaming `extend` to `alloc_chunk` to be consistent: does step 3.1
