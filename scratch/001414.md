Commit title: Add 'extends' dependencies in typing code rather than during decling
Commit body:
Summary:
High-level goal: decling code should not add any dependency edge. This diff is a first step towards this.

Why? Decling code is run non-deterministically and possibly multiple times. Decling logic will be ported to rust and shouldn't have to deal with dep edges.

We basically remove Decl_env.add_extends_dependency and all its caller and instead add `Typing_env.add_extends_dependency` and appropriate calls to it.

I've tried multiple options for where in the code to add those edges:
* In Typing_extends. However we would forget edges from members of `xhp_attr_uses`, which are parent classes providing XHP attributes.
* In `Typing_env.get_class` by adding a `~is_parent` parameter to the function. But we would still miss edges from members of `xhp_attr_uses` because we never call `get_class` on them!

The solution I've opted for is to reuse the same code which also adds a constructor dependency, in `Typing_class.check_is_tapply_add_constructor_dep` (which I've renamed).
