Commit body:
Summary:
D39361121 (https://github.com/facebook/hhvm/commit/cebbb4a0cdd32684d5e664409b23829a1db4cead) ended up breaking the behavior of `XLOG_SET_CATEGORY_NAME()` by
using `folly_detail_xlog_filename` instead of `folly_detail_xlog_category`.

Unfortunately, gcc-8.5 crashes with an internal compiler error when trying to
compile this code if we do use `folly_detail_xlog_category`.  We still do have
some CI automation for our open source GitHub repositories that test the
behavior of folly with gcc-8.5, so for now I have added an `#if` check that
keeps the older broken behavior when compiling with gcc-8.5.
`XLOG_SET_CATEGORY_NAME()` is rarely used, and I figured it was probably
better to keep the constexpr log category name calculation rather than having
`XLOG_SET_CATEGORY_NAME()` work but log category name calculation occur at
runtime.
