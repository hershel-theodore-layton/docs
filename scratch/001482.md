Summary: The `Function<R(A...) noexcept>` constructor will soon accept only callables which are noexcept-invocable. Currently, it is possible to construct an instance of this `Function` type with a callable which was not nothrow-invocable. This callable, of course, may throw - in which case the owning `Function` terminates. Let us expose these mismatches at compile time.
