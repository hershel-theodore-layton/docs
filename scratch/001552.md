Commit title: Add ppx for deriving combined top-down / bottom-up transforms
Commit body:
Summary:
A ppx to derive combined top-down/bottom-up transforms over OCaml datatypes.

When added with `[@deriver transform]` to a group of type declaration, deriver will generate:
- A module `Pass`
- For each type and for each record field or variant constructor marked as `transform_explicit`, a function `transform_...`
- For type which is non-opaque and traversable and for each traversable record field or variant constructor marked as `transform_explicit`, a function `traverse_...`

A type is not traversable if
- it is a primitive
- it is a variant where all data constructors are not traversable
- it is a record where all fields are not traversable

A data constructor is not traversable if
- it is a nullary constructor
- it is a tuple constructor where all types in the tuple are not traversable
- it is an inline record constructor where all fields are not traversable

A record field is not traversable if the type of the field is not traversable.

The code for the `transform_...` function is generated by `Gen_transform.gen_{sig, str}` and the structure item for the optional `traverse_...` function by `Gen_traverse.gen_str`.

The `transform_...` functions have the following form:

```
and (transform :
          t -> ctx:'ctx -> top_down:'ctx Pass.t -> bottom_up:'ctx Pass.t -> t)
          =
          fun elem ->
            fun ~ctx ->
              fun ~top_down ->
                fun ~bottom_up ->
                  let initial_ctx = ctx in
                  match top_down.Pass.on_t with
                  | Some td ->
                      (match td elem ~ctx with
                       | (_ctx, `Stop elem) -> elem
                       | (ctx, `Continue elem) ->
                           let elem = traverse elem ~ctx ~top_down ~bottom_up in
                           (match bottom_up.Pass.on_t with
                            | None -> elem
                            | Some bu ->
                                (match bu elem ~ctx with
                                 | (_ctx, (`Continue elem | `Stop elem)) ->
                                     elem
                                 | (_ctx, `Restart elem) ->
                                     transform elem ~ctx:initial_ctx
                                       ~top_down ~bottom_up))
                       | (_ctx, `Restart elem) ->
                           transform elem ~ctx:intial_ctx ~top_down
                             ~bottom_up)
                  | _ ->
                      let elem = traverse elem ~ctx ~top_down ~bottom_up in
                      (match bottom_up.Pass.on_t with
                       | None -> elem
                       | Some bu ->
                           (match bu elem ~ctx with
                            | (_ctx, (`Continue elem | `Stop elem)) -> elem
                            | (_ctx, `Restart elem) ->
                                transform elem ~ctx:initial_ctx ~top_down
                                  ~bottom_up))
```
This will vary when the `~restart:`Disallow` argument is provided to the deriver.

The form of the `traverse` function will depend on its type.

The `Pass` module has the signature of the form:
```
module Pass : sig
  type t = { ... }
  val identity: unit -> t
  val combine: t -> t -> t
end
```

The type `Pass.t` is generated using `Gen_pass.gen_{sig, str}`, the `identity` function is generated by `Gen_identity.gen_{sig, str}` and the `combine` function by `Gen_combine.gen_{str, sig}`.

The type `Pass.t` will contain :
- a field, named `on_ty_[type name]`, for each type declaration group to which the `[@deriving transform]` attribute is attached which does not have a `[@transform.opaque]` attribute
- a field, named `on_fld_[type name]_[field name]`, for each record field with a `[@transform.explicit]` attribute
- a field, named `on_ctor_[type name]_[constructor name]`, for each variant constructor with a `[@transform.explicit]` attribute
- a field, named `on_[module name]`, for each type mentioned in the type declarations but defined in an external module
