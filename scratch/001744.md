Commit title: Clean up use of File APIs, and fix at least one bug
Commit body:
Summary:
Replace `std::fs::OpenOptions::new().read(true).open(f)` with
the equivalent `File::open(f)`.

Also, in some places, replace `std::fs::OpenOptions::new().write(true).create(true).open(f)`
with `File::create(f)`. However, these are *not* equivalent, because the latter also truncates
the file. If you're not appending  to the file it probably is, since otherwise if you write
less data then was there before, the trailing garbage remains in the file (!).
We had this bug in `write_edges_file` and `write_dep_graph`. I don't know if
`hh_custom_dep_graph_save_delta` is wrong or not, since it specifies `append(true)`
(and was, redundantly, specifying `write(true)` as well). I'm assuming it's intentionally
appending more edges to a file.
