Commit title: experimental support for <<__NoAutoDynamic>> attribute on toplevel functions and classes
Commit body:
Summary:
Under implicit pessimisation (eg. `--everything-sdt`), the `<<__NoAutoDynamic>>` attribute can be placed on functions and classes to locally disable the implicit pessimisation.

This diff:

- updates decl_parsing to prevent the implicit pessimisation of type annotations inside class and functions  annotated with `<<__NoAutoDynamic>>`.  Since the smart parser combinator for classes or function is invoked only _after_ invoking the combinators for all the inner class/function elements, upon parsing  a type, the corresponding combinator does not know if the enclosing function/class is annotated with `__NoAutoDynamic` or not.  We overcome this by setting a flag to true upon building the `__NoAutoDynamic` attribute, and resetting it upon closing the top-level element.  A similar strategy is already used to rewrite the `self` keyword with the enclosing class in type constants;

- ensures decl-types that are implicitly pessimised not during parsing but during decl querying are not pessimised if the enclosing element is labelled `<<__NoAutoDynamic>>`.  This is done by updating the `maybe_pessimise_xxx` functions in `Decl_enforceablity`.

- updates Naming so that implicit pessimisation is not performed on functions and classes annotated with `<<__NoAutoDynamic>>`.
