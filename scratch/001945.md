Commit title: fix handling of SDT traits
Commit body:
Summary:
A trait "type" `T` should support the dynamic type only if one of its trait requirements constraints the trait to be used only from SDT classes, and the trait itself is declared SDT.

The strategy that ensures this behaviour is the following:
- during decl parsing, the `support_dynamic_type` flag is not set for traits, even if they are marked SDT;
- during decl flattening, trait requirements are checked and, if needed, the `support_dynamic_type` flag is set on the folded decl for the trait.
