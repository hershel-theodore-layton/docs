Commit title: Non-existent classes in HHBBC should result in Bottom, not unresolved classes
Commit body:
Summary:
For historical reasons, if you try to resolve a class which doesn't
actually exist (or is uninstantiable), we produce an "unresolved"
class. All the reasons for this are no longer relevant, so instead
treat such a missing class as Bottom instead. Doing so revealed a
couple of pre-existing bugs and some places which was conflating
unresolved classes with non-existing classes. (A non-existing class
was always unresolved, but an unresolved class was not necessarily
non-existing).
