Commit title: Make aast::Block a newtype
Commit body:
Summary:
Generate a tuple struct of one field instead of a type alias when converting `Aast_defs.block` in hh_oxidize (as we did for `Aast_defs.program` in D33721950 (https://github.com/facebook/hhvm/commit/837fcf45d07e06243d1d5d33644da2f14cfe4857)). This allows us to handle `Block` differently from `Vec<T>` when implementing traits, which is useful in elaboration passes which need to handle blocks (e.g., [elab_block](https://www.internalfb.com/code/fbsource/%5Bbaef246f0321%5D/fbcode/hphp/hack/src/elab/pass/elab_block.rs?lines=23), where the `on_ty_block` method of the Pass trait and Block's impl of the Transform trait can be generated after this diff and D43097011).

Alternatively, maybe we could ditch the Transform trait and do something similar to `ppx_transform` (generate a toplevel function `transform_ty_foo` for every type `Foo`; understand type expressions in the code generator, generate `list.iter_mut().for_each(transform_ty_foo)` for fields of type `Vec<Foo>`; etc).

Alternatively, maybe we could implement `Transform for Vec<Stmt>` (and likewise for everything else that occurs in a vec in the AST, since specialization isn't ready yet(?)) rather than `impl<T: Transform> Transform for Vec<T>`. We'd also need to revise hh_codegen to emit `Pass` methods for type aliases (specifically, `on_ty_block`) in D43097011.
