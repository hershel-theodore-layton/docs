Commit title: SDT function call inhibited by like
Commit body:
Summary:
There is an incompleteness associated with like-type pushing, illustrated by the following example (using explicit SD syntax).
```
function vectorAppend_likes<Tv as supportdyn<mixed> >(~Vector<Tv> $v, ~Tv $item):void { }

<<__SupportDynamicType>>
class Wrap<+T> {
  public function __construct(private T $item) { }
}

<<__SupportDynamicType>>
function getVecInt():~vec<int> { return vec[3]; }

<<__SupportDynamicType>>
function makeVector<T as supportdyn<mixed>>():Vector<T> {
  return Vector<T>{};
}

function test2():void {
  $x = makeVector<Wrap<int>>();
  $y = new Wrap(getVecInt()[0]);
  vectorAppend_likes($x, $y); // vectorAppend_likes<Wrap<int>> works
}
```
Consider the call `vectorAppend_likes`. Its arguments have types `Vector<Wrap<int>>` and `Wrap<~int>`. We would like Hack to infer `Wrap<int>` for the generic parameter but currently it infers `Wrap<~int>`. The call gets rejected, because the type of `$x` is not a subtype of `~Vector<Wrap<~int>>`.

The fix is to make use of the following equivalence: for a covariant type `Wrap`, if `t <:D dynamic` then `Wrap<~t> <: ~u` iff `t <: u`. For now, we apply this equivalence in the case that `u` is a type variable, so in the example above, we have `Wrap<~int> <: ~#1` and instead of immediately reducing this to `Wrap<~int> <: #1` (which loses solutions), we reduce it to `Wrap<int> <: #1`. The new function `strip_covariant_like` removes `~` from covariant positions in a type to achieve this.
