Commit title: fix the module boundary error message when invoking a top-level function from a method
Commit body:
Summary:
In the example below a module boundary violation arises when method `C::getFoo` calls the top-level function `foo`:

```
\\\ file a.php
<?hh

module A;

internal function foo(): void { echo "I am foo"; }

\\\ file b.php
<?hh

module B;

class C {
  public function getFoo(): void { foo(); }
}

<<__EntryPoint>>
function bar(): void {
  (new C())->getFoo();
}
```

The interpreter correctly reports the error:

```
Accessing internal function foo in module A from module B is not allowed
```

but the jit incorrectly reports:

```
Accessing internal method C::foo in module A from module B is not allowed
```

This is due to the fact that the jit invokes `raiseModuleBoundaryViolation` by passing `C` as class context (since the caller is method `C::foo`), which triggers the "internal method" error message.  This diff fixes the incorrect error message by performing an extra check on the callee when printing the error message.
