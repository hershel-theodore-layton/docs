Commit title: Always pessimise inout params in implicit mode
Commit body:
Summary:
In implicit mode, we don't pessimise `inout` parameters. We should - they act as both parameter and return.

For the function type decl itself, we pessimise `inout` parameters regardless of enforcement - we don't know how the function is implement.

For the definition, we add `like` to the type if it's not enforced.

Note that we end up accepting more programs in implicit mode because of our use of dynamic-aware subtyping for override checking. This will be addressed in a future diff.
