Commit title: Improve build time by using multiway lookup
Commit body:
Summary:
`FindOrdinal<T, Args...>` returns the Ordinal of T in `[Args...]`.

Current implementation is scanning `[Args...]`, which has `O(N)` lookup time complexity.

This diff added `MultiwayLookup` class, which is defined this way (in this diff `N == 63`):

```
template<class A0 = T0, class A1 = T1, ..., class A_N = T_N>
struct MultiwayLookup {
  template<class> static const int value = 0;
  template<> static const int value<A0> = 1;
  template<> static const int value<A1> = 2;
  ...
  template<> static const int value<A_N> = N + 1;
};
```

So that `MultiwayLookup<Args...>::value<T>` returns ordinal of `T` in `[Args...]` in O(1). The limitation is that `[Args...]` can not have more than `N` elements.

If `[Args...]` has more than `N` elements, we can use `MultiwayLookup` to lookup in batch -- check first `N` elements to see whether we can find `T`. If not, we check the rest elements.

Note that this only works if there is no duplicated elements in `[Args...]` (otherwise we can not consturct `MultiwayLookup`).

This diff implemented `FindOrdinalInUniqueTypes` which uses the algorithm mentioned above.

NOTE: Due to [MSVC](https://godbolt.org/z/vee6se1ET) and [GCC](https://gcc.gnu.org/bugzilla/show_bug.cgi?id=85282) bug, currently this optimization is only enabled for clang.
