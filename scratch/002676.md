Commit title: Distinguish between defs checked once and under normal/dynamic assumptions.
Commit body:
Summary:
This diff changes the `under_dynamic_assumptions` environment section to hold three values rather than a boolean do distinguish the following three cases:

- The method/function was only checked once because it was deemed that it didn't need a check under dynamic assumptions.
- The method/function was checked twice and it was under "normal" assumptions that is using the (possibly pessimised) types from the source code.
- The method/function was checked twice and it was under dynamic assumptions that is the parameters and the return were treated as dynamic.

This change allows us to make statements about the code by inspecting the IDE. For example, we can fire a lint rule based on types iff it the lint result can be derived both under the dynamic and normal assumptions or there wasn't a need to typecheck twice.
