Commit title: Make inline assembly work with AT&T and Intel style
Commit body:
Summary:
This fixes the header when included in an `-masm=intel` context for clang >= 14. Clang versions before that always assumed AT&T for inline assembly regardless of the `-masm=` flag. Though FWIW GCC always interpreted inline assembly according to the `-masm` flag. See also https://reviews.llvm.org/D113707

See https://gcc.gnu.org/onlinedocs/gcc/Extended-Asm.html "Multiple assembler dialects in asm templates" for this unusual syntax.

While on it also fix the operand to ask for an 8-bit register with `%b0`.
