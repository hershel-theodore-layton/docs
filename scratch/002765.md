Commit title: squiggles from clientIdeDaemon 1/4
Commit body:
Summary:
We want clientIdeDaemon to power squiggles for open files by itself, with no connection to hh_server.

With this diff, immediately after each didOpen and didChange, clientIdeDaemon now computes TAST+errors and returns the errors to clientLsp (which doesn't yet do anything with them). The TAST+errors will behind-the-scenes be cached for future requests.

Still to come:
1. clientLsp should display those errors
2. This diff is only a first step to the clientIdeDaemon contract. I think we'll want to change it so *every* clientIdeDaemon action can return errors for the file, if the errors are known to have changed; didOpen and didChange will be only two examples of that. (why? because imagine if I edit A.PHP, and my edit affects what squiggles appear in B.PHP, when should those new squiggles be manifest? likely at the time the user focuses on B.PHP, i.e. when VSCode sends its volley of upon-focus messages like codeActions and documentSymbols, but not didOpen nor didChange).
3. Need to think what happens upon transition from During_init to In_init, i.e. as soon as saved-state has loaded and we're hence now able to compute TASTs. The user will expect squiggles to light up for their open documents.
