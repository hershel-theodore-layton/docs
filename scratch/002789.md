Commit title: Use `CMSG_SPACE` instead of `CMSG_LEN` to avoid alignment footgun
Commit body:
Summary:
Technically, `CMSG_LEN` works, because there's only one control message in the list, and thus there are no alignment constraints on the second message.

However, both the Linux and OpenBSD manual pages (`man CMSG_DATA`) encourage sizing `msg_controllen` using `CMSG_SPACE` because that eliminates the footgun that adjacent messages are not aligned.

> CMSG_SPACE(len)
> This routine determines the size in bytes needed to hold a control message and its contents of length `len`, which includes the control message header. This value is what is normally stored in `msg_msgcontrollen`. This routine accounts for any alignment constraints on the beginning of ancillary data as well as any needed to pad the next control message

Compare [the definitions](https://elixir.bootlin.com/linux/latest/source/include/linux/socket.h#L124).

Hopefully, the 4 bytes of stack space don't ruin our cache locality. If there were to be a perf impact, this usage of `CMSG_LEN` ought to have a BOLD COMMENT.
