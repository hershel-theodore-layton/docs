Commit title: Handle I/O wait Xenon events before throwing fatals
Commit body:
Summary:
If there was a long I/O operation that caused a request time out, we would
throw the time out fatal exception first, then process the Xenon surprise flag
while unwinding HH\Asio\join(), incorrectly attributing the time spent waiting
for that I/O operation as a CPU time spent by HH\Asio\join().

Fix that by processing the potential Xenon event first.

Ideally we would do the same change everywhere else where we check for surprise
flags, and perhaps even make it a part of handle_request_surprise(), but that
becomes somewhat more complicated due to onFunctionUnwind() being different.
We also don't have multi-second delays between surprise flags during regular
code execution, so the skew there is minimal.
