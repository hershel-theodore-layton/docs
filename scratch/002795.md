Commit title: Allow `setReadAncillaryDataCB` before `connect`
Commit body:
Summary:
- For convenience, I want to set this callback in the constructor of my upcoming `AsyncUnixFdSocket`.
 - Currently, the callback is not used anywhere (per `zbgs`), so nothing relies on any sort of implicit invariant here.
 - Unlike the true invariant of `readCallback_ == nullptr` unless the socket is in a reading state, this current assertion has no teeth -- the callback isn't cleared on socket close or error, for example. This means that there are no lifetime-shortening constraints that are enforced by the socket, the caller of `setReadAncillaryDataCB` has to mind the lifetime on their own.
 - Also, `ReadAncillaryDataCallback` cannot be invoked if the main read callback isn't set, so the `readCallback_` guarantees ensuring it's only called on a reading socket equally apply to `readAncillaryDataCallback_`.
