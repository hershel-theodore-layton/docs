Commit title: Simplify: only 1 flag to turn on the global access check
Commit body:
Summary:
Previously, there are 4 arguments for the global access checker:
- `--enable-global-access-check-files path_prefixes` to enable running the checker on files whose paths start with the specified prefix (e.g. "/" for all files);
- `--enable-global-access-check-functions json_file` to enable running the checker on functions whose names are in the specified JSON file;
- `--disable-global-access-check-on-write` to disable checking global writes;
- `--disable-global-access-check-on-read` to disable checking global reads.

This diff simplifies the 4 arguments into only 1 bool flag `--enable-global-access-check` (which simply turns on the global access checker that is turned off by default) based on the following reasons:
- For the current setting of HAGVAH (in which the global access checker runs on only part of WWW, i.e. the functions that are either transitively called by the given entry point functions or in the policy zone of specified policy name / zone id), we always use the config `--config enable_type_check_filter_files=true` to check files listed in ~/.hack_type_check_files_filter, while the arguments  `--enable-global-access-check-files` and `--enable-global-access-check-functions` are essentially useless.
- For the new design of HAGVAH (in which the global access checker will run on the whole WWW), we plan to check both global writes & reads at the same time and associate them together in the post-processing, making it OK to remove the arguments  `--disable-global-access-check-on-write` and `--disable-global-access-check-on-read`.
