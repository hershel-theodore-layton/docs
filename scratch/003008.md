Commit title: Mitigate intish/stringish enum typehole with like types
Commit body:
Summary:
Hack enums suffer from intish/stringish cast-related type error. Particularly, the following code (and its symmetrical `int` enum equivalent) typechecks, but throws at runtime at the function boundary:

```
<?hh

enum WAT: string {
  KO = "1";
}

function enforcement_goes_boom(WAT $_): void {}

<<__EntryPoint>>
function main(): void {
  $wat = 1 as WAT;
  enforcement_goes_boom($wat);
}
```

This diff mitigates the problem under sound dynamic by weakening the refined type to like of the enum type involved in the refinement.
