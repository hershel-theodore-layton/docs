Summary:
I'm writing this diff because I have three major goals:
1. redo the way progress is reported, to allow us to fetch progress even without having established a connection to the monitor, so that clientLsp can shell out to `hh check` and `hh --find-refs` and still display rich progress
2. redo the way errors are reported, by storing them in a file alongside the progress file, so anyone can `tail -f` the errors and hence we can at last achieve streaming errors
3. eliminate the Informant, and switch from watchman subscriptions to watchman queries.

All three goals will involve heavy-duty work in the monitor. I find its current module structure too difficult to navigate. This diff simplifies its module structure.

-----------

I've always found monitor code layout confusing because of its functors:
* serverMonitor is an abstract module parameterized on Server_config and Informant. It has logic for running the actual monitor.
   * ServerConfig is an abstract module with methods `start_server` and `kill_server`
   * Informant is an abstract module with methods `init`, `reinit`, `should_start`
   * We have only one instantiation of each, called HhServerMonitorConfig and HhMonitorInformant.
* serverMonitor is in `src/monitor:server_monitor`, a base module used by many other parts of the server and typechecker - but only because it's where MonitorRpc and ServerProgress happen to live. (these are common types shared by lots of things).

I found it confusing because I'm trying to figure out how the monitor works, but I can't cmd+click on its calls to `start_server` or `should_start` because they're all parameters to the serverMonitor parameter.

This diff removes the functorization:
1. There are three new low-level modules with IPC types which are shared by multiple higher-level components, and so each deserve their own target with minimal dependencies: `src/server:monitor_rpc`, `src/server:server_args`, `src/server:server_progress`.
2. Server module never depends upon monitor. (it only depends upon monitor_rpc for receiving handoff from monitor, and server_progress for sending progress to the client0.
3. ServerMonitor depends upon Server, because indeed it's what launches/kills the Server. It is the highest-level component.
4. ServerMonitor is no longer functorized. It references HhServerMonitorConfig and HhMonitorInformant directly. They in turn reference Server.

Actually, there was only one place where functorization was used. That was in informant_server_lifetime_test, which used ServerMonitor with a mocked Server_config and Informant underneath it. I think this one use of mocking was not sufficient justification for such a confusing code structure. And in any case my project is to remove the informant entirely, and this current diff is a first stepping stone along the way. So, I deleted the test.

This diff also renames some .ml files:
* HhServerMonitorConfig -> ServerController (since it has methods that start/kill the server)
* HhMonitorInformant -> Informant
* ServerMonitor -> MonitorMain (by analogy with ServerMain)
* ServerMonitorUtils -> MonitorUtils
* HhServerMonitor -> MonitorStart (its only method is "start", and its only job is to start the monitor)
