Commit title: shell out to "hh check --json" for squiggles
Commit body:
Summary:
This diff does an async shell-out to "hh check --json" and scrapes the output for squiggles. It kicks off a shell-out at startup, and also upon receipt of didChangeWatchedFile. It merges squiggles from the two sources (clientIdeDaemon and `hh check --json`) thus:
1. Upon LSP actions didOpen and didChange, have clientIdeDaemon recompute squiggles for the file and publish them.
2. Upon the end of a `hh check --json`, scrape its output...
   1. Iterate all files which currently have published diagnostics in VSCode. If the file is closed and its squiggles were published (from either source) before the start of hh check, then publish updated squiggles that we scraped from the output; or publish "no squiggles" if there were none.
   2. Iterate all files for which the scraped output has errors. If the file is closed and has no squiggles, publish the freshly parsed ones.

There's no particular need to cancel the shell-out ever. That's based on my knowledge of how hh_server behaves. In particular, if we're part way through a shell-out and a didChangeWatchedFile arrives, then hh_server itself will recheck any disk changes and will delay giving us an answer until it's settled. Also, upon termination of "hh_client LSP", I think we don't even care that we've shelled-out to an "hh check" because OS process cleanup will deal with it.
