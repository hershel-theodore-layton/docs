Commit title: Fix handling of escape sequences in Hack annotations
Commit body:
Summary:
Fix a few issues in the Hack generator mostly related to handling of escape sequences in structured annotations in general and adapters in particular:

* The `\\` escape sequence is incorrectly emitted as `\\` in both qualified identifiers and strings. Apart from being inconsistent (and broken) internally and with other languages, this makes it impossible to provide an escape hatch for qualified names that contain valid escape sequences such as `Str\replace`. This is fixed by unescaping strings where needed. We should probably diagnose this but it is out of scope of the current diff.

* There are multiple memory leaks in handling of adapters. Fix them by replacing raw pointers with `boost::optional<std::string>`.

* In one path a pointer is emitted instead of the name:
   ```
        // Here `name` is a pointer to `std::string`:
        out << indent() << "$" << name << " = " << inner_str << ";\n";
   ```
