Commit title: Fix handling of escape sequences in metadata
Commit body:
Summary:
String generation is partially broken in metadata:

* Escape sequences are not translated.
* Double quote is translated into `\"` because the `string_value` mstch method is not intended to be used with raw strings emitted by metadata.

Fix some of the issues by replacing raw strings with normal strings, escaping newlines and stray `\`.

For example, given the Thrift code (simplified from `thrift/compiler/test/fixtures/adapter/src/module.thrift`:

```
edward-io.Adapter{name = '\\Adapter2'}
typedef set<string> SetWithAdapter
```

this results in the following change.

Before:

```
cvString(R"(\\Adapter2)")
```

After:

```
cvString("\\Adapter2")
```

Notice that `\\` is now correctly translated into an escape sequence `\\` rather than literal `\\` string. In other words the number of backslashes is not doubled anymore.
