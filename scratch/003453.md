Commit title: Implement lexing of some escape sequences
Commit body:
Summary:
Implement lexing of the following escape sequences: `\a`, `\b`, `\f`, `\t`, `\v`. Handling escape sequences in the frontend will allow simplifying similar logic in generators and improve consistency between languages. Instead of each generator trying to redo parts of the escaping, sometimes in multiple ways, they will only have to deal with normalized representation. Escape sequence validation will also be in the frontend where it belongs.

It is done as a separate function rather than a part of `get_next_token` to keep passing tokens simple and to allow applying context-sensitive rules in the future (for example package names should be lexed differently).

Quotes are now passed as a part of string literal tokens which makes more sense lexically.

Support for other escape sequences will be added separately because they require more thorough testing and changes to generators.
