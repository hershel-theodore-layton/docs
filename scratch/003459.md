Summary:
This diff defunctionalizes "notifier" (that's the thing that abstracts over dfind/watchman). Currently, notifier is done by a cluster of closures in ServerEnv.genv
```
type genv = {
  ...
  notifier_async: unit -> ServerNotifierTypes.notifier_changes;
  notifier_async_reader: unit -> Buffered_line_reader.t option;
  notifier: unit -> SSet.t;
  wait_until_ready: unit -> unit;
}
```
The closures are initialized by ServerEnvBuild.make_genv, and that's called in a few places:
* in hh_server, ServerMain.setup_server calls ServerEnvBuild.make_genv followed by ServerEnvBuild.make_env
* There are six other tools of various kinds that call ServerEnvBuild.make_genv

When we finally get to look at the code which handles watchman interrupts by calling `notifier` or `notifier_async`, it's not easy to cmd+click and to go back to see where the closures were first initialized, nor what they do.

This diff creates a new module `ServerNotifier` with the four methods (renamed as `get_changes_async`, `get_changes_sync`, ...) and uses a standard API pattern:
```
type t

val init : ... -> t

val wait_until_ready : t -> unit
val get_changes_async : t -> changes
val get_changes_sync : t -> changes
val async_reader_opt : t -> Buffered_line_reader.t option
```
This way, when we Cmd+Click on a call to `get_changes_sync`, it's now easy to see what happens.

Why had the code initially been written with closures? I'm not entirely sure. Maybe it was a way around target dependency issues? I solved these by splitting up the target `server_env`. Previously it combined very low-level stuff like serverLocalConfig.ml data-structures, along with high-level stuff like ServerEnv. I moved part of it into a separate low-level target `server_config`.

## Why am I doing this?

1. I want to roll out ide_standalone for clientLsp
2. In order to do that, I need to sort out progress reporting and squiggle shelling-out. Also it'd be nice to get streaming errors so as to avoid regressing.
3. In order to get streaming errors, and make them race-free, I need ServerTypeCheck to report the watchman clock at the start of a typecheck
4. When it was using closures, the code to get that watchman clock was too convoluted for me to follow. So I decided to defunctionalize it first, and afterwards have it return watchclock.
