Summary:
## What

"Extract into https://pxl.cl/2z6Zv variable" refactor

## Fiddly parts

- We skip offering the refactor if there is an already-seen variable/parameter name `$placeholder_`. This is to avoid the following flow:
    - user invokes the refactor, generating `$placeholder_`
    - then user renames `$placeholder_`
    - then (unexpected) a bunch of unrelated code changes.
- We (best effort) avoid generating invalid code by: skipping lvalues, `await`s, etc.

## To consider

There's now a rename refactor in the integration test for missing methods codefixes. I think this is probably OK, since integration tests show things from the user's point of view. Please let me know if this isn't the intended behavior or you think it's best to add filtering to our lsp tests.

## Caveats

This refactor is "best effort":
- The refactor can change the meaning of side-effecting code (example in extract_variable_unsafe_1.php). I don't like this, but don't know of an affordable alternative. [Refactors for other languages have the same problem](https://play.kotlinlang.org/embed?short=isarlHogA).
