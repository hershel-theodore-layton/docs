Summary:
I wrote this diff from a simple need - for streaming errors I wanted to write this code to display animated status while waiting for watchman
```
ClientConnect.tty_progress_reporter (Some "[watchman sync]");
let%lwt r = get_watchman_since ~clock in
ClientConnect.tty_progress_reporter None;
```
The problem is, `tty_progress_reporter` doesn't animate by itself. It only animates each time you call tty_progress_reporter. If users see it non animated, stuck on "/", they assume something has crashed. (it hasn't). I'd have to write a bunch more code to make it animate:
```
let rec update_spinner () =
   tty_progress_reporter (Some "[watchman sync]");
   let%lwt () = Lwt_unix.sleep 1.0 in
   update_spinner ()

let future = update_spinner () in
let%lwt r = get_watchman_since ~clock in
ClientConnect.tty_progress_reporter None;
Lwt.cancel future;
tty_progress_reporter None
```

I wanted to change that! And while I was at it, I saw some other opportunities to work on the spinner. So here's what the diff does.
1. It animates by itself, automatically.
2. It writes to Hh_logger.log each time the message changes to something new. We were already writing this to Hh_logger during clientConnect callbacks, but I also wanted it written to Hh_logger during all other times (monitor connection, streaming errors, ...)
3. It also writes a "heartbeat", once a second, to a new scuba table [hh_client_spinner](https://fburl.com/scuba/hh_client_spinner/ao4avq0j). My goal with this is so that, if our goal is to reduce time taken for users at the CLI, we'll now be able to see where the time is going.
