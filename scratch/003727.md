Commit title: Use tracing-indicatif for progress bars
Commit body:
Summary:
At this point, `check::Console` is only used to render progress bars.
Hh_distc's parse, decl, and typing code has been converted to use `tracing`,
which associates log events with spans, which are tree-structured units of work.

Tracing-indicatif provides `tracing` listeners that render progress bars, allowing
us to remove Console tendrils from hh_distc's core async code.
tracing-indicatif renders this Span tree with spinners by default, and we
provide custom bar styles for decl & typing, similar to our previous progress bars.

I got rid of the separate progress bar for "Typing Start" it's not very important.
There's no clean way to have 2 progress bars for 1 span, and it's not worth creating
a nested span just for the sake of having 2 bars.

Instead, the typing bar starts at length 0, increments length when each batch starts
(subject to `--num-tasks` throttling), and increments position when each sub-batch
completes.
