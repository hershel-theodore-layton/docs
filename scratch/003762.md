Commit body:
Summary:
When trying to write LSP integration tests for streaming errors, I noticed that eager inits were failing under `--config produce_streaming_errors`.
```
$ rm ~/t/a.sql; hh_server --check . --save-naming ~/t/a.sql --config produce_streaming_errors=true --config lazy_init2=false

Uncaught exception: (Failure "Cannot report in state Absent")
```

We have so many initialization paths! It's hard to keep track of them all.

This issue arises because `Typing_check_service.go` will call `ServerProgress.ErrorsWrite.report`. It therefore requires the errors-file to have been previously initialized. This is already done properly when it's called by `ServerTypeCheck.type_check`. But it turns out that there are two other callers, which don't initialize the errors file -- eager init, and hulk.

This diff fixes them both to not produce streaming errors at all.

(Another strategy would have been to change `Typing_service_types.check_info` to have another boolean for whether or not `Typing_check_service.go` should invoke `ServerProgress.ErrorsWrite.report`. But that would result in duplication: we'd have to figure out whether error production is enabled in lots of places -- in typing_check_service.ml, in ServerTypeCheck.ml to report errors, in ServerTypeCheck.ml to start+end reporting, and in serverMain.ml to unlink error reporting at the end. I prefer the approach in this diff which affects fewer places.)
