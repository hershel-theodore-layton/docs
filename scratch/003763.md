Commit title: fix patch bug when patch has assign op
Commit body:
Summary:
Since currently other ops will be ignored if we have assign op.
To add more patches, we need to split assign op to field patch first.

The existing logic clears the patch, and then uses ensure to set each field.

This seems make sense, however,

1. for optional field, clear will reset the field, which makes it not patchable anymore.
2. for non-optional field, there is another bug -- it only set ensure when field is not empty (`!op::isEmpty<op::get_type_tag<T, decltype(id)>>(*field)`). This has the assumption that field is terse field, which is not always correct.

This diff rewrites this logic

1. If the field is absent in assigned data, it means we will clear this field after assign, we just clear it in PatchPrior
2. If the field is not absent in assigned data, we will ensure, then assign in PatchAfter (in case that field already exists and ensure becomes no op).

After that we can clear assign since it's replaced by patch prior, ensure and patch after.
