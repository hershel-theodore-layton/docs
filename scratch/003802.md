Summary:
For ide_standalone, we still want to show hh_server status in the status bar. Status-bar shows two things:
* **Disposition**
   * *Stopped* -- hh_server has stopped or crashed or isn't working. Human intervention is needed. Represented with a cross inside a circle, the standard notation for error.
   * *Working* -- hh_server is doing something, and the human just has to wait for it. Representing with a spinning circle+arrow.
   * *Ready* -- hh_server is working correctly and is ready to handle the next thing we ask it to. Represented without any icon.
* **Message**.  Human-readable text.

Currently, the progress.json status is used solely by the command-line "hh_server is busy [typechecking] /". For this purpose, by definition, the disposition is "working". That's why we never bothered to store disposition in the progress.json file before.

As for VSCode status bar, it used to obtain hh_server disposition+message from the RPC connection:
* if we have a connection then hh_server is either Ready or Working, and which one of the two is communicated by push notifications sent from hh_server over the persistent connection. The message is inferred from those push notifications but it's fairly granular (either "doing local check" or "doing global check").
* if we don't have a connection then hh_server is Stopped. The message just says "stopped" in this case. (but, for log purposes, it also obtains the reason from the server-finale-file).

Our project is to eliminate the RPC connection. I intend to display status simply by reading the message from the progress.json file. However, that file doesn't currently distinguish between Ready/Working/Stopped. Hence, we don't know whether to put an error or spinner icon next to the message we display in the status bar.

This diff changes it so the progress.json file now stores Ready/Working/Stopped disposition.
