Commit title: Fix a bug on static analysis signal targets
Commit body:
Summary:
For the static analysis part of HAGVAH, the TAST checker reports global variables (i.e. analysis signal targets, including static variables, super globals and memoization) separated by "`,`". However, when investigating the analysis results, I just realized that "`,`" may be part of a single global variable (i.e. "AlwaysDenyRule<IFBViewerContext, IEntPerson>::get" that is a single memoized method). Hence, for HAGVAH V2, this variable would be accidentally split into 2 variables and store into table "analysis_signal_to_target". Notice that this would not be a problem for HAGVAH V1, since the global variables are stored together as a string in one column.

To solve this problem, this diff uses "`;`" to separate global variables, since I do not think "`;`" can be part of any variable name or function name.
