Commit title: Force InlineAdapter to always provide the concrete underlying type
Commit body:
Summary:
Currently InlineAdapter accepts template template parameters, e.g.

```
template<class T>
struct Wrap {
  // ...
};

using Adapter = InlineAdapter<Wrap>;
```

We can simplify the implementation of InlineAdapter by always asking user to provide the concrete type.

# Motivation

1. This makes the implementation of InlineAdapter much easier (it doesn't need to deal with template template parameter).
2. We can implement `infer_tag<Adapted>` to always get the correct adapter from `detail::Wrap`.

Consider

```

namespace detail {
template<class UnderlyingStruct>
struct Wrap {
  // ...
};
}

template<class UnderlyingStruct>
struct Patch: detail::Wrap<UnderlyingStruct> {
  // ...
};

```

If you have native type `Patch<Struct>`, without this diff, there are two possible type tags

1. `adapted<InlineAdapter<Patch>, struct_t<Struct>>`.
2. `adapted<InlineAdapter<Patch<Struct>>, struct_t<Struct>>`.

This diff banned the first case. After this diff, the type tag will always be the second case, thus we can have `infer_tag` to get type tag from `Patch<Struct>`.
