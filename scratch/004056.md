Commit title: report errors by tailing errors.bin
Commit body:
Summary:
hh_server produces streaming errors in an errors.bin file, if started with `--config produce_streaming_errors=true`. D44159580 changed clientCheck.ml so that `hh check --config ide_standalone=true` will consume streaming errors. This diff changes clientLsp.ml to consume them as well.

Why?
1. One option is to leave things as they are, shelling out to `hh check --json` upon `didChangeWatchedFile` and getting the results once the typecheck (if any) is done. This wouldn't give us streaming though.
2. Another option is to invent a new format `hh check --json --line-at-time` which produces machine-readable text error format, one line at a time, which we could scrape for errors. This would be okay but involve yet another errors format and lots of conversion work.
3. Another option is to read the same underlying errors.bin format which hh_server produces and which `hh check` streams from. This is more strongly typed and involves less conversion code. It's also nicer because errors.bin self-identifies whether we need to read it for errors, which is nicer than using some external trigger (like didChangeWatchedFile) to learn when to check for errors.

I opted for solution 3.

How?
1. I figure that clientLsp is in one of two modes, either *seeking* for a new errors.bin file, or *tailing* an errors.bin file.
2. I stored `errors_conn` (with information about seeking/tailing) in a global mutable variable. I didn't want to! I wanted to store it in Lost_env! But unfortunately we need this information in order to render status messages in the VSCode status bar, and places in the code that call `refresh_status` are not part of the state monad. The existing convention, for these kinds of status things, are to store them in global mutable variables.
3. The logic for when to replace or update or remove errors is similar to what it was before: when we get errors for a file then, so long there aren't existing errors that came more recently than the start of the typecheck, report them; when we get "completed-typecheck" signal then erase all errors that were last reported prior to the start of the typecheck.
