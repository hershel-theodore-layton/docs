Commit title: Allow to deactivate saved state rollouts for some revisions.
Commit body:
Summary:
This will be especially useful for the following two cases:
- if a flag is found to be falty, it will allow to rollout the flag again later after releasing a fix without impacting the www revisions for which hh is falty
- if a flag makes candidate saved state creation job fail, this will allow to deactivate those jobs (this will have to be implemented in Sandcastle in a later diff)

This is done by adding a flag deactivate_saved_state_rollout in .hhconfig. Forcing anything with ss_force will have priority over that flag. This is so that we can still test or do mass replays.
