Commit title: 7/7 Completion_resolve_location shouldn't take file_contents
Commit body:
Summary:
I wish to make some systematic changes to clientIdeMessage.ml in future, and in preparation I'm spending some time streamlining it.

BEFORE:
```
  | Completion_resolve_location :
      document * location * SearchUtils.si_kind -> DocblockService.result t
```

AFTER:
```
  | Completion_resolve_location :
      Path.t * location * SearchUtils.si_kind -> DocblockService.result t
      (** "completionItem/resolve" LSP messages - if we have file/line/column.
      The scenario is that VSCode requests textDocument/completion in A.PHP line 5 col 6,
      and we responded with a completion item that points to a class defined in B.PHP line 10 col 5,
      and now VSCode requests completionItem/resolve [(B.PHP, {line=10; column=5;}, class)],
      and this method will look up B.PHP to find the docblock for that class and return it.
      Typically B.PHP will not even be open. That's why we only provide it as Path.t *)
```

Previously we were sending `document`, i.e. filename+contents. This diff changes it to merely send filename.

The consuming code in clientIdeDaemon makes clear that this is the right thing to do:
```
  | ( Initialized istate,
      Completion_resolve_location ({ file_path; _ }, { line; column }, kind) )
    ->
    (* We were given a location but it often will not be an opened file.
       We will only serve autocomplete docblocks as of truth on disk.
       Hence, we construct temporary entry to reflect the file which
       contained the target of the resolve. *)
```
