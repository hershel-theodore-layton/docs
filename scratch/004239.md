Commit title: Conditionally add "<service name>." prefix to method names
Commit body:
Summary:
Currently, generated server code for Rust unconditionally prefixes method names
with [`"<service name>."`](https://github.com/facebook/fbthrift/blob/34e7754c53d2510b8c3c935a48f26cafa8790c04/thrift/compiler/generate/templates/rust/lib/server.mustache#L218) for the [`on_read_data`](https://github.com/facebook/fbthrift/blob/34e7754c53d2510b8c3c935a48f26cafa8790c04/thrift/compiler/generate/templates/rust/lib/server.mustache#L227-L231) and [`on_write_data`](https://github.com/facebook/fbthrift/blob/34e7754c53d2510b8c3c935a48f26cafa8790c04/thrift/lib/rust/src/help.rs#L114-L118)
hooks as well as the [response envelope](https://github.com/facebook/fbthrift/blob/34e7754c53d2510b8c3c935a48f26cafa8790c04/thrift/compiler/generate/templates/rust/lib/server.mustache#L283-L290). `<service name>` can be either the
service name as defined in the Thrift spec with `service <service name>` or the
interaction name if the current method is a part of an interaction.

```
interaction MyInteraction {
    method1();
}

service MyService {
    method2();

    performs MyInteraction;
}
```
For example, the service names for the above snippet would be `MyInteraction`
for `method1` and `MyService` for `method2`, and the `METHOD_NAME`s in the
generated code would be `MyInteraction.method1` and `MyService.method2`
respectively.

These method names are inconsistent, however, with [generated C++ code](https://github.com/facebook/fbthrift/blob/34e7754c53d2510b8c3c935a48f26cafa8790c04/thrift/compiler/generate/templates/cpp2/service_tcc/process_and_return.mustache#L293) and
[Rust clients](https://github.com/facebook/fbthrift/blob/34e7754c53d2510b8c3c935a48f26cafa8790c04/thrift/compiler/generate/templates/rust/lib/client.mustache#L109-L112). In C++ and Rust clients, the `"<service name>."` prefix is only
included for interactions. Because of this, if a client were to send a request
with the exact method name returned from the server or recorded in the
`on_{read,write}_data` hooks, the server would [not handle the request properly](https://github.com/facebook/fbthrift/blob/34e7754c53d2510b8c3c935a48f26cafa8790c04/thrift/compiler/generate/templates/rust/lib/server.mustache#L407-L411)
because of the unexpected prefix.

This diff tweaks the method name used for the `on_{read,write}_data` hooks and
the response envelope to only include the `"<service name>."` prefix when the
method is part of an interaction. Changing the method name in the response
envelope could be a breaking change, but envelopes are largely deprecated and
the method name in the response envelope is [unused in generated Rust clients](https://github.com/facebook/fbthrift/blob/34e7754c53d2510b8c3c935a48f26cafa8790c04/thrift/lib/rust/src/help.rs#L158-L165),
so the change should be safe.
