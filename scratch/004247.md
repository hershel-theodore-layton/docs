Commit title: Treat `as mixed` same as no bounds
Commit body:
Summary: Static calls like `$x::f` and `$x::f()` were getting different error messages if the type of `$x` was `classname<T>` depending on whether `T` has no upper bound (very specific error message) or has a `mixed` or `supportdyn<mixed>` upper bound (generic "got mixed" error message). In general, the type checker should treat unbounded the same as `mixed` bounded.
