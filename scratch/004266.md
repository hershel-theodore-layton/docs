Commit body:
Summary:
There's no need for a dependency on that library in the Rust `typing_deps.rs`. I'd included it purely for memory layout parity with `typing_deps_mode.ml`, but it's not actually used, and `UnsafeOcamlPtr` has the same effect.

# Context

This change unblocks later diffs working on the batch index FFI. It seems that `dune` has a problem when an FFI is accessible via multiple paths in a dependency graph. In this case, certain OCaml tests  had the following dependencies: `client_ide_service` and `typing_deps`.

`typing_deps` eventually depends on `hh_fanout_rust_ffi`:
```
typing_deps -> hh_fanout_rust_ffi_externs -> hh_fanout_rust_ffi
```

`client_ide_service` eventually depends on `hh_fanout_rust_ffi` too, through the new `rust_batch_index_ffi`. **This dependency path is what this diff removes**:
```
client_ide_service -> rust_batch_index_ffi -> hackrs_provider_backend -> deps_rust -> hh_fanout_rust_ffi
```
