Summary:
`hh download-saved-state` had been hard-coded to use `Naming_and_dep_table { naming_sqlite = true }`. I don't know why. That doesn't seem right.

The command `hh download-saved-state` is only ever used during OD preparation, hoping to get a saved-state ready on the machine so that later on when the user acquires it, then `hh lsp` will invoke clientIdeDaemon and find the saved-state already present. We alas don't collect telemetry on its invocation. But here's the only callsite: https://www.internalfb.com/code/fbsource/[a0bd7f185961f2bc9ec5ca9159be175954af8c3f]/fbcode/ondemand/preparer/requirements/hhvm.py?lines=54
```
        self.run(
            [
                "hh_client",
                "download-saved-state",
                "--from",
                "ondemand.preparer",
                "--type",
                "naming-table",
                self.repo_path,
            ],
            as_svcscm=True,
            cwd=self.repo_path,
        )
```

Ultimately we want to get rid of this part of OD-prep. We instead want clientIdeDaemon to use the same distc saved-state as hh_server.
