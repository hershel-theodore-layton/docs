Commit title: Move `user_error` to separate lib
Commit body:
Summary:
Currently our errors library is something on which our parsing, naming, nast check and typing libraries depend on.

They are depending on it for:
1) The definition of errors and error codes
2) The ability to generate an error as a side-effect

Reason (2) makes sense but (1) seems to be an accident of history and causes a number of limitations including:
- Our error data types can't reuse common data types (e.g. visibility, variance etc)
- Our typing errors can't contain types so we have to lazily render them to strings instead; this means we can't oxidize typing errors, amongst other things
- We can't influence _how_ errors are evaluated to `User_error.t`s from each phase

We can eliminate these limitations by splitting out our `User_error.t` and the error data types corresponding to each phase

This diff is the first in a stack which does this and moves `User_error.t` to its own library
