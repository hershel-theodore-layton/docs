Commit title: allow clientIdeDaemon to return errors from didClose+codeAction
Commit body:
Summary:
In ide_standalone, whenever clientIdeDaemon recomputes the TAST then it might have updated squiggles to send back.

When might it recompute the TAST?
1. `didOpen`. Prior to ide_standalone it didn't compute a TAST on this event (it only computed TAST on demand); it merely created an `entry`. Now it does compute TAST+errors and sends errors back.
2. `didChange`. Prior to ide_standalone it again didn't compute a TAST but merely invalidated any TAST there happened to be. Now it does compute TAST+errors and sends errors back.
3. `didClose`. A tricky one this. Imagine you made unsaved modifications to a file (didChange) so now it has squiggles, and then you close the file. We'll have to remove the squiggles. Or imagine if you opened a file which had errors in it (didOpen), and made unsaved modifications to remove the errors (didChange), and then close the file. We'll have to restore the squiggles. In general, after didClose on a modified file, we have to recompute TAST+errors for the unmodified version and send squiggles.
4. `codeAction`.  If you saved modifications to decls in A.PHP, and then switch tab to B.PHP, it might be that the squiggles in B.PHP have to be regenerated. We could decide to spontaneously recompute squiggles in all open files upon any disk-file-change but that seems kind of heavyweight. So instead we'd like to recompute squiggles in B.PHP as soon as you switch tab to it. There's no official LSP message for "switch tab". The closest we have is "textDocument/codeAction", which is sent pretty eagerly when you open a tab. So this message will be an important one for sending back updated squiggles.

Error-reporting on `didOpen`+`didChange` was already present. This diff adds it for `didClose`+`codeAction`. The last one is `Errors.t option`, using the None case for the common scenario that TAST+errors hadn't in fact been recomputed. (The possibility of 'None' doesn't apply to didOpen/didChange. I could have used None for didClose but I thought it's a less common event, and I'd rather keep the code simple than prematurely optimize.)

This diff changes the clientIdeMessage types to reflect all the messages that might recompute an entry's TAST+errors. But it doesn't yet send updated errors, nor consume them. That will come in future diffs.
