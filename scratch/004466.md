Summary:
Streaming errors is sometimes failing with this sort of message
```
[2023-04-21 18:14:20.640] [Check#jcPnlQrEEw] CLIENT_BAD_EXIT
client_command=Check
exit_status=Exit_status.Uncaught_exception
exit_code=221
exn=Invalid_argument("Prefix 'hhi' has not been set!")
stack=src/utils/relative_path.ml @ 60
src/utils/relative_path.ml @ 119
```

The reason is that the errors.bin file contains `Errors.error`, which are errors that use `Relative_path.t` in their `pos`. Then hh_client tries to read and print them, but it can't because it doesn't know how to render the filepath of an error reason that mentions a `Relative_path.Hhi` file. Here's an example:
```
function test_use_hhi(): void {
  stdClass::f();
}

No static method `f` in `stdClass` (Typing[4090])
  File "/tmp/hh_server/hhi_1dea6373/classes.hhi", line 31, characters 15-22:
  Declaration of `stdClass` is here
```

The way normal (non-streaming) hh works is that ServerRpc.ml systematically turns relative-paths into absolute-paths prior to sending anything to the client...
```
  | STATUS { max_errors; _ } ->
    let error_list = Errors.get_sorted_error_list env.errorl in
    let error_list = List.map ~f:User_error.to_absolute error_list in
    ...
  | IDENTIFY_SYMBOL arg ->
     ServerSymbolDefinition.go ... |> List.map ~f:SymbolDefinition.to_absolute
  | FIND_REFS find_refs_action ->
    ServerFindRefs.go ... |> map_env ~f:to_absolute
```

This diff does exactly the same: it makes errors.bin now contain `Error.finalized_error`, which is what you get from `User_error.to_absolute`.

Note: errors.bin actually needs to contain a map from filename to the list of errors inside it. How should we store that filename itself? (1) `Path.t` i.e. fully qualified with warrant that all symlinks have been resolved and the runtime invariant that clients can strip the root prefix from it on their end. (2) `string` i.e. a root-relative suffix, with the runtime invariant that symlinks have been resolved. (3) `Relative_path.t` with the runtime invariant that only prefix=Root will appear. All options are unsatisfactory, but I picked (3) because I think it conveys the most information.
