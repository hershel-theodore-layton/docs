Commit title: resume full check 5s after edit
Commit body:
Summary:
I discovered an irritating behavior in hh_server. If you have a full typecheck underway, and then interrupt it by typing a character into an IDE buffer, then it *won't resume the full typecheck*. It only resumes upon some triggers:
* if there is a pending RPC call (e.g. "hh check") and 5.0s have elapsed since it was interrupted
* a file change happens on disk

I'd noticed a lot of "ready" messages in hh_client_spinner. The reason for this, I'm guessing now, is that hh_server was waiting for those 5.0s to elapse and it printed "ready" in that case.

Anyway, the advent of streaming errors makes those resumption conditions insufficient: previously if you did "hh check" then it would eventually resume, but now if you do "hh check --config consume_streaming_errors" then it will sit there indefinitely at "hh_server is busy [ready]".

This diff does two things:
1. change the busy message to "will resume" in this situation
2. make it so it will resume after 5.0s, regardless of whether there's a pending RPC call

Note: once we finish ide_standalone, then there'll be no such thing as EDIT messages, and it'll be fine to resume always.
