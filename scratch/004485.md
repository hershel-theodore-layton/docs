Commit title: Refactor like pushing
Commit body:
Summary:
When we have `t <: ~u`, if `u <: supportdyn<mixed>`, then we just do `t <: u` with `super_like` set, followed by dyn_finish. This single disjunction simple enough that we can manage the error messages as in D35615041. However, if `u <: supportdyn<mixed>` is checked with `is_subtype_for_union_i` which can fail if `u` contains unsolved type variables, even if bounded above by `supportdyn<mixed>`. This sends onto a code path that does like pushing immediately, instead of defering it via `super_like` and has a more complicated pattern of disjunctions that makes the error message much harder to manage.

This diff refactors so try to be more uniform whenever there is a like-type on the right, always checking `t <: u` then trying like pushing, and then the default dyn_finish. This puts the subtype for dyn disjunct in a uniform place, instead of as part of expanding `t <: u1 | u2` into `t <: u1 || t <: u2 || t <: like_push(u)`.

Further simplifications might be possible.
