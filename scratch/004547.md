* Before: if an edit is performed, then we of course do a lazy_check for IDE files, but we refrain from doing any full typecheck needed unless either (1) a disk change happens, or (2) a "hh" command is pending and has been waiting for at least five seconds

The motive for that diff was so that, if someone does "hh check --config consume_streaming_errors=true", then the full check will still happen. (consuming-streaming-errors doesn't count as a pending "hh" from the perspective of hh_server).

Anyway, it exposed raciness in tests: if it's been 5s then we'll expect to see output from a full check, otherwise not. (previously, no hh command was pending, so no full check was done, so we didn't see output from it).

Strangely, only dune tests in phabricator were experiencing the raciness. I guess they run on machines where sometimes they did wait 5s before being paged back in. However I found a way to trigger raciness everywhere, by simulating as if 10s had passed.

This diff simulates as if 10s has passed, and fixes the racy tests to now include the effects of completing the hh check.
