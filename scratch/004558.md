Summary:
"hh" won't display typing errors if there are parsing errors, per code in Typing_check_service.process_file:
```
let process_file ... =
  let (file_errors, ast) = Ast_provider.get_ast_with_error ~full:true ctx fn in
  if not (Errors.is_empty file_errors) then
    { file_errors; deferred_decls = [] }
  else
    ...
    Typing_check_job.check_typedef opts fn name ...
```

This diff makes it so that clientIdeDaemon uses the same behavior when reporting live squiggles (in didOpen, didChange, didClose, codeAction).

I should clarify that this diff doesn't actually stop clientIdeDaemon from *calculating* typing-errors. It merely stops it from displaying them. (it would be a touch more efficient to refrain from calculating typing-errors in case there are parsing errors; but we still need the TAST anyway, which is the slow bit, so it would feel like a premature optimization to skip the tast-check step).

As to what the desirable behavior is? I don't know. I kind of don't want to adjust existing hh behavior though. For now, I just want to get clientIdeDaemon to parity.
