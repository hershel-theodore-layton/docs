Commit title: don't wipe errors upon restart
Commit body:
Summary:
What happens to the diagnostics currently displayed under various end-of-errors-file situations?
1. [existing correct behavior] If the problems pane shows 80 errors across various files which we obtained from currently-underway errors.bin, and then hh_server stops (so deleting errors.bin), then we should clear out those 80 errors from the pane.
2. [existing correct behavior] If it shows 80 errors from currently-underway errors.bin, and then hh_server completes its typecheck, then we should leave those errors as they are.
3. [subject of this diff] But what if it shows 80 errors from currently-underway errors.bin, and then a file is changed so hh_server restarts its typecheck -- should we leave the errors as they are? or wipe them all?
   1. I think we should leave them as they are. It's never good for errors to disappear in the middle of you working on them. Saving a file should never be a trigger for errors to disappear.

This diff changes it so the errors will be left as they are upon typecheck-restart.
