Commit body:
Summary:
[This is part of an 19-diff stack whose purpose is to remove the redundant Errors.Parsing and Errors.Decl phases]

It used to be that if a file had `Errors.Parsing` errors then ServerTypeCheck refrained from putting its decls into the decl-store; instead, we merely retained the prior good decls. This got changed by Steve Cao. Now, we use the direct-decl-parser to obtain decls, so files with parse errors still get their best-effort version placed in the decl-store.

I'm reviewing code in serverLazyInit.ml and serverEagerInit.ml. This built up `defs_per_file`, a list of the `FileInfo.t` of files that changed since saved-state. The init code used to remove from this list all the files that had experienced parsing errors. The list was subsequently fed into the decl-diffing routine to calculate fanout.

I think this code in serverLazyInit.ml and serverEagerInit.ml should be changed similar to what Steve did. That's what this diff does.
