Commit title: normalize ServerTypeCheck use of Errors.Parsing
Commit body:
Summary:
This diff concerns hard-to-understand code patterns in ServerTypeCheck. The result of this diff is changing code to make it more clear that, because `phase=Errors.Parsing` and `phase=Errors.Typing` are produced at the same time in **do_type_checking**, then they should be cleared at the same time. (the consequence of this, further down the diffstack, is that `phase=Errors.Parsing` can be folded into `phase=Errors.Typing)`.

BEFORE:
In the **do_parsing** phase,
```
push_and_accumulate_errors
          Errors.empty
          ~do_errors_file:false
          ~rechecked:files_to_parse
          ~phase:Errors.Parsing
```
What this does is erase all `phase=Errors.Parsing` errors inside `files_to_parse` which had been reported on these files during a previous round of the **do_type_checking** phase. It does this for errors-paradigm (1) env.errorl, and (2) persistent-connection-push. (It skips it for paradigm (3) errors.bin, on the grounds that it's `Errors.empty` i.e. solely about removing errors, which isn't needed for errors.bin)

`files_to_parse` is `env.ide_needs_parsing U env.disk_needs_parsing U env.failed_naming`.

Later on in the **do_type_checking** phase, it typechecks all modified files plus their fanout plus `env.needs_recheck`. As soon as a file is typechecked, it updates that file's (paradigm-2) persistent-connection errors:
```
      Diagnostic_pusher.push_new_errors
        diag
        ~rechecked
        new_errors
        ~phase:Errors.Typing
```
I honestly don't know how this works: `new_errors` might include `phase=Errors.(Parsing|Typing)`, but we pass `~phase:Errors.Typing`. So what happens? Does it push all errors but only erase `Errors.Typing` ones? I couldn't understand the code.

And at the end of Typing_check_service, it removes errors from (paradigm-1) env.errorl. Specifically, it removes all `phase=Errors.Typing` errors that were in the files_checked and which didn't encounter new errors.
```
        Errors.incremental_update
          ~old:errors
          ~new_:errorl\'
          ~rechecked:files_checked
          Errors.Typing
```
So how did it remove `phase=Errors.Parsing` errors? I suppose we must trust that those were all removed by our earlier call to `push_and_accumulate_errors Errors.empty files_to_parse`. In other words, it rests on the invariant that if we had found a parse-error in the fanout on a previous iteration, and that parse-error should be removed now, that can only be because the file itself was modified. This is of course a true invariant!

AFTER:
I found the code above too mysterious and disconnected. It didn't feel right to have its correctness depend on an invariant between separate areas of one round of ServerTypeCheck and the next. I think that since `phase=Errors.(Parsing|Typing)` errors are produced at exactly the same time in **do_type_checking**, then they should be reported and erased at exactly the same time too. Therefore:

In the **do_parsing** phase, it no longer removes any errors. This makes sense since it didn't report any errors.

Within Typing_check_service, it continues to call `Diagnostic_pusher.push_new_errors` exactly as before in service of (paradigm-2) persistent-connection.

At the end of Typing_check_service, in service of (paradigm-1) env.errorl, it now removes all `phase=Errors.(Parsing|Typing)` in all of the files-to-check and fanout, if they hadn't been reported.
```
      let errors =
        Errors.incremental_update
          ~old:errors
          ~new_:Errors.empty
          ~rechecked:files_checked
          Errors.Parsing
      in
      let errors =
        Errors.incremental_update
          ~old:errors
          ~new_:errorl\'
          ~rechecked:files_checked
          Errors.Typing
      in
```

I think this makes sense. Typing_check_service is the only thing that produces `phase=Errors.(Parsing|Typing)`. If we ran typing_check_service over some files, then the fact that a Parsing error wasn't produced is definitive proof that this file is free of Parsing errors.
