[This is part of an 19-diff stack whose purpose is to remove the redundant Errors.Parsing and Errors.Decl phases]

The only places that ever created `phase=Errors.Decl` were callers of `Decl.make_env`. I had a hypothesis that Decl.make_env never actually creates any errors. Look at it:
```
let make_env
    ~(sh : SharedMem.uses) (ctx : Provider_context.t) (fn : Relative_path.t) :
    unit =
  match Direct_decl_utils.direct_decl_parse_and_cache ctx fn with
  | None -> ()
  | Some parsed_file ->
    List.iter parsed_file.Direct_decl_utils.pfh_decls ~f:(function
        | (name, Shallow_decl_defs.Class _, _) ->
          (match Provider_context.get_backend ctx with
          | Provider_backend.Rust_provider_backend backend ->
            Rust_provider_backend.Decl.declare_folded_class
              backend
              (Naming_provider.rust_backend_ctx_proxy ctx)
              name
          | _ ->
            let (_ : _ option) =
              Decl_folded_class.class_decl_if_missing ~sh ctx name
            in
            ())
        | _ -> ())
```

I wrote D44736172 which added telemetry should `Errors.add_error_impl` ever be called to create a `phase=Decl`. It was never hit. That was conclusive proof that `phase=Errors.Decl` never exists. I'm therefore writing a few diffs to clean up the dead code.

This diff cleans up code in ServerTypeCheck.ml in the light of the fact that `phase=Errors.Decl` never exists.
