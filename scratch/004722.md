Commit title: Adjust method name for read and write hooks
Commit body:
Summary:
Currently, the [`onReadData`](https://github.com/facebook/fbthrift/blob/bdb837b9023d1305701928a9f5d1d44c319cafa5/thrift/lib/cpp2/async/AsyncProcessor.h#L1403) and [`onWriteData`](https://github.com/facebook/fbthrift/blob/bdb837b9023d1305701928a9f5d1d44c319cafa5/thrift/lib/cpp2/async/AsyncProcessor.h#L1482) hooks that record Thrift
requests and responses use [`<method name>`](https://github.com/facebook/fbthrift/blob/bdb837b9023d1305701928a9f5d1d44c319cafa5/thrift/compiler/generate/templates/cpp2/service_tcc/process_and_return.mustache#L82) and [the empty string](https://github.com/facebook/fbthrift/blob/bdb837b9023d1305701928a9f5d1d44c319cafa5/thrift/lib/cpp2/async/AsyncProcessor.h#L1507) respectively for
the recorded method name. This diff changes the recorded method name to
`[<interaction name>.]<method name>` in both cases. My understanding is that
the plain `<method name>` for the read hook is left over from before
interactions were implemented, and the empty string for the write hook was
unintentionally used during the migration away from envelopes. This diff
ensures that the consumers of these hooks get the same method name that would be
sent by the client and used when mapping the method name to a handler server side.
It also factors out the `[<interaction name>.]<method name>` into a common
template.
