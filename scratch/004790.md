Commit title: "hh check" flushes scuba logs once a second
Commit body:
Summary:
We use EventLogger.flush in long-running processes -- hh_server does it once a second, and clientLsp does it every 1s idle tick.

"hh check" is another long-running process. Sometimes it runs for 30+mins, accumulating HackEventLogger messages in ram, but never writing them until the very end.

This diff flushes them once a second.

An incidental beneficial side-effect is that, when the user hits Ctrl+C, the outstanding accumulated HackEventLogger messages get simply dropped. That is despite us already calling EventLogger.flush upon exit https://www.internalfb.com/code/fbsource/[272d0144878c]/fbcode/hphp/hack/src/facebook/logging/eventLogger.ml?lines=583. II don't know why... maybe it's because the scribe-writing process sees that its parent has died, and so terminates rather than processing its stdin first. Anyway, with this diff, we will get useful telemetry about the course of a typecheck even if the user did Ctrl+C.
