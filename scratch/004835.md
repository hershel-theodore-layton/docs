Summary:
This diff adds HhvmOptions support (-c, -v, -d) to "hackc compile".
```
                        recommended?   multifile?     HhvmOptions?
                        ------------   ----------     ------------
hackc compile ~/a.php   yes!           supported      not-supported
hackc ~/a.php           deprecated.    not-supported  supported
```
* Multifile is when a single physical file can denote multiple subfiles with `//// subname.php`.
* HhvmOptions include things like `-v Hack.Lang.AllowUnstableFeatures=true`, `-c config_files`, `-d NAME=VALUE`.

This diff adds HhvmOptions support to "hackc compile". I'm doing this because I want to combine multifile with unstable-features.

The key changes are in how `hackc compile` constructs NativeEnv.
```
BEFORE:
NativeEnv {
  hhbc_flags: {
    emit_cls_meth_pointers: true,
    emit_meth_caller_func_pointers: true,
    fold_lazy_class_keys: true,
    log_extern_compiler_perf: true,
    ..Default::default()
   }
  hhvm: Default::default(),
}

AFTER:
NativeEnv {
  hhbc_flags: <from HhvmOptions>
  hhvm: <from hard-coded auto_namespace_map(), and HhvmOptions>
}
```
I think that's better, right?
