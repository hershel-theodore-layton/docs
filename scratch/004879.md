Commit body:
Summary:
These were previously needed because of an upgrade to boost that caused boost regex to start including Windows.h, which will, by default, break anything using std::numeric_limits, since NOMINMAX is not provided as part of boost's include.
This resolves the issue by moving the boost regex includes to the end of the include list, which resolves the issue directly since TestUtil.cpp doesn't actually use numeric_limits itself, and Benchmark.cpp already includes folly/FileUtil.h which is pretty much guaranteed to have already included Windows.h with the right defines.
This also adds documentation around each include to make it clear why things are the way they are.
