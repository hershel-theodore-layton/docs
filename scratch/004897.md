Commit title: sanity checks on <<__ModuleLevelTrait>> attributes
Commit body:
Summary:
This diff implements sanity checks on the `<<__ModuleLevelTrait>>` attribute:

- Only public traits can be declared `<<__ModuleLevelTraits>>`.   Internal traits can only be used by traits/classes belonging to the same module, so the attribute would not change the default semantics.

- A trait annotated with `<<__ModuleLevelTraits>>` can only use traits annotated with  `<<__ModuleLevelTraits>>`.  Since in the runtime data-structures the `originalModuleName` of a method gets shared among all copies of the method, it is awkward to support a module level trait (where all methods are annotated with `originalModuleName`) using a non module level trait (where methods might miss the `originalModuleName` annotation).  Additionally, classish-level attributes that change the semantics of the methods do not play well with diamond inheritance.
