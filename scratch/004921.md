Summary:
This diff adds exhaustive tests for reserved keywords, in both hh and hackc.

## Existing

For hh there already exist some tests, particularly https://www.internalfb.com/code/fbsource/fbcode/hphp/hack/test/full_fidelity/cases/keyword_as_class_reserved.php.errors.exp although
* it only tests classes, not other constructs which are also checked for reserved words
* it includes some like "double, dict" that aren't reserved
* it omits some like "callable, nothing, _" that are reserved
* it doesn't test the namespace case.

There are also other hh tests scattered here and there, in tests associated with the individual keyword, e.g. https://www.internalfb.com/code/fbsource/fbcode/hphp/hack/test/typecheck/nonnull/nonnull_keyword.php.exp

There are also a bunch of hhvm tests e.g.
* https://www.internalfb.com/code/fbsource/fbcode/hphp/test/quick/reserved_class1.php.expectf
* https://www.internalfb.com/code/fbsource/fbcode/hphp/test/slow/parser/hh-reserved-name-nothing-2.php.expectf

### Why a new test suite?

So why am I adding a new test suite?
1. The existing hh tests aren't comprehensive. I believe the hhvm ones also aren't, but I'm having a hard time being sure because they're split over so many individual files.
2. I wanted a test suite that plainly and clearly juxtaposes the hh and hackc treatment of reserved names
3. Our source code for the "reserved_names" functions can point to this test suite, as a way to encourage future code authors to keep tests and code comprehensive.
4. I am about to change the way hh reports "reserved name" keywords, and I wanted a solid baseline for my changes.

## Structure of this suite

There are three places I looked at where reserved names are checked:
1. rust_parser_errors.rs `cant_be_classish_name` shared by hh and hackc
2. naming_global.ml `check_type_not_typehint` used only by hh
3. emit_class.rs `validate_class_name` used only by hackc

I read through the code and made a union of (1) the syntactic constructs that are checked for reserved names, (2) the set of reserved names against which they're checked. This test suite simply exercises the cross product of the two.

```
case type Foo = int;
type Foo = int;
newtype Foo = int;
newctx Foo as [defaults];
module newtype Foo as int = int;
enum Foo : int {}
enum class Foo : int {}
interface/class/trait Foo {}

x

arraykey, bool, callable, classname, darray, dynamic,
false, float, int, mixed, nonnull, noreturn, nothing,
null, num, parent, resource, self, string, this, true,
varray, void, _

x

\Name
\HH\Name
\N\Name
```

The final axis is because some parts of the code accept a name "\N\keyword" but don't accept "\keyword" or "\HH\keyword". Actually, for the tests, they were getting too voluminous so I skipped the "\HH\keyword" case.

There are also two additional places -- I don't understand how their role is different from the one above, and they're not part of my mission to eliminate hh_server's naming_global.ml, so I didn't look into them.
1. naming_elaborate_namespaces_endo.ml `is_reserved_type_hint`.
2. elaborate_namespaces_visitor.rs `on_ctx_hint_ns`
