Summary:
The previous diffstack observed that since the parser now detects all reserved-name-errors itself, then additional reserved-name checks in emit_class are redundant.

The same is true for hh. Prior to this diffstack, some reserved-names were reported by the parser `(Parsing[1002])`, some by hh `(Naming[2068])`, and some by both. The diffstack has brought us to the point where nothing is hh-only.

Therefore, this diff removes the redundant hh checks, and therefore too the duplicate errors:
```
PRIOR TO DIFFSTACK:
interface arraykey {} // Naming[2068]
interface bool {} // Parsing[1002]

BEFORE THIS DIFF:
interface arraykey {} // Parsing[1002] + Naming[2068]
interface bool {} // Parsing[1002]

AFTER:
interface arraykey {} // Parsing[1002]
interface bool {} // Parsing[1002]
```

This looks nicer!

## Why am I doing this?

I want hh to report errors solely on a map/reduce basis, so the only errors reported for a file are those detected when we process the file (be it through a distributed typecheck with RE, or squiggles in the IDE). Previously the Naming[2068] errors were done centrally by hh_server, but not by RE or IDE. Now, all reserved-name errors will be done identically everywhere.
