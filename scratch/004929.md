Summary:
UPDATE: v1 of this diff proposed to allow `classname, darray, varray` as class names. Based on discussion here, I wrote D45697534 to disallow `darray, varray` as alias names. Therefore, v3 of this diff has shrunk and now only proposes to allow `classname` as a class name.

--------

`hh` treats reserved-names for {classish, enum, enum-class} almost identically to reserved-names for aliases {type, newtype, module newtype, case type, newctx}.

It differs only in one respect: **classname** is disallowed for {classish, enum, enum-class} but allowed for aliases. Indeed we define an alias named `classname` in classname.hhi, so `classname` has to be allowed for aliases!
```
  newtype typename<+T> as string = string;
  newtype classname<+T> as typename<T> = typename<T>;
```

I have an idea. What if `classname` were allowed also for classish/enum? From the language design perspective, this change would mean that all types will now have identical rules about reserved names. (Also, it just seems weird with respect to the above file that 'classname' is reserved for classish+enums but 'typename' isn't reserved.)

However I don't understand the implications of this...
