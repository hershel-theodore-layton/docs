Commit title: Support for struct type as map-key
Commit body:
Summary:
When a struct is used as a map key - it needs to be a "concrete" struct, not a pointer:
`map[MyStruct]int64` vs `map[*MyStruct]int64`

However, there is a caveat - a struct may be incomparable (if it contains a slice or a map inside). An incomparable object cannot be used as a map-key. We need to account for that.

If struct is comparable - use "concrete", if struct is not comparable - use pointer (pointers are always comparable).

Using a pointer does not guarantee key uniqueness (because struct contents are not checked for equality) - but the code will be valid and will compile.
Which is a major win over the legacy generator.
