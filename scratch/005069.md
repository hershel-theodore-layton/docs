Summary:
This diff deletes `hh --color` and `hh --coverage`

`hh --color flib/intern/chess/ChessBot.php` claims it renders the file showing which bits are typechecked, which are partially checked, which are unchecked, i.e. use **Tany**.  (but now, with True Types, pretty much everything is checked according to this definition). There have been only five users who used it over the past month, all probably incorrectly guessing it was a way for hh to colorize its *error messages*!

`hh --coverage flib/intern/chess/ChessBot.php` shows what % of expressions are typechecked. Code in clientCoverageMetric.ml, serverCoverageMetric.ml. No invocations in the past month.

LSP prior to VSCode used to show the %coverage of a file in the status bar. Users could click this status bar indicator and it would toggle some kind of coverage analysis. No one ever used it.

Wilfred writes:

> --color and --coverage are very dead, and pretty darn broken. It needs a bit of plumbing to rip them out, but it's well worth doing. IIRC --color was intended to help when moving files to strict mode, and I doubt it does anything meaningful at this point. --coverage used to be exposed in the VS Code UI (there was a button at the bottom) to show what was type checked, but it predates constraint-based type checking. --coverage also had some gotchas in the UI: you could turn it on but couldn't turn it off. I don't think you'd want to reuse it.

This diff deletes everything relating to --coverage and --color

(Why am I doing this now? I'm trying to clean up the API in Typing_check_job, and --coverage uses that API in weird ways, and I'd rather delete --coverage than fix it.)
