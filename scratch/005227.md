Summary:
Look at the error messages we generate:
```
function foo(): void {}
function foo(): void {}
// ERROR:
// Name already bound: `foo` (Naming[2012])  <- points to2nd definition
// Previous definition here <- points to 1st definition

function bAr(): void {}
function bar(): void {}
// ERROR:
// [BEFORE THIS DIFF]
// Name already bound: `bar` (Naming[2012])  <- points to2nd definition
// Previous definition `b~~A~~r` differs only by case  <- points to 1st definition

// [AFTER THIS DIFF]
// Name already bound: `foo` (Naming[2012])  <- points to2nd definition
// Previous definition here <- points to 1st definition
```
I'm reimplementing "name already bound" errors because their current implementation is bad
* it doesn't support distc nor ClientIdeDaemon being done in a central phase at the start of ServerTypeCheck
* it is implemented by looking "bar" in the naming-table sqlite with a case-insensitive search, finding the filename in which the decl is defined, parsing it, walking the parsed form to find any decl whose case insensitive hash matches the one we're looking for, uses this to determine the canonical capitalization "bAr", then queries the naming-table sqlite a second time to find the file which stores this decl, parsing it again to obtain the location, and comparing whether the location is the same as the current location
* This is the only place in the code which makes all these horrible requirements on what the naming-table stores and what has to be cached.

As I re-implement it in a place that's suitable for distc and clientIdeDaemon, I don't want to carry forwards this baggage. My new proposed implementation is similar to what's already in [typing_class.ml](https://www.internalfb.com/code/fbsource/[84b7db29a73857b9bf9964117701a4750e55633c]/fbcode/hphp/hack/src/typing/typing_class.ml?lines=1828):
* fetch the (position-full) decl for the symbol by case insensitive search. Compare the positions in that decl to the current AST node. If they don't match, then we must be checking a duplicate.

This new proposal will be simpler, faster, and won't require extra caches.

But as I do the new one, I kind of just don't have the energy to maintain the existing "this differs in capitalization" nicety. That's a bunch of work that's not justified by the return. And will in any case become irrelevant once we switch to case-sensitivity throughout, which edwinsmith is already part way towards.

This diff is preparation. It removes the special-cased error message about capitalization, so that future diffs will be easier.
