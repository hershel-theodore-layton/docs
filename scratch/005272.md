Commit title: Make switch case scrutinee mismatch use disjointness
Commit body:
Summary:
With true types, the lint rule that detects when switch case and scrutinee can never match become noisy because in many cases a type (say an enum) `E` became `~E` and the rule was looking for strict subtyping relationships that were no longer satisfied.

This diff reduces the false positives by switching the implementation to use type disjointness relation.

Not only this got rid of the bug, but it also eliminated false positives that existed prior to the release of true types.

**N.b.** The test cases show funny results for the exhaustiveness check, but that's preexisting behaviour and this diff aims to address problems with case/scrutinee mismatch.
