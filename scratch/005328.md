Commit title: Report multiple errors from conjunctions
Commit body:
Summary:
Consider
```
function expectTwo(int $x, bool $y):void { }
function expectPair((int,bool) $p):void { }
function expectShape(shape('a' => int, 'b' => bool) $s):void { }

function testThem():void {
  expectTwo("A", 2.3);
  expectPair(tuple("A", 2.3));
  expectShape(shape('a' => "A", 'b' => 2.3));
}
```
Currently Hack reports two errors for the call to `expectTwo`, one for each of the parameters. But it reports only one error each on `expectPair` and `expectShape`, even though the second element of the tuple and field `b` are incorrectly typed.

The root cause is that when we use the `&&&` conjunction combinator during subtyping, we drop any conjuncts that are unsatisfiable, thus losing the error that was carried in the `Disj` constructor. If instead we merge errors from conjuncts, then we get to report all errors associated with conjunctive features such as tuples and shapes.

Most of the time the errors that are produced are an improvement. Other cases need further improvement. For example, consider the following under implicit pessimisation:
```
type TS = shape(
  'a' => int,
  'b' => bool,
);

function expectShape(TS $_):void { }

function getVecInt():vec<int> {
  return vec[];
}

function testit():void {
  $x = shape('a' => getVecInt()[0], 'b' => 2.3);
  expectShape($x);
}
```
Previously, the following would be reported:
```

-> Expected int [2]
-> But got dynamic [3]

shape_like_sub.bad.php:19:15
     3 |
     4 | type TS = shape(
[2]  5 |   'a' => int,

    18 | $x = shape('a' => getVecInt()[0], 'b' => 2.3);
[1] 19 |   expectShape($x);
```

This is not helpful, as it doesn't identify the actual use error (float field where bool was expected). Under this diff, two errors are reported:
