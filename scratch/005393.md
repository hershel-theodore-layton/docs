Summary:
Overview of this stack of five [type-ast] diffs is fully explained in D45834281. Summary:
* Currently the typechecker takes a list of top-level names to typecheck, then iterates over that list of names, fetches the winning definition of that name in the file, and typechecks it.
* Thanks to this stack, the typechecker will instead iterate over the list of definitions in the file and typecheck them.

---------

Currently, `Typing_check_service.process_file` and `Typing_check_utils.type_file` both both take an AST, then call `Nast.get_defs` to obtain a list of toplevel symbol names in lexical order, then typecheck those names.

This diff changes it so `Nast.get_defs` returns a list of pairs `(name, ast_node)`. That way the caller will be able to iterate ast-nodes rather than having to iterate names. I renamed the existing functionality `Nast.get_def_names`.
