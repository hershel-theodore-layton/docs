Commit title: make ~full explicit parameter
Commit body:
Summary:
I don't like the optional parameter in lots of Ast functions e.g.
```
val find_class_in_file :
   ?full:bool -> Provider_context.t -> Relative_path.t -> string
   -> Nast.class_ option
```
Why?
1. I don't believe that non-full ASTs should even exist anymore in our codebase, since we now have direct-decl-parser. Making it explicit is my step towards removing it.
2. It feels important to know whether you have a full or partial AST in hand! Maybe the two should even be expressed differently in the type system. But for now, just an explicit parameter is a good enough first step.
