Commit title: Add types to `Violated_constraints` and `Subtyping_error` secondary errors
Commit body:
Summary:
Custom errors will work by allowing user-defined pattern matching on errors and attaching the associated message. To support our known use-cases for custom errors, our typing errors need to contain types.

Currently, we pretty print types and render reasons for `Violated_constraints` and `Subtyping_error` messages _inside_ subtyping. This diff modifies the definition of those errors to directly contain the sub- and super types for which a subtyping constraint has failed and moves the rendering of reasons into typing error evaluation.

Note that this means the environment used during rendering will be provided from typing, after the tyvars have been solved to upper/lower bounds, rather than from subtyping, before any solving. You can see the impact of this change in the handful of modified tests.
