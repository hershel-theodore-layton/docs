Summary:
[Overview: I'm changing it so duplicate-names are no longer reported during hh_server's main loop when it calls Naming_global; instead they'll be reported along with every other parse+typing error during Typing_toplevel]

The previous diff changed it so that `Naming_global.ndecl_file_error_if_already_bound` never reports the errors. This diff cleans it up.
```
BEFORE:
val ndecl_file_error_if_already_bound :
  Provider_context.t ->
  Relative_path.t ->
  FileInfo.t ->
  Errors.t * Relative_path.Set.t

AFTER:
val ndecl_file_and_get_conflict_files :
  Provider_context.t -> Relative_path.t -> FileInfo.t -> Relative_path.Set.t
```
FYI: The "conflict files" which this function used to return, and still does, are the two or more files involved in each duplicate-name errors. It's stored in `env.failed_naming`. Hh_server uses this so that if the winner gets deleted then it knows to recheck the loser file. It actually does something more broad but still safe -- on every watchman file-change, redo naming based on ALL watchman changes plus conflict files.
