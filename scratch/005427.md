Summary:
[Overview: I'm changing it so duplicate-names are no longer reported during hh_server's main loop when it calls Naming_global; instead they'll be reported along with every other parse+typing error during Typing_toplevel]

We currently don't use distc in cases where there are duplicate naming errors.

Previously, this was enforced by looking whether ServerTypeCheck.do_naming had reported any errors in phase=Errors.Naming. But I moved error-reporting out of there into Typing.top_level so it's no longer any use.

A better way to enforce it is whether `env.failed_naming` is empty. This is the "underlying truth" for hh_server about whether there are any duplicate name errors and where they can be found.
