Summary:
[Overview: I'm changing it so duplicate-names are no longer reported during hh_server's main loop when it calls Naming_global; instead they'll be reported along with every other parse+typing error during Typing_toplevel]

There has been a common confusion that `Errors.Naming` must be what `Naming.program` generates. That's not actually the case, and is not what ServerTypeCheck does. Instead, `Errors.Naming` used to be solely for duplicate names that were discovered during reverse-naming-table update, while `Errors.Typing` was used for parsing, naming, typing.

The following code uses the wrong category. This diff fixes it.
```
    let (naming_errors, nast) =
      Errors.do_with_context
        entry.Provider_context.path
        Errors.Naming
        (fun () -> Naming.program ctx ast)
```

I also updated the comment to indicate that duplicate-name errors are in fact no longer reported during reverse-naming-table-updates, and are instead reported during Naming.program (where they properly get the phase `Errors.Typing`).
