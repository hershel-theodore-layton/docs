## background

test_lsp.py has two paradigms of tests:
```
self.load_and_run(
   "rename", variables, wait_for_server=False, use_serverless_ide=False
```
This first "load_and_run" paradigm will (1) spin up an LSP server, (2) send to it LSP requests found in lsp_exchanges/rename.json, (3) expect to find LSP responses matching lsp_exchanges/rename.expected

```
self.run_spec(spec, variables, wait_for_server=False, use_serverless_ide=True)
```
This second "run_spec" paradigm again has you construct declaratively the requests you want to send and the responses you want to get back, but you construct the declarations of what you send+receive in python and it allows a bit more flexibility.

Before doing either of those two tests above, most tests also set up a file on disk:
```
self.setup_php_file("completion.php")
```
This writes the file to disk, but also has the side effect of launching hh_server. (why? so we can learn the path on disk where hh_server wrote its hhi files...)

## On to the point of this diff

The two parameters `wait_for_server` and `use_serverless_ide` mean the same thing across both paradigms. They are poorly named parameters because they reflect how the thing is going to be used, rather than what it does. So what do they do?
* `wait_for_server` causes us to do an implicit "hh check" before the test starts
* `use_serverless_ide` causes us to do an implicit "hh stop" before the test starts. It also suppresses a feature whereby, if the test machine was overloaded so much that the test couldn't connect to hh_server, then the test would be marked as "skipped" rather than failed.

This diff changes things around to make all tests have identical behavior, and to avoid launching hh_server if possible.
1. `setup_php_file` no longer has the side effect of launching hh_server. I simply abandoned our need to learn the location where hh_server wrote its hhi files. In any case, that doesn't make sense, because clientIdeDaemon writes its hhi files to a different location! This is made possible by D17849528, which uses a regexp to rewrite hhi paths wherever it sees them into "/tmp/cleansed_hhi_path"
2. `wait_on_server` is now never used. No tests will implicitly do an "hh check" nor start hh_server. If a test wants to start hh_server (like e.g. test_rename) then it can do so explicitly.
3. `use_serverless_ide` is now never used. We no longer have need to do "hh stop" since hh_server isn't running.
4. We will use the "skipped" technique in all cases now.

You might be confused about all the "use_serverless_ide" flags... They're all different!
1. In the previous diff, "use_serverless_ide" was used as a parameter to write_load_config to decide what contents go into hh.conf
2. In this diff, "use_serverless_ide" is used as a parameter to load_and_run to decide whether to do "hh stop" before the test starts.
3. In the next diff, "use_serverless_ide" is used as a parameter to init_spec to determine which messages get sent back and forth to the LSP server, particular during initialization.
