[I'm trying to rollout ide_standalone. This computes squiggles with Tast_provider rather than hh_server. I saw telemetry that HH_FIXME suppressions aren't being honored; these make up the only user-reported issue with ide_standalone.]

Fixmes are stored in a global mutable store. They're updated upon parsing a file:
```
//// Full_fidelity_ast.ml
let process_scour_comments (env : env) (sc : Scoured_comments.t) =
  if (not env.disable_global_state_mutation) && env.keep_errors then (
    Fixme_provider.provide_disallowed_fixmes env.file sc.sc_misuses;
    Fixme_provider.provide_hh_fixmes env.file sc.sc_fixmes
  )

//// Fixme_provider.ml
let provide_hh_fixmes filename fixme_map =
  if not (IMap.is_empty fixme_map) then
    HH_FIXMES.add filename fixme_map
```
I have many objections to this, though the current diff isn't the time to change them.
1. The flag `disable_global_state_mutation` is normally false as you'd expect. It is set to true only in test/facebook/ffp_www_perf/run.ml. It should be removed
2. The flag `keep_errors` appears to normally be true, but set to false solely in serverOutline. This feels like a bug possibility; I think it should always be true.
3. The behavior of `provide_hh_fixmes` is just bizarre. We've parsed the file and determined that there are no fixmes. We should therefore be REMOVING the fixmes from Fixme_provider. But we're not! we're leaving it as a no-op! It doesn't make sense.
4. Fixmes simply shouldn't be stored in a global mutable data. They are AST artifacts that come out of Ast-parsing, and should be returned as a tuple along with the AST, and cached with it.

Given problem (3), how does hh_server ever get things correct when you delete a fixme? The answer is as terrible as you'd expect. When it detects file-changes, it resets all fixmes for that file PRIOR to parsing.
```
let indexing genv env to_check cgroup_steps =
  Fixme_provider.remove_batch disk_files;
  Direct_decl_service.go ...
```

## What this diff does

What I've done in this diff is make clientIdeDaemon replicate the same pattern as serverTypeCheck: if it encounters a changed file, then it resets the Fixme_provider for it.

I think there should be different more major structural improvements, but those will have to be left for future.
