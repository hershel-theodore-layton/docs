Commit title: Represent more user attributes in decls
Commit body:
Summary:
User attributes are currently represented in a degenerated form
that has the least amount of information required for typing. As
decls get more use outside typing, the semantic value carried
by user attributes and lost during decling starts missing. This
diff enriches a little bit the user attributes that can be represented
by allowing string literals, enum class labels, and classnames
to appear as parameters of a user attribute.

Of interest to me (see task linked) are the new variants of
memoize (e.g., `__Memoize(#KeyedByIC)`) that use enum
class labels.
