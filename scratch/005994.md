Commit body:
Summary:
`BINARY` is not a valid Thrift protocol type.

Thrift fields can be `binary` (no to be confused with protocol types) - but under-the-hood they are treated as `STRING` type: https://thrift.apache.org/docs/types#special-types

> binary: a sequence of unencoded bytes
> N.B.: This is currently a specialized form of the string type above, added to provide better interoperability with Java. The current plan-of-record is to elevate this to a base type at some point.

Also: https://www.internalfb.com/intern/staticdocs/thrift/docs/idl/#primitive-types
> binary and string are encoded identically in the Binary and Compact protocols used for RPC and are interchangeable. However, they are encoded differently in JSON protocols: binary is Base64-encoded while string only has special characters escaped.

See downstream diff explaining how `BINARY` erroneously came to be.
