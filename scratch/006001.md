Commit title: Improve user attributes parsing
Commit body:
Summary:
After this diff we stop conflating all user attribute parameters as
classnames. User attributes are always of the form `AttrClass(e1, e2, ...)`.
For the parameter expressions `e1, e2, ...` we now accept string literals,
concatenations of string literals, integers, enum class labels, and classnames.

I also simplified the field `string_literal_params` in the user attribute
node into being an option rather than a slice: we only ever considered
the first element of this slice.

The parsing of string concatenations was also made more strict.
