Commit title: use serde_json::Value for attribute values
Commit body:
Summary:
attribute arguments in Hack can be strings, classnames, integer,
bool, shape, etc. Currently the direct decl parser reveals these values
as strings, and the facts::Facts ADT in facts.rs exposes them as
Vec<String>.

However:
* the Facts api allows arbitrary hack values with vec<dynamic>. see HH\Facts\file_attribute_parameters(), method_attribute_parameters(), etc.
* in C++, make_file_facts(), SymbolMap, and FactsStoreImpl represent attribute values as folly::dynamic.
* parsing facts involves several representations: text -> decls -> facts::Facts -> json -> folly::dynamic -> HPHP::FileFacts -> sqlite, and in the last 2 steps, attribute values are preserved in their folly::dynamic form. That means even though facts::Facts represents them as Vec<String>, they end up as folly::dynamic strings and stay that way.
* in sqlite3, they are converted to serialized json and back by SymbolMap

As a first step, change facts:Facts to use serde_json::Value for these values - this allows them to round-trip faithfully into json and then folly::dynamic. Whatever facts.rs decodes from decls, that's what will go all the way through.

This doesn't require any sqlite schema changes since the various attribute_value columns are already considered to be json text.
