Summary:
[I'm working towards rolling out ide_batch_process_files. This means that changed-files after saved-state-init are done multicore synchronously, and DidChangeWatchedFiles too.]

## Background

The ide_batch_process_files feature will reduce raciness. Previously if we had say 1000 files to work through and update the naming-table for, and they were processed one at a time, then if we attempted to compute some file's TAST+errors during that time, we might have used stale names. With this diff we'll use less stale names.

(We're still subject to raciness, e.g. if we try to typecheck a file but maybe watchman hasn't yet sent the update for it, or maybe VSCode hasn't forwarded that as a DidChangeWatchedFile. That can only be solved once we implement decl-consistency and an exception "sorry disk changed under your feet". So we've only reduced it, not eliminated it.)

The ide_batch_process_files feature will also improve perf. As we worked through those 1000 files one by one over 5-30s, each time we processed one, we threw away *every* TAST for every open file. So if the user was hovering in various places in their file, every time they hovered, there's a good chance they'd incur the cost of having to recompute the TAST. With this diff, the TASTs only get invalidated once.

## This diff

This diff makes us process DidChangeWatchedFiles synchronously. Previously, if DidChangeWatchedFiles arrived, we stuck the changed-files in a queue to be handled (in a synchronous batch) the next time clientIdeDaemon became free. After this diff, they're handled immediately in the DidChangeWatchedFiles handler.

This doesn't significantly improve or change those two wins of the ide_batch_process_files feature. Its only behavioral change will be to make the processing happen a touch sooner.

But what this diff does is make possible some cleanup after ide_batch_process_files has been fully rolled out. At that time, I will be able to remove "changed_files_to_process / changed_files_denominator" from Initialized state. The only thing to exist will be "changed_files_to_process" in During_init state.

It also makes telemetry more straightforward: now, telemetry about duration is recorded in time_taken_ms of CLIENT_LSP_METHOD / didChangeWatchedFile.

I also added telemetry about duration of the batch processing that happens during initialize2, to index all changed_files after a saved-state-load.
