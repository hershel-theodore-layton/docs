Commit title: Improve property analysis logic a bit in HHBBC
Commit body:
Summary:
- Rather than updating prop.val and prop.attrs during analysis, defer
  the updates for the update phase. Doing it during analysis is unsafe
  because other threads might be reading it at the same time. This is
  unlikely to cause crashes, but can introduce non-determinism. To
  avoid adding anymore space to FuncAnalysis (which we have a lot of),
  use UniqueEither to re-use the space for resolved constants (we'll
  never resolve constants and property values in the same php::Func).

- Don't bother recording public static property mutations during the
  analyze constants phase. We don't do public static property tracking
  during analyze constants, so recording the mutations is pointless
  work. If we did do the tracking during analze constants, it would be
  unsound anyways, as we're not analyzing all of the functions at that
  point.

- We don't need to store the initializer type separately for public
  static properties, nor do we need the resolved flag. This was all
  work-arounds for the first issue where php::Prop val could change
  during analysis.

- Instead of pre-creating information about every public static
  property, create it only as necessary.
