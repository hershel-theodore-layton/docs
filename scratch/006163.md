[The ide_standalone "shellout to hh" technique is used to power rename, find-all-refs, go-to-impl. But the code doesn't make clear the invariant that if we kicked off a shellout then we must eventually deliver an LSP response for it, and indeed we don't deliver any LSP response in several scenarios. This diffstack address it.]

This diff is a refactor on the way to streamlining the `handle_shell_out_hh_feature` and `respond_jsonrpc_for_shell` methods.

It comes with two behavioral changes:
1. I switched shellout telemetry from storing duration as float seconds, to storing duration as integer ms like everything else does.
2. When parsing the shellout's stdout, we returned `Error string` for some cases of fail to parse, we used Yojson exception for other cases, and we used `InvalidIdePatchType` for another case. The Error cases were handled by sending back an error LSP response, but the exception cases just bubbled up to the general-purpose "clientLsp unhandled exception handler" where they'd fail to deliver an LSP response. I changed to use only exceptions, and to generate LSP errors for them.
