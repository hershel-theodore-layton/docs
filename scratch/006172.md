Summary:
[This short diffstack ends with changing the behavior of `hh --autostart-server false`. Previously, regardless of the value of this flag, if there was a version mismatch then hh_server would always terminate. After this diffstack, in case of version mismatch, hh_server will only terminate in case of `--autostart-server true`. I figured it as "put your money where your mouth is" -- hh_client is only able to cause hh_server to terminate, if hh_client is willing to restart it afterwards.]

This diff is a no-op change that adds stronger types. The deal is that when hh_client opens up a connection to the monitor, each party might actually come from a different version. Therefore they speak only in json strings (which can be safely marshalled/unmarshalled even between different versions of hack). They read the values manually, supplying defaults as needed in case the old version didn't provide certain fields.

Previously the code to serialize into a json string, and deserialize out of it, was scattered around the place. This diff:
1. brings the functions "serialize" and "deserialize" together, right next to each other in the source code, in monitorUtils.ml
2. changes from exceptions in Result monad for parsing errors, which I found easier to reason about.
3. inlines some functions

I changed the logging+telemetry around a little bit too. I think none of us have ever looked at the telemetry about restarts on version mismatches...
