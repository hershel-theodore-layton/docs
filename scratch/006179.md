Summary:
This diff streamlines result_telemetry, the optional telemetry structure we return at the end of handle_client_message which populates our telemetry columns `lsp_result_count` and `lsp_result_extra_data`.
1. I made a constructor function `make_result_telemetry` so that (the majority of) functions which don't provide lsp_result_extra_data, don't need to provide it
2. I renamed the codebase `result_extra_telemetry` to `result_extra_data` to reflect its name in scuba
3. For any function which returned a constant count, I removed it -- this isn't adding any value in the telemetry!
4. There were two high-volume requests with lsp_result_extra_data which I deleted because I can't imagine them ever being useful, and json isn't very compressible, and they're high volume: for "hover" we were recording line+pos, which I dropped; for "definition" we were recording whether the target is an XHP attribute, which I dropped.

I'm doing this in preparation for the next diff which will make shell-outs report their telemetry in CLIENT_LSP_METHOD.
