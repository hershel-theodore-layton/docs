Commit title: shell_out reports telemetry in CLIENT_LSP_METHOD
Commit body:
Summary:
Prior to this diff, when the user did a shellout action like rename or FindRefs, then CLIENT_LSP_METHOD stored information about the first local half, and CLIENT_LSP_SHELLOUT stored information about the shellout.

This diff changes it so CLIENT_LSP_METHOD stores complete information about how the method was handled, both local part and shellout. My goal is
1. to make our telemetry easier to read from without needing to know special-case knowledge about rename/findReferences
2. critically, I want cancellation to be logged correctly e.g. for shellouts that received a $/cancelRequest or were displaced by another shellout, and this seemed the best way to do it.
3. I wanted detailed breakdown of time-taken amongst the various phase (wait for local, local processing, shellout, post-shellout wait, postprocessing)
