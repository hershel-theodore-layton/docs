Commit title: Cache both dynamic and non-dynamic tasts
Commit body:
Summary:
The hover IDE functionality requires a dynamic TAST. Other functionality doesn't. D45777027 introduced a shared cache line for dynamic and non-dynamic TASTs. As the IDE requested us to do different actions, the cache line kept being invalidated.

Solution: maintain two cache lines. One for the dynamic-aware TAST and one for the non-dynamic aware tast.

-----

Discussion: Ideally, the AST structure itself should not be a heterogenous list of dynamic and non-dynamic tasts, but it should contain tuples. For example, `Tast.fun_def` should be a tuple, i.e. `Tast.fun_def= {fun_without_dynamic: Tast.fun_; fun_wtih_dynamic: Tast.fun_ option}` or something equivalent. However that's just too much work.

The above would involve:

  1. Updating the TAST structure
  2. Auditing all visitors
  3. Changing all clients that use the TAST structure (linting, hover, code actions, autocomplete, tast checks, holes, ...)

This solution is cheaper and works fine.
