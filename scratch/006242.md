Commit title: Destructuring of value that intersects with a mixed element type
Commit body:
Summary:
Tuples are represented at runtime by `vec`, and this is observable via refinement. So it's sound to simplify
```
vec<t> & (t1, ..., tn)
```
to
```
(t & t1, ..., t & tn)
```
However, tuples are not subtypes of `vec` according to Hack's subtyping rules, so for completeness we need to preserve the `vec` conjunct i.e. simplify to
```
vec<t> & (t & t1, ..., t & tn)
```
This simplification is particularly useful in conjunction with `supportdyn` and refinement against a tuple e.g. `$x as (mixed, int)` where `$x` has static type `vec<supportdyn<mixed>>` will allow tuple destructuring to a first element of type `supportdyn<mixed>` rather than `mixed`.
