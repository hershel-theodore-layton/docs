Commit title: extract lists
Commit body:
Summary:
Use the internal `Tuple` structure of thrift-python lists to get fast access to individual list elements.

Define a `capi::list<ElementThriftT, CppT>` type. The `ElementThriftT` indicates the type of the nested `Extractor` to use, and `CppT` specifies what the actual intended cpp type of outer `Extractor` return is. The tricky bit is mapping from `CppT` to `ElementCppT`. E.g., if `type` override is `folly::small_vector<uint64_t>`, then `ElementCppT` is `CppT`. If we can assume most containers follow STL convention, then `CppT::value_type` gives `ElementCppT`. I audited main containers in `folly` and verified they conform to this assumption for vectors and sets, as well as `key_type`, `mapped_type` convention for maps.

Another alternative is replacing `CppType` with more serious templates like
```
template <
    typename ElemThriftT,
    template CppContainer<typename, typename...>,
    typename ElemCppT,
    typename... Params>
struct Extractor<list<ElemThriftT, CppContainer<ElemCppT, Params...>>> {
};
```
But this may be more expensive for C++ to compile and produce larger code size, so I'd prefer to just rely on the STL convention where the container states its inner type(s).
