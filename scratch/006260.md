Commit title: Have hh_distc workers parallelize over toplevel definitions
Commit body:
Summary:
Make hh_distc workers typecheck per-toplevel-definition instead of file-per-file.

This diff makes a couple of changes:

1. Expose `Nast.get_def_names` to the worker main process
   1. In the worker main process, use it to get all the top-level definitions OR parse errors
   2. Change the main-worker process to send toplevel-definitions to its forked children instead of file indices
1. In `typecheck.ml`: rename `typecheck` to `typecheck_def`
    1. Add a utility to `Typing_check_job` that calculates the errors and the tast for a single definition
    2. Call it from the main-workers forked children

We needed to make some adjustments to the setup of the typecheck-workers:

  1. Don't clear the AST cache, otherwise it's too slow. The cache should have a builtin limit anyways. So I am not too concerned about that
  2. Don't clear the Fixme cache. Since we're now caching ASTs, we can't be clearing it, as it gets filled during AST parsing.
  3. In the Rust orchestrator, make sure we don't allow partially successfully typechecked files to slip through. If a file partially failed to typecheck, filter out the logs and resulting errors.

----
