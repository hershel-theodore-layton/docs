Commit title: fix Extractor memory leak
Commit body:
Summary:
Added test to detect memory leak in `Extractor`. This works because primitive types are placed directly into struct internal data without conversion, so the same object can be round-tripped through the struct. In other words, the object put into struct field at construction `is` the same object returned by accessor for `int`, `float`, and `bytes`.

The leak happens because `getThriftData` uses `._fbthrift_data` in cython, which `INCREF`s. Therefore, need to put the return in a `StrongRef` to `DECREF` on scope exit.
