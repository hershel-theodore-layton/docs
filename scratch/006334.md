Commit title: Nested encode/decode optimization tests
Commit body:
Summary:
Verifies that nested field and type adapter (`FA`, `TA`) can use the encode/decode optimization. No additional code changes beyond the previous implementation would be appropriate to address these cases.

Cases:
0: no field/no type implementations
1: no field/has type
2: has field/no type
3: has field/has type

The intended logic is as follows:
If there is a field adapter encode/decode implementation (cases 2, 3), it should call `FA::encode`/`decode` logic, which may also call encode/decode for the type-level tag. If it does, we shouldn't avoid performing this call.
Otherwise (cases 0, 1): Has `FA::to`/`fromThrift` call to perform the `Encode`/`Decode` at type-level.
