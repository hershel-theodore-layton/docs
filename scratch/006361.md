Summary:
This diff changes some defaults. My objective is (1) leave JK rollouts untouched for end-users, (2) but for hack team members who use "hh switch buck2", they should get all the modern defaults.

`ide_standalone` means that clientLsp does per-file squiggles, and shells out for rename+references, and reads streaming-error-file.
* Regular users will still get the JK (i.e. this diff doesn't affect them); it has been at 50% for a week, and today D47019078 rolls out to 100%
* "hh switch buck2" don't use JK, and the setting wasn't present in hh.conf, so they used to get the ServerLocalConfig.ml default which was "false" -- after this diff they'll get "true"

`ide_serverless` was the predecessor to ide_standalone (and is implied by ide_standalone) and means that clientLsp+clientIdeDaemon do most other per-file queries.
* Regular users will have the JK of ide_standalone (rollout today at 100%) which overrides this flag anyway, so it's really a no-op
* "hh switch buck2" don't use JK, but the setting was set to true in hh.conf, so we always used to get "true". But it's a no-op.

`ide_batch_process_changes` makes clientIdeDaemon uses Tom's fast rust parallel indexing.
* Regular users will have the JK which is currently at 0% (not yet rolled out)
* "hh switch buck2" don't use the JK, and the setting is absent in hh.conf, so we fall back to the default. After this diff, the default will now be "true"
