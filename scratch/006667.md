Commit title: Replicate ensureDirExistsAndWritable behavior in new API with robust error return
Commit body:
Summary:
While investigating memcache push, an unexpected log entry was found before a failure on startup: P778896834
```
ConfigApi.cpp:60] Failed to create directory '"/var/facebook/logs/libmcrouter"'. Error code: system:0
```

ConfigApi's usage of the `ec` content requires boost to fill the information in, but this is accomplished under the hood by the util itself.  Another fault lies from any failure found by checking permissions.  In that call, there is no interface with boost, so there's no way to know which check actually failed.

After some discussion, we'd like a new set of utility APIs which surface accurate errors for any failure in this operation.
So I created such that wraps an exception with detailed message and returned, rather than a simple bool.
The caller can now print the error reason and not concern itself with the implementation detail of the util.

Since these are new utilities, existing callers (including OSS) will not suffer backwards incompatibility.
