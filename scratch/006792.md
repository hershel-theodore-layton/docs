Commit title: Support nested wildcards in type arguments
Commit body:
Summary:
Introduce a new `wildcard_action` field into `expand_env`, used when localizing to interpret the wildcard type `_`. There are six values of `wildcard_action`:

* `Wildcard_fresh_tyvar`: generate a fresh type variable, i.e. interpret `_` as "please infer the type". Until now, this was used only for top-level type arguments e.g. `foo<_,int>(...)` and `new C<_>(...)`. From now, permit its use in nested positions in type arguments e.g. `foo<vec<_>>`.
* `Wildcard_fresh_generic`: generate a fresh generic parameter e.g. `T#1`. This is used for refinement expressions e.g. `$x as Vector<_>` will assign `$x` the type `Vector<T#1>`.
* `Wildcard_fresh_generic_type_argument`: generate a fresh generic parameter for *all* type arguments to classes and type-defs, not just wildcards. This is used only for checking case types.
* `Wildcard_require_explicit tp`: reject wildcard because it has been used inside a type argument for a type parameter `tp` that has the attribute `<<__Explicit>>`.
* `Wildcard_illegal`: we've already rejected the wildcard in the naming phase because it's not legal here e.g. in a function or method signature, or other top-level signatures.
* `Wildcard_higher_kinded_placeholder`: wildcard is a placeholder used to describe the arity of a higher-kinded type parameter e.g. `function foo<T1,T2<_>>(T1 $x, T2<int> $y): void`.

This diff also fixes a bug whereby we have been permitting `_` in nested positions where a parameter is declared `<<__Explicit>>`. For example, we were not rejecting the following code:
```
function foo<<<__Explicit>> T>(T $_):void { }
function testit():void { foo<vec<_>>(vec[3]); }
```

A future diff will extend the use of `Wildcard_fresh_generic` to lambda parameter and return types.
