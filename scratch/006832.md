Commit title: Cheaply propagate exception out of ClientSink::sink()
Commit body:
Summary:
In a recent investigation, we noticed that a lot of CPU cycles from our C++ service (Query & Indexing's Eunomia) are spent on throwing exceptions and unwinding the stack through which these exceptions propagate.

See https://fb.workplace.com/groups/thriftusers/posts/1241365293239547 for more details

This diff tries to make this exception-throwing path less expensive by wrapping the coroutine inside a `folly::coro::co_nothrow` so we could cheaply propagate the exception out of the calling coroutine. Reference: https://www.internalfb.com/intern/wiki/Coro/#avoiding-exceptions-bein
