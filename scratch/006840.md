Commit title: filecalls can refer to several callees
Commit body:
Summary:
A symbol (at a given position) can have more than one definition. When we build the FileCall facts, we currently pick only one. Consequently
- we miss some callee_xrefs, which could/should be exploited by diff sketch
- we sometimes choose an unresolved callee  (represented as an `occurrence` value) for the `callee_xref` field, when there's actually a resolved callee available.

The proposed fix is
* add a new field callee_xrefs which contains all possible targets
* Prioritize a resolved callee for  `callee_xref` field
