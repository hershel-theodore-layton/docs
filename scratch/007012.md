Commit title: build-size tweaks to ThreadLocalPtr helper ElementWrapper::set
Commit body:
Summary:
The overload not taking any deleter does only one thing which is documented as fallible - i.e., maybe throwing -, which is to acquire a lock on a mutex.

But, in practice, lock acquisition failure is a logic error indicating a bug in `ThreadLocalPtr` and not a runtime error that must be handled, so termination should be a reasonable outcome. We mark the function as `noexcept` to force that termination.

Therefore, there is no longer a need in that overload of `ElementWrapper::set` to handle failure, and the failure-handling code may be removed.
