Summary:
This diff changes hh_single_complete from SymbolIndexCore.update_files to update_from_addenda.

* SymbolIndexCore.update_files - this is an ugly function which we're in the process of deleting.
   * Its behavior is (1) it gets a FileInfo, (2) it attempts to read the file off disk, (3) it parses the file using Facts codepaths, (4) from this it figures out whether a type is a class/interface/trait/enum (needed for SymbolIndex to know what autocomplete icon it should have) and whether it's abstract/final. If it fails to read the file off disk then it falls back to using just the information from FileInfo, which lacks that information,
* SymbolIndexCore.update_from_addenda - this is the better replacement. It is provided with both FileInfo and "addenda" already, so it doesn't need to read from disk. zhyty invented this concept of "addenda".

This change doesn't seem to have altered any test output! I guess I didn't think it would. I could try constructing a test whose behavior changes, but it doesn't seem worth it.

The main benefit is in contributing towards getting rid of the facts code and SymbolIndexCore.update_files. (Next: nt591 wil complete rollout of Tom's change in clientIdeIncremental which will get rid of the call to update_files from there, and now we have ide_standalone then I'll be able to remove the feature from hh_server too, and those will be the last.)
