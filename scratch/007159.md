Summary:
We need a "tombstone" mechanism so that if (say)
1. the user deleted a.php
2. this is reflected in SymbolIndex's local delta
3. the user does a search for "Arachnid"
4. it's not found in the local delta, so we fall back to glean
5. glean finds it, in file a.php
6. TOMBSTONE: the glean result must be discarded because a.php has been tombstoned

Prior to this diff, the tombstones are stored as hashes, which were stored in the www.autocomplete glean database. However, www.hack.light doesn't store hashes; it only stores filenames.

I could have converted filenames to hashes. However there doesn't seem to be any point. I switched to using filenames as the tombstone key, rather than hash. It makes other bits of code easier, and more debuggable.
