Commit title: make definition a parameter, not RPC'd
Commit body:
Summary:
Everything centers around the fact that it's not meaningful to RPC a Relative_path.t between server and client. (because the two binaries have no reason to agree on the location of Hhi root).

It also makes for good hygiene: we know that `hh` command-line utility is an external-facing untrusted party which only ever deals with string pathnames, and there's a single point of transition where paths get validated and realpathed and converted into Relative_path.t, and then hh_server deals solely in Relative_path.t. (also, clientIdeDaemon deals in Relative_path.t)

See also D46239349 for a bug I had to fix where relative_path.t got converted to string and back again, losing information.

The way "rename" is written is confusing. It has an "action" structure with some fields "definition" and "filename_for_deprecated_wrapper" which both mention paths. It operates under the all-too-subtle invariant that those fields are always None when marshalling an action between hh_client and hh_server, but might be Some either for internal hh_server use (e.g. from go_ide to go) or clientIdeDaemon use.

So what I'm doing is cleaning it up. I'm going to make it so the action structure never contains paths. There'll be no confusion.

Why am I doing this now?
1. I rolled out ide_standalone
2. I therefore want to delete all the old IDE legacy code
3. including ServerCommandTypes.IDE_RENAME `hh --ide-rename`
4. but its replacement ServerCommandTypes.RENAME `hh --refactor` doesn't support deprecated-wrapper-generation. **But it should!** So I'll change it.
5. The mechanism for deprecated wrappers depends is currently implemented by passing Relative_path.t over the "action" structure. That's why it can't be supported in `hh --refactor` as is.
6. Therefore I have to change to a different mechanism!

My plan, therefore: "action" structure should solely be the vehicle for marshalling, and the places which need RelativePath.t should be communicated by other more appropriate means.

**What this diff does**: move "definition" so it's no longer communicated by the marshalled action structure, but instead is a parameter. (being a parameter it will necessarily not be marshalled!)
