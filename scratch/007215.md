Summary:
For an autocomplete like `$x = new Vec\f|`, what is the `query_text` which autocompleteService passes to SymbolIndex? What is the `context` (Acid/Acnew/...)?

This diff changes hh_single_complete to expose that information.

Previously,
1. `hh_single_complete --auto-complete a.php` would take file (or multifile) a.php, scan it for AUTO332, internally calculate the query_text and angle query, perform a glean search, and show results.
2. `hh_single_complete --glean-query a.prefixes` would take the file a.prefixes, treat each line as a `query_text`, show the angle query, perform a glean search, and show results.

After this diff,
1. `hh_single_complete --glean-query a.php` will also have the ability to take the file or multifile a.php, scan it for AUTO332, **display** *the `query_text` and `context` it figured out for that AUTO332*, display the angle query, perform a glean search, and display results.

In this way, we'll at last have solid observable statement about how autocompleteService synthesizes `query_text`, including how it deals with namespaces.
