Summary:
This diff adds telemetry to glean. I wanted to be able to answer questions like:
* how long do glean queries take?
* which queries are slower than others?
* do connection failures (or slow queries) correlate with age of the glean connection?
* how does hack.6 perf compare to hack.1 perf?
* should we decide to compare hack.www.light vs hack.www vs hack.www.incr, can we judge perf?
* for particular failures, can we use telemetry to debug them further?

**Glean connection** GLEAN_INIT, GLEAN_INIT_FAILURE. These events pre-existed and I'm changing what data is stored.
1. `glean_age`, the age of the previous glean connection (if any),
2. `glean_reponame`, which database we're connecting to
3. `data`, upon failure, full exception message+stack (therefore, trusting rust to produce a good failure when it calls `unwrap_ocaml` i.e. failwith, and faithfully recording everything it produces)

**Glean query** GLEAN_QUERY, GLEAN_QUERY_FAILURE. These events are new.
1. `glean_age`, the age of the current glean connection
2. `glean_reponame`, which database we're connecting to
3. `glean_mode`, what kind of query (Acid/Acnew/..., filter_kind for autocomplete+search, and action-kind for find-refs)
4. `time_taken_ms`, how long the query took
5. `data`, in case of >1s duration or glean failure, the full text of the query
6. `count`, in case of success, the number of results returned
7. `data`, upon failure, full exception message+stack

In case of reconnect events, they will be shown by (1) GLEAN_INIT has a non-null `glean_age` (representing the age of the previous connection), (2) a preceding GLEAN_QUERY_FAILURE.

The `rollout_flags` also says whether JK flag `glean_v2` is enabled. Its effect is to override the default/.hhconfig setting of glean_reponame to be "www.hack.light". It won't bring value to these GLEAN* events (since they already include reponame) but it will be useful for slicing+dicing the CLIENT_LSP_METHOD events.
