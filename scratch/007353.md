Commit title: Don't need Find_refs.ide_result
Commit body:
Summary:
```
module Find_refs = struct
  type server_result = (string * Pos.t) list
  type result = (string * Pos.absolute) list
  type ide_result = (string * Pos.absolute list) option
end
```
What do you think these three are for?

`server_result` -- this represents the result of doing a find-refs on a symbol like "Foo::bar". It uses Pos.t, hence Relative_path.t, and therefore cannot be shared across the hh_server/hh_client boundary, nor can it be printed. Each item is a SymbolOccurrence -- its text content, and its span.

`result` -- this is exactly the same as `server_result` but has been turned into Pos.absolute, hence string instead of Relative_path.t, and can be shared across the hh_server/hh_client boundary and can be printed.

`ide_result` -- this represents the result of doing find-refs on something like "a.php line 5 column 3". It might be that no symbol exists at the target location, in which case it returns None. Or there might be a symbol in which case it returns the fully qualified name of the symbol (hence different from SymbolOccurrence text content which isn't qualified), and a list of references to it. This one simply drops the text content of each SymbolOccurrence since the IDE never needs them.

Once we switched from IDE_FIND_REFS (takes file+line+col) to IDE_FIND_REFS_BY_SYMBOL (takes fully qualified name) then the "option" and "string fully-qualified-name" of `ide_result` became the wrong thing to return.

Therefore, this diff gets rid of `ide_result` entirely.

-------

Why am I doing this? -- I wish to implement streaming results for find-refs. I therefore wanted to write a single "FindRefsWireFormat" module in which I can put writing+reading code for the wire format. But I was baffled as to whether it should contain `ide_result` or `result`, indeed why they both even exist. This diff is part of my attempt to clean up.
