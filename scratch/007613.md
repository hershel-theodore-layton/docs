Commit title: use capi for inline py3 to_python conversion
Commit body:
Summary:
Motivation: On a prototype diff to migrate `//dsi/logger` to ligen and thrift-python, added `._to_python()` calls introduced a performance regression. Changing the generated `ThriftPy3Struct._to_python(self)` to call the `thrift-python-capi` `Constructor` completely mitigates this performance regression.

More generally, this can help any `thrift-py3` to `thrift-python` migration by preventing a performance regression during the intermediate stage where conversions happen at the boundaries.

The micro-benchmarks on the next diff show that serialization is more efficient than the current python reflection-based approach for most cases. Combined with marshal-based capi, the performance win is even greater.

The intention is that this will be enabled on the `thrift-py3` <-> `thrift-python` boundary to unblock migrations that would otherwise be blocked on performance. As the migration progresses, this is then disabled when `"py3"` is removed from thrift_library `languages`. The `"python_capi_converter"` options should be used with `"python_marshal_capi"` option for best results.

### Effect on build size

I did a quick check to see effect on build size with the opt-in.
- On trunk, the converter benchmark binary is 4.8 MB.
- with the diff, it’s 5.0 MB.

Command to repro:
```
buck2 build --show-output @//mode/opt-clang-thinlto //thrift/lib/python/benchmark:converter
ls -lh ~/fbsource/<output_path>
```
