Commit title: Fix/improve/cleanup async test namespacing and build targets
Commit body:
Summary:
Multiple fixes centered around making it easier to reuse test utilities outside of folly:

- **Namespacing:** Multiple utility header files did not have any namespacing, which causes naming conflicts and confusion when the header files are used elsewhere. Added `folly::test`namespace where appropriate. In parallel, added `using folly::test` and `using folly` to translation units where appropriate and removed test definitions from the namespace.
- **Targets:** Split up the `async_test` target into individual utility library and test targets. In parallel, resolved corresponding `BUCK` file issues which were preventing tests from running in xplat. All tests now run in xplat, although there appear to be xplat specific issues on some of them.
- **Cleanup:** Deleted unused function declarations and definitions in `AsyncSSLSocketTest.h` and `AsyncSSLSocketTest.cpp`. Renamed `TFOTest.h/.cpp` to `TFOUtil.h/.cpp` to make it clear that the files contain utilities and not actual tests. Split out some test components to `CallbackStateEnum.h/.cpp` and `ConnCallback.h/.cpp`.

There's still more to clean up, including:
- Changing `AsyncSocketTest` and `AsyncSSLSocketTest` so that they use the same set of connection callbacks (Connect, Read, etc.) for tests to avoid issues in cases where a test uses from both files. Some of this already had to be mitigated via `ConnCallback.h/.cpp`.
- Switching enums to to scoped (class) enums to reduce potential for naming conflicts
