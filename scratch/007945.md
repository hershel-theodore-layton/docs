Commit title: faster py `Enum` to int conversion + remove generated cython
Commit body:
Summary:
thrift-python generated enums inherit from `int`, so it's legal to call `PyLong_AsLong` directly on the object. This enables deletion of the cython (good for binary size), and it's faster: extract benchmarks are much faster, including in the pre-allocated enum case. I think this latter case is closer to what happens with static python.

The current way on trunk is bad because `Enum` is a regular python class, where `value` is a `property`, so calling `.value` is equivalent to a python method call. I tried returning `_fbthrift_value_` directly but no gain because it's not a `cdef` class member.

Another potential solution is making a `cdef EnumBase` class with `_fbthrift_value_` cdef'd, but that would add an additional base to the `Enum` metaclass situation, so it needs more thorough testing. Thus, I'd prefer to do this first.

Another issue with the current way is that it requires a cython module import, which may be relatively expensive if a function is called once from many different callsites (as opposed to being called in a loop, where only the first is expensive).

A secondary benefit is that putting in a bad type like a struct no longer raises `AttributeError`. Instead it raises `TypeError`, which is actually what we want.

Note that we are now extracting 1.5x faster for the case where enum instantiation included in benchmark (vs. 1.2x). When enum pre-instantiated, we are 1.1x faster (vs. 0.7x faster)
