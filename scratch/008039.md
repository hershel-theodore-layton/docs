Commit title: Fix readonly + ??=
Commit body:
Summary:
Null-coalesce assignment has a weird behavior in that it tries to preserve the bytecode stack between the the initial QueryM and (assuming null) the SetM.  But with a readonly op we were using a base of BaseC for the QueryM but a BaseL for the SetM - which resulted in a different stack size so when the SetM freed the stack slots it was freeing the wrong count.

I'm surprised that readonly w/ `??=` passes the typechecker in the first place and then I'm surprised it isn't an "always error"... but either way it shouldn't panic hackc.
