Commit title: Add strict switches: check for missing and redundant defaults
Commit body:
Summary:
Exhaustivity checking in Hack misses many cases (see [this post](https://fb.workplace.com/groups/hackforhiphop/permalink/24988113060810640/) or D47890092). This diff starts the implementation of a new strict switch behind, gated behind an option.

The diff has two main parts (a) calculating the disjunctive-normal-form set of values based on a given type (b) checking the cases and default against this type. It also includes some logging to aid debugging, which is gated behind another option.

a) For now, the only value defined is `Univ`, for "universe", meaning all values. Aside from `Tprim Tnoreturn` (which returns the empty set), all other types currently overapproximate the set of values a type represents by returning `singleton Univ`. Successive diffs will define more precise values and thus reduce this overapproximation.

b) At this stage, the only checks involve whether the switch neeeds a default, and whether it has one. If both are aligned, then there is nothing to do, otherwise there is an error: either missing or redundant defaults. At this stage, a redundant default would only be triggered by switching on an expression of type `noreturn`, which is prevented by other checks, so this part of the code will be expanded upon later.
