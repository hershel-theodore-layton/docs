Summary:
The IDE functionality+testing looks like this:
1. **clientLsp**, receives LSP messages, handles some stuff itself related to the LSP protocol, dispatches down a level for the actual work
   1. **test_lsp.py** is an end-to-end integration test at the LSP layer
2. **clientIdeDaemon**, handles open files, init, incremental changes, dispatches down a level for the actual work
   1. ---> **test/integration_ml/ide/**  <---- This diff introduces this test platform, as a way of testing clientIdeDaemon
3. **serverAutocomplete, serverIdentifyFunction, ...**, handles the actual logic usually by reading a TAST
   1. **hh_single_complete** is a CLI for testing serverAutocomplete and other things that need a symbol index
   2. **hh_single_type_check** is a CLI for testing serverIdentifyFunction, serverRename, and other things that don't need a symbol index

History:
1. Long ago, it used to be that all IDE functionality was handled by having nuclide shell-out to "hh --type-at-pos" and the like.
2. Around 2015 it was changed so all IDE is handled by a "persistent connection" to hh_server, and also error squiggles get delivered back to the IDE over that persistent connection. Then in 2017 we changed the protocol to be based on LSP.
3. In April 2020 it was changed so almost all IDE functionality was handled by clientIdeDaemon (an IDE-only process) and we left the hh_server persistent connection only to deal with rename, find-all-refs, and error squiggles.
https://fb.workplace.com/groups/321528938206999/posts/1091083671251514. In June 2023 it was changed so that rename and find-all-refs are handled by shelling out "hh --rename" and "hh --ide-find-refs-by-symbol", and current-file squiggles are done by clientIdeDaemon, and O(repo) squiggles are done by "tail -f errors.bin". At this point (like the long ago history), the IDE no longer has any tendrils into hh_server.

It used to be that "test/integration_ml/ide" was for testing IDE at the level of driving the hh_server persistent connection and seeing how it handled things. But now that's irrelevant! So this diff switches it to the morally equivalent thing: driving clientIdeDaemon and seeing how it handles things.

We do we bother testing at the level of clientIdeDaemon, when testing already exists at the level of clientLsp over the LSP protocol? -- it's because these tests are easier! they're pure ML, they don't have messaging loops or state machines, you can debug-step into them more easily and see callstacks that go all the way up to the test.

Plan of work:

3. D48938968 deletes other tests that used to make sense for hh_server persistent connection, but no longer make sense for clientIdeDaemon
4. D48939449 deletes the test-driver-code that used to drive the hh_server persistent connection
