Plan of work:
1. D48938946 introduces the ability to drive clientIdeDaemon from a test
2. D48938969 ports a load of tests from the old hh_server persistent connection over to clientIdeDaemon
3. D48938968 (this diff) deletes other tests that used to make sense for hh_server persistent connection, but no longer make sense for clientIdeDaemon
4. D48939449 deletes the test-driver-code that used to drive the hh_server persistent connection

See D48938946 for overview+explanation. See D48938969 for an explanation of the different "philosophy" between the old hh_server persistent-connection tests, and the new clientIdeDaemon tests.

There are some tests that just didn't make sense to port from hh_server to clientIdeDaemon, because they were tests for things that were inherently tied to the internals of the hh_server philosophy. This diff deletes them.
1. **error throttling** -- hh_server used to push O(repo) squiggles to the IDE, and had to truncate the list in case it was too huge. But clientIdeDaemon only ever pulls squiggles from the currently-open files in response to didOpen or didChange, and there's no need for truncating.
2. **exception_handling** -- this relates to what happens when the persistent connection gets broken. We no longer have a connection.
3. **hhi_phpstdlib** -- tests for hhi functionality have been moved to hh_single_complete, e.g. glean6.php, which does a complete end-to-end of autocomplete for those symbols
4. **ide_disk, check, redecl, status** -- all relating to hh_server's interplay of its state of truth reflecting IDE-open files rather than on-disk files; no longer relevant now that we have a simpler model
5. **typing_dels** -- relates to the fanout hh_server has to do for computing O(repo) squiggles based on IDE changes; now, hh_server only does that based on disk changes, and it's tested elsewhere. (no longer an IDE test)
