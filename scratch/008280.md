Commit title: Strict switch: add support for null/nullable type
Commit body:
Summary:
Exhaustivity checking in Hack misses many cases (see [this post](https://fb.workplace.com/groups/hackforhiphop/permalink/24988113060810640/) or D47890092). This diff continues the implementation of a new strict switch gated behind an option.

This diff adds support for nullable, null, nonnull and negative types respectively.

It does so by adding the `Null` to the `Value.t` variant, and then updating the subsequent code to:
* Safely over-approximate the symbolic `ValueSet` difference as `{ Other } - { Other } = { Other }`.
* Return `{ Null }` for `Tnull` and `Tvoid` .
* Use the symbolic difference for type `Tnonnull` and `Tneg (Neg_prim _)`.
* Safely over-approximate`Tneg (Neg_class _)` as `universe`.
* Check that types which require null have exactly one `null` literal case expression.
  - Count none/more than one null literal case expressions as missing/redundant case.
* Requiring a `default` if the computed set of values is non-empty and contains any non-finite (or dynamic) values.

**Design choices:** I could have check for cases of *type* null rather than the `null` literal expression. Ultimately I think case branches should only allow literals or class constants, and so error on non-literal expressions.
