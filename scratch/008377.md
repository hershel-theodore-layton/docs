Commit title: ide_idle
Commit body:
Summary:
There used to be an awful mechanism, `ServerEnv.ide_idle`, where if the IDE had sent any rpc, then hh_server would decline to do any typechecking until the IDE further sent an IDE_IDLE rpc. The goal was so that the server wouldn't embark upon a typecheck until after the user had stopped typing, since otherwise the typecheck would start and stop too much. It ended up being quite a fragile mechanism, because of the places where the client failed to send IDE_IDLE for whatever reason.

Anyway, we don't need this mechanism any longer: without a persistent connection, hh_server is no longer affected by (keyboard) typing, and it straightforwardly just kicks off a typecheck in response to disk-file changes.
