Commit title: python: intercompatible typing
Commit body:
Summary:
This diff introduces the concept of "compatible type":

Every struct/enum `Foo` in thrift-python will now inherit from a `_fbthrift_compatible_with_Foo` class,
and in all `__init__` and `__call__` functions where a `Foo` is expected, `_fbthrift_compatible_with_Foo` is now expected instead

This diff on its own won't affect user at all, as the only child class of `_fbthrift_compatible_with_Foo` is `Foo`, but in next diff (D49238208) I'll make py3 struct/enum `types.Foo` inherit from this `thrift_types._fbthrift_compatible_with_Foo` as well (when intercompatible option is on), that way we achieve intercompatible typing

In the future if we want to make `py-deprecated` intercompatible, we can let py-deprecated struct inherit from this class as well.

Note that this only changes `.pyi` file, so no runtime behavior change
