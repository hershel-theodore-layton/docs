Summary:
`hh --concatenate-all` hasn't been used for at least the past year https://fburl.com/scuba/scuba_hh_server_events/w8bh8ccu. I'm therefore deleting it.

I'm motivated to do this because I'm oncall, and the oncall hub says that test_concatenate_all is flakey during stress runs. https://www.internalfb.com/intern/test/281475069910296/
 {F1091428265}

The feature was introduced in https://github.com/facebook/hhvm/pull/8598 for the following goals:
* generating a single-file version of the HSL suitable for embedding [I don't know if this got anywhere]
* potential make_systemlib.sh replacement [but we still have make_systemlib.sh, so I guess this didn't happen]
* potential phar replacement [I don't know what this is]

Looking at the source code of the test, it looks like all instances of the test overwrite the same directory, which would be a cause of flakiness:
```
TEST_DIR="$(realpath "$(dirname "$0")")"
DATA_DIR="${TEST_DIR}/data/concat_all"
OUTPUT_DIR="${DATA_DIR}"
...
"${HH_CLIENT}" --concatenate-all no_ns*.hack > "${OUTPUT_DIR}/no_ns.hack.out"
"${HH_CLIENT}" --concatenate-all ns_body*.hack > "${OUTPUT_DIR}/ns_body.hack.out"
"${HH_CLIENT}" --concatenate-all ns_empty_body*.{hack,php} > "${OUTPUT_DIR}/ns_empty_body.hack.out"
```
If there are two separate instances of the test running, they might overwrite or race+interleave+overwrite each other's files.

I figured it was easier to delete the code than to fix the tests.
