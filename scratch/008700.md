Commit title: Remove unused onNetworkSwitch logic
Commit body:
Summary:
This logic does not appear to provide any value and is complicating the transition to using `QuicAsyncUDPSocketWrapper` in stack D48714615.

Today:
1. `HTTPSessionBase` defines virtual function `void onNetworkSwitch(std::unique_ptr<folly::AsyncUDPSocket>)`. The default implementation is empty.
2. `HQUpstreamSession` inherits from `HTTPSessionBase` and contains the only non-empty implementation of `onNetworkSwitch`.  It passes the socket off to `quic::QuicSocket::onNetworkSwitch`, which is a virtual function with a default empty implementation.
3. `quic::QuicClientTransport` (indirectly) inherits from `quic::QuicSocket` and contains the only non-empty implementation of  `quic::QuicSocket::onNetworkSwitch`. This implementation only takes action if the socket passed is non-null.
4. `SimpleSessionHolder::onNetworkSwitch` is the only invocation point of `HTTPSessionBase::onNetworkSwitch` and passes `nullptr` for the `std::unique_ptr<folly::AsyncUDPSocket>` parameter.
5. Given that a `nullptr` is passed for the socket in (4), (3) never takes any action. As a result, the only sequence in which there are invocations of this chain results in a no-op.

More generally, it's unclear what these codepaths are doing and why we need to route this state through the HTTP layer. Given this, deprecating the entire callpath.
