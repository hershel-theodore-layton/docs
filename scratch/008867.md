I added comments why this should never arise. It can only arise if the invariant is broken.

I observe that Max's transcript did exhibit a break of the invariant, `Invalid_argument("Lwt.wakeup_later")`. Specifically,
```
textDocument/references id 10
...
$/cancelRequest id 10
textDocument/references id 11
```
The handler for request id 11 suffered the Lwt.wakeup_later bug (fixed in the previous diff). In pseudocode, the handler was meant to do this:
1. unlink the file for request id 10 (succeeded)
2. send a SIGKILL to request id 10 (threw Lwt.wakeup_later exception)
3. replace current_hh_shell with None, or rather, a new different Some (it never got here, thanks to the exception)

Therefore when we subsequently heard that the shellout for id 10 had completed, and we tried to handle `next event: Shell_out_complete`, we discovered that current_hh_shell didn't have the file on disk that we expected!

I believe that the previous diff in the stack will make this problem go away. I'm submitting this diff to add documentations about the invariant.
