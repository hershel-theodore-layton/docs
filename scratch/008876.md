Summary:
It has long vexed me, when reading logs, that I don't see a timestamp of when it started right at the very top. Instead I have to scroll through all the configuration options that it read.

This diff prints an Hh_logger.log (hence with timestamp) right at the top of the log, for both monitor and server.

Conceptually it's strange that we're using Hh_logger.log before we've even read the config args, hence before we know the verbosity level. What if the user wanted a lower verbosity level that didn't include Hh_logger.log? ... well, at startup we already print all the config options anyway via Printf.eprintf, so I don't think this extra logging will hurt.
