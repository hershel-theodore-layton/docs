Summary:
Before D49804201, refineTmps did not look at types at all. It updated SSATmps
so that at any given point we would use the most recent available refinement
(any passthrough instruction), but did not attempt to make any assumptions
what a refinement is. In the end, you could always reach the original defining
instruction via these refinements from any updated source via any path. Types
would get broken during the refineTmps pass and it relied on reflowTypes() to
eventually fix them. There was also no attempt to track block reachability.

D49804201 started to interpret the output types of these refinements during
the execution of the pass. It would replace SSATmps from refinements with raw
constants whenever possible. These constants would then flow into the newly
created phis, making their source no longer trackable.

This becomes a problem if we do not properly track the types. Imagine the
following situation:

  B1:
    t1:{Str|InitNull} = ...
    t2:{Str} = CheckType<Str> t1:{Str|InitNull} -> ...
   -> B2

  B2:
    t3:{Str} = CheckType<Str> t1:{Str|InitNull} -> B4
   -> B3

  B3:
    Jmp t3:{Str} -> B6

  B4:
    t4:{InitNull} = CheckType<InitNull> t1:{Str|InitNull} -> ...
   -> B5

  B5:
    Jmp InitNull -> B6

  B6:
    t5:{Str|InitNull} = phi t3:{Str}B2, InitNull@B5
    t6:{Int} = LdStrLen t2:{Str}

Before D49804201, the pass would:
 - B1: map t1 to t2 (going to B2)
 - B2: use t2 in CheckType, then map t1 to t3 (going to B3)
 - B3: nothing
 - B4: use t2 in CheckType, then map t1 to t4 (going to B5)
 - B5: nothing
 - B6: schedule an additional phi of t3 and t4, then map t1 to that phi, then use that phi in LdStrLen
   - note that phi of t3 and t4 is Str|InitNull, so suddenly LdStrLen gets Str|InitNull input
 - reflowTypes() then updates t4 to a Bottom and a new phi to a Str, fixing the mess

However, D49804201 would replace mapping of t1 to InitNull in B4. The newly
scheduled phi will then be formed from t3 and InitNull, losing the ability of
reflowTypes() to fix its type.

The simplifyPass would eventually kill the dead code and remove the InitNull
phi source, but that's too late for a debug build, as checkEverything() would
already assert.

This diff adds a unit test to cover this situation. While this one is fixable,
D49804201 was reverted due to other issues.
