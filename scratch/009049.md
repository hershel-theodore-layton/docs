Commit title: Unhack t_function API
Commit body:
Summary:
* Now that streams and interactions are decoupled from return types, remove the vector of return types hack.
* Clarify in a comment that the return type is void even if it is omitted (implicit void) and when it can be omitted.
* Remove `set_return_type` and `set_response_pos` which are no longer needed since `t_function` is constructed with the correct return type that doesn't need patching.
* Don't override the return type for function declarations that establish a stream in `return_type`.
* Make `return_type` return `const type_ref&` because we decided to repurpose `t_type_ref` to provide source locations for types.
* Arrange `t_function` accessors in the order corresponding constructs appear in the grammar for easier navigation.
