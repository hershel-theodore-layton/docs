Commit title: use marshal for structs w/o cpp.Type, cpp.Adapter override
Commit body:
Summary:
If no `cpp.Type`, `cpp.Adapter` on fields, we can safely enable python_capi marshal by default for all structs.

For unions, have to fix NoLegacy annotation issue, so defer that for now.

__Effects__
- most thrift-python users: no change; they don't depend on `python_capi`
- ligen users, users of other entry points:
  - Binary size: marshal reduces the amount of cython generated compared to serialize mode. The reduced cython size overwhelms small increase in compiled C++ size. On one thrift-python artifact, building in `@//mode/opt`, enabling marshaling increases the C++ .a from 12K to 15K and reduces the cython .so from 535K to 384K, so net win.
  - Build speed: slightly slower, but still faster than `-cpp2-types` build.
  - DevX: don't have to waste time tracing down recursive deps and enabling with `"marshal_python_capi"` build option.
  - Perf: Marshal C API is 5-10x faster than serialization.
