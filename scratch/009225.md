Commit title: Introduce per-process unique request id
Commit body:
Summary:
HHVM didn't have a concept of unique request id. Instead, Logger used its own
request id that was unique per thread and APC relies on Treadmill generation
number to be unique.

This diff introduces request id stored in RequestInfo and propagates it to the
Logger whenever Logger previously bumped it.

Treadmill no longer gets request id from Logger, instead it gets a RequestInfo
pointer and obtains request id from there (it is used only for logging
purposes). This has a benefit of linking Treadmill state with RequestInfo
state, which might be useful for debugging, especially in lldb which has
trouble of obtaining thread locals.

Allows APC to be moved from Treadmill generation numbers to request ids.
