# Motivations

The  hack indexer doesn't use a  proper datatype to represent Glean facts.  It stores them as json value and lose typing information.

For instance, in this type
```
type fact_map = (Hh_json.json * Pos.t list) Fact_id.Map.t
```
We don't know what type of facts this actually represents.

The function that build facts  rely on naming conventions which we can't always easily relate to the schema. For instance, this build a "MethodDeclaration" fact.
```
val build_method_decl_nested : string -> string -> string -> Hh_json.json
```

Moreover Fact creation functions aren't type safe since they combine `Hh_json.json` facts to create new ones.

# This diff

* Adds a schema datatype in `symbol_glean_schema.ml` so we can decouple fact construction from json conversion.
* Gets rid of all `HH_json` use, except those in `symbol_glean_schema.ml`

This solves (almost) all above mentioned issues.

```
type fact_map = (Hh_json.json * Pos.t list) Fact_id.Map.t
```
becomes
```
type fact_map = (XRefTarget.t * Pos.t list) Fact_id.Map.t
```

Example of fact creation and json conversion

```
 DeclarationComment.(
      { declaration; file = File.Key path; span = ByteSpan.of_pos pos }
      |> to_json_key)
```

We don't need auxiliary functions to build facts anymore, the schema type constructors are clear enough and type safe.  This allows us to get rid of most of `Symbol_build_json`

This is very big diff. I gave up trying splitting it in smaller increments. I tried to limit the changes to use the new datatype. I trust the test plan for correctness.

# Next steps

I wrote the schema datatype manually, inspired by [flow gleanSchema.ml](https://fburl.com/code/yuvss6g2). Note that Flow indexer is simpler because it only uses nested facts while hack can also use fact ids within facts. Eventually, I'd like to generate automatically this datatype and use the generator for both hack and flow.

The translation pattern is consistent and could be automatized. There are a few minor exceptions, mostly specific constructors added for convenience.

There's an unfortunate limitation in the current schema. Fact ids aren't typed.  For instance, we don't know in what facts we can use the fact id returned by `indexerInputHash`.
```
val indexerInputsHash :
  string -> Md5.t list -> Fact_acc.t -> Fact_id.t * Fact_acc.t
```
We could probably use a phantom type (`Predicate_XXX.t Fact_id.t`) or use different fact_id types `Predicate_XXX.Fact_id.t`.

The bulk of the diff was making use of the new schema everywhere. I expect it to be comparatively simpler to iterate on this schema

There are many other potential improvements. For instance, we should be able to merge parts of `Symbol_predicate` with `Symbol_glean_schema` and remove the predicate type in the add_fact function. The `*json*` modules should be renamed too.

I leave that for a next iteration as this diff is big enough and is an improvement as it is.
