Commit title: RFC: ServerProgress: allow "stacking" of messages
Commit body:
Summary:
Before this diff, the server progress message would get stuck on `getting members of x/x classes` for a while. This is due to failing to update the progress message as we do stuff. I want the progress message to help us get a sense of what takes time. While it shows `doing x`, it should be "doing x".

With this diff, I allow stacking of messages. A new function `ServerProgress.with_message msg f` allows show `msg` while executing `f`. Once we're done executing `f`, the show back the previous message we were showing before calling `f`. This is implemented by using a stack of messages in `ServerProgress`.
I made is so that not all displaying of messages need to use `with_message`, i.e. we can still use `write` instead, to facilitate migration. See API doc for new functions `with_message` and `with_frame` for more details.

After this diff, we aren't stuck on `getting members of x/x classes` anymore but instead on `figuring out files to recheck`, which seem much more plausible.
