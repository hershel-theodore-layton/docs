Commit title: no longer allow multiple saved-state-types
Commit body:
Summary:
At the high point, we had four different kinds of saved-state:
```
hack/64
hack/64_distc
hack/naming
hack/shallow_decls
```

Did our team function better for having the possibility of so many different saved-state-types?

I think what we've discovered is that OD prep means that the same saved-state-type that's used by hh_server should also be used by IDE.

The recent move to compressed-depgraph was accomplished without a new saved-state-type.

I'm not sure that the move from 64 to 64_distc was best handled as a saved-state-type. It could have been a flag that changed the project name.

Catherine's rollout-flags now allow a different way to have different content in saved-states.

I wonder what nt591 and CatherineGasnier think -- do we still benefit from the code allowing different saved-state-types? Or is it time to simplify the code and hard-code only one?
