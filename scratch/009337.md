Commit title: Avoid UB in memcpy
Commit body:
Summary:
Some platforms annotate memcpy with nonnull.Folly assumes that the underlying memmove will handle a size of 0, which is not always true

The C standard, 7.24.1(2) says:
> Where an argument declared as size_t n specifies the length of the array for a function, n can have the value zero […] pointer arguments on such a call shall still have valid values, as described in 7.1.4.

Respect this by returning early when the size argument is zero.
