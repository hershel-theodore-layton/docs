Commit title: Specific reasons for like types
Commit body:
Summary:
For code that mixes implicit pessimisation and non-SD code, error messages are poor. For example,
```
<<__NoAutoDynamic>>
function expectInt(int $x):void { }

interface I {
  public function get(): int;
}

function testit(I $y):void {
  $z = $y->get();
  expectInt($z);
}
```
produces
```
Typing[4110] Invalid argument [1]
-> Expected int [2]
-> But got dynamic [3]

t.php:13:13
     3 |
     4 | <<__NoAutoDynamic>>
[2]  5 | function expectInt(int $x):void { }
     6 |
     7 | interface I {
[3]  8 |   public function get(): int;
     9 | }
    10 |
    11 | function testit(I $y):void {
    12 |   $z = $y->get();
[1] 13 |   expectInt($z);
    14 | }
```
There is no `dynamic` in the program!

We can easily improve matters by attaching specific reasons to the `dynamic` type that is added.
```
Typing[4110] Invalid argument [1]
-> Expected int [2]
-> But got dynamic because the type of this return is implicitly a like-type [3]
```
