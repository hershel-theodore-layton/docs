Summary:
Autocomplete works by constructing a modified version of the file with "AUTO332" at the caret location, then constructs a (normal,dynamic) TAST pair from it, then walks the normal TAST looking for whichever symbol has AUTO332 in it.
```
  let { Tast_provider.Compute_tast.tast; _ } =
    Tast_provider.compute_tast_quarantined ~ctx ~entry
  in
  let tast = tast.Tast_with_dynamic.under_normal_assumptions in
  (visitor ctx autocomplete_context sienv_ref naming_table tast)#go ctx tast;
```

Well, why did it even bother computing the dynamic TAST? This diff suppresses the dynamic-TAST-computation.

I also checked whether we need to suppress TAST checks? `Tast_provider.compute_tast_quarantined` internally uses `~mode:Compute_tast_only` which eventually becomes `Typing_toplevel.nast_to_tast ~do_tast_checks:false`. So autocomplete is already suppressing tast-checks as desired.
