Summary:
My goal for this diffstack is to redo the way ClientIdeIncremental, Provider_utils.quarantine and Provider_utils.invalidate work. (1) Users currently experience bugs due to them not invalidating the necessary decls. (2) They invalidate unnecessary decls, which I suspect hurts perf.

-----

The previous diff moved si_kind and si_addendum from search into FileInfo.ml. The goal was that they should become a lingua franca where many parts of the system (including low-level parts like Provider_utils) can operate upon these types. The final type I need to move is this:
```
  type changed_file_info = {
    path: Relative_path.t;
    old_file_info: FileInfo.t option;
    new_file_info: FileInfo.t option;
  }
```
The multithreaded rust indexer uses direct-decl-parser in each of its threads, and marshals into `new_file_info` which is easily transportable between threads. Then we gather `old_file_info` from the forward naming table. Together what we have is necessary and sufficient to describe a file change.

FileInfo.ml already includes some other types+functions which represent diffs between old and new FileInfo.t. So, moving this type in there as well isn't too big a shock.

While I'm here, I also created a type name for this in FileInfo.mli (previously it had simply been an Int64.t). We'll be using more of this type further up the diffstack.
```
(** a position-free hash of decls in the file, generated by [Direct_decl_parser.parse_and_hash_decls] *)
type pfh_hash = Int64.t
```
