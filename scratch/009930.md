Summary:
This diff is some cleanup work. Currently, when there's a file-change, Provider_utils exposes three entry-points, and the caller ClientIdeDaemon is expected to know what they do and use them right (which is tricky because some of them do the wrong thing!)
```
val invalidate_tast_cache_of_entry : Provider_context.entry -> unit

val invalidate_local_decl_caches_for_file :
  Provider_backend.local_memory -> FileInfo.t -> unit

val invalidate_local_decl_caches_for_entries :
  Provider_backend.local_memory -> Provider_context.entries -> unit
```
This diff encapsulates the caches by replacing those three with a single entrypoint, to be called upon disk change.
```
val invalidate_upon_change :
  ctx:Provider_context.t ->
  local_memory:Provider_backend.local_memory ->
  changes:FileInfo.change list ->
  entries:Provider_context.entries ->
  unit
```

Incidentally, the preceding diffs had moved the `change` datatype into FileInfo.ml. This diff is the first part of the payoff! ClientIdeDaemon is able to just pass `changes` straight over to Provider_utils without having to deconstruct it.
