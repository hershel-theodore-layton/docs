Summary:
This diff moves `Shallow_classes_provider.get_shallow_class` into `Decl_provider`.

The way Decl_provider is architected in three layers:
1. Decl_provider - the main API that people call. It is responsible for pessimisation, decl-telemetry, and (in the case of non-rust-provider) folding.
2. Decl_enforceability (pessimisation) and Decl_folded_class/Typing_classes_heap (folding)
3. Decl_provider_internals - this is the base layer for fetching raw decls via naming-table and direct-decl-parser

In this diff I had to decide: if someone called `Shallow_classes_provider.get_shallow_class`, what layer? The answer is, callers in pessimisation and folding call the internal `Decl_provider_internals.get_shallow_class`, and all other callers call the public API `Decl_provider.get_shallow_class`.
