Summary:
I'm updating the cancellation API slightly, allowing ocaml to (1) read whether cancellation is requested, (2) raise the WorkerCancel.Worker_exited exception if it is.
```
+val is_stop_requested : unit -> bool
+val raise_if_stop_requested : unit -> unit
 val stop_workers : unit -> unit
 val resume_workers : unit -> unit
```
Previously, `raise_if_stop_requested` was only accessible from code in hh_shared.c where it was called on every single decl-fetch or decl-store. And `is_stop_requested` wasn't exposed.

Why am I doing this? Because my goal is that the IDE should be able to interrupt requests and typechecks rather than waiting until they're done. Previously we used to support this in hh_server by having that "raise_if_stop_requested" be called on decl shmem access in hh_shared.c. But that fell by the wayside with our move to a rust naming table, and in any case the IDE doesn't use sharedmem decls.

I therefore intend to move the checks into ocaml land, to place `WorkerCancel.raise_if_stop_requested` in a few key places in inner loops. That's what this diff supports.

Oh, I also made a behavioral change. Previously if someone called `raise_if_stop_requested` from hh_shared.c but they hadn't initialized shmem then it raised an ocaml failwith, telling them to initialize shmem. I had two choices:
1. Change every single test which uses typechecking (hence `WorkerCancel.raise_if_stop_requested`) to initialize shmem before starting
2. Change the behavior of `WorkerCancel.raise_if_stop_requested` so that it no longer does failwith, and instead simply returns if no one has requested cancellation (which, if they haven't connected to shmem, then they obviously can't!)

I picked the second option because the first was too irritating.
