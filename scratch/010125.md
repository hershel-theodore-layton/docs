Summary:
I'm working on supporting immediate VSCode-triggered cancellation. The cancellation technique I plan to use is just re-using the existing hh_shared.c "cancel bit", where a master process sets the bit in shmem, and worker processes poll the bit frequently to decide whether to abort.

This is just a single bit. It naturally can't support multiple concurrent requests -- after all, if two requests are ongoing, and we want one of them to be cancelled, how would workers know which one to cancel?

Our codebase already only has a single request to ClientIdeDaemon at a time so this is fine. But in the absence of a linear type system, I can't see any way for our Lwt.t-based API to express this. Instead, in this diff, I add a HackEventLogger.invariant_violation_bug to get telemetrical proof that there's only ever a single request ongoing at a time.

Actually, reading through the code, I found only one exception, one place where multiple requests at a time might be triggered. In this diff I changed it to only have a single request at a time.
