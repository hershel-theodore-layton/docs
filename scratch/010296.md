Commit title: Time based `distributed_mutex::spin`
Commit body:
Summary:
`pause` instruction might have a different latency on different
microarchitectures. Below is a cite from Intel 64 and IA-32 Architectures
Optimization Reference Manual (sec. 2.6.4 Pause Latency in Skylake Client
Microarchitecture):

> The latency of the PAUSE instruction in prior generation microarchitectures
> is about 10 cycles, whereas in Skylake Client microarchitecture it has been
> extended to as many as 140 cycles.

Let's use dynamic pause loop, based on time instead number of iterations, to
spin for approximately the same time on different microarchitectures.

Time to spin was determined experimentally via benchmark code.

```
BENCHMARK(PauseLoopRdtscIters, iters) {
  while (--iters) {
    std::uint64_t spins = 0;
    while (++spins < 4000) {
      const auto current = folly::hardware_timestamp();
      folly::doNotOptimizeAway(current);
      folly::asm_volatile_pause();
    }
  }
}

BENCHMARK(PauseLoopRdtscTimeOneIter, iters) {
  while (--iters) {
    const auto current = folly::hardware_timestamp();
    folly::doNotOptimizeAway(current);
    folly::asm_volatile_pause();
  }
}
```

Output of the benchmark is the following.

```
============================================================================
[...]nization/test/SmallLocksBenchmark.cpp     relative  time/iter   iters/s
============================================================================
PauseLoopRdtscIters                                       205.96us     4.86K
PauseLoopRdtscTimeOneIter                                  44.44ns    22.50M
```

So, `spin` time should be somewhere between 177 us (44.44 ns * 4000 iterations
~ 177760.0 us ~ 177.76 us) and 205.96 us.
