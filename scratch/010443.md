Summary:
This diff makes `getThreadIdCollector()` (as implemented in `IOThreadPoolExecutor`) part of a dedicated interface and implements it in `EventBase`, so we can use it in `IOThreadPoolDeadlockDetectorObserver` instead of the current solution which is very coupled with the internals of `IOThreadPoolExecutor`.

The behavior is optional so it adds no overhead when not used and almost negligible overhead when enabled (a custom implementation of `ThreadIdCollector` was added to avoid locking in loop setup/cleanup, which `ThreadIdWorkerProvider` would do)
