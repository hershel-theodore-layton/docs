Commit title: Fix handling of forward references to constants
Commit body:
Summary:
The Thrift compiler currently treats unresolved identifiers in initializers as strings. Apart from being obviously wrong, this has practical implications. For example, it is impossible to distinguish the following two cases:

```
enum E {}
const list<E> c = [nonexistent.Value];
```
and
```
enum E {}
const list<E> c = ["nonexistent.Value"];
```
and provide a good diagnostic.

Get rid of this hack by representing an unresolved identifier explicitly in the AST and fix the diagnostic for

```
enum E {}
const list<E> c = [nonexistent.Value];
```
Before:
```
string is incompatible with `E`
```
After:
```
use of undeclared identifier 'nonexistent.Value'
```

Remove a noisy warning about using constants before they are defined. We already support this and don't emit such warning in other similar (and more complex) cases such as types.
