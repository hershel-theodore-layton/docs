Commit title: much faster "indexing" for repos where watchman root != hhconfig root
Commit body:
Summary:
Why is "hh --no-load" so slow at "indexing..." in some checkouts vs others? (Confusingly, "indexing" is when we ask watchman for a list of all files in the repo, and "parsing" is when we index those files into a naming table).

This diff fixes it. It boils down to the difference between these two
```
# Previously we did this
time watchman -j <<< '["query","/data/users/ljw/fbsource",{"fields":["name"],"expression":["allof",["anyof",["dirname","fbcode/hphp/hack/test/integration/data/simple_repo"],["name","fbcode/hphp/hack/test/integration/data/simple_repo"]],"exists",["type","f"],["anyof",["name",".hhconfig"],["suffix","php"]]]}]'

# This diff makes us do this
time watchman -j <<< '["query","/data/users/ljw/fbsource",{"fields":["name"],"expression":["allof",["dirname","fbcode/hphp/hack/test/integration/data/simple_repo"],"exists",["type","f"],["anyof",["name",".hhconfig"],["suffix","php"]]]}]'
```
The difference is that the slower previous behavior had to do an O(repo) search for every single file that matches the "name" predicate.

The poor watchman query used to be skipped in places where the .hhconfig project root was identical to the watchman watch root, hence okay for www. But it was run whenever the two were different, e.g. fbsource/fbcode/hphp/hack/test/integration/data/simple_repo and fbsource/www. With this diff, I expect the latter two will be faster.
