Summary:
This stack addresses a few issues:

**1** Currently, we have the builtin return type deduction as follows:
https://www.internalfb.com/code/fbsource/[8e9bcbcb6fbaf704629484c40f6046f4360eac74]/fbcode/hphp/runtime/vm/jit/irgen-builtin.cpp?lines=1946-1948

This causes everything to narrow down to `asSystemlibType`, which means that any composite types will be pessimized to InitCell. For example,
`(1851)t374:InitCell=CallBuiltin<-17,HH\array_key_cast>t2:FramePtr,t3:StkPtr,t373:PtrToFrame => B512<Catch>`

Here `HH\array_key_cast` returns 'Str|Int' but we pessimize it to initcell.

**2** All the reference types returned by builtins are assumed to be nullable, which causes us to add extra code in `cgCallBuilin` to first check if the data is null, and then conditionally move the type either to Null or to the exact ref type as shown below.

https://www.internalfb.com/code/fbsource/[e8528af8a08342e082841ab0bdaa17fcd56e953b]/fbcode/hphp/runtime/vm/jit/irlower-call.cpp?lines=407-415

So, in this stack we'll introduce nonNullable ref types such as StringRet, ArrayRet and ObjectRet. This will also unblock future cases where we want non nullable ref types

**This diff** modify the func emitter code to add a new flag that will tell the irlower that this function returns a non nullable reference type
