Commit title: Standardize TokenBucket::available(), add balance()
Commit body:
Summary:
`TokenBucket::available` and `DynamicTokenBucket::available` return a value >=0. More specifically, if the token bucket is in debt (has negative balance of tokens), `available` returns 0.

However, both of these functions call `TokenBucketStorage::available` under the hood, and the comment for that function makes it clear that it was designed to return a negative number if the token bucket is in debt:

> Returns the number of tokens currently available. This could be negative (if in debt); will be a most burstSize.

This creates a few problems:
1. It's easy to misread `TokenBucket.h` and assume that `TokenBucket::available` will return a negative number if the token bucket is in debt. This is due to the nesting, but also because `TokenBucketStorage::available` specifically states it will return a negative number when the token bucket is in debt, while `TokenBucket::available` and  `DynamicTokenBucket::available` use`std::max` to ensure the value returned is always >=0.
2. There's no way to get the current token bucket balance, since the accessor functions exposed through the user-facing classes don't support it.

This diff solves these problems as follows:
1. Renames `TokenBucketStorage::available` to `TokenBucketStorage::balance` so that it is clear that it returns the current balance in the token bucket, and improves comments.
2. Adds `TokenBucket::balance` and `DynamicTokenBucket::balance`, both of which do not perform any transformation on the signal returned by `TokenBucketStorage::balance`, and thus can be used to determine the current balance when the token bucket is in debt
3. Improves commenting and adds a typed-parameterized test to verify functionality
