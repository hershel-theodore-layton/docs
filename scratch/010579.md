Commit title: lfu_cache not use polymorphic compare
Commit body:
Summary:
https://blog.janestreet.com/the-perils-of-polymorphic-compare/ "when I think of things to do to optimize an OCaml program, one of the first things on the list is to stamp out unnecessary invocations of compare_val [i.e. polymorphic compare]"

`lfu_cache` is what we use to cache the 10s of thousands of decls needed in ClientLsp to typecheck files. It's currently backed by `Hashtbl.Poly.create ()` which uses polymorphic compare. This diff changes it to `Hashtbl.create ~size:max_size (module KeyWrapper)`

1. I'm explicitly providing the compare function to use, via `module KeyWrapper`
2. Many years ago we had thought to cap the cache by size in bytes of its entries, using `reachable_words`. But this is a slow thing for debugging, and should not be used in production, so we removed it. There are a few vestigial `get_size` functions left over from that era which aren't currently used. This diff removes them.
3. Left over from those days, in tests we previously initialized the shallow decl cache to size `140 * 1024 * 1024` = 146,800,640. That made sense if size referred to number of bytes, but it actually refers to count of elements. This is a ludicrous size. I bumped it down for tests to 20,000. This number is based on my observation that EntBusinessUser.php (a horribly demanding file) needs 75k shallow decls, and ChessBot.php (a modest file) needs 25k shallow decls. I think more tuning can be done, but this is a start. Meanwhile, for production use, it's set by JK `ide_max_num_shallow_decls` at 10,000.
