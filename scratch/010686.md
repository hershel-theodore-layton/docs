Commit title: "Unresolve" type-constraints of missing classes during init-types pass
Commit body:
Summary:
During flatten classes, if a type-constraint refers to a class and
that class is not known to be missing, we go ahead and resolve the
type-constraint to SubObject of that class. However, we might later
learn that that class is uninstantiable (or missing). Add logic to the
init-types pass to "unresolve" any such type-constraint back to
Unresolved. This avoids having resolved type-constraints referring to
non-existant classes.
