Commit body:
Summary: This diff proposes to add a global option to select if `fb_intercept2` is implemented with surprise flags (the current behaviour) or with instruction smashing (the "fast" behaviour).   Both implementation are kept in the codebase, so we can rollback to the surprise-flag based implementation if problems arise during the rollout of the fast `fb_intercept2`.  Also, the flag might give flexibility to measure the perf impact of the fast `fb_intercept2`.
