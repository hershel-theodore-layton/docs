# Context

This diff creates a new library `folly_dynamic` in `thrift/lib/cpp2` that provides a way to convert Thrift
structs to and from `folly::dynamic` objects. The library is designed to be lightweight and efficient, and it is intended to be used in conjunction with other Thrift libraries **without** old reflection.

# Implementation notes and possible improvements

- Just like old version, current version doesn't have a support for adapters. It will be published in the next diff separately.
- Tests are not changed so that not to include fatal headers at all. This will be changed in the next diffs as well.
- Due to how library is designed to propagate the references to Thrift object, I couldn't find a way to "ensure" field and obtain its mutable reference to propagate further (case of `std::shared_ptr<const T>`). Instead, I created a new shared pointer with empty object, will `const_cast` be a considerable safe solution?
- To preserve the old behaviour, we required a cleared object to be passed in `from_dynamic` API and additionally cleared empty unions in there

- At present, there is no API to get union/struct field based on string name (that's [why](https://www.internalfb.com/intern/staticdocs/thrift/docs/fb/languages/cpp/reflection/#why-do-we-need-ident)), so these types are handled differently in a new model. As for struct case, the loop iterates through all fields and tries to find each field in a dynamic map. As for union case, the loop iterates through all fields until matches with a single dynamic name.

- Currently, `to_dynamic` sets "nullptr" for all non-optional non-set reference fields and this behaviour remains compatible, hence this else branch:

```
else if (!apache::thrift::detail::is_optional_or_union_field_ref_v<
                   apache::thrift::op::get_field_ref<Struct, Id>>) {
      out[fieldName] = nullptr;
}
```

- Lastly, namespace changed from `apache::thrift` to `facebook::thrift` in order to avoid collision during future migration

- I hope everything else is clear!
