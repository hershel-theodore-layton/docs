Commit title: suppress violations of warning deprecated-declarations
Commit body:
Summary:
The nested-name lock-holders in `SharedMutex` have lock-transition converting constructors, where they name each other. Since each lock-holder type is marked `[[deprecated]]`, each lock-transition constructor necessarily violates warning `deprecated-declarations`. But the ensuing warnings which the compiler may emit for these violations are not actionable - so we suppress them.

Internal;
The `nettools_ebb_arista_eos` build is broken, with blame to {D52371884}. This fixes that breakage.

The `mode/arista-mel` mode must somehow enable `-Werror=deprecated-declarations` after the base mode has already suppressed it, or otherwise must not suppress it. It may be worthwhile to investigate this further.
