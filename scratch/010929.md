Commit title: Add support for immutable settings
Commit body:
Summary:
* Adds support for `FOLLY_SETTING_DEFINE_IMMUTABLE(project, ...)` which can't be `set` or `reset` after `freezeImmutables({project})` has been called
* These can be useful for:
  * Documentation if the setting is only read during startup
  * To enforce that the setting value is the same for the lifetime of the process (ex: if read twice during the same request and we assume the value is the same both times)
* `freezeImmutables` only freezes a set of setting projects (instead of all of them) to support folly setting usages in libraries which are pulled into services that also use folly settings. See [this doc](https://docs.google.com/document/d/197nH5YD-NPKihAE6a89nnArW51Q2pS-TOZnSReXIuAU/edit?usp=sharing) for more details
