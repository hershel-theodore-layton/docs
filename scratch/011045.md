Commit title: Add count of total element wrappers allocated for a StaticMeta
Commit body:
Summary:
ThreadLocal implementation uses a per thread array of ElementWrappers
to track each instance of the ThreadLocal object created using the same tag
(same underlying StaticMeta object). In cases where there are lots of threads
and lots of thread locals, the arrays can end up being very sparse when each
thread is only using a small subset of the thread locals.

The diff adds a tracking counter on total elements allocated across all
threads. It can be used to surface the cost and consider whether alternate
approaches are worth considering: Trade off access speed for lower overhead by
using map per thread or shrinking ElementWrapper to not have list of threads
that use that variable or building true core-local support for stat objects
that use a lot of thread locals otherwise.

(Note: this ignores all push blocking failures!)
