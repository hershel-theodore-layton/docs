Commit title: Report hphp_cmd stdout+stderr when running repo mode tests
Commit body:
Summary:
The test runner merges `exec`'s stdout and stderr
https://www.internalfb.com/code/fbsource/[57142e69a236ee36cf73a09fb06f9bcfcae81618]/fbcode/hphp/test/run.php?lines=1198-1202

which means that `exec_with_cmd` gets stderr like `Possible bad config node: AllVolatile` in the `$output` of its return tuple. For repo mode tests, this is only reported to the user if the hphp cmd's `$success` is false, and is discarded otherwise.

The result is that most tests lack signal when a flag is mistyped for .hphp_opts e.g. `-vEval.*` vs `-vRuntime.Eval.*`. You have to manually make the test fail first e.g. by appending garbage to the .expect file, then run the repro commands to see the bad config node error.

This change retains the output of hphp_cmd + hhbbc_cmd and prepends them to the test output. This caused some tests to fail in repo mode, mostly complete output here: P1048286288; see test plan for more.
