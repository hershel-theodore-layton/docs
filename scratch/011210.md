Commit title: Avoid 1 move constructor and 1 destructor per element when parsing list for parseValue
Commit body:
Summary:
The optimization affects parsing small primitive elements that is expensive to move around since move is as expensive as copy.

Previously `SmallListInt` was ~7.6x slower, not it's ~4.6x slower parsing small list of integer , which is ~60% improvement.

Previously `BigListInt` was ~8.9x slower, not it's ~4.5x slower parsing small list of integer , which is x2 improvement.

Per each element:
Previous: default construct + move construct + one destruct
now: default construct
