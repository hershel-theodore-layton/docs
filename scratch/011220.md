Commit title: Have makeTFM clear the TFM header
Commit body:
Summary:
**Internal:** WWW has no concept of folly::RequestContext where `ThriftFrameworkMetadata` can be stored, so it uses a global singleton `ThriftContextPropState` to manage the TFM state instead.

Because WWW hosts communicate over HTTP, the thrift context (both TFM and TFM OnResponse) is transported as part of request/response headers, so when we consume incoming TFMs we first search the [headers](https://www.internalfb.com/code/fbsource/[772787b7567b]/fbcode/thrift/lib/cpp2/transport/core/ThriftRequest.cpp?lines=87), then look at the attached framework metadata Thrift structure.

However this workaround is causing a bug because on outgoing requests when we call the respective `makeThriftFrameworkMetadata` method to produce the TFM, we don't update the header value, so if the TFM structure is updated at any point during a hop, the TFM value in the headers could become stale, then get propagated. The host on the receiving end will then ingest the stale TFM header as we prefer header TFMs over the internal representation.

This diff fixes that behavior by having the make method remove the TFM header from the incoming/outgoing headers. I gated this behavior with a Thrift flag.
