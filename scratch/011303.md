Commit body:
Summary:
- Make one place for all config definitions
  - /hphp/doc/configs.specification
- Make it possible to namespace things so not everyone just put everything in Eval
- Each namespace gets its own header file so files can include the namespace they care about instead of all of runtime-option.h
  - Also the generated header files don't contain any default values or implementation so changing the default does not recompile the world
- Only one place to configure even if it should be part of repooptionsflags, globaldata or unitcacheflags.
- Will later be used for to get validation rules that we can use for validating hdf files.
- I'm open to other name suggestions than `Configs` and `Configs::Namespace::`. Currently `Configs::Namespace::Foo` is shorter than `RuntimeOption::NamespaceFoo` but longer than `RO::NamespaceFoo`. We could add `C::Namespace::Foo` to make it just one character longer than the RO version.
