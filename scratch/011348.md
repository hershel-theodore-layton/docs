Commit title: Count spinners as waiters in ThrottledLifoSem
Commit body:
Summary:
`ThrottledLifoSem` currently doesn't count spinning waiters in the number of waiters, so a post may start a waking chain even if there is a waiter that can immediately consume it. This was done to avoid one state operation in the case where the value is positive, and because the spin time is usually short it does not matter too much.

This however can be counter-intuitive if setting a large spin time. Thus change the behavior to count spinners as well, and have an explicit fast path for the positive value case.
