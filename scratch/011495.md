Commit title: Move targets shared by hh_client and hh_server from src/server to src/client_and_server
Commit body:
Summary:
## What

We have a bunch of targets in //hphp/hack/src/server that are included in both the hh_client and hh_server binaries. Put them in a dedicated directory.

This change enables us to, later in the stack (D53353242), ensure that `hh_client` doesn't depend on anything in `//hphp/hack/src/server/...`. Which is pretty cool.

## Why

- The status quo was so confusing! When I write or review code, I'd like to know which binary it is running in
- I strongly suspect we don't need lots of IDE functionality in both hh_client and hh_server. Having extra code slows down build times. This change at least gives us better visibility into where some of the weird dependency paths are.

## How did we get here?

Here's my best guess about how `hh_client` ended up depending on stuff in `//hphp/hack/src/server`:
-  dependencies left over from the serverless IDE work (where logic moved from the server to the client)
    - This includes weird stuff we can't get rid of: --xhp-autocomplete-snippet is an untested "temporary hack" that is really hard to remove from hh_server (I tried: D53267616). It makes hh_server depend transitively on Glean.
- dependencies used for communicating between client and server. `serverProgress.ml` is an example, iuc.
- time
