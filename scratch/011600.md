Summary:
## What

Provide a way to disable the dependency on hh_distc.

With this change, we now have a way to build hh_server with buck2 that is faster than building with dune. Even though the buck2 build is pulling in *more* fb dependencies than the dune build (everything except hh_distc).

dev:

```
buck2 build \
    @//mode/dev-nosan-lg \
    -c hack.distc=0  \
    //hphp/hack/src:hh_server
```

release:

```
buck2 build \
    @//mode/opt-clang \
    -c hack.distc=0 \
    //hphp/hack/src:hh_server`
```

## Design

Why not skip all fb dependencies?
- Not even our dune builds do that! Some dune stubs are always used, and some are only used for open-source. [Here's an example where `rage` is used for internal builds only]
- Most of our fb dependencies are small and have few dependencies
- Skipping a dependency and falling back to something that no-ops or throws can make things harder to debug and/or increase the ways things can break during development.
- Here are dune stubs that are always used: P1181597960, and here are dune stubs that are used only in open-source builds: P1181597714

Which fb dependencies should be skippable?
- based on [unigraph](https://www.internalfb.com/unigraph/explorer?GraphPluginOptionsAtom=%7B%22fbsource%22%3A%7B%22excludes%22%3A%7B%22fromLeft%22%3A%5B%5D%2C%22fromRight%22%3A%5B%5D%7D%2C%22excludesTransitive%22%3A%7B%22fromLeft%22%3A%5B%5D%2C%22fromRight%22%3A%5B%5D%7D%2C%22excludesByNameMatch%22%3A%7B%22fromLeft%22%3A%5B%5D%2C%22fromRight%22%3A%5B%5D%7D%2C%22showTotalConjointCost%22%3Atrue%7D%7D&graphQueryKey=%22GQK3aac75e40b00a1d5bbfec98a89d11b9d9fbc4ad0ab050fd81acc818b5c2524c9%22&selectedPath=%5B18077001%5D), hh_distc_ffi, justknobs, and glean have a lot of dependencies. What to do about this:
    - We add a flag to skip the JustKnobs dependency in D53475601. Building and linking-in JustKnobs only costs 1-2 seconds of build time, but might as well provide the option to skip it.
    - The glean dependency for hh_server is unfortunately very hard to extricate due to a "quick hack" for Bloks that we are stuck with until/unless there is better editor support for XHP required attributes. See discussion on D53267616. The "quick hack" has zero tests and is pretty messy it, we should stop doing stuff like that. Bloks team may stop relying on this feature this year, so there's hope we can remove at some point.
