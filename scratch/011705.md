Commit title: Provide the "extract into variable" refactoring even in braceless lambdas
Commit body:
Summary:
## What

Provide the "Extract into variable" refactoring for code inside bracless lambdas (Example: `() ==> 3 + /*range-start*/5 + 2/*range-end*/`). Before we did not provide the refactoring in such cases because the logic for doing so is kind of fiddly.

https://pxl.cl/4lvF4

## Why now

- Removes a blocker for adapting the "Extract into variable" refactoring as a quickfix for the hard-to-action "`await` cannot be used as an expression in this location because it's conditionally executed" error: {D53757680}
- Several users asked why the "Extract into variable" refactoring wasn't available in cases like this. The behavior was confusing.

## Notes on snapshot tests

You'll see the following changes:
- Main change: we provide the "Extract into variable" refactoring in cases where we previously did not. The tests introduced in {D53756767} are all updated: see `inline_variable_in_bracless_lambda_*.php.exp`.
- Some code actions now look different at the LSP protocol level, but applying the code action produces the same code. This is because we now represent that "Extract into variable" refactoring as a single big edit rather than several small edits. It was easier to implement this way and afaict makes no user-perceptible difference.
- Our tests for unrelated refactorings now record that the "Extract into variable" refactoring is available in more places.
