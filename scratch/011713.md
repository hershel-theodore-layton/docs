Commit title: Prevent overflow evaluating UnwindSafe autotraits during doc build
Commit body:
Summary:
Fbcode rustdoc builds are crashing with OOM since around the time of the Rust 1.75 update. I believe the root cause is as follows:

- Rustdoc in 1.75 performs more type-checking than it used to in previous Rust versions.
- There is a large library target whose doc build is failing in Remote Execution due to the new checks.
- Normally a single failed target would not bring down the whole rustdoc job. Documentation would still be built and published for all other targets.
- However, it's going wrong in this case because the failing target is so large (skynet). After the failed RE action, Buck's hybrid execution then falls back to locally rerun the action to verify the failure locally. Ordinarily the local action would fail the same way as the remote one and things would move on. However, the large skynet library is too big for rustdoc to run in parallel with the Buck daemon responsible for all the rest of the remote actions, and this leads to an OOM which brings down the whole job.
