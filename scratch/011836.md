Summary:
We avoid adding superfluous parentheses around`await`s introduced by our refactor/quickfix.

Examples in the video:

 https://pxl.cl/4nF0M

See test cases for more examples.

## Implementation Alternatives Considered

- Always wrapping "await" expressions in parentheses and then using `Libhackfmt` to remove the extra parentheses.
   - This doesn't work because hackfmt does not remove extra parentheses. I discussed with a few teammates whether it should. Such a change would be a high cost and probably low or negative benefit. It's a bit subjective what "superfluous" means as sometimes extra parentheses help for clarity. And cost is high because we have a lot of operators, a lot of precedence rules, and hackfmt uses the concrete syntax tree. And `(int)` and `int` are different types (as madgen pointed out).
- Using Full_fidelity_rewriter. I don't think this approach isn't viable because afaict there is no way to tell Full_fidelity_rewriter "keep going": you must tell it how to replace every node in the AST. I considered updating the API, but we already have a ton of different kinds of rewriters, I don't want to add more. Or touch too much Full_fidelity_x stuff.
