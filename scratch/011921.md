# Current Implementation
In the current production, we're currently using `__builtin_ctzll(_pext_u64(a, 0x8080808080808080ULL) + 1) + 1` to calculate num of valid bytes. In a bit more details, it follows these steps:
1. extract continuation bits: `b = _pext_u64(a, 0x8080808080808080ULL)`
2. count number of tailing 1 in continuation bits: `c = __builtin_ctzll(b + 1)`
3. include the highest byte whose continuation bits is zero: `c + 1`

# Optimization (avoid one `_pext_u64` call, 3-18 CPU cycle reduction per [wiki](https://en.wikipedia.org/wiki/X86_Bit_manipulation_instruction_set#Parallel_bit_deposit_and_extract))

We should be able to compute the result without _pext_u64 calls by replacing it with `__builtin_ctzll((bits & 0x8080808080808080ULL) ^ 0x8080808080808080ULL) / 8 + 1`, the high-level steps become:
1) only keep the continuation bits: `b = a & 0x8080808080808080ULL`
2. toggle the continuation bits (for tailing 0 counting): `c = b ^ 0x8080808080808080ULL`
3. count number of tailing 0: `d = __builtin_ctzll(c)`
   **NOTE**: As `d` included data bits, the results would be 8 times of tailing 1s in continuation bits
4. the final valid bytes would be: `(d >> 3) + 1`
