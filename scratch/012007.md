Commit title: Add support for configurable spinning in MuxIOThreadPoolExecutor
Commit body:
Summary:
In `MuxIOThreadPoolExecutor` one evb wake-up can turn into 3 wake-ups: poller, then worker thread, then again poller to rearm the fd. This should not happen if the poller has enough work to do, but we can reduce the overhead on very quick round-trips by spinning a bit on both sides. Since spinning can be done without syscalls with `io_uring`, default backend was switched.

Also added an optional sleep to further force batching.
