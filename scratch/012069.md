Summary:
D54000838 updated the "displayString" fields to use the new pretty-printer. This diff migrates the other type/context fields to use the same pretty-printer and gets rid of the old one. I also precise the expected format

```
# Type and contexts are represented as strings.
# Qualified names use "\\" as separator, don't start with a leading "\\".
# The most common types don't start with HH https://fburl.com/code/uavv841q
#
# Example: fully qualified name -> representation in DB
# \\HH\\Contexts\\throws<\\FooException> -> HH\\Contexts\\throws<FooException>
# \\HH\\Awaitable -> Awaitable
# \\HH\\Contexts\\defaults -> HH\\Contexts\\defaults
# \\HH\\Traversable -> Traversable
```

Motivation:
- Improve the pretty printing of functions signatures in codehub (see linked task). D54000838 only addressed part of the signatures - the type parameters, and the return type,  but not the context and type parameters
- Simplify the code with only one well-understood representation. Eventually, we can turn this pretty-printing into a proper indexer for types.

A possible issue is that there might be existing clients which rely on the actual string representation which will be slightly changed by this diff, mainly the qualified names formatting. Alternatively, we could always generate  fully qualified names (e.g. \\HH\\Contexts\\throws<\\FooException>), this would minimize risk of break clients, but we would need to adapt codehub to perform the strip ns part (done https://fburl.com/code/uavv841q)
