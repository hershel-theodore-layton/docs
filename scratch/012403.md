Commit title: Introduce ThreadPoolExecutor::TaskObserver
Commit body:
Summary:
This diff serves 4 purposes:

- Generalize the `subscribeToTaskStats()` API so we can install a hook (`TaskObserver`) that tracks all the important task events (enqueue, dequeue, processed). The old API is deprecated and rewritten in terms of the new one. Tasks are assigned a process-wide unique id so that the events can be correlated.

- By having an explicit event on task dequeue we can remove the override for the queue observer factory introduced in D43339556. The factory was never supposed to be overridden, because it is made specifically for the global queue lag detector, which needs unique ownership of the `CPUTask::queueObserverPayload_` field (so queue observers cannot be chained). Custom queue observers are ported to the new interface in the diffs above in the stack.

- Similarly introduce USDTs for enqueue and dequeue. Together with the existing USDT on task completion, they can be used for tracing causal dependencies in request traces. The USDTs are now implemented in `EDFThreadPoolExecutor`, which did not have them before.

- Remove the read lock on the the subscribers list. The lock is unnecessary since subscribers cannot be destroyed before joining the executor, so we can replace it with a simple linked list which does not require any fenced instructions on reads.
