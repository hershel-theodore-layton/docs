Commit title: Fix bug that "swap" can not be the field name
Commit body:
Summary:
If we use `swap` as field name, currently we generate the following code

```
Foo& Foo::operator=(Foo& other) {
  Foo tmp(other);
  swap(*this, tmp);
  return *this;
}
```

here `swap` is a function we generated for all structs under the same namespace.

https://www.internalfb.com/code/fbsource/fbcode/thrift/compiler/generate/templates/cpp2/module_types_cpp/swap.mustache

The problem is that if we have `swap` field, we will generate `Foo::swap()` which has higher priority than the free function, thus we will only lookup `swap` in `Foo` struct. Since the function signature won't match, we will get a build failure.

This diff added an additional function call to fix this issue, e.g.

```
static void __fbthrift_swap(Foo& lhs, Foo& rhs) { swap(lhs, rhs); }
Foo& Foo::operator=(Foo& other) {
  Foo tmp(other);
  __fbthrift_swap(*this, tmp);
  return *this;
}
```

Note that cpp.Ref is necessary in the unit-test, otherwise compiler generates

```
Foo& Foo::operator=(Foo& other) = default;
```

This is a prod issue reported by user when struct has `swap` field:

https://www.internalfb.com/code/fbsource/[246492935ef0f14fe809621eb7be6ccd89426f6c]/fbcode/tupperware/if/common.thrift?lines=640
