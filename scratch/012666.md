Commit title: TypeInfo uses Constraint instead of EnforceableType
Commit body:
Summary:
ir and hhbc represent TypeInfo differently - hhbc::Constraint vs ir::EnforceableType.
This diff reconciles them by going with hhbc::Constraint, and deriving EnforceableType
on the fly where we need to in IR consumers like textual.

Constraint and EnforceableType (ET) are not inter-convertable by themselves;
conversion to ET requires inspecting other TypeInfo state. Too much code in Hackc/HHVM
needs Constraint, and too much IR code needs EnforceableType, to try to reconcile them
as part of this migration; hence the on-the-fly conversion.

we must unify TypeInfo to unblock unifying several other ir/hhbc types that contain nested TypeInfos.
