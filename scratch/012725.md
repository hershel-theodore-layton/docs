Commit title: Remove ThreadEntry destructor check
Commit body:
Summary:
Crashes seen by android builds point to ThreadEntry being somehow used
in an unexpected way. It is unclear what the source of the ~ThreadEntry call
is. The check in ~ThreadEntry assumes ThreadEntry are only created to be tied,
via pthread_key_t, to specific thread local. If there is on stack use or some
other path doing new & delete on it, the check will trip. For now remove the
check (and hence the dtor). I will adjust the logic so the check is only done
for instances that are allocated for use with pthread_key.
