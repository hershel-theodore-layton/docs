Commit title: use Vec<UpperBound> in ir::Func
Commit body:
Summary:
ir::Func represented tparam bounds with:
  HashMap<ClassName, TParamBounds { Vector<TypeInfo> }>
but ir::Class, hhbc::Class, and hhbc::Body use:
  Vec<UpperBound { ClassName, Vector<TypeInfo>}>

A HashMap allows O(1) lookups of tparam names, but doesn't preserve order.
I couldn't find anywhere where O(1) lookups matter, and tparam lists are typically
short so I don't think linear lookup is so bad. The unified IR should preserve original
order, or define a good canonical order.

Therefore, unify on Vec<UpperBound>
