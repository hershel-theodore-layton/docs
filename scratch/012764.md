Commit title: Refactor TypeErasedValue to be more like std::any
Commit body:
Summary:
This diff brings `TypeErasedValue` more in line with `std::any`.

Firstly, it eliminates `TypeErasedStorage` altogether (and the related base classes) which simplifies the code. There is no meaningful difference between `TypeErasedStorage` and `TypeErasedValue::makeEmpty()`.

Secondly, we drop the factory functions and make constructors look like `std::any` minus the `ValueType&&` and `std::initializer_list` overloads because we don't need them. This allows using `TypeErasedValue` in `AllocationColocator`, which performs direct-non-list-initialization (the current private constructor won't work for that).
