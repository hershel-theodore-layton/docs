Commit title: meth_caller should produce a readonly function type
Commit body:
Summary:
The `readonly` qualifier on function types (e.g. `(readonly function(int):bool)` means "this function does not capture any non-readonly values" i.e. "this function captures only readonly values".

The `readonly` qualifier on method definitions (e.g. `public readonly function foo(int):bool { ... }`) means "the `$this` parameter is readonly".

Confusingly, these are both represented inside the type-checker as a flag `Flags.Fun.readonly_this` (and various helpers with names involving `readonly_this`).

Perhaps for this reason, we don't do the right thing when typing `meth_caller(C::class, 'foo')`. This *should* have a `readonly` function type, because it doesn't capture any values. And if `C::foo` is itself marked readonly, then the `$this` parameter should be marked `readonly`. For example, for
```
class C {
  public readonly function foo(int):bool { ... }
  public function bar(int):bool { ... }
}
```
the expression `meth_caller(C::class, 'foo')` should have type `(readonly function(readonly C, int): bool)` and `meth_caller(C::class, 'bar')` should have type `(readonly function(C, int): bool)`.
