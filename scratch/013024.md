Commit title: Writing named enum constants instead of integers in .cconf generated by Configo
Commit body:
Summary:
See [this doc](https://docs.google.com/document/d/1uWS2ALoyKIZtTdEzSjAa98k2nu7CeATnXN3BiTQDfyY/edit) for context.

The idea behind this approach is that `config.readFromJson()` call gets an additional parameter `wrap_enum_constants`, which, when set, will lead to the integers representing enum constants being wrapped in a class that is aware of the enum class, so that its `__repr__` method outputs `EnumClass.VALUE` instead of the integer.

To enable this, I modified the code that generates ttypes.py files. Other methods (`read()`, `write()`, `_to_python()`, etc.) in ttypes.py haven't changed, and the behavior is identical to the one before unless `readFromJson()` is called with `wrap_enum_constants` set to `True`.

The test in JSONReaderTest.py passes (which proves that one can write data to a binary protocol after reading it with `wrap_enum_constants` flag):

```

```
