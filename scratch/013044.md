Commit title: Don't look for closure vars in typechecker-only code
Commit body:
Summary: hackc uses a visitor to compute the free variables of a lambda to know which ones go into the closure. That visitor was entring into the type-checker-only fields of ExpressionTree expressions. This made it inappropriately put temporary variables for the splices (`$0splice0`) in the closure. This updates the computation to only consider the `runtime` part of the ExpressionTree expression.
