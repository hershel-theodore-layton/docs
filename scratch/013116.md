Commit title: Refcounted Vec/Dict/Keyset literals for TypedValue
Commit body:
Summary:
Later in the stack, we eliminate Unit::adata, by storing literals directly in
the instructions that reference them (opcodes with immediate type AA,
wich maps to AdataId). However, the same literal can be referenced by multiple
instructions across a Unit, and cloning a large array literal is slow.

Turns out we already have this problem in general for anyone that clones
TypedValue, including constant folding, ir_to_bc, and bc_to_ir. Fix it by
(threadsafe) refcounting.

std::sync::Arc would get this done, but it does not have an FFI compatible
layout. Instead, use triomphe::Arc, which provides two nice properties:
* it is more compact & efficient than std::sync::Arc by dropping support
for weakrefs. this is fine because array cycles are impossible without inner mutability.
* it provides OffsetArc, a version of Arc<T> whose representation is a
   raw pointer of type `Vector<T>*`. This is intentionally for C++ FFI.

Replace Vector<T> with ArcVec<T> for the TypedValue Vec/Dict/Keyset
variants. ArcVec<T> is simply a newtype for OffsetArc<Vector<T>>.
Note this adds an extra indirection because it does not use a slice
representation like Arc<[T]> or Box<[T]>; flattening this might be a nice
future optimization.

As a result, sizeof(TypedValue) drops from 4 words (32 bytes) to 2 (16 bytes),
similar to HPHP::TypedValue.
