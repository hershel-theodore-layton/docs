Summary:
Remove AdataId -> TypedValue indirection by storing a TypedValue
directly in the Vec, Dict, and Keyset instructions, which are the only instructions
that use AA. This removes the Unit::adata vector, which gets hhbc and ir functions
one step closer to unification.

Each hhbc builder continues to maintain a per-unit intern table for array literals,
so if the same literal is mentioned by more than one instruction in the unit,
the underlying ArcVec holding array elements will be shared.

This won't increase bytecode size in memory. sizeof(TypedValue)=16,
well below sizeof(FCallArgs)=72, which is the long pole that determines
sizeof(Opcode)=96.

We haven't lost anything in hackc-translator either; hhbc::Unit's adata array
is already being thrown away. hackc-translator is globally interning array literals
and building up UnitEmitter's array data table from that.
