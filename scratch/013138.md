Commit title: codegen fix for multi-file thrift with interactions
Commit body:
Summary:
this thrift is enough to demonstrate the problem:
```
// multi_thrift1.thrift

interaction FooInteraction {
}

service FooService {
  performs FooInteraction;
  FooInteraction fooInteraction();
}
```

then, client code for `fooInteraction` will include something like the following:
```
...

pub(crate) use crate::multi_thrift1 as client;

...

impl<P, T, S> MultiThriftService for MultiThriftServiceImpl<P, T, S>
  where
    ...
{
   fn fooInteraction(&self,) ->
      ::futures::future::BoxFuture<'static,
        ::std::result::Result<crate::client::FooInteractionClient,
          crate::multi_thrift1::errors::foo_service::FooInteractionError>
    > {
      ...
    }
}
```
that's all well and good if `multi_thrift1.thrift` is the only source file in `thrift_library(name = "foo", ...)` but on the other hand, if there are multiple thrift files involved, then `multi_thrift1.thrift` will give rise to a submodule `multi_thrift1` and in this case, `crate::client::FooInteractionClient` won't be found:
```
error[E0433]: failed to resolve: could not find `client` in the crate root
   --> multi_thrift1/mod.rs:255:77
```

to resolve this name correctly (and similar cases elsewhere), the code should read `crate::multi_file_thrift1::client::FooInteraction`.
