Commit title: Improve large-buffer crc32c performance by 50-85%
Commit body:
Summary:
Land the AVX512 portion of this integration.

Integrate faster crc32c algorithms into Folly.  See earlier diff for a longer
summary of the motivation here.

Algorithm selection around 4kB size boundary was chosen empirically.

Add a bunch of explicit unit tests around the new routines.  Add a test of very
long buffers and apply it to all of the reasonably fast existing HW
implementations as a sanity check.

Facebook's HHVM runs in a very weird environment where a link postprocessing
tool (BOLT) modifies functions that contain EVEX instructions (i.e., AVX512
operations) to trap with the `ud2` instruction.  This environment does not mask
AVX512 feature flags in `cpuid`, unfortunately.  So we use a new mechanism in
Folly to detect this environment and avoid using the routines which will trap
there.
