# Problem

D49734568 added support for `co_scope_exit` in `AsyncGenerator`, but there is a problem that `co_scope_exit` is not attached if `next()` of the generator is never `co_await`ed. This is a big problem in the case when ownership of an object that requires async cleanup is passed as an argument to the generator.

# Solution

Introduce `AutoCleanup<T>` template class that allows to wrap input arguments that require async cleanup. When the coroutine promise of the `CleanableAsyncGenerator` is created, it automatically attaches a `co_scope_exit` task that performs async cleanup of all the arguments wrapped in `AutoCleanup`. This way `co_scope_exit` is attached even before `next()` is `co_await`ed.
