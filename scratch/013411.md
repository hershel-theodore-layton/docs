Commit title: Introduce flow-based reason constructors
Commit body:
Summary:
Reaons are our implementation of type provenance, telling us something about why an expression or hint has its type. At the moment, `Reason`s constructors are either

1) `Rnone` records the lack of a `Reason`

2) Simple 'witnesses' which take the position of some syntactic element and encode some information used in error reporting, e.g.:
   -- `Ridx` records the fact that an expression is begin used to index into a container
   -- `Rhint` records the fact that a type comes from a user provided hint

3) More complex constructors used to store ad-hoc structural information during typing, usually detailing  how reasons are carried through type constructors e.g.:
   --`Rlambda_param` is used to record the position of a lambda parameter along with the reason for the enclosing lambda expression
   -- `Rtypeconst` is used to record information about a type constant along with the reason for the enclosing class

4) Witnesses for non-subtype constraints, e.g.:
   -- `Runpack_param` is provided when constructing `Tdestructure` constraint
   -- `Rforeach` is provided when constructing a `Tcan_traverse` constraint and _included_ in the `can_traverse` record

This diff introduces three new data constructors which will allow us to record the linear path through a program which explains why an expression has its type. The constructors are:

- `Rflow : locl_phase t_ * locl_phase t_ -> locl_phase t` : concatenates two paths
- `Rrev : locl_phase t_ -> locl_phase t_`: records reversals in paths due to contravariance
- `Rprj : prj * locl_phase t_ -> locl_phase t_`: records reasons through type constructors

Where `prj` records 'projections' into type constructors.

In subsequent diffs, we'll use these constructors in typing, inference and localization to trace the provenance of  a type given the given the constraints imposed on it. For example, for a subtype constraint `C<TL1,TL2> <: C<TR1,TR2>`, where we have `C<+T1, -T2>:

For the covariant type argument:

- Construct reason `r_sub_sup` as `Rflow(r_sub,r_sup)` recording the flow of our subtype `C<TL1,TL2>` into our supertype `C<TR1,TR2>`

- Construct a reason `r_prj` as `Rprj(Prj_class('C',0,Covariant), r_sub_sup)` to record the projection into the first type argument

- Update the reason of our type argument of our subtype to indicate the flow of its reason into the projection i.e. `Rflow(r_tl1, r_prj)`

- Make a recursive calls with the `TL1 <: TR1`

For the contravariant type argument

- Construct reason `r_sup_sub` as `Rflow(r_sup, Rrev(r_sub))` recording the contravariant flow of our supertype

- Construct a reason `r_prj` as `Rprj(Prj_class('C',1,Contravariant), r_sup_sub)` to record the projection into the second type argument

- Update the reason of our type argument of the supertype to indicate the flow of its reason into the projection i.e. `Rflow(r_tr2, r_prj)`

- Make a recursive calls with the `TR2 <: TL2`
