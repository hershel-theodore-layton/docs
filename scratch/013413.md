- Modify the template so that we use `object` instead of `Any`.  This should also get rid of the `pyre-ignore` generated by these functions but we will see
- `object` is better than `Any` because the type checker will force the caller to do type refinement on the `object` instance before calling any non-object methods on it.  The type checker will let the caller do anything with `Any`.  I also suspect that this function table thing is never user facing, so it's not consequential anyways
- It looks like the `getFunctionTable` method is meant to be private to the thrift lib processor adaptor, which is the only consumer of this function in the IG codebase
