Commit title: Make HandlerCallback::result take argument by value
Commit body:
Summary:
Right now `HandlerCallback<T>::result` takes its input by `const&`. This works fine today because `result` calls `doResult` synchronously which serializes the provided struct into an `IOBuf`.

With `ServiceInterceptor`, `doResult` will be scheduled to run after asynchronously executing `ServiceInterceptor::onResponse` which means either copy or move inside `result()`. For a binary field, we are provided a `const std::unique_ptr<IOBuf>&` which doesn't let us perform a move.

For regular Thrift structs, this does now rely on copy-elision by the compiler. However, capturing by value is necessary for asynchrony and in case the compiler can't optimize away the copy, there is always `std::move`.
