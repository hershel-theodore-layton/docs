Commit title: Use IntrusiveSharedPtr for all HandlerCallback
Commit body:
Summary:
The functional change is in `AsyncProcessor.h` where we change `HandlerCallbackPtr` from `std::unique_ptr` to `apache::thrift::util::IntrusiveSharedPtr`.

Some of fbcode had to be codemodded for this reason.
* Calls to `folly::to_shared_ptr(std::move(callback))` have been removed since `IntrusiveSharedPtr` has shared ownership semantics out of the box.
* Function signatures accepting `std::shared_ptr` (implicitly constructible from `std::unique_ptr&&`) were updated to `HandlerCallbackPtr`.
* Calls to `HandlerCallbackPtr<T>::release` have been updated to `HandlerCallbackPtr<T>::unsafeRelease`.
* Calls to `HandlerCallbackPtr<T>`'s constructor with a raw pointer have been updated to use the marker struct, `UnsafelyFromRawPointer`.

**All of these changes should be no-op.**

The real changes (non-codemod) are in `AsyncProcessor.h` and `GeneratedCodeHelper.h`.
