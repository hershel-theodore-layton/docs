Summary:
I update the logic to check if `Src value` positive overflows. I break the logic apart in to two pieces to handle floating point types and integral types that have a larger range than time_t/int64_t.

This change fixes a floating-integral conversion UB (C++ Spec Section 7.3.11) when `Src value` has a value of 9223372036854775808.0. The UB happens because that value is outside the range of representable time_t/int64_t values.
