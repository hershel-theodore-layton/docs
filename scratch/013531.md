Commit title: auto-migrate compatible private api replacement
Commit body:
Summary:
## Background
Currently, there are many cython .pyx files that use the “private” py3 API to efficiently convert between thrift-py3 object and thrift C++ object. Specifically,
- `struct_instance._cpp_obj` accesses `shared_ptr[cMyStruct]`, effectively converting from thrift-py3 to C++. `struct_instance` must be statically typed in cython for this to work, so a common usage pattern is `(<MyStruct>struct_instance)._cpp_obj`.
- `MyStruct._fbthrift_create(shared_ptr[cMyStruct])` converts from C++ to thrift-py3.

These cython use cases are currently blocking the auto-migrate strategy because they only compile when thrift-py3 compiled cython objects are available, and they aren’t compatible with thrift-python object. We need a way for cython use cases to easily do the C++ conversions, and it has to work whether auto-migrate is enabled or disabled.

## Proposal
In order to avoid unnecessary build size bloat, thrift-py3 can generate a `converter.pyx` module. The `types.pyx` target won’t depend on it, so the `types.pyx` compile size won’t change. The `converter.pyx` will cimport cython types from `types.pyx` only in normal, un-migrated mode. In both modes it will import cpp-bound types.

This automates a lot of painful work with the current python-capi backdoor functions for cython, which require a manual `cdef extern` include of `thrift_types_capi.h`, as well as remembering to include both the cpp and cython python_capi targets. More importantly, it unlocks bi-compatibility for the 100 cython files that use the py3 private API, and means they'll automatically get the fastest possible replacement with thrift-python types.
