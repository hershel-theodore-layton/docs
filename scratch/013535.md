Commit body:
Summary:
new_iter_array_cold() handles the generic case of constructing an array
iterator. It is used only from places that already handled simple cases, such
as an empty array, vanilla vecs and dicts and bespoke structs. We also already
populated m_data.

The logic of IterImpl constructor trivializes to setting m_pos/m_end and
calling setArrayNext().

The remainder of the logic just obtains the current value (and possibly key),
so let's just do that directly using the ArrayData instead of via Local vs
non-Local helpers.

Kill all the code that became dead (new_iter_array_cold, various IterImpl
constructors and setArrayData()).
