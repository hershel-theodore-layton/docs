Commit title: Eliminate exn Success variant
Commit body:
Summary:
For a fallible service method like `Success example() throws (1: Bloop bloop)`, Thrift previously generated a server trait like this:

```lang=rust
pub trait MyService: Send + Sync + 'static {
    async fn example(&self) -> Result<Success, ExampleExn>;
}

pub enum ExampleExn {
    #[doc(hidden)]
    Success(Success),
    bloop(Bloop),
    ApplicationException(ApplicationException),
}
```

where the `ExampleExn::Success` only exists for sloppy implementation reasons, and is never supposed to be returned by the server impl. If a server does return `Err(Success(_))`, we had to check for that and turn it into an assertion violation. Various methods of `ExampleExn` would also panic if called on a `Success`, such as `.exn_name()` which gets the exception name ("bloop"), not a thing that makes sense on a success value.

This diff eliminates `Success`.

```lang=rust
pub enum ExampleExn {
    bloop(Bloop),
    ApplicationException(ApplicationException),
}
```

and instead uses `Result<Success, ExampleExn>` correctly throughout the generated code, just as the server trait's return type has always done.

For now, infallible service methods continue to have their own unique error type, but as it now has just 1 variant, a possible future extension would be to allow infallible methods (ones with 0 `throws`) to return `Result<Success, ApplicationException>`.

```lang=rust
pub trait MyService: Send + Sync + 'static {
    async fn infallible(&self) -> Result<Success, InfallibleExn>;
}

pub enum InfallibleExn {
    ApplicationException(ApplicationException),
}
```
