Commit title: Add extended reasons for function subtyping
Commit body:
Summary:
Adds extended reasons to record function subtyping and generates debug output when `--extended-reasons` is set.

Given function types and reasons:

```
(function ((TL1, RL1),  inout (TL2 ,RL2)): (TL3, RL3) ) , RL0
<:
(function ((TR1, RR1),  inout (TR2 ,RR2)): (TR3, RR3) ) , RR0
```

we generate the following constraints:

1) For the first argument:

```
(TR1, Rflow(RR1, Rprj(Prj_fn_arg(0,0,Contravariant), Rflow(RR0, Rrev RL0))))
<:
(TL1, RL1)
```

The reason can be read as an explanation of dataflow:

TR1 flows into the type TR0 via the first argument, which is contravariant.  The function type TR0 flows from the function type TL0 and into the type TL1 flows into that function type via the first argument.

```
RR1 --> contravariant fn arg 0 --> RR0 <-- RL0 --> contravariant fn arg 0 --> RL1
```

2) For the second argument, which has an `inout` annotation, we will  generate one contravariant constraint which is similar to the above and a covariant constraint since we type this argument as invariant:

```
(TL2, Rflow(RL2, Rprj(Prj_fn_arg(1,1,Covariant),Rflow(RL0, RR0))))
<:
(TR2, RR2)
```

```
RL2 --> covariant fn arg 1 --> RL0 --> RR0 --> covariant fn arg 1 --> RR2
```

3) For the return types, we generate only a covariant constraint this time with a `Prj_fn_ret` projection:

```
(TL3, Rflow(RL3, Rprj(Prj_rn_ret,Rlow(RL0,RR0))))
<:
(TR3, RR3)
```

```
RL3 -> covariant fn ret --> RL0 --> RR0 --> covariant fn ret --> RR3
```

The extended reasons also allow for variadic arguments.
