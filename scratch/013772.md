Commit title: Add extended reason for function calls
Commit body:
Summary:
Adds extended reason for typing of function calls; since we don't use function type subtyping, we replicate the flows we would get as closely as possible. For a call `foo($x, $y)` we would

- infer type for each argument
- generate a fresh return type
- construct a function type from these type
- find the definition of `foo` and instantiate any type arguments (using
 fresh vars if explicit args are not provided)
- generate a subtype constraint with the declared type as subtype and the infered function type as supertype

subtyping would then
- generate a contravariant projection on each function param
- generate a covariant projection on the function return

There are a couple of differences we get from the typing implementation:
1) The witness point to the name of the function call and the function name of the declaration - it would be better to point to the function header
2) The treatment of `inout` parameters is different between typing and subtyping - in subtyping they are treated as invariant but in typing they are treated as contravariant, the same as any other function param, with the 'write back' the local variable happening in a separate step
