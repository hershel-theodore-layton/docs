## Note on the approach

I tried a few approaches that involved getting the types from the tast and printing them. They required much more invasive changes and there are only a few small cases where the alternative would produce better results (on the current approach we don't generate `detail` for enum class members and are missing type information for non-type class constants that are missing type hints).

On these alternative approaches, I would probably create a new LSP extension method like `textDocument/facebookExperimantal/typedDocumentSymbol` with separate logic.
