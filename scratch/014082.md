Commit title: Error on non-void __clone return
Commit body:
Summary:
it is an occasional misunderstanding that you should return the new object (or anything) from `__clone`. Any returned value is lost as the `__clone` method is meant to be sid-effect-ful.

Possible feedback point: Should we allow `noreturn/nothing` ? We won't recognize `noreturn`-ness at the `clone` operator (callsite), but maybe it's reasonable for a user to express this in their implementation?
