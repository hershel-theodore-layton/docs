Summary:
Populates `hack.HackToThrift` predicate based on annotations in thrift generated files.

See test case `TestService.php` and `test_types.php` for  annotations, and `entityIdl.out` for the resulting mapping. Almost all hack entities are indexed, except union/enum/typedefs (left as follow up).

Thrift schema doesn't support xrefs to fields definitions, so the targets for fields xrefs are the enclosing struct.

## Caveat/follow up

The Thrift team showed concerns about modifying the comments in the hack generated code (potential for performance regression?).  Fortunately, the existing comments contain* all information needed by Glean.

The main downside is that changing these comments is likely to break xlang navigation.  In C++, the comments are explicitly targeted toward Glean and are json, so shouldn't be changed accidentally.

We should guard against that risk here by generating `TestService.php` in our test but it's currently hard-coded.

(*) almost... D56913167 added name of thrift source files, and union types are incorrectly annotated as struct.

## Implementation

- regenerate ocaml thrift datatypes `buck2 run fbcode//glean/schema/gen:gen-schema --  --ocaml fbcode/hphp/hack/src/typing/write_symbol_info/glean/ --dir ~/fbsource/fbcode/glean/schema/source --schemas hack,src,gencode,builtin,fbthrift`
- update `index_decl.ml` so it processes the thrift annotations in hack code generated from thrift.
- the actual annotation parsing and thrift fact generation is done in new module `Thrift`.

Note: the comment for a given generated entity doesn't contain the full information to generate the thrift declaration, so it makes the `Thrift` module more complicated that it could have been otherwise.

For instance, to generate a thrift funcation declaration fact, we
1. get the thrift file from the hack file header
2. get the thrift service from the hack interfaces that the generated class implements
3. get the thrift function from a class member method

I found the simplest way to implement this was to make `Thrift.t` stateful: it remembers the relevant info seen in previously parsed comments.  Should annotation change in the future, only the `Thrift` module will need to be updated.
