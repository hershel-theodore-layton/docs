Commit title: Emit IterNext even in absence of profile data from IterInit
Commit body:
Summary:
Split SpecializedIterator into two parts:
- IterProfileInfo, that carries profile info hint from IterInit to IterNext
- IterSpecInfo, that is used to deduplicate compatible loop header/footer logic

Make IterInit record IterProfileInfo. Use the profile info to lazily emit loop
header, if IterSpecInfo does not exist yet. This logic is equivalent to the
previous one, except for what gets recorded in IRGS and improved deduplication
of compatible loop headers.

In IterNext, instead of just checking whether the loop header exists and bailing
out if it does not, it now first tries to reconstruct profile info, by either
checking for IterProfileInfo recorded by IterInit, or by using trivial
ArrayKeyTypes and using IterNext's bespoke profiling for ArrayLayout. Then we
lazily emit loop header (and also footer), similar to IterInit.

Whenever we were previously able to specialize IterNext based on IterInit
information, we continue to do so. But we now also try to specialize IterNext
when there is none or conflicting information coming from IterInit.

This allows specialization in situations where IterInit is not part of the
translation (e.g. translation started at resumed await inside a loop), or where
IterInit and IterNext point to mismatched body offsets (e.g. because of hhbbc
splitting critical edges and inserting UnsetLs, a problem we will try to solve
as well later).
