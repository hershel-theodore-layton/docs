Commit title: don't use ServerSymbolDefinition.go
Commit body:
Summary:
For computing the xref map, the Hack indexer reuses the same API that is used by the Hack LSP for computing hovers and go-to-def links.  It computes xrefs in two steps
1. Use the `all_symbol` visitor which returns all the `SymbolOccurrence.t` in a file
2. Resolve these occurrences to `SymbolDefinition.t` using `ServerSymbolDefinition.go`

`SymbolOccurrence.t` type does't contain all the information needed by in the indexer. Specifically,
- Class symbols encompass classes, traits, interfaces, enum, typedefs
- Members come with their "receiver" class but we need the "origin" class (e.g. in `Foo::Bar`, `Bar` origin can be a parent of `Foo`).

The `ServerSymbolDefinition.go` method used to perform this resolution is inefficient, complex, and does more than needed:  For each occurrence of a class member reference, it fetches the defining AST, and scan all members in order to find their position.

This diffs reimplement `Sym_def.resolve` without relying on`SymbolDefinition.go`. The new implementation doesn't  fetch target ASTs (via `Ast_Provider`) but relies only on the regular `Decl_provider`.  Unlike the IDE,  the indexer doesn't need to dynamically look up for target spans since they're indexed. The resulting code a lot simpler.

The file references are now computed in a separate pass.

# Next

The IDE symbol services aren't ideal for the indexer. Beyond the main performance issue fixed by this diff, the API isn't adequate. For instance,

1. `SymbolDefinition.full_name` was intended to be human-readable and we parse it to extract the class name
2.  there are two passes when one should be enough.

We should reimplement a visitor that resolves the references in one pass.
More modestly, we can make `Sym_def.t` more structured -> D57538737.

Besides, indexing doesn't no longer need to fetch files outside of the change set anymore, which I hope is going to unblock to migration to RE.
