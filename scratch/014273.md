# Summary
Currently, all user exceptions (declared and undeclared) that are sent as part of a stream are logged to scuba with `APP_UNKNOWN` error reason and [`EncodedStreamError::what()`](https://fburl.com/code/i4uvqicm) as the error reason what, which depends on the metadata received from the server. However, we never populate this metadata for declared exceptions and we only populate the `what` field in the metadata if it is an undeclared exception.

This explains why we don't see the error message in SR scuba: https://fburl.com/scuba/service_router/njxsz8eo (the samples which have some error message in Error Reason What are undeclared exceptions) which makes it hard to investigate issues (eg. S392979).

This diff updates `encode_stream_exception` to set the `name` and `what` metadata for both undeclared and declared exception.

# Observable (to users) change:

## Declared exceptions:
**Before:**
Error Reason: `"App Unknown"`
Error Reason What: `"(APP_UNKNOWN) apache::thrift::detail::EncodedStreamError:"`

**After:**
Error Reason: `"DefinedException"`
Error Reason What: `"facebook::servicerouter::DefinedException: foobar"`

## Undeclared exceptions:

**Before:**
Error Reason: `"App Unknown"`
Error Reason What: `"(APP_UNKNOWN) apache::thrift::detail::EncodedStreamError: std::runtime_error: foobar"`

**After:**
Error Reason: `"runtime_error"`
Error Reason What: `"std::runtime_error: foobar"`

# Other Notes
* This doesn't affect what exception is raised to the user (this worked correctly before too)
* This doesn't affect logging for the stream request, it only affects logging for stream payloads that are sent after a successful stream request
