Commit title: opt-in folly::IOBuf types
Commit body:
Summary:
`folly::IOBuf` is special. So special in fact that even `thrift-python` reads the `cpp.Type` annotation for this one case and makes the python type `folly.IOBuf` instead of `bytes`.  In the future this should be `python.IOBuf`, but that migration hasn't been done.

The thrift-python C API should automatically opt-in structs that are otherwise eligible if their only `cpp.Type{name = "<cpp_type>"` has `cpp_type` `folly::IOBuf` or `std::unique_ptr<folly::IOBuf>`.

This diff matches the behavior of `thrift-python` where a leading `::` (like `::folly::IOBuf`) doesn't match and therefore isn't turned into `folly.IOBuf` type (remains `bytes)`.

This diff also lays some groundwork to enable `cpp.Type{template = "<std_or_folly_ns::some_template>}"`

Started a `lib/python/util.h` lib to centralize some logic shared between thrift-python and python_capi to ensure they're in sync.
