Commit title: thrift: rocket: only send an error on close() if transport is not errored out
Commit body:
Summary:
It's possible to reach RocketServerConnection::close() from a read error on an AsyncSocket:

```
RocketServerConnection::close()
Parser<T>::readErr()
AsyncSocket::failRead()
AsyncSocket::processNormalRead()
```

At this point, it doesn't make sense to try and send an error frame back to the client through the very socket that errored out.

This is benignly handled by AsyncSocket's writeChain() impl: https://fburl.com/code/inr80u0n

But it would be better to not call it in the first place.

AsyncIoUringSocket fails silently: https://fburl.com/code/56pk8em4

Which I will fix separately to behave more like AsyncSocket, though I'm also adding a check to only sendError() if the underlying transport isn't errored out.
