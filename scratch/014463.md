Commit title: folly: AsyncIoUringSocket: fail writes on error
Commit body:
Summary:
Ucache is experiencing crashes after enabling io_uring, see: https://fb.workplace.com/groups/238877298815471/posts/469089799127552

The crashes are caused by a deliberate SIGABRT when the process fails to drain within a deadline of 20 secs.

After digging through a coredump, I came to the following conclusions:

* AsyncIoUringSocket is in state_ == 4 == ERROR which can only realistically be caused by a read error
* When propagating this read error back up to Parser/RocketServerConnection, it tries to send an error back to the client and then enters a CLOSING state
* The send is queued in inflightWritesQueue_...
* But AsyncIoUringSocket will silently refuse any sends once it is in an error state
* A non-empty inflightWritesQueue_ prevents RocketServerConnection from transitioning into a CLOSED state and cleaning up
* Which then causes ThriftRocketServerHandler and its parent Cpp2Worker from being freed, ultimately causing the abort

Fix this by failing writes on socket error. This happens in two places:

1. writeChain() rejects writes and calls back with an exception if the socket is closed or errored out
2. processWriteQueue() fails all pending writes with an exception
