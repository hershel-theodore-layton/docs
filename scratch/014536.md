Commit title: Add ServerGeneratorStream::fromProducerCallback
Commit body:
Summary:
Add a way to create a ServerGeneratorStream from a `ProducerCallback` object. `ProducerCallback::provideStream()` will be called by the server's IO thread when the stream is being established and will pass a `ServerGeneratorStream::Ptr` to the callback  so that it can interact with the stream.

* The `ProducerCallback` can call `ServerGeneratorStream::publish()`  to send serialized payloads as stream chunks to the client
* The `ProducerCallback` must keep track of how many credits it has and only call `ServerGeneratorStream::publish()` if it has credits
* The `ProducerCallback` can get credits from the client if they were received by calling `ServerGeneratorStream::wait()` which will return true iff there are no messages from the client and we need to wait until we get some messages from the client
* After ensuring there are messages from the client, the `ProducerCallback` can get the messages by calling `ServerGeneratorStream::getMessages()`
* The messages are signed integers with positive values representing credits sent from the client and negative values being special control messages (`-1 == CANCEL`, `-2 == PAUSE`, and `-3 == RESUME`)
* To end the stream, the `ProducerCallback` must call `ServerGeneratorStream::publish()` with an empty `Try` (to complete the stream successfully) or it must call `ServerGeneratorStream::publish()` with a `folly:exception_wrapper` containing either a user-declared serialized Thrift exception or an undeclared exception
* The `ProducerCallback` must call `ServerGeneratorStream::serverClose()` after it ends the stream and then destroy the `ServerGeneratorStream::Ptr`
