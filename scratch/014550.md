This diff implements `ServiceInterceptor::onResponse`. This happens prior to serialization (`doResult`, `doException`, `doDone` as seen in this diff).

Per this diff, Exceptions thrown in `ServiceInterceptor::onRequest` **do not** execute `ServiceInterceptor::onResponse` though this changes in {D56493313}. This is primarily to break down the complexity of the change over multiple diffs.

Like `ServiceInterceptor::onRequest`, exceptions are collected into a list meaning that `onResponse` for *all* `ServiceInterceptor` instances will be executed. However, in the case that there is already an "active" exception (meaning the user code threw an error), these are thrown away (logging locally) and the user-thrown exception takes precedence.
