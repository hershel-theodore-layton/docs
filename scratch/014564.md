Commit title: Optimize template rendering to eliminate string allocs
Commit body:
Summary:
Previously, every output fragment created during rendering would be returned up the stack in its own `std::string` (often heap-allocated) in various function return values, and accumulated into the final contiguous string output of the template by the following loop:

https://www.internalfb.com/code/fbsource/[e5b0978092786009bf6ed0c699aad0f1d9da0945]/fbcode/thrift/compiler/detail/mustache/render_context.cpp?lines=82-84%2C86%2C90%2C92-94

In fact, individual fragments of output often got copied across a large number of different allocations across different levels of the template evaluation. Every interpolated node evaluated to a `std::string`, every section evaluated to a `std::string`, every "partial" (helper template) evaluated to a `std::string`. So deeply nested content, which might be behind a dozen or more levels of sections and helper templates, would be copied successively into each of those dozen different heap allocations as it propagated up the stack.

This diff applies an optimization to write all template output directly in-place into the same `std::string` that will be returned to the caller of the top-most `render` entry point. Individual fragments now never get heap-allocated into their own small heap allocations, and never get copied around across multiple different strings.

This improves compiler performance by about 6% from allocating less often and copying less string data.
