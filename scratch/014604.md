Commit title: Add option to use hash of definition uri or scoped name to identify definitions
Commit body:
Summary: The current scheme identifies definitions using DefinitionId in some places and TypeUri in others, which apart from being inconsistent both come with downsides: DefinitionId makes it difficult to shard and merge schemas by program, while TypeUri relies on all definitions having unique URIs configured which has proven to be difficult to ensure in practice, and the fallback using scoped names has been observed to produce significant collisions. The new scheme computes a hash of the path + definition name to consistently identify definitions even when the same file is processed from multiple different including files, allowing us to generate root program only schemas that can be trivially merged to save on space.
