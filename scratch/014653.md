Commit body:
Summary:
Drain ZC TX queue when closing the socket
If we zend data with ZC enabled and we close the socket, there is a chance we can have outstanding memory that is either queued in the kernel or it has been sent to the driver.
There is no reliable way to get notified when the memory has been release in this case (since we are closing the socket) but there is an approach suggested by the developers ate Google.
We try to reap the available completions without waiting
If there are still remaining entries, we set SO_LINGER to 0 and we start a timer of 1 second to free the outstanding buffers.
This should in practice guarantee the data has been sent or discarded.
