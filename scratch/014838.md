Commit title: Pass type-erased request arguments to ServiceInterceptor::onRequest
Commit body:
Summary:
This diff exposes incoming request arguments from an RPC to `ServiceInterceptor::onRequest` in a type-safe but type-erased manner.

It achieves this by creating a vtable (at compile time) mapping compile-time constructs (`std::get<Index>(std::tuple)` and `std::tuple_element_t<Index, std::tuple>`) to runtime constructs (see `getTypeErased` which returns `std::get<Index>` as `const void*` and `std::tuple_element_t` as `std::type_info`).

The runtime cost is minimized as much as possible — additional compile time work is required to create the dynamic jump table for the machinery described above, and dynamic type-checking only happens upon access. When they are not used, the additional cost is setting some pointers (one per argument) in `ArgsState::asTupleOfRefs` in generated code (see `process_and_return.mustache`).
