Commit title: Support exponential growth schedule in QueueAppender
Commit body:
Summary:
Using a constant growth can penalize both small messages (too much overhead) and large messages (too much fragmentation). Optionally support bounded exponential growth, so we can experiment with it.

This diff doesn't change the growth strategy for existing use cases, the single-argument constructor preserves the old behavior.

Since the allocation code is centralized to support the growth strategy, we can also avoid calling `preallocate()` and instead create the `IOBuf` ourselves; this is mostly to make it apparent in the code that we double the growth only when we allocate a new buffer.

As an intended consequence of reorganizing the code, the fast path of `write()` is unexplainably improved.
