Commit title: Optimize IOBuf storage refcount operations
Commit body:
Summary:
When deleting a non-shared `IOBuf` (which is the common case) we shouldn't be doing any atomic RMW operations, but in fact we do two CASs on `HeapPrefix::flags`: one to release `SharedInfo`, and then one to release `IOBuf`.

We can go down to 0 in a few steps:
1) Do not distinguish between "data in use" and "`SharedInfo` in use", since the lifetime of those is the same and we can just track "`SharedInfo` in use".

2) Move from a bitmask (`flags`) to a simple refcount (which can be 1 or 2).

3) This enables a read-only fast path on the last reference (note that we already do this for the `SharedInfo` refcount in `decrementRefcount`)

4) Detect whether `SharedInfo::releaseStorage` is being called by the `IOBuf` that owns the storage. In this case, the storage's `buf` is owned by this thread, so we know that it cannot be destroyed concurrently and there cannot be a concurrent refcount operation, so we can use a plain store.

The first two steps also considerably simplify the code.
