Summary:
Delete the elaboration pass I wrote last year for validating top-level statements, because it is dead code.

**Explanation of deadness**:

Two cases to consider:
1. use Naming.program, which elaborates top-level statements into a single top-level function. Validation for top-level statement won't produce any errors because top-level statements are gone.
2. use Nast.get_defs to get top-level things (statements, functions, classes, etc.) and validate each of those top-level things. Again, validation for top-level statements won't preoduce any errors because a statement that is nested under another `def` isn't top-level.

**Evidence of deadness**

CI is green for the version of the code in D58787474, which introduces a `failwith`.

## Alternatives considered

It would feel more consistent (to me) to elaborate top-level statements into a function in an elaboration pass. However, this doesn't play nicely with how case (2) works above: Typing_check_job.calc_errors_and_tast independently elaborates each kind of top-level def.
