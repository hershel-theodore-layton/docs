Commit title: let ThreadEntrySet::erase periodically shrink the data structure
Commit body:
Summary:
When the size is much less than the capacity, shrink to fit.

The potential scenario is that many threads are created, access a given id, and are destroyed. Then the thread-entry-set for that id will grow to accommodate but will not shrink. If this happens repeatedly for a single id, the storage will be reused. But if this happens repeatedly for different id's, or all at once for multiple id's, the storage will not be reused between the id's. We could end up with wasted memory on the order of O(num-ids × max-num-threads), which is precisely the order which we would like to avoid.
