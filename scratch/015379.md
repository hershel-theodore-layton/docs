Commit body:
Summary:
This diff introduces a global `init` function similar to `folly::init` except for Thrift.

`ServiceInterceptor` is nicely wrapped up in `ServerModule` via `ThriftServer::addModule`. However, the story for `ClientInterceptor` is much more complicated.

Since Thrift clients can be created basically *anywhere* in a C++ program (even before `main`) , the state must be global (it sucks, but oh well). Part of the `InitOptions` accepts client-side `TProcessorEventHandler`s which replaces `TClientBase::addClientEventHandler`.

`apache::thrift::runtime::getGlobalLegacyClientEventHandlers()` will *appear* to be empty before `init()` is called. This is the desired behavior since clients created before main tend to be sensitive to implicitly included dependencies (such as `TProcessorEventHandler` sneaking in).
