Commit title: icsp_any: generalize ensure_thrift_any_type a bit
Commit body:
Summary:
one might hope that if you wrote a program like this
```
  4     let foo = foo::Foo { bar: 42 };
  5     let any: any::Any = icsp_any::serialize(&foo);
  6     match icsp_any::deserialize::<foo::Bar>(&any) {
  7         Ok(_) => (),
  8         Err(e) => println!("error:\n{:#?}", e),
  9     }
```
or this,
```
 11     let bar = foo::Bar::x("hello".to_owned());
 12     let any: any::Any = icsp_any::serialize(&bar);
 13     match icsp_any::deserialize::<foo::Foo>(&any) {
 14         Ok(_) => (),
 15         Err(e) => println!("error:\n{:#?}", e),
 16     }
```
that errors would be printed but that's not how deserialization works (well defined and valid thrift values are produced by both).

to help avoid head-scratching from this kind of "type mismatch" there exists the utility `ensure_thrift_any_type<T>` which is called before any deserialization happens at the start of `icsp_any::deserialize()`.

however, as indicated by [this comment](https://www.internalfb.com/code/fbsource/[7a25a4e79650]/fbcode/syx/common/thrift_any/src/deserialize.rs?lines=48-49), `ensure_thrift_any_type<T>` doesn't consider the case of `TypeUri`s containing hash prefixes of uri strings and so the check was disabled in the syx fork of icsp_any since this was shown to be incompatible with their python clients.

this diff improves `ensure_thrift_any_type<T>` such that in a subsequent diff we can unfork `syx_thrift_any::deserialize()`.
