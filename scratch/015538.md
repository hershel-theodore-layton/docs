Commit title: Randomised well-typed program generator
Commit body:
Summary:
Inspired by the difficulty of anticipating unintended combinations of languages features with newly developed features and the SEVs this has recently led to both for Hack and HHVM, this diff introduces `milner` a modest CLI tool to generate well-typed Hack programs.

## How is this useful?

It gives us new testing opportunities with less bias and labour.
- No program generated by `milner` should cause HHVM to fatal, so we can continuously feed programs to HHVM that combine language constructs in unexpected ways to reveal bugs early during feature development. Hopefully going to production without costly soundness issues.
See the `TypehintViolationException.php.template` for a simple program to uncover issues of this sort.
- We can detect completeness issues. If a program generated by `merlin` leads to a static type error, it is either a bug in `milner` or a completeness issue in the language.
- We can do property-based testing in exp-style. That is we can encode properties that we expect to hold but without explicitly coding it in. See the `intersection.php.template` and `union.php.template` for examples of these kind that check that `union` and `intersection` satisfy their basic identities.

## Isn't generating well-typed programs really really hard?

It is! That's why fuzzing statically-typed programming languages is hard.

We take a type-driven approach on program templates to make this problem tractable:
* There are template Hack files with placeholders like `TYPE#1` and `expr#1`.
* We first pick candidates for `TYPE#1`s randomly (but deterministically based on a seed).
* We note any additional definitions needed along the way.
* Then we pick `expr#1` in a way that `expr#1 : TYPE#1`.
* Finally, we feel in the chosen types to generate a complete well-typed program.

## Limitations

This approach is not without flaws. It has both
* [**fundamental**] The generated test files are as good as the templates we include in the harness.
* [**fundamental**] Type generator needs to grow to a comprehensive size to find interesting programs.
* [**fundamental**] Unlike successful fuzzers in other domains, this approach is not coverage-driven.
* [**doable**] Feature developers must remember to extend `milner` to get any benefits.
* [**doable**] For certain features such as modules, placeholders for types and expressions are not enough and we need other placeholder types.
