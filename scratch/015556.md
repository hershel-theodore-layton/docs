Summary:
This fixes a copy inherent in list_getitem where copy assignment operator used. Now we just access directly by ref with `operator[]`. This should be material savings for strings and nested containers. This even improves marshal times for ints... go figure.

Also, noticed an unnecessary `bytes` creation then immediate `decode` for `str` cpp to python. Just init the unicode `str` directly with `PyUnicode_FromString`.

With this diff, it's now faster than trunk for first access string list iter. Still slower for single index access, but this access pattern should be uncommon for lists. Int list iter also improved; now comparable with thrift-python.
