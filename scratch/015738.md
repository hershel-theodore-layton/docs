The previous attempt fails when a readonly db is loaded with the old schema. Turns out the kSchemaVersion is not respected currently. When loading an existing db, the init code for the db still runs the CREATE TABLE statements for the entire db. This fails attempting to create the new module_membership table.

The new version has the following differences to the original diff:

- when loading an existing readonly DB, if the module_membership table is not present, then it is not created.
- otherwise, when creating a new DB the module_membership table is created. This can be overridden with the new setting FactsExcludeModuleMembership.
