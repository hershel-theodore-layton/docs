Commit title: Support optional qualifier for interface and abstract method parameters
Commit body:
Summary:
Hack has support for default values for function and method parameters. For example:
```
class C {
  public function foo(string $s, int $i = 0, bool $b = false):void { }
}
```
Strangely, Hack allows default values for parameters in interface methods and abstract methods, but the value is ignored. It really just flags that any implementation of the abstract method should provide a default value for the parameter - and there is no check that the value agrees with the one specified in the abstract method.
Recently we introduced [optional parameters in function type hints](https://fb.workplace.com/groups/hacklang.design/posts/7052899591468586). Now let's do the same for abstract method signatures. For example, we can define an interface that is implemented by the class `C` above:
```
interface I {
  public function foo(string $s, optional int $i, optional bool $b):void;
}
class C implements I {
  public function foo(string $s, int $i = 0, bool $b = false):void { }
}
```
Or we can define an abstract base class:
```
abstract class Base {
  abstract public function foo(string $s, optional int $i, optional bool $b):void;
}
class C extends Base {
  public function foo(string $s, int $i = 0, bool $b = false):void { }
}
```
Some boring details:
* It is not permitted to use `optional` in a non-abstract method (the existence of a default value for a parameter implies that the parameter is optional)
* It's illegal for a function to have an `optional` parameter precede a non-optional one
* It's illegal to combine `optional` with `inout`
* It's illegal to combine `optional` with `...`

For now, the Hack typechecker rejects use of `optional` on parameters unless `enable_abstract_method_optional_parameters=true` is specified in `.hhconfig`. That way, we can land the parser change in HHVM, and later enable the use of the feature in type-checking.

HHVM support is required for compatibility checks in overrides (to match existing checks when default values are specified), and for reflection, so that the `isOptional()` method on `ReflectionParameter` returns `true` for parameters marked `optional`.

Swayze run passes fine. https://www.internalfb.com/intern/hhvm/automator/workflows/144183/
