Commit title: Obtain Transport reference through GetTransport trait, instead of AsRef<dyn ...>
Commit body:
Summary:
I need this change in order to enable {D59920017}, which in turn unblocks {D59945283}.

Previously, Thrift client traits were implemented for more-specific client structs as follows (in simplified form). Given `service DerivedService extends BaseService`, we'd have:

```lang=rust
// service BaseService

pub trait BaseServiceExt<T> { ... }

impl<T, S> BaseServiceExt<T> for S
where
    S: AsRef<dyn BaseServiceExt<T> + 'static>,
{ ... }
```

```lang=rust
// service DerivedService

pub trait DerivedServiceExt<T> { ... }

pub struct DerivedServiceImpl<T> {
    parent: BaseServiceImpl<T>,
}

impl<T> DerivedServiceExt<T> for DerivedServiceImpl<T> { ... }

impl<T> AsRef<dyn BaseServiceExt<T> + 'static> for DerivedServiceImpl<T> {
    fn as_ref(&self) -> &(dyn BaseServiceExt<T> + 'static) {
        &self.parent
    }
}
```

The `AsRef` impl exists **instead of** needing `impl<T> BaseServiceExt<T> for DerivedServiceImpl<T>`. If BaseService contains *N* methods and there are *M* services that transitively extend BaseService, all *M* of those services' client structs implement the BaseService trait using just *N*+*M* total generated methods (*N* in `impl<T, S> BaseServiceExt<T> for S` + *M* `as_ref` functions) instead of *N*×*M* functions (*M* separate BaseService impls containing *N* methods each).

None of the client impls generated by the Rust Thrift compiler contain any borrowed data, so the `'static` bounds above haven't been an issue. But mocks *do* contain borrowed data, for example in the case of something like:

```lang=rust
let mut requests = Vec::new();

let client = example_mocks::new::<dyn DerivedService>();
client.foo.mock(|req| { requests.push(req); Ok(()) });
```

So `AsRef<dyn BaseServiceExt<T> + 'static>` is too restrictive of a bound. In order to relax this to `AsRef<dyn BaseServiceExt<T> + 'a>` in the bounds of `impl<T, S> BaseServiceExt<T> for S` (D59920017), the transport `&T` needs to be made available in a different way not involving the trait object, because `self.as_ref().transport()` would end up having the potentially shorter lifetime `&'a T` instead of the required one.
