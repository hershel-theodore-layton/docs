Summary:
This change does not change any behavior, but instead captures and documents existing behavior (as well as inconsistencies) for future work.

General principles:
1. At initialization time, arguments with `None` values should simply be ignored (i.e., as if they were not present).
2. When "updating" a struct, explicit presence of a `None` means "reset". For instance, the implementation of the call operator is equivalent to a "deep-copy" followed by an "update" operation.
3. For direct assignment (only supported by mutable API, obviously), `None` is treated as the actual value that is meant to be assigned, and therefore is only valid for optional fields. Attempts to assign `None` to non-optional fields must raise an error.
4. Keyword argument names MUST always be valid (regardless of their value).
