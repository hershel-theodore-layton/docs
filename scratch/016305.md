Commit title: Add faststats library for lock/wait free logging of histograms and rate counters
Commit body:
Summary:
This creates a new library in fbplatform called fast stats. The premise here is to create non blocking stats primitives such as distributions and rate counters that use lock/wait free semantics. Other stats library tend to use synchronized when doing accounting work. We see high lock contention in the push server on Bergamo machines (177 cores) for stats in both thrift and our server level stats.

This diff contains both distributions and rate counters.

Distributions are powered by HDR histogram. I've added a multi window distribution that has 1m, 10m, 60m and all time histograms. I've also included a single window distribution which contains a 1m histogram for those who want less memory consumption and only more performance. The histograms use HDR Histogram's recorder abstraction to do lock free recording. A background thread will take an interval snapshot every 10's and add the results to a circular buffer in each underlying histogram. In the case of the multi window histogram, it'll add this 10 second sample the ring buffer in the 1m, 10m 60m and all time histogram. The ring buffer is updated to ensure that old data is phased out as the time goes on. This means that samples older than the respective window will be lost. For example samples over 1 minute old will be phased out of the 1m histogram, samples over 10 minutes old phased out of the 10 minute histogram etc....

HDR Histogram uses large arrays to keep loss less samples up to a given precision. These underlying arrays take space up to a kilobyte in some instances. The ring buffers are kept small, on the order of 5-6 buckets which reduces time resolution but enables smaller footprints. Again we're trading of high time accuracy and memory for nonblocking high throughput.

The ExpMovingAverage uses alpha decay to track 1m, 10m and 60m rates, where the sliding time window implementation uses a ring buffer to increase per minute rate accuracy. They have different trade off's so I've included both to allow developers to use which one they please.
