Commit title: Case Type Bugs
Commit body:
Summary:
While we flatten a type, when we encounter types that are unresolved, we append them to the end of our queue.
This is an issue, because we also maintain a variable `curEnum` to determine whether we are currently in an enum. This is broken in the below when resolving `CT_0`.

```
case type CT_0 = CT_1;
case type CT_1 = CT_2;
case type CT_2 = A_4 | E_3;
type A_4 = C_5;
class C_5 {}
enum E_3: int { A = 42; }
```

q.push(CT_0)
 ---
q.pop(CT_0)
curEnum=false
q.push(CT_1)
 ---
q.pop(CT_1)
curEnum=false
q.push(CT_2)
----
q.pop(CT_2)
curEnum=false
q.push(A4)
q.push(E3)
 ---
q.pop(A4)
curEnum=true
q.push(C_5)
 ---
q.pop(E3)
curEnum=true
q.push(A)
 ---
q.pop(C_5)
curEnum=true \\ yikes, this is not inside an enum
