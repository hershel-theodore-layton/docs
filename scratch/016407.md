Commit title: no ub strict-aliasing violation in SpookyHashV2
Commit body:
Summary: Avoid possibility of ub strict-aliasing violation from unaligned loads in `SpookyHashV2` by using `memcpy` when unaligned-access is available to read individual 8-byte words at a time. It is not necessary to do this when unaligned-access is unavailable because the code already does a bulk `memcpy` of the entire span, and the code already does this because unaligned-access is unavailable. All modern compilers lower this 8-byte `memcpy` to a `mov` or `ldr` and do not emit actuall calls to `memcpy`. Benchmarked perf is neutral.
