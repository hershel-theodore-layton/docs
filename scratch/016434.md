Commit title: Avoid infinite recursion with mutually recursive case types
Commit body:
Summary:
Case types are lazily expanded, that is we only expand if need be in various type operations like subtyping (any others? What about array access and member access?). This puts us at risk of infinite recursion during those operations if we're not careful.

Unfortunately, the way we currently prevent infinite recursion is not bullet-proof against mutually recursive case types and this diff aims at fixing that.

In the case of an infinite recursion (see added unit test), the stack overflow looks something like: subtype calls into localize calls into union calls into subtype. (subtype -> localize -> union -> subtype -> ...). Both `localize` and `subtype` do type alias expansion, localize because that's where most type alias expansions happen, and subtype because it expands a case type at hand if need be. So to fix the infinite recursion, I'm threading a `Type_expansions.t` throughout the calls. (It's already used by localize to detect cycles and prevent infinite recursions).

For subtype, we add the `Type_expansions.t` to `subtype_env`. `union` does not have a `union_env`, so it's just an additional parameter. (A future diff will create a `union_env` param)
