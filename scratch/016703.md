Commit title: Remove virtual inheritance from Task/AsyncGenerator/ViaIfAsync
Commit body:
Summary:
First, note that the extended coroutine interface can be simplified:
 - I see no benefit to `getHandle()` being part of the virtual inteface. The code certainly gets shorter!
 - Remove `ExtendedCoroutineHandle::getPromise` -- it's is unused, and of dubious value.

After these simplifications, we're left with **only** `getErrorHandle`, which can be provided via a manual vtable, instead of an implicit one.

Why do this instead of e.g. marking `getErrorHandle` final on every child?
 - The main value of this is that it makes `TaskPromise` (and analogs) open for inheritance without making them polymorphic classes. Right now, they have to be marked `final` in order to enable the non-polymorphic compiler optimizations. The goal of inheritance, in turn, is to allow customized `Task`-like coros, such as for example the upcoming `SafeTask`.
 - A side benefit is that we get an explicitly optimized, 1-pointer "vtable" inlined in the class instance. I don't know if the compiler is allowed to elide this indirection on its own, but it certainly can't do better.

Note: While the #SLOC went up slightly, this is due to me adding more comments. IMO, the before/after code complexity is otherwise identical.
