Commit body:
Summary:
There are apparently some differences in how LLVM-15 vs 17 present some* templated type names in the DWARF ([post](https://fb.workplace.com/groups/llvm.gcc/posts/26762125333409395) investigating this).

This diff adds a check for LLVM version before trying to get the type associated with a name, in a test.

*Caveat: I didn't do this check for/try to fix up all arbitrary type names passed into `utils.Type` because apparently some types *can* be looked up with the namespace prefix in the inner template parameters in the DWP produced by LLVM 17, so it's not always consistent right now:
```
lldb hhvm
(lldb) script
lldb.target.FindFirstType("HPHP::VMFixedVector<HPHP::Func::ParamInfo>")
No value
lldb.target.FindFirstType("HPHP::CompactTaggedPtr<const HPHP::StringData>")
template<> struct TokenOrPtr<const HPHP::StringData> {
private
...
```

Thus, just updated a single test for now to unblock.
