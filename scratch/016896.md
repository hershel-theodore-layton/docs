Summary:
If the container size is larger than supported, it could lead to OOM errors in WWW.

Root cause of S442291 :  Thrift deserialization extension tried to deserialize a vector and attempted to reserve a Vec of 3,902,543,916 bytes. This triggered hhvm crash.

This diff adds 2 checks -
1. if the received size is larger than what's supported, then raise a warning ~~an exception instead of trying to reserve vec.~~
2. ~~If the size is within bounds,~~ only reserve 16k entries at a time instead of trying to pre-allocate the maximum specified size.
  a. This was already added in binary deserialization in D47927494.
