Commit title: Consolidate AsyncClient future_ and semifuture_ method implementations
Commit body:
Summary:
This change is no-op.

This diff merges the `future_*` and `semifuture_*` generated `AsyncClient` method implementations. Merging the two implementations allow us to implement `ClientInterceptor` dispatching only once and have it work for both.

Currently, they both implement different `RequestCallback` types and delegate to the unprefixed callback-based generated method variant. That API is impossible to build `ClientInterceptor`s for. After this change, they use the same `RequestCallback` type with the difference that `SemiFuture` is inline-safe (see `FutureRequest.h`).

The existing `SemiFutureCallback` implementations have been renamed with the `Legacy` prefix since Python + `thriftdbg` omniclients still use it. That will be cleaned up in a future diff.
