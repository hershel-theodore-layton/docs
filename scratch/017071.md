Summary:
Regarding: https://github.com/facebook/folly/issues/985.

The `dynamic::dynamic(Iter, Iter)` constructor is confusing since it can easily be used incorrectly. The PR gives this example of intended vs accidental use:
```
folly::dynamic data = folly::dynamic::object("key", "value"); // correct
folly::dynamic data = folly::dynamic("key", "value"); // incorrect
```

The incorrect example will compile because `char const*` is indeed an iterator. But the behavior in theory will be undefined and in practice will be unpleasant.

Add a new tagged constructor and a new static member factory function to forward to the tagged constructor.

Call-sites may begin migrating to the new forms. If they all migrate, the existing constructor may be removed.
