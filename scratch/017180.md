Commit title: Add option to set XBOX thread timeouts
Commit body:
Summary:
XBOX threads were deadlocking due to recursive calls and no timeouts.

Lets call HTTP requests "request" and Xbox requests "xbox". Also assume that there is only one xbox worker thread (the same thing will apply).
Here is how things happen right now:
1. Request begins in main worker pool
2. Request makes an xbox call (A) and starts waiting for it to complete
3. Xbox A begins in xbox worker pool, using up a thread
4. Xbox A makes an xbox call (B) and starts waiting for it to complete
5. Xbox B gets added to the xbox queue because the only available thread is used by A
(we are now in deadlock)
6. Request waits on Xbox A until its own request timeout, then fails with a timeout exception
7. Xbox A continues to wait on B until its timeout, then fails with a timeout exception
8. Xbox B finally starts to get executed, might finish or might also time out.

Basically new threads were queued until queue was full and max xbox threads running.  Because running threads were waiting on queued threads to complete, it deadlocked until the request died.  But the request dying doesn't clear the queue.

By having the option to set a TTL on queued xbox threads, we can virtually eliminate the possibility of running into this deadlock.

Default to the current behavior of it to no timeouts.
