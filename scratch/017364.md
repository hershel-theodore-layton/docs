Commit title: Fix soundness bug in localization
Commit body:
Summary:
When expanding type definitions with cycles (benign or otherwise), localization could produce error type variables without producing the corresponding error, allowing later typechecking to solve the variable to something specific. We change one of these cases to return mixed to stop code later on from making assumptions about the type definitions.

This change doesn't introduce any new soundness concerns, since the error type variable could have always been inferred to be mixed if that's what the system had wanted to do.

Where the bound was `supportdyn`, use `supportdyn<mixed>` instead of mixed. This introduces a new error under pessimisation in `test/typecheck/case_type/case_type_cyclic_new_type.php` where the `Recursive` bound on `Recursive` doesn't have a `supportdyn` wrapper.  This used to pass because the error type var could unify with `supportdyn<mixed>`.
