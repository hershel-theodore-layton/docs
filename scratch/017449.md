Summary:
Currently here is the dependency graph

DynamicPatch --> AssignPatch --> protocol/Patch.h

We want to re-implement protocol::Object based patch with DynamicPatch, but this will add create circular dependency (due to the new dependency protocol/Patch.h --> DynamicPatch).

Since DynamicPatch does not use AssignPatch, we can just move AssignPatch out of the dependency tree to break the circle.

Eventually we need to ask users to include `thrift/lib/cpp2/op/AssignPatch.h` explicitly if they want to use AssignPatch. For now, to avoid breaking existing code, we will still include it in the generated patch headers.
