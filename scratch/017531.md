Commit title: Open tuples: parsing
Commit body:
Summary:
Implement parsing (direct-decl and in lowerer) for optional and variadic components in tuples. The basic element of a tuple now looks like
```
tuple_type_element ::= [optional] hint [...]
```
i.e. an optional `optional` keyword preceding a hint, preceding an optional ellipsis. In a tuple type, `optional` and `...` cannot appear together, `...` can only appear at most once, in the last element, and an optional element cannot precede a required element.

The `<<file: __EnableUnstableFeatures('open_tuples')>>` attribute must be used to enable the feature.
