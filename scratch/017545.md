Commit title: move types and constants into sub folder
Commit body:
Summary:
move types and constants into sub folder
This way the thrift library and the generated go code can reference these types
Then we can import generated code into the type library without causing a circular dependency

I chose the name "types" for the package to contain all the types and constants, but I am open to another name.

These are examples of the things that were moved to the types folder
```
thrift.ZERO
thrift.PrependError
thrift.Int8Ptr // and other Ptr functions
thrift.STRING, thrift.BOOL // and other contants
thrift.RequestChannel
thrift.Protocol
thrift.NewSerialChannel
thrift.ClientInterface
thrift.ProcessorFunction
thrift.Processor
thrift.Decoder
thrift.Struct
thrift.Exception
thrift.WritableStruct
thrift.Encoder
thrift.REPLY
thrift.ApplicationException
thrift.NewApplicationExceptionCause
thrift.INTERNAL_ERROR
thrift.STOP
thrift.Type
```
They are also temporarily aliased in thrift/alias.go so as not to break code.
We can then slowly remove these and only alias the necessary ones.

In `go.bzl` we also remove the option that was passed to the thrift generator
```
- opts = {
-   "thrift_import": "thrift/lib/go/thrift",
- }
```

And also updated the generated buck file to depend on the new package, instead of thrift
```
- out_deps.append("//thrift/lib/go/thrift:thrift")
+ out_deps.append("//thrift/lib/go/thrift/types:types")
```

And we also rename the import in the generator from `github.com/facebook/fbthrift/thrift/lib/go/thrift` to `github.com/facebook/fbthrift/thrift/lib/go/thrift/types`. This import is aliased, so we did not need to change any of generated code right now. Although we can definitely consider this in future.

## Mocks

Also if you are mocking something on thrift that has been moved to types, like `RequestChannel`, `Struct`, etc. then you now need to add `//thrift/lib/go/thrift/types:types` to your `deps`.
