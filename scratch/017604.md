Commit title: Add new shape field kind
Commit body:
Summary:
Shapes currently have 2 field name kinds
- literal string
- class consts
  - C::class
  - C::X

> and a 3rd int kind conjured by Regex::match. Literal int shape keys like shape(1=>2) are parser errors.

Shapes are statically enforced to be homogeneous in their key kinds.

This diff aims to separate out `C::class` and `C::X` by introducing a new "classname" field kind that will be a sink for `nameof C`. An `SFclassname` must go through namespacing, like `SFclass_const` and unlike `SFlit_str`.

The emitter will treat SFclassname like a nameof, i.e. a string, so incremental migration will simply eliminate implicit conversion.

For typing, we will use the `SFclass_const` with a conjured "::class" const, which admits incremental migration between a `C::class` key and `nameof C`. Later, and given a correctly specified transformation to the runtime name, we can move to `SFlit_str`.

Expanded handwritten comparators to hopefully be more readable.
