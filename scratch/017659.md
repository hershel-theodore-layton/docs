Commit title: Implement 'legacy' mode for extended reasons & create baseline tests
Commit body:
Summary:
Using extended reasons during typing/subtyping but not during reporting changes the baseline error due to the special-casing introduced when not using extended reason:

1) In several places we use the `if_unsat` combinator which reports the subtyping failure at the parent type

2) when typing constructors we use the special-case `contravariant_generic` and `invariant_generic` reasons

3) we 'postprocess' errors involving dynamic when sound dynamic is enabled adding the `Not_sub_dynamic` reason.

This diff adds a new 'legacy' option for extended reasons which exercises this behavior and adds tests to track these differences
