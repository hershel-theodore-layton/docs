# Motivation

We want to define functions that are *polymorphic in arity*, as below:
```
function callTwice<TArgs as (mixed...)>((function(...TArgs):void) $f, ...TArgs $args): void {
  ($f)(...$args);
  ($f)(...$args);
}
function foo(int $x, string $y):void {
  // whatever
}
function testit():void {
  callTwice(foo<>, 3, "A");
}
```
There are two distinct but co-operating features here: open tuples (written `(mixed...)`) and type splatting (written `...Targs`).

# Syntax and restrictions

The syntax of a type splat parameter is an ellipsis followed by a type e.g. `...T`.

The splat syntax may be used only in a parameter declaration (function or method) or in the parameter position of a function type hint.

Additionally
* A type splat may only appear as the last parameter of a function or function type.
* It may not be preceded by optional or variadic parameters, or parameters with default values.
* It may not have an `optional` or variadic (trailing ellipsis) annotation.
* It may not have a `readonly` or `inout` annotation.

These restrictions ensure that the “required precedes optional precedes variadic” invariant for open tuples and parameters is preserved under expansion of a splat.

The feature is currently experimental and must be enabled by writing `<<file: __EnableUnstableFeatures('open_tuples', 'type_splat')>>` at the top of a file.
