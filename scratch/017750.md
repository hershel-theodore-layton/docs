Summary:
# Context:
EdenFS has some very specific shutdown requirements - continue processing any queued requests after stopping. We call
`setStopWorkersOnStopListening(false)` and `leakOutstandingRequestsWhenServerStops(true)` when creating our Thrift server. Until recently this all worked fine. A recent set of changes resulted in the tear down of some state this is needed for these requests to successfuly be processed.

In fact, we crash now. The crash is located here: https://www.internalfb.com/code/fbsource/[9d5d9ac47838]/fbcode/thrift/lib/cpp2/server/ThriftServer.h?lines=2846-2847. This is caused because when exiting `serve` `processedServiceDescription_` is reset - https://www.internalfb.com/code/fbsource/[e9abe470e6647a23d8e0e9bcd26289c1b1f594ff]/fbcode/thrift/lib/cpp2/server/ThriftServer.cpp?lines=1501 and then later accessed as part of processng the queued requests.

# This Diff:
Makes changes to `getServiceInterceptors()` to return an empty list when `processedServiceDescription_` is `nullptr` and related change to where `shouldProcessServiceInterceptorsOnRequest()` is invoked - allowing it to return `false` rather than `DCHECK` failing.
