Note that `MqttThriftHeader` does not have float types, it has two strings, so readFloat indicates bad input data in this case.  All threads appear to be spinning in this method. The only espace from `read0` is if we get a and end struct byte.

```
while(true) {
            TField __field = oprot.readFieldBegin();
            if (__field.type == 0) {
                oprot.readStructEnd();
                return builder.build();
            }
```

End struct is read in `readFieldBegin` with the following code
```
    byte type = readByte();

    // if it's a stop, then we can return immediately, as the struct is over.
    if (type == TType.STOP) {
      return TSTOP;
    }
```

For this implemenation readByte() is implemented as follows

```
  public byte readByte() {
    read(Byte.BYTES);
    return buffer[0];
  }

...

  private void read(int length) {
    try {
      inputStream.read(buffer, 0, length);
    } catch (IOException e) {
      throw Exceptions.propagate(e);
    }
  }
```

When the end of an InputStream is reached, the return value will be -1. If this is the case, `read(int length)` returns successfully and `readByte()` returns `buffer[0];`. Buffer will be left over data from the previous read. In our case it appears the `buffer[0]` value get's coerced in the `Type.FLOAT`. This triggers the `read0` method to enter the `skip` method and continue reading. All future reads result in the same data from the last successful read, causing  an infinite loop. We believe this is malformed data from some bad client that MQTT is talking too.

This diff adds a boundary condition to ensure that if we attempt to read past the end of the `InputStream` that we throw an exception. This is roughly equivalent to how the `AbstractByteBuf` implementation works, where it checks to ensure that when `readByte()` is called that the bytes actually exist.

```
    public byte readByte() {
        checkReadableBytes0(1);
        int i = readerIndex;
        byte b = _getByte(i);
        readerIndex = i + 1;
        return b;
    }
```
