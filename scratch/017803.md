Commit title: support multifile tests in PackageV2
Commit body:
Summary:
PackageV2 matches file paths against `include_path` in the PACKAGES.toml file.  Multifile tests mangle filenames by prepending the global .php filename to all the file names in the multifile tests.

This diff:
- adds a global option `package_v2_support_multifile_tests`; when set to true package matching in `get_package_for_file` attempts to strip the multifile prefix from the file name.  The option is intended to be used only by `hh_single_type_check` runs in the hack package test suite.  Tests can now be expressed naturally, as in eg. `unrelated_package_path.php` and `nested_package_path.php`.

- since files defined in multifile tests do not exist as standalone files, `hh_single_type_check` does not check anymore the validity of paths in PACKAGES.toml files.  Path validity in `PACKAGES.toml` files is still checked by `hh` and `hhvm`.  This enables cleaning up the test suite and delete the fake `cross_package_access_internal1.php--foo.php`, `illegal_cross_package_call_to_tests.php--__tests__.php`, `illegal_cross_package_basic.php--foo.php` files.
