Commit title: Error ordering: Redo D43774369 but preserve ordering by phase rather than error code
Commit body:
Summary:
D43774369 aimed at making error ordering stable. Before that diff, the comparison function was comparing error phases ( = code / 1000) then by position in the file, but was never comparing codes, leading to non-deterministic ordering (as there are errors which are identical but with different codes, apparently!). The way D43774369 fixed that was to compare by code instead of phase, but that effectively changed the ordering of errors: errors would be compared by code first, then by position in the file, which is counter-intuitive: we'd want to compare errors by positions first before ordering by code.

So with this diff, I'm restoring the initial ordering (first by phase then by position), while still making the ordering stable. I do the latter by adding a final comparison by code in `compare_internal`. I'm also preserving the same deduplication behaviour, which disregards codes.

This also allows to simplify the signature of `compare_internal`.
