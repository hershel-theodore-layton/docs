Commit title: Use poll instead of select when calling processes
Commit body:
Summary:
In the past, we've hit the issue several times that the `select` syscall can only take file descriptors lower than 1024. hh_distc uses thousands of TCP connections, therefore calling select after calling into distc reliably causes EINVAL.

Quoting `select` man page:
> WARNING: select() can monitor only file descriptors numbers that are less than FD_SETSIZE (1024)—an unreasonably low limit for many modern applications—and this limitation will not change. All modern applications should instead use poll(2) or epoll(7), which do not suffer this limitation.

This diff allows to call `poll` instead of `select`. The new API around `poll` is in Sys_utils.Poll, and for now it contains these functions, based on how we commonly use select throughout the codebase:
```
  val wait_fd_read :
    Unix.file_descr -> timeout_ms:int option -> (bool, Flags.error list) result

  val wait_fd_read_non_intr :
    Unix.file_descr -> timeout_ms:int option -> (bool, Flags.error list) result

  val wait_fd_write :
    Unix.file_descr -> timeout_ms:int option -> (bool, Flags.error list) result

  val wait_fd_write_non_intr :
    Unix.file_descr -> timeout_ms:int option -> (bool, Flags.error list) result
```
We use `wait_fd_read_non_intr` in `Process.maybe_consume`, since that one was at the origin of a recent SEV. We shall convert other calls to `Unix.select` and `Sys_utils.select_non_intr` in the future.
