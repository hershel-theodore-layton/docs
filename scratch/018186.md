Commit title: Ensure that InputStreamByteBuf reads expected number of bytes
Commit body:
Summary: The input stream API has the following api, `read(byte[] b, int off, int len)`, where 0-N bytes will be copied into the buffer b, where N <= length. They key here is that up to `len` bytes can be copied, but it’s not guaranteed. In the event that we don’t read up to `len` bytes we see that the thrift serializer throwing exceptions. This is because in some cases it never finished reading a field because the underlying input stream didn’t return enough bytes. This manifests with the snappy compression stream. Some teams use snappy compression around the thrift encoding to compress payloads. Snappy seems to only return up to ~32kb per read call. Payloads larger need to call `read(...)` multiple times to get entire binary payload fields. This diff ensures that all bytes up to `len` have been read and ensures the buffer is full before returning to the thrift codec.
