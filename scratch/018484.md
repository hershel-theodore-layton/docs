Commit title: Store package in aast_defs + decls under package_v2
Commit body:
Summary:
**High-level goal**: we're trying to store the name of the package a symbol belongs to in its aast+decl representation, so that we only calculate its package membership once at parse time. Currently, this calculation is performed every time a symbol is getting referenced at typecheck time.

**This diff**:
- Currently we're storing `package_override` in decls (fun, typedef, class). Augment the value of `package_override` to be the symbol's package altogether, whether it's determined from `get_package_for_file` or `__PackageOverride`. Note that since this diff is already too big with the aast changes, I'm renaming the `package_override` field in decls in the next diff (D64450663)
- It's not sufficient to only know the package for the target symbol being referenced, but also that for the current symbol. This requires storing package in the aast_defs for fun, typedef, and class as well
- In the lowerer and the direct decl parser, call `get_package_for_file` on each symbol and store the result
