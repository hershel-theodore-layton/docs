Commit title: 1/[thrift][compression] Add `CompressionAlgorithm` variants.
Commit body:
Summary:
Adds support for `LZ4` compression, along with `_LESS`, and `_MORE` variants of all compression algorithm enums.

With this, thrift supports ZLIB, ZSTD, and LZ4 compression. All three compression algorithms utilize folly compression codecs. The `_LESS` variants (`ZLIB_LESS`, `ZSTD_LESS`, `LZ4_LESS`) compress less, but also use less CPU and memory. The `_MORE` variants (`ZLIB_MORE`, `ZSTD_MORE`, `LZ4_MORE`) compress more, but also use more CPU and memory.

Unit tests fore new and existing Compression implementation is also added.

`apache::thrift::rocket::compressBuffer` is added. The API matches more closely to `apache::thrift::rocket::uncompressBuffer` than the existing `apache::thrift::rocket::detail::compressPayload`. The existing API is now marked deprecated.

`apache::thrift::rocket::detail::compressPayload` is deprecated in favor of `apache::thrift::rocket::compressBuffer`.

Meta:

Calls to the now-deprecated `apache::thrift::rocket::detail::compressPayload` will be removed in the next diff in this stack.

The decision to add the `_LESS` and `_MORE` variants to the `CompressionAlgorithm` enum is a trade-off. Ideally, we would not add any of these variants to the `CompressionAlgorithm` enum, and we'd be able to reliably capture the `CodecConfig` settings from a `RequestRpcMetadata`. Unfortunately, the complex interactions between HeaderChannel, PayloadUtils, PayloadSerializer, SerializedRequest, and other object I'm forgetting about made it difficult to carry `CodecConfig` through and be 100% sure that nothing would break. By packing the compression level information into the `CompressionLevel` algorithm, we can be certain that none of the intermidiate logic is affected.

`CompressionAlgorithm` is an enum that is only used internally in Thrift, giving us the ability to completely deprecate it once we feel it is safe to do so.

External users that wants to set compression level will use the `ZstdCompressionCodecConfig`, `Lz4CompressionCodecConfig`, etc. structs. `levelPreset` settings are the actual, intended user-facing part of the `RpcMetadata`.
