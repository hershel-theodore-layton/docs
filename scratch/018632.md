Summary:
Context: S464000
> The root cause is that at the server startup time, the parser options get copied out of Hack's global options into a separate entity within the server environment, and the legacy package code registered package information after this fork. Now inside the server we have (1) parser options (2) typechecker options (which is really just global options and encompasses parser options), and only the latter is passed on to the remote typechecking service. D64265328 moved package information from typechecker options to parser options, and because of the way package v1 infra registered package information, it ended up in (1) instead of (2) and was never threaded through to the remote typechecking service

This diff loads package info as soon as hhconfig is read, and stores it inside the first creation of global options, so it's not prone to any options decoupling down the line.
