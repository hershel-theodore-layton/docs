Commit title: Support internal priority within RoundRobinRequestPile
Commit body:
Summary:
Currently `InternalPriorityRequestPile` implements prioritization for existing interactions by creating two `RoundRobinRequestPile`s, one for new interactions and non-interaction requests and another for existing interactions, always preferring to dequeue from the existing interaction RequestPile first.

This results in two problems:
1. When using priorities within `RoundRobinRequestPile` itself (eg. using `ThreadManagerType::PRIORITY_QUEUE`), **all** interaction continuations would be prioritized over non-continuations, even if there is a regular request with higher priority enqueued. For example, if there is a regular request with HIGH priority and an interaction continuation with BEST_EFFORT priority, the continuation would be executed first.
2. DLS doesn't use `InternalPriorityRequestPile`. If we simply wrap the DLS `RoundRobinRequestPile` inside an `InternalPriorityRequestPile` we end up with the same problem as #1.

To fix this, we move the logic of internal priority within `RoundRobinRequestPile` itself by doubling the number of priorities specified if the service is using interactions.

Pending follow ups:
- Update DLS to use `addInternalPriorities`
- Delete `InternalPriorityRequestPile`
