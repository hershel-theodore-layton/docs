Commit title: support for PackagesV2 ActiveDeployment at repo compile time
Commit body:
Summary:
In PackagesV2  the set of files belonging to a package is specified using directory globbing in `include_path` fields of the package specification and per-file `PackageOverride` attributes.

This diff makes the Repo compiler aware of the PackageV2 specification and updates the `shouldIncludeInBuild` compiler check to obey the PackageV2 package specifications when an ActiveDeployement is set.

In detail:
- the `PackageV2` compiler option is added; when set to true the compiler expects a PackageV2 compiler specification rather than older package specification (which, in the long term, won't be supported anymore);

- updates the `compiler.cpp` handling of `PACKAGES.toml` files to support the `include_paths` package specification.
  -  Given a `PACKAGES.toml` file and an ActiveDeployment, all `include_paths` of all packages are sorted wrt path inclusion and a map `include_path -> isInTheActiveDeployment` is built.  The `default` package includes all files that do not match an `include_path` or have a `PackageOverride` attibute, so the root path is added last to the map, with a `isInTheActiveDeployment`field set to `true`.
  -  When PackageV2 is enabled, `shouldIncludeInBuild`:
      - checks if the file has a PackageOverride attribute.  If yes, it checks if the overridden package belongs to the ActiveDeployement; otherwise
      - it performs a linear scan of the current file name against the sorted include paths and once a match is found the corresponding `isInTheActiveDeployment` field is used to decide if the file belongs to the build or not.
