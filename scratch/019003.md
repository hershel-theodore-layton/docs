Commit title: Add virtual dtors to ensure vtable emission and make dynamic_cast happy
Commit body:
Summary:
https://fb.workplace.com/groups/474291069286180/permalink/27360979140190675/

The set of classes defined in fbcode/thrift/compiler/ast/ are pure headers or they are classes which don't define a "key function". The result is no vtable is emitted, and dynamic_cast using these classes fails to work under the following conditions:
- the ast set of classes is being referenced cross dylib boundaries. fbcode/mode/mac will activate the build layout to be dylibs, so this readily exposes this issue.
- pika or xbat based on a newer LLVM is used. This issue does not surface for the older Minimal Xcode toolchain.

Repro:
```
buck2 build fbcode//mode/mac fbcode//smart/edge_cloud/ecod_push_node:validate
```

The following is the bare minimum based on:
- https://www.internalfb.com/code/fbsource/[2f10a9c4055e50bf2f18c1367aabd633390755eb][history]/fbcode/thrift/compiler/ast/ast_visitor.h?lines=179-189
- https://www.internalfb.com/code/fbsource/[2f10a9c4055e50bf2f18c1367aabd633390755eb][history]/fbcode/thrift/compiler/sema/check_initializer.cc?lines=64-76

Use of dynamic_cast to the ast/ classes is actually more widespread so in addition to the ast classes affecting `ecod_push_node:validate`, we also have classes listed in P1677944873 that use dynamic_cast.
