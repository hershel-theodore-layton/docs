Commit title: fix CLI error streaming during first typecheck
Commit body:
Summary:
Before this diff, error streaming would simply not work for the first typecheck of hh_server, i.e. when running `hh` after stopping the server, the first typecheck would not stream errors, but subsequent typechecks would.

Sequence of event when running hh after `hh stop`:
* we enter ClientCheckStatus.go_streaming
* we realize the errors file is absent, so we run connect_then_close to start hh_server
* connect_then_close runs ClientConnect.connect which deals with starting hh_server.
* In there, if `do_post_handoff_handshake` is true, we wait for a hello message from the server.
* Because of the broken way hh_server deals with incoming messages from client, that "hello" will only be sent at the end of the first typecheck.
* once we receive hello, we can exit connect_and_close and start streaming, at the end of typecheck!

Our fix is to not wait for "hello" when streaming errors by setting `do_post_handoff_handshake` to false.
