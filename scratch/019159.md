# What?
`arc pyre check thrift/lib/python/...` failed with the errors below

```
Type errors in target fbcode//thrift/lib/python/test:adapter_thrift-python-types
../buck-out/v2/gen/fbcode/3cc3cae8ebb1ba74/thrift/lib/python/test/__adapter_thrift-python-adapter.thrift__/out/gen-python/python_test/adapter/thrift_mutable_types.pyi:32:23 Parsing failure [404]: invalid syntax
../buck-out/v2/gen/fbcode/3cc3cae8ebb1ba74/thrift/lib/python/test/__adapter_thrift-python-adapter.thrift__/out/gen-python/python_test/adapter/thrift_types.pyi:17:23 Parsing failure [404]: invalid syntax
```

The reason it failed was because `buck-out/v2/gen/fbcode/3cc3cae8ebb1ba74/thrift/lib/python/test/__adapter_thrift-python-adapter.thrift__/out/gen-python/python_test/adapter/thrift_types.pyi` had the import below.

`import typing.Sequence[typing.Sequence[typing`.

# Why?
The imports above were generated by an function that extracts module paths from a given type-hint. The function just looked for the last `.` in the string and returned the string upto that `.`. This works for simple type-hints like `module.path.typename`. The type-hint that caused the failure was `typing.Sequence[typing.Sequence[typing.Mapping[str, int]]]`. The search of the last `.` and the subsequent extract results in `typing.Sequence[typing.Sequence[typing`, which is what you see above.

# Fix
Add logic to look for generic types that have a `[` and return a set of module paths rather than a single one.

# Side-effects
This fix exposes type errors that were hidden due to the failure to parse the type stubs with the issue this change fixes. Add `pyre-fixme` as necessary to land this diff independent of the changes needed to fix those error. Subsequent changes will fix those errors.
