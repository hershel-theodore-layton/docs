Commit title: Call optimize_edges() before corrupting the state it uses
Commit body:
Summary:
optimize_edges() attempts to simplify the next() and taken() branches from the
block being optimized, using the next/taken out state from the analysis phase.
It doesn't otherwise use the current block.

Currently, we first optimize instructions of the current block. This might
optimize the last instruction and change the meaning of next() and taken()
branches. For example, if CheckLoc always passes the type and takes the next()
branch, it would get replaced with Jmp and take its taken() branch. We also run
inline simplification that might perform arbitrary CFG changes. Consequently,
this makes usage of next/taken out state from the analysis pass unsound.

Fix this by calling optimize_edges() before the optimize_inst() loop.
