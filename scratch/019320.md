Commit body:
Summary:
When streaming errors, we start with keep_trying_to_open, which sill keep trying to open the errors file until it find a satisfying one. There are cases where it finds an errors file, but that file isn't good, e.g. the server has died since, or the watchman clock is too old. In that case, it will retry. This diff makes it so that it'll retry until a different file is seen.

Prior to this diff, we'd rely on the already seen watchman clock to determine whether to retry or not. However, this new way relies on the file inode and ctime. This is more reliable in the case where we'd retry because the server had died. Before this diff, when opening an errors file from a defunct server, we'd start hh then retry ([here](https://www.internalfb.com/code/fbsource/[a8e991fad44ca85feba620c2fda72a1486266358]/fbcode/hphp/hack/src/client/clientCheckStatus.ml?lines=565-572)), then immediately fall into [this branch](https://www.internalfb.com/code/fbsource/[a8e991fad44ca85feba620c2fda72a1486266358]/fbcode/hphp/hack/src/client/clientCheckStatus.ml?lines=573) which would exit, because the new server would not have time to recreate a new errors file.
