Commit title: Make class <: classname subtyping a separate relation
Commit body:
Summary:
Similar to `<D:` dynamic-aware subtyping, where we want `T <: dynamic` depending on context, I'd like to exclude the rule `class<C> <: classname<C>` (implicit in the rewrite rules) when doing well-formedness checks on types -- specifically, along bounds of generics. If a generic is `T as string` or similar, when checking an instantiation, do not allow `class<C> <: string` by rewriting to `classname<C> <: string`.

It will still be possible to have a locl ty `dict<class<C>, mixed>` (and separate tast checks will seek to ban insertion of `class<C>` into a dict), but we will prune the "bad type" at a type hint boundary, requiring `dict<classname<C>, mixed>`.
