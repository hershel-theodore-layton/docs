# Overview

To reduce build-time, this diff moved the instantiation of `patch(...)` to the generated patch cpp file.

# Implementation

Today we have `patch(...)` template method:

```
template<...>
class BaseEnsurePatch {
  // ...
 public:
  template<class Id>
  decltype(auto) patch() { ... }
};
```

Since we already have codegen for each thrift file to generate .h file, we can also generate .cpp file and extern `patch(...)`, e.g.,

```
// generated module.thrift.h

// extern the template so that users won't instantiate it.
extern template decltype(auto) StructPatch<MyStructPatchStruct>::patch<ident::field_1>();
extern template decltype(auto) StructPatch<MyStructPatchStruct>::patch<ident::field_2>();
// ...
```

```
// generated module.thrift.cpp

// instantiate in the dedicated .cpp file so that we only instantiate once (vs in every callsites)
template decltype(auto) StructPatch<MyStructPatchStruct>::patch<ident::field_1>();
template decltype(auto) StructPatch<MyStructPatchStruct>::patch<ident::field_2>();
// ...
```

However, the approach above won't work -- the `MyStructPatchStruct` is an incomplete type in the header, in which case C++ compiler cannot deduce the return type and the `StructPatch<MyStructPatchStruct>` cannot be instantiated.

The reason `MyStructPatchStruct` has to be incomplete type is that `module_types.h` will include `module.thrift.h`, not the other direction.

To fix this, we will need to modify the implementation a bit and introduce a type-erased layer that can be extern

```

template<class Id, class Patch>
void* typeErasedPatchImpl(Patch& patch) {
  return reinterpret_cast<void*>(&patch.patchImpl<Id>());
}

template<...>
class BaseEnsurePatch {
  // ...
 public:
  template<class Id>
  decltype(auto) patch() {
    using ReturnType = decltype(patchImpl<Id>());
    void* ret = typeErasedPatchImpl(*this);
    return *reinterpret_cast<ReturnType*>(ret);
  }

  template<class Id>
  decltype(auto) patchImpl() { ... }
};
```

So that we can extern `typeErasedPatchImpl` instead:

```
// generated module.thrift.h
extern template void* typeErasedPatchImpl<ident::field_1>(StructPatch<MyStructPatchStruct>&);
extern template void* typeErasedPatchImpl<ident::field_2>(StructPatch<MyStructPatchStruct>&);
// ...
```

```
// generated module.thrift.cpp
template void* typeErasedPatchImpl<ident::field_1>(StructPatch<MyStructPatchStruct>&);
template void* typeErasedPatchImpl<ident::field_2>(StructPatch<MyStructPatchStruct>&);
// ...
```

BTW the reason it is free function is avoiding the instantiation of `StructPatch<MyStructPatchStruct>`. If it's a member function, C++ will still try to instantiate `StructPatch<MyStructPatchStruct>`;

# Why do we need `intentionally_unimplemented_function(...)`?

The problem of the code above is that not all fields are patchable. e.g., cpp.ref fields are not patchable (`patch<ident::cpp_ref_field>()` will fail to build).

While in patch's thrift file codegen, we knew whether fields are patchable, but we don't have this information when generating patch's .h and .cpp file.

To avoid duplicating the logic, this diff just instantiated all fields and introduced `intentionally_unimplemented_function(...)` to avoid build failure, e.g.,

```
template<class Id, class Patch>
void* typeErasedPatchImpl(Patch& patch) {
  if constexpr (patchable<Id>) {
    return reinterpret_cast<void*>(&patch.patchImpl<Id>());
  } else {
    return intentionally_unimplemented_function();
  }
}
```

# Why do we need `only_defined_in_generated_patch_cpp(...)`?

Functionality wise, we don't need it (we can delete it and everything still works). This gives us the guarantee we did not instantiate `patchImpl<id>()` on the user side accidentally (i.e., we always instantiate `patchImpl<Id>()` in the generated cpp file).
