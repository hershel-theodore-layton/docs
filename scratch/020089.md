Commit title: Various fixes for recursive case types
Commit body:
Summary:
Fixes a few issues with the (not yet shipped) recursive case types feature:

 - Recursive case types shouldn't be enforceable in is/as positions (the enforcement as implemented would cause C++ stack overflows with deeply nested structures).
 - The recursive union type structure was dropping generic parameters when it should be preserving them in a `generic_types` field.
 - Recursive structures featuring type aliases could fail to resolve if resolution is started at the case type rather than the type alias.
 - HHBBC is sometimes able to resolve part but not all of a set of types comprising a recursive structure. In these cases if runtime resolution reuses the precomputed result from HHBBC it can end up with a non-canonical structure that recurses more deeply than in the purely runtime resolved equivalent
