Commit title: Fix: Adapter type-hint double adapts.
Commit body:
Summary:
Consider [this struct](https://fburl.com/code/h7b4s73u):
```
python.Adapter{
  name = "one.AdapterOne",
  typeHint = "typeshed_one.AdapterOneType[]",
}
struct B {}
```

The generated code for this struct looks like

```
class _fbthrift_unadapted_B(... elided ...):
    ... elided ...

B = typeshed_one.AdapterOneType[_fbthrift_unadapted_B]
```

Consider [this code](https://fburl.com/code/0fxeqgnv), which uses the above struct.

The (incorrectly) [generated code](https://fburl.com/code/vub66bgy) looks like:

```
import b.thrift_mutable_types as _fbthrift__b__thrift_mutable_types

class MyStruct(_fbthrift_python_mutable_types.MutableStruct, _fbthrift_compatible_with_MyStruct, _fbthrift_python_abstract_types.MyStruct):
    property
    def a(self) -> typeshed_one.AdapterOneType[_fbthrift__b__thrift_mutable_types.B]: ...
```
Notice the return type is `typeshed_one.AdapterOneType[_fbthrift__b__thrift_mutable_types.B]`.  As you can see from the definition of `B' above,`B = typeshed_one.AdapterOneType[_fbthrift_unadapted_B]`, that the template parameter is already adapted. Therefore, `typeshed_one.AdapterOneType[_fbthrift__b__thrift_mutable_types.B]` is a template instantiation of an already instantiated template, which is incorrect. This happens because the mustache template (I know, too many templates here), is effectively `adapter_type_hint[adapted_type]`, which results in the incorrectly rendered type in the generated code.

# The fix
The correct return type is `_fbthrift__b__thrift_mutable_types.B`, which resolves to `typeshed_one.AdapterOneType[_fbthrift__b__thrift_mutable_types._fbthrift_unadapted_B]`, which is equivalent to `adapter_type_hint[unadapted_type]`.
