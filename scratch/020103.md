# The Problem
Consider [this struct](https://fburl.com/code/h7b4s73u):
```
python.Adapter{
  name = "one.AdapterOne",
  typeHint = "typeshed_one.AdapterOneType[]",
}
struct B {}

```
The [generated code](https://fburl.com/code/vub66bgy) looks like:

```
import b.thrift_mutable_types as _fbthrift__b__thrift_mutable_types

class MyStruct(_fbthrift_python_mutable_types.MutableStruct, _fbthrift_compatible_with_MyStruct, _fbthrift_python_abstract_types.MyStruct):
    property
    def a(self) -> typeshed_one.AdapterOneType[_fbthrift__b__thrift_mutable_types._fbthrift_unadapted_B]: ...
```
The implementation leaves `typeshed_one.AdapterOneType[]` as invariant i.e. it specififies neither `covariant = True` nor `contravariant = True`. This implies  `typeshed_one.AdapterOneType[_fbthrift__b__thrift_mutable_types._fbthrift_unadapted_B]` is invariant, which leads to inconsistent override errors between the type in the abstract base class and the derived classes.

# The solution
Categorize these types as invariant, which will then remove any abstract members that use these types.
