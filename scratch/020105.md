Commit body:
Summary:
This introduces `dsl::polymorphic_native_handle<Base, SubClasses...>` which can be used in conjunction with `dsl::function` to extract arguments of polymorphic types.

## Why is polymorphism needed?
Thrift AST (`t_*` types), for example, `t_type`, `t_primitive_type`, `t_enum`, `t_struct` etc... use v-table-based polymorphism in C++. `dynamic_cast` is often needed for this pattern of code. Since we will need to work with these types quite often in Whisker, we want good support for polymorphic types.

## Why not `dynamic_cast`?
Since the `native_handle<>` stored in `whisker::object` is type-erased, we cannot use the "magic" of `dynamic_cast` (although the [itanium C++ ABI could certainly achieve that even with `std::type_info`](https://github.com/gcc-mirror/gcc/blob/master/libstdc%2B%2B-v3/libsupc%2B%2B/dyncast.cc#L44-L48)). The solution is to enumerate (at compile time) all subclasses that we care about and compare exact `type_info`s. This will work with Thrift's AST types because they are more so `std::variant` rather than truly polymorphic types with unknown implementations.

## How will this be used?
See the next couple of diffs. Especially the one where we use it in `t_whisker_generator`.
