Commit title: Mark callable types made by `FOLLY_INVOKE_MEMBER`
Commit body:
Summary:
Up-stack, in `async_closure()`, I need to distinguish `FOLLY_INVOKE_MEMBER`s from other callables. The crucial difference is:
  - `INVOKE_MEMBER` guarantees that the first argument is the implicit object parameter.
  - An arbitrary callable, on the other hand, can have the implicit object parameter in position 15.

This makes a difference to `async_closure`'s memory-safety type check logic. Specifically:
  - If it sees an `INVOKE_MEMBER` callable, `async_closure()` **dereferences** the first arg before passing it to the callable.
  - If the argument order were different in a custom callable, the above algorithm might flat-out incorrect!

Secondarily, this simplifies the UX, since the error message for `async_closure` + `MemberTask` can explicitly tell users to use `FOLLY_INVOKE_MEMBER`.
