Summary:
## What

Start implementing https://fburl.com/hack-safe-abstract, specifically the [typing rules](https://fburl.com/hack-safe-abstract-concise)

The changes in this diff are to:
- introduce configuration to gate the feature
- introduce `concreteclassname<T>`, which is like `classname<T>`, except it indicates that we know `T` is not an abstract class.

## User impact

None, all behind a flag.

## Why

I'm doing a proof of concept implementation in order to get metrics and examples for WWW, in order to determine feasibility of the approach outlined in https://fburl.com/hack-safe-abstract.

## Choices
- Do not yet handle class pointers. So, in this stack, the features (safe abstract and class pointers) behave in a nonsensical way when used together.
     - Why:  It got too complicated to handle class pointers and class names at the same time. Instead, will do in future. And I may cheat in the near-term by (locally) codemodding away class pointers in WWW in order to get metrics.
