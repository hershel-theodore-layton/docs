## What

Add the `<<__NeedsConcrete>>` attribute from the proposal described in D69180811

## Internals

There weren't any unused bits in ClassElt flags. So I reused and renamed a bit. The packing is fine, since `readonly_prop` only applies to properties and `needs_concrete` only applies to methods. Thanks andrewjkennedy for suggesting this solution!

## User-facing

Nothing, behind a flag

## Follow-on

Use the attribute:
- use `__NeedsConcrete` in the safe_abstract_check tast check to ensure that `static` always refers to a concrete class in a `__NeedsConcrete` method: D69180812
- hierarchy check in D69055023
- There should probably be more restrictions on where `<<__NeedsConcrete>>` is allowed before we make this user-facing: T213971384
