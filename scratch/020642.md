This diff does two related things:

* ~~When the set of assumptions is FALSE drop the environment because this signifies the branch is impossible/dead -- this solves the issue where not updating the environment would result in contamination when this should-be-dead environment is later join with another cancelling out any refinements of type parameters in the other env.~~
* Handle like types differently from dynamic.
  * Presently, dynamic is stripped from like types before we do the GADT style logic for class refinement (refine_and_simplify_intersection in typing.ml https://fburl.com/code/eauqipn0). This isn't sound (T214130596) but it's not clear how to handle this as treating dynamic as a simply opaque type would, in many cases, simply result in not updating type parameters or generics during refinement.
  * So for now, the goal for this diff is to enable matching the current behavior where we still draw GADT-style conclusions ignoring the dynamic but only do so for like types and not for bare dynamic. We do this by:
    * Detecting unions with dynamic and stripping the dynamic.
    * We split the stripped type and put the dynamic back later assuming that the dynamic will end up in the span (which it would).
    * If we stripped the dynamic we don't drop the environment.

Some other finer details are annotated as inline diff comments.
