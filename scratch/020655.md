Summary:
Facts about thrift-python and thrift-py3 that no one wanted to know:
- `python.server.ThriftServer` extends on `py3.server.ThriftServer`
- `py3.server.ServiceInterface` extends `py3.server.AsyncProcessorFactory` and is the base of various py3 generated service interfaces
- `python.server.ServiceInterface` is the base of various python generated service interfaces
- meanwhile, `python.server.PythonAsyncProcessorFactory`:
  - extends the py3 `AsyncProcessorFactory`
  - composes the python `ServiceInterface`

Insofar as customer code uses `py3.server.ThriftServer` it will break in auto-migrate without some compatibility code to branch based on type info between `python.server.ThriftServer` and `py3.server.ThriftServer`. There are about 40 places this affects: https://fburl.com/code/aau6dgqy

As a first step, I wanted to enable basic test coverage, so I did the dumb obvious thing. Now we pass 19 of 21 cases in auto-migrate.

As a next step, I'll look at how to add some compatibility logic more centrally.
