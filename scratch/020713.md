Commit title: for fiber stack size, detect optimization v.s. debug
Commit body:
Summary:
Use `!defined(__OPTIMIZE__)` v.s. using `!defined(NDEBUG)` as the signal to multiply the default fiber stack size.

In non-optimized builds, the compiler emits object code which is not particularly careful about stack usage. For example, the compiler will typically assign every local variable a location on the stack (https://godbolt.org/z/xbnqdTasT), even when an optimization would keep that local variable entirely in a register.

Historically, it was common for us to have optimized ndebug builds and non-optimized, non-ndebug builds. So we used `!defined(NDEBUG)` as a heuristic for determining whether optimizations are enabled at all. But the signal that we really want is, for example,  whether or not the compiler always spills every local variable to stack rather than keeping some in registers.
