Commit title: Update random access benchmarks for associative containers
Commit body:
Summary:
The previous implementations for `SparseAccess` for map & set don't correctly capture the performance characteristics of associate containers.

Instead the benchmark now does the following:
* `SparseAccess:SingleRandom` will determine the first key of the container (order not guaranteed) & then perform a key-based lookup for that container
* `SparseAccess::Half` will now collect a set of half the keys of the container & then perform an associative lookup for each one in sequence

The creation of the keys for these lookups is excluded from the benchmarking time.
