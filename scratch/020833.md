Commit title: Optimize varint encoding: 1.7x to 2.6x speedup for common cases
Commit body:
Summary:
## Proposed change
Add support for branch-free varint encoding on aarch64. This already exists for x86.

Currently the code is identical for both architectures (except for the pdep / bdep intrinsic). I'm proposing we land this change because the wins are quite large. We might be able to further tune for aarch64 as a follow-up.

## Benchmarks (uniform random)
The `any` benchmarks generate uniform random values across the full range for each dtype:
```
bench_write(u8_any_unrolled)                                3.08us   324.31K
bench_write(u8_any_branch_free)                 101.32%     3.04us   328.58K
bench_write(u16_any_unrolled)                               4.79us   208.89K
bench_write(u16_any_branch_free)                152.94%     3.13us   319.48K
bench_write(u32_any_unrolled)                               5.50us   181.70K
bench_write(u32_any_branch_free)                167.88%     3.28us   305.03K
bench_write(u64_any_unrolled)                               8.51us   117.45K
bench_write(u64_any_branch_free)                261.92%     3.25us   307.62K
```
We are 1.7x faster for 32-bit and 2.6x faster for 64-bit.

## Counter-argument
This diff introduces a branch-free encoder (on arm64). The size of the win depends on the efficacy of branch prediction. The benchmarks use uniform random data, which is a worst-case scenario for branch prediction. Also, we don't have PGO / BOLT enabled in the benchmark build, which makes branches more expensive. Thus, we could argue that the benchmarks don't reflect production.

Response: instead of generating uniform random data, we can generate varints with a fixed number of bytes. The branches in varint encoding depend on the number of bytes, so by fixing the number of bytes, we make every branch 100% predictable in the benchmark.

As shown in the section below, we have nice wins even when the branches are 100% predictable.
