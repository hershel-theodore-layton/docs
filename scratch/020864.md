Commit title: Improve codegen for `_to_python()`, `_to_mutable_python()`, and `_to_py3()`
Commit body:
Summary:
When trying to fix a Pyre2 bug (D70144456), I noticed that the thrift-generated python files contain the following pattern:
```
class Foo:
    ...

    def _to_python(self):
        import thrift.python.converter
        ...
        return thrift.python.converter.to_python_struct(...)
```
Technically speaking this is not wrong, but I think the codegen can be slightly optimized into this:
```
class Foo:
    ...

    def _to_python(self):
        from thrift.python import converter
        ...
        return converter.to_python_struct(...)
```
The observation here is that if we already have the `thrift.python.converter` module imported, we could just save the imported module into a local variable `converter` and invoke `to_python_struct()` from there. This saves 2 additional attribute accesses on `thrift` and `thrift.python` at runtime. Probably won't have big runtime impact. But can be a small perf improvement.
