Commit title: Add an exponential-distribution varint benchmark
Commit body:
Summary:
Per suggestion from yfeldblum, add a benchmark for exponentially-distributed integers.

I added three cases. "1b" has median 127, i.e. half of the values encode to one byte. "2b" means half the values encode to at most two bytes, etc. Open to any suggestions for how I can choose better cases.

## Results: aarch64
On aarch64, the branch-free encoder is faster for all cases. That's good news, since it unblocks AdRanker wins from D69827726!
```
# aarch64 results:
bench_write(exponential_1b_unrolled)                        3.33us   300.23K
bench_write(exponential_1b_branch_free)         105.91%     3.15us   317.96K
bench_write(exponential_2b_unrolled)                        5.95us   167.96K
bench_write(exponential_2b_branch_free)         159.17%     3.74us   267.34K
bench_write(exponential_3b_unrolled)                        5.88us   170.07K
bench_write(exponential_3b_branch_free)         181.51%     3.24us   308.69K
```
Note: PGO / BOLT may change these results in production, since branch prediction is important here.

# Results: x86
On x86, it looks like the branch-free encoder is slower for the 1b exponential case. That's exciting, because it means maybe there are some wins for x86! Although I'm not sure what % of total varint cycles are represented well by the exponential benchmark.
```
# x86 results:
bench_write(exponential_1b_unrolled)                        1.40us   713.32K
bench_write(exponential_1b_branch_free)         92.045%     1.52us   656.57K
bench_write(exponential_2b_unrolled)                        3.09us   324.02K
bench_write(exponential_2b_branch_free)         139.78%     2.21us   452.92K
bench_write(exponential_3b_unrolled)                        2.44us   409.32K
bench_write(exponential_3b_branch_free)         112.61%     2.17us   460.94K
```
