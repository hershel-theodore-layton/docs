Commit title: always vfork in Subprocess and suppress sanitizers in child
Commit body:
Summary:
For `Subprocess`, the intention is to `exec` the next program without affecting the child program state in any substantive way.

If we use `fork`, the `atfork` handlers will have to run. Some libraries install `atfork` handlers that mostly work, but it is very tricky to get exactly right. If the application only `fork`s to `exec`, then there is no real need to run the `atfork` handlers.

So we want to use `vfork` instead of `fork` in `Subprocess`, to skip all `atfork` handlers.

The original code used `vfork` in the non-detached and non-thread-sanitizer case, and otherwise used `fork`.

The use of `fork` in the detached case looks like a misunderstanding. The manpage does not restrict the use of double `vfork` to detach. It just says that the child process, after returning from `vfork`, must end with either `_exit` or `execve` and without returning from the caller. However, simply switching that case to `vfork` does not work with address sanitizer - the tests for the detached case abort.

So it is necessary to suppress the sanitizers.

Reverts {D68522771}, which marks `detach` as `[[deprecated]]`. Detaching is not actually deprecated - it just needs to avoid `fork` and stick to `vfork`.
