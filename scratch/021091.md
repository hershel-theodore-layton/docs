Commit title: no need in Subprocess for a special err-fd
Commit body:
Summary:
`Subprocess` creates a special pipe for the child process to communicate errors back to the parent process during preparation of the child process, up to and including the call to `execve`.

If the child process is created with `fork`, a technique like this would be necessary. The child does not share address space with the parent, so they need some other way to communicate.

But now that the child process is always created with `vfork`, this technique is not necessary. It is simpler just to allocate storage on the stack of the parent process before `vfork`, permit the child process to modify that state, and let the parent process observe any modifications. This works because the child process shares address space with the parent process, and the parent process does not return from its call to `vfork` until after the child process has terminated its sharing of the parent process's address space with either `_exit` or `execve`.
