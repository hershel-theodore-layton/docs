Commit title: Improve immediately-awaitable task handling (`NowTask`)
Commit body:
Summary:
- Make `Timeout.h` work with immediately-awaitable tasks, returning `Task` for non-immediate inputs, and `NowTask` for `must_await_immediately_v` ones. Fixing `timeout()` requires moving a `NowTask` into a coroutine. C++ doesn't support prvalue semantics for coros -- the spec explicitly specifies a (move)copy into the coro frame, so the old "turn `this` into a prvalue" trick didn't work. So, I replaced the "unsafe move" escape hatch by a "movable callable", which can be invoked inside the coro to reconstitute a prvalue of the immediately-awaitable type.
    - Before: `std::move(awaitable).unsafeMoveMustAwaitImmediately()`
    - After: `mustAwaitImmediatelyUnsafeMover(std::move(awaitable))()`

- Move immediately-awaitable machinery out of `Coroutine.h` into `AwaitImmediately.h`, and improve the docs.

- Add object-slicing detection for operations that unwrap a wrapped task (like most `getUnsafeMover` implementations). The next diff on the stack extends this to `unwrapTask()` and `unwrapTaskWithExecutor()`.

- Fix the empty-base optimization when commutative wrappers are applied to immediate awaitables, e.g. `co_awaitTry(someNowTask())`. Specifically, I noticed that awaitable was 16 bytes instead of the expected 8. The fix was to stop using a private base of `MustAwaitImmediately` to tag types. The new convention is the member type `folly_private_must_await_immediately_t`, which is to be added via `public AddMustAwaitImmediately<ActualBase>` (which also makes the type immovable).
