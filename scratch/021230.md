Commit title: Add prototype-based programming support for native_handle
Commit body:
Summary:
This diff adds "prototypes" to `native_handle` objects which allows property access on them like `a.b.c`. This means we can have `enum.name` instead of `(t_named.name enum)`.

This approach is modeled after JavaScript's prototypes: https://developer.mozilla.org/en-US/docs/Learn_web_development/Extensions/Advanced_JavaScript_objects/Object_prototypes

The advantage of this approach is that we can emulate inheritance hierarchies without modifying data types. In other words, we can access `t_enum::name` as `{{enum.name}}` without creating a wrapper type around `t_enum`. In general, this allows us to expose `t_*` AST nodes and their member functions to whisker templates without re-inventing the inheritance hierarchy like mstch does today.
