It is clear that the difference is due to a change in how `XML_ENTITY_DECL` is rendered.

In fact, this is an intended behaviour change on the part of libxml2, as in v2.9.9 `xmlNodeGetContent` on an `XML_ENTITY_DECL` is marked as a TODO, while in v2.13.5, it is actually implemented (and shares the same implementation as `XML_ELEMENT_NODE` and friends)!

Thus, calling `xmlNodeGetContent` on a parent node of this document that has both an `XML_ENTITY_DECL` and an `XML_TEXT_NODE` will return `"hello world"` on v2.9.9, but `"hello worldhello world"` on v2.13.5. The base64 encoded data is decoded in the case of the ENTITY decl, and the entity is replaced in the case of the text node due to `XML_PARSE_NOENT`.
