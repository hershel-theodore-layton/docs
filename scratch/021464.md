Summary:
(Also makes `ClosureTask` non-movable.)

The user-facing explanation is in `APIBestPractices.md` (D65408249).

 ---

If your member coro is always awaited immediately, you should just use `NowTask`.

This new `safe_alias` level and `MemberTask` type alias can be used in two ways:
 - For pure structured concurrency: Awaited immediately, like `NowTask`, but with the added constraint that none of the args are `safe_alias::unsafe`.
 - For deferred tasks: Via `async_closure(FOLLY_INVOKE_MEMBER(memberName), objCapture, ...)`, which has some special-case logic to derefrence `objCapture`.

The closure verifies the safety of all the args (i.e. `MemberTask` is only responsible for checking that args >= 2 aren't taken by reference). That makes it possible, e.g. to schedule `MemberTask`s on `SafeAsyncScope`s belonging to an `AsyncObject`.

The other flavors of `SafeTask` wouldn't do here, since none of them allow arg 1 to be a reference, and implicit object params are always taken by-reference. Furthermore, this is more usable than `ClosureTask`, since users **can** directly await it.
