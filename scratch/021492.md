Commit title: Work around @rust.Type bug
Commit body:
Summary:
`rust.Type` currently generates invalid Rust code for a field that has a default value expression. This scenario:

```lang=rust
struct Struct {
    rust.Type{name = "HashMap"}
    3: map<string, Value> m = {"k": "v"};
}
```

There is 1 occurrence in fbcode working around it using the old `rust.type` like this:

https://www.internalfb.com/code/fbsource/[2dc5783fcf4d6c7991ebd2b3446631e5b4c4647e]/fbcode/configerator/compiler_service/if/compiler_service.thrift?lines=108%2C122-124%2C302-304

I promise to fix this for real, but since all of the following are true:

- there is only 1 occurrence of this in fbcode
- that one uses `= {}`
- an `= {}` can just be deleted, because empty map is the default value of map fields without needing to specify it
- needing to have a nontrivial default value somewhere would be extremely unusual
- this is the last unstructured Rust annotation remaining in any of our repos
- I have made an attempt to fix the bug and it is not straightforward
- I understand what is going wrong and roughly what the fix will look like

this diff simply deletes the `= {}` in that file to unblock {D71433482}.
