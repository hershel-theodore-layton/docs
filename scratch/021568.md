Commit body:
Summary:
This diff adds standard resource pool setup for hhvm thrift server.

- Currently ResourcePool is only used when the hhvm config `ThriftFBServer.UseThriftResourcePool` is set to true.
  - When set to false (or not provided), server will continue to use HHVM [JobQueueDispatcher](https://fburl.com/code/avud4662) for queuing requests and execution.
  - When set to true, HHVM JobQueuesDispatcher will be skipped entirely and queuing will be handled by ResourcePool.
- When enabled,
`ThriftServerCPUWorkerThreads` should be set to an appropriate value.
  - For testing, I set it to the same value as `Server.MaxThreadCount` i.e. 120
  - If unchanged (i.e. set to 2), queue timeout is triggered even with fewer requests
- Some of the options from hhvm `Server` config are reused for ResourcePool setup in this diff as well as next diff.
- RequestHandler is used similar to dispatcher and is created once per worker thread.
  - RequestHandler has the main logic to execute given http request in php. Removing or reimplementing this handler for thrift server is out-of-scope for this task.
  - Request Handler could be [HttpRequestHandler or WarmUpRequestHandler](https://fburl.com/code/eoth6ufp)
  - Handler is wrapped in a new class `HHVMThriftWorker` which is similar to [`ServerWorker`](https://fburl.com/code/5mgy23nk) used by JobQueueDispatcher

I have added inline comments where necessary for highlighting important changes or decisions.
