Commit title: Repro for segfault in folly.python.iobuf
Commit body:
Summary:
When C++ thread destroys folly.python.iobuf wrapper around
Python-managed memory, it can result in a segfault.

The reasoning goes as follows:
 - Python code calls some Cython code that creates a folly.python.iobuf wrapper
   around Python-managed bytes and gives it to C++ code
 - Python code runs to its end and interpreter starts shutting down
 - Later on, C++ code destroys folly.python.iobuf wrapper on non-Python thread
 - In this state, `PyGILState_Check()` returns 1

I haven't confirmed the exact reason of this behavior, but I suspect it's due
to this check in `pystate.c`:
```
if (!gilstate->check_enabled) {
    return 1;
}
```
so while Python interpreter is shutting down, every thread thinks it holds GIL.
The resulting attempt to `Py_DECREF` ends in a segfault because there's no
Python thread state and no interpreter state.
