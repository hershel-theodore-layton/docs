Summary:
As described in D70874850, there's a regime under which destroying
folly.python.iobuf results in a segfault.

This commit "fixes" (or, rather, patches up) the problem by checking whether
Python interpreter state is valid during destruction of IOBuf wrapper.

Even after this fix, folly.python.iobuf's destructor is still problematic: the
executor passed into IOBuf wrapper constructor is no longer alive when IOBuf
wrapper is being destroyed while Python interpreter is shutting down.
