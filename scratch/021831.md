Commit title: New exhaustivity check
Commit body:
Summary:
This diff introduces the new exhaustivity (and related) checks in `switch_exhaustivity_check.ml`.

It is guarded through the `new_exhaustivity_check` flag. When active, this flag enables the new checks and disables the old checks.

Summary of changes:
* A switch statement either needs to be exhaustive or have a default to be error free
* In addition to unions and intersections of enums and enum classes, nullables, `bool`s, and `tuple`s are also checked precisely for exhaustivity
* Enum class values and enum class labels now use field types in `HH\MemberOf` and `HH\EnumClass\Label` types to cut down the cases that need to be handled to be exhaustive
* Stop distinguishing between enum class label base types for expressivity and safety
* Demote redundant case and default checks from errors to warnings
* Enhance the redundant case check to discover more cases of dead code
* Remove the check that prevents the use of one enum value case when switching over another enum
