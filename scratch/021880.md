Commit title: Erase functions from FunctionScheduler storage upon cancelling
Commit body:
Summary:
Before this commit, FunctionScheduler will only erase cancelled
function from its heap when it's that function's turn to run. This poses a
problem for some uncommon but real scenarios. When a lot (tens of millions)
functions with large (hours) repeat interval are added to the function
scheduler and then quickly (much shorter than repeat period) removed, these
functions will linger in FunctionScheduler heap.
FunctionScheduler::RepeatFunc is itself pretty large (over 200 bytes on x64),
but it also holds function name which can also be large.
In one real-world scenario, lingering functions accounted for about 300GB of
memory which was stranded for the functions' repeat interval. Since the repeat
interval itself measured many hours, this created apparent memory leak.
This commit makes function scheduler eagerly evict a function from its heap
once the function is cancelled. This raises the cost of cancelling function
from O(1) to O(log N) where N is the number of functions currently scheduled,
but in turn allows keeping the number of functions lower in certain scenarios.
