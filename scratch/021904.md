Commit title: Fix thread manager load test
Commit body:
Summary:
Fix a number of issues in the thread manager load test:

1. Use `steady_clock` instead of platform-specific choice of `clock_gettime(CLOCK_REALTIME, ...)` or `gettimeofday`. The former is monotonic and, unlike the other two, suitable for reliable measurement of time intervals. Neither of the current choices are monotonic, quoting the docs "The time returned by `gettimeofday()` is affected by discontinuous jumps in the system time".

2. Use the average time of `usleep` execution instead of the timeout when computing the "ideal" time because it depends on system scheduling and likely other factors which are outside of our control. We mostly care about thread manager itself not adding too much overhead. In particular, this fixes the test on macOS where scheduling overhead is much higher than on Linux and the number of available cores on test machines is low.

3. Use chrono types instead of integers where appropriate.

4. Use gtest logging instead of glog because the latter may be disabled in tests.

5. Use {fmt} for chrono formatting since ostream formatting doesn't work at least on some platforms.
