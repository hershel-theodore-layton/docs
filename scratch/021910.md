Commit title: fix for implicit const initialization
Commit body:
Summary:
A thrift const like the below implicitly references a type from a different .thrift module. Since the type isn't explicitly named, the include checker proactively discourages including it. This has come up before, and the solution was to use absolute imports, i.e. `.`-separated imports. It's only necessary for constants because that's the syntax that allows implicit types.
```
const tpolicyvars.TPolicyVars kDefaultPurposesOnlyPolicy = {
  "purposePolicyVars": {"policyName": "default_purposes_only"},
};
```
