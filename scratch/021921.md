Commit title: opt-in auto hinting for exception_ptr_get_object_hint
Commit body:
Summary:
This sets the stage for exception types that can internally store a compile-time error message, **or** a dynamic one, thus transparently saving memory & allocations where no runtime message is required. Here's how one might use such a hint:

```cpp
template <typename Ex>
struct WithConstMessage final : Ex { const char* message; };
template <typename Ex>
struct WithRuntimeMessage final : Ex { std::string message; };
template <typename Ex>
struct CheapErrorCrtp {
  using folly_get_exception_hint_types = folly::tag_t<
      WithConstMessage<Ex>, WithRuntimeMessage<Ex>>;
};
struct MyError : CheapErrorCrtp<MyError> { /* ... */ };

template <typename T, typename... Args>
exception_wrapper makeCheapError(ConstexprCharPtr what) {
  return folly::make_exception_wrapper<WithConstMessage<T>>(what);
}
template <typename T, typename... Args>
exception_wrapper makeCheapError(StringWrapper what) {
  return folly::make_exception_wrapper<WithRuntimeMessage<T>>(
      std::move(what));
}
```

Above, a user declares a base error type (`MyError`), but `auto ew = makeCheapError<MyError>(...)` secretly instantiates one of two derived types (`WithConstMessage<MyError>`, `WithRuntimeMessage<MyError>`) depending on the supplied message.

The change in this diff makes `ew.get_exception<MyError>()` try first the "const" and then the "runtime" message, which succeed in ~3ns and ~5ns, respectively. For comparison, a non-polymorphic lookup of `std::system_error` takes ~4ns.
