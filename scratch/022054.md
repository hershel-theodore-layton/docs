Commit title: Make QueueTimeHeaderTest less flaky
Commit body:
Summary:
`QueueTimeHeaderTest` is pretty flaky.

It fails almost all the time on macOS:

 {F1976857415}

It occasionally fails on Linux:

 {F1976857429}

One source of failures is load shedding:

```
libc++abi: terminating due to uncaught exception of type apache::thrift::TApplicationException: Load Shedding Due to Queue Timeout: 100 ms
```

Make it less likely to occur by increasing the "default" queue timeout and change the value to be more identifiable. We don't really care about specific value in this test, just that it's large enough for load shedding not to kick in and that it cannot be easily confused with other values.

Another source of failures is over-specified expected queueing time:

```
fbcode/thrift/lib/cpp2/test/server/ThriftServerTest.cpp:3119: Failure
Value of: queueingTime.value()
Expected: (is > 8-byte object <05-00 00-00 00-00 00-00>) and (is < 8-byte object <32-00 00-00 00-00 00-00>)
  Actual: 8-byte object <04-00 00-00 00-00 00-00>
```

I don't think we can put a reliable lower bound here other than 0, so remove it altogether.
