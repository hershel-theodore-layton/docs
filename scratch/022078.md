## Implementation

This update modifies the string representation of NaN and Infinity values to align with the reference C++ implementation.

https://www.internalfb.com/code/fbsource/[e4abbd518aac03beb4956c27ec041c84b4e30d05]/fbcode/thrift/lib/cpp/protocol/TJSONProtocol.cpp?lines=541-572

## Notes

While the new serialization conforms to the reference C++ implementation and passes the roundtrip test using simplejsonprotocol, there is one case where it may affect behavior in an unexpected way. This is better demonstrated in the updated unit tests below; for now, consider both:
1. serialization using simplejsonprotocol
2. deserialization using serde_json

In this case, when special values are passed during serialization on one end, deserialization on the other end no longer fails immediately as it did before. Instead, it produces `String` objects such as "NaN" or "Infinity". If handled differently, this may alter the control flow of the deserialization caller, potentially leading to thread panics, value loss, or unpredictable behavior. Which then brings us back to the announcement dated back to 2020 - [PSA: Please use fbthrift::simplejson_protocol over serde_json for guaranteed compatibility](https://fb.workplace.com/groups/rust.language/posts/4545422672172979).
