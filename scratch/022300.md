Commit title: Improve readVarint cases with mispredictions
Commit body:
Summary:
On D72522727 we verified marking readVarint's last conditional jump as LIKELY caused a performance regression.

We now tested flipping the last statement, keeping it as UNLIKELY and having the exception codepath behind it.

This change greatly improved performance of cases testing different codepaths, where mispredictions occur.

Old asm: https://godbolt.org/z/EhE4TcGEz
New asm: https://godbolt.org/z/EboaGcaoE

To achieve this pattern, function has been split per var size. This is actually desirable too, following D72762195 which left the function ugly.

before:

bench_read(u16_any)                                         1.97ns   508.73M
bench_read(u32_any)                                         1.80ns   556.88M
bench_read(u64_any)                                         2.88ns   347.34M

after:

bench_read(u16_any)                                         1.53ns   653.99M
bench_read(u32_any)                                         1.56ns   639.60M
bench_read(u64_any)                                         2.76ns   362.86M

The change has a greater effect on cases of small vars, as those have less branches.
We see now performance for 16-bit and 32-bit vars remains flat across tested cases:
