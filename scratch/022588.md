Commit title: Fix nested ET variable problem
Commit body:
Summary:
Move the addition of macro splice variables to the environment. Previously, we added them when entering an expression tree. This had two problems
- they weren't removed when the expression tree was left
- the expression tree expression contains sub expressions of hack code to evaluate the splices outside of the virtualised expression, and the macro splice variables would clobber hack variables of the same name.

Now we add the macro splice variables when checking the `Efun` that wraps the virtualized expression. Now
- we take advantage of the Efun checking environment management to clear out the environment of the new locals
- the new locals only are in place for the virtualized expression and not the splices
