Commit title: Fix false positive AddressSanitizerInitializationOrderFiasco in ExceptionCounterLib
Commit body:
Summary:
When using `ASAN_OPTIONS=strict_init_order=true` (https://github.com/google/sanitizers/wiki/AddressSanitizerInitializationOrderFiasco#strict-init-order-checking), if some other global initializer throws an exception, this leads to
```
==2675213==ERROR: AddressSanitizer: initialization-order-fiasco on address 0x000076d59040 at pc 0x00002dfbfecc bp 0x7ffc4ccb0a10 sp 0x7ffc4ccb0a08
READ of size 4 at 0x000076d59040 thread T0
SCARINESS: 8 (4-byte-read-initialization-order-fiasco)
    #0 0x2dfbfecb in (anonymous namespace)::throwHandler(void*, std::type_info*, void (**)(void*)) fbcode/third-party-buck/platform010/build/libgcc/include/c++/trunk/bits/atomic_base.h:481
    #1 0xb70bd5c in __cxa_throw fbcode/folly/debugging/exception_tracer/ExceptionTracerLib.cpp:82
...
0x000076d59040 is located 0 bytes inside of global variable '(anonymous namespace)::gExceptionStats' defined in 'fbcode/folly/debugging/exception_tracer/ExceptionCounterLib.cpp' (0x76d59040) of size 40
```

In practice this is a false-positive because this code can only be reached after `registerCxaThrowCallback(throwHandler)` has been called which requires this translation unit's globals to have already been initialized, but ASAN doesn't know about this in the strict mode.
