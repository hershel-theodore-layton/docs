Commit title: Align thrift module metadata ServiceName with regular ServiceUri
Commit body:
Summary:
When working on context prop and policy zones enforcement logic on thrift calls, I noticed that some services are not enforced correctly. Drilling down a bit I found that there's a discrepancy between:

 `apache::thrift::metadata::ThriftServiceMetadataResponse` in `*_metadata.cpp` (generated as a separate file)

vs

 `apache::thrift::MethodMetadata::Data` that gets generated in `*ServiceAsyncClient.cpp`

Comparing between these two structs:

`apache::thrift::MethodMetadata::Data` uses the `serviceUri` as the service name
`apache::thrift::metadata::ThriftServiceMetadataResponse` uses `file_name.service_name` as service name

This diff moves the latter to use `serviceUri` as well to make sure the service name SR sees stays consistent.
