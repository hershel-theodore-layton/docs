Commit title: avoid re-initializing struct field on access
Commit body:
Summary:
We're currently calling `_initStructTupleWithValues`, which eagerly initializes all fields of the internal data tuple with their default values. If we move this call from `__cinit__` to `__init__`, then it's no longer part of `__new__`. For places where `__new__` is used and a "blank" internal data is needed,  create helper method `_fbthrift_new`, which will continue to call this default initializer for internal data tuple.

In the thrift micro-benchmark, this improves first access time from 0.53 us to 0.310 us, which is now comparable to enum creation time. It is now faster than mutable thrift python (0.370 us) but slower than py-deprecated (0.070 us).
On customer benchmark, it improves runtime of thrift "parse results" section:
-  30s (original)
- 25s (with field descriptor change)
- 14.5s (with this diff)

This diff does not change memory usage.
