Commit title: not_null: fix circular SFINAE condition in enable_if
Commit body:
Summary:
When not_null is being used as a PtrT, the compiler performs overload resolution on the conversion operator of not_null, which included evaluating the SFINAE conditions and find all viable functions.

As part of this, the conversion operator template's constraints `is_not_null_castable` and `is_not_null_move_castable` are checking if `not_null<PtrT>` is not convertible to `U` [here](https://www.internalfb.com/code/fbsource/[e4336b7c311eca50c1c432c03e367ec23f3fbdbd]/fbcode/folly/memory/not_null-inl.h?lines=102).

However, the evaluation of `is_convertible_v` is usually implemented with a helper like this:
```
template <class Void, class From, class To>
constexpr bool is_implicitly_convertible_impl = false;

template <class From, class To>
constexpr bool is_implicitly_convertible_impl<
    void_t<decltype(declval<void (&)(To)>()(declval<From>()))>, From, To> = true;

template <class From, class To>
constexpr bool is_implicitly_convertible_v = is_implicitly_convertible_impl<void_t<>, From, To>;
```

As you can see, the expression SFINAE we use here: `declval<void (&)(To)>()(declval<From>())` causes the compiler to perform overload resolution on the conversion operators again, which causes recursion. This is usually Ill-formed, No Diagnostics Required.

To solve this circular dependency in SFINAE, we can further constraint the constraint to evaluate only when `U` is not `PtrT`. When `U` is same as `PtrT`, the overload is chosen as the exact match.
