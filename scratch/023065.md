Summary:
This diff adds some integration testing for the recently added `Edenfs_watcher`-backed variant of `ServerNotifier`.

 It uses the existing machinery in fbcode/hphp/hack/test/integration/. In particular, the new class `CommonTestsOnEden` in `test_edenfs_file_watcher.py` extends `CommonTests` from `common_tests.py`, meaning that it inherits all theses tests. These tests check things such as the type checker correctly picking up added/removed/modified files.

Crucially, `CommonTestsOnEden` executes these tests using a new test driver, which is different from the existing one in the following ways:
1. The setup of the mini repo where `hh` will be executed is changed to use an Eden repo.
2. We set `edenfs_file_watcher_enabled` in the server config.

I've also added some tracing to the existing `setUp`/`tearDown` functions in our testing framework, just to make it easier to debug what is executed when.

## What's actually being tested once this lands?

Right now enabling `edenfs_file_watcher_enabled`  means that Hack will use the `EdenfsFileWatcher` variant in `ServerNotifier.t`. However, this only means that we initialize an `Edenfs_watcher` instance, but the actual `ServerNotifier` API is still provided by a Watchman instance. My new test suite verifies that the `Edenfs_watcher` initialization succeeds.

The idea is to put these tests into place now, before I change the `Edenfs_watcher`-backed variant of `ServerNotifier` in the future to rely less on Watchman.
