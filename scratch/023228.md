Summary:
This diff fixes and re-enables the `edenfs_file_watcher_test` integration test.

The test previously had two issues:
1. We would unmount the Eden repository that `hh_server` is running of before stopping the server, which (unsurprisingly) could lead to spurious errors
2. When running the a large number of the test cases in the test suite in parallel (e.g. during the stress testing that the CI performs), this would lead to Eden and Watchman becoming very slow. This was due to the fact that all tests were using a the single, global instance of Watchman and Eden for all testing.

Concretely, this diff:
- Reorders the teardown steps to fix 1. above
- To address 2, create fresh instances of both Eden and Watchman for each test case. This is achieved using the corresponding test instance python classes from the Watchman and Eden integration test suites.
- In `rust_edenfs_watcher.rs`, make sure to always provide the mount point (derived from the `root` parameter given to `init_`, instead of trying to guess the mount point using things like the current working directory. This ensures that our `Edenfs_watcher` library is able to talk to the right Eden testing instance, instead of the global Eden instance.
- Set the `ServerLocalConfig` option `watchman_sockname` to the socket for the Watchman testing instance. This ensures that `hh_server` talks to the correct Watchman instance. I've manually checked that whenever we invoke `Watchman` in Hack, we provide the correct `--sockname` option to make it use the correct socket. The only exception from this is `ClientCheckStatus`, in a code path not triggered by `edenfs_file_watcher_test`. I'm patching it in the follow-up diff D75140228 to resolve that separately.
