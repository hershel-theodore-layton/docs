Commit title: Fix handling std::vector<bool, Alloc>::reference when Alloc is user-defined
Commit body:
Summary:
The class template specialization `std::vector<bool>` can have a custom allocator. When it does, it may affect what type `std::vector<bool, Alloc>::reference` holds.

The overload for `protocol_methods<type_class::integral, bool>::read` here works for any `std::vector<bool, Alloc>::reference` under GNU libstdc++, because the type alias ultimately are the same `_Bit_reference` type. However, the reference is implemented differently as a template in libc++, i.e. `__bit_reference<vector<bool, Alloc>>`. Example error: P1816283537

A naive attempt at fixing this would be making `Alloc` a deduced template parameter and have it read
```
  template <typename Protocol, typename Alloc>
  static void read(Protocol& protocol, std::vector<bool, Alloc>::reference out) {
```
However, since we are meeting with `__bit_reference<...>` here, and compiler fundamentally can't deduce `Alloc` while referring to the member alias `std::vector<bool, Alloc>::reference`.

We are introducing this concept `folly::vector_bool_reference` so that we can match on all vector<bool>::reference types.

See: https://isocpp.org/files/papers/P3719R0.html
