Commit title: Explicit cancellation handling for `AsNoexcept` et al
Commit body:
Summary:
Today's `folly::coro` reports task cancellation as an exception, which means that current `AsNoexcept<Task<T>>` will terminate the program if the task completes due to cancellation.

This seems like a giant footgun, since it's just as often that you want to treat cancellation as success. See present-day `AsyncScope::addImpl` for a concrete example, or https://wg21.link/p1677 for a more philosophical take.

The present diff makes the behavior on cancellation painfully explicit. You can write one of:
  - `AsNoexcept<Task<int>, terminateOnCancel>`
  - `AsNoexcept<Task<int>, OnCancel(42)>`
  - `AsNoexcept<Task<>, OnCancel<void>{}>` -- specialization for `void`

Later, we can debate if the `void` specialization should default to `OnCancel<void>{}`. For non-trivial or non-empty types, being explicit seems like the only reasonable way to go.
