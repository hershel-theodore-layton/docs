Commit title: Wait until EventBase is looping in ThriftClientTest
Commit body:
Summary:
We weren't waiting until the `t` thread actually starts looping the `EventBase`. There's a chance that when the client tries to write/flush, the `EventBase` isn't running.

The "async" scheduling `RequestChannel::sendRequestAsync` will try to send the request on the current (test) thread instead of on `t`, which is wrong. Building in dev mode, a run will crash with something like

```
F0529 06:38:34.402493 3456390 EventBase.cpp:445] Check failed: evbTid == curTid (3456689 vs. 3456390) This logic must be executed in the event base thread. Event base thread name: "ThriftClientTes", current thread name: "ThriftClientTes"
```
The change waits until the thread is actually looping the `EventBase` so the scheduling  (and eventual IO) can happen on the correct thread.

Meta:

This showed up when I tried to run all tests under `thrift/lib/...`. Will really only crash when lots of threads are running. I'm sort of surprised we don't see this failure in https://www.internalfb.com/intern/test/562950033732128?ref_report_id=0, would expect *some* stress runs in there.
