Commit body:
Summary:
This diff ensures that when `edenfs_file_watcher_enabled` is set, then `ServerNotifier.get_changes_async` is actually implemented by calling into `Edenfs_watcher`.
Technically, this diff also changes the sync version (i.e., `ServerNotifier.get_changes_sync`) to use `Edenfs_watcher`, but within`Edenfs_watcher` the sync version currently redirects to the async one.

The actual changes in this diff are the following:
- Better error handling in `Edenfs_watcher`. The idea is that if the worker thread talking to Eden fails, it must not just stop working. Instead, we now inform the main thread by turning the shared state between worker and main thread into a variant. If the worker fails, we set it to `WorkerFailed`. Upon the next call to `get_changes_{sync, async}`, the main thread will then notice that something went wrong.
- We now have new exit codes to indicate that Eden failed, similar to the Watchman ones. Over time I will get a better idea of what amount of recovery logic we want to add, as well as adding some reporting to `HackEventLogger`.
- If Eden tells us that it may have lost track of some changes, we turn this into an error.
- I had to tweak the `throttle_time_ms` value passed to `stream_changes_since`. See the comment on the call as to why that was necessary.
