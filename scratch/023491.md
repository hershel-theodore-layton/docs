Commit title: fanout support for hh -> hh_distc invocation
Commit body:
Summary:
When hh encounters a fanout over `hh_distc_fanout_threshold` it invokes
hh_distc which performs a full init.

This diff adds the option `hh_distc_fanout_aware_threshold`:
- when `fanout_size > hh_distc_fanout_threshold`, hh_distc performs a full init;
- when `hh_distc_fanout_aware_threshold < fanout_size < hh_distc_fanout_threshold`, hh_distc performs a full decl, and then typechecks only the files in the fanout.
- when `fanout_size < hh_distc_fanout_aware_threshold`, incremental hh is used instead.

By default, `hh_distc_fanout_aware_threshold == hh_distc_fanout_threshold` and thus, unless the latter is overridden, fanout aware distc is disabled.

**Batching strategy**

Batches for typechecking are the derived from the batches used for decl:
- each batch is filtered removing files not in the fanout from the decl batches
- batches with no files in the fanout are discarded

A later diff will support other batching strategies for experiments.

**Logging**

This diff adds several columns to `scuba hh_distc`.

- *fanout size*:
  - when hh_distc performs fanout aware typechecking, events `DISTC_SPAWN` and `DISTC_TYPE_CHECK_END` record the fanout size (in files);
  - field is `null` when fanout aware hh_distc is not used and hh_distc performs a full init;
- *batches count*: the number of batches used in the typecheck phase.  This is recorded in the `DISTC_TYPE_CHECK_END` event, both for fanout-aware and full-init invocations;
- *batches fill rate*: recorded in the `DISTC_TYPE_CHECK_END` event:
  - fill_rate is 1 if no files have been removed from decl batches
  - otherwise is the ratio of the files in typecheck batches vs files in non-deleted decl batch
