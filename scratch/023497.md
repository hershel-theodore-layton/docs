Commit title: Use NUMA API to optimize for NUCA architectures
Commit body:
Summary:
AMD CPUs have ccx, each with a local L3 cache. In this diff, we deal with the situation where there is a single NUMA node, but multiple L3 caches that have different access latency on different CPU cores.

The current strategy is to have some hhvm worker threads pinned to a single CCX, and more hhvm worker threads pinned to the union of two CCXes (to provide flexibility in load balancing), while trying to balance the utilization of CCXes. Pinning is done only on high-priority worker threads, up to twice the number of CPU cores. Efforts are made to avoid threads created from pinned threads to inherit the pinning, by clearing CPU affinity settings upon thread renames.

This could be turned off by setting `Eval.EnableNuca` to false.
