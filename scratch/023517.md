Commit body:
Summary:
This diff allows `Edenfs_watcher` to provide a file descriptor to OCaml that can be `select`-ed on to detect file system changes.

The most important use of this FD is to support our interrupt mechanism in `MultiWorker`. This means that we can now cancel a type-check if new changes happen on disk.

Some detaills:
- The actual FD is obtained from creating an in-memory pipe on the Rust side
- In theory, the data we write to the pipe doesn't matter, an arbitrary byte per change would suffice. I'm writing some information about the involved Eden `JournalPosition` into the pipe instead to enable some consistency checking between the pipe and the other shared data. See the comment on the new  `NotificationPipeEntry` type for details
- We now need to mutate the `EdenfsWatcherInstance` on the Rust side, but the `Custom<>` FFI magic doesn't give you a mutable reference. Therfore, we now pass a new type `EdenfsWatcherInstanceHandle` over the FFI boundary which is just a `RefCell` wrapper around the `EdenfsWatcherInstance`.
- I've slightly cleaned up the `ServerNotifier` API: It was previously returning a `Buffered_line_reader` for anyone wanting to use the notification mechanism. For `Edenfs_watcher`, a line-based reader makes little sense, so it's now returning a FD directly. There's also a new convenience function in `ServerNotifier` to check if changes may be available.
