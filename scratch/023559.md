Commit title: Clear RequestCompletionCallback pointers when moving ServerRequest objects
Commit body:
Summary:
`ServerRequest` objects are moved around a lot.

Concurrency controllers, like `ParallelConcurrencyController`, can call `ServerRequest::setConcurrencyControllerNotification` to register a callback to clean up their own state when the request is finished (on destruction). But that callback should only be invoked once. Currently it's invoked by every `ServerRequest` object, including the "moved from" objects.

Introduce small struct type to handle clearing "old" callback pointers after they've been copied during a move.

Meta:

See https://fb.workplace.com/groups/677796806483229/posts/1781031616159737

In my example, the `notifyConcurrencyController_` callback would end up getting invoked twice and performing this bit of housekeeping
```
--counters.requestInExecution;
```
while `requestInExecution` was 0. Because it's a `uint32_t`, that would overflow to some max value, which was clearly above `currentLimit`, and the CC would therefore never schedule its next execution.
