Commit title: Traverse superclasses when collecting serverHandlers
Commit body:
Summary:
In current implementation `GeneratedRpcServerHandlerBuilder` doesn't traverse the hierarchy to lookup all parent interfaces that have `serverHandlerBuilder` method, and has a hard failure if such method is missing. Change in `GeneratedRpcServerHandlerBuilder` is dedicated to lookup all classes of the hierarchy, and only add all the ones who have a `serverHandlerBuilder` method to `serverHandlers` list.

This however poses a problem with possible duplicated methods (e.g. in case of [`HivePermissionService`](https://www.internalfb.com/code/fbsource/[b9510326b8ed61dc8783bcc8ef4f6224d3ff00bc]/fbcode/datainfra/hive/warehouse_permission/if/warehouse_permission.thrift?lines=935)
 that extends `WareHousePermissionService`) - CompositeRpcServerHandler fails when duplicates are passed to create mapping.
Netty3 deals with that as part of `ThriftServiceMetadata` creation - all parent classes are discovered, but [duplicates in the same hierarchy are skipped](https://www.internalfb.com/code/fbsource/[061a880a36af]/fbcode/thrift/facebook/java/swift/swift-codec/src/main/java/com/facebook/swift/codec/metadata/ReflectionHelper.java?lines=157).
