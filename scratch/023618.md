Commit title: reified check: be more careful leaking type params through `this`
Commit body:
Summary:
## What

Allow reifying `this` in final classes only when the lexical class has no type parameters. See test case for an example.

And tweak error messages slightly to reflect the change.

## Why

In D75142486, we allowed reifying `this` in final classes. As dlreeves [points out] (https://www.internalfb.com/diff/D75142486?dst_version_fbid=2071678536575827&transaction_fbid=1244006060771101) that's a bit too loose.

It doesn't make sense to reify `C<T>` where `T` is not reified, and my previous change made it possible to sneak such a reification in.

Example from a test case:
```

final class C<T> {
      // Even if we think of `this` in a final class as sugar
      // for the lexical class, C::Tc shouldn't be reifiable.
      // Consider that we also ban
      // const type Tc = Id_of<C<T>> since type arguments
      // are not allowed in type constants
      const type Tc = Id_of<this>;
}
```
