Commit title: add a new upgrade lock flag to the state
Commit body:
Summary:
Introduce a new mutex state – "upgrade locked" which requires using two lower order bits to discern the mutex state instead of just one before this change. This change alone has two implications
* We lost one bit for counting the readers. `assert`s are added in case of overflow.
* When not unlocked, `state >= kSharedLockCountIncrement` and `state != kExclusiveLockFlag` are no longer equivalent, due to the new "upgrade locked" state. Changes are made to make sure conditions are expressed in a way that's compatible with the introduction of upgrade locked state.
