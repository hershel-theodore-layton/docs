Summary:
When using `Edenfs_watcher`, two different situations can happen:
1. The directory we are asked to watch *is* the mount point of an Eden repo. For example, this happens when running `hh` on `~/www`: We are watching the root of (an Eden mount of) a hg repository.
2. The directory we are asked to watch is a subfolder of the mount point. For example, this happens when running `hh` on `~/fbsource/www`: Here, `fbsource` is the mount point, and we are asking the `Edenfs_watcher` to run a subfolder of it.

Prior to this diff, our integration tests all set up a testing environment that exhibits situation 1, except for a single dedicated test for situation 2.

This diff changes the setup of our integration tests so that every test is run twice, once in situation 1. and once in situation 2. This seemed necessary as extended the testing this was has already caught a bug in this stack.

Technical details:
- This is achieved by having a single class `EdenfsWatcherTests` that defines all tests. This class inherits from `CommonTests`, so that we inherit all tests from there and run them, too
- The tests in `EdenfsWatcherTests` are executed using `EdenfsWatcherTestDriver`, which does all the necessary setup of Eden and Watchman.
- There is a new `EdenfsWatcherNonMountPointRepoTests`, which does not define any tests of its own but inherits all of the ones from `EdenfsWatcherTests`. It defines a small test driver of its own which is a minor variation of `EdenfsWatcherTestDriver`.
