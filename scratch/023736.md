Commit title: clean up file change handling in Informant
Commit body:
Summary:
The `Informant` has its own Watchman subscription that it uses to learn if we check out a new commit in www (in particular: if the merge base changes)

This diff simplifies the interaction with Watchman in the `Informant` in two ways
1. We observe that the `Informant` never cares about what *files* changed. It ignores all `Files_changed` notifications received from Watchman. When it receives a `Changed_merge_base` notification, it stores the list of changed files attached to the notification, but that list of changed files is never read again. Therefore, this diff stops saving the `files` list received from `Changed_merge_base` within the `Informant's` own data strucutres.
2. Following the observation that the `Informant` does not care about file changes, we can simplify its Watchman subscription: Previously, `FilesToIgnore.watchman_monitor_expression_terms` contained a Watchman expression term saying that we want to be informed about changes to more or less all files. This diff replaces the entire expression term with `[false]`, which means that we don't want to be informed about any file changes.
