Commit title: Add support for quota_exceeded counter
Commit body:
Summary:
Implement support for the quota_exceeded counter. The `TENANT_QUOTA_EXCEEDED` error code may originate from the request pile enqueue process (as seen in the  [laser use case](https://www.internalfb.com/code/fbsource/fbcode/graph_index/common/ResourcePoolUtils.cpp?lines=72-77)) or from the reprocessing stage, but not both simultaneously.

Other considerations :

* Reasons for not adding the `quota_exceeded` to `server_overloaded` aggregated counter:
There might be customers relying on this counter; adding a new counter could break customer use cases.

* Reasons for not adding another aggregated counter, such as `loadshedding`:
a. It serves a similar purpose to `server_overloaded` and could have the same problems.
b. Some counters categorized as loadshedding are not actually an overload signal, for example, [HostOverloaded](https://www.internalfb.com/code/fbsource/[b5446cdcb616788b3c57c57267c982177fc7f576]/xplat/thrift/lib/cpp2/transport/rocket/server/ThriftRocketServerHandler.cpp?lines=938%2C946%2C950%2C958).

The safest and most useful approach is still emitting counters for individual purposes.
