## Context

We want to remove all uses of `DefaultFacebookBaseImpl` (trait that implements `FacebookService`) and eventually `fb303.FacebookService`. In WWW, all uses of this trait and hence `fb303.FacebookService` is handled via base class `FacebookAsyncBase`. In addition, this base class also provides access to trait `TThriftServicesPrivacyBypassingVCCentralizedAPI` which can only be used by `FacebookAsyncBase` and services that need this `vc` trait have to extend `FacebookAsyncBase`. As a result, this base class cannot be removed

1. **No need for `FacebookAsyncBase`** : Around **24%** of services that use `FacebookAsyncBase` do not need either of the traits.
2. **Only need FacebookService :** Around **50%** only need `DefaultFacebookBaseImpl` and not `TThriftServicesPrivacyBypassingVCCentralizedAPI`
3. Rest (26%) **need both**.

This stack mainly addresses the first 24%  by removing access to `DefaultFacebookBaseImpl` where not needed. (eg: service doesn't extend from `fb303.FacebookService` in the `.thrift` file.)

The other 75% requires changes to IDL files. Once IDL file is updated, the codemod will do the migration for those classes too.
