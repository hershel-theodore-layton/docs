Commit title: support ServerRevisionTracker when using Edenfs_watcher
Commit body:
Summary:
In general, `ServerRevisionTracker` gets informed about the following by `ServerNotifier`
1. Enter and leave transitions for the `hg.update` and `hg.transaction` states
2. Number of changed files

`ServerRevisionTracker` uses this information to make decision about when it may restart the server.

This diff ensures that when using a `ServerNotifier` backed by `Edenfs_watcher`, we correctly pass on this information to `ServerRevisionTracker`.

Since we cannot get informed about state transitions (i.e., item 1. above) by Eden, yet, this diff ensures that when `ServerRevisionTracker` is backed by `Edenfs_watcher`, we carry a Watchman instance around that we can query for these state changes. The Watchman instance we use for this purpose is configured to ignore all file changes, only reporting state transitions to us.

This diff also ensures that when processing changes we receive from `Edenfs_watcher` directly, we call `ServerRevisionTracker.files_changed` in the right moment (item 2. above).
