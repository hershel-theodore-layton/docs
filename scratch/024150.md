Commit title: Hh_logger compatible logging
Commit body:
Summary:
This diff changes logging inside the `Edenfs_watcher`. Since this code is only ever run by calling it from the server process, I want the logging to integrate seamlessly with the logging done by `Hh_logger`.

- Actual logging code moved from `libs.rs` to new dedicated file `log.rs`
- It respects two config options: a) Is info-level debugging enabled in `Hh_logger`? and b) is `edenfs_file_watcher_debug_logging` set?
- I've changed a few `log::info` to `log::debug` to make logging less noisy by default. In particular, the worker thread only uses the latter now.
- In the worker thread and `get_changes_sync`, we now debug-log the raw changes received from Eden, before processing and filtering them with `translate_changes`.
- MInor change in `get_changes_sync`: Don't print the new clock if it's the same as the previous one.

In general, I'm not a huge fan of this logging approach, since I'm implementing a limited, bespoke logger instead of using one of the many out there. But it seems like the least bad approach at the moment:
- There is the `hh_slog` crate, which is built around `slog`. But that seems to be designed for standalone executables, in particular it ignores the configuration of `Hh_logger`.
- I could use `slog` directly, but that disabled debug-level logging in release builds at compile time. They can only be re-enabled by enabling a particular cargo feature, which I don't think is possible using buck. But I want end users to be able to enable `edenfs_file_watcher_debug_logging` on a prod build and get debugging output in a `hh rage` result.
- We also use `env_logger` elsewhere, but that's supposed to be configure with environment variables, while I want to log in a way compatible with `Hh_logger`.
