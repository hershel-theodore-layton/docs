Summary:
This is a refactoring the preservers behaviour, while getting rid of more uses of the type `KindDefs.Simple.named_kind`.

## Status quo

Before the changes in this stack, we had the following groups of related functions in `Typing_phase`:

First group:
```
localize_targs_with_kinds
localize_targs
localize_targs_by_kind
```

Second group:
```
localize_targ_with_kind
localize_targ
localize_targ_by_kind
```

I don't know how we ended up having both a `by_kind(s)` and `with_kind` version in each groups.

After D77513436, the first two members of each group have been unified.

## In this diff

This diff changes the `_by_kind` functions in each group. Instead of making them act on kinds (represented as `KindDefs.Simple.named_kind` values), we can now define equivalent functions that just act on `decl_tparam` values.

Logically, these functions localize a type argument, but if the argument is a wildcard, they turn it into a `Tgeneric` and add appropriate bounds. Originally these bounds were obtained from the kind, now they are obtained from the `decl_tparam` value.

The code for doing so still behaves exactly the same as before: First add a value of type `KindDefs.kind` with the bounds to the environment, then add the bounds.

To reflect more closely what the functions are doing now, I've renamed both functions:
- `localize_targs_by_kind` becomes `localize_targs_constrain_wildcard`
- `localize_targ_by_kind` becomes `localize_targ_constrain_wildcard`

It would probably be worthwhile to consolidate the functions with and without the `constrain_wildcard` further, but I don't dare to go there at this point.
