Commit title: await_resume_result() protocol for co_await_result()
Commit body:
Summary:
The new comment in `AwaitResult.h` goes into the motivations for this, but the strongest reasons are these:

(1) For `Task<V&> foo()`, we can use `co_await co_await_result(foo())` to get `result<V&>`, which is a much more seamless experience than the `Try` analog

(2) This makes `co_await_result(foo())` more of a first-class citizen, as far as hot-path performance is concerned.

(3) This is the first significant step towards being able to transparently migrate `Task` to use `result<>` for internal storage. Then, combining that with `rich_error` (D73731681) would allow very efficient non-throwing, non-RTTI error paths in coro code. In particular, `rich_error` would give us extremely cheap "is stopped" signaling.
