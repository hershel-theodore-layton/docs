Summary:
Previously, any `CommutativeWrapperAwaitable` would unconditionally provide `getUnsafeMover()`, even if the wrapped thing did not.

The net result was that the example from the title would fail with

```
error: no member named 'getUnsafeMover' in 'folly::coro::Future<int>'
```

The reason would be that `detected_or` in the `mustAwaitImmediatelyUnsafeMover` declaration would see the `CommutativeWrapperAwaitable::getUnsafeMover` and try to use it. But that implementation of `getUnsafeeMover` would then call a non-existent member fn on `inner_`.

The resolution is to SFINAE-gate `CommutativeWrapperAwaitable::getUnsafeMover`.
