Summary:
Tests for reflection of `require this as` trait constraints.

[RFC] `require this as` constraints are returned (as all other trait constraints) by the `getRequirements` and `getRequirementNames` reflection functions.  However using the current API it is not possible to distinguish eg. `require this as` from `require extends` constraints.  For `require class` a separate `getRequiredClass` reflection function was added to access the class specified in a `require class` constraint.  Is it worth to add a similar call for `require this as`, so they can be told apart from `require extends`?
