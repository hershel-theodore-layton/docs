Commit body:
Summary:
We spend $2M+ on `enum_find_name` https://pxl.cl/7CD7B. We believe we can do better by prepopulating an array-based index for dense enums – `max() - min() < 2*size (or similar)`.
If a client only performs the value-to-name lookup on a dense enum, it might avoid creating the F14 lookup map as well.

clang's defaults `-fconstexpr-steps` to 1048576 – https://github.com/llvm/llvm-project/blob/main/clang/include/clang/Driver/Options.td#L2006C1-L2006C65. In this diff we limit the max size to 10k to avoid running into the limit; and 10K is large enough that should cover most thrift enums.
