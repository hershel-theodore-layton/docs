Commit title: IoUringBackend: do not issue recvzc for loopback sockets
Commit body:
Summary:
Add an option to disable zero copy receive on an AsyncIoUringSocket even if it is supported.

A Thrift server configured for zero copy receive may have connections from localhost that goes through loopback. These sockets have invalid NAPI IDs (i.e. is 0) and do not go through a real NIC so don't 'zero copy'. If these are processed with recvzc requests, they end up hitting the copy fallback path. This is both inefficient and causes problems because only NAPI can trigger refills.

Fix the problem by disabling zero copy receive on an AsyncIoUringSocket, if the underlying socket is loopback. This will cause the socket to be processed by an ordinary multishot recv request.
