Commit body:
Summary:
This diff ensures that an `Edenfs_watcher`-backed `ServerNotifier` returns clock values from `get_changes_{sync,async}`. Previously, we always returned `None` for the clocks.

This involves:
- Adding a variant for Eden clock values to `ServerNotifierTypes.clock`
- Making a few more `Edenfs_watcher` functions return a clock value
- In `hh_client`, handling only `Watchman` clocks, and handling `Eden` clocks the same as if there is no clock in the errors file at all (note that this means that this diff preservers the existing behavior in the client)

Technical details:
- Made `Edenfs_watcher.clock` abstract, as it should be.
- To avoid some cyclic dependencies, we cannot pass `ServerLocalConfig.t` objects to `Edenfs_watcher` anymore. I'm just passing the single boolean we care about directly now.
- To support the Meerkat deferral workaround (D77305320), we now store the most recent Eden clock in a `ref` inside `ServerNotifier`.
