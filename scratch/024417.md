Commit title: avoid deep copies for most mutable thrift-python inits
Commit body:
Summary:
If we remove unnecessary deep copies, we can completely close the deserialization gap between mutable and immutable python.
- 3x speedup on deserialization. This completely eliminates the gap with immutable Python.
- On init benchmark, mutable goes from 60% slower than immutable on one-element container part to slightly faster

Impl details: We currently keep a cache map of pre-initialized struct definitions, then deep copy unconditionally. However, deep copy (slow Python) appears to be way more inefficient than generating structs from scratch (C++), so let's skip the caching to avoid the deep copy. We still have to deep copy for select user-provided (IDL) defaults for non-scalar fields (structs and containers).
