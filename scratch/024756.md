Commit title: ThriftRocketServerHandler: reset Cpp2ConnContext userdata when closing conn
Commit body:
Summary:
In S537253, Ucache is not able to gracefully shutdown with Thrift workers not joining the main thread within a deadline.

`RocketServerFrameContext` belonging to a request holds `RocketServerConnection` alive via `inflightRequests_`. This context object is stored within a `RocketThriftRequest`.

Ucache uses Thrift EB mode, meaning requests are processed inline on the IO threads. Some TAO requests end up in a slow path and get enqueued into `slowReqsQueue_` in `tao::ConnectionContext`: https://fburl.com/code/nql8o7yz

Note that `tao::ConnectionContext` is userData within `Cpp2ConnContext`. This userData has a user supplied dtor that will drain `slowReqsQueue_`: https://fburl.com/code/8powahjd

This queue is only processed via `onWriteQuiescence_` callback when writes succeed on the socket: https://fburl.com/code/2buzy6wd During the shutdown sequence, writes may no longer succeed, meaning nothing will drain the queue of requests, but these requests also prevent the connection from being destroyed. Thus causing the deadline to expire.

To fix this problem, explicitly destroy the Cpp2ConnContext userdata when closing. This would happen normally anyway once `ThriftRocketServerHandler` is destroyed.
