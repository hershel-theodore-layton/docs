Commit title: use serialization-deserialization for true deep copy
Commit body:
Summary:
After some discussion, we opted not to use memo deepcopy, even though it fixes the internal data sync bug. The reason is that deepcopy with memo has implications for container of struct, like python `list[MyMutableStruct]`. If `lst = [s, s]`, then `deepcopy.copy(lst)` yields `[s1, s1]`. The current behavior on trunk yields `[s1, s2]`, which is better aligned with expected behavior. Using serialization + deserialization roundtrip

This diff also reverts the changes that disabled mutable serializer, to ensure the tests added in D78853414 still pass.
