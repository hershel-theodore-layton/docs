Summary:
This no-op code shuffle was inspired by two observations:
 - The user-facing vocabulary doesn't depend on `binding_policy`, and shouldn't need to know about it. Less stuff to compile in end-user code is better!
 - `binding_policy` is actually `bind_to_storage_policy`, since e.g. `safe_closure()` needs a completely different kind of policy (upcoming as `bind_as_argument()`), which is binding a value **from** storage to a function argument.

Here, I split out the policy stuff to emphasize the looser coupling, and updated the comments to make it clear that multiple policies are possible.

Note that I'll fix up `Bind.md` on-stack.
