Commit title: Use address of `abort` instead of `malloc` as random seed
Commit body:
Summary:
Turns out using address of `malloc` as a random seed is not a great
idea, because it is too complicated.

1. `malloc` defined as a weak symbol to allow redifinition and it dev builds
address of this definition is quite stable.
2. When `malloc` is linked statically into binary there are not a lot of
randomization either, because by default ASLR randomizes only mmap base, stack,
VDSO page, but code randomized only for PIE-linked binaries. See [kernel
documentation][1] for more details.

In contrast, shared libraries loaded address will be random by default, when
ASLR is on. Because of that address `malloc` is not a great seed value, while
`abort` (or any symbol, that is coming from shared object is better).

Basically, current implementation doesn't work as designed, because
randomization is quite limited. I would like to have simple **per-run** random
instead of probability of per-build random.

[1]: https://docs.kernel.org/admin-guide/sysctl/kernel.html#randomize-va-space
