Summary:
Member functions of `std::vector` that can cause a reallocation usually requires the value type to be [Cpp17MoveInsertable](https://en.cppreference.com/w/cpp/named_req/MoveInsertable), because a type with deleted move constructors (and hence "usually" not move constructible, but not quite, see exception below) cannot generally be safely moved in vector reallocation.

However, the tricky part is that a type that's not move constructible can be trivially constructible, and small_vector's `reserve()` and `resize()` operations has historically accepted these types. This behaviour diverges from both libstdc++ and libc++'s vector implementation and makes a migration to one of the standard vector types impossible.

### Why move constructible?

One may ask why we choose to require move constructibility instead of copy on trivially copyable types. The answer is that vector almost always perform relocations with move construction. A trivially copyable type with deleted move constructor, e.g. (std::shared_mutex under libstdc++) is never intended to be moved.

[[over.match.funcs.general]/9](https://eel.is/c++draft/over.match.funcs#general-9) states that, "A defaulted move special member function that is defined as deleted is excluded from the set of candidate functions in all contexts." Hence, the following example shows a class that has a defaulted but implicitly defined as deleted move constructor is move constructible: https://godbolt.org/z/e6snzPdbq
