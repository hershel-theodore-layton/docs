Commit title: simplify set and map comparisons
Commit body:
Summary:
- I was worried that set comparison had the same issue as map, where comparing internal data containing mutable structs is buggy.
- However, this is not possible for `set` because mutable structs are not hashable.
- Added a comment to explain this.
- Simplify the map comparison.
- The current implementation converts `other` to internal data, but it'd be simpler to just compare the python values (implicitly converting `self` from internal data).
- The efficiency is the same but much simpler.
- This resolves undesired behavior where converting int types to internal data can cause `raise OverflowError`. Delegating to `__contains__` catches the exception and lets us return `False` instead.
- Similarly, `__contains__` catches `TypeError` lets us translate to `False`.
- Remove `_key_to_internal_data` method and `_key_type_is_container` member. Mutable containers are not hashable, so should not be used as key for map, or set element type.
