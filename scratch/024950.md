Summary:
Sink is partially implemented on the client side. While the logic for request seems already complete, the logic for handling response was unimplemented.

To more concretely explain what this is doing:
- `IOBufClientSink` is an alias for `IOBuf` specialization of `ClientSink`.
- When we initialize it, we connect it with the `ClientSinkBridge`, which does all the callback handling for sinks on the client side. We also provide a serializer (for encoding the streamed payloads), and a deserializer (for reading the final response).
