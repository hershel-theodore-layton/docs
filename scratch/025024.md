Commit title: Fix bug in parentage Rust implementation
Commit body:
Summary:
The `parentage` function recurses down the AST to find the full path to the leaf node covering the given source file offset.

It's supposed to work by recursively finding the child of each AST node that covers the given byte offset, by subtracting off
the byte spans of each child until it finds the one that encompasses the offset.

That's what the [OCaml implementation](https://www.internalfb.com/code/fbsource/[6c64013c7535c605e7943e4ccbab381e3192f936]/fbcode/hphp/hack/src/parser/full_fidelity_positioned_syntax.ml?lines=286-297) does:

```
(* Takes a node and an offset; produces the descent through the parse tree
   to that position. *)
let parentage node position =
  let rec aux nodes position acc =
    match nodes with
    | [] -> acc
    | h :: t ->
      let width = full_width h in
      if position < width then
        aux (children h) position (h :: acc)
      else
        aux t (position - width) acc
  in
  aux [node] position []
```

Note how the object `h` that it calls `full_width` on is the same one it recurses on.

Unfortunately, when ported to Rust, the Rust code used the wrong local variable, and rather than subtracting off the byte range
of each child AST node as it iterates, it kept subtracting off the width of the parent node over and over again.
This fixes the code to subtract off the child position.
