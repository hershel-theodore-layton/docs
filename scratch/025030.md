Commit title: Support implicit fallback of unresolved variables through Whisker self prototype
Commit body:
Summary:
Fallback into `self` object for missing variables in `mstch_compat` layer. This will allow redirecting missing `mstch_*` variables to the Whisker prototype exposed explicitly through `*:self.*`.

E.g. consider a `mstch` object which defines a property `my_obj:property` and its Whisker prototype which exposes `my_obj:self.property`. Using implicit fallback, we could remove the `mstch` property `my_obj:property` and have any usages automatically redirect to the Whisker prototype's `my_obj:self.property`.

The implicit fallback is implemented as a back-stop to `mstch` rather than the primary layer because the Whisker prototypes' properties return referenced objects' Whisker prototypes directly, rather than the equivalent `mstch` types.

If we automatically migrate these to Whisker prototypes as the primary lookup provider, later usages of properties can break due to the change (since they are now operating on a different type - a Whisker prototype, instead of the `mstch` object - with a different interface).

This streamlines migration to Whisker, while still requiring each `mstch` property to be removed to explicitly trigger its fallback to Whisker in later diffs.
