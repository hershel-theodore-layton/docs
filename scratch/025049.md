## Change to internals

Now, to expose a Typing_env API to Tast_env:
- Just move the declaration under `Expose_to_tast_env` in typing_env.mli
- 0 lines of code, just movement

See [example in next diff](https://www.internalfb.com/diff/D78813501?permalink=2514010865630971)

Advantages:
- Now it's easier to do the right thing (use Tast_env.env)
- Less risk of drift from having to keep typing_env and tast_env signatures and names in sync manually
- A lot less work to do the right thing. This diff removes ~120 LOC of boilerplate so far in tast_env.mli and Tast_env.ml, and prevents future boilerplate

## Before this diff

Before this diff, the process to expose use a Typing_env API when you have a Tast_env.env in your hand was to:
- "do the right thing":
     - copy-paste from typing_env.mli to tast_env.ml
     - write a boilerplate function in tast_env.ml that delegates to the corresponding Typing_env function

> Alternatively "do the wrong thing": punch a hole in the abstraction using "Tast_env.tast_env_as_typing_env". This diff unfortunately doesn't get us all the way to eliminating the abstraction-break entirely, but is a start

## Follow-on

Many abstraction-breaking calls removed in {D78813501}, using the technique introduced here.
