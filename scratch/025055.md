The current implementation of adapters uses BTree collections without the ability to specify a different type.

This diff is a quick way to unblock the incorrect code gen discussed in the workplace post by separating adapter logic used for structs. This enables users to specify both an adapter on a typedef and a field annotation to change a collection's type (`rust.Type {name = ...}` that uses that typedef.

That means a thrift file setup like:
```
rust.Adapter{name = "::fbthrift_adapters::UuidAdapter<>"}
typedef binary uuid

struct Foo {
  rust.Type{name = "HashMap"}
  1: map<uuid, i32> hmap;
  2: uuid standard_uuid;
  3: map<uuid, i32> btree_map;
}
```

Will generate output like:
```
pub type uuid = <::fbthrift_adapters::UuidAdapter<::std::vec::Vec<::std::primitive::u8>> as ::fbthrift::adapter::ThriftAdapter>::AdaptedType;

#[derive(Clone, PartialEq)]
pub struct Foo {
    pub hmap: ::fbthrift::builtin_types::HashMap<crate::types::uuid, ::std::primitive::i32>,
    pub standard_uuid: <crate::types::adapters::uuid as ::fbthrift::adapter::ThriftAdapter>::AdaptedType,
    pub btree_map: <::fbthrift::adapter::MapMapAdapter<crate::types::adapters::uuid, ::fbthrift::adapter::IdentityAdapter<::std::primitive::i32>> as ::fbthrift::adapter::ThriftAdapter>::AdaptedType,
```

## Limitation
Originally, I was trying to solve the general problem of allowing the (`rust.Type {name = ...}` on anything. This is pretty complicated using mustache alone since different thrift types `typedef`, `const type`, `struct` have different AST contexts that don't have a common function of pulling out annotations. For example; checking the annotation on a field of a struct can be done in mustache using `{{#field:type_annotation?}}`, but if a `const map` tries to use the same mustache template it throws an error since it doesn't have the `field` context.

This diff solves the problem of structs using `rust.Type {name = ...}` on the fields, but it doesn't solve scenarios where the (`rust.Type {name = ...}` is applied to a typedef.

```
rust.Adapter{name = "::fbthrift_adapters::UuidAdapter<>"}
typedef binary uuid

rust.Type {name = "HashMap"} // this doesn't work
typedef map<uuid, i32> uuid_map // this ignores the annotation and returns a BTreeMap

struct Foo {
  1: uuid_map data;  // this is a BTreeMap
}
```

I plan to solve this limitation by adjusting the generator in the thrift compiler to supply a common function for all types that have the (`rust.Type {name = ...}` annotation.
