Commit title: switch Eval.RenamableFunctions to hphp_fast_string_set
Commit body:
Summary:
There's at this point 75 functions in this config. In repo mode, this doesn't matter, but in sandbox mode we evaluate it:

* from HPHP::Func::unwrap() called from HPHP::jit::svcreq::handleResume
* HPHP::Func::lookupKnownMaybe called from HPHP::jit::irgen::emitFCallFuncD
* HPHP::FuncEmitter::create

We basically call it on every single (? correct me if I'm wrong here) function call to every builtin in sandbox mode. https://fburl.com/sbdive/v5gi0pxp shows that for workflows that call builtins often, this function can take up to 16% of wall time. Switching from RB-tree to a fast hash set will reduce computational complexity of funcIsRenamable from  O(k*logn) to O(k), and for 75 keys, it should be roughly ~3x improvement.

I'm also adding template specialization to encoders for std::string, because after D38920030, hphp_fast_string_set isn't supported for globaldata.
