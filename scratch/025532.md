Commit title: Fix hhvm instruction counters
Commit body:
Summary:
We sometimes observe decreasing instruction counts for psp instructions in dynostats: https://fburl.com/scuba/dynostats/nqsd1m7g

On investigating the issue seems to happen due to the scaling factor introduced due to multiplexing of counters(https://perfwiki.github.io/main/tutorial/#multiplexing-and-scaling-events)
e.g it is possible to get 2 data points that lead to a decreasing value

value = 5, time_elapsed = 10, time_running = 2, final value = 25
value = 6, time_elapsed = 12, time_running = 4, final value = 18

What we need to do here is to use the delta between subsequent values instead

final value = 25 + (6-5) * (12-10/4-2) = 26

This will allow us to scale the counters correctly

References:
1. D19406260 and D5556100 do something similar in dyno for kernel counters
2. https://fb.workplace.com/groups/dynousers/permalink/28791637380458170 similar note on bperf measurement discrepancies
