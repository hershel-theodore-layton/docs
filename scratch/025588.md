Commit body:
Summary:
context: https://fb.workplace.com/groups/192968587972839/permalink/1794182631184752/

An executor is responsible for restoring the RequestContext of the Task before execution (see ThreadPoolExecutor: https://fburl.com/code/jgso22bo). BlockingWaitExecutor wasn't doing this. This is rarely a problem, as the folly::coro::Task wraps the task in logic to restore the context as part of the await_suspend: (see https://fburl.com/code/mtop038c ). Unfortunately this leaves a tiny gap of time between when runTask starts and when the context is actually restored.This caused a minor bug in a custome Executor wrapper we used that uses a pattern similar to the SequenceExecutor.
