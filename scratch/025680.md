Commit title: improve register allocator behavior for callFuncEntry
Commit body:
Summary:
Problem:

Virtual call func entry callees are both copied into a physical register and are used to extract the func entry out of.

Previously, we would first copy `%callee` into the %fe_callee_id physical register (rsi in x86), then load `offset(%callee)` into a different register. This caused the register allocator to consider rsi as an ineligible register for `%callee`, causing unnecessary moves.

Flip the order to fix this.

This diff itself should be perf-netural, but will have an impact once we start calling virtual func entries.
