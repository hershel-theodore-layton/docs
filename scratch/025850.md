Summary:
Problem:
- Inbound H2 RST_STREAM(NO_ERROR) could crash via adaptor path: HTTPTransactionAdaptorSource::onError -> HTTPException2HTTPErrorCode -> ErrorCode2HTTPErrorCode(NO_ERROR) (pre-fix had a CHECK).
- NO_ERROR is valid on the wire per H2/H3; session layer also normalizes H2 NO_ERROR to CANCEL for consumers.

Fix:
- Allow NO_ERROR in ErrorCode2HTTPErrorCode and HTTP3ErrorCode2HTTPErrorCode (remove CHECK), preserving mapping semantics.

Tests added:
- H2DownstreamSessionTest.ResetStreamNoError: client sends RST_STREAM/NO_ERROR; verify source sees CANCEL and message suffix "details=received RST_STREAM from peer".
- HTTPTransactionAdaptorSourceTests.IngressNoErrorAbortNoCrash: drive adaptor onError with codec status NO_ERROR; verify error surfaced and no crash.

Repro (pre-fix):
- Reintroducing XCHECK(ec != ErrorCode::NO_ERROR) causes adaptor test to abort, confirming the crash path.

Notes:
- This aligns behavior with RFCs and avoids fatal checks for legitimate peer behavior.
