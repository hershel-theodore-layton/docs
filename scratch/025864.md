Commit title: Make the algo "only" quadratic instead of exponential
Commit body:
Summary:
Per every allocated Hack object, objprof recursively walks all reachable items
and add up their memory cost.

When there are multiple paths, it would take all of them, which could be
exponentially many, as trivially demonstrated by the updated unit test.

When that happens, HHVM will be stuck in objprof until the heat death of the
universe. That's not the nicest way for HHVM to die, so let's get this fixed.

The algorithm already had protection against cycles. Trivially replace stack
values with seen values.

There are APIs that try to obtain list of all paths, but these APIs are
inherently unsupportable, so after this diff they will just return one path.
