## Context

EdenFS notifications stores state inside a special folder in the mount root. When a 'root' value is passed in, changesSincev2 filteres out any values not in the specified folder, including state changes.

The intention of this stack is to add a new bool field into changesSinceV2 to allow using root values alongside states.

State changes are currently read inside the stream_changes_since_with_states wrapper, but it would be cleaner to just handle it here since we're currently adding feature support for roots as well

## Other options

At D75562824, we tried integrating reading these values directly into the changesSinceV2 stream.

In a followup diff D78737776 to the states library, Frank offered something similar to support Hack's use case, but alongside the eden client.

The original reason for not tracking state changes inside the EdenServiceHandler was that we were trying to avoid making large changes inside changesSinceV2 because of prior dependencies upon it. Since we're making a change now, it might be worth considering pushing change parsing down into it at this point in time
