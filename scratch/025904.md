Commit title: Make 'type:structured' operate on typedef-resolved type
Commit body:
Summary:
- Make `mstch_type::get_structured` (aka `type:structured`) consistent with other properties and act on the resolved true type rather than (potential `typedef`) unresolved type
- Stop resolving `get_true_type()` in `python_mstch_type` base constructor call
  - This allows the Python Whisker `t_type` prototype to have access to the un-resolved type, rather than only the resolved type
  - Update Python Whisker `t_type` prototype properties to call `get_true_type` which was previously pre-resolved by `python_mstch_type` prior to `self` instantiation
- Remove `TODO` about `typedef` not being visible in Python metadata
  - Root cause was since typedefs were transparently resolved, the information was unavailable to the template
  - Replaced with a feature flag until we have a resolution on whether to start emitting typedef metadata
- Update a handful of other languages' templates which were manually resolving `typedef` for structured definitions by recursing the same template, as a workaround for the `mstch_type::get_structured` behaviour
  - Fixtures are unchanged - output is identical
  - This is to simplify templates, and also as a proof-of-concept that this change is safe across all languages
  - More instances of this still pattern remain, to avoid bloating the scope of this change too much and also as a safety test for non-changed templates
