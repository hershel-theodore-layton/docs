Commit title: Clear missing decls between individual typechecks on worker level
Commit body:
Summary:
After running some individual actions I've noticed that workers produce pending files in non-determinitstic fashion. This could be easily tested by running the same action multiple times and comparing it outputs. This shouldn't be like that though - with the same input action is supposed to produce the same result. Actions were producing the same results in terms of missing decls but pending files were varying each time. I've noticed that after typechecking each individual definition we produce a list of missing decl here:
https://www.internalfb.com/code/fbsource/[99d65ca8be6bde60dac4efb94ecc78610c3e737b]/fbcode/hphp/hack/src/facebook/hh_distc/worker/typecheck.rs?lines=568
The problem is that it appears like we never clear this list which mean that as soon as worker typechecks one definition with missing decls all the subsequent typechecks are poisoned and also report missing decls. Since RE worker runs multiple workers itself in parallel the behaviour I've described above introduces non-determinism.

This non-deterministic behaviour is problematic since it means that all the batches except the original batches created at decl stage are not stable so we don't hit CAS caches and keep uploading more and more data which is not being reused.

This diff sets up an experiment based on `hack/config:distc_clear_missing_decls` JK to clear missing decls between individual definition typechecks which results in deterministic pending files returned, which in turn results in typecheck attempts having stable batches.
