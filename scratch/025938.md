Commit title: implement libc++ specific whole word bitset find_first and find_next functions
Commit body:
Summary:
Efficient (but unfortunately, not very clean) implementation of bitset find_first and find_next using bit counting STL functions one word at a time.

The motivation of this diff is to provide an implementation for `std::bitset::_Find_first()` and `std::bitset::_Find_next()` which are provided as extensions only in GNU C++. These two functions are not standardized so unfortunately libc++ won't implement them. To make things worse, the specification of bitset doesn't expose any implementation detail on the underlying data structure which are usually implemented as [words](https://github.com/llvm/llvm-project/blob/main/libcxx/include/bitset#L199C3-L199C17).

The implementation here chose to poke into `std::__bit_reference` since it's relatively stable. We can obtain such from the `operator[]`. Then, we use the dangerous `reinterpret_cast` to find the underlying word

This implementation did not refer to how `_Find_first` and `_Find_next` are implemented due to licensing reasons. I implemented this strategy based on the belief that checking entire words are faster than checking it bit by bit. It's not hard to see that repeating the whole steps of reading a word from memory, computing a mask, and checking eq to zero is a lot slower than `std::countr_zero` at word level.

My microbenchmark results seem to support this claim.
