Commit title: Add new option to ShardSplitRoute to change the fanout of a client from one to N replicas.
Commit body:
Summary:
ShardSplitRoute ensures that a single clients read traffic will go to a single replica.
If a shard is hot, split traffic from a given client to a given shard will use only a single proxy. This proxy can become a bottleneck and cause TKOs. This diff implements the routie handle option:

```
"split_shard_fanout": INTEGER
```

The split_shard_fanout will mean that instead of using a single connection, a client can use split_shard_fanout connections to talk to the backend server.
