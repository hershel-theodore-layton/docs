Commit title: Handle parallel observers and transport-generated events.
Commit body:
Summary:
AsyncSocket allows multiple observers.  If any observer registers for an event (eg TX/ACK), the byteEvent callback will be called on all observers.  This could have caused these CHECKs to fire, because the other observer did not request a write callback.  This can only really happen when the underlying transport generates its own writes (eg: TLS messages other than TLS records carrying application data).

Now we allow updating the max(tx/ack)Offset and call fireEvents.

1) It may cause a previous callback to fire, when the cumulative ack includes both an HTTP registered event and a non-HTTP one.
2) The use of the offset is to determine if a TX or ACK happened before we were able to schedule the event. The path is

a. Register for WRITE+TX
b. transport->write
c. Write Event fires
d. Transport generated write
e. Cumulative TX byte event fires
f. transport->write returns
g. scheduleOrFireTxAckEvent

In this case, maxTransportTxOffset_ might be greater than maxTransportWriteOffset_, so use >= instead of == checks to determine whether the event has already fired.

It's not clear any transports (eg: TLS) do this in practice.
