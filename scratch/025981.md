Commit title: Ensure types are fully resolved before running standard mutators
Commit body:
Summary:
When `allow_missing_includes` is true, we may end up with unresolved types (types which are coming from an include which is missing).

If these types are forwarded locally (included from a missing program `foo.thrift`, into a root program called `foo.thrift` and aliased locally with `typedef foo.MyType MyType`), the typedef can end up self-referencing.

Semantic validation cycle detection catches this, but if `t_type::get_true_type` is called *before* the cycle detection, it can get stuck in an infinite loop resolving the typedef to itself. None of our standard mutators mutate user-defined types, but a number do access `t_type::get_true_type`, so we run them after the cycle detection check has passed.
