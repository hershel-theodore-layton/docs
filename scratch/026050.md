Commit title: Fix FieldInfo is-primitive and adapter info for function result types
Commit body:
Summary:
Fix `FieldInfo` for function return/response/stream types - previously, when the active scope is a type rather than a field, the `field:has_adapter?` and `field:type` properties would evaluate to null (falsy), and always result in `None` for adapter info and `False` for primitive-ness.

Fixed by changing the `is_primitive` template to act on a type, and by changing the `adapter_info` template to be AST node type agnostic, as long as it supports `has_adapter?`.

Remove no longer necessary `allowed_undefined_variables` directive in Python generators.
