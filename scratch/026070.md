Commit title: Implementing io_uring receive buffers into folly.
Commit body:
Summary:
This diff implements **incremental receive buffers** functionality for io_uring in folly, which enables more efficient handling of partial buffer consumption and buffer reuse.

Motivation:

Currently, the buffers provided to services using folly-io_uring are designed with a constant size. Each `IoBuf` is mapped to a single provided buffer (1:1 mapping), even when the buffer size is significantly larger than the object itself. This leads to fragmentation problem where utilization of the underlying memory is minimal. With these changes, the provided buffers can be consumed partially.

Implementation Changes:
* Added `BufferState` struct to track buffer metadata including reference counts, offsets, and parent references.
* Replaced the previous `ioBufCallbacks_` vector with a`bufferStates_` array for proper state management.
* Modified `IoUringBufferProviderBase::getIoBuf()` to accept a new `hasMore` parameter that indicates whether there's more data coming for the same buffer.
