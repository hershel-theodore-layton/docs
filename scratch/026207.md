Commit title: Lint unscoped enum value resolution mismatch
Commit body:
Summary:
In the Thrift IDL, an enum value can be used without providing the enum name as a scope, e.g.
```thrift
> in foo.thrift

enum Thing {
    FOO = 1,
    BAR = 2
}

const Thing A_THING = FOO;
```

This is problematic because `FOO` can be resolving by multiple different identifiers:
* `FOO` - Just the value name
* `Thing.FOO` - Unscoped enum_name + enum_value
* `foo.FOO` - Scope name + enum_value
* `foo.Thing.FOO` - Fully qualified name

Contrary to non-enum-value definitions, newer *flattened* enum values (i.e. `foo.FOO`) do **not** override prior definitions in the global resolution map.
Due to this inconsistency, there's a fairly high likelihood of conflict during resolution.

While we should likely disallow the usage of enum values
as identifiers by themselves, currently the resolution mismatch lint is capable of detecting ambiguity **only** when the enum value is overridden by another thrift program, i.e.
when `<scope>.FOO` is overriden by another `<scope>.thrift` file's enum value `FOO`.
