Commit title: Always use RequestContextSaverScopeGuard to restore request context
Commit body:
Summary:
There is a common pattern of saving the request context and restoring at the end of each iteration of a loop. This could fail to restore if the loop body throws an exception.

This diff switches those patterns to using `RequestContextSaverScopeGuard` and `restoreContext()` instead. Besides the exception safety, this has the additional benefit of avoiding a `shared_ptr` copy when the context is already the right one (which should be the common case), and of removing direct calls to `RequestContext::setContext()`.
