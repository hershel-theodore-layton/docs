Commit title: Add const-ref overload for make(Semi)?Future(ExceptionObject) for calls explicitly specifying exception type template parameter
Commit body:
Summary:
**Background:**
Previously, `folly::make(Semi)?Future` did not have an overload for rvalue exceptions. As a result, calling `folly::makeSemiFuture<int>(SomeExceptionClass(initializers...))` would copy the exception object instead of moving it.

**Change in [D81684918](https://www.internalfb.com/diff/D81684918):**
- Updated `folly::make(Semi)?Future` to accept exceptions via universal references instead of `const&`.
- This allowed both lvalue and rvalue exceptions to be handled optimally.
- However, universal references require automatic function template argument deduction.
- Usages that explicitly specified the exception type and passed an rvalue started failing to compile.

**This Diff:**
- Reintroduces the `const&` overload to support cases where the exception type is explicitly provided and an rvalue is passed.
- Marks the `const&` overload as deprecated.
- This allows existing code to compile and provides a path for graceful migration away from explicit template parameter usage, without blocking compilation.
