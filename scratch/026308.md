Commit title: introduce optional call count counters for all translations and log to scuba
Commit body:
Summary:
Problem: We don't have visibility into which translations end up as live vs. optimized, and have encountered performance characteristics that indicate we have an unexpectedly high number of live prologues being called.

This change makes it so that when the `Jit.CollectTranslationStats` flag is set, HHVM will emit extra counters at each region's first instruction that gets bumped on each call, and the totals of these counters will be written via StructuredLog during process shutdown for all SrcKeys above a min call count threshold. The data collection is modelled after `IncProfCounter`.

By default, the lowest threshold to report is 5000 calls. This may be modified by the `Jit.ReportTranslationStatsMinCallCount` config that does what it says on the tin.
