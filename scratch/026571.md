## Code Guide

- The logic for checking args was and remains pretty complex and involves multiple passes. Focusing on main changes:
     - Before:
          - We tracked how many "plain params" were remaining in a pass. "Plain params" (my terminology) are non-optional, non-variadic, non-named, and non-splat. They were previously represented by the `paraml` parameter passed to recursive calls.
              - The "l" in "paraml" apparently stood for "list" even though we use pluralization elsewhere. I originally thought it stood for "left" as in "remaining", but probably not.
         - We did not track how many plain parameters there were: instead we calculated the same value from scratch on each recursive call. I found this confusing, and also didn't want to do the same thing for named params (since the calculation is longer), so calculated this once at the top: `plain_params_remaining`
    - After:
         - For plain params (see definition above), we track which are left in a pass (`plain_params_left`) and the original from the function param list (`plain_params`)
        - For named params, we track which are left in a pass (`named_params_left`) and the original from the function param list (`named_params`).

## Trade-offs:

- I renamed `check_arity` to `check_arity_and_names`. I did this so it would be obvious where we need to update code, and hard to forget to check for extra-and-missing-names
- I originally split arity/name-checking and type-checking into two diffs, but didn't want the reviewer to have to look at all the snapshots twice.

## Future work

- checks for overridden methods
- etc., see proposal https://fburl.com/hack_named_parameters_proposal
