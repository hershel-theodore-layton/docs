Commit title: New type loading mechanism for false cycles
Commit body:
Summary:
The current autoloading algorithm will attempt to retry loading every symbol in a unit until it reaches a fixed point. This is effective at negating the effect of dependency ordering within a unit, but does not address the potential for cross unit-dependencies to be order sensitive. Consider the new test that contains these dependency chains:

 - B1 (cycle.inc) -> A2 (cycle.php) -> I (cycle.inc)
 - A1 (cycle.php) -> B2 (cycle.inc)

Alone there is no cycle here, but because these dependencies span two files we fail to load them as there is no way to fully load either `cycle.php` or `cycle.inc` without partially loading the other. Even more confounding, if we had loaded `cycle.inc` first rather than `cycle.php` the old loading algorithm would succeed.

This new approach instead loads symbols individually using a topological sort to ensure that dependencies are loaded in the correct order.
