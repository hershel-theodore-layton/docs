Commit title: Byte Event callbacks and Telemetry
Commit body:
Summary:
HTTPByteEvents are coro's way to implement telemetry. You add a ByteEventRegistration to a HTTP event (header or body) and you can register for 4 types of events:
- TRANSPORT_WRITE = 0x01,
 - KERNEL_WRITE = 0x02,
 - NIC_TX = 0x04,
  - CUMULATIVE_ACK = 0x08,

For HTTPTelemetry (https://fburl.com/code/pquj4312), we need the latter three

ByteEventRegistrations have a weak pointer to the callback, so the callback *could* be deleted by the time the event happens. We don't want this to happen, so I made our byte event callbacks self-owned.

Before we run PSP, we want to ensure all byte event registrations were either cancelled or fulfilled. So, I made a class called `CallbackCounter` which you can get a lease by running `acquireLease()`, and you can co_await `wait()` which will wait until all outstanding leases are deleted. We give every byte event callback a lease, and have it delete itself upon fulfill or cancel, and then in `summarizeRequest` we just `co_await wait()` so we're sure the transaction is actually complete (at least as far as we care).

Two callbacks:
- `HeaderSizeByteEventCallback` which takes a telemetry and a lease and will update the telemetry with the egressed header size (as well as the time when the first header bytes were acked)
- `BodyByteEventCallback` which takes a telemetry and a lease and will update the relevant timepoints in the telemetry

One filter, `HTTPTelemetryFilter`, which registers the above callbacks on events passing through the filter

A few other related changes, including
- Change `CompletionVisitorFilter` to `CompletionTransformFilter` so the HTTPRevProxyHandler's filter (which is this filter) can modify HTTPEvents
- `getUpstreamServers()`, `get[Upstream|Downstream]Telemetry()`, `getUpstreamTransportInfo()`
