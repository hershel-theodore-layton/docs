ConnectionManager is the main place where we can control the connections drop flow. In this diff I try to smooth the drain process by splitting all connections to drop in one round into batches

Now the logic is following:
1. Call the `ConnectionManager` with
1.1 percentage of drop
1.2 total time we want to use for the drop
1.3 time of each round of connection drop

2. `ConnectionManager` at the time of the function call will calculate the target amount of connections it should have (`conns_.size() * (1.0 - dropPct)`) and will start a first round of drop
3. After the first round, we recalculate how much time more do we have, and schedule next round
3.1 If we don't have any more time, we will drop all remaining connections right away
3.2 If for any round we spent too much time, we will adjust the amount of connections we will drop in the next round
4. If the connections amount is `<=` our target amount, we stop scheduling next rounds. So we don't care if we dropped those connections, or they closed via other mechanisms

The old logic was:
1. Call the `ConnectionManager` with percentage of drop
2. `ConnectionManager` drops `conns_.size() * dropPct` one by one simultaneously
