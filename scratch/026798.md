Commit title: Fix stopTLSv1
Commit body:
Summary:
### Problem

The Thrift stress test client crashed with the following error: `EventBase.cpp:453] Check failed: evbTid == curTid`.
This occurred when running with `--stopTLSv1 true` and the stopTLSv1 negotiation failed (i.e., the server does not support stopTLSv1). This error indicates **EventBase operations were being executed on the wrong threads**, violating Folly's strict thread affinity requirements.

### Root Cause Analysis

Three threading violations were identified:

1. **Socket Creation Threading Issue**: The `AsyncSocket` constructor was being called on the connection thread instead of the target EventBase thread, even though the correct `targetEvb_` was passed as a parameter.

2. **Fizz Client Destructor Threading Issue**: The `fizz::client::AsyncFizzClient` was being destroyed on the wrong thread when `FizzStopTLSConnector` went out of scope.

3. **Server Compatibility Threading Issue**: When servers don't support stopTLSv1, the negotiation timeout/failure caused the `FizzStopTLSConnector` destructor to be called on the wrong thread during error handling.

### Fixes Applied

#### 1. ClientFactory.cpp - Simplified Socket Creation

**Problem**: Complex thread-checking logic caused `runInEventBaseThreadAndWait()` to be called from within an EventBase loop, which is forbidden.

**Solution**: Simplified to direct socket creation since client initialization already happens on the target EventBase thread.

#### 2. FizzStopTLSConnector.h - Fixed Client Destruction Threading

**Problem**: The Fizz client was being destroyed on the target EventBase thread instead of the connection thread where it was created.

**Solution**: Explicitly move the client to the connection thread for safe destruction.

#### 3. ClientFactory.cpp - Added Graceful Fallback for Non-Supporting Servers

**Problem**: When servers don't support stopTLSv1, negotiation timeouts caused threading violations during cleanup.

**Solution**: Added try-catch around stopTLSv1 negotiation to detect failures and automatically fall back to regular FIZZ connections with proper error logging.

#### 4. FizzStopTLSConnector.h - Enhanced Destructor Thread Safety

**Problem**: The destructor didn't properly handle cases where the object was destroyed due to exceptions or timeouts.

**Solution**: Added explicit destructor that ensures `AsyncFizzClient` cleanup always happens on the correct EventBase thread, regardless of how the connector object is destroyed.

### Notice
When benchmarking stopTLSv1 and stopTLSv2, please use the target `fbsource//xplat/thrift/conformance/stresstest:Server` on the server side, rather than `fbcode//thrift/facebook/stresstest:Server`. The latter relies on `ServiceFramework` and will ignore the input options.
