# Motivation

Coro HttpServer currenty only supports a single socket/ single acceptor. This is probably feasible for 99% of cases. Fwdproxy however, relies on being able to define multiple ports/acceptors, for example to support multiple ports or different protocols. Our offnet fwdproxy implementation currently uses Coro HttpServer, and we now have a few cases (cloud, CIFT++) where we want to support multiple ports

# This diff

In this diff, I lay the groundwork for support multiple sockets/acceptors will remaining backwards compatible. This diff simply upgrades our data structures from singular socket/singular acceptor to multi-socket/multi-acceptor. **All the existing code for initializing the socket/acceptors** still assumes we are creating only one, as again this covers all existing cases right now.

I modify a few functions that really only make sense in the single socket/acceptor to continue to only be used for these use cases, and will throw otherwise to make backwards compatibility simpler.
