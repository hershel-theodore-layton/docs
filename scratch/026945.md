Note: this diff is the successor to D79832731 after addressing feedback that effectively required rewriting the diff - rather than using a lot of messy/bloated subclasses, we introduce a pluggable std::function.

# Context

coro HTTPServer only supports a single socket/acceptor model right now - we wish to expand fwdproxy to be handle to support multiple ports, and multiple acceptors for our implementation using HTTPServer.

# Last diff

Last diff (D79056566) we modified HTTPServer's internal data structures to support multiple sockets/acceptors, but gave no easy mechanism to set multiple instnaces.

# This diff

In this diff, we introduce the ability for users of HTTPServer to provide a custom function to generate socket and acceptors, superseding whatever existing logic is used within HTTPServer's implementation.

This allows fwdproxy, which heavily relies on it's own config rather than the HTTPServer:Config object, to build its own custom socket/acceptors.

# Next diff

Has an application of these changes to enable fwdproxy to use multiple ports.
