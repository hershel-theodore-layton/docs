Server-side API looks approximately like this (example):
```

service FileService {
  i32 /* file size */, stream<binary> StreamFileChunks(1: string filePath);

```

# Go Handler code
func (h *Handler) StreamFileChunks(ctx context.Context, filePath string) (int32, func(context.Context, chan<- []byte) error, error) {
    fileInfo, err := os.Stat(filePath)
    if err != nil {
        return 0, nil, fmt.Errorf("error statting file: %w", err)
    }

    file, err := os.Open(filePath)
    if err != nil {
        return 0, nil, fmt.Errorf("error opening file: %w", err)
    }

Supports:
* Initial response (optional - if Thrift schema defines it)
* Initial error
* Streaming elements
* Streaming error
* Streaming is done by a user-defined `func` object.
    * The function will be invoked by Thrift library logic outside of codegen (to be implemented downstream).
    * `Context` object *should* be used for detecting stream interruption (e.g. client disconnected) and gracefully cleaning-up/terminating the stream.
    * `chan` should be used to "stream" elements.
    * Streaming can be interrupted upon an error ("streaming error") - by returning the error from the function.
    * Upon successful stream completion, the function should cleanup resources and return `nil` to notify Thrift library logic of completion.
    * Users *should* follow recommended practices above to avoid Go-routine or other resource leaks.
