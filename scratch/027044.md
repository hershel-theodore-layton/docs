Summary:
# Problem
The converter's `_to_py_deprecated()` method attempts to import py-deprecated or py-deprecated-asyncio modules even when the thrift compiler never generated those variants. The original design expected these imports to fail with `ModuleNotFoundError`, but due to Python's global namespace for imports, the converter sometimes successfully imports completely unrelated modules that happen to have similar names. This leads to incorrect conversion behavior where the converter uses the wrong module.

# Solution Approach
Only generate converter import code for py-deprecated variants that actually exist. Instead of always attempting imports and relying on import failures, the solution uses compiler flags (`has_py_deprecated`, `has_py_deprecated_asyncio`) to determine which variants were actually generated. If a variant wasn't generated by the compiler, the converter raises `NotImplementedError` immediately rather than attempting any imports.

# Impact
Eliminates incorrect converter behavior caused by accidental imports of unrelated modules, ensuring converters only attempt conversions for variants that actually exist. This makes the system more reliable and prevents subtle bugs from namespace collisions.
