Add a few new microbenchmark functions for basic aligned and (cache line and page) unaligned memory accesses. Benefits of these new functions are:

1. They show concrete numbers about unaligned access penalties, which are usually not documented in CPU specs.

2. They help understand and validate assumptions in string function implementations. For example, when memcpy's source and destination pointers cannot be both aligned, which pointer should we align for better performance? If unaligned loads are cheaper than unaligned stores, then we should probably align the dest pointer and vice versa.

3. They help reverse-engineer microarchitectural details of CPUs such as whether a CPU supports store-to-load-forwarding (STLF) or not, and how well it supports STLF. For example, on Arm64 Neoverse V2, we got the following results,
// scalar_memops(aligned_reads_writes)                         3.53ns   283.00M
// scalar_memops(aligned_reads_writes_stlf)                    2.01ns   496.65M
On AMD Bergamo,
// scalar_memops(aligned_reads_writes)                         7.47ns   133.86M
// scalar_memops(aligned_reads_writes_stlf)                    1.23ps   810.34G
It appears that both CPUs support STLR and AMD Bergamo's STLF support is much more aggressive than Arm64 Neoverse V2.
