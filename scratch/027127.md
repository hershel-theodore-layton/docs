Commit title: Emit one fixture test case per compiler command
Commit body:
Summary:
Currently, the fixture test emits one test case per fixture, which loops through all the compiler invocations within that fixture.

This has a few downsides:
- failures are reported per fixture, not per language
- one failure aborts any subsequent comparisons within that fixture
- debugging one failing case is difficult, because you need to break on the specific case you're interested in within the loop
- lower concurrency when executing tests

This change switches to emitting one test case per fixture/command combination. This makes each test case more granular, resulting in more granular results reporting (i.e. failure reporting is at the level of *adapter fixture for python_a failed*, rather than *one of the adapter fixtures (any language/file) failed*), easier debugging due to granularity, and 50+% test execution time reduction due to increased concurrency.
