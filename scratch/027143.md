Commit title: Add fixture to reproduce inject metadata fields issue.
Commit body:
Summary:
This change creates tests to reproduce a specific failure with `internal.InjectMetadataFields`. The failure occurs when an injected metadata field is a struct type from an included thrift file, which in turn depends on a type from a different thrift file that is not included in the thrift file that injects the metadata field. This transitive dependency chain results in execution failures due to undefined symbols, as the generated Python code references types that haven't been imported.

Existing tests did not capture this multi-file dependency scenario. This change adds both components needed to reproduce the issue:

• **Test files**: Creates thrift files with the specific dependency chain pattern (`test_inject_metadata_fields.thrift` → `dependency.thrift` → `injected_field.thrift`) and adds a Python test case in `metadata.py` to validate the import behavior

• **Fixtures**: Establishes thrift test fixtures that mirror the same transitive dependency pattern, which allows consistent reproduction of the undefined symbol errors across the thrift test suite

The tests create a controlled environment to reproduce the failure and validate when fixes correctly handle these transitive dependency scenarios.

This thrift-python user post - [link](https://fb.workplace.com/groups/thrift.py3/permalink/3258680190950417/) - revealed that this problem is visible in user code.
