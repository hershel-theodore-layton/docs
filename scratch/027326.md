Commit title: Initiate path probing and active connection migration on the client
Commit body:
Summary:
Implements active connection migration with path probing on the QUIC client. The client can not probe a path before migrating to it.

**Behavior Changes**
- onNetworkSwitch() now initiates a path probe and immediately migrates to that path, rather than switching sockets without sending probe packets.
- Client now drops packets from unknown peer addresses (i.e., not from current, probing, or migration paths) instead of processing them.
- After migration, the old path's socket is cached in the path manager rather than closed, allowing the user to fallback to a previously used path. A socket is closed when the user explicitly removes the path.

**Design Changes**
New Public APIs:
- *startPathProbe(socket, callback)* - Initiates path probing on a new socket with optional validation callback
- *migrateConnection(pathId)* - Migrates the connection to a different path
- *removePath(pathId)* - Removes a path from the path manager
- QuicClientTransportLite now implements QuicPathManager::PathValidationCallback, and uses that to report path validation results to the user if a callback was provided.

Updated to HQClient to support active connection migration. It is currently triggered after every other request on the connection.
