Summary:
Many of the hhvm lldb tests have been failing since 9/24. I'm not sure what changed on the LLVM, LLDB, or HHVM side, but:

Last success (Sept 24 5:02 AM): https://www.internalfb.com/intern/sandcastle/job/2192747355

First failure (Sept 24 8:06 AM): https://www.internalfb.com/intern/sandcastle/job/22518000323036134

Example testx invocation: https://www.internalfb.com/buck2/34c382e4-47a2-4d07-81e6-c87bbdc36d0a

It looks like -gpubnames is behaving poorly with the hhvm test binary used for our lldb hhvm tests. The solution is to either remove -gpubnames flag when building, or to run `settings set plugin.symbol-file.dwarf.ignore-file-indexes true` before loading the file in lldb so it will index things rather than use the existing string symbol table in the binary that was created via -gpubnames. One slight good side effect of not using -gpubnames is that it won't cause the string table to become huge in the main binary, with the downside that index creation will take longer (though Greg says it's improved recently).
