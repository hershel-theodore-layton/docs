Summary:
mysql mtr test main.log_backtrace_debug is flacky https://www.internalfb.com/intern/test/281475214309905. the test verifies mysqld signal handler is called by searching logs produced by mysql/server/sql/signal_handler.cc:handle_fatal_signal.

after some debugging, it seems folly callPreviousSignalHandler did not trigger old signal action.

MetaMate suggested this change and it fixed the problem:

**Root Cause:** Folly's signal handler doesn't use the `SA_NODEFER` flag, so when it's executing, the signal is automatically blocked. When `callPreviousSignalHandler` restored the old handler and called `raise()`, the signal remained blocked and pending, never being delivered to the restored handler.
