Summary:
* this diff implements the erasure/deallocation of stream when it reaches a terminal state
* a terminal states are entered when a fin dequeued from egress handle and fin read from ingress handle
* a handle that is "invalid" (i.e. egress handle for a server-initiated unidirectional stream) immediately starts off in the terminal state
* a read handle and a write handle are linked (`WriteHandle*` member in ReadHandle, `ReadHandle*` member in WriteHandle), so that it is simpler to detect whether a stream is bidirectionally complete/terminal when one side is complete
* **note** that we likely can elide the `WriteHandle*` and `ReadHandle*` members in lieu of `offsetof()`, but whatever
