## Summary

Fix heap-use-after-free crash in Python Thrift services caused by dangling references when connections close mid-request.

### Problem

thrift-python services were experiencing random SIGSEGV crashes caught by ASAN. The issue occurred when:
1. A request creates a `PythonAsyncProcessor` with a `functionFullNameMap_` member
2. `ContextStack` is created with `string_view` references pointing to strings in this map
3. Client closes connection mid-request
4. `PythonAsyncProcessor` is destroyed (owned by the connection), which frees `functionFullNameMap_`
5. `ContextStack` destructor later accesses the freed `string_view` → heap-use-after-free

### Solution

Moved `functionFullNameMap_` from the per-request `PythonAsyncProcessor` to the service-lifetime `PythonAsyncProcessorFactory`. The processor now holds a const reference to the factory's map instead of owning its own copy.

Since the factory lives for the entire server lifetime and outlives all processors and requests, the `string_view` references in `ContextStack` are guaranteed to remain valid even if connections close mid-request.

### Benefits

- **Fixes the crash**: Eliminates heap-use-after-free by ensuring proper lifetime guarantees
- **Performance improvement**: Map is computed once per service instead of once per request
- **Maintains optimization**: Keeps the string_view optimization from D75822247
- **Minimal changes**: Only required modifications to two header files
