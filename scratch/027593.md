Summary:
Note most public methods in IncrementalResolver already lock the mutex.

We should add to the remaining one.

The only problem is `programOf()`: we can't just add lock it, since we also called program() in getDefinitionNode (https://fburl.com/code/1f2f7mcx). That would cause dead-lock.

We added a special logic (disableReadLockOnProgramOfMethodForAGivenThread_) to address this.

We could consider implementing a shared recursive mutex, though recursive mutex is often considered an anti pattern.
