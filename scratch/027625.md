Commit title: document float32 overflow issue
Commit body:
Summary:
Thrift-python has weird behavior when a float32 "overflow" occurs.
1. In Python, make struct with float32 value set to creater than float max. Anything >= 2^128 will do.
2. The struct creates successfully and the value can be accessed, because thrift-python stores as Python `float` (C++ `double`).
3. On serialization, we don't get a round-trip. Instead, in the C++ TableBasedSerializer, the `double` is assigned to a C++ `float`. This happens right before creating the `ThriftValue` in the static cast during serialization. In C++, the standard requires the value becomes `Inf`. So we silently lose the exact value during serialization.
4. On deserialization, we get the Python `float` `Inf`.
