Commit body:
Summary:
When a thrift-python struct with 32-bit float field is serialized, any values that overflow on conversion from C++ `double` (Python internal representation) to `float` are implicitly converted to +/- `inf`. See previous diff for details on where this happens in the TableBasedSerializer.

The thrift-python C-API should *always* match the serializer behavior. The current behavior is for `Extractor` of `float` (32-bit) to `raise OverflowError`. This diff changes it to *match* the serializer behavior.
