Commit title: add protocol parameter to ScopedServerInterfaceThread::newStickyClient
Commit body:
Summary:
Extended `ScopedServerInterfaceThread::newStickyClient()` to accept an optional protocol parameter, enabling tests to specify protocols other than the hardcoded `T_BINARY_PROTOCOL`.

This change makes `newStickyClient()` consistent with `newClient()`, which already accepts a protocol parameter. The default remains `T_BINARY_PROTOCOL` for backward compatibility.

## Use Case:

This enables test code to create sticky clients with `T_COMPACT_PROTOCOL` for HTTP/2 testing scenarios where custom headers (like authentication tokens) need to be set via `setPersistentHeader()` and maintained across multiple requests on a single connection.

## Changes:

**`ScopedServerInterfaceThread.h`:**
- Added `protocol::PROTOCOL_TYPES prot` parameter with default value `T_BINARY_PROTOCOL`

**`ScopedServerInterfaceThread-inl.h`:**
- Updated implementation to use the provided protocol parameter instead of hardcoded `T_BINARY_PROTOCOL`

Both `fbcode/` and `xplat/` versions updated to maintain consistency.
