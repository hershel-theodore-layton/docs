Commit body:
Summary:
Two optimizations to reduce overhead in the hot HHVM async execution loop based on assembly analysis: https://fburl.com/strobelight/5c5vzaxa)

**1. Cache AsioSession::Get() to eliminate TLS overhead**

Assembly analysis showed that TLS
segment lookups via %fs:-0x5f40 were a bottleneck in the runUntil hot loop.
Each call to AsioSession::Get() dereferences the thread-local s_current
pointer, causing costly segment register accesses. Profiling data shows TLS
operations at 10.1-10.2% sample concentration (LBR) (~9,050 cycles per occurrence)
at multiple points in the hot path (assembly lines 881a096, 881a0c4, 881a0cd).

Changes:
- Cache session pointer once at function entry (asio-context.cpp:179)
- Update lambda capture from [&] to [&, session] (line 190) to pass cached
  pointer to nested lambdas

Both changes have no functional impact - only performance improvements by
reducing overhead in the critical async execution loop.
