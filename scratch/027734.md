# Problem

Today, WWW does **not** participate in incrementing depth, like C++ services do via our TraceContinuationHandler. This means if we have a call path:

C++ (depth = 1) -> thrift/HHVM (depth = 1, BAD!) -> C++ (depth = 2)

the depth is wrong.

It should be:
C++ (depth = 1) -> thrift/HHVM (depth = 2, GOOD!) -> C++ (depth = 3)

We should similarly account for BDP, but depth is a bigger prio given we are trace limiting on it. Say for some reason theres megatraces from deeply nested hhvm -> hhvm calls, we would never be incrementing depth
