Commit title: Make the validation of Sets with string elements lazy
Commit body:
Summary:
This diff implements lazy validation for Thrift Python sets with `string` elements. Instead of eagerly validating all string elements when accessing a set field, validation is now deferred until the set is accessed in ways that require all elements to be valid. String elements may be stored as `str` or `bytes` internally - `bytes` indicates a string that failed UTF-8 decoding during deserialization.

The implementation now has three explicit code paths: elements needing no conversion (e.g., int, float, double, binary) pass frozenset directly with no validation, string elements use lazy validation, and elements needing conversion (e.g., structs, containers) convert eagerly as before.

The Glean query D85260454 shows that ~50% of Set fields are strings, presenting an opportunity for optimization, as benchmarks in D85263803 show string operations are much slower than int.
