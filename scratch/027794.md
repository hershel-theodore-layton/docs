Commit title: catch std::exception in stripEnvelope to prevent throwing on malformed envelope
Commit body:
Summary:
Fix a crash in `EnvelopeUtil::stripEnvelope` when processing malformed thrift requests over HTTP2. The function was only catching `TException`, but `folly::Cursor` can throw `std::out_of_range` which was not being handled, causing the server to crash.

The crash occurred when sending malformed thrift data (e.g., via `curl --http2-prior-knowledge` with invalid binary data like `$'\x82\x22'`). The `folly::Cursor::read()` method throws `std::out_of_range` when it can't read enough bytes, but this wasn't caught by the existing `TException` handler.

The fix changes the catch block to catch `std::exception` instead of just `TException`. This ensures all standard exceptions (including `std::out_of_range` from folly and thrift exceptions which inherit from `std::exception`) are properly handled and logged, returning `folly::none` instead of crashing.

See P2022289550 for the crash stack trace before the fix.
