Commit body:
Summary:
* Create `TTLSTunnelStopTLSAsyncTransport`, a wrapper transport which pipes `write(Chain)` calls to the underlying TCP `AsyncSocket`, and holds any pending read callbacks set by the application.
* The above uses `OuterStopTLSHandler`, which starts the `AsyncStopTLS` in "Server" mode to initiate sending the close_notify; on stopTLSSuccess, `moveToPlaintext` the fizz transport, set the pending read callback and exchange the underlying transport of the `TTLSTunnelStopTLSAsyncTransport`.
* Create `TTLSTunnelStopTLSAwaitableTransport` which works within the `AwaitableTransport` paradigm, which expects to take in an inner TLS transport wrapping an outer TLS transport. It extracts the outer TLS transport, wraps it in a `TTLSTunnelStopTLSAsyncTransport`, then shoves the `TTLSTunnelStopTLSAsyncTransport` in as the underlying transport of the outer TLS transport, and returns the outer TLS transport.
