Commit title: Template base for strong types aka newtypes
Commit body:
Summary:
It is very common to want a strongly typed wrapper around a primitive type. It was even proposed for the core language, see [n3320](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n3320.htm).

Strong types improve readability just like type-aliases do:
```cpp
void countAttendees( // clear
    const std::map<PersonId, SchoolId>&, SchoolId);
void countAttendees( // confusing
    const std::map<uint64_t, uint64_t>&, uint64_t);
```

But, additionally, they improve safety:

```cpp
// WRONG -- but compiles with type aliases
personToSchool.emplace({school, person});
```

The proposed `strong` provides that basic functionality of clarity & safety, but so does this:

```cpp
struct PersonId { uint64_t id_{}; };
```

However, trying to make the aggregate `PersonId` **usable** quickly runs into hassles.
  - People often forget to value-initialize the member.
  - You need a strong convention for naming the member, or it gets harder to use since you get blocked on member name lookups.
  - Adding basic comparison support is easy by defaulting `operator<=>`, but there are a lot of subtleties in making it comparable with the underlying type -- which is nice when you're trying to use the strong type together with maps supporting heterogeneous lookups.
 - Making it hashable is another hurdle.
 - Making it printable / formattable -- another, etc.

The `strong` proposed here rolls up all these ease-of-use improvements into a concise package:

```cpp
struct PersonId : public strong<uint64_t, PersonId> {
    using strong<uint64_t, PersonId>::strong;
};
```

And, you can still easily extend these types. E.g. making `PersonId` implicitly constructible from integers adds 1 line [*]:

```cpp
/* implicit */ PersonId(uint64_t n) : strong{std::move(n)} {}
```

[*] Caveat: One might want to use a constrained template instead to prevent construction from convertible types like `double`.
