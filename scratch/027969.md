Commit title: DumpRequestOnCrashModule: dump thrift request if we crash during request handling
Commit body:
Summary:
See: https://fb.workplace.com/groups/thriftusers/posts/1350128065696602/

This adds a new ServiceFramework module that automatically dumps the thrift request if we crash (LOG(FATAL), CHECK, segfault, etc) while handling a thrift request. This helps us significantly speed up investigation and mitigation for many SEVs, where it is hard to identify the "request of death" during the SEV. Example: S389657

Notes on the implementation:
- There is NO performance overhead while the thrift server is working normally. The only cost is during ServiceFramework initialization (enabling the module) before the server takes requests, and during signal handling if we crash while handling a request.
- This means that this module is fairly safe to enable by default on all thrift servers. I also added a killswitch to allow disabling it if needed.
- The signal handler requires looking at the current thread's `folly::RequestContext` to get the root id to match the requests running on this thread. This means that if we're in a request handler, and the request handler calls `folly::RequestContext::create` or `folly::RequestContextScopeGuard`, the thrift context is wiped, and we will be unable to find the current thread's thrift request if we crash. This is an OK tradeoff, as this use-case is relatively rare.
