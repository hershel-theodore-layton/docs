Commit title: Support type constants in XHP attribute declarations
Commit body:
Summary:
This diff adds support for using type constants in XHP attribute declarations, which was previously blocked. This feature allows XHP attributes to reference type constants like `MyClass::TMyType`, enabling more flexible and type-safe XHP component APIs.

Key changes:
1. Added a new experimental feature flag `xhp_type_constants` that must be enabled to use this functionality
2. Updated the parser lowerer to only raise errors when the feature is disabled
3. Modified the hackc emitter to handle type access hints in XHP attributes by falling back to mixed type (with TODO for future enhancement)
4. Moved the old test case to a new test directory with proper feature flag configuration
5. Added comprehensive test cases covering simple usage and advanced scenarios with `this::TType` refinement

The feature is marked as unstable and requires explicit opt-in via the `__EnableUnstableFeatures('xhp_type_constants')` attribute.

This enables use cases like:
- Declaring XHP attributes with abstract type constants that can be refined in subclasses
- Using `this::TData` for polymorphic XHP components
- Better type safety for XHP attribute declarations
