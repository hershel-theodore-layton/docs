Commit title: Remove caching from Map._fbthrift_lazy_getitem for lazy conversion
Commit body:
Summary:
This change simplifies the lazy conversion strategy for Map by removing the caching mechanism in `_fbthrift_lazy_getitem()`. Previously, when accessing a map value by key in lazy mode, the method would convert the value and cache it `in _fbthrift_elements`. This dual-structure approach—maintaining both `_fbthrift_internal_elements` and a partially populated `_fbthrift_elements`—improved repeated access performance  but also introduced some overhead.

The new implementation retains the lazy conversion optimization (deferring value conversion until accessed) but removes caching of individual converted values. Each access to the same key now performs the conversion again. In this implementation, we assume that the likelihood of accessing the same `key` multiple times is low.

The `__getitem__` method is also simplified to check the lazy flag first before attempting direct element access, thereby avoiding the try-except overhead by directly raising a `KeyError`.

**Performance benchmark**
 {F1983506323}

Removing caching shows **significant improvements** in Random Access:

*   Map<i32, string>: **48.9% faster** 🚀
*   Map<string, string>: **47.0% faster** 🚀
*   Map<i32, Struct(list<string>)>: **23.8% faster**

(But please note the downside is that repeat accessing would be worse.)
