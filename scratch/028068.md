Commit title: Replace usages of deprecated AST method t_typedef::get_type in codegen
Commit body:
Summary:
Since code generation happens after semantic validation, type refs must have already been resolved. Therefore `t_typedef::get_type`, which is implemented as a `get_type` call on the wrapped `t_type_ref`, is equivalent to `&typedef.type().deref()` (i.e. the address of the type resulting from dereferencing the `t_type_ref` that the typedef aliases).

In cases where the `get_type` return value is immediately dereferenced, it can be equivalently replaced using `t_type_ref`'s `operator*` / `operator->`, which are implemented using `deref()`.

NOTE: These assumptions are only valid *after* semantic validation has ensured there are no unresolved `t_type_ref`s remaining. Hence why this replacement is only applied in the code generation phase.

In changed methods, replaced `dynamic_cast<T*>(t_type*)` down-casts with `try_as<T>`.
