Commit title: Fix CachedRpcClientFactory memory leak and stale connection issues
Commit body:
Summary:
Fixed a critical memory leak in CachedRpcClientFactory where RSocket keep-alive timeout exceptions were cached indefinitely, causing suppressed exceptions to accumulate on each .block() call. The root cause was Reactor's .cache() operator replaying the same exception instance to all subscribers, with each subscriber adding a new suppressed exception via BlockingSingleSubscriber.

The fix implements the following key improvement:

1. Active Cache Invalidation: Subscribe to RpcClient.onClose() to detect connection termination and invalidate the cached Mono, allowing FusableReconnectingRpcClientMono to reconnect on the next request.

Previously, when an RSocket keep-alive timeout occurred:
- ConnectionErrorException was thrown and cached forever
- Every subsequent .block() call added a suppressed exception to the same object
- FusableReconnectingRpcClientMono could not reconnect because the cache never cleared
- Memory leaked as suppressed exceptions accumulated indefinitely

After the fix:
- onClose() fires → cache is invalidated
- FusableReconnectingRpcClientMono sees DISCONNECTED state → reconnects
- Next request gets a fresh connection
- No exception accumulation, no memory leak
