Commit title: Add cpp.NonOrderable annotation to delete operator<
Commit body:
Summary:
Introducing the `cpp.NonOrderable` annotation which:
* Marks the `operator<` for structured types as deleted & omits any definition.

This interacts with various other annotations:
* `cpp.noncomparable` takes precedence in that it omits both the declaration & definition of `operator<` & `operator==`
* `no_default_comparators` & `EnableCustomTypeOrdering`: These both impact only the definition, not the declaration. Using either one of the three causes the definition to be omitted.

## Context

The omission of `operator<`'s definition can cause issues in various dynamic library builds, as the definition can be missing, which won't always be detected at build time, see T243929333.

## Future

Ideally we can:
- Split up `cpp.noncomparable` & `cpp.NonOrderable` further, to only impact one operator
- Remove implicit omission of `operator<` & make this **opt-in** via `cpp.OrderableVia` or equivalent
