Commit title: Allow configuring HTTP session wheel timer default timeout
Commit body:
Summary:
Previously, the HTTP session's wheel timer was always initialized with a hardcoded 500ms default timeout in the HTTPClientChannel constructor. This timeout is used by the session's wheel timer as the default for various HTTP operations when they don't explicitly specify a timeout. There was no way to configure this value, making it impossible to adjust timeout behavior for different use cases.

This change adds a `sessionDefaultTimeout` parameter to both `newHTTP2Channel()` and the HTTPClientChannel constructor, allowing callers to configure the wheel timer's default timeout. The parameter defaults to `kDefaultTransactionTimeout` (500ms) to maintain backward compatibility.

Note: This is distinct from the `timeout_` member variable which can be changed dynamically via `setTimeout()`. The `sessionDefaultTimeout` is specifically for wheel timer initialization and is used only during session creation.

Additionally, `kDefaultTransactionTimeout` was converted from a static const member to an inline constexpr to avoid the need for a separate definition in the .cpp file.
