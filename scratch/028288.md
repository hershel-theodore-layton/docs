Commit title: Implement the ability to apply StructPatch to the serialized data directly
Commit body:
Summary:
The idea is that if we apply patch to serialized data directly, we can avoid materializing the data to `protocol::Value` and improving the performance.

There are still a lot of optimizations unimplemented, though the benchmark already looks decent -- it's always equal or faster than deserializing everything to protocol::Value.

# Benchmark result

The reason "few_small_fields" is so fast is that the thrift struct for "few_small_fields" looks like this:

```
struct Struct {
  1: i32 field_1;
  2: list<bool> field_2; // This field has 10000 elements
}
```

The patch only touched `field_1`, so that we can skip the whole 10000 elements in field_2. (this is also why partial_deser is faster -- we only deserialize field_1 and skip field_2).
