Commit title: rename TxnBytesEvent::REQUEST_HEADERS_COMPLETE to TxnBytesEvent::LAST_HEADER_BYTE_READ
Commit body:
Summary:
The previous name `REQUEST_HEADERS_COMPLETE` was misleading because it only accurately describes the event from the server's perspective (when receiving request headers). However, from the client's perspective, this same event occurs when it finishes reading response headers, not request headers. The name was therefore ambiguous and perspective-dependent.

The new name `LAST_HEADER_BYTE_READ` is more accurate and perspective-neutral, as it describes what actually happens: the last byte of the HTTP headers (whether request or response) has been read.

Note: The string literal `"REQUEST_HEADERS_COMPLETE"` is still used for logging purposes in `/data/users/alexsn/fbsource/fbcode/proxygen/facebook/lib/ptm/modules/http_trace/PTMHttpTraceModuleImpl.cpp`. The owning team can rename this string if needed.
