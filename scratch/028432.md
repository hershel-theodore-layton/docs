Commit title: Fix VirtualThreadScheduler Worker memory leak and serialization bugs
Commit body:
Summary:
The VirtualThreadScheduler's Worker implementation had critical bugs that violated the Reactor Scheduler contract and caused memory leaks:

**Deficiencies:**

  1. **Memory Leak**: Worker used Disposable.Composite to track all scheduled tasks but never removed completed tasks. This caused unbounded memory growth as the composite accumulated disposables indefinitely, even after tasks finished.

  2. **Broken Event Serialization**: Worker.schedule() delegated directly to the scheduler's executor, allowing tasks to run concurrently on multiple virtual threads. This violated the fundamental Worker contract specified in the Reactor Scheduler API: "Workers should usually run tasks in FIFO order" and events must be serialized within a single worker.

  3. **Incomplete Disposal Semantics**: When a worker was disposed, delayed/periodic tasks didn't report as disposed because:
     -- TrampolinedTask didn't track parent worker's disposal state
     -- Pending delayed tasks scheduled on periodicScheduler weren't cancelled
     -- DisposableFuture.isDisposed() only checked isCancelled() instead of isDone()

  4. **Resource Leaks**: Timers for delayed/periodic tasks continued running even
     after worker disposal, causing unnecessary wakeups and holding references.

 **Fixes:**

Implemented queue-based serial execution pattern based on reactor.scheduler.forkjoin.ForkJoinPoolScheduler:

  1. **Replaced Disposable.Composite with Task Queue**: Worker now uses ArrayDeque with synchronized access. Queue is cleared on disposal, preventing memory leaks. No need to track individual disposables since tasks check parent disposal state.

  2. **Implemented FIFO Serialization**: Added executing flag pattern where:
     -- Tasks are added to queue under lock
     -- First task triggers queue processor on virtual thread
     -- Subsequent tasks reuse same processor (no new threads spawned)
     -- Processor runs tasks serially until queue empty
     -- This guarantees FIFO order and serialization per Worker contract

  3. **Added DisposableWorkerTask**: Wrapper that checks both self disposal and parent worker disposal before execution. Tasks queued when worker is disposed won't execute even if already dequeued.

  4. **Enhanced TrampolinedTask**: Now accepts BooleanSupplier for parent disposal tracking. Delayed tasks properly report isDisposed() when parent worker is disposed, satisfying Disposable contract.

  5. **Track and Cancel Delayed Tasks**: Worker maintains Set<Disposable> of pending
     delayed/periodic tasks. On disposal, all are explicitly cancelled to:
     -- Stop timers immediately (no resource waste)
     -- Ensure composite disposables report isDisposed() correctly
     -- Free references held by periodicScheduler

  6. **Fixed DisposableFuture.isDisposed()**: Changed from isCancelled() to isDone() to properly indicate when Future is no longer active (covers completion, cancellation, and exceptions).

**Contract Conformance:**

- Worker serialization: Tasks execute serially in FIFO order on single virtual thread
- Disposable semantics: isDisposed() accurately reflects disposal state
- Resource cleanup: All timers cancelled, references freed on disposal
- Virtual thread usage: All task execution happens on virtual threads
- Thread safety: Lock-based synchronization prevents race conditions
- Reactor Scheduler API: Full compliance with documented contracts

The implementation follows the ForkJoinPoolScheduler pattern while maintaining compatibility with virtual threads and improving upon it by properly tracking and disposing delayed tasks.
