Commit title: Make Reactive Clients disposable
Commit body:
Summary:
The .dispose() call on the reactive client interface didn’t do anything. This diff ensures that the reactive clients can be disposed of to force a disconnect of the underlying transport.

The coded added uses doOnNext behavior to track the rpcClients that have been generated. When the Mono is subscribed to a client is created and connected. On Next attempt to track them for disposal. It also subscribes to the RpcClient's onClose() hook for when the client is closed at a different level.

Performance Characteristics

  Hot path (99.99% of calls - client already tracked):
  - Lock-free contains() check → returns true → skip everything
  - Cost: 1 ConcurrentHashMap lookup (very fast)

  Cold path (first call with a client):
  - contains() returns false
  - add() locks internally, one thread wins
  - Winner does double-check + subscription setup
  - Cost: 1 extra _disposed.get() call (negligible)
