Commit title: Preserve RequestContext in ReconnectingRequestChannel queue
Commit body:
Summary:
Fixes request context loss when requests are queued during channel reconnection. Previously, when the channel was not good and requests were added to the request queue, the folly::RequestContext was not preserved, causing the queued requests to lose context information when eventually executed.

This change captures and restores the RequestContext for all queued request types (request-response, request-no-response, streaming, and sink) by saving the context when queuing and restoring it with a ScopeGuard when the lambda is invoked. This ensures that queued requests maintain the same execution context as if they had been sent immediately.
