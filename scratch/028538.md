Commit title: Add compiler option to skip constants codegen
Commit body:
Summary:
`ThriftCodegenDeleteFileRule` exists to allow skipping codegen for constants entirely (ie not producing a `*_constants.php` file at all) in order to avoid name collision errors between generated constant structs with duplicate names (eg [this file](https://www.internalfb.com/code/fbsource/[7a755b5800e7]/fbcode/commerce/features/if/features.thrift?lines=13) would clash with [this generated code](https://www.internalfb.com/code/fbsource/[225ae2d1e9dfd927534f5329e473083d11e8472c]/www/flib/__generated__/ThriftMeerkatStep/fbcode/commerce/data/if/commercedata.thrift/commercedata_constants.php?lines=12))

We can instead support this behavior with a `skip_constants` compiler option - once this change is released to WWW, all usage of the post-processing rule will be migrated and the rule will be deleted
