Commit title: enable float32 conversion for float fields
Commit body:
Summary:
This diff makes thrift-python apply 32-bit floating point rounding when the struct is created. This makes the field value (in Python) match the eventual serialized (or deserialized) value.

## Context:

[This post](https://fb.workplace.com/groups/thrift.py3/permalink/3343290539156048/) documents the issues with `float` field handling in current thrift-python.

## Please fix-forward!

It is expected that this diff may break some tests not covered by buildall. **Thrift team will fix all test failures bisected back to this diff. Please give us time** :). There are two options to fix forward:

1. **Preferred**: Fix-forward the brittle tests using `assertAlmostEqual`, `math.isclose` (with `rel_tol=1e-7` kwarg), or `thrift.python.test_helpers.assert_thrift_almost_equal`. This latter function can be used for arbitrarily deep thrift structs and containers, whether thrift or native python.
2. Temporarily opt-out of float32 (keep old behavior) using the `typedef` annotation:

- `python.ConstrainedFloat32{ precision_loss = python.ConstraintLevel.ALLOW_INVALID}`. Available in fbsource and www; soon available in configerator.
- Less than ideal: `python.EnableUnsafeUnconstrainedFloat32`. Deprecated, but available in configerator.

## Benefits:

- Remove a known API difference between thrift-py3 and thrift-python (note removal of `brokenInAutoMigrate` test tag).
- Remove 8 `# BAD` documented API defects related to self-consistency.
