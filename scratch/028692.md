Commit title: stop discarding changes on get_all_files
Commit body:
Summary:
This diff changes the behavior of `Edenfs_watcher.get_all_files`. Previously, the behavior was that it would intentionally discard all changes that had not been picked up by calls to `Edenfs_watcher.get_changes_{sync,async}` before the call to `get_all_files`. This diff stops this discarding of outstanding changes.

The reason for implementing the original discarding behavior was that I thought that this was what the Watchman counterpart (i.e., our own `Watchman.get_all_files` function) intentionally does.

However, I have now realized the following, which is why I consider the previous behavior a bug:
- `Watchman.get_all_files` only discards changes if the `subscribe_mode` config setting for Watchman is disabled, no discarding happens if `subscribe_mode` is enabled. I suspect that behaving differently depending on `subscribe_mode` is not intentional, but just a bug in our `Watchman` module.
- The discarding behavior of `get_all_files` can actually make `hh_server` completely miss file changes. See the test plan for a repro of this and why I think this is unlikely to have actually happened during real-world usages.

Note that I'm only changing `Edenfs_watcher.get_all_files`. `Watchman.get_all_files` does not exhibit the problem if `subscribe_mode` is enabled, which is the configuration we have been using for years.  I'm not sure if fixing `Watchman.get_all_files` would break things in unintended ways. Therefore, I just left a comment in the latter function to point this out.
