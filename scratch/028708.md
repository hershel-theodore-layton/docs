Summary:
Fix folly build on fedora 43's g++ 15.2.1

GCC’s __type_pack_element is a non-standard builtin. GCC 15  tightened diagnostics around its use to now emit an error if you put it directly in a mangled context (like a function signature), because the builtin doesn’t produce a proper mangling and can lead to ODR issues. Earlier GCCs tolerated it.

Folly’s type_pack_element_t wraps the builtin when available and carries a comment that under GCC it must not be used where it might be mangled (e.g. return types). The LargeTuple test violated that guidance by using type_pack_element_t in a function signature; GCC 15 now enforces the restriction, hence the build failure. Using the fallback implementation instead avoids the mangling issue and keeps the code portable.
