Commit title: Take vault state lock at the start of Singleton::createInstance
Commit body:
Summary:
# What
Take a read lock of a singleton's vault state at the beginning of `createInstance`, and hold it for the full duration of `createInstance`

# Why
SEV: S583583

Because the current setup of the code may result in a deadlock during singleton creation for *forked children*.

Sequence of events that can lead to deadlock:
1. Parent main thread prepares for a fork by calling `destroyInstances`, which acquires the vault state read lock
2. Parent background thread attempts to access a Singleton that's already destroyed, and thus acquires the Singleton's creation `mutex_`
3. Parent background thread stalls on the vault state read lock
4. Parent main thread finishes `destroyInstances`, releases the vault state read lock
5. Parent main thread forks, BEFORE the background thread acquires the read lock necessary for the early quescing return.
6. Child tries to create the singleton who's `mutex_` was held by the background thread
7. Child deadlocks forever
