I found the following pattern useful -- benchmarks can also run as `cpp_unittest`s, with a single `TEST` that demonstrates that a few iterations of the benchmark neither crash (due to internal asserts), nor trigger ASAN.

This approach should never replace dedicated unit tests, but it's a nice complement that can (unexpectedly) catch bugs.

To support this testing strategy cleanly, the test sets a low iteration count, like 5.
