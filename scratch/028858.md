Commit title: Fix bug around nested metadata in processInteraction()
Commit body:
Summary:
When MultiplexAsyncProcessor routes interaction methods to sub-processors, it was passing the ServerRequest with outer multiplex metadata still attached. This caused DCHECK failures when nested multiplex processors tried to use sourceIndex values that were valid for the outer processor array but out of bounds for their own processor arrays.

The fix unwraps the inner metadata before passing the request to sub-processors, matching the behavior of processSerializedCompressedRequestWithMetadata which already unwraps metadata correctly.

This fix is fairly basic, but this bug is breaking us, and we need this fixed.
