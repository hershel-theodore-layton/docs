Commit title: Fix zero-byte EOM ACK event crash by immediately firing when writeBuf_ is empty
Commit body:
Summary:
This fixes the crash at HTTPCoroSession.cpp:3096 where
txAckEvent->sessionByteOffset == sessionBytesScheduled_.

The crash occurred when:
1. A zero-byte EOM is sent (HTTP/1.x with Content-Length satisfied)
2. An ACK event is registered at sessionByteOffset == sessionBytesScheduled_ (writeBuf_ is empty)
3. The event is queued to txAckEvents_
4. A second request comes in and tries to write, hitting the XCHECK because the
   queued event's offset equals sessionBytesScheduled_ instead of being greater

The fix passes sessionBytesScheduled_ to registerByteEvents() and immediately
calls scheduleOrFireTxAckEvent() when sessionByteOffset == sessionBytesScheduled_
(which indicates writeBuf_ is empty) instead of queuing the event to txAckEvents_.

This is safe because scheduleOrFireTxAckEvent() will either:
- Fire the event immediately if maxTransportTxOffset_ >= sessionByteOffset, or
- Schedule a timeout for the event

In either case, the event won't be waiting in txAckEvents_ for a future write.
