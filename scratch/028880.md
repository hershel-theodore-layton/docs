Commit title: Improve determinism for HHBBC
Commit body:
Summary:
I noticed that the cache hit rate for HHBBC declines very
quickly, even during index building. This suggests that there's some
non-determinism causing jobs with identical inputs to produce
different outputs.

After investigating, there were 3 culprits: The main cause (by an
overwhelming amount) was that TypeConstraints were not
deterministic. That is, they sorted the class list by pointer
address. This meant the ordering was (effectively) random. Fix this by
sorting the list by name, which is deterministic.

The second cause was that there's a number of system constants which
changed with every build. This didn't cause non-determinism per-say,
but it meant that these could change with any build, making caching
less effectively. "Opt out" these constants by treating them as
dynamic.

Finally we weren't always initializing all fields in php::Unit, which
could mean we were serializing garbage in a few cases.
