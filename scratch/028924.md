Commit title: Add chunksInMemory tracking to CREDIT_TIMEOUT error message
Commit body:
Summary:
When a stream times out due to lack of credits (CREDIT_TIMEOUT), it's difficult to determine whether the issue is:
1. Slow transport/network (chunks stuck in egress buffer)
2. Slow client not sending credits

This change adds a `chunksInMemory` counter to `RocketStreamClientCallback` that tracks chunks currently in flight (received but not yet sent to the wire). The counter is:
- Incremented when a chunk is received (`onStreamNext`)
- Decremented when a chunk is actually sent (`messageSent` callback)

On CREDIT_TIMEOUT, the error message now includes this counter:
```
Stream credit timeout: chunksInMemory=150
```

If `chunksInMemory` is high, it indicates chunks are stuck in the egress buffer (slow transport). If it's low/zero, it indicates the client is not sending credits fast enough.

The counter uses `shared_ptr<uint64_t>` to ensure the callback can safely decrement even if the stream is destroyed before pending write callbacks complete.
