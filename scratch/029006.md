Commit title: Improve trace bumps in HHBBC for better debugging
Commit body:
Summary:
This diff improves HHBBC's tracing infrastructure to provide better context
when debugging analysis issues. The trace bump mechanism increases trace level
for specific functions, classes, or units, but it was inconsistently applied
across different analysis paths.

The main improvements are:

1. Fixed inline analysis trace bumps: Only bump trace level for top-level
   analysis, not inline analysis, so we preserve the caller's trace context
   when analyzing inlined functions.

2. Added comprehensive trace bumps: Now properly bump trace level for class
   constant analysis, 86init analysis, property analysis, closure analysis,
   and scheduler operations.

3. Centralized bump logic: Added helper functions (bump_for_class,
   bump_for_func, etc.) to Index to compute appropriate bumps based on entity
   names and their associated units.

4. Improved class context inference: trace_bump_for now extracts class name
   from func->cls when available, providing better context for method tracing.

5. Added unit tracking to TypeMapping: This enables proper trace bumps when
   processing type aliases and enum types.

6. Added HPHP_TRACE guards: Wrap trace utilities in compile-time guards to
   avoid overhead when tracing is disabled.
