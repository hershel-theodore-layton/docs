Commit title: Preserve unresolved type in py3_mstch_type
Commit body:
Summary:
`py3_mstch_type` previously passed the true (i.e. typedef-resolved) type to the `mstch_type` base constructor. This makes it impossible to access the Whisker prototype for the underlying typedef.

This prevents the Whisker prototype from accessing a type's `cached_properties`. `py3_mstch_type` uses the non-resolved type as the key. Whisker needs access to the non-resolved type pointer to get access to the same `cached_properties` instance.

- Pass the original (potentially `t_typedef`) type pointer to `mstch_type` base constructor
- Update existing mstch properties to use `resolved_type_`, to maintain existing behavior
- Update existing properties on the `t_type` prototype that don't access `cached_properties` to call `get_true_type()`
