Commit title: Update HeapTimekeeper to be friendly to JNI
Commit body:
Summary:
We have run into some nasty bugs where a TimeKeeper triggers a callback on its own thread that on android ends up scheduling things on executors that require JVM attachment.

(e.g timeout -> callback -> attempt to create a NativePooledExecutor -> throws for no JVM attached)

This change exposes the worker function through a virtual protected member, so we can easily subclass the TimeKeeper and wrap it in a JNITimeKeeper (following diff)
