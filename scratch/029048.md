Commit title: Fix HTTP 429 misclassified as RECV_UNKNOWN, map to APP_OVERLOAD
Commit body:
Summary:
HTTP 429 (Too Many Requests) was incorrectly being classified as a receive error (RECV_UNKNOWN) instead of a server-side overload error. This caused 429 responses to be treated as transport failures rather than retriable throttling responses.

The fix handles HTTP 429 at the Thrift HTTP2 layer (SingleRpcChannel), similar to how HTTP 503 with Retry-After is already handled. Both now set the kAppOverloadedErrorCode ("22") which ServiceRouter translates to ErrorReason::APP_OVERLOAD, making the error retriable via RETRY_ON_HOST_OVERLOADED.

Error flow after fix:
- HTTP 429 → kAppOverloadedErrorCode → APP_OVERLOAD → RETRY_ON_HOST_OVERLOADED ✓
