Commit title: Strongly typed TypedFormatString
Commit body:
Summary:
Currently, Hack recognises that literals such as `"A string %s and an integer %d"` are special "format strings" if passed to a `printf`-like function whose first parameter is of type `FormatString<I>`, where `I` is a classish type with special methods such as `format_s` and `format_d` whose parameter types then determine the types of the variadic arguments passed to the `printf`-like function.

Unfortunately this doesn't generalize to "first-class" use of `FormatString` values, and we have to resort to FIXMEs.

We can fix this by parameterizing a new `TypedFormatString` type on a tuple type representing the place-holders in the format string. For example, `"A string %s and an integer %d"` could have type `TypedFormatString<MyStringFormat,(string,int)>` where `MyStringFormat` has methods `format_s(string $s):string` and `format_d(int $d):string`. We can then give a proper type to functions such as `printf` e.g.
```
function printf<Targs as (mixed...)>(TypedFormatString<MyStringFormat,Targs> $format, ...Targs $args):void;
```

More precisely, we introduce this type in `typenames.hhi`.
```
newtype TypedFormatString<T, Targs as (mixed...)> = string;
```
For backward compatibility, we can redefine
```
newtype FormatString<T> as TypedFormatString<T, (mixed...)> = string;
```
And now, this lets us "pass on" typed format strings, for example:
```
// BEFORE
final protected static function invariant(
  bool $assertion,
  HH\FormatString<PlainSprintf> $format_msg,
  mixed ...$format_args
): void {
  if (!$assertion) {
   /* HH_FIXME[4027] this is fine... propagate non-string literal */
   static::invariantViolation($format_msg, ...$format_args);
  }
}

// AFTER
final protected static function invariant<Targs as (mixed...)>(
  bool $assertion,
  HH\TypedFormatString<PlainSprintf, Targs> $format_msg,
  ... Targs $format_args,
): void {
  if (!$assertion) {
    static::invariantViolation($format_msg, ...$format_args);
  }
}
```
Notice how the signature is now fully-typed, and there is no need for an `HH_FIXME`.

To make this work *without* the need for "retyping" of functions such as `printf`, we introduce two changes to the typing of strings.

1. Any string literal `"s"` can be considered a `TypedFormatString<I,(t1,...,tn)>` if the format interface `I` can be used to process `s` with placeholders having types `t1,...,tn`. In practice, we can do this only if the literal appears in a context that Hack is *expecting* a `TypedFormatString<I,_>` for a known interface `I`, such as a return position, or as the argument to a function. This subsumes the existing trickery with "retyping" of `printf`-like functions.
2. We support concatenation of format strings. If `e1` has type `TypedFormatString<I,(t1,...,tn)>` and `e2` has type `TypedFormatString<I,(u1,...,um)>` then `e1 . e2` has type `TypedFormatString<I,(t1,...,tn,u1,...,um)>`. This subsumes the support for concatenated literals being passed to `printf`-like functions, except that the component literals must be well-formed format strings e.g. `printf("%" . "d", 5);` would be rejected.
