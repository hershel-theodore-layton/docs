Commit title: Some improvements to update_bytecode in HHBBC
Commit body:
Summary:
Don't actually mark the bytecode as changed, if we know the change
will produce the same block. Changing a block's successor can actually
cause the fixed-point result to change (because it may make blocks
unreachable), so mark that change as requiring re-analysis. For
further efficiency we could detect if the change causes a block to
become unreachable, but we don't do so now.
