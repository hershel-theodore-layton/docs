Commit title: Allow default values for structured types
Commit body:
Summary:
This seems to mostly already work (at least when compared to C++) with one edge case I'm aware of.

Notably, when nested thrift structs are defined in other thrift files that have the hack_collections option enabled (or the other way around), we cannot use the correct type for creating them.

Example:
```
struct Outer {
  1: Inner inner = {}
}

// another thrift file
struct Inner {
  1: list<i32> ids;
}
```
If the thrift file with `Inner` uses hack collections , but `Outer` does not, we run into issue trying to specify default values
```
Inner::fromShape(
  'ids' => vec[1,2]
)

needs to be

Inner::fromShape(
  'ids' => Vector { 1, 2 }
)
```

This diff adds `legacy_default_values` as a compiler flag to retain existing behavior.
