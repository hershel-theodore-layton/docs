Commit title: Don't shadow uninstantiable-class errors with needs_concrete warnings
Commit body:
Summary:
## TLDR

For `new static` in an `abstract final` class when checking with `--config needs_concrete=true`, don't hide "uninstantiable" errors (4002).

> This change does not affect users (yet) since `needs_concrete=true` isn't in hhconfig yet

### Why

For `new static` in an `abstract final` class when checking with `--config needs_concrete=true`, we have a few options:
- show only the "uninstantiable class" error (4002):
    - Behavior introduced in this diff
    - Good: we don't miss errors and we don't annoy the user with redundant warnings
- show only the warning:
    - Behavior before this diff
    - **Bad**: warnings shouldn't affect type-checking
- show both a warning and an error
    - That would probably be annoying and/or confusing for users, so I didn't pursue this option.

### How

- in typing.ml, put things back the way they were before needs_concrete was introduced: https://www.internalfb.com/code/fbsource/[a874550fe7747249bae31667411c2009f257d6e4]/fbcode/hphp/hack/src/typing/typing.ml?lines=10421-10439&base=156d49a8f9e5&offset=100&pagesize=100

- in typing_needs_concrete.ml, add some more logic to avoid making warnings that are redundant with 'uninstantiable class' (error 4002)
