Commit title: rich_exception_ptr supports get_exception w/ rich_ptr
Commit body:
Summary:
`get_exception` is the uniform way to access exception objects in containers (`result`, `exception_ptr`, etc). For `result` to be implemented in terms of `rich_exception_ptr` the latter must therefore speak the protocol.

Conceptually, the implementation is straightforward -- get the underlying error's `rich_exception_ptr`, and then do `get_outer_exception<>` on that.

However, since this is **the** most critical query for error-checking perf, we provide a specialized traversal instead of the above simple algorithm.

 ---

Since rich errors support provenance tracking via enrichment wrappers, this `get_exception` doesn't return a raw pointer, but rather `rich_ptr_to_underlying_error`, which quacks like the raw pointer (minus some footgunny implicit conversions), but also captures the enrichment information for ~free.

The net-net is that unless you format it, you don't know you have a rich pointer, but in the logging application, the outcome is **much** better.
