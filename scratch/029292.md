Commit title: Add support for class type alias in HHVM sandbox mode
Commit body:
Summary:
We add support for class type alias in HHVM sandbox mode, gated behind the runtime flag Eval.AllowClassTypeAliases.

When HHVM tries to resolve a type alias, we check if it contains a single constraint that refers to a non-nullable class. If it does, we bind the Named Entity (NE) for that type alias directly to that class. We do that by storing the aliasing class's RDS link in the cached class field (also an RDS link) of the type alias's NE. To really clarify, the RDS link of cached class stores the memory address of another RDS link that stores the aliasing class*. Once the type alias is resolved, HHVM should behave as if there exists a PHP class with the same name as the type alias. Therefore, it supports all the class features like
1. Implementing from a interface type alias
2. Extending from a class type alias
3. Using a trait type alias
4. Accessing static properties (including methods) of a class type alias
5. Instantiating a class from its type alias

We add a basic test for each of these cases.

Currently, this only works without HHBBC. HHBBC changes are not exactly trivial even without it being distributed. Rick is landing distributed HHBBC, which will add even more complexity. So HHBBC changes will take longer (thinking Q2 2026). When those changes are ready, we can enable the flag and release the feature.

We also add tracing to type-alias.cpp to make the logic easier to follow for anyone reading this code in the future.
