Commit title: Fix type error when field name shadows Python builtin `str`
Commit body:
Summary:
# Problem
When a thrift field is named `str`, the generated `__iter__` return type annotation uses bare `str` which refers to the field, not the Python builtin type.

This causes Pyre error: "Annotation _fbthrift_SleepService_space_args.str is not defined as a type"

# Fix
Use `builtins.str` in service arg type stubs for `__iter__` return type tuples, consistent with how struct types already handle this in fields.mustache.
