Commit title: Fix type error for interaction factory methods
Commit body:
Summary:
When a factory method name matches the pattern `create{{interaction_name}}` (e.g., `createStreamingSession` creates `StreamingSession`), the generated code produces two methods with the same name but different signatures. The type checker cannot distinguish which method `self.createStreamingSession()` calls.

Introduce a private `__fbthrift_create*` method that both the factory and public helper delegate to, which eliminates the ambiguous call.
