Commit title: Fix SIGBUS in iterateSections/iterateProgramHeaders
Commit body:
Summary:
The bounds checks in `iterateSections()` and `iterateProgramHeaders()` previously only verified that **one** header fit within the mapped file bounds, but these functions iterate through `e_shnum`/`e_phnum` headers respectively. When encountering malformed or truncated ELF files (e.g., files claiming more headers than actually exist), the iteration would access memory beyond the mapped region, causing a SIGBUS crash.

This is a possible source of the frequent crashes (example: P2124097787) in Strobelight when a malformed ELF file were encountered:
https://fburl.com/scuba/coredumper/xxwaynox
 {F1984565007}

**Changes**
Validate that all headers fit within the mapped file bounds before iterating, using `folly::checked_mul` and `folly::checked_add` to prevent integer overflow.

This follows the same pattern already used in `iterateSectionEntries()` which correctly validates that the entire section data fits within bounds before iterating:

https://www.internalfb.com/code/fbsource/[dc5d59ff41b4638af2bd91fddb778924d30e33fa]/fbcode/folly/debugging/symbolizer/Elf-inl.h?lines=92-110
