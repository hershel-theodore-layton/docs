Summary:
Remember the virtual interface for immortal errors `immortal_exception_storage` from D89023194? The one that type-erased `rich_exception_ptr` uses to implement immortal error functionality?

Here it is -- at last -- the implementation of that interface, for rich errors.

I do not currently support non-rich immortals:

 - Constant-evaluated code has no ability to twiddle pointer bits. Therefore, there's a hard trade-off between "support packed `rich_exception_ptr` storage" and "instantiate non-rich immortals during constant evaluation". I chose the former.

 - Non-rich errors should typically have `std::exception` as the base, and that's not `constexpr` until C++26 (whereas rich errors add it in a sneaky way on top of the hierarchy). If needed, this could be fixed by making these leaky singletons, as we do for rich errors.

Note that if one gives up on the requirement of making immortal `rich_exception_ptr`s in constant-evaluated code, then there's nothing preventing the "leaky singleton + runtime bit twiddling" implementation of arbitrary immortal errors. It will probably even be pretty fast -- it just wasn't requested yet.
