Commit title: Integrate rich errors into result
Commit body:
Summary:
Use `rich_exception_ptr` instead of `exception_wrapper` to implement `non_value_result`.

This has 2 user-observable consequences:
 - `get_exception(resultLike)` now returns a formattable `rich_ptr` instead of a bare pointer. They mostly quack the same, but I did have to fix some callsites' type declarations.
 - You can now construct `non_value_result` from `immortal_rich_error<>` instances.

Up-stack, a 3rd feature is added -- `enrich_non_value(resultLike)` for recording error provenance.

Of course, this change also enables the perf / RTTI-avoidance features of `rich_exception_ptr`. Most importantly, rich errors that are constructed into result-like containers, and never leave will be RTTI-free (as will be their code access). The "stopped" state also supports a fast path, but this needs more work to make it broadly applicable to existing `folly::coro` code.
