Summary:
The mechanics of enriching a `result`-like are pretty simple:
  - If `has_value()`, do nothing.
  - Otherwise, allocate a new `rich_exception_ptr wrapper` with a `detail::enriched_non_value`, whose `next_` is the original `rich_exception_ptr`.
  - Set the underlying error of the new `wrapper` to `next_.underlying_error()` if set -- or to `next_` otherwise. The latter part requires us to define custom copy/move operations.

The lifecycle cost of this wrapper is about 60ns to construct and destruct the underlying `std::exception_ptr`. That same structure currently uses 100-150 bytes of heap storage.

In `docs/future_enrich_in_place.md`, a more efficient scheme is described, which ought to achieve 5-10ns and < 32 bytes per enrichment, amortized.
