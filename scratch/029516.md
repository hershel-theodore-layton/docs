Summary:
## What
Modified `run_on_intersection` in `typing_utils.ml` to only consider actual
errors (not warnings) when deciding which intersection branches are valid.

## Why

When `needs_concrete` is enabled, run_on_intersection was producing spurious errors because existince of warnings changed the type checker code path.

Also: without this change, warnings could changed type checker behavior in future, which could cause bad effects like spurious type errors or missing expected type errors.
