Commit title: address issue in skip_enum_name_map to have correct enum
Commit body:
Summary:
Problem: When an enum has java.swift.skip_enum_name_map annotation (needed to avoid Java's 64KB method size limit) AND a struct field uses that enum with a default value, the Java Swift code generator produced uncompilable code like:
  private AugmentationEnum resultAugmentationId = AugmentationEnum.UNKNOWN; // Error!

 Solution: Modified the Thrift Java compiler to check for the skip_enum_name_map annotation and use fromInteger() instead of named constants.

Files Changed:

  1. xplat/thrift/compiler/generate/t_mstch_java_generator.cc (lines 328-334):
    - Added enumSkipNameMap? property to the make_prototype_for_type function
    - This property checks if the type is an enum with the java.swift.skip_enum_name_map annotation                 2. xplat/thrift/compiler/generate/templates/java/common/const_value.mustache (lines 114-120):
    - Modified the enum default value generation to check type.enumSkipNameMap? first
    - When true, it generates fromInteger(value) instead of trying to use named constants
