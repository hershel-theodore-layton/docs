Summary:
Apply Fix 2: Use `return_ignore_readonly` in `ExpectedTy.make` when creating the expected type for return expressions.

This propagates `ignore_readonly` through bidirectional type checking. When a lambda returns another expression (e.g., another lambda), the ExpectedTy for that expression inherits the `ignore_readonly` flag. This allows nested lambdas to also suppress readonly errors in their returns.

Without this fix, nested lambdas like:
```hack
takes_callback(() ==> () ==> returns_readonly_fn());
```
would fail because the inner lambda's `return_ignore_readonly` would be false (not inherited from the outer lambda's ExpectedTy).
