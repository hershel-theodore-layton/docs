Commit title: reduce InterceptorFrameworkMetadataStorage size from 1024 to 640
Commit body:
Summary:
Defer allocation of `frameworkMetadata` in `ServiceInterceptorRequestStorageContext` until actually needed. Previously, each request context allocated 1024 bytes inline for interceptor framework metadata even when interceptors weren't used.

 Reduce `TypeErasedValue` buffer from 1024 to 640 bytes

**Why need this change?**

- **Problem**
  - Axon hosts with many connections/requests can suffer **excessive memory usage** because they store **~1 KB of metadata** on **both the client and server sides**. https://fb.workplace.com/groups/677796806483229/permalink/1979094813020082/
  - This increases risk to **capacity and availability**, including **out-of-memory (OOM)** failures.

- **Example (high-scale cluster)**
  - One cluster has **~175k** *append streams* (client requests).
  - Per host, this drives:
    1. **~175k inbound requests** received by the server.
    2. Additional **outbound requests** to:
       - `openAppendSink` ~175k
       - `openAppendReplyStream` ~175k
    3. **~170k outbound subscription metastore requests** per host.
  - Reference: https://pxl.cl/8Klq3

- **Estimated memory savings (per host, theoretical)**
    - Save: `0.384KB * (175*3k+170k) = 266 MB` per host
