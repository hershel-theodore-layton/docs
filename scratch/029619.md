Summary:
D46698753 added a new `getThriftHelper()` method on `FizzPeeker` and switched Cpp2Worker to utilize this method.

This means that FizzPeeker no longer serves any use.

First, it has no state of its own, beyond what it inherits from wangle::Acceptor::DefaultToFizzPeeker

Second, `FizzPeeker::getHelper` was not even being invoked before this diff.
apache::thrift::Cpp2Worker instances [place themselves as the first peek callback
to be invoked](https://github.com/facebook/fbthrift/blob/1e28d6a855c08cf566e7c23589e4a4d6ea98dab4/thrift/lib/cpp2/server/Cpp2Worker.h#L104)
even before wangle::Acceptor. Since the Cpp2Worker [getHelper() implementation](https://github.com/facebook/fbthrift/blob/1e28d6a855c08cf566e7c23589e4a4d6ea98dab4/thrift/lib/cpp2/server/Cpp2Worker.cpp#L404-L414) only invoked [`getThriftHelper`](https://github.com/facebook/fbthrift/blob/1e28d6a855c08cf566e7c23589e4a4d6ea98dab4/thrift/lib/cpp2/server/Cpp2Worker.cpp#L351-L352), this was effectively dead code.

This diff removes `apache::thrift::FizzPeeker`  Since the `Cpp2Worker` is responsible for creating the asynchronous handshake object (handshaker), **and** it was already using a custom function (on `apache::thrift::FizzPeeker`) to create it, it makes more sense to simply inline the ThriftFizzAcceptorHandshakeHelper directly in Cpp2Worker.

The immediate motivation for this diff is that I want to add more per-connection state to the handshake helper. But as I was looking at how I would do so through `getFizzPeeker`, I was wondering which method I should change, and whether or not I would need to update the interface to PeekingAcceptorHandshakeHelper::PeekCallback altogether. This is cognitive burden that is nothing but distracting.

After this diff, it should be very obvious -- Cpp2Worker creates the handshaker. If there are custom Thrift specific properties that need to be set, the natrual place to do this would be in Cpp2Worker, rather than in an interface that is supposed to implement a wangle::PeekingAcceptorHandshakeHelper::PeekingCallback.
