Commit title: Rework <<__RequirePackage>> and support <<__SoftRequirePackage>>
Commit body:
Summary:
The existing approach for `__RequirePackage` attempts to represent it on the type of a method. This is incorrect, as the requirement is not relevant to subtyping, and is more akin to a visibility modifier. As a result, there are bugs and incompletenesses when calling polymorphic functions and general issues composing with the rest of packages.

Changes:
- delete `ft_require_package` field
- add `package_requirement` to decls
- model `<<__SoftRequirePackage>>`
- shift inheritance validation from subtyping to Typing_extends
- add sanity checks for function requirements wrt. the file's package
