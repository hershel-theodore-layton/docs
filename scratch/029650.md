Commit title: Autocomplete on enum class label calls should not assume arity
Commit body:
Summary:
When completing a call such as
```
foo(#AUTO332
```
to a function whose signature is similar to
```
function foo<Targs as (mixed...)>(HH\EnumClass\Label<C, Targs> $label, ...Targs $args): void
```
we filter the possible values for `$label` according to the type, which includes a `Targs` generic. Unfortunately, in the absence of any arguments, we end up inferring `()` for `Targs`, and so we lose enum constants that make sense if there *are* other arguments.

A somewhat hacky fix is to notice the autocomplete token `#AUTO332` during type checking of the call, and "pretend" that there are any number of further arguments by creating a splat (unpacked) argument, as though the user had written
```
foo(#AUTO332, ...junk)
```
