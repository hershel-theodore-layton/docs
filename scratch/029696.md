Commit title: Simplify CommutativeWrapperAwaitable with uniform by-value overloads
Commit body:
Summary:
`CommutativeWrapperAwaitable` is the CRTP base for wrappers like `value_or_error` or `co_awaitTry` that commute with `co_viaIfAsync` and `co_withCancellation`.

I noticed that the wrapped type is always a movable *or* must-use-immediately awaitable, both of which are handled by the "by-value / unsafe-mover" idiom. The mover is a no-op for types that don't need it.

The only awaitable requiring pass-by-&& is the immovable `Baton`, and this doesn't support `await_resume_try` or any of the other awaitable-wrapper protocols. As I noted before, if we DO want to add that support, it should be by making the `Baton` **not** be directly awaitable.

Removing `-> decltype(auto)` from the lambdas forces by-value return. This avoids a stack-use-after-free from that annoying default `co_withCancellation` that returns `Awaitable&&`.

Reduces 6 overloads to 3, ~50 line win.
