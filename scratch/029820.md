Commit title: Add pack and unpack functions to FunctionCredential
Commit body:
Summary:
Adds pack and unpack methods to FunctionCredential so that it can be transferred across an Xbox boundary in service of [hack class authentication](https://docs.google.com/document/d/175V7iBD1Qpr7R4BVBp4l1zLpab_8x7DaCHXITdQcuF4/edit?tab=t.0#heading=h.l7iy1mul08n3). The packing format is:
{"class_name": ... | null, "function_name": ..., "valid_until": <timestmap>}:<AUTHENTICATION TAG>. The "valid_until" flag is used to make sure that this value can't be unpacked long after it was created since for the xbox use case it should realistically be deserialized within seconds at most. The valid_until is hardcoded to 5 minutes which is more time than we need while still mitigating any potential replay threat. Not 100% sure this is necessary but I think we can afford to have it

The authentication tag is computed over the json object using a per process random key. This authentication tag serves two purposes:
1. Prevent hack land from forging a valid function credential serialization without calling `serialize()` on a real `FunctionCredential` object
2. Prevent a function credential object from being unpacked in an entirely separate hhvm process

Largely written with the help of claude
