Commit title: Replace default allocator for `AtomicUnorderedInsertMap`
Commit body:
Summary:
Default memory allocator for `AtomicUnorderedInsertMap` is `MMapAlloc` which
calls `mmap()` and `munmap()` under the hood. This seems like a reasonable
idea: we are bypassing memory allocator internals and allocating directly from
the OS. There is a problem though: `mmap()` and `munmap()` calls in the Linux
Kernel are protected by a per process RW `mmap_lock`, so each
`mmap()`/`munmap()` call grabs this lock on write a stalls all other lock
users. One possible solution to this problem is to cache memory to avoid too
much interaction with the OS. That is exactly what userspace memory allocators
do: cache memory from OS. Another bonus is that there are multiple arenas in
jemalloc memory allocator each of them have it is own lock, so there is no more
contention on the per process `mmap_lock`.
