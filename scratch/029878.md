Summary:
This diff refactors the `RocketClientChannel` architecture by extracting common client channel logic into a new `RocketClientChannelBase` abstract class,
while allowing concrete implementations to provide different transport types (`SecureRocketClient` or `RocketClient`):

**What changed:**
- Added `RocketClientChannelBase` - Abstract base class containing all shared client channel logic.
  - Defines virtual methods for accessing transport implementation
	      virtual rocket::RocketClient& getRocketClientImpl();
          virtual const rocket::RocketClient& getRocketClientImpl() const;
  - Derived classes provide concrete transport implementation (`RocketClient` or `SecureRocketClient`)

- Added `SecureRocketClientChannel` - New channel implementation that derived from `RocketClientChannelBase` and `SecureRocketClient`, provides the `SecureRocketClient` as transport implementation.

- Updated `RocketClientChannel`: Now derives from RocketClientChannelBase and `RocketClient`, provides the `RocketClient` as transport implementation.

This diagram illustrates Rocket client architecture supporting two concurrent use cases during.
   - Use Case 1 - ServiceRouter (Secure Path):
Utilizes the new SecureRocketClient with custom implementations of RocketClientLogger and RocketConnectionTerminationPolicy, routed through SecureRocketClientChannel.
   - Use Case 2 - Proxygen (Legacy Path): Continues using the existing RocketClient via RocketClientChannel.
