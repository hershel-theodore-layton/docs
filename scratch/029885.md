Commit title: Fix segfault in reified generics is check for shape/tuple type mismatch
Commit body:
Summary:
Fixes a segfault when `is` checks for reified generics. Specifically, checking
if the generic is a shape or tuple when the actual type is not.

The type structure helpers `get_ts_{d,v}array` call to `ArrayData::get` which,
as documented, returns an unitialized typed value if the key is not present.
Since the representation of a type structure sets some string keys based on the
underlying expected data, if we don't check that the input kind matches the
type kind, we'll eventually dereference an uninitialized pointer.

The fix adds kind checks before accessing type-specific fields:
- For T_tuple: check input is also T_tuple before calling get_ts_elem_types
- For T_shape: check input is also T_shape before calling get_ts_fields
