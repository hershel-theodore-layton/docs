Commit title: Ensure valid positions for typing_enference_env
Commit body:
Summary:
## What

- Propagate positions when working with typing_inferenve_env so we don't end up with empty positions.
- Add validation so we don't regress proper environment-propagation

## Why

We are seeing thousands of InconsistentTyVarState errors in prod but they won't be actionable until`env.pos` is `None`.

https://fb.workplace.com/groups/hacklang.oncall/permalink/1298606922105856/

We have been trying case-by-case but it was whackamole before this diff.

In particular, we know that the main (only?) source of these bugs is in a tast check, and typing_inference_env.pos was, afaict, always `None` in tast checks.

## How

- A helper that sets the position, and returns a function for restoring the position. This is inspired by [a pattern from Rust](https://github.com/rust-lang/rust-analyzer/blob/65a1538/crates/stdx/src/lib.rs#L18) (but with less safety in our OCaml).
    - Note: we call restore_pos everywhere it makes sense to. It doesn't make sense to right before an env is about to be thrown away (like at the end of a function) and there's nowhere to put restore_pos in such cases anyway.
- Using an invariant_violation if the position isn't set - this doesn't block the user in development but causes our snapshot tests to fail if the position isn't propagated–this helped me isolate where to use the helper

## Alternative considered

I considered using the `with` callback pattern:

https://ocaml.janestreet.com/ocaml-core/v0.12/doc/stdio/Stdio/In_channel/index.html#val-with_file

But didn't:
- Too much nesting
- I worried about creatingmany closures with large environments in a hot part of the type checker
