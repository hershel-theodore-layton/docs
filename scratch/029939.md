Commit title: Noexcept.h -> ValueOrFatal.h with better API naming
Commit body:
Summary:
Rename and API cleanup for the "noexcept awaitable" wrapper. This refactor doesn't fundamentally change the functionality -- we're still declaring tasks that can be awaited without risk of exception or cancellation.

The policy refactor has one minor functional change: instead of `std::terminate()` we throw the exception under `noexcept` to give the runtime a chance to print a more useful error.

**Motivation:** The extra polish helps up-stack, where making tasks value-only-awaitable becomes a key ingredient in async RAII.

### Align naming with C++26 `std::execution` and `folly/result`

Make it extra-clear that non-value completions may fatal. Previously, one could plausibly confuse `as_noexcept` and `co_nothrow`.

| Old | New |
|-----|-----|
| `Noexcept.h` | `ValueOrFatal.h` |
| `as_noexcept<Task<T>, Cfg>` | `value_or_fatal<Task<T>, Policy>` |
| `noexcept_awaitable_v<T>` | `value_only_awaitable_v<T>` |
| `NoexceptAwaitable` | `ValueOrFatalAwaitable` |
| `NoexceptAwaiter` | `ValueOrFatalAwaiter` |

### Policy API replaces ad-hoc cancel config

The new policy API is also C++26-aligned, while being easier to customize correctly.

| Old | New |
|-----|-----|
| `terminateOnCancel` | `on_stopped_and_error<will_fatal>` |
| `OnCancel<void>{}` | `on_stopped_void` |
| `OnCancel(42)` | `on_stopped<42>` |
| (no equivalent) | `on_stopped_and_error<V, W>` (different defaults for stopped vs error) |

When customizing the policy, you can use the tag `will_fatal` to clearly state "terminate on this completion".
