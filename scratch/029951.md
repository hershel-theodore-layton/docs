Commit title: Skip over inherited type constraints when attempting to retrieve the main type hint
Commit body:
Summary: TypeIntersectionConstraint represents a vector of types that will be enforced for a parameter or return type (or property). Currently it is constructed in such a way that one of its elements represents the type hint (main type) and  other members represent upper bounds (types specified using the as clause e.g. T as Foo where T is a generic or type alias). There are some places in the HHVM codebase that build on this assumption such as the getType() method on ReflectionParameter. Inherited type constraints are introduced in an upcoming change that enforces monotonicy of return types (D73601786). After this change, the above assumption is no longer true. Introduce a temporary helper method that skips over the inherited constraints. This method will be deprecated once getType() is deprecated.
