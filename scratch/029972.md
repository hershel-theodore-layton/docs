Commit title: breadth limit on WWW -> tao + mc service calls
Commit body:
Summary:
This effectively is the WWW version of the C++ Continuation handler.

Memcache/ucache and TAO do NOT go through the standard thrift handler setup - they use separate low-level handlers (`FBTraceGlueTaoExtension`, `FBTraceGlueMCX`) when propagating trace context. Because of this, these service calls were NOT being counted against the breadth limits established by `TraceSizeEstimationContextHandler`.

This diff adds the breadth limit checks to both glue classes:
1. Check `shouldBlockTraceContinuationOnOutgoingRequest()` - if true, suppress trace continuation by returning null
2. Call `bumpBreadth()` to ensure these calls are tracked for trace size estimation

Adding ODS counter for o11y here.
