Client-side Sink API looks approximately like this (example):

```
# Thrift schema
service DataService {
  FinalResponse, sink<Request, FinalResponse> UploadData(1: UploadMetadata metadata);
}
```

```
# Go Client code
func uploadFile(ctx context.Context, client *FileServiceClient, fileName string, file *os.File) (int64, error) {
    // Call the sink RPC - returns initial response (upload id) and a callback function
    uploadID, sinkCallback, err := client.UploadFileChunks(ctx, fileName)
    if err != nil {
        return 0, fmt.Errorf("error initiating upload: %w", err)
    }
    fmt.Printf("Upload started with ID: %d\n", uploadID)

    // Create an iterator that yields file chunks
    chunkSeq := func(yield func([]byte, error) bool) {
        chunk := make([]byte, 4096)
        for {
            n, err := file.Read(chunk)
            if err == io.EOF {
                return // done
            }
            if err != nil {
                yield(nil, err) // send error to server
                return
            }
            if !yield(chunk[:n], nil) {
                return // caller stopped consuming
            }
        }
    }

    // Invoke the callback to send all chunks and get final response (checksum)
    checksum, err := sinkCallback(chunkSeq)
    if err != nil {
        return 0, fmt.Errorf("error during upload: %w", err)
    }

    return checksum, nil
}
```

Supports:
* Initial/first response (optional - if Thrift schema defines it)
* Initial error (returned from the RPC call itself)
* Sink elements sent via Go iterator (iter.Seq2[ElemType, error])
* Sink element errors (declared exceptions are wrapped and sent to server)
* Final response (returned from the callback function)
* Final error (returned from the callback function)
* Interactions (optional - if Thrift schema defines it, an interaction client is also returned)

The callback-based API allows users to:
* Control when to start sending sink elements
* Use Go's iterator pattern (iter.Seq2) to lazily produce elements
* Send declared exceptions as part of the sink stream
* Receive the final response synchronously after all elements are sent
