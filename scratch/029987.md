Commit title: co_cancelled -> co_stopped_may_throw, eliminate co_error(OperationCancelled{})
Commit body:
Summary:
Motivation:
- **Align with C++26's `std::execution`** --  The design in [P2300](https://wg21.link/p2300) calls cancellation
  "stopped" -- a distinct completion signal, [not an error (see P1677)](https://wg21.link/p1677).
- **Prepare for `co_stopped_nothrow`, reduce bugs** -- the current primitive throws `OperationCancelled` in awaiting coroutines, unless they use a non-throwing wrapper (`value_or_error`, `value_or_error_or_stopped`, `co_awaitTry`, `co_nothrow`). Not only is this inefficient (1usec+ per throw), but it also makes it easy to accidentally break cancellation via catch-alls. The upcoming
  `co_stopped_nothrow` will propagate cancellation without throwing within `folly::coro` await chains.
- **Reduce `OperationCancelled` usage** -- In order to reinforce "**cancellation is not an error**", direct use of `OperationCancelled` as
  an exception is discouraged. The new AP avoids constructing exception objects on the cancellation path.
