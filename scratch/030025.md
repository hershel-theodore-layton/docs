Commit title: Fix AddressSanitizer crash and add RefCounted fair-share accounting for fbstring
Commit body:
Summary:
Fix an AddressSanitizer crash when calling `allocatedSizeOf()` on
`folly::fbstring` instances using Large (RefCounted) storage mode,
and add proper fair-share accounting for shared strings.

## Root Cause

`folly::fbstring` has three storage modes:
- **Small (SSO)**: Strings ≤23 bytes stored inline in the object
- **Medium**: Strings 24-254 bytes with direct malloc allocation
- **Large**: Strings >254 bytes with RefCounted allocation

For Large strings, the memory layout includes a RefCounted header:
```
malloc'd pointer
     ↓
     [refCount_ (8 bytes)][string data...]
                          ↑
                     data() returns this
```

The previous implementation called `bytesAddressedByAllocatedPointer(string.data())`
which internally calls `malloc_usable_size(data())`. For Large strings, `data()`
is offset 8 bytes from the actual malloc'd pointer, causing AddressSanitizer to
detect an invalid pointer:

```
ERROR: AddressSanitizer: attempting to call malloc_usable_size()
for pointer which is not owned
```

## The Fix

1. **Add `use_count()` API to folly::fbstring** - Returns the reference count
   for Large strings, or 1 for SSO/Medium strings. This enables fair-share
   memory accounting similar to `std::shared_ptr::use_count()`.

2. **Add `is_counted()` API to folly::basic_fbstring** - Returns true for
   Large strings that use RefCounted storage. This allows accurate memory
   accounting by including the sizeof(size_t) header overhead.

3. **Update allocated_size_traits** - Use capacity-based size estimation with
   `bytesAllocatedForSize()` instead of `malloc_usable_size()`. For Large
   strings, add `sizeof(size_t)` for the RefCounted header and divide by
   `use_count()` for fair-share accounting. Supports the same flags as
   `std::shared_ptr`:
   - Default: divide by use_count() for fair-share
   - `SharedPtrOnlyUnique()`: return 0 if shared
   - `SharedPtrAlwaysFull()`: return full size regardless of use_count

## Testing

Added comprehensive unit tests:
- `LargeRefCountedString`: Reproduces the ASAN crash with strings >254 bytes
- `MediumStringAccuracy`: Verifies accuracy against `malloc_usable_size()`
- `AllModes`: Tests boundary conditions across SSO/Medium/Large transitions
- `UseCountAndIsCounted`: Tests the new `use_count()` and `is_counted()` APIs
- `RefCountedFairShare`: Tests fair-share division and flags behavior
- `RefCountedHeaderOverhead`: Verifies Large strings include header overhead
