Commit title: Make `rich_exception_ptr` formattable
Commit body:
Summary:
The goal here is to make these work:

```
fmt::format("Oops: {}", result.error_or_stopped());
LOG(INFO) << "Oops: " << result.error_or_stopped();
```

`get_exception<Ex>(rep)` can use `Ex`-specific formatters, but `fmt::format("{}", rep)` cannot.

Since `rich_exception_ptr` is type-erased, we can only do a few things:
- Rich errors use `format_with_epitaphs()`, which handles epitaph chains, and delegates to virtual `rich_error_base::format_to()`. No loss of debuggability for rich errors!
- For `std::exception` types, we show the demangled type name + `what()`.
- For all other types, the demangled type name is all we can do.
- Plus, REP has a few edge-case states, like `[empty]`.

 ---

I also snuck in `kImplementsSmallValue` here, because there's no point in having small-value dead code until real small-value support is added. On my benchmarks up-stack, this made barely any difference (<1% on a result-heavy bench), but dead code is not free.
