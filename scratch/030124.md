Summary:
## Motivation
`ThriftRocketServerHandler` has grown into a monolithic class (~1117 lines) that violates the Single Responsibility Principle by mixing multiple concerns: connection lifecycle management, request handling, error handling, service interceptor coordination, and observability.

This refactoring extracts these responsibilities into focused, testable components: `RocketSetupProcessor`, `RocketErrorHandler`, `RocketContextManager`, `RocketRequestProcessor`, and `RocketRequestOrchestrator`, culminating in a new `RefactoredThriftRocketServerHandler` that composes these modules. The modular design improves code clarity, testability, and maintainability while preserving existing behavior.

This diff extracts `RocketSetupProcessor` from `ThriftRocketServerHandler`, which is responsible for the entire setup handshake when a Rocket client first connects to the server.

## Implementation Details

**Public API:**
- `handleSetupFrame()` - Main entry point for processing setup frames
- `SetupResult` struct - Contains all initialized components (processor factory, thread manager, event base, etc.)

**Private validation methods:**
- `validateSetupFrameBasics()` - Checks for required metadata presence
- `validateProtocolKey()` - Validates protocol key with legacy key support
- `deserializeSetupMetadata()` - Unpacks setup metadata from payload
- `negotiateProtocolVersion()` - Implements version negotiation: min(serverVersion, clientMax)
- `validateMimeTypes()` - Ensures version 9+ uses rocket MIME types
- `runSetupInterceptors()` - Executes setup frame interceptors
- `setupProcessorFactory()` - Configures processor (custom handler or default)
- `configureConnectionSettings()` - Applies QoS marking and sends setup response
