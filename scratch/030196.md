Commit title: Fix Netty ByteBuf memory leak: Bidirectional cancellation in FutureUtil
Commit body:
Summary:
When converting a Mono to ListenableFuture via FutureUtil.toListenableFuture(), cancellation of the ListenableFuture was not propagated back to the Mono subscription. This left upstream resources (like Netty ByteBuf) unreleased.

The fix adds hookOnSubscribe() to ListenableFutureSubscriber which:
- Registers a listener on the SettableFuture
- When the future is cancelled, calls dispose() on the subscriber
- This cancels the upstream Mono subscription and triggers cleanup handlers

Combined with Fix 1, this ensures cancellation signals flow in both directions:
- Mono -> Future: Already handled by existing hookOnCancel()
- Future -> Mono: Now handled by the new hookOnSubscribe() listener

This is part 2 of 3 fixes for the ByteBuf memory leak issue:
1. MonoTimeoutTransformer: Cancel upstream on timeout
2. FutureUtil: Bidirectional cancellation between ListenableFuture and Mono (this commit)
3. LegacyRpcClient: Lazy ByteBuf allocation with Mono.defer()
