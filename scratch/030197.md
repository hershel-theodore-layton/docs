Commit title: Fix Potential Netty ByteBuf memory leak: Lazy ByteBuf allocation with Mono.defer()
Commit body:
Summary:
Refactor LegacyRpcClient to lazily allocate ByteBuf only when the Mono
is subscribed, using Mono.defer(). This prevents memory leaks in scenarios
where the Mono is never subscribed to (e.g., timeout fires before subscription).

The Problem:
Previously, both singleRequestSingleResponse() and singleRequestNoResponse()
allocated the ByteBuf eagerly when the method was called. If a timeout occurred
before the Mono was subscribed to, the ByteBuf would never be released because
the reactive pipeline never executed.

The Solution:
Wrap the entire request handling logic in Mono.defer(), which defers execution
of the lambda until subscription. This ensures:

1. ByteBuf is only allocated when there is actual downstream demand
2. If a timeout fires before subscription (via MonoTimeoutTransformer), no
   ByteBuf is allocated, so no leak can occur
3. Once subscribed and writeAndFlush() is called, Netty takes ownership of
   the ByteBuf and handles its release on write completion

This is part 3 of 3 fixes addressing ByteBuf memory leaks in the Thrift
client layer:
- Part 1: MonoTimeoutTransformer cancellation
- Part 2: FutureUtil bidirectional cancellation
- Part 3: Lazy ByteBuf allocation (this commit)
