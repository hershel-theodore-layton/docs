Commit title: result no longer implemented via Expected
Commit body:
Summary:
The change has a few main benefits:
 - For types with throwing move ctors, the new `result<T>` has no valueless-by-exception state, unlike `folly::Expected`, which does. Simpler usage model, simpler code.
 - The new `result<>` (i.e. `void`) is only 8 bytes, not 16.
 - Perf is better. Up-stack, I replaced `Try<T>` with `result<T>` inside of `folly::coro` tasks, and ran some benchmarks. The old `result` was slower than `Try`, and the offending code mapped onto the `Expected::operator=` impl. The new `result` was neutral-to-better than `Try` despite being more feature-rich.

Replacing the internals of `result` not to use `folly::Expected` is tricky, because some of the interface behaviors used to delegate to `Expected`. To make sure I broke nothing of value, I focused on before/after testing:
 - Stacked below this change are a bunch of new tests for areas that were poorly covered. I.e. I explicitly covered the areas where I was implicitly relying on `Expected` before. D92113457
 - Remove tests for the valuless-by-exception behavior. D92770825
 - Add more benchmarks, to ensure perf noninferiority.
 - Do the refactor (this diff)
 - Add some more tests for the new behaviors (D92775096)

The "before" tests are green, as are the "after" tests. So, all behavior changes are circumscribed by the test changes you see on this diff, and the new tests up-stack.
