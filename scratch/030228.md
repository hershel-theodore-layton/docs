Python Thrift clients were not using client interceptors - enabling this involves two main changes:
- Have `OmniClient` invoke client interceptor callbacks on `onRequest` and `onResponse`
- Register `OmniClient` with global interceptors.

Currently, Python processes (via InitFacebookLight) only register `ContextPropClientInterceptor`, which:
- Implements only `onRequest`
- Is non-blocking (reads only thread-local RequestContext)
- Has multiple early-exit paths (flag/mask checks, switches, etc.)

We expect this to be a relatively safe change with low-medium risk as the interceptor is already registered and used in C++ Thrift clients.

**For SR/Thrift team reviewers**: Please review interceptor invocations in `OmniClient.cpp`. Would also welcome any suggestions on test cases to cover the new logic.
