Summary:
In order to build WA deltoid metrics, we need to add WA User RID field.

This change adds WhatsApp User RID support to the ContextProp framework, following the pattern established in D66217701 for FB and IG user identifiers.

## Changes

### ThriftContextPropState.php

**New UserIdCategory enum value:**
- Added `WA = 2` to `UserIdCategory` enum to support WhatsApp user identification

**New public API methods:**
- `updateWAUserRid(?int $wa_user_rid, string $src, UserIdSource $user_id_source): bool` - Static method to update WA User RID with ODS tracking, validation, and override protection (only ViewerContext can override existing values)
- `getWAUserRid(): ?int` - Read only getter to retrieve the WA User RID from baggage

**New private setter:**
- `setWAUserRid(?int $wa_user_rid): void` - Private setter with lazy initialization of baggage/user_ids and cache invalidation via `dirty()`

**Validation in deserialization:**
- Added `wa_user_rid` validation in `getTfmFromString()` to coerce/validate WA User RID when deserializing ThriftFrameworkMetadata, matching the pattern for `fb_user_id` and `ig_user_id`

**ID validation:**
- Extended `coerceId()` switch statement to handle `UserIdCategory::WA` - WA User RID only requires positive integer validation (no range check like FB IDs)

### ThriftContextPropStateTest.php

**New test for invalid IDs:**
- Added `testUpdateWAUserRidWithInvalidId` with DataProvider to verify zero and negative IDs are rejected

**Combined nullable test:**
- Merged WA User RID tests into `testUserIdsNullable` to test all three user ID types (FB, IG, WA) together:
  - Tests initial null state for all user IDs
  - Tests setting values for all three user IDs
  - Tests null override rejection for all three
  - Tests individual updates don't affect other user IDs
This change adds WhatsApp User RID (Resource ID) support to the ContextProp framework, following the pattern established in D66217701 for FB and IG user identifiers.
