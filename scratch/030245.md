Summary:
Add support for stream/sink methods without channel in Thrift PHP client

This diff enables Thrift stream and sink methods to work without requiring a non-null channel by introducing a fallback mechanism using async handlers.

**Changes:**

1. **New async handler methods:**
   - Added `genWaitStream()` to TClientAsyncHandler to return an async generator for stream payloads
   - Added `genWaitSink()` to TClientAsyncHandler to return a sink function for consuming payloads
   - Implemented corresponding multi-handler versions in TClientMultiAsyncHandler

2. **ThriftClientBase updates:**
   - Modified `genAwaitStreamResponse()` to support channel-less operation by using async handler's genWaitStream()
   - Modified `genAwaitSinkResponse()` to support channel-less operation by using async handler's genWaitSink()
   - Relaxed invariant checks to only require TMemoryBuffer transport (removed channel null check)

**How it works:**
- When a channel is present, the existing channel-based flow is used
- When channel is null, client will continue to serialize the arguments as before and then invoke the async handler methods. The expectation from async handler is that it would get the serialized argument from transport and eventually serialize the response that client can then read. For stream/sink, async handler will also provide the necessary async generators.
- The async handler is responsible for making the first response available on the input transport

This enables more flexible Thrift client configurations and allows stream/sink methods to work in environments where channels may not be available. A use case for this is FAAS client that acts intercepts the client request and proxies the request to FAAS serverless setup.
