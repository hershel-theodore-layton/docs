Commit title: Avoid bail!() for control flow in SimpleJSON deserializer
Commit body:
Summary:
The SimpleJSON deserializer's `possibly_read_comma()` uses `eat()` → `eat_only()` → `bail!()` to detect end-of-container (e.g., `}` instead of `,`). This is expected control flow, not an error. However, when `RUST_BACKTRACE=1` is set, each `bail!()` captures a full stack backtrace through a process-wide global mutex (`backtrace-0.3.76/src/lib.rs` static LOCK). Under high concurrency with large thrift responses, this causes severe mutex contention — all threads serialize through one lock, effectively making the server single-threaded.

The fix replaces the error-based control flow with a peek-based approach: check the next byte before consuming it. `possibly_read_comma()` now peeks for `,` instead of trying to eat it and catching the error. Similarly, `read_bool()` now peeks for `t`/`f` instead of trying to eat "true" and falling back to "false" on error. This eliminates all `bail!()` calls on the normal parsing happy path.
