Commit title: Validate sealed field types
Commit body:
Summary:
Adds two new extra-validation flags to the `thrift` compiler:
1. `non_sealed_key_type` (defaults to `none`)
  * Determines the action to take when a non-sealed type is used in a situation where a sealed type is required, i.e. as a map key or set element type.
  * The current implementation only validates the types of fields in structured types. Subsequent work will add validation for typedefs (and, potentially, function parameters, etc.)
2. `unnecessary_allow_unsafe_non_sealed_key_type` (defaults to `error`)
  * The previous validation of sealed key types can be explicitly disabled for a specific field/usage by adding the `thrift.AllowUnsafeNonSealedKeyType` annotation. This extra-validation determines the action to take when this annotation is used in a context that does not make sense (either because the target type is properly sealed, or is not even a map/set).  It defaults to `error` because, unlike the first validation, this is a completely new concept being introduced, so there's no need for backwards compatibility.
