Commit title: add WtStreamManager per-stream read callbacks
Commit body:
Summary:
When integrating WtStreamManager with the quic layer, we need per-stream events that effectively ignore connection-level wt flow control semantics (as these will be set to kMaxVarint anyways). WtStreamManager doesn't know the state of the underlying quic transport and so we need some support to signal when the application has read/written data

For example:
* when implementing a read loop we only want to read and buffer at most 64KiB in WtStreamManager before resuming reading from the quic socket. When data is read out of WtStreamManager, we invoke ReadCallback to let the backing transport know we'd like to resume reading from the quic socket
