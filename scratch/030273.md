Commit title: Add codemod: annotate_allow_unsafe_non_sealed_key_type
Commit body:
Summary:
Add a new codemod that annotates fields, typedefs, and function parameters with `thrift.AllowUnsafeNonSealedKeyType` when they have `map<K,V>` or `set<E>` types where the key/element type is not sealed. This is needed to exempt existing code from the new sealed-type validation being introduced in the compiler.

The codemod only annotates direct types — if a field's type is a typedef to a non-sealed set, the typedef itself is annotated, not the field. Function return types are out of scope (annotation scope doesn't allow placement on functions).
