Commit title: Fix data race on static counter in hdf wildcard parsing
Commit body:
Summary:
The HDF parser in neo_hdf.c uses a `static int counter` to generate unique names for wildcard (`*`) entries like those in `.hhvmconfig.hdf`'s `IndexedMethodAttributes`. This counter is shared across all threads with no synchronization, causing a data race when multiple threads parse HDF concurrently (e.g., concurrent `RepoOptions::forFile()` calls in HHVM server mode).

When two threads race on `counter++`, they can produce the same counter value. Since `_set_value` uses a hash table to look up children by name (for nodes with >10 children), a duplicate name causes the second entry to overwrite the first instead of creating a new child. This silently drops one entry from the parsed result.

The fix makes the counter `_Thread_local` so each thread gets its own counter, eliminating the race while preserving the uniqueness guarantee within each parse.
