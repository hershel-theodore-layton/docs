Commit title: Fix AnyPatch extract after clear+ensureAny merge==
Commit body:
Summary:
AnyPatch::merge() internally calls tryPatchable() which decomposes assign(value)
into clear() + ensureAny(value). This is semantically correct for apply() — clearing
the AnyStruct and then ensuring it holds the given value is equivalent to assigning it.

However, extractDynamicPatchAsIf() and extractPatchAsIf<>() did not model this
correctly. Both DynamicPatchExtractionVisitor and AnyPatchExtractionVisitor treated
ensureAny() as a no-op when the type matched, since a matching type means "nothing to
do." But after clear(), the type is gone — so ensureAny() with a matching type actually
means "assign this value." Without tracking the clear state, the extraction visitors
would visit clear() (wiping the extracted patch) and then skip ensureAny() (losing
the value entirely), producing an empty or corrupted extracted patch.

Fix: Add a cleared_ flag to both extraction visitors. clear() sets cleared_ = true.
ensureAny() checks: if cleared_ is true and the type matches, create an assign patch
from the ensured value (modeling clear + ensureAny(value) = assign(value) at the typed
level), then reset cleared_ to false. If the type doesn't match, the extracted patch
is reset entirely as before.
