Commit title: Reorganize typing_case_types.ml by purpose
Commit body:
Summary:
Split the monolithic typing_case_types.ml into five purpose-specific modules:

- typing_data_type.ml: Core functor engine with Tag, DataTypeReason, TagWithReason, SET signature, Make functor, ApproxTagSet, and default DataType instantiation. The functor allows purpose 3 (refinement) to eventually swap in a different set implementation.
- typing_case_type_check.ml: Well-formedness checking for case types (check_overlapping, data_type_from_hint). Used by typing_typedef.ml.
- typing_case_type_variant.ml: Simplification of unions/intersections via case type variant filtering (get_variant_tys, filter_variants_using_datatype, has_where_clauses). Used by typing.ml, typing_intersection.ml, typing_refinement.ml.
- typing_atomic_data_types.ml: Disjointness logic facade for type refinement (of_ty, of_tag, complement, are_disjoint, are_locl_tys_disjoint). Used by typing_refinement.ml.
- typing_case_type_utils.ml: Where-clause recursive mention helpers. Used by typing_typedef.ml, typing_subtype.ml, typing_type_wellformedness.ml.

All callers migrated, original typing_case_types.ml deleted.
