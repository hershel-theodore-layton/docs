Commit title: Hide reason-tracking complexity from non-check DataType consumers
Commit body:
Summary:
After reorganizing typing_case_types.ml into purpose-specific modules, the DataTypeReason trail-tracking machinery was exposed through typing_data_type.mli to all consumers. However, only typing_case_type_check.ml uses reason/trail information for detailed error messages. The other consumers (typing_case_type_variant.ml, typing_atomic_data_types.ml) always pass empty trails and gain nothing from this complexity.

This diff adds trail-free wrappers in the DataType module that shadow the trail-taking leaf functions with versions that internally create and pass an empty trail. The .mli signature for DataType is simplified to remove ~trail and ~reason parameters. typing_atomic_data_types.ml no longer references DataTypeReason at all.

The full Make/SET/DataTypeReason/TagWithReason types remain exposed for typing_case_type_check.ml, which uses Make(ApproxTagSet) directly with full trail tracking.
