Commit title: Separate witness and non-witness ApproxSet module types
Commit body:
Summary:
Only one caller (`typing_case_type_check.ml::check_overlapping`) actually needs the witness-producing `disjoint` function that returns `Sat | Unsat { left; relation; right }`. All other downstream typing code only needs `are_disjoint` (bool) and `is_subset` (bool). This diff separates the two concerns at the module type level so that `BddSet.Make` is no longer forced to implement witness production it doesn't need.

Split `ApproxSet_intf.S` into `S` (non-witness: `are_disjoint`, `is_subset`) and `S_with_witness` (extends `S` with the `disjoint` type and function). `ApproxSet.Make` implements `S_with_witness` while `BddSet.Make` implements only `S`. In `BddSet`, the `disjoint` type and function are removed and `are_disjoint` is rewritten to use `check_relation` directly.

In `approxset_test.ml`, the `Test` functor is split into `TestBase` (parameterized by `S`) and `TestWithWitness` (parameterized by `S_with_witness`). Most tests (`test_union`, `test_intersection`, `test_diff`, `test_complex`, `test_unknown`, quickcheck tests) are rewritten to use `are_disjoint` (bool) instead of pattern-matching on the `disjoint` type, so they work with the non-witness `S` interface. Only `test_origin_reporting` — which inspects the `Unsat` witness payload — lives in `TestWithWitness`. `ApproxSet` tests use `TestWithWitness`; `BddSet` tests use `TestBase`.
