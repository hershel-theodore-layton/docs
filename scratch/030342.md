Commit title: Handle SSL_ERROR_WANT_CLIENT_HELLO_CB in AsyncSSLSocket::handleReturnFromSSLAccept
Commit body:
Summary:
When an SSL_CTX_set_client_hello_cb callback returns SSL_CLIENT_HELLO_RETRY (e.g. to perform async cert generation or key lookup), OpenSSL's SSL_accept() returns SSL_ERROR_WANT_CLIENT_HELLO_CB. Today, AsyncSSLSocket doesn't recognize this error code — it falls through to the generic error path and kills the connection with a handshake failure, even though the handshake is intentionally paused and expected to resume.

This diff adds handling for SSL_ERROR_WANT_CLIENT_HELLO_CB following the same pattern already used for SSL_ERROR_WANT_ASYNC: transition to STATE_ASYNC_PENDING, unregister event handlers, and wait for the caller to resume via restartSSLAccept().
Without this, any use of the OpenSSL client hello callback's async/retry mechanism is incompatible with AsyncSSLSocket.
