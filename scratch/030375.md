Commit title: Handle non-2xx HTTP response status in HTTPClientChannel
Commit body:
Summary:
HTTPClientChannel was not checking HTTP response status codes, allowing non-2xx responses (like 4xx or 5xx errors) to be processed as successful responses. This caused issues where HTML error pages from proxies would be deserialized as Thrift responses, resulting in confusing errors like:

```
E0211 11:07:04.390982 1830203392 EnvelopeUtil.h:86] Unknown protocol: <
E0211 11:07:04.394377 1830203392 RequestCallback.cpp:41] Couldn't parse envelope, would serialize the exception with 2
```

This aligns HTTPClientChannel with the behavior in SingleRpcChannel, which explicitly handles HTTP status validation.

Also simplified the error message formatting for empty HTTP responses.
