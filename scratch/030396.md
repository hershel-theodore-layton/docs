Summary:
A conservative version of D92444327 (check summary for context)

Use co_awaitTry in collectAllTryRange to avoid exception unwinding overhead when collecting results into folly::Try. co_awaitTry captures errors directly via await_resume_try() instead of throwing and catching, which is significantly faster on the error path (~19-38x in benchmarks) with no overhead on the success path.

A compile-time has_co_awaitTry_v detection trait gates the optimization: awaitables that support co_awaitTry use the fast path, while others fall back to the original try/catch pattern. This ensures backward compatibility with any SemiAwaitable type that doesn't yet support co_awaitTry.
