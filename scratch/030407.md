Commit title: psp: Close underlying socket on errors/cancelations
Commit body:
Summary:
If we are performing a PSP handshake (represented by an AsyncPSPUpgradeFrame)
and the caller wants to cancel the operation (e.g. due to a timeout), we need
to ensure that the cancellation occurs synchronously with respect to destroying
the AsyncPSPUpgradeFrame.

Any outstanding I/O we are performing must be canceled. Reads are event driven,
so unsubscribing from the read callback (which was done prior to this diff) is
sufficient.

However, AsyncSocket does not allow cancellation of queued writes. Once a write
has been enqueued into AsyncSocket, there is a pending reference to the
WriteCallback (AsyncPSPUpgradeFrame) which will only be fired upon write
completion. This diff explicitly closes the socket during any terminal error
case in order to ensure that that pending writecallbacks do not outlive the
AsyncPSPUpgradeFrame.

This is also the correct thing to do semantically as well. Cancelling the PSP
upgrade before completion puts the underlying socket in an nondeterministic
state (have we already written the first SA? have we already rx_assoc'd?). The
only safe thing to do would be to explicitly destroy the socket, to prevent
the application from acting on a socket that is not considered "established".
