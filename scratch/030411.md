Commit title: Fix double sqlite3_step() in SQLite3Stmt::execute()
Commit body:
Summary:
SQLite3Stmt::execute() called sqlite3_step() followed by sqlite3_reset(), and SQLite3Result::fetcharray() called sqlite3_step() again. This caused every SELECT query to execute twice when using the standard execute()->fetcharray() pattern, since the first step's result was immediately discarded by the reset.

Fix by buffering the first-row state in SQLite3Result. When execute() steps to SQLITE_ROW, skip the reset and set m_first_row_buffered. On the first fetcharray() call, read from the already-positioned cursor instead of calling sqlite3_step() again. The SQLITE_DONE path (write queries) is unchanged.

Also adds sqlite3_reset() at the top of execute() to ensure clean cursor state when execute() is called again without an explicit reset(), which was previously broken.
