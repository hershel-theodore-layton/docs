Commit title: Consolidate surprise flags into StackLimitAndSurpriseFlags
Commit body:
Summary:
Consolidate the free-standing surprise-flag helper functions (setSurpriseFlag, clearSurpriseFlag, getSurpriseFlag, checkSurpriseFlags, fetchSurpriseFlags) into a StackLimitAndSurpriseFlags struct that wraps the combined stack-limit/surprise-flags atomic word.

This is a pure structural refactoring with no behavior change. The struct lives in surprise-flags.h and inverts the previous dependency (surprise-flags.h no longer includes rds-header.h; instead rds-header.h includes surprise-flags.h). A global accessor stackLimitAndSurprise() in rds-header.h returns the struct, and all call sites now use member functions through it.

Key design decisions:
- m_value (the raw atomic word) is private; typed helpers (setFlag, clearFlag, getFlag, hasSurprise, fetchFlags, clearFlags) replace direct atomic access
- initialize(stackLimit) replaces the raw store and asserts the stack limit has no surprise-flag bits
- FlagSaver is an RAII helper for temporarily masking flags (replaces manual fetch_and/SCOPE_EXIT/fetch_or)
- valueOffset() exposes the offset of m_value for the JIT's kSurpriseFlagsOff computation
- hasSurprise() (was checkSurpriseFlags) is named to remain accurate after a follow-up diff that will move flags to a separate 64-bit field

Preparatory refactoring for expanding beyond 16 surprise flags.
