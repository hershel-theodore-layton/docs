Commit title: Populate aliased exception metadata
Commit body:
Summary:
When an exception is `typedef`ed and then used as a declared exception for a
function,
```
exception Exception {}
typedef Exception ExceptionAlias

service Service {
  void foo() throws (1: ExceptionAlias ex);
}
```

the exception is not added to the `ThriftMetadata::exceptions` map returned by
`getThriftServiceMetadata`, however, it is added to the
`ThriftService::functions::exceptions` exception list for the function.

This is because the check to determine whether the exception has structured
metadata, and thus whether it should be added to `metadata.exceptions`, is
based on whether the immediate type is structured. Because the immediate type
is `Kind::TYPEDEF`, not `Kind::EXCEPTION`, this condition fails. Logically, it
makes sense for the underlying exception to be added to `metadata.exceptions`,
even when referenced by `typedef`, so this diff ensures that it is by checking
if the underlying or "true" type is structured, instead of the immediate type.
