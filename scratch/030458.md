Commit title: Introduce scaffolding for PSP negotiation (server side)
Commit body:
Summary:
This diff includes some mechanical changes necessary in order to begin negotiating PSP on Thrift server connections.

The overall negotiation is done over TLS, along with the other post-handshake protocols (e.g. StopTLS)>

The Thrift extension is augmented to include a `pspUpgradeProtocol` uint64_t, representing a bitmask of supported PSP negotiation protocols. The client will advertise a list of supported "PSP negotiation protocols" through corresponding bits, and the server shall choose one. The server chooses the highest set bit (highest version) that it shares in common with the client.

PSPNegotiationPolicy is intended to be a function that can be configured on the ThriftParametersContext to determine which versions the current client/server supports. It is parameterized by the "peer address", as we do expect the available PSP negotiations to change _based on_ the address of the peer. For example, a possible negotiation policy could be to query the route used for the peer address to determine the corresponding network device and to only advertise PSP support if the network device indicates it)
