Commit title: Fix SIGSEGV crash in OmniClient destructor
Commit body:
Summary:
Fixes a SIGSEGV crash in `OmniClient::~OmniClient()` that occurs when calling `eb->runInEventBaseThread()` on an EventBase that has already been destroyed.

The crash was reported in T256278681 with the following stack trace:
```
@ folly::EventBase::runInEventBaseThread(folly::Function<void ()>)
@ apache::thrift::python::client::OmniClient::~OmniClient()
```

**Root Cause:**
The destructor used `eb->runInEventBaseThread()` which can crash if the EventBase has been destroyed before the OmniClient destructor runs.

**Fix:**
Replace with the safer `folly::getKeepAliveToken(eb).add()` pattern. This pattern is already used in `OmniInteractionClient::terminate()` in the same file (lines 530-543). The `getKeepAliveToken()` returns a null token if the EventBase is being destroyed, and `.add()` on a null token simply doesn't execute the callback, avoiding the crash.
