Commit title: update mtimes of all files and folders related to a saved state on load
Commit body:
Summary:
This diff is part of a workaround for the problem described in T255951179. The bug is currently triggered when `tmpwatch` deletes parts of a saved state, but not the entire folder. The general workaround is that instead of relying on `tmpwatch` to delete saved states, we use our own cleanup mechanism in `State_cleaner` more aggressively.

This diff prepares this by modifying the `mtime` of any file associated with a saved state we load. We do this because `State_cleaner` uses the `mtime` of one of those files to decide what to delete. But touching all files seems like a good idea anyway, and is what an existing comment in `load_internal` already suggested anyway.

Concretely, for an example saved state named `hack_saved_state_tree_hack_64_distc_a2de6bb8b6b2c4ad8d68f3d28841fa9052985bc6_626c442dca84befca1d0faddf36ea3116d366242-ab2480741218c829126c7e9785f0a7d6e00c4b65-00` the mtimes of the following are updated on every load now:
- File`hack_saved_state_tree_hack_64_distc_a2de6bb8b6b2c4ad8d68f3d28841fa9052985bc6_626c442dca84befca1d0faddf36ea3116d366242-ab2480741218c829126c7e9785f0a7d6e00c4b65-00_info` (note the trailing _info). This is the main change to make `State_loader` discard the least recently *used* instead of least recently *created* saved state.
- Inside the folder `hack_saved_state_tree_hack_64_distc_a2de6bb8b6b2c4ad8d68f3d28841fa9052985bc6_626c442dca84befca1d0faddf36ea3116d366242-ab2480741218c829126c7e9785f0a7d6e00c4b65-00`. These changes are just for consistency (as suggested by the comment already in `load_internal`).
  + The folder itself. This was previously implicitly updated only on creation.
  + Files `hh_mini_saved_state`{`_64bit_dep_graph_decompressed.hhdg`, `_64bit_dep_graph.zhhdg`, `.err`, `_naming.sql`}. Previously these were just updated on creation.
  + Files`hh_mini_saved_state.err.json` and `hh_mini_saved_state_info.json`. Previously their mtimes were never updated, due to the corresponding names missing from `fillenames` (as mentioned in T255951179)
