# Facebook
This adds an integration test for `hh_server --with-mini-state`. I noticed that we currently have no tests for it at all. In D93226858 I'm deliberately breaking it, but all tests still pass.

There are only two interesting things to note:
- We need to get a suitable saved from somewhere, so we actually create one ourselves using `hh_distc` (but in local execution mode, no RE is used). This means we actually test the whole saved state creation -> consumption pipeline!
- The setting `require_saved_state` is supposed to make `hh_server` exit if saved state loading fails. That part works, but it's surprisingly tricky to test: If saved state loading does fail and `hh_server` exits (as instructed), then just invoking  `hh_client` afterwards without further arguments acts surprisingly: It will start a new server, and in the absence of both`--with-mini-state` and `--config load_state_natively_v4=true`, that server is allowed to do a full init despite `require_saved_state` being set. To avoid this, I changed the test harness so that `start_hh_server` does not always do `hh_client`. Instead, we run it ourselves, but with `--autostart-server false`.
