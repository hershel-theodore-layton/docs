Commit title: Mustache-to-Whisker migration: adapter context to computed properties
Commit body:
Summary:
Move adapter generation logic from recursive Mustache templates to computed C++ functions in the generator. This replaces the mstch `adapter_node()` context-switching pattern with simple string properties on Whisker prototypes.

Added `compute_adapter_name()` and related functions that replicate the logic of `lib/adapter/name.mustache` in C++

Added Whisker properties: `has_adapter?`, `adapter_name`, `adapter_qualified` on t_type/t_typedef/t_field/t_structured prototypes, plus `adapter_struct_qualified` on t_field and `adapter_transitive_only?` on t_typedef.

Converted adapter template tags from mstch context-switching (`{{#type:has_adapter?}}{{> lib/adapter/qualified}}{{/type:has_adapter?}}`) to Whisker syntax (`{{#if type:has_adapter?}}{{type:adapter_qualified}}{{/if type:has_adapter?}}`).

Removed `adapter_node()`, `rust_mstch_type`, `rust_mstch_typedef` classes, and `has_adapter` methods from `rust_mstch_struct`/`rust_mstch_field`. Deleted 3 adapter partial templates: `name.mustache`, `qualified.mustache`, `struct.mustache`.
