Commit title: Optimize simplejson protocol deserialization with memchr
Commit body:
Summary:
Optimize the simplejson Thrift protocol deserializer by leveraging the memchr crate for faster byte seeking operations. This change uses a **hybrid approach** that combines fast paths for short strings with SIMD-accelerated scanning for longer strings.

## Changes:
- Added memchr dependency to BUCK file
- Optimized 4 critical deserialization functions with hybrid fast-path/SIMD approach:
  1. **strip_whitespace()** - Check first 8 bytes inline, then continue scanning if needed
  2. **read_json_number_string()** - Use memchr for quoted numbers, chunked scanning for unquoted
  3. **read_string()** - Check first 32 bytes inline for common field names, then use memchr2 (HOT PATH)
  4. **read_binary()** - Use memchr for closing quote

## Hybrid Approach:
The implementation balances two competing concerns:
- **Short strings** (field names like "field_1" to "field_99"): Simple inline loops avoid SIMD setup overhead
- **Long strings** (base64 data, large text): SIMD instructions (AVX2/SSE2) process multiple bytes per cycle

This gives us the best of both worlds - fast paths for common cases and SIMD acceleration for heavy lifting.

The optimizations are particularly beneficial for:
- Long strings with many characters
- Base64-encoded binary data
- Documents with lots of whitespace
- Large JSON payloads
