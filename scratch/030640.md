Commit title: Use precise variance for type parameters occuring in class refinements
Commit body:
Summary:
Currently our function pointer typing treats type parameters occuring inside class refinements as though they occur invariantly. This diff aims to be more precise and further simplify the function types we produce and avoid first-class polymorphic types wherever possible.

We can look at class (or type constant) refinements as existentially quantfied types. Given an abstract class with an abstract type constant

```
abstract class WithTypeConst {
  abstract const type T;
}
```

The hint `WithTypeConst` can be read as `∃ T. WithTypeConst with { type T }`. Class refinements with bounds can also be understood in this way:

```
WithTypeConst with { type T as X } === ∃ T as X. WithTypeConst with { type T = TC }
WithTypeConst with { type T super X } === ∃ T super X. WithTypeConst { type T = TC }
```

Finally class refinements with equality is existential elimination:

```
WithTypeConst with { type T = X }
```

The variance of `X` in each existential is the dual of it universal counterpart, i.e.

#### Bounded Universal: `∀X≤S. T`

```
S₂ <: S₁      [X <: S₂] ⊢ T₁ <: T₂
──────────────────────────────────────
    ∀(X≤S₁).T₁  <:  ∀(X≤S₂).T₂
```

#### Bounded Existential: `∃X≤S. T`

```
S₁ <: S₂      [X <: S₁] ⊢ T₁ <: T₂
──────────────────────────────────────
    ∃(X≤S₁).T₁  <:  ∃(X≤S₂).T₂
```

Using this duality, the diff updates the type parameter variance analysis so that type parameters occurring in refinements are given the correct polarity
