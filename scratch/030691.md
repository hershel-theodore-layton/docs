Commit title: Migrate split-mode properties to Whisker, remove rust_mstch_program
Commit body:
Summary:
Migrate the 5 remaining split-mode properties (type_splits, types_with_constructors, current_split_structs, current_split_typedefs, current_split_enums) from rust_mstch_program to Whisker prototypes on t_program, and remove the rust_mstch_program class entirely.

The key insight is that per-instance split_id_ state (previously requiring a new rust_mstch_program object per split) can be replaced by mutable current_split_id_ on the generator class, set before each render call. Whisker property lambdas evaluate lazily, reading the current value at render time, so the same cached_program() object can serve different split renders.

The split computation logic (initialize_type_split + generate_split_data + generate_reference_set) is consolidated into a single initialize_type_splits() method on the generator class, using a recursive lambda for the reference set traversal.
