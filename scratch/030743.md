Commit title: Add optional ValidationCallbacks to deserializeValue
Commit body:
Summary:
Add a template Callbacks parameter to deserializeValue and its internal deserialize overloads. The default (ThrowingValidationCallbacks) preserves today's behavior. Custom callbacks receive notifications for unknown fields, type mismatches, and multiple union fields. When a callback does not throw, the problematic data is skipped and deserialization continues.

The ValidationCallbacks concept requires three methods:
- onUnknownField: called when a field ID/name is not found in the schema
- onTypeMismatch: called when wire type doesn't match the schema's expected type
- onMultipleUnionFields: called when a union has more than one field on the wire

Skip-and-continue semantics when a callback doesn't throw:
- Unknown field: data consumed by the callback via reader.skip()
- Type mismatch on struct/union field: mismatched field skipped, field retains default
- Type mismatch on container element: entire container skipped, returned empty
- Multiple union fields: remaining fields drained via reader.skip() loop
