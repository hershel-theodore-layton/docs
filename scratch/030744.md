Commit title: Add peekValueTType and type-check container elements for SimpleJSON
Commit body:
Summary:
SimpleJSON omits container element types on the wire (kOmitsContainerElemTypes), so type mismatches in map/list/set elements were only caught when the read function threw, producing a generic deserialization error instead of a specific type mismatch callback. This adds a peekValueTType() method that inspects the next JSON value's leading character without consuming data, and uses it in the container deserialization paths to detect and report type mismatches before attempting to deserialize.

Changes:
- JSONProtocolCommon.h: Add peekValueTType() to JSONProtocolReaderCommon and isJsonTypeCompatible() free function that maps JSON types to compatible Thrift types (e.g. JSON numbers are compatible with all numeric Thrift types, JSON objects with maps, JSON arrays with sets).
- JSONProtocolCommon-inl.h: Implement peekValueTType() by saving/restoring all reader state (cursor, context meta, skip-tracking), advancing past context separators and whitespace, then peeking at the leading character to determine the JSON value type.
- Serialization.h: In the kOmitsContainerSizes() deserialization paths for map, list, and set, peek at element types before deserializing. On mismatch, report via callbacks.onTypeMismatch and skip the element.
- JSONProtocolCommonTest.cpp: Add tests for peekValueTType (all JSON value types, whitespace handling, non-consumption) and isJsonTypeCompatible (exact matches, T_VOID passthrough, numeric compatibility, struct/map and list/set compatibility, incompatible types).
