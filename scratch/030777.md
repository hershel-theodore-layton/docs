Commit title: Fix package_allow_all_generics_violations enabling errors on decl-level generics
Commit body:
Summary:
Bug: package_allow_all_generics_violations was erroring on ALL generic type arguments when set to false, including generics in implements, extends, use, type annotations, etc. It should only error on explicit generics in function calls, method calls, and new expressions.

Root cause: There are two code paths that check this flag:
  1. typing_type_integrity.ml:check_targ_well_formed - handles type argument well-formedness during declaration-level type walks (covers implements, extends, type annotations, etc.)
  2. typing_phase.ml:localize_targ - handles explicit type arguments specifically for "constructors or functions" (covers new Foo<T>(), bar<T>(), $obj->method<T>()).

Of the above, both had the package_allow_all_generics_violations check, but only path #2 should have it.

Fix (typing_type_integrity.ml): Removed the package_allow_all_generics_violations branch from check_targ_well_formed. This function now only checks reified generics (gated by package_allow_reified_generics_violations). Non-reified generics in declaration positions are no longer flagged.
Additionally, the package_allow_all_generics_violations check in localize_targ now only fires when tparam is Some _. This function is called from two contexts:
  - localize_targs (plural) — for explicit type arguments on function calls, method calls, and new expressions. These always pass ~tparam for each targ, so the check still applies.
  - Collection literal wrappers (vec<Foo>[], dict<K,V>[], keyset<T>[]) — these call localize_targ without ~tparam (it defaults to None), so the check is now skipped
