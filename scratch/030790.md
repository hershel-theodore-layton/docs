Commit title: Guard structDictTypeBoundCheckReturn against union type bounds
Commit body:
Summary:
When `StructDictTypeBoundCheck` has a non-const slot index (i.e., the dict key
isn't a constant string or the layout isn't concrete), `getTypeBound(Type slot)`
falls through to `getUnionTypeBound()`, which unions ALL field type bounds
(e.g., `TInt | TStr`). This multi-DataType union then flows into
`structDictTypeBoundCheckReturn()` → `Type::operator&` → `Type::operator<=`,
which asserts `!rhs.isUnion()`.

**Debug builds** (`profiled`, no `packedptr`): Hit the assertion cleanly (SIGABRT).
**Release builds** (`packedptr_profiled`): Assertion compiled out → silently
proceeds with corrupted type info → diverse downstream crashes in
`simplifyPass`, `reflowTypes`, `jemalloc`, etc.

The fix mirrors what `simplifyStructDictTypeBoundCheck` already does at
`simplify.cpp:4173`: bail out when the union type bound isn't a known single
DataType. In `structDictTypeBoundCheckReturn`, instead of bailing we return the
value's type unrefined (no narrowing), which is the conservative-correct
behavior for return type prediction.

**Impact**: ~1,321 coredumps across www_thrift over 6 days (Feb 18-24), all
triggered by `EntZippyDBSingleKeyCrossPlatformValueSerializer::coerceAttributes`
causing struct dict lookups with non-const keys. 85% of crashes were in
`packedptr_profiled` (production release) builds with diverse signatures; 2%
were clean assertion failures in debug builds — connecting the two was the key
to root cause.
