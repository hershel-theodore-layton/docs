Commit title: AsyncSocketTransport: take pre-bound fd in connect()
Commit body:
Summary:
Add a new param `boundFd` to `connect()`, which is a sockfd that already called `bind()`. The current AsyncSocket API does not allow such a fd to be used.

Users can either pass in a sockfd that is already connected. Or they can pass in a `bindAddr` to `connect()`, and AsyncSocket will create a fd and `bind()` to it in `connect()`.

# Why
For Thrift client zero copy receive.

Zero copy receive works by hashing special flows identified by its 5-tuple into special NIC hardware queues that are configured for zero copy. Each NIC hardware queue is bound to an EventBase. Sockets configured for zero copy have its flow steered into a specific queue X, and this socket must then be processed on EVB Y that is tied to queue X.

This is easy on the server side that is listening and accepting connections. At the point of accept(), we know which queue the flow is hashed to. AsyncServerSocket uses a separate EVB anyway, so dispatch the accepted the socket to the right target EVB.

This is hard on the client side that has to connect() to a server. Before connect() succeeds and at least 1 packet has been received from a server (SYN-ACK usually), clients do NOT know which queue the flow will has to. This means creating a client socket is a two step process: create socket, connect(), find which queue it got hashed to, then move the socket (via detach/attach) to the target EVB. Annoying to do.

An alternative is to find a hash collision by varying the src port. tl;dr is this let us find src ports that will hash the flow to the desired queue, avoiding moving the socket between EVBs.

Of course, these computed src ports may be in use already. So we have to try to bind() until it succeeds.

Hence this diff is needed to let us pass a bound fd into AsyncSocket.

Make changes to AsyncSocketTransport (used by both AsyncSocket and AsyncIoUringSocket), and then implement it in both.
