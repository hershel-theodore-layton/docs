Commit title: Fix recursive case type expansion soundness via under_type_constructor flag
Commit body:
Summary:
# Context

When a recursive case type like `case type CT = vec<CT> | int` is expanded, the type argument `CT` inside `vec<CT>` hits the cycle detection in `add_type_expansion_check_cycles` and gets replaced with `mixed`, yielding `vec<mixed> | int`. This makes `vec<Bar> <: CT` succeed for any `Bar`, because the subtyping check reduces to `Bar <: mixed` which always holds. This is a soundness bug: `vec<Bar>` should only be a subtype of `CT` when `Bar` is itself a subtype of `CT` (i.e., `Bar` is `int`, `CT`, or `vec<CT>`).

The root cause is that cycle detection unconditionally collapses the recursive reference to `mixed`, losing the identity of the case type. When the recursive reference appears *inside* a type constructor like `vec<_>`, we need to preserve the `Tnewtype` wrapper so that subtyping through the constructor's type parameters remains sound. When the recursive reference appears *bare* at the top level of a typedef body (e.g., `case type A as A = int`), collapsing to `mixed` is correct and necessary for proper error reporting.

# Solution

A boolean field `under_type_constructor` is added to `expand_env` (`ety_env`). This flag controls what the `Error cycle` branch in `expand_typedef_` returns when a recursive case type reference is detected:

- **Flag is `true`**: Return `Tnewtype(x, argl, mixed)` for case types, preserving the type's identity inside the constructor. For simple typedefs, still return `mixed`.
- **Flag is `false`**: Use the existing `visibility_behavior`-based logic. `Always_expand_newtype` returns `Tnewtype` (needed for wellformedness checks); all other modes return bare `mixed`.

The flag is set to `true` in `typing_phase.ml` when localizing sub-types of **type constructors** — types where the inner type is structurally guarded by the outer constructor:

| Type form | Sets flag? | Rationale |
|---|---|---|
| `Tvec_or_dict` | Yes | Built-in container |
| `Ttuple` | Yes | Structural container |
| `Tshape` | Yes | Structural container |
| `Tclass_ptr` | Yes | `class<T>` is a container |
| `Tfun` | Yes | Guards params/return covariantly and contravariantly |
| `Tapply` → class | Yes | `vec<T>`, `Map<K,V>`, etc. |
| `Tapply` → typedef | Yes | Conservatively yes — type args are localized *before* the typedef body is expanded, so a typedef like `type Box<T> = vec<T>` needs the flag since the cycle is detected before Box expands to `vec<T>` |
| `Toption`, `Tlike` | No | `?T` and `~T` are unions, not containers |
| `Tunion`, `Tintersection` | No | Don't guard their members |
| `Taccess`, `Trefinement` | No | Projection/constraint, not containers |

The flag is reset to `false` in `expand_typedef_` before localizing the typedef's RHS and constraint (via `ety_env_inner`), so that bare recursive references at the top level of a typedef body still produce `mixed` with proper `illegal_recursive_type` error messages.

No new cycle-tracking mechanism is introduced. The existing `add_type_expansion_check_cycles` catches all cycles as before; the only change is what we *return* on cycle detection in type-arg positions.

### Example trace: `case type CT = vec<CT> | int`

1. `expand_typedef_("CT")`: chain `[]` → add CT → `[CT]`. Ok.
2. Reset flag to `false` for RHS/constraint localization.
3. Localize RHS `vec<CT> | int` with `under_type_constructor = false`:
   - `vec<CT>`: class `vec`. Type arg CT → set flag to `true`.
   - `expand_typedef_("CT")`: chain `[CT]` → CT in chain → **Error cycle**.
   - Flag is `true`, CaseType → return `Tnewtype(CT, [], mixed)`.
   - Result: `vec<Tnewtype(CT, [], mixed)>`
   - `int` → `int`
4. Final: `vec<Tnewtype(CT, [], mixed)) | int`

Now `vec<string> <: CT` → expand CT → `vec<Tnewtype(CT, [], mixed)) | int` → `vec<string> <: vec<Tnewtype(CT, [], mixed)>` → `string <: Tnewtype(CT, [], mixed)` → expand CT → `string <: vec<...> | int` → **correctly fails**.

### Self-recursive bounds: `case type A as A = int`

- `expand_typedef_("A")`: chain `[A]`. Ok. Reset flag for constraint.
- Constraint `A`: flag = `false`. Cycle → `mixed` with `illegal_recursive_type`. **Unchanged**.
