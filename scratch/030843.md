Commit title: Add [@@oxidize.exclude] annotation support to hh_oxidize
Commit body:
Summary:
# Context

The `hh_oxidize` tool generates Rust type definitions from OCaml source. OCaml's `ty_` is a GADT with two phases: `decl_phase` (types as declared in source) and `locl_phase` (types after localization/inference). The oxidizer currently ignores GADT return types (`pcd_res`), flattening all constructors into a single Rust `Ty_` enum. Since Rust only needs decl types, the locl-only constructors and their supporting types are dead code that creates unnecessary coupling.

The existing mechanism for suppressing types is a hardcoded denylist in `convert_type_decl.ml`. This works but doesn't handle GADT variant filtering — even when a type like `locl_phase` is denylisted, constructors returning `locl_phase ty_` are still generated.

# Solution

Add a general-purpose `[@oxidize.exclude]` annotation that provides two behaviors:

1. **Type exclusion**: Types annotated with `[@oxidize.exclude]` are recorded as excluded and skipped during Rust codegen.

2. **GADT variant filtering**: When processing a GADT variant, if `pcd_res` (the return type annotation) instantiates a type parameter with an excluded type, that variant is silently filtered out. For example, `Tvar : Tvid.t -> locl_phase ty_` is filtered because its return type instantiates `ty_`'s parameter with the excluded `locl_phase`.

The excluded types set is maintained per-file (reset between files in multi-file mode) and accumulates as type declarations are processed sequentially.

Annotated the following types with `[@oxidize.exclude]`:
- `typing_reason.ml`: `locl_phase`, `witness_locl`
- `typing_defs_core.ml`: `locl_phase`, `dependent_type`, `exact`, and the full type predicate cluster (`type_tag`, `type_tag_generic`, `shape_field_predicate`, `shape_predicate`, `tuple_predicate`, `type_predicate_`, `type_predicate`) — all dead code once `Tneg` is filtered

These annotations have no effect until `oxidized_regen` is run with the updated `hh_oxidize` (Diff 3).
