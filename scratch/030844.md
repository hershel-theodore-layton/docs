Commit title: Fix unsound Tany introduced by type constant propagation to `mixed` upper bounds.
Commit body:
Summary:
When a type variable with type constants, created by type access on a type parameter in a `where` clause, gains another type variable as a lower bound, `add_tyvar_type_const` propagates the type constants to the new lower bound's variable.

The transitive step then iterates over that variable's upper bounds, expanding `bound::type_const` for each.

When the upper bound is `supportdyn<mixed>`, expanding `supportdyn<mixed>::TR` unwraps to `mixed::TR`, which hits the catch-all in `typing_taccess.ml` that returns `Missing` and creates `Tany`.

This `Tany` then pollutes the type constant tyvar's bounds, causing all related type variables to solve to `Tany`.

The fix adds a `bound_is_mixed` check in `add_tyvar_type_const` to skip upper bounds that are `mixed` or `supportdyn<mixed>` when propagating type constants. This mirrors the existing `is_mixed` short-circuit already present in `make_all_type_consts_equal` for lower bounds.
