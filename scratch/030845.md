Commit title: Add RFC 9298 CONNECT-UDP support
Commit body:
Summary:
Implement RFC 9298 (CONNECT-UDP) alongside the existing legacy CONNECT-UDP
method. The RFC approach uses Extended CONNECT (`:method=CONNECT`,
`:protocol=connect-udp`) with `https` scheme, URI template-based paths, and
`Capsule-Protocol: ?1` headers. A backward-compatible `rfcMode_` flag
preserves existing internal behavior.

Key changes:

- **ConnectUDPUtils** (new): URI template expansion (RFC 6570 Level 3) with
  IPv6 percent-encoding, and context ID prepend/strip helpers for RFC 9298
  datagram framing.

- **HTTPTransaction**: Add `connectUdpStream_` bit flag (same pattern as
  `wtConnectStream_` for WebTransport) to detect Extended CONNECT with
  `:protocol=connect-udp` on a per-stream basis.

- **HQSession**: Skip session-layer context ID encoding/decoding for
  `connectUdpStream_` streams (context IDs are an application-layer concern
  per RFC 9297, not base H3 datagram framing). Replace ENABLE_CONNECT_PROTOCOL
  TODO with logging.

- **H3DatagramAsyncSocket**: When `rfcMode_=true`, use QUIC v1 (not MVFST),
  send `_HQ_DATAGRAM_RFC` (0x33) + `ENABLE_CONNECT_PROTOCOL` settings, set
  `Capsule-Protocol: ?1` header, and handle context ID 0 framing in
  write()/onDatagram().

- **Forward proxy**: Update `isRequestConnectUDP()` to recognize Extended
  CONNECT, update `isRequestHTTPConnect()` to exclude it. Extract target
  host/port from URI path query parameters for RFC 9298 requests. Add context
  ID handling in `ProxyConnectUDPHelper` when `rfcMode_`.

- **H3DatagramClient**: Add `--masque_template` flag for RFC 9298 mode.

- **MasqueClient** (new): Standalone interop binary for testing against
  masque-go (or any RFC 9298 proxy). Sends random payload through tunnel and
  verifies echoed response.
