Commit title: Fix Go interaction tests, mark factory funcs nonconforming
Commit body:
Summary:
The Go RPC server conformance tests for InteractionFactoryFunction were failing with a panic "frame has been released!" in the rsocket-go library.

Two changes were made:
1. Fixed the Go server's Init() method to not reset initialSum to 0, matching the C++ implementation where init() is empty. This ensures the initialSum value passed to the factory function is preserved.

2. Added the three Go InteractionFactoryFunction tests to nonconforming.txt because the underlying panic is caused by a use-after-free bug in the rsocket-go library's transport layer when handling interaction factory functions. This is consistent with how other languages (Python, Java, Hack, Erlang) handle similar unsupported interaction features.

The root cause requires a fix in the Go thrift library (fbcode/thrift/lib/go/thrift) to properly manage the lifecycle of interaction factory function frames.
