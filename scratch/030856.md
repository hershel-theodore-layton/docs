Commit title: Allow partitioning of CH tiers
Commit body:
Summary:
Allow `SRRoute` to target a subset of hosts in a CHRH tier via two new settings:
| **Setting** | **Description** |
|`partition_start`| The //server_id// [*] of the first host in the partition |
| `partition_size` | Number of hosts in the partition |

[*] ServiceRouter expects each host in a Ucache CH tier to define a //server_id// SMC property (aka DP Replica ID) ranging from [0, N), where N is the number of hosts in the tier. ServiceRouter expects //server_id// values to be unique within the tier. There should be no gaps.

If `partition_size` is 0, all hosts having //server_id// >=`partition_start` will be targeted.

If `partition_size` exceeds the number of available hosts, the effective partition size will be automatically adjusted as appropriate.

Example: Route to servers with //server_id// in the range [10,100):
```
"route" {
  "type": "SRRoute",
  "service_name": "ucache.prod.frc.0.dp",
  "set_routing_key": true,
  "partition_start": 10,
  "partition_size": 90
}
```

IMPORTANT:  Tier partitioning should only be used with CHRH tiers. For this reason, we require `set_routing_key` when partitioning is enabled.
