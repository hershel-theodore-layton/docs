## Problem

Thrift servers configured with `setAllowPlaintextOnLoopback(true)` fail to accept plaintext connections from localhost on ondemands. This causes SSL/TLS errors like "Connection reset by peer" when services try to communicate locally without TLS.

See [this post](https://fburl.com/workplace/zpwwjoal) for some real world examples.

## Root Cause

Ondemands use IP-Per-Task (IPT) networking, which redirects loopback addresses (`::1`) to ILA (Identifier Locator Addressing) addresses via BPF hooks. This happens transparently at the kernel level:

1. Server binds to `::1` → Kernel redirects to ILA address (e.g., `2401:db00:eef0:1100::abc`)
2. Client connects to `::1` → Kernel redirects to the same ILA address
3. From the application's perspective, both client and server see the ILA address, not `::1`

In `Cpp2Worker::shouldPerformSSL()`, the loopback check used `clientAddr.isLoopbackAddress()` which only recognizes standard loopback addresses (`::1`, `127.0.0.1`). Since the client address appears as an ILA address (not `::1`), the check fails and the server incorrectly requires TLS for what is actually a local connection.

## Solution

Implemented a pluggable function pattern to extend loopback detection:

1. **Cpp2Worker.h/cpp**: Declares and registers a pluggable function `isEffectivelyLoopbackAddress()` with a default implementation that only checks standard loopback addresses. This maintains backward compatibility for non-Meta environments.

2. **TransportMetadata.cpp**: Provides a Meta-internal override that uses `LocalhostUtil::isLocalhost()` to recognize ILA addresses. This function explicitly knows which IP addresses belong to the local machine, including ILA addresses on OnDemand servers.
