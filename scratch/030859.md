Commit title: add memory usage metric for zstd compression workplace
Commit body:
Summary:
Axon today shows 80-90% heap memory usage not tracked by metrics, so we don’t know where it’s used. Profiling on big1 revealed one main gap is zsd compression. Add a metric to track memory usage there.

Compared to the [profile](https://fburl.com/scuba/heap_profiles/on_demand/ya2ztg59), the estimate is about 20% higher, because:

- The estimate uses `ZSTD_estimateCStreamSize(level)`, which gives a conservative upper bound for capacity planning (worst-case internal buffer sizes).
- Actual allocation (`ZSTD_sizeof_CCtx` / heap profile) is lower, since ZSTD doesn't always allocate the maximum workspace predicted.

Alternative approaches not pursued:
1. **Probe-based measurement:** Create a temporary `ZSTD_CCtx`, trigger allocation with minimal compression, then query actual size via `ZSTD_sizeof_CCtx()`. Not used—workspace is deterministic per compression level, so result is a constant (just like the estimate), only slightly more accurate. with added complexity.

2. **Per-leader real memory tracking via folly:** Add a `memoryUsage()` API to folly's `StreamCodec` to expose `ZSTD_sizeof_CCtx()` per codec. Not used—folly's `ZSTDStreamCodec` returns the `ZSTD_CCtx` to the global pool after each frame, so method would return 0 between compressions. Would also require broader folly code changes.
