Commit title: jit support for CallFuncEntry calling convention of basic named param calls
Commit body:
Summary:
The func entry calling convention of calls with named params is quite simple in the absence of optional named args. Since HackC already orders args so that named ones are sorted and precede positionals, the VM stack is already arranged the way the relevant func entry expects.

Thus, in the prepareAndCallKnown case, all we need to do is insert compile-time checks that look at namedArgNames and compare it to the parameters, raising the appropriate warning as applicable. Otherwise just call the func entry normally, no extra registers. The generated code is then equivalent to all parameters being passed positionally in the happy path :)

One note is that prepareAndCallKnown with packing punts to a repacking prologue. We need to interpret that until we get prologues translated properly.
