Commit title: Improve error message for package violations in type constants
Commit body:
Summary:
The error message for package boundary violations within type constants was confusing:
1. It said "Cannot access type constant `MyInternClass`..." but `MyInternClass` is not a type constant — it's the type being referenced within the type constant definition.
2. For reifiable type constants, the error didn't show the position of the `<<__Reifiable>>` attribute.

This diff fixes both issues:
- The message now uses "within a" phrasing for type constant contexts: "Cannot access `MyInternClass` defined in package `pkg2` which may not be available within a type constant" — correctly identifying the referenced type and the context it appears in.
- For reifiable type constants, a new reason line points to the `<<__Reifiable>>` attribute declaration.

Implementation: a new `\`YesTC` variant was added to `check_reason` to represent all type constant package checks (both reifiable and non-reifiable). It carries an optional `(Pos_or_decl.t * string)` for the reifiable attribute position and type constant name, which is `None` for non-reifiable type constants. This keeps the change minimal — only the type constant code path in `typing_type_wellformedness.ml` and the dispatch in `typing_visibility.ml` are affected, with no changes to unrelated call sites.
