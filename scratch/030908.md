Commit title: Add configurable log_dir to separate logs from state
Commit body:
Summary:
Watchman currently co-locates its log file with state files (socket, pid) in the
same directory. This is problematic for containerized dev environments where log
preservation requires bind-mounting a specific path.

This adds a new `"log_dir"` config key (in `/etc/watchman.json` or
`~/.watchman.json`) that allows storing logs in a separate directory from state.
When set, the log file is placed at `<log_dir>/<user>/log` instead of
`<state_dir>/log`.

Precedence (highest to lowest):
1. `--logfile` CLI flag (unchanged)
2. `"log_dir"` config key (new) -> `<log_dir>/<user>/log`
3. Default: `<state_dir>/log` (unchanged)

For container deployments, set `"log_dir": "/var/facebook/logs/watchman"` in
`/etc/watchman.json`, then bind-mount `/var/facebook/logs/<container_id>/` to
`/var/facebook/logs/` inside the container. All tools writing under
`/var/facebook/logs/<toolname>/` get log preservation through one mount point,
without per-tool configuration.
