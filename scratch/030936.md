Commit title: Platform-gate symbolizer dep in epitaph for Android SO packaging
Commit body:
Summary:
D92859914 added an unconditional dep on `folly/debugging/symbolizer` from `folly/result/epitaph`, pulling the symbolizer subgraph (libunwind, libdwarf) into the Android link closure.  This shifted SO module boundaries in the Messenger APK, causing `libmozjpegturbo.so` to end up in the wrong downloadable module and crash at startup with `UnsatisfiedLinkError`.

This is a packaging workaround — the symbolizer works fine on Android.  The fix gates the symbolizer dep via `select()` to exclude Android only, using a build-local `FOLLY_EPITAPH_USE_SYMBOLIZER` macro (defaults to 1 for CMake/OSS).  The `#include <folly/debugging/symbolizer/StackTrace.h>` in the header is replaced with a forward declaration of `getStackTrace`, kept in sync by a compile-time check in `stack_epitaph_test.cpp`.  Also uses `<folly/portability/SysTypes.h>` to fix `ssize_t` on Windows MSVC.

Also adds `EXTRA_TARGET_DEPS` to `generate_cmake.py` for deps inside `select()` that the regex parser can't see.
