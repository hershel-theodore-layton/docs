Commit title: Split into V1 and staging versions
Commit body:
Summary:
Split FindMyTests code within hh into two versions with separate CLI args and server commands:
- FindMyTestsV1 is just a copy of the current version of FindMyTestsStaging. Invoked via `--find-my-tests-v1` (the existing `--find-my-tests` is kept as a deprecated alias for this, since this is what we currently use in prod)
- FindMyTestsStaging is invoked via `--find-my-tests-staging`. Future development goes here.

The integration tests are refactored to run against both versions: `TestFindMyTests` tests staging, `TestFindMyTestsV1` inherits all test methods and runs them against V1. This makes it easy to skip certain tests on V1 in the future if they are only supported by the staging version.

I'm expecting that there will usually just be one stable version and the staging version around. Maybe two stable versions during a short period where a new stable version is branched off, but we still use the old one in prod. So the main raeson for naming what we now have "V1" instead of "Stable" is to make it more obvious what the current stable version is.
