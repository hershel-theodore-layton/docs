Commit title: fb_compact_serialize: add compact keyset encoding via FB_CS_EXT
Commit body:
Summary:
See S624340 for why this matters.

My high-level goal is to use `fb_compact_serialize` for SandboxCache serialization. I've crunched the numbers and the win for the more compact serialization format is pretty large: 30%~ smaller, 20%~ faster compression, 40%~ faster serialization, etc.

The problem is that we're missing two necessary features:
1. Keysets are serialized as dicts, which destroys the win for 40%~ of SandboxCache classes. They need to be serialized without duplicating the value.
2. We need `keepClasses` to preserve class pointers.

 ---

**This diff** improves handling for keysets. fb_compact_serialize currently encodes keysets as MAP with duplicated key=value pairs (e.g. keyset['a','b'] becomes MAP,'a','a','b','b',STOP), doubling their wire size. This adds a new FB_COMPACT_SERIALIZE_KEYSETS option flag to encode keysets compactly: EXT,EXT_KEYSET,values...,STOP.
