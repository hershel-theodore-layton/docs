Commit title: fb_compact_serialize: add keepClasses option via FB_CS_EXT
Commit body:
Summary:
See S624340 for why this matters.

My high-level goal is to use `fb_compact_serialize` for SandboxCache serialization. I've crunched the numbers and the win for the more compact serialization format is pretty large: 30%~ smaller, 20%~ faster compression, 40%~ faster serialization, etc.

The problem is that we're missing two necessary features:
1. Keysets are serialized as dicts, which destroys the win for 40%~ of SandboxCache classes. They need to be serialized without duplicating the value.
2. We need `keepClasses` to preserve class pointers.

 ---

fb_compact_serialize currently converts class and lazy class values to plain strings, losing the class type information on deserialization. This adds a new FB_COMPACT_SERIALIZE_KEEP_CLASSES option flag that uses the FB_CS_EXT extension mechanism to preserve class types: EXT,EXT_CLASS,<class_name_string>.

On deserialization, this produces a LazyClassData value, matching the behavior of serialize()'s keepClasses option. Without the flag, class values continue to be serialized as plain strings (legacy behavior)
