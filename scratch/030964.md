Commit body:
Summary:
HHBBC expects that closure classes have an owning context, which is tracked by the createClMap:

https://www.internalfb.com/code/fbsource/[19ee29873bb8a79fdf900e4abe0c73c31f559bdf]/fbcode/hphp/hhbbc/parse.cpp?lines=81-85

(see base of this stack and https://www.internalfb.com/code/fbsource/[cf6a417652ef3073a4893a6c3bddb2ca83c4d05b]/fbcode/hphp/hhbbc/check.cpp?lines=184)

The problem is, we run `closure_convert` to emit classes for lambdas first, but then we avoid emitting `CreateCl` ops when they're in the dead branches of conditional exprs. This is relevant to both ordinary closures, and the ones we emit for expression tree splices, which have an extra layer of indirection.

While we work out the correct contract between HackC and HHBBC, let's not crash for the most trivial of optimizations possible. Since this optimization is based on the `expr`, we can restore it by writing it as an elab pass over the AST that we sequence before closure_convert.
