Commit title: Fix storeUnaligned type mismatches caused by D94555197
Commit body:
Summary:
D94555197 changed `folly::storeUnaligned` to require an explicit type parameter
and added a static_assert to verify the type of the value matches the type param.
This caught type mismatches in two files where integer promotion caused the value
type to differ from the template parameter:

1. `BitVectorCoding.h`: When calling `storeUnaligned<SkipValueType>`, the values
   `size_` (type `size_t`) and `value` (type `ValueType`) were being passed directly.
   Due to different type sizes, this violated the new static_assert.

2. `FixedWidthCoding.h`: When calling `storeUnaligned<T>` with
   `(val >> remainingBitsInByte)`, the shift operator caused integer promotion,
   converting `uint8_t`/`uint16_t` to `int`.

Fixed by adding explicit `static_cast<TargetType>()` to ensure the value type
matches the template parameter type exactly.
