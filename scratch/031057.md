Commit title: Avoid adding `Tany` bounds to cyclic type constants
Commit body:
Summary:
The typeconstant 'cycle' detection allows us to write both of the following without error.

```
abstract class Foo {
  abstract const type TFoo as this::TFoo;
}

abstract class Bar {
  abstract const type TBar1 as this::TBar2::TBar1;
  abstract const type TBar2 as Qux with {
     type TBar1 = this::TBar1;
  };
}

abstract class Qux {
  abstract const type TBar1;
}
```

These definitions are the same as the following given in terms of type paramters, which we also allow without error

```
abstract class FooPrime<TFoo as TFoo> {}

abstract class BarPrime<TBar1 as TBar1, TBar2 as QuxPrime<TBar1>> {}

abstract class QuxPrime<TBar1> {}
```

In the type parameter case we recognise these as vacuous bounds so both `TFoo` and `TBar1` have an implicit upper bound of `mixed`.

In the type constant case `typing_taccess` determines that there is a cycle and gives us `TAny` as the upper bound.

This diff changes the behavior so it is consistent with the universal encoding
