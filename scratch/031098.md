Commit title: Migrate 5 simple cpp_mstch_program properties to Whisker prototype
Commit body:
Summary:
Migrate the following simple (primitive-returning) properties from
`cpp_mstch_program` mstch methods to `make_prototype_for_program` Whisker
prototype definitions:

- `frozen_packed?` — checks `frozen == "packed"` compiler option
- `cpp_declare_hash?` — checks struct/union/typedef annotations
- `include_prefix` — computed include prefix with out_dir_base (overrides base prototype)
- `has_schema?` — checks if program has a schema
- `schema_name` — returns the schema name

This also results in fixture changes: `schema_name` is now resolved on the
program prototype unconditionally, whereas the mstch version was only resolved
when accessed through a mstch context. Templates that access
`program.schema_name` on a Whisker handle (e.g. `schema_association.mustache`) now always resolve the property.
