Commit title: Track last activity time and add terminateInteraction API
Commit body:
Summary:
Add `lastActivityTime_` to `Tile` to track when each interaction was last
active (updated on incRef and decRef). Expose the timestamp via
`getLastActivityTime()` on both `Tile` and `TileInternalAPI`, and include
it in the `InteractionInfo` snapshot struct.

Also add a `terminateInteraction(int64_t id)` virtual method to
`ManagedConnectionIf` with a concrete implementation on
`RocketServerConnection` that safely schedules onto the connection's
event base. This enables external callers (e.g. ServiceRouter quota
enforcement) to terminate long-idle interactions.

BUCK autodeps fixes included.

  User Experience

  After this diff, any code that iterates ManagedConnectionIf
  objects (e.g., dvaar, MySQL proxy, idle-connection reapers)
  gains two new capabilities:

  1. Detect idle interactions: getInteractionSnapshots() now
  returns InteractionInfo::lastActivityTime alongside the existing
   creationTime and refCount. Services can compute now -
  lastActivityTime to identify stale interactions without needing
  custom per-service bookkeeping.
  2. Terminate specific interactions:
  connection->terminateInteraction(id) is callable from any
  thread. Previously, terminateInteraction was only reachable from
   within the frame handler (triggered by client metadata push).
  Now external code (e.g., an idle-reaper timer) can kill a
  specific interaction by ID without dropping the entire
  connection.

  Both APIs are opt-in — existing code sees no behavioral change.
  The terminateInteraction default on ManagedConnectionIf is a
  no-op, so non-Rocket connections are unaffected.
