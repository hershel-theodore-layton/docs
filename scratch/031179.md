Commit title: Fix py_deprecated -> thrift python union conversion silently mishandling in -OO mode
Commit body:
Summary:
When converting py_deprecated thrift unions to thrift-python (immutable or mutable), the converter calls `get_<field>()` accessors which use `assert self.field == N` as a guard. In production `-OO` mode, Python strips all `assert` statements, so every `get_*()` method silently returns `self.value` regardless of which field is actually set.

The caller iterates over all fields calling `_get_src_union_field_value()` for each, and the first field whose value successfully converts wins — silently corrupting the union by assigning the value to the wrong field.

The fix replaces the `get_*()` accessor pattern with `getType()` (which reads `self.field` directly, no assert guards) combined with `src_union.value` to retrieve the raw value. This is the same approach already used by the IG feed team's workaround in `distillery/feed/ranking/steps/thrift_conversion_utils.py`.
