Commit title: Fix DbEntry::isSet() performance regression from exception-based control flow
Commit body:
Summary:
D92877266 added `hash_type` and `hash_hex` fields to `AsBlockDbEntry` with `isSet()` checks in `parseArchiveBlock()`. When SQL queries don't include these columns, each `isSet()` call triggers `Row::isNull()` → `RowFields::fieldIndex()` → `throw std::out_of_range`, caught by `isSet()` to return `false`. With ~18M blocks per shard and 2 missing columns, this creates ~36M exceptions per shard scan, causing 94.8% CPU spent in `ExceptionTracerLib`.

Evidence:
1. CPU profile in be_consistency_checker: https://fburl.com/strobelight/pourzefz
2. the regression aligns with the push of cold_storage.be_consistency_checker:219, which contains D92877266
