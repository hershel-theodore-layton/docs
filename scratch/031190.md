Commit title: Fix switch exhaustivity checking for newtypes with enum upper bounds
Commit body:
Summary:
When a newtype has an enum as its upper bound (e.g., `newtype MyEnumWrapper as MyEnum = MyEnum`), switch statements on values of that newtype type could not be checked for exhaustivity. The type checker would emit error [4489] ("This switch case cannot be checked for exhaustivity. Please provide a default.") because the `of_ty` function in `switch_exhaustivity_check.ml` only handled `Tnewtype` when the name was an actual enum (via `Tast_env.is_enum`), falling through to the catch-all case for user-defined newtypes.

The fix adds a new case in `AlternativeSet.of_ty` that, when encountering a `Tnewtype` that is not itself an enum, recursively checks its upper bound type for exhaustivity. This enables exhaustive switching on newtypes whose upper bound is an enum, which is the expected behavior since the newtype values are constrained to be valid enum values.

Resolves T258661912.
