Commit title: test behavior of isset with BadEnum field
Commit body:
Summary:
Validate what happens when we have an unset, unqualified enum field, where the enum has no specified arm for value 0. While it's entirely expected that it produces `BadEnum`, the isset behavior here is illogical. It's labeled as set (deserialized unqualified field) even though it was manifestly produced by deserializing unset behavior. And as a bonus, JSON has different behavior than BINARY/COMPACT protocols.

The upshot:
- `isset` True does not imply valid data when used with certain enums
- if we're just trying to remove `isset` from customer code without changing the existing behavior, we actually need to avoid explicitly checking `isinstance` `BadEnum` even though it's semantically the correct thing to do.
