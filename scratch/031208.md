Commit title: Fix OutgoingFrameHandler correctness bugs
Commit body:
Summary:
Fix multiple correctness bugs in `OutgoingFrameHandler` and related components:

- Default `rocket_use_outgoing_frame_handler` to `false` until performance overhead is addressed.
- Remove misplaced `pendingConnections_.clear()` that caused frames to be buffered but never written to the socket. Route through `handleSerializedFrame` → `send()` → `WriteBatcher` instead.
- Fix `SerializationEvent` `streamId` member ordering: declare before container so streamId is initialized from `frame.streamId()` before the frame is moved into container.
- Fix `sendPayload()` to bypass `OutgoingFrameHandler` for FD-bearing payloads (`FrameContainer::serialize()` drops FDs) and pass `SendCallback` through.
- Fix `sendError()` to bypass `OutgoingFrameHandler` for connection-level errors (StreamId 0) so `dropConnection()` can flush them before closing.
- Fix `sendMetadataPush()` to always use direct `WriteBatcher` path.
- Fix `isOutgoingFrameHandlerBusy()` to check `pendingOutgoingFrames_` counter instead of always returning false (needed for graceful shutdown).
- Fix `resetPendingWritesState()` to use `std::exchange` for `DestructorGuard` to prevent re-entrant double-destruction.
- Add `DCHECK` for `pendingOutgoingFrames_` underflow in `handleSerializedFrame()`.
- Fix `RingBuffer` to use `::operator new/delete` (avoid default-constructing all elements).
- Initialize `WriteBatcher` `IOBufQueue` with `cacheChainLength()`.
- Fix `RocketClientTest` data race: int hit → `std::atomic<int>`.
