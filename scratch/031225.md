Commit title: Fix notifications for states with dot in name
Commit body:
Summary:
This diff fixes and issue where we would sometimes miss a state change notification if the state has . in its name.

The root cause is that our `EdenfsWatcherInstance::get_changes_sync` calls `EdenFsClient::get_changes_since` and uses the results, including the state change notifications in there.
However, the state change notifications in the resulting `ChangesSinceV2Result` may use the name `hg_transaction` when the actual name is `hg.transaction`. This is due to some name santiation that Eden does. This is properly reverted to the correct name when receiving all changes through `StreamingChangesClient::stream_changes_since_with_states_wrapper`. The latter is what our `Worker` uses, which is why it was not affected by this issue.

The fix is that in `EdenfsWatcherInstance::get_changes_sync`, if we receive a result from `EdenFsClient::get_changes_since`, we now create a singleton stream with that result, and apply `stream_changes_since_with_states_wrapper`. It should be okay to do this unconditionally, but for extra safety, we only do this if `config.state_tracking` is enabled. This happens in a new helper function `eden_client_get_changes_since`
