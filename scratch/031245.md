Summary:
Assign oncall ownership to 27 HHVM-specific extensions under runtime/ext/ that
currently have NO_ONCALL_YET. Each extension was individually researched by
analyzing code authors, commit history, domain scope, dependency oncalls, and
documentation to determine the correct owner.

- mcrouter → "memcache" (thin wrapper around mcrouter_core, domain-owned by memcache team)
- 26 remaining extensions → "hphp_hphpi" (core HHVM runtime infrastructure)

Extensions covered:
- Core: hh, xhp, implicit_context, collections, server, intrinsics, functioncredential
- Profiling/Debug: xenon, objprof, heapgraph, vsdebug
- HSL native backing: hsl_os, hsl_locale, hsl_str, hsl_random, hsl_regex, hsl_systemlib, hsl_time, hsl_io
- Compression: snappy, lz4, scrypt
- Utility: fribidi, unitfilecache, xreqsync
- Caching: mcrouter
