Commit title: Add agent CLI tracing for Hack CLIs with full context propagation
Commit body:
Summary:
When AI agents invoke Hack CLI scripts (e.g., `phps SomeScript`, Meta CLI
commands), outbound Thrift RPCs are not attributed to the agent. The C++
TracingInterceptorLight handles C++/Python CLIs but Hack uses a different
Thrift client stack (TClientEventHandler) that requires its own solution.

This diff adds `AgentCLITracing`, the Hack equivalent of
TracingInterceptorLight. Called from `ThriftContextPropHandlers::install()`
on the first Thrift client creation, it:

1. Gates on `ENABLE_AGENTS_CLI_TRACING_THRIFT=1` env var
2. Starts an Artillery trace with a fresh trace ID
3. Enables the `agent_cli_tracing` www_services policy via
   `addEnabledPolicy()` — required for `isOnForCategory(THRIFT)` to pass
   the two-layer gate (PSP constraints + category check)
4. Sets up full context propagation:
   - Creates CoreContext via `setArtilleryTraceIdIfAbsent()`
   - Registers `ArtileryOutgoingRequestContextHandler` for edge creation
   - Sets `trace_source` via `logTraceStartingProps()` for Tracery
5. Annotates the service block with agent identity (`ai_agent_id`,
   `ai_agent_invocation_id`), CLI metadata (`cli_type=hack`,
   `cli_script=<ScriptName>`), and `is_service_block=True`
6. Sets execution unit `service_id` to `<agent_id>.cli`

The result: every outbound Thrift RPC from an agent-invoked Hack CLI
carries Artillery trace context to downstream services, producing traces
with full edges visible in Tracery.

Also includes:
- `AgentCLITracingE2ETestScript`: calls EmployeeService via SRClient
- `CLAUDE.md` for the Artillery Hack SDK documenting the initialization
  chain and `isOnForCategory()` two-layer gate
- LLM rule for auto-discovery of SDK gotchas
