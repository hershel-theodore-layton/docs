Commit title: Add ThriftMetadataHandler codegen to the Java compiler
Commit body:
Summary:
Adds compile-time codegen for Thrift service metadata in the Java compiler,
replacing the need for runtime reflection or `ThriftCodecManager`, used by  legacy `ThriftMetadataServiceHandler`.

**Codegen pipeline:**

1. `t_mstch_java_generator.cc` — computes metadata (FQNs, function signatures,
   type expressions) for each Thrift service at compile time and feeds them into
   mustache templates.

2. `ThriftMetadataHandler.mustache` — generates a per-service
   `XxxThriftMetadataHandler.java` class implementing the `ThriftMetadataHandler`
   interface with service metadata, parent chain traversal, and type maps.

3. `Service.mustache` — adds a `static getMetadataHandler()` method on each
   generated service interface.

**What is codegen'd:**
- Per-service function signatures with full type resolution
- All primitive types (void, bool, byte, i16, i32, i64, float, double, string,
  binary)
- Struct, enum, union type references in function arguments/return types
- Container types (list, set, map) including nested containers
- Service inheritance (parent chain via `getParentHandler()`)
- Exception declarations in function throws clauses
- Oneway function flag

**Runtime interface:**
- `ThriftMetadataHandler` interface in `thrift/lib/java/runtime` — defines the
  contract for generated handlers.
