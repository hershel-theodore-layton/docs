Commit title: Don't treat files with malformed script markers as PHP
Commit body:
Summary:
A typo in the `<?hh` script marker (e.g., `<?h h`, `<?hx`, or bare `<?`) currently causes  `hh` to silently classify the file as PHP and skip it entirely and report no errors. This happens because:
1) The lexer's make_markup_suffix() only recognizes *exactly* `<?hh` as a name token after `<?`. Anything else produces no name token, which the mode parser interprets as `Language::PHP`.
2) The mode parser treats all non-`<?hh` headers (including bare `<?`) as PHP files to be silently ignored.

This diff modifies the lexer so that it scans all contiguous name characters after `<?`, producing a proper name token for `<?php`, `<?h`, `<?hx`, etc. It also changes the mode parser so that it explicitly checks the name text:
- `<?hh` is Hack,
- `<?php`  and `<?` ('short tag') are PHP (silently skipped, preserving the intended behavior),
-  anything else (`<?h`, `<?hx`, ...) is treated as Hack so that errors in the file are surfaced

A later diff makes anything other than `<?hh`, `<?php` or `<?` an error
