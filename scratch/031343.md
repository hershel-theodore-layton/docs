Commit title: Replace service:parent_service_* usage in service/interaction-only contexts in cpp2 generator
Commit body:
Summary:
`mstch_service` / `cpp_mstch_service` expose a few `service:parent_service_FOO` properties to get around the fact that our mstch templates do a lot of context switching and make it difficult to access properties from parent nodes.

In Whisker, we can more easily access parent contexts.

For interpolations which are only rendered in service contexts, we can just replace `service:parent_service_FOO` with `service:FOO` because `mstch_service::parent_service()` returns the service itself for non-interaction nodes.

Note: the compiler explicitly validates and disallows nested interactions (functions within an interaction returning an interaction), so any context guarded by `function.creates_interaction?` can only render for a service function, not an interaction function.

For interpolations which are only rendered in interaction contexts, capture a reference to the parent service via a `#let` declaration before the context switch to interactions (where `service:self` would actually return the interaction's Whisker prototype), and use that to access the respective properties on the containing service context.

After this, all remaining cases are in templates which are rendered in a mix of service and interaction contexts.
