Commit title: Fix uninitialized nextId_ in RegistryIdManager causing LOG(FATAL)
Commit body:
Summary:
Initialize `nextId_` to 0 in RegistryIdManager. Without initialization,
`nextId_` has undefined value. When this random value is >= 4096
(1ull << kReserveBits), the first call to getId() triggers
CHECK_LT(id, 1ull << kReserveBits) at RequestsRegistry.cpp:44,
causing a LOG(FATAL) crash.

This was the root cause of transient test crashes in ZippyDB's
PrimaryRedirectionTest and AddAndDropIntegrationTest during [R20351.1.](https://www.internalfb.com/conveyor/zippydb/zippydb/releases/20352.1/nodes/Contbuild%20Tracking%20Node%20(zippydb)/runs/4315449242054388?pipeline_names[0]=main&node_details_tab=run_details_summary)
The failures were non-deterministic because they depended on whatever
value happened to be in uninitialized memory.

Fix: `uint32_t nextId_{0};` (member initialization)
