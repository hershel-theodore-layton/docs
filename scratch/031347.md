## Context

We have a lot ELB OOM kills (700+ in last 6 months) on edge which is due to high memory pressure https://fburl.com/scuba/netcons_ooms/myqzufen

Take one as example, the task already exceeds the memory util limit and shed, but not enough and still killed by high memory pressure.

https://pxl.cl/90Vj4

Beyond triggering OOMs, high memory pressure can also increase latency and degrade overall performance. To address this, we should incorporate memory pressure signals to amplify shedding once memory utilization crosses the soft limit.

-------

# Implementation

With the introduction of memory pressure soft / hard limit in last diff, this diff is to calculate the memory pressure saturated ratio and update memory saturation ratio

Same as other resources, the calculation is:

memory pressure saturation ratio  = (memory pressure - memory pressure soft limit) / (memory pressure  hard limit - memory pressure soft limit)

And the memory saturation ratio is now updated to:

- if memory util saturation ratio <=0, memory saturation ratio = 0;

- if memory util saturation ratio > 0, memory saturation ratio = max (memory util saturation ratio, memory pressure saturation ratio)
- This is to only consider memory pressure when memory utilization exceeds the soft limit to avoid noisy shedding at low utilization where pressure spikes are typically benign kernel reclaim

For now limit is set to 100% for both, which means pressure saturation ratio is always 0, we won't shed on memory pressure at current stage. I added two jk to override the limit so that I can do some experiment to see what is the right value.
