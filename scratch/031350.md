Commit body:
Summary:
# Context

The `disable_legacy_soft_typehints` parser option controls whether the
legacy `T` syntax for soft type hints produces a parser error. The
modern replacement is `<<__Soft>> T`. The flag defaults to `true` in
both OCaml and Rust, meaning `T` is already rejected by default. The
configurable aspect is dead code — no production config sets it to
`false`.

# Solution

Remove the flag entirely and make the parser error unconditional:

- Remove `disable_legacy_soft_typehints` field from `ParserOptions`
  (OCaml type, Rust oxidized type, default values)
- Remove from `Full_fidelity_parser_env` (OCaml type, Rust oxidized
  type, `make` parameter, accessor function)
- Make `disabled_legacy_soft_typehint_errors` unconditional in
  `rust_parser_errors.rs` — always emit the error for
  `SoftTypeSpecifier` nodes
- Remove CLI flags from `hh_single_type_check` and
  `fullFidelityParseArgs`
- Remove config key from `config_keys.ml/mli` and `serverConfig.ml`
- Remove hackc's explicit `disable_legacy_soft_typehints: false`
  override in `compile.rs`
- Remove passthrough in `hh_config.rs`
- Update FFI bridge tuple indices in `rust_parser_errors_ffi.rs`
- Remove `--disable-legacy-soft-typehints` from test HH_FLAGS (the
  error is now unconditional)
