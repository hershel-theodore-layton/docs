Commit title: Fix BiDi test callbacks wrapped in DCHECK that are stripped in opt builds
Commit body:
Summary:
Several BiDi test utility classes (BiDiConfigurableServer, BiDiEchoServer,
BiDiFiniteClient) placed callback function calls with side effects inside
DCHECK() macros. In optimized builds (e.g. opt-tsan), DCHECK is a no-op
and its argument is never evaluated, so callbacks like
`clientCallback_->onStreamComplete()` were silently never called. This
caused the client to never reach terminal state and the test to hang
indefinitely waiting on the completion signal.

Fixed by extracting the callback call outside DCHECK so it always executes,
while keeping the assertion on the return value inside DCHECK:
```
// Before (broken in opt):
DCHECK(!clientCallback_->onStreamComplete());

// After (always calls the callback):
auto alive = clientCallback_->onStreamComplete();
DCHECK(!alive);
```
