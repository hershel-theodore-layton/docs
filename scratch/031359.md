Commit title: Add thrift_service_name parameter to IPolicyEnforcerAtThrift::genExtractEnforcableAssets
Commit body:
Summary:
`AIModelSeriesVirtualPolicyEnforcer::genExtractEnforcableAssets` was switching
on `$smc_service_name` (the SR config name, e.g. `'fblearner.predictor.a'`)
to dispatch between FBLearner and InferencePlatformSp code paths. However,
`TClientPoliciedAsyncHandler` passes `$this->srConfigServiceName` for this
parameter, which is the deployment-level SR config name, not the thrift
service name (e.g. `'FBLearnerPredictionService'`). This caused FBLearner
enforcement to silently stop working after D94736398 introduced the switch.

Fix: Add `$thrift_service_name` as a new first parameter to the
`IPolicyEnforcerAtThrift::genExtractEnforcableAssets` interface, sourced from
`$xid->getServiceName()` at the call site. This provides the reliable thrift
service name that `ThriftDataSystemPolicyEnforcerFactory` already uses for
dispatch. The AIModelSeries enforcer now switches on this parameter.

All 11 implementations and the `PolicyEnforcer` base class are updated to
accept the new parameter. Parameter `$func_name` is also renamed to
`$thrift_func_name` for consistency.
