# RFC/Context

This diff enables automatic `folly::RequestContext` propagation across `tokio::spawn` boundaries, eliminating the need for manual `.with_current_rctx()` wrapping on every spawn call. Without FRC awareness, instrumented tokio tasks are dropped completely given Artllery's dependency with folly::RequestContext (see  tokio_spawn_example.rs examples in Test Plan)

**Problem:** Today, `tokio::spawn` in Rust currently requires manually wrapping the future with `.with_current_rctx()` to propagate `folly::RequestContext`. This is easy to forget, causing lost Artillery traces and contextprop across spawned tasks (recent examples: D91720032, D91911323, D31547937, D66986232). According to devmate, 95% of Rust async code is through tokio tasks.

Similar past problem: **Python's** asyncio library used to face the identical issue, and required patching RequestContextAwareTask (before fried changes as discussed in https://fb.workplace.com/permalink.php?story_fbid=pfbid0bCRrXqDKSRduu3xLCWpugBVYMfwGUVMFirS62fu6iw4YgV1jEVC1F6fgJDDjhFMql&id=100021860808578). By introducing a simple one-time patch, users don't need to worry about explicitly managing FRC across tokio tasks. See the example in the Test Plan.

**Solution:** Use Tokio's task lifecycle hooks (`on_task_spawn`, `on_before_task_poll`, `on_after_task_poll`, `on_task_terminate`) — already enabled at Meta via `tokio_unstable` — to automatically capture, restore, and update `RequestContext` around every task poll. This mirrors Python's `PyContext_AddWatcher` approach that made `RequestContextAwareTask` obsolete (D83068906, D83181028).

**Usage:**
```rust
use request_context_tokio::BuilderExt as _;

let runtime = tokio::runtime::Builder::new_multi_thread()
    .install_request_context_hooks()  // what this diff introduces
    .enable_all()
    .build()?;
```

After that, all `tokio::spawn`ed tasks automatically inherit the spawner's `RequestContext`

# Decision to make opt-in
For now, automatic folly::RequestContext propagation is an opt-in feature that requires explicitly calling install_request_context_hooks() before starting the Tokio runtime. This conservative approach allows customers to:

## Test the feature in isolation before broader rollout
Evaluate any performance impact on their specific workloads
Verify compatibility with existing context propagation patterns

# Future Integration with #[fbinit::main]
This feature is designed to be trivially integratable into Meta's #[fbinit::main] attribute macro  https://fburl.com/code/r5r6vykl

```
pub fn tokio_main<F>(tokio_workers: Option<usize>, f: F) -> <F as Future>::Output
where
    F: Future,
{
    let mut runtime = tokio::runtime::Builder::new_multi_thread();
    if let Some(tokio_workers) = tokio_workers {
        runtime.worker_threads(tokio_workers);
    }
    // to add runtime.install_request_context_hooks()
    runtime.enable_all().build().unwrap().block_on(f)
}
```
