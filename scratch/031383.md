Commit title: Fix codegen for binary typedefs with java.swift.type annotation
Commit body:
Summary:
D96171605 removed annotation lowering that copied `java.swift.type` from
typedefs to inner types, replacing it with typedef chain walking in the
generator. However, when ReadType/WriteType templates recurse from a typedef
with `java.swift.type` into the inner `binary` type, the `javaType` context
is lost. This produces `readBinary().array()` (byte[]) instead of
`readBinary()` (ByteBuffer), and `ByteBuffer.wrap(this.field)` instead of
`writeBinary(this.field)` — causing type mismatches.

Fix: handle binary typedefs with `javaType` at the typedef level in
ReadType.mustache and WriteType.mustache, matching the existing pattern for
`isBinaryString?`. This preserves the `javaType` context so ReadTypeBinary
skips `.array()` and WriteType skips `ByteBuffer.wrap()`.
