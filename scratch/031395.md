Commit body:
Summary:
# Context

The `disable_lval_as_an_expression` parser option controls whether
assignments used as expressions (e.g., `f($x = 1)`) produce a parser
error. The flag defaults to `true` in both OCaml and Rust, meaning
lval-as-expression is already rejected by default. No production config
overrides this.

# Solution

Remove the flag and make the parser error unconditional. Same cleanup
pattern as `disable_legacy_soft_typehints`:

- Remove field from `ParserOptions` (OCaml + Rust oxidized types)
- Remove from `Full_fidelity_parser_env` (OCaml + Rust)
- Make `lval_errors` unconditional in `rust_parser_errors.rs`
- Remove CLI flags from `hh_single_type_check` and
  `fullFidelityParseArgs`
- Remove config key from `config_keys.ml/mli` and `serverConfig.ml`
- Remove HHVM HDF config from `hhvm_config.rs`
- Remove passthrough from `hh_config.rs`
- Update FFI bridge tuple indices
- Clear `--disable-lval-as-an-expression` from test HH_FLAGS
- Update test snapshots (the check now catches more patterns since it
  runs unconditionally in all test contexts)
