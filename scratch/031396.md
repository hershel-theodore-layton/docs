Commit title: Add ValSet reference implementation for BddSet completeness testing
Commit body:
Summary:
## Motivation

The existing soundness tests verify that when BddSet claims disjointness or subset, the ground truth (witness denotation) agrees. But there was no test in the other direction: if a disjointness or subset relationship *should* hold given the pairwise `Domain.relation` constraints, does BddSet actually prove it? We need a completeness test to catch regressions where BddSet fails to derive something it should be able to.

## Approach

The key challenge is defining "should hold" precisely. The correct ground truth for completeness is: a property holds iff it holds under *every* valuation of atoms that is consistent with the pairwise `Domain.relation` results. For example, if `relation(A, B) = disjoint`, then no consistent valuation has both A and B true.

`ValSet` implements this directly. It stores set expressions as trees and evaluates them by brute-force enumeration over all 2^n valuations of the n atoms, filtering to those consistent with pairwise relations:

```
eval(v, Empty)       = false
eval(v, Singleton t) = v(t)
eval(v, Union(a,b))  = eval(v,a) || eval(v,b)
eval(v, Inter(a,b))  = eval(v,a) && eval(v,b)
eval(v, Diff(a,b))   = eval(v,a) && not eval(v,b)

is_subset(s1, s2) = for all consistent v, eval(v,s1) => eval(v,s2)
```

This is obviously correct by construction — it *is* the mathematical definition. `op_to_valset` replays the `ASet.op` expression tree (which records the exact sequence of set operations) as a `ValSet` expression, so the reference impl evaluates the same expression BddSet does.

## How the test works

`test_completeness` checks both soundness and completeness in a single pass over 10k random trials:

- **Soundness** (same as before): if BddSet says true, the witness denotation must agree
- **Completeness** (new): if BddSet says false, `ValSet` must also say false (or return `None` for too many atoms). If `ValSet` says true but BddSet says false, that's an incompleteness bug.

The completeness check only invokes `ValSet` when BddSet says false, so the common case (BddSet correct) has zero overhead. Atom count is capped at 20 to keep enumeration fast.

## Other changes

- Added `expect_complete : bool` to `S_for_test` so completeness checking is parameterized per implementation (ApproxSet: false, BddSet: true)
- Added `gen_neg_interface` to the type set generator to exercise `diff(mixed, to_datatypes(interface))` patterns, modeling `Tneg(IsTag(ClassTag(...)))` in the real type checker
- Added `test_negated_interface_incompleteness` to verify soundness of `are_disjoint(class, complement(interface))`
