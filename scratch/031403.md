Commit title: Replace std::filesystem::path with std::string in DB result structs and avoid makeStaticString in diff loop
Commit body:
Summary:
Two related changes that eliminate unnecessary type conversions in the Facts query and init paths:

1. Replace `std::filesystem::path` with `std::string` in `SymbolPath`, `MethodPath`, and `PathAndHash` structs in `autoload-db.h`. These structs are returned from SQLite queries and consumed by `SymbolMap`, which immediately extracts the string via `.native()` to construct `Path` objects. The `fs::path` intermediary adds construction overhead (parsing, normalization) with no semantic value.

2. Change `getAllPathsWithHashes()` to return `hphp_fast_map<std::string, SHA1>` instead of `hphp_fast_map<Path, SHA1>`, and update `getFreshDelta()` to diff using raw strings. Previously, constructing a `Path` for each of the 7.4M DB rows called `makeStringPtr()` → `makeStaticString()`, which does a global locked hash table lookup/insert into the HHVM static string table. These strings were only needed for a one-shot hash comparison in `getFreshDelta()` and were immediately discarded, but they remained permanently in the static string table (by design — "static" means process-lifetime), consuming ~800MB of memory that could never be reclaimed. Switching to `std::string` keys uses value-equality comparison, which is semantically identical for this use case and avoids both the lock contention and the memory leak.

Benchmarked with opt-hhvm against a 12GB production facts DB:
- `getMethodsWithAttribute("GraphQLQueryRootField")` (94K rows): 108.6ms -> 79.8ms (27% faster)
- `getMethodsWithAttribute("GraphQLField")` (913K rows): 623ms -> 339ms (46% faster)
- `getTypesWithAttribute("GraphQLObject")` (216K rows): ~176ms -> 126.9ms (28% faster)

These correspond to the `HH\Facts\methods_with_attribute()` and `HH\Facts\types_with_attribute()` Hack functions, which show p99 latencies of 449ms and 226ms in production Scuba data (hhvm_sandbox_events).
