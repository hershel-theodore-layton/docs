Commit title: Add reserve() to LazyTwoWayMap::getKeysForValue before bulk insertion
Commit body:
Summary:
Add `reserve()` call before the insertion loop in `LazyTwoWayMap::getKeysForValue` to pre-allocate hash map capacity when loading large result sets from the DB. Without this, the hash map grows through multiple rehashes during insertion. This code runs under a write lock on `m_syncedData`, so reducing the write-lock hold time benefits concurrent readers.

Benchmarked with opt-hhvm against a 12GB production facts DB, measuring the full cold path for `getMethodsWithAttribute("GraphQLQueryRootField")` (94K rows including DB query, MethodDecl construction, and LazyTwoWayMap cache insertion):
- Without reserve: 127.7ms
- With reserve: 118.4ms (7.3% faster)

The cache insertion phase in isolation improved by ~38% (from ~13ms to ~8ms).
