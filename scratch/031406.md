Commit title: Remove unnecessary readOrUpdate from DB-only query methods
Commit body:
Summary:
Three SymbolMap methods use the `readOrUpdate` pattern but never read from or write to the in-memory cache — `readFn` always returns `nullopt` and `writeFn` just passes through the DB result. This causes them to needlessly acquire an upgrade-to-write lock on `m_syncedData`, blocking all concurrent readers for no benefit.

Changed methods:
- `getAllModules()` — always queries DB, never caches
- `getTypeMethodAttributes()` — DB-only because the in-memory `m_methodAttrs` map is keyed by MethodDecl, not by type
- `getFilesAndAttrValsWithAttribute()` — DB-only because the query is a JOIN that doesn't map to the in-memory data model

These now query the DB directly without touching `readOrUpdate` or the shared lock. This eliminates spurious write-lock acquisitions that serialized concurrent readers through the `SharedMutexWritePriority` lock.
