Summary:
## What

Add `hh --outline-for-agents`

## Why

Agents tend to refuse to read large files. When a file is above certain limits, they fall back to guessing ranges to read.

We can give agents a tool to see which ranges in a file are most relevant

see fb-only section for stats

## How

- show only what something is (function/class/enum class/trait/etc.) and its name
- show line ranges
- hide private members

## Choices

**made the flag user-facing**

I added `--outline-for-agents` so it shows up in `hh --help`. We could, alternatively, hide it so it only shows up in `hh --ultrahelp`. I am leaning slightly toward making the feature visible in order to help find product-market fit, maybe devs will see it and do things with it, or maybe agents will spontaneously discover the feature.

**very byte and token-cheap**: we could have included, for example, type information in the outline. But it's common in generated large files to have types that are longer than function bodies. So I biased toward conserving tokens: the job of the tool is to show where symbols are defined, and then agents can use `read` to grab things like types if they need them.

## Follow-on

`hh --outline-for-agents` can be integrated into coding agents. I'm experimenting with adding a hook to Claude Code so that when it fails to read a large Hack file it knows it can call `--outline-for-agents`. Example run: P2233168841
