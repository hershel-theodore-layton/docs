Commit title: go-to-parent heuristics for methods
Commit body:
Summary:
This diff ensures that if we have a method `C::m` in our graph, we add `P::m` to the graph for each immediate parent `P` of` C` where `P::m` is defined (i.e., P has a definition of `m` or inherits `m`).

The motivation is that this allows us to follow static references that may occur when dynamic dispatch will cause a method we are interested in to be called. Given `A` <: `B`, and method `A::m` is changed by a diff, a test would previously not selected if it does `$b->f()` where the static type of `$b` is `B`.

The new configuration option `max_method_parent_steps` determines how many consecutive go-to-parent steps we are allowed to take, independent from the general maximum distance setting.
