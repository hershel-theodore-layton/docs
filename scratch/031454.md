Commit title: go-to-enclosing-class heuristic for all methods
Commit body:
Summary:
Prior to this diff, we already have the following heuristic: If we are given root method `C::r`, we add a node for the enclosing class `C`.

When subsequently expanding `C`, we
- select any test file that references `C` in any way
- look for `C::class`, `class<C`, and `new C()` and continue searching from there.

This diff makes this heuristic broader, we now add the enclosing class for any method  we add to the graph, not just root methods.

There's only one restriction: If we add an enclosing class `D` for a method that is not a root, we don't look for `new D(...)`. For root methods, the idea is that if a diff changes a class, we should look for instances of it being created. But let's not look for instantiation for *any* class defining a method we find during our traversal.

Technical detail: There was some ad-hoc code that did the original enclosing-class-for-any-root method. It has now be subsumed by more principled code in `get_method_successors`.
