Commit title: use Timeout.with_timeout as extra safety net
Commit body:
Summary:
So far, our timeout mechanism is entirely cooperative: We check against a deadline in our main graph construction loop, and in `FindRefsService.find_refs` (which may type-check lots of files and therefore take long).

This diffs plugs some holes where this was not enough to stop the algorithm in time, causing the Hack side to kill `hh_client` and not get any partial results back.

1. In `FindRefsService.find_refs`, we now use `Timeout.with_timeout`: If computing a particular TAST takes too long, this stops that. We can't just set `tco_timeout`, since that timeout is applied per definition: If a class has 5000 methods, each taking a second to type-check, a 10 second timeout would never fire.
2. I'm wrapping the entire graph construction in `Timeout.with_timeout`, in case some other graph construction step takes unexpectedly long. This is mostly intended as a fail-safe in case everything else fails.

In general, `Timeout.with_timeout` is a bit hacky. It relies on signal handling and I'm not sure if it always works 100% reliably. For that reason:
- I'm trying to avoid triggering such a timeout while a `MultiThreadedCall` is still running.
- I'm always setting grace periods, so that the cooperative mechanisms have a chance to trigger first.
