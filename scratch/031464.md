Commit title: allow skipping symbols with very big fanout
Commit body:
Summary:
This diff adds two flags that allow skipping parts of the graph if it is infeasibly expensive to build them.

Details:
When expanding a node/symbol in our graph, we look for references to that symbol. This happens in two stages, similarly to what `ServerFindRefs` does:
1. We use the depraph to find all dependents of that target symbol, then look up the corresponding files.
2. We call `FindRefsService.find_refs` on those files and our target symbol. This basically builds a TAST for every file and traverses the TASTs to look for usages of our actual target symbol.

Sometimes in step 1. we see that the set of deps or files is so big that there is no chance for us to finish getting the TASTs for them.

This is particularly bad when doing parent walking: Since we basically store the transitive closure of all dependencies, walking up the hierarchy increases the number of files we would have to check.  For example, if we walk from from some `EntFooSchema` class all the way up to `IEntSchemaBase `, the latter gives us over 500k files to check.

Due to the potential affect of parent-walking, I'm introducing two thresholds in this diff.  One applies to nodes we got from a go-to-parent step, the other threshold to all other nodes:
- `parent_max_fanout_files`
- `non_parent_max_fanout_files`

If we are expanding a node and the set of files we get in step 1. for that symbol is larger than the threshold, we skip and don't proceed to step 2.
