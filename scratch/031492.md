Commit title: Fix missing response attributes in QueryLoggingData for sync client
Commit body:
Summary:
`specializedCompleteOperation()` in both `MysqlFetchOperationImpl` and
`ThriftFetchOperationImpl` was calling `readResponseAttributes()` to re-read
response attributes from the connection handle for logging. However, the
response attributes were already correctly saved in `current_resp_attrs_`
during `CompleteQuery` processing.

For the sync MySQL client (`cpp_sync_query`), the second read from the MYSQL
handle returns incomplete data — all string response attributes
(`db_storage_backend`, `purpose_policy_check_result`, `privacy_policy_result`,
`client_stats`, etc.) are lost. This is because `SyncMysqlConnection::getResult()`
uses `mysql_store_result()` which processes the OK packet differently than the
async path's `mysql_use_result()`.

Evidence from `mysql_client_logs` Scuba:
- `cpp_async_query`: all response attributes present
- `cpp_sync_query`: `server_cpu` (bigint, auto-cast) present, ALL string
  response attributes NULL globally

Fix: use the already-saved `current_resp_attrs_` (captured at CompleteQuery
time when attributes are definitively available) instead of re-reading from
the connection handle.
