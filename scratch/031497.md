Commit title: Handle int->string conversion in JSON map keys for Dynamic Thrift deserialization
Commit body:
Summary:
In JSON, map keys are always strings regardless of the Thrift key type. Previously, `isJsonTypeCompatible` would reject string-typed map keys when the expected type was numeric (e.g., i32), causing deserialization to skip valid map entries like `{"1": 2}`.

This adds an `isMapKey` parameter to `isJsonTypeCompatible` so that when checking map key types, string values are considered compatible with numeric Thrift types. The underlying read functions (readI32, readI64, etc.) handle the string-to-type conversion correctly.

This is an alternative to D96823170 which removed the key type check entirely — this approach preserves the type checking while allowing the known string-to-numeric conversion that JSON requires for map keys.
