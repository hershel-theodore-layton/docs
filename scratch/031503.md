Commit title: Fix TRC per-request CPU variance caused by RequestContext leaking into QUIC write path
Commit body:
Summary:
`EventBase::runInLoop()` captures the ambient `folly::RequestContext` by default. When proxygen schedules HQSession write callbacks (`scheduleWrite()`, `scheduleLoopCallback()`), the ambient context belongs to whichever HTTP request triggered the scheduling. This context then propagates through the entire QUIC write path:

```
HQSession::scheduleWrite() [captures Request A's context]
  → WriteScheduler::runLoopCallback() [runs under Request A's context]
    → sock_->notifyPendingWriteOnConnection()
      → QUIC runOnEvbAsyncOp() [captures ambient → still Request A]
        → TransportLooper::commonLoopBody()
          → aead.inplaceEncrypt() ← AES-GCM encryption charged to Request A
```
