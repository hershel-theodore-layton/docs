Commit title: Fix flaky ResponseWriteTimeout test by throttling all read delivery paths
Commit body:
Summary:
The SlowReadCallback in ResponseWriteTimeout test only throttles reads via
readDataAvailable() (with a 100ms sleep), but forwards readBufferAvailable()
and readZeroCopyDataAvailable() without any throttling. On CI machines that
may use io_uring (AsyncIoUringSocket), reads are delivered via
readBufferAvailable() instead of readDataAvailable(), completely bypassing
the slow-read throttle. This causes the response to complete before the
1-second write timeout fires, making the test flaky (~68%).

Add the same 100ms sleep to readBufferAvailable() and
readZeroCopyDataAvailable() so the throttle works regardless of the
underlying transport's read delivery mechanism.
