Commit title: Add E2E tests for resource pool routing
Commit body:
Summary:
Add a comprehensive E2E test suite for ThriftServer resource pool routing.
This was identified as a P0 gap -- resource pools had good unit test coverage
for individual components but no E2E tests verifying the complete routing
pipeline from client request through pool selection to execution.

The test suite includes 6 test cases:
- DefaultPoolHandlesAllRequests: basic sanity, requests complete on default pool
- ConcurrencyLimitEnforcedOnDefaultPool: excess requests queue when limit reached
- CustomPoolRoutedBySelectResourcePool: per-method routing via selectResourcePool()
  override routes echo to "EchoPool" while voidMethod goes to default
- PriorityBasedRouting: with PRIORITY_QUEUE and 1 worker, HIGH executes before
  BEST_EFFORT
- PoolExhaustionDoesNotAffectOtherPools: blocking one custom pool doesn't affect
  requests to another
- DynamicConcurrencyLimitChange: changing setExecutionLimitRequests on a live
  server takes effect immediately

Key infrastructure:
- RoutingProcessorFactory: wrapper that overrides selectResourcePool() for
  per-method routing to custom pools
- BlockableHandler: handler that cooperatively blocks the first echo() call
  using std::atomic<bool> (safe for multiple invocations, no Baton reuse issues)
