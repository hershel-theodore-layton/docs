Commit title: Add E2E tests for stream/sink backpressure and flow control
Commit body:
Summary:
Add a comprehensive E2E test suite verifying Thrift stream and sink backpressure
behavior, including credit-based flow control, memory-based flow control, chunk
timeouts, stream expiry, and BiDi interactions. This was identified as a gap in
the existing E2E test coverage -- no tests previously verified that backpressure
mechanisms work end-to-end across the Rocket transport.

The test suite includes 8 test cases:
- SlowConsumerCausesServerStreamBackpressure: slow consumer with small credit
  buffer; backpressure throttles the server, all items arrive in order
- AllItemsDeliveredWithMinimalCredits: chunkBufferSize=1 (minimum credits),
  all items delivered without drops
- SlowServerConsumerCausesSinkBackpressure: server consumes slowly with small
  buffer; client throttled by credit-based flow control
- MemoryBasedFlowControlDeliversAllItems: setMemoryBufferSize with alternating
  small/large payloads, dynamic credit adjustment
- StreamChunkTimeoutOnSlowServer: chunk timeout fires when server is slow
  between stream items
- SinkChunkTimeoutOnSlowClient: server-side chunk timeout fires when client
  pauses too long between sink items
- StreamExpireTimeWithSlowConsumer: server stream expiry triggers when client
  stops consuming
- BiDiSlowSinkDoesNotBlockStream: BiDi echo with slow sink sender verifies
  the two directions do not deadlock
