Commit title: Cache compiled decode graph as singleton in vixl Decoder
Commit body:
Summary:
The vixl aarch64 Decoder rebuilds its entire compiled decode graph
(ConstructDecodeGraph) on every construction. This is very expensive — profiling
tc-print on a production TC dump showed it consuming ~97.5% of total CPU time
when Decoder objects were created per-region.

This is a performance regression from the vixl 1.x → 8.0.0 upgrade. The old
decoder (v1.x, under hphp/vixl/a64/) had an empty constructor (`Decoder() {}`)
and used hardcoded switch/if-else chains for instruction dispatch — zero runtime
construction cost. The new decoder (v8.0.0) replaced this with a data-driven
compiled decode graph (`DecodeNode` → `CompiledDecodeNode` tree with string-keyed
maps and lookup tables) to support the much larger ISA (~230+ instruction classes
vs the old ~43, including SVE, NEON, crypto, etc.). While more maintainable, this
introduced an expensive per-instance ConstructDecodeGraph() call.

The compiled decode graph is identical for every Decoder instance and is
immutable after construction. This diff makes the default constructor build
it once (via a function-local static singleton) and share it across all
instances. Each Decoder still has its own visitor list.

To enable this, CompiledDecodeNode::Decode() now accepts an optional Decoder*
parameter. When provided, it dispatches through the caller's visitor list
instead of the Decoder* baked into the compiled node at graph-build time.
Decoder::Decode() passes `this`, so each instance's visitors are used
correctly. Existing callers require zero changes — `Decoder dec;` just works.
