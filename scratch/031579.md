Commit title: Remove __fbthrift_clear_terse_fields
Commit body:
Summary:
Now that custom defaults are banned for terse fields (D70813088), the
`__fbthrift_clear_terse_fields()` method is no longer necessary.

Previously, this method was called at the start of deserialization to reset
terse fields to their intrinsic defaults, ensuring that fields missing from
the wire would not retain custom default values from the IDL. With custom
defaults on terse fields now a compiler error, terse fields always have
intrinsic defaults and this pre-deserialization clearing step is redundant.

This removes:
- The `__fbthrift_clear_terse_fields()` declaration from generated struct headers
- The `__fbthrift_clear_terse_fields()` definition from generated struct sources
- The call to `__fbthrift_clear_terse_fields()` in `readNoXfer()` deserialization
- The `clear_terse_fields.mustache` codegen template
- The `clear_terse_fields_fn` invoker and free function from `Thrift.h`

Provides a small build time improvement (~0.0122 EYS) by reducing generated
code size across all non-union Thrift structs.
