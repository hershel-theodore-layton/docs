Commit title: fix a corner case in conflicting method checks
Commit body:
Summary:
Hack checks for multiply defined methods inherited from traits where incomplete in the following scenario:

```
trait TraitA {
  public function foo():void {}
}

trait TraitB {
  public function foo():void {}
}

class D {
  use TraitA;
}

class C extends D {
  use TraitA;
  use TraitB;
}
```

because, after checking C against class D and then TraitA - but before checking against TraitB -, the Hack state was ignoring method `foo` from `traitA`, and keeping instead `foo` from `D`, which does not conflict with the later import of `foo` from `TraitB`.

This diff updates the Hack state computation to drop method `foo` from class `D` and propagating instead method `foo` from `TraitA` (mimicking what happens in HHVM trait flattening).  As a result, Hack now raises an error in the scenario above.
