Commit title: Fix cursor reader crash when reading absent trailing optional field
Commit body:
Summary:
`StructuredCursorReader::beforeReadField()` crashes when reading an optional
field that is the last field in a struct and is not set in the serialized data.

The bug is in the while loop that skips preceding fields to reach the target
field. After skipping the last serialized field, `readFieldBegin()` reads
`T_STOP` (end of struct), which sets `fieldId = 0`. The out-of-order check
`lastRead >= readState_.fieldId` then compares e.g. `9 >= 0` and erroneously
throws "Reading fields that were serialized out of order" before the loop
condition can re-evaluate and exit via the `fieldType != T_STOP` guard.

Fix: break out of the loop immediately when `T_STOP` is read, before the
field ID ordering check.
