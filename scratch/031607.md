Commit title: Add @rust.EnumType annotation for memory-optimized enum codegen
Commit body:
Summary:
Thrift enums in Rust codegen are always wrapped as `pub struct FooEnum(pub i32)`.
The C++ codegen already supports `cpp.EnumType` to control the underlying
integer type (i8, u8, i16, u16, u32) for in-memory optimization. This diff adds
the same capability for Rust via a new `rust.EnumType` annotation, enabling
smaller enum representations when the full i32 range is not needed.

This is purely an in-memory optimization — the wire format remains i32 regardless
of the underlying type, so there are no protocol-level changes or compatibility
concerns.

**Changes:**

1. **Annotation definition** (`thrift/annotation/rust.thrift`): Added
   `EnumUnderlyingType` enum (I8, U8, I16, U16, U32) and `scope.Enum
   struct EnumType` annotation, in both fbcode and xplat copies. I32 is
   intentionally omitted (matching `cpp.EnumType`) since it is the default.

2. **URI constant** (`ast/uri.h`): Added `kRustEnumTypeUri` to the central URI
   header alongside all other language URIs (C++, Java, Python, Hack, Go). This
   is needed because the validator (`sema` target) depends on `ast:ast` but not
   on the Rust generator. The existing Rust URIs remain in `generate/rust/uri.h`
   as they are only consumed by the Rust generator.

3. **Codegen** (`t_mstch_rust_generator.cc`): Added `rust_enum_underlying_type`
   enum and a `rust_underlying_or_i32` property to `make_prototype_for_enum()`.
   This reads the `rust.EnumType` annotation and returns the Rust type string,
   defaulting to `i32` when the annotation is absent.

4. **Template** (`enum.mustache`): Replaced hardcoded `i32` references with
   `{{enum:rust_underlying_or_i32}}`. Added `as i32` casts at serialization,
   display, inner_value, and from_str boundaries so the trait and wire format
   contracts remain unchanged. Deserialization uses `TryInto` instead of `as`
   for safe narrowing — returning an error if the wire value exceeds the
   underlying type's range rather than silently truncating.

5. **Validator** (`standard_validator.cc`): Added `validate_rust_enum_type()`
   that validates enum values fit within the declared underlying type's range at
   compile time. Reports out-of-range values with a suggestion for the smallest
   fitting type. Follows the same pattern as `validate_cpp_enum_type()`.

6. **Test fixture** (`rust-enum-type`): New fixture covering `SmallEnum(i8)`,
   `SignedEnum(i16)` with negative values, `MediumEnum(u16)`, `LargeEnum(u32)`,
   and `DefaultEnum` (no annotation, defaults to i32). All 132 existing fixtures
   regenerated.
