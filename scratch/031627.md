Commit title: Enable client interceptors for Rust thrift clients
Commit body:
Summary:
Rust Thrift clients had a gap identical to the one Python had (fixed in D92163251):
`initThrift` registers `TracingInterceptorLight` and other `ClientInterceptor`s into
`runtime::getGlobalClientInterceptors()`, but Rust's `methods.h` hardcoded `nullptr`
for `clientInterceptors` at all 4 call sites. This meant CLI tracing (Artillery),
context propagation, and privacy interceptors never fired for Rust thrift clients.

This diff follows the same pattern as the Python OmniClient fix:
- Adds `enable_rust_client_interceptors` thrift flag (default false) for safe rollout
- Replaces `nullptr` with `getRustClientInterceptors()` at all 4 call sites
  (request/response, stream, sink, bidirectional)
- Adds `processClientInterceptorsOnRequest` calls in all 4 send methods
- Adds `processClientInterceptorsOnResponse` calls for request/response RPCs
  (stream/sink/bidi deferred to follow-up as they require capturing ContextStack)
- Includes a Rust verification binary (`hello_employee_rust`) for E2E testing

Scope:
- This diff: `onRequest` for all 4 RPC types + `onResponse` for request/response only
- Follow-up: `onResponse` for stream/sink/bidi (requires capturing ContextStack into callback classes)
- Rollout: Behind `enable_rust_client_interceptors` flag (default false)
