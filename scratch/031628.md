Commit title: Break typing_phase/typing_tdef dependency cycle
Commit body:
Summary:
# Context
There is a logical mutual dependency between typing_phase and typing_tdef.
typing_phase calls typing_tdef to expand typedefs during localization, and
typing_tdef calls back into typing_phase (via Phase.localize_rec) to localize
the expanded body and constraint. This cycle was broken at compile time via
ref cells in typing_utils, but the logical coupling remained.

# Solution
Make typing_tdef operate purely at the decl level. Instead of localizing its
results, expand_typedef now returns unsubstituted decl_ty values (body,
constraint, tparams) and lets the caller handle substitution and localization.
typing_phase's localize_typedef_instantiation receives the decl expansion
result, sets up ety_env.substs from the localized type args, and localizes
the body — preserving wildcard identity that decl-level substitution would
break. Cycle detection continues to work through ety_env.type_expansions
threading.

The ~force_expand parameter is eliminated; expansion behavior is now
controlled entirely through ety_env.visibility_behavior (Always_expand_newtype
serves the same purpose). A new typing_tdef_locl module provides the
locl-level force_expand_typedef that bridges decl expansion and localization
with direct calls to both modules — no ref indirection needed.

The expand_typedef types (Expanded | Opaque | Cyclic and expansion_result)
now live in typing_tdef where they belong, and the ref-based expand_typedef
indirection in typing_utils is removed entirely.
