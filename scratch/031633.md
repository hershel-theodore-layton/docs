Commit title: Split service destruction into cleanup and destroy phases
Commit body:
Summary: We're getting some shutdown crashes, https://fburl.com/tasks/2egjpuo1, and a common pattern between them is that some things are running after event bases are destructed. I'm trying to address these holisitically by splitting service destruction into two steps. Previously, destruction would stop certain things as well as destroy/de-allocate others. I'm introducing a new `cleanup` function on the abstract service class that is responsible for stopping, and then destruction is responsible for de-allocation/destroying.
