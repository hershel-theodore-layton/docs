Commit title: Enlighten fixStackUnwinding for Arm64
Commit body:
Summary:
On aarch64, `make_fcontext` (boost) does not initialize the FP (x29)
slot in the fiber's initial context frame. When jemalloc heap profiling
is enabled, `prof_backtrace_impl` walks the frame pointer chain and
eventually hits the uninitialized FP value (e.g. 0x7fffffff), causing
a SIGSEGV. Due to the same reason, `bt' in lldb can't unwind a fiber's
stack to the main thread's stack.

The existing `fixStackUnwinding()` in folly only handled x86_64 by
stitching the fiber's frame pointer chain to the main context. This
diff extends it to also handle aarch64, using the correct offsets
(0x90 for FP, 0x98 for LR) from the boost fcontext layout.

This was root-caused from ServiceLab perflab crashes where HHVM on
aarch64 consistently hit SIGSEGV in `prof_backtrace_impl` during
malloc profiling on folly fiber stacks.
