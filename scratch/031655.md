Commit title: Set per-RPC timeout on Rocket channels from client timeout
Commit body:
Summary:
The `timeout` parameter in `get_sync_client()` only controlled socket connect timeout, not per-RPC timeout. This meant callers expecting `timeout=15` to limit RPC duration were silently getting the Rocket channel's 60-second default instead.

Fix by calling `chan->setTimeout(channel_timeout)` after creating Rocket channels in both TCP and Unix socket paths. This sets the channel-level default RPC timeout to match the user-specified timeout. This matches setting the socket timeout in the `thrift-py-deprecated` library.

Per-RPC `RpcOptions` overrides still take precedence when set.
