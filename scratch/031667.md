Commit title: Fix inverted return value in RocketBiDiClientCallback::onStreamRequestN
Commit body:
Summary:
`RocketBiDiClientCallback::onStreamRequestN` was negating the return
value of `serverCallback_->onStreamRequestN(n)`. Per the stream callback
contract, `true` means the callback is still alive and `false` means a
terminating method was called. The negation inverts this meaning,
returning "dead" when the server callback is alive and vice versa.

All other forwarding methods in the same "Incoming methods" section
(e.g. `onSinkNext`) pass through the return value without negation.

The bug is currently harmless because the only call site
(`handleFrame(RequestNFrame&&)`) discards the return value, but it
would cause incorrect behavior if a future caller relied on it.
