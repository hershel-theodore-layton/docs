Commit title: Fix py3 codegen for typedefs with @cpp.Type after D96346025
Commit body:
Summary:
D96346025 removed annotation lowering for cpp.type on typedefs, which
broke py3 code generation for types like LazyAny (a typedef of Any with
a custom C++ type).

Two issues fixed:

1. **Wrong cbinding module path**: The `need_cbinding_path?` property
   used `get_true_type_program` which resolves through typedefs. For
   custom types on typedefs, the ctypedef lives in the typedef's
   program's cbindings, not the true type's program. Fixed by using
   `self.program()` when the type has a custom cpp type.

2. **C++ reference_shared_ptr ambiguity**: The generated Cython code
   calls `reference_shared_ptr<CustomType&>(...)` which causes ambiguity
   between the generic overload (from thrift/lib/py3/types.h) and
   user-provided specialized overloads (e.g., LazyAnyImpl in LazyAny.h).
   Fixed by adding explicit template arguments to reference_shared_ptr
   calls using the true (resolved) type instead of the custom type. This
   ensures the generic overload's parameter type doesn't match when a
   specialized overload exists.
