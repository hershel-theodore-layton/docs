Commit title: Add test for stream cancellation race
Commit body:
Summary:
Add a test that demonstrates the stream cancellation bug where `aclose()` on the server-side async-generator stream wrapper fails to propagate while awaiting next item from async iterator / generator.

The test creates a handler that `yield`s one item, then blocks forever. After the client reads the first item and disconnects, it asserts that the server-side generator is properly cleaned up (cancellation propagated). Without the fix (class-based stream wrapper with Task-based cancellation), `aclose()` silently fails because Python async generators cannot be `aclose()`-d while `__anext__()` is running.

Marked as `unittest.expectedFailure` until the fix is ready.
