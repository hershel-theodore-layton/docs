Commit title: Add BiDi client crash E2E test
Commit body:
Summary:
While investigating the server-side behavior of Thrift BiDi streaming
when a client disappears, we wanted to verify that the server handler
does not hang indefinitely. This test validates that when a client
process crashes mid-stream (via SIGKILL), the server-side handler
coroutine unblocks promptly.

The test uses a separate client binary (BiDiCrashClient) that:
1. Opens a BiDi echo stream and sends 3 items, keeping the sink open.
2. Waits for all 3 echoed responses (confirming the server is now
   blocked on input.next() waiting for the 4th item).
3. Kills itself with SIGKILL, causing the OS to close the TCP socket.

The test (BiDiClientCrashE2ETest) runs the server in-process, spawns
the client binary as a subprocess, and asserts that the server handler
unblocks within 30 seconds. In practice it unblocks in ~1ms —
the server receives "coroutine operation cancelled" via the cancellation
propagation chain through the Rocket connection close path.

A separate binary is necessary because in-process tests cannot simulate
a process-level TCP socket close — killing a thread does not close the
socket, only process exit does.
