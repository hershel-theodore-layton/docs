Commit title: Re-implement aarch64 crc32 hashing functions to match x86
Commit body:
Summary:
Currently hash_string_i/hash_string_i_unsafe produce different results on x86 and aarch64

The main difference, althoguh not the only one, lies on how the string's tail gets handled.
When the string's length modulo 8 is not 0, the aarch64 implementation treats each remaining byte individually.
The x86 implementation loads all remaining bytes into a register and performs just 1 extra round of crc32 encoding.
This algorithmic difference results in the ARM version to execute the crc32 instruction 7 times for a string of length 7, whereas the x86 variation will execute the crc32 instruction only once.

This diff re-implements crc32 hashing on aarch64, to address this performance gap and produce the exact same hash as in x86.

The changes also introduce a 2x unrolling in the function's main loop, as it proved to be the fastest approach for crc32c computation in D95633651
