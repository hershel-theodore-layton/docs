Commit title: Guard getMysqlConnection() calls against null connection in noexcept handlers
Commit body:
Summary:
timeoutHandler() and isDoneWithTcpHandShake() call getMysqlConnection()
which throws InvalidConnectionException if mysql_connection_ is null.
When these calls happen inside noexcept event handlers (timeoutExpired,
handlerReady), the thrown exception causes std::terminate and crashes
the process.

This can occur when both the regular timeout and TCP timeout fire in the
same event loop iteration: the first handler closes the connection via
attemptFailed() -> conn().close(), and the second handler then calls
getMysqlConnection() on the now-null connection.

Add conn().ok() guards before calling getMysqlConnection() in both
timeoutHandler() and isDoneWithTcpHandShake() to prevent the crash.

Note, that we have NOT experienced this that we know of.  It was found via Claude investigating the code, but the fixes do look useful.
