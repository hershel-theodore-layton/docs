Commit title: Fix cert validator dangling pointer in MysqlConnectOperationImpl
Commit body:
Summary:
MysqlConnectOperationImpl registers the SSL cert validator callback with a
raw pointer to the transient ConnectOperation as context (&getOp()). After
the connection completes and the ConnectOperation is destroyed, the MYSQL*
handle retains the stale context pointer. If libmysql later triggers an SSL
renegotiation or auto-reconnect (e.g. during mysql_send_query()), it invokes
the callback with the dangling pointer, causing a use-after-free crash in
mysqlCertValidator() — manifesting as a SIGSEGV in the FetchResult variant
destructor (_M_reset) because the freed ConnectOperation memory has been
reused.

The fix clears both the cert validator callback and its context from the
MYSQL* handle in specializedCompleteOperation() before the ConnectOperation
is destroyed, via a new MysqlConnection::clearCertValidatorCallback() method.
