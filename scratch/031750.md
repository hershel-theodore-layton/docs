Commit title: Changes to ServerBiDiStreamFactory to support hhvm/www server bidi streaming
Commit body:
Summary:
- Add a callback-based constructor to ServerBiDiStreamFactory for runtimes
(like HHVM) that need direct access to the stream and sink bridge pointers
instead of using the template-based StreamTransformation pattern. The callback ownership follows the same pattern as ConsumerCallback and
ProducerCallback — the caller owns the callback lifetime.

- Set ServerConsumer template to `QueueConsumer` instead of `CoroConsumer` in both server and sink bridge.
  - This is also similar to ServerGeneratorStreamBridge and ServerSinkBridge to allow non-coroutine based servers to use these classes.
