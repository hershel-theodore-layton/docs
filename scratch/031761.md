Commit title: Re-raise File_provider.File_provider_stale instead of swallowing it
Commit body:
Summary:
`File_provider.File_provider_stale` is an exception specifically designed to propagate up to the recheck loop so it can restart a full init cycle (repopulating the naming table from scratch). However, `handle_exn_as_error` in `typing_check_job.ml` was catching it as a generic exception, recording it as a spurious diagnostic error via `Diagnostics.exception_occurred` instead of letting it propagate. This manifested when a file was deleted/renamed/moved during type checking:
the unbound name check would try to look up a canonical name's position (`Naming_global.GEnv.type_pos` → `get_type_full_pos`), find the file missing, and raise `File_provider_stale`. Instead of triggering a recheck cycle, the exception was swallowed and an internal error was reported.
