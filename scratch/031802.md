Commit title: Optimize stream interceptor per-payload overhead
Commit body:
Summary:
Two optimizations targeting the hot path in stream
interceptor payload processing:

1. Cache QuantileStat pointers in total stat methods.
   addTotalStatValue() did a string-keyed lookup through
   Synchronized<F14NodeMap> (reader lock) on every
   payload. Now each on*TotalComplete() caches the
   pointer in a static local.

2. Move per-interceptor timing to the caller loop.
   Each interceptor created its own stop_watch
   (clock_gettime) internally. Now the caller measures
   time as deltas, reducing clock_gettime calls from
   2N+2 to N+1 for N interceptors.

folly::Benchmark (32 streams, 30s/case, opt):
  Case                    cpu/payload
  StreamBaseline            2.40us
  StreamAsyncInterceptorX1  2.75us (+15%)
  StreamAsyncInterceptorX3  3.09us (+29%)

Per-interceptor per-payload overhead: ~230ns
(down from ~263ns at commit 1, ~13% reduction)
