Commit title: Disable interceptor metric timing by default with RAII timer
Commit body:
Summary:
Add InterceptorTimer RAII class that replaces
folly::stop_watch at all interceptor timing sites.
When InterceptorMetricCallback::isEnabled() returns
false, the timer skips clock_gettime entirely — zero
timing overhead.

Fb303InterceptorMetricCallback now defaults to
disabled (isEnabled() returns false) with an explicit
setEnabled(true) to opt in. NoopInterceptorMetricCallback
also returns false. This eliminates steady_clock::now
calls that were consuming ~50% of CPU in stream
interceptor callbacks.

Call sites remain clean with no conditionals — the
RAII timer handles the enabled/disabled logic
internally.

folly::Benchmark (32 streams, 30s/case, opt):
  Case                    cpu/payload
  StreamBaseline            2.45us
  StreamAsyncInterceptorX1  2.54us (+4%)
  StreamAsyncInterceptorX3  2.64us (+8%)
  StreamSyncInterceptorX1   2.50us (+2%)
  StreamSyncInterceptorX3   2.53us (+3%)

Per-interceptor overhead: ~63ns async, ~27ns sync
(async down from ~127ns at commit 4, 50% reduction;
 sync down from ~103ns, 74% reduction)

Cumulative improvement from commit 1 to commit 5:
  Async per-interceptor: 263ns -> 63ns (76% reduction)
  Sync per-interceptor: N/A -> 27ns (new fast path)
