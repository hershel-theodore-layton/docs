Commit title: Fast path for closed shape unions bypassing subtype checks
Commit body:
Summary:
When unioning two closed shapes (s_unknown_value = nothing), the existing code path performs:
1. ty_equal: O(n) structural comparison — fails because shapes differ
2. is_sub_type_for_union × 2: O(n) full subtype checks — always fail for closed shapes with different field sets
3. negate_type + is_sub_type_for_union × 2: more O(n) checks — always fail
4. union_lists → simplify_union_ → repeats steps 1-3

This is ~9× O(n) wasted work per join point. For files with k conditional shape field assignments (like `if ($value is nonnull) { $logger['field'] = $value; }`), this creates k join points where two shapes differing by one field are unioned, giving O(k × n) = O(k²) total overhead.

The fix adds a fast path in union_ that matches two closed shapes (both have is_nothing s_unknown_value) and jumps directly to union_shapes, bypassing all the expensive subtype and negation checks. This is safe because closed shapes with different field sets cannot have a subtype relationship.

Open shapes are not affected by this fast path — they still go through the full subtype checking path, which is necessary for canonical representation (e.g., shape('x' => int, ...) | shape('x' => int, 'y' => string, ...) should simplify to the former).
