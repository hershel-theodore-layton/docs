Commit title: Optimize shape branch joins with phys_equal
Commit body:
Summary:
# Context

The Hack type checker exhibits O(n²) performance on functions that conditionally assign to many fields of a shape variable. Each `if ($value is nonnull) { $shape['field'] = $value; }` block creates a branch where the type checker must join two shape types at the merge point. The join iterates all fields of both shapes, and since the shape grows with each assignment, the total cost is O(1 + 2 + ... + n) = O(n²/2).

Three operations were hot:
- `TShapeMap.merge_env` in `union_shapes`: O(n log n) list-based merge via `bindings` + `find_opt`
- `shape_type_compare`: O(n) allocation via `TShapeMap.elements` + `List.compare`
- `simplify_subtype_shape`: O(n log n) `TShapeSet` construction with per-field subtype checks

# Solution

Exploit physical equality of shared map structure. When `Stdlib.Map.add` creates a new map by modifying one key, the resulting map shares all tree nodes with the original except O(log n) on the path to the modified key. By checking `phys_equal` on field records, we skip expensive operations for shared fields.

- `union_shapes`: Replace list-based `merge_env` with `TShapeMap.merge` (O(n) vs O(n log n)). Add `phys_equal` on field records to skip `union` for identical fields. Track identity preservation to return the original map pointer when result matches input.
- `shape_type_compare`: Replace `TShapeMap.elements` + `List.compare` with `TShapeMap.compare`. Add `phys_equal` fast-paths on field maps and field records.
- `simplify_subtype_shape`: Replace `TShapeSet.of_list(keys @ keys)` with `TShapeMap.merge` that filters out physically identical fields, reducing per-merge cost from O(n) to O(diff_fields).
