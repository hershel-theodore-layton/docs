Commit title: Replace unsafe from_utf8_unchecked with from_utf8_lossy in emitter
Commit body:
Summary:
Three places in the hackc emitter used `from_utf8_unchecked` on binary string
data (`BString`/`BytesId`). The original authors left FIXME comments noting
this was unsound. `from_utf8_unchecked` doesn't throw or panic on invalid
UTF-8 — it silently creates a `String` that violates Rust's invariant,
causing undefined behavior in any downstream string operation.

`from_utf8_lossy` produces identical output for valid UTF-8 (which covers
~100% of real Hack source) while replacing invalid bytes with U+FFFD instead
of triggering UB.

- `emit_type_constant.rs`: shape field name from `SFlitStr`
- `emit_expression.rs`: method name from string literal in `$obj->$str()` calls
- `constant_folder.rs`: enum class label from `BytesId`
