Commit title: IoUringZeroCopyBufferPool: Set IOBuf capacity to actual received length
Commit body:
Summary:
The IOBuf returned by getIoBuf() was previously created with its capacity
set to bufferSize_, the full per-buffer allocation size. However, since
the kernel may write data immediately after the returned buffer area
within the shared memory region, using the full buffer size as the
capacity is incorrect — it could allow downstream code to read into
memory that could be concurrently modified by the kernel.

Fix this by setting the IOBuf capacity to the actual CQE-reported length
instead of the full buffer size. This ensures the IOBuf accurately
reflects the valid data region and prevents accidental access to adjacent
kernel-managed memory.

While this is unlikely to happen with 4K pages (As it is the smallest
granularity available), this will be more common when using large pages.
