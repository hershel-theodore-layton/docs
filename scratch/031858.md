Commit title: Fix MultiQueryStreamHandler
Commit body:
Summary:
The original code for MultiQueryStreamHandler was bug prone as it played around with the internal synchronization primitives of the connection object and it was written _only_ for the sync client.  TAO (one of the two users of it - the other is Unicorn) is exploring moving to the async client and MultiQUeryStreamHandler just fails outside of the sync client.

I've completely rewritten the code to only be driven off the streaming callbck.  In this version there is a "pipe" (essentially an asynchronous queue) for the query results and inside each query result there is another pipe for the rows and other results being returned.  This version works across all the different clients that we support.

I also moved all the code out of DbResult.[h|cpp] and into its own files.  This makes DbResult much easier to look at with less irrelevant code when not using streaming.
