Commit title: Fix cross-test cache pollution in LLDB pretty-printer tests
Commit body:
Summary:
## Problem

`test_pp_tvs_2` in `PrettyPrintTypedValuesTestCase` has been disabled via
`unittest.skip("Caching is interacting strangely with unit tests")` since
August 2024 (D60883655, 18+ months). The test passes when run individually but
fails when run alongside other tests in the suite. It shows up as a flaky
`WARNING_NO_SIGNAL` on hack diffs.

The three subtests that fail (PersistentDict, Dict, Keyset) exercise dict-like
array iteration, which requires resolving `HPHP::kInvalidDataType` via
`get_cached_global()`.

## Root Cause

`clear_caches()` in `hphp/tools/lldb/utils.py` is called in `setUp()` before
each test case (line 52 of `base.py`). However, it only clears `_target_cache`
(the per-target type/global/module cache) but does NOT clear `_all_caches` --
the list of `memoized` function caches.

The `memoized` decorator (lines 189-206) stores each function's cache dict in
`_all_caches`. When a previous test creates a memoized result based on one
target's state, that stale cache persists into the next test's fresh
`SBDebugger`/`SBTarget`, causing LLDB to fail resolving globals like
`HPHP::kInvalidDataType` because the cached module reference is invalid.

## Fix

Added `for cache in _all_caches: cache.clear()` to `clear_caches()` when called
with `target=None` (the full-reset path used by test setUp). This ensures all
memoized function caches are also cleared between test cases. Removed the
`unittest.skip` decorator from `test_pp_tvs_2`.
