Summary:
# Context

`RepresentableAs<T>` was previously defined only in the type checker's HHI file (`hphp/hack/hhi/representable_as.hhi`), making it available for static type checking but invisible to the HHVM runtime. This is the same gap that `MemberOf` and `EnumClass\Label` had before they were given systemlib definitions — the type exists at check time but not at execution time.

We also need a way to unwrap a `RepresentableAs<T>` back to `T` at runtime. Since `RepresentableAs<T>` is a newtype whose underlying representation *is* `T`, the unwrap operation is the identity function, but it needs to exist in both the HHI (for the type checker) and the systemlib (for the runtime).

# Solution

Following the pattern established by `member_of.ns.php`, a new systemlib file `representable_as.ns.php` defines both the newtype and a `reveal` function in the `HH\Runtime` namespace. The `.ns.php` extension is required by `make_systemlib.sh` because the file contains an explicit namespace block.

The `reveal<T>(RepresentableAs<T> $x): T` function is the identity at runtime — it simply returns its argument. Its purpose is to give the type checker a way to express the `RepresentableAs<T> → T` conversion that would otherwise require an unsafe cast, since the newtype's bound is `mixed` (so `RepresentableAs<T> <: T` does not hold).

The HHI file is updated to declare `reveal` so the type checker knows about it. The systemlib manifest (`php.txt`) and its generated counterpart (`php.bzl`) are updated to include the new file.

A runtime test in `hphp/test/slow/representable_as/` verifies that values pass through `RepresentableAs<T>` typed parameters unchanged, that tuple-to-vec upcasting works at runtime, and that `reveal` returns its argument as-is.
