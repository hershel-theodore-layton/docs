Commit title: Fix flaky Arena.Clear test by priming arena before loop
Commit body:
Summary:
The Arena.Clear test was flaky with a ~23% failure rate (133 failures out of 541 runs in the last 7 days). The address equality assertion at line 323 would fail with addresses consistently shifted by 0x500 (1280 bytes = one block).

Root cause: On iteration 0, the first pass starts with an empty arena (ptr_=nullptr). When a "large" allocation (roundUp(size) > minBlockSize but <= block capacity ~1264 bytes) occurs before any "small" allocation, it goes through allocateSlow which creates a LargeBlock — this does NOT update ptr_/end_, they remain nullptr. After clear(), LargeBlocks are freed but regular blocks are retained, and ptr_ is reset to the start of the first regular block with full capacity (~1264 bytes). In the second pass, the same large allocation now fits through the fast path into the regular block (since ptr_ is valid and the block has capacity), consuming regular block space and shifting all subsequent addresses forward by one block size.

Fix: Prime the arena with a small allocation and clear() before the loop. This ensures at least one regular block exists before the first iteration, so both the first and second passes start from the same state (ptr_ pointing to a full-capacity regular block).
