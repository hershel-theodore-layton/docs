Commit title: Add type-erased readEnum overload using detail::st::enum_find
Commit body:
Summary:
In Json5, enums can be encoded by name. Today, `Json5ProtocolReader::readEnum(EnumType& value)` resolves name <-> value mappings via `TEnumTraits<EnumType>`. However, this does not work with table-based serialization where everything is type-erased.

This diff introduces:

- A non-template `readEnum(int32_t&, detail::st::enum_find<Int>&)` overload on `Json5ProtocolReader` that accepts a type-erased enum lookup table.
- The existing template `readEnum<EnumType>` now delegates to this new overload via `enum_find_instance<EnumType>()`.
- Adds `#include <thrift/lib/cpp2/detail/Enum.h>` and the corresponding BUCK dependency for the `enum_find` symbols.

In follow-up diffs, table-based serialization will pass `enum_find` instances constructed from schema metadata.
