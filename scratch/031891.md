Commit title: add server-side protocol reporting for stoptlsv2 connections
Commit body:
Summary:
stoptlsv2 connections currently show up as plain "Fizz" in scuba because AsyncFizzBase::getSecurityProtocol() unconditionally returns "Fizz". this makes it impossible for the WS benchmarking team to distinguish stoptlsv2 from regular fizz connections in their data.

fix this by:
- adding a setSecurityProtocolOverride() mechanism to AsyncFizzBase so callers can tag transport variants without subclassing
- adding a kSecurityProtocolStopTLSV2 ("Fizz/StopTLSV2") constant to SSLUtil
- setting the override in FizzPeeker::fizzHandshakeSuccess() when getNegotiatedStopTLSV2() is true
- adding "Fizz/StopTLSV2" to the LoggingEventHelper protocol allowlist so it gets proper TLS-style logging

after this change, scuba queries will show "Fizz/StopTLSV2" instead of "Fizz" for stoptlsv2 connections.
