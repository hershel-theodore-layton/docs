Commit title: add security_protocol column to thrift_request_events
Commit body:
Summary:
adds per-request security protocol visibility to the fleet-wide thrift_request_events scuba table. the security protocol string (e.g., "Fizz", "TLS", "stopTLS", "Fizz/StopTLSV2") is read from the connection context at request logging time and written as a new "security_protocol" normal column in scuba. the column auto-creates on first write — no schema migration needed.

follows the same .empty()-guarded addNormalValue pattern used by other string fields in RequestEventLogEntry::getSample() (routingTarget, methodName, etc.).

changes across 3 files (~8 LOC):
- LoggingEvent.h: added std::string securityProtocol field to RequestLoggingContext struct (after cpuConcurrencyControllerMode)
- ThriftRequest.cpp: populated field from reqContext->getConnectionContext()->getSecurityProtocol() with null-safety check in buildRequestLoggingContext()
- EventLogEntry.cpp: logged "security_protocol" column via .empty()-guarded addNormalValue in RequestEventLogEntry::getSample()

re: enum vs string — the entire codebase uses std::string for security protocol (getSecurityProtocol() returns string everywhere, including Cpp2ConnContext, folly::AsyncTransport, and ConnectionEventLogEntry). creating an enum would be a larger cross-cutting change best done separately.

note: thrift_connection_events logs the equivalent value under "tls_implementation". this diff uses "security_protocol" for the request events table as it is more semantically accurate and aligns with the getSecurityProtocol() API name.
