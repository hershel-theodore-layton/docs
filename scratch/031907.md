Commit title: Remove 7 dead SQLite Repo config options
Commit body:
Summary:
HHVM's repo system originally used a SQLite database to store compiled
bytecode. This was replaced with a new binary repo format, but 7 config
options that controlled SQLite-specific behavior were never cleaned up.
These options generate Cfg:: static variables via the config code generator,
but no hand-written C++ code anywhere in hphp/runtime/, hphp/util/,
hphp/hack/, or hphp/facebook/ references them.

**Removed options:**

1. **Repo.Central.FileMode** (default: 0)
   Controlled Unix file permissions (chmod mode) for the central repo SQLite
   file. Searched for `Cfg::Repo::Central::FileMode` — zero references.

2. **Repo.Central.FileUser** (default: "")
   Controlled Unix user ownership (chown user) for the central repo SQLite
   file. Searched for `Cfg::Repo::Central::FileUser` — zero references.

3. **Repo.Central.FileGroup** (default: "")
   Controlled Unix group ownership (chown group) for the central repo SQLite
   file. Searched for `Cfg::Repo::Central::FileGroup` — zero references.

4. **Repo.AllowFallbackPath** (default: true)
   Allowed falling back to an alternative filesystem path when the primary
   repo SQLite database was unavailable. Searched for
   `Cfg::Repo::AllowFallbackPath` — zero references.

5. **Repo.Journal** (default: "delete")
   Controlled the SQLite journal mode (e.g., "delete", "wal", "off") for
   the repo database. The journal mode affects how SQLite handles crash
   recovery and concurrent writes. Searched for `Cfg::Repo::Journal` —
   zero references.

6. **Repo.Commit** (default: true)
   Controlled whether compiled bytecode was committed (written) to the repo
   SQLite database. Setting to false could be used for dry-run compilation.
   Searched for `Cfg::Repo::Commit` — zero references.

7. **Repo.BusyTimeoutMS** (default: 15000)
   Set the SQLite busy timeout in milliseconds, controlling how long SQLite
   would wait when the database was locked by another process. Searched for
   `Cfg::Repo::BusyTimeoutMS` — zero references.

**Verification methodology:**
- Searched for each option's Cfg:: variable name across hphp/runtime/,
  hphp/util/, hphp/hack/, and hphp/facebook/ using Meta's code search tool
- Also searched test/ directory for .opts/.hphp_opts references (none found)
- Confirmed none have PostProcess or Default functions in repo-impl.cpp
- Build verified: `buck build fbcode//hphp/util/configs:` and
  `buck build fbcode//hphp/runtime/base/configs:` both succeed

**Audit scope:** This is part of a comprehensive audit of all 940 runtime
options in hphp/doc/configs.specification. Every option was checked for
references in hand-written C++ code across hphp/runtime/, hphp/util/,
hphp/hack/, and hphp/facebook/ (excluding auto-generated config headers).
Options with globaldata, unitcacheflag, hackc, compileroption, or
repooptionsflag tags were preserved even without runtime C++ references,
as they serve compile-time or serialization purposes. Options used only in
hphp/facebook/ (internal extensions) were also preserved. The full audit
identified 34 dead options across 4 diffs: D98228315, D98228313,
D98228314, D98228312.
