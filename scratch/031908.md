Commit title: Remove 9 phantom config entries that were never wired up
Commit body:
Summary:
These config options exist in configs.specification (which generates Cfg::
static variables), but no hand-written C++ code anywhere in the codebase
references the generated variables. They appear to be options that were
added to the spec but whose implementing code was either never written,
was removed without cleaning up the spec entry, or was moved to a
different mechanism.

**Removed options:**

1. **Eval.FactsExcludeModuleMembership** (default: false)
   Described as "Whether to force the old Facts SQLite DB format."
   Searched for `FactsExcludeModuleMembership` across hphp/runtime/,
   hphp/util/, hphp/hack/, and hphp/facebook/ — zero references in any
   C++ or Rust file. The Facts system does not read this option.

2. **Eval.GetClassBadArgument** (default: 0, owner: emil)
   Described as "0 -> no warning, 1 -> warning, 2 -> exception" for bad
   get_class() arguments. Searched for `GetClassBadArgument` — zero
   references. The enforcement logic was never implemented.

3. **Eval.LogHackcMemStats** (default: false)
   Intended to log hackc compiler memory statistics. Searched for
   `LogHackcMemStats` — zero references. The logging was never wired up.

4. **Eval.DeploymentViolationWarningSampleRate** (default: 1)
   Intended as a sample rate for deployment violation warnings. Searched for
   `DeploymentViolationWarningSampleRate` — zero references. The warning
   system was never implemented or uses a different mechanism.

5. **Eval.ProfileHeapAcrossRequests** (default: false)
   Intended to enable heap profiling across requests. Searched for
   `ProfileHeapAcrossRequests` — zero references. The feature was never
   implemented.

6. **Eval.DumpAst** (default: false)
   Intended to dump the AST during compilation. Searched for
   `Cfg::Eval::DumpAst` — zero references. Other Dump* options (DumpHhas,
   DumpIR, etc.) are alive; this one specifically is not.

7. **Eval.LogThreadCreateBacktraces** (default: false)
   Intended to log backtraces when threads are created. Searched for
   `LogThreadCreateBacktraces` — zero references.

8. **Eval.MemInfoCheckCgroup2** (default: true)
   Intended to control cgroup2 memory info checking. Searched for
   `MemInfoCheckCgroup2` — zero references in runtime/, util/, or
   facebook/. The memory info code does not use this flag.

9. **Server.RequestMemoryMaxBytesSet** (default: false)
    A boolean companion to Server.RequestMemoryMaxBytes, presumably to
    track whether the max was explicitly set. Searched for
    `RequestMemoryMaxBytesSet` — zero references. The runtime reads
    RequestMemoryMaxBytes directly without checking this flag.

**Verification methodology:**
- Each option was searched for by its C++ variable name (e.g.,
  `Cfg::Eval::DumpAst`) using Meta's code search tool across all
  hand-written code in hphp/runtime/, hphp/util/, hphp/hack/, and
  hphp/facebook/
- Generated headers in hphp/util/configs/ were excluded (those are
  auto-generated from the spec file itself)
- None of these options have `globaldata`, `unitcacheflag`, `hackc`,
  `compileroption`, or `repooptionsflag` tags, confirming they serve
  no compile-time or serialization purpose
- No test .opts/.hphp_opts files reference any of these options

**Audit scope:** This is part of a comprehensive audit of all 940 runtime
options in hphp/doc/configs.specification. Every option was checked for
references in hand-written C++ code across hphp/runtime/, hphp/util/,
hphp/hack/, and hphp/facebook/ (excluding auto-generated config headers).
Options with globaldata, unitcacheflag, hackc, compileroption, or
repooptionsflag tags were preserved even without runtime C++ references,
as they serve compile-time or serialization purposes. Options used only in
hphp/facebook/ (internal extensions) were also preserved. The full audit
identified 34 dead options across 4 diffs: D98228315, D98228313,
D98228314, D98228312.
