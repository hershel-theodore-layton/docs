Commit title: Remove 5 dead migration/notice flags and Stats.Memory toggle
Commit body:
Summary:
These options gated migration behaviors, override mechanisms, or stats
toggles that are no longer functional. Each was verified to have zero
runtime references that read the config value.

**Removed options:**

1. **Eval.VecHintNotices** (default: false)
   Raised a notice when a ClsMeth type was passed to a function expecting
   vec/varray. Part of the ClsMeth-to-vec migration which is now complete.
   Searched for `VecHintNotices` across hphp/runtime/ and hphp/util/ —
   zero references. The notice was never emitted by any runtime code.
   Also cleaned up 17 test .opts/.hphp_opts files that set this flag.

2. **Eval.NoticeOnMethCallerHelperUse** (default: false)
   Described as triggering E_USER_WARNING when getClassName()/
   getMethodName() is used on __SystemLib\MethCallerHelper. Searched for
   `NoticeOnMethCallerHelperUse` — zero references in hphp/runtime/,
   hphp/util/, hphp/hack/, or hphp/facebook/. The warning was never
   implemented in runtime code. Also cleaned up 3 test .opts files.

3. **Eval.TaoMigrationOverride** (default: "")
   A string override for TAO (Meta's object storage) migration. Searched
   for `TaoMigrationOverride` — zero references anywhere. The migration
   override mechanism was never consumed by runtime code.

4. **Eval.SRRouteMigrationOverride** (default: "")
   A string override for ServiceRouter route migration. Searched for
   `SRRouteMigrationOverride` — zero references anywhere. Same situation
   as TaoMigrationOverride.

5. **Stats.Memory** (default: false)
   A boolean to enable memory statistics tracking. The admin request
   handler has a "stats-mem" command that toggles this value on/off
   (admin-request-handler.cpp:1288-1291), but no code anywhere reads
   Cfg::Stats::Memory to make any behavioral decision. It is a write-only
   toggle — the admin command changes the variable but nothing observes
   it. In contrast, Stats.Web (used by server-stats.cpp, transport.cpp,
   server-worker.cpp) and Stats.SQL (used by mysql_common.cpp) are
   properly wired up. Removed both the config entry and the dead admin
   handler toggle code.

**Verification methodology:**
- Searched for each option by Cfg:: variable name across hphp/runtime/,
  hphp/util/, hphp/hack/, and hphp/facebook/
- Verified no PostProcess/Default functions exist for these options
- Confirmed no test .opts files reference the removed options (after cleanup)
- Options with no `globaldata`, `unitcacheflag`, `hackc`, or
  `compileroption` tags, confirming no compile-time purpose

**Audit scope:** This is part of a comprehensive audit of all 940 runtime
options in hphp/doc/configs.specification. Every option was checked for
references in hand-written C++ code across hphp/runtime/, hphp/util/,
hphp/hack/, and hphp/facebook/ (excluding auto-generated config headers).
Options with globaldata, unitcacheflag, hackc, compileroption, or
repooptionsflag tags were preserved even without runtime C++ references,
as they serve compile-time or serialization purposes. Options used only in
hphp/facebook/ (internal extensions) were also preserved. The full audit
identified 34 dead options across 4 diffs: D98228315, D98228313,
D98228314, D98228312.
