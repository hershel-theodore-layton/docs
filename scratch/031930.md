Commit title: Fix ~1% flaky failure in heap_vector SimpleSetTest
Commit body:
Summary:
The "bad insert hint" block inserts value 33, checks it, then erases it,
expecting the operation to be size-neutral. However, if 33 was already in
the set from random data (~1% chance with 1000 values from [0, 100000)),
the insert is a no-op while the erase removes the original, causing a net
loss of one element. The subsequent size check then fails.

Fix: use a value outside the random range [0, 99999] so it is guaranteed
not to already be in the set.
