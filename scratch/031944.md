Commit title: Avoid fresh type variable for async lambda return when expected type is Awaitable
Commit body:
Summary:
When checking an async lambda against an expected function type with
`Awaitable<T>` return, the typechecker was generating a fresh type variable
(`Awaitable<#fresh>`) instead of using the expected type directly.

This happened because the expected return type was like-wrapped (e.g.,
`~Awaitable<T>`), represented as `Tunion [dynamic; Awaitable<T>]` in the
locl phase. `force_return_kind` didn't recognize this as a valid Awaitable
return type, falling through to create a fresh type variable.

Fix: In `typing_return.ml`, update `force_return_kind` and `strip_awaitable`
to handle like-wrapped Awaitable types using `try_strip_dynamic`.
