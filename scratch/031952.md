Commit title: Add whisker prototype properties for struct/enum/exception metadata
Commit body:
Summary:
Adds the C++ foundation for migrating struct/enum/exception metadata
codegen from mstch to whisker, without any template or output changes.

C++ changes (t_mstch_java_generator.cc):
- Added `collect_referenced_types()` and `collect_types_from_service_functions()`
  helpers that traverse the type graph of service function signatures to
  collect all transitively-referenced struct, enum, and exception types,
  with cycle detection.
- Added whisker prototype properties on `make_prototype_for_interface`:
  `referenced_structs`, `referenced_enums`, `referenced_exceptions` (flat
  arrays) and `referenced_struct_batches` (batch=20),
  `referenced_enum_batches` (batch=1), `referenced_exception_batches`
  (batch=50) for JVM method size limits.
- Added `batch_whisker_array()` utility for splitting whisker arrays into
  fixed-size batches.
- Added `value_batches` (batch=200) and `has_multiple_value_batches?` on
  `make_prototype_for_enum` for large enums with thousands of values.

Template changes (common/metadata.mustache):
- Added `thrift_type_expression_metadata` partial — identical to
  `thrift_type_expression` except binary is wrapped in ThriftListType
  for legacy parity with the reflection-based ThriftMetadataServiceHandler.

No templates consume these new properties yet — that comes in the next diff.
