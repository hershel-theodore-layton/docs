Commit title: Raise Lint 5655 for __PackageOverride on as expressions, reifiable type consts, and explicit generic arguments
Commit body:
Summary:
Previously, Lint 5655 (__PackageOverride cross-boundary access) only fired for direct type references (e.g. `new MyInternType()`). It did NOT fire for:
- `as`/`?as` expressions (`$x as MyInternType`) — these are a ticking bomb if they exist without lint, since they create hard dependencies on intern types that bypass package boundaries silently
- reifiable type constants (`const type T = MyInternType`)
- explicit generic type arguments (`foo<MyInternType>()`)

These were gated behind `package_allow_*_violations` flags — when the flags were true (the default), the entire package boundary check was skipped, suppressing both errors AND lint.

This diff adds a `LintOnly` variant to the package access `check_reason` type. When a carveout flag is set (true), `LintOnly` runs the package boundary check but only emits lint warnings (Lint 5655), suppressing hard errors. This ensures the lint fires by default for all expression types, making __PackageOverride dependency edges visible regardless of flag settings.

Changed behavior — now raises Lint 5655 by default on:
- `as` expressions
- reifiable type consts
- explicit generic arguments
