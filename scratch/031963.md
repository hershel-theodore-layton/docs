Commit title: Fix typedef-through-container codegen crash
Commit body:
Summary:
The C# code generator crashes when processing typedefs wrapping
container types (e.g., typedef map<K,V> MyMap). The Whisker template
engine resolves predicates like type.map? through typedefs, but
key_type/val_type/elem_type properties are only defined on the actual
container types (t_map, t_list, t_set), not on t_typedef.

Fix by inserting .true_type. indirection before accessing container
element/key/value types in read_expr.mustache and union.mustache,
matching the pattern already used in types.mustache and
write_field.mustache.

Error before fix:

  named 'key_type'. The object with the missing property is:
  <native_handle type='apache::thrift::compiler::t_typedef'>
