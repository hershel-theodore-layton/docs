Commit title: Fix HackLint5644 autofix for always-true/always-false boolean expressions
Commit body:
Summary:
The autofix for HackLint5644 (pointless booleans) was incorrect for the
"always true" (`expr || true`) and "always false" (`expr && false`) cases.
It always stripped the boolean literal and operator, replacing with empty
string. This is correct for "pointless" cases (`expr && true` -> `expr`,
`expr || false` -> `expr`) but wrong for "always" cases: `expr && false`
was autofixed to `expr` instead of `false`, effectively treating literal
`false` as if it were `true`.

The fix makes `check_the_error` return both the diagnostic message and
the replacement text. For "pointless" cases the replacement is still `""`
(strip the literal+operator). For "always true/false" cases the
replacement is `"true"`/`"false"` and the quickfix span covers the entire
expression.
