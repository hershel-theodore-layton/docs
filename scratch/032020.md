Commit title: Force-inline for_each_field_id and StructEncode to close perf gap with generated code
Commit body:
Summary:
When StructEncode was rolled out (D84278317), it replaced hand-generated
per-field write() code with a generic for_each_field_id loop. While
functionally correct, the generated code had regressions on some
benchmarks (up to ~12% slower on nested maps, ~8% on complex structs).

Root cause analysis via disassembly showed that the per-field lambda
passed to for_each_field_id was NOT being inlined by the compiler. The
call chain goes through 3 layers of abstraction:
  1. for_each_field_id creates an intermediate wrapping lambda
  2. for_each_ordinal_impl does pack expansion calling that wrapper
  3. The wrapper calls the user's writeField lambda

Each layer produced a separate non-inlined function call per field,
adding ~18 cycles of overhead each (6 register pushes in prologue,
closure pointer loads, call/ret, 6 register pops in epilogue).

For a 4-field struct, the old StructEncode disassembly showed 4 call
instructions to per-field lambda instantiations:
```
  bc: call  <for_each_field_id lambda for ordinal 1>
  c1: call  <for_each_field_id lambda for ordinal 2>
  c9: call  <for_each_field_id lambda for ordinal 3>
  d4: call  <for_each_field_id lambda for ordinal 4>
```

Fix: add FOLLY_ALWAYS_INLINE throughout the for_each_field_id call
chain, and replace lambdas with FOLLY_ALWAYS_INLINE functors at every
level:

1. **Get.h (shared infrastructure)**: Mark for_each_ordinal,
   for_each_ordinal_impl, for_each_field_id, for_each_field_id_ascending,
   and for_each_field_id_ascending_impl as FOLLY_ALWAYS_INLINE. Replace
   the intermediate wrapping lambda in for_each_field_id with a
   ForEachFieldIdAdapter functor whose operator() is FOLLY_ALWAYS_INLINE.

2. **Encode.h (StructEncode)**: Replace the per-field lambda with a
   WriteField functor whose operator() is FOLLY_ALWAYS_INLINE. StructEncode
   now uses the standard for_each_field_id / for_each_field_id_ascending
   APIs rather than reimplementing pack expansion.

The fix lives in the shared for_each_field_id infrastructure, so any
caller that passes a FOLLY_ALWAYS_INLINE functor will also benefit.

After the fix, the disassembly shows zero per-field functor/lambda
calls — all field writes are inlined into a single monolithic function
body. The only remaining calls are to real operations
(ensureSlowNoinline for buffer growth, throwExceededDepthLimit for
error paths).
