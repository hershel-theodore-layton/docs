Commit title: Eden-backed InformantNotifier
Commit body:
Summary:
This diff adds an Eden backend for InformantNotifier, so that the server informant can use Eden instead of Watchman.

The new code is only used when the new config setting `edenfs_informant_enabled` is true, which I will gradually roll out.

Some details:
- The main difference in behavior is that Eden returns `Changed_commit` events every time we changed commits in any way, intead of the `Changed_merge_base` events that Watchman produces. But luckily, we can treat them exactly the same in `Informant`:  We make our decisions about restarting the server based on the difference between the old and new globalrev when changing merge bases. But when we get a `Changed_commit` that did not change the merge base (e.g, we just moved around our local stack), the globalrev simply stays the same.
- The Eden backend does not propagate state enter/leave events outside of `InformantMonitor`, because it does not know the associated hg revs.
- Eden requires `fbinit`, which is why `MonitorStart` now does `Startup_initializer.init ()` instead of `Folly.ensure_folly_init ()`. The former subsumes the latter.
