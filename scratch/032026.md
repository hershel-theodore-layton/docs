Commit title: Check field-level @cpp.Type directly in templates
Commit body:
Summary:
Add field-aware template partials and properties so the py3 generator can resolve field-level `cpp.Type` annotations explicitly via the field, not the type. This unblocks removing the sema lowering that propagates `cpp.Type` from fields to type nodes (D97165387).

**C++ changes:**
- Added field-level type properties to `make_prototype_for_field`: `type_iobuf?`, `type_iobufRef?`, `type_iobufWrapper?`, `type_flexibleBinary?`, `type_customCppType?`, `type_customCppType`, `type_cythonCustomType`, `type_cppTemplate`, `type_flat_name`, `type_need_cbinding_path?`, `has_field_cpp_type?`.
- `get_cached_type_props` takes explicit `field` parameter for field-level annotation lookups. Non-container types (including typedef-wrapping-containers) use a field-keyed cache (`field_type_properties_`) since their type pointer may be shared across fields with different annotations. Raw containers use the type-keyed cache since each declaration has a unique AST node.
- For typedef-wrapping-containers with field-level annotations, `visit_type` propagates the first field's properties to the type-keyed cache (via `emplace`) so program-level rendering can find them without a field parameter.
- Added `field_custom_ctypedefs` for shared types with field-level `cpp.Type`.

**Template changes:**
- Added 7 field-aware wrapper partials in `common/types.mustache`: `field_python_type`, `field_cython_python_type`, `field_python_is_instance_type`, `field_cython_cpp_type`, `field_cpp_value_type`, `field_cpp_arg_type`, `field_cpp_stack_arg_type`.
- Updated all template call sites to use field-aware partials when rendering field types.

Output-preserving: all fixture outputs are identical before and after.
