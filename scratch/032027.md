Commit title: Fix flaky bidi concurrency test by reducing load
Commit body:
Summary:
The test `test_bidi_service_str_request_concurrently` was flaky (T261113171) because it relied on the server's default queue timeout (100ms), which was too tight for 10,000 concurrent bidirectional stream operations on a single-threaded Python Thrift server, causing intermittent "Load Shedding Due to Queue Timeout" errors.

The fix increases the queue timeout to 1.0s for this test by:
1. Adding an optional `queue_timeout` parameter to `TestServer`, which calls `ThriftServer.set_queue_timeout()` when provided.
2. Passing `queue_timeout=1.0` in the bidi stress test to give the server sufficient time to drain its queue under load.
