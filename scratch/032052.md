Commit title: Index Hack closures as FunctionDeclaration for Glass cost attribution
Commit body:
Summary:
Hack closures (Efun/Lfun, e.g. `async () ==> {}`) were not indexed as declarations in Glean. This meant they had no `DeclarationSpan`, so Glass's `assignCost` algorithm attributed all closure body lines to the enclosing function/method — inflating its cost incorrectly.

In C++, Glean already handles this: lambdas get their own `Cxx::FunctionDeclaration` with name `"(lambda)"` and a proper `Src::Range`, so `assignCost` carves them out from the parent. This diff does the same for Hack.

**Changes:**
- Walk the TAST using `Tast_visitor.iter_with` to find all `Efun`/`Lfun` expressions
- For each closure, emit a `FunctionDeclaration` with synthetic name `(closure)$line_col`, a `FunctionDefinition` with signature info, and `DeclarationLocation`/`DeclarationSpan` facts using the closure's position and `f_span`
- No schema changes needed — `hack.FunctionDeclaration` already documents support for inline functions
- No Glass changes needed — `assignCost` already handles nested definition spans via its stack-based algorithm
