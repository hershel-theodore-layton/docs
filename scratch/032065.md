Summary:
MicroLock was refactored from raw futex calls to folly's
atomic_wait/atomic_notify_one abstraction, but several comments
weren't updated:

- The class doc claimed std::mutex is faster under contention "because
  we need to wake up all waiters when we release." The unlock path
  actually calls atomic_notify_one (wakes one waiter, not all).
  Reword to a more accurate general statement.
- The class doc referenced sleeping "on the lock futex" — now
  atomic_wait.
- lockSlowPath referenced "heldbit(slot)" and "FUTEX_WAKE" — the
  slot concept is gone (single lock per byte), and the actual
  mechanism is waitBit + atomic_notify_one.
