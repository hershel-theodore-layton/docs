Commit title: Add SIOF-safe get_name() and get_class_name() function templates
Commit body:
Summary:
The existing `get_name_v` and `get_class_name_v` inline variable templates
require dynamic initialization and are subject to the C++ Static Initialization
Order Fiasco (SIOF) when accessed during static initialization.

This is currently breaking `cogwheel_ards_adranker_asan_test` in ServiceLab
with a SEGV (null-pointer dereference in `strlen`) during static init, before
`main()` runs. The crash occurs when the `ucache_nvm_usecase_config` folly
setting serializes its default Thrift struct value via `SimpleJSONProtocolWriter`,
which reads field names from the not-yet-initialized `get_name_v`. See
P2257849800 for the crash log.

This adds `get_name<T, Id>()` and `get_class_name<T>()` function templates
that compute the value on demand, avoiding SIOF entirely. This follows the
same pattern as D91010117 which added `getName()` to the reflection layer.

The old variables are preserved for backward compatibility but annotated
with deprecated comments directing users to the new functions.

See also: D91010117
