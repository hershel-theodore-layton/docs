The second `contains()` overload (for containers with `key_type`) has a fallback
`else` branch that calls `contains(container, key)` when the container lacks both
`.contains()` and `.find()` methods. This was intended to dispatch to the first
overload (generic linear-search), but because the second overload is a better match
for containers with `key_type`, it recurses into itself infinitely, causing a stack
overflow.

This is triggered for any container type that has a `key_type` typedef but lacks
both `.contains()` and `.find()` member functions.

The fix inlines the linear-search logic directly in the fallback path, avoiding
the ambiguous overload dispatch entirely.
