Commit title: Fix bidi stream sink cancellation not propagating promptly
Commit body:
Summary:
When a server bidi handler finished processing, the `ServerSinkGenerator` (and its C++ `IOBufSinkGenerator`) was not released promptly — cleanup relied on GC. This meant the C++ cleanup guard that notifies the client the sink is done wouldn't fire, causing the client to hang.

This diff replaces the `async for` loop in runtime with `CloseableGenerator` in the server-side sink handler code, and adds logic to distinguish between `CancellationError` from user handler code (should be `ApplicationError`) from  `CancellationError` from external cancellation (should be end of stream), e.g., due to channel disconnect.

Changes:
- `bidistream.pyx`/`sink.pyx`: Pass `input_gen`/`sink_elem_gen` directly to the callback instead of wrapping in `lambda:`. Remove the intermediate `invoke_cpp_iobuf_gen` async generator wrapper.
- `closeable.pyx`: Don't set `_closed` on `CancelledError` (only `StopAsyncIteration` and `aclose()` set it). This lets `runGenerator` distinguish framework cancellation (end-of-stream) from user-raised `CancelledError` (error).
- `py_promise.pyx`: Type `generator` param as `CloseableGenerator`. Check `generator._closed` on `CancelledError`: if `True`, treat as end-of-stream; if `False`, report as error. Add `closeable` cimport.
- `sink.pyx`: Guard `future.add_done_callback` with `x.cancelled()` check before calling `x.exception()`. Remove dead `try/except CancelledError` around `return future`.
- `services.mustache`: Update sink and bidi wrappers to accept async generators directly instead of `Callable[[], AsyncGenerator]`.
- `service_arg_types.mustache`: Replace async generator `_fbthrift__sink_elem_handler` with `CloseableGenerator` construction.
- `sink_imports.mustache`: Add `CloseableGenerator` and `UserExceptionMeta` imports.
- `BUCK`: Add `closeable` dep to `py_promise` target.

Test changes:
- `test/bidi.py`: Add `test_bidi_server_handler_raises_cancelled_error` and `test_bidi_sink_cancel_propagates_during_blocked_anext`. Remove `expectedFailure` decorator.
- `test/sink.py`: Remove `expectedFailure` decorator from `test_sink_cancel_propagates_during_blocked_anext`.
