Commit title: Fix server-side non-determinism on sink exception
Commit body:
Summary:
Add `aclose()` to `ServerSinkGenerator` so the server-side sink input
stream can be explicitly closed, releasing the C++ `IOBufSinkGenerator`
resources promptly. Without this, a reference loop between the C++
`ServerBiDiSinkBridge` and the Python generator chain can cause a deadlock
when the server handler raises an exception. This only occurred sometimes.

Note that we must manually call `aclose` when `raise ex` from server-side `async for _ in _iobuf_agen` because an exception does not call `aclose` on `_iobuf_agen` automatically. Previously, we were relying on GC, resulting in the non-determinism.

**Bonus**: quiet a noisy print on server side when client sink throws expected exception.

The fix chain:
- `sink.pxd/pyx`: Change `_cpp_gen` to `unique_ptr` and add `close()`/
  `aclose()` to `ServerSinkGenerator` so C++ resources can be destroyed
  on demand.
- `closeable.pxd/pyx`: Add `_cleanup_gen` attribute and
  `_register_cleanup()` so `CloseableGenerator.aclose()` propagates
  cleanup to the linked `ServerSinkGenerator`.
- `bidistream.pyx`: Register `input_gen` for cleanup via
  `_register_cleanup()` when the output generator is created.
- `py_promise.pyx`: Call `await generator.aclose()` in `runGenerator`'s
  `except Exception` handler to break the reference loop before
  reporting the error to C++.
