Commit title: set affects_prod_build=false for symbols in type/newtype aliases
Commit body:
Summary:
Similarly to D94516856 which tracked symbols that don't affect the prod build for class pointers, nameof, and attributes, this diff extends the same logic to type and newtype aliases.

**Type aliases (`type`):**
When `package_allow_typedef_violations` is set to `true` (the default), symbols appearing on the RHS of type alias definitions (e.g., `type MyType = ForeignPackageType`) will have `affects_prod_build = false`, since the prod build does not follow typedef dependencies in that configuration. When `package_allow_typedef_violations` is `false`, these symbols retain `affects_prod_build = true`.

**Newtype aliases (`newtype`):**
Symbols appearing on the RHS of newtype definitions (e.g., `newtype MyType = ForeignPackageType`) always have `affects_prod_build = false`, regardless of the `package_allow_typedef_violations` config. This is because newtypes create an opaque type boundary that prevents the underlying type from leaking across packages.

This is achieved by:
- Adding `in_typedef` and `in_newtype` flags to the visitor in `identifySymbolService.ml`
- Setting `in_typedef` to `true` in `on_typedef` (for the body, not the declaration name)
- Setting `in_newtype` to `true` when the typedef has `Opaque` or `OpaqueModule` visibility
- Checking these flags in `on_class_id` (for `CI` class references) and `on_Happly` (for type hints)
