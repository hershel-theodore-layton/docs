Commit title: set affects_prod_build=false for symbols in is/as expressions
Commit body:
Summary:
Extends the `affects_prod_build` tracking in `identifySymbolService.ml` to handle `is` and `as` expressions.

**`is` expressions:**
Symbols appearing on the RHS of `is` expressions (e.g., `$x is Foo`) always have `affects_prod_build = false`, since the prod build does not depend on type refinements.

**`as` expressions:**
Symbols appearing on the RHS of `as` expressions (e.g., `$x as Foo`) have `affects_prod_build = false` when `package_allow_as_expression_violations` is `true` (the default). When `false`, they retain `affects_prod_build = true`.

This is achieved by:
- Adding `in_is_expression` and `in_as_expression` flags to the visitor
- Overriding `on_Is` and `on_As` to set these flags when visiting the RHS hint
- Checking these flags in `on_class_id` (CI) and `on_Happly`
