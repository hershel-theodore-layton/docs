Commit title: Support percentile-based total latency distribution in LatencyInjectionRoute
Commit body:
Summary:
Add a new `total_latency_percentile_ms` config field to LatencyInjectionRoute that accepts an array of [percentile, latency_ms] tuples. For each request, a random number is drawn uniformly in [0, 100) and the corresponding percentile bucket's latency is used as the total latency target (step function). This enables simulating realistic latency distributions instead of a single fixed value.

If both `total_latency_ms` (fixed) and `total_latency_percentile_ms` are set, the fixed value takes precedence.

Example JSONM config:
```
{
  "type": "LatencyInjectionRoute",
  "child": {
    "type": "SRRoute",
    "service_name": "my_service",
    "server_timeout": 1000
  },
  "total_latency_percentile_ms": [[50, 10], [90, 50], [99, 100], [99.9, 200]]
}
```

This injects total latency sampled from the distribution:
- 50% of requests: 10ms
- 40% of requests (p50-p90): 50ms
- 9% of requests (p90-p99): 100ms
- 0.9% of requests (p99-p99.9): 200ms

The support is meant for use in AWS EBS test for HHVM by simulating EBS latency.
