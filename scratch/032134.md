Commit title: thrift/cmake: decouple thriftprotocol from the networking stack
Commit body:
Summary:
thriftprotocol linked PUBLIC against the thrift INTERFACE target, which
transitively pulls in async -> wangle -> fizz. It also had a direct dep
on wangle::wangle. Neither is needed: the protocol source files only use
folly, fmt, glog, and thrift-core headers.

Removing those deps breaks the circular dependency that forced rpcmetadata
and thriftmetadata to duplicate five protocol source files
(CompactProtocol.cpp, JSONProtocolCommon.cpp, TBase64Utils.cpp,
TProtocolException.cpp, VarintUtils.cpp) as a workaround. Those targets
now link thriftprotocol directly instead.

After this change, consumers that only need Thrift serialization
(CompactSerializer, field access, generated *_types.h) can build
thriftprotocol without compiling wangle, fizz, or mvfst. The thrift
INTERFACE library and thriftcpp2 are unchanged — they continue to bundle
the full networking stack for consumers that need it.

This matches the structure already used in the Buck build, where
//thrift/lib/cpp2/protocol:protocol has no dependency on wangle or fizz.
