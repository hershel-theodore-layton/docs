Commit title: Fix binary field type bug in ThriftMetadataServiceHandler and codegen
Commit body:
Summary:
The legacy `ThriftMetadataServiceHandler.convertType()` incorrectly reports thrift `binary` fields backed by Java `byte[]` as `list<binary>` instead of `binary` (THRIFT_BINARY_TYPE). This breaks the thrift-proxy's TypedTranscoder for any Java service with `binary` struct fields. It also break Thrift Fiddle (https://www.internalfb.com/thrift_fiddle)

## Repro:
Run thrift fiddle with `datainfra.metastore` call `get_partition_by_name`   with
```
{
    "db_name": "instagram",
    "tbl_name": "test_yundin_schema_undo_table_1",
    "part_name": "ds=2026-04-06"
}
```
{F1988012677}

Affected Metastore Types (dumped from Thrift Fiddle)
PartitionInternalProperties, DeltaEntity, InternalGetMetadataObjectResponse

## Root cause
`convertType()` line 356 used reference equality (`==`) to check `swiftType == ThriftType.BINARY`. The static `ThriftType.BINARY` constant has `javaType=ByteBuffer.class`, but Java-Swift codegen maps thrift `binary` to `byte[]`, producing a coerced ThriftType with `javaType=byte[].class`. The `==` check failed, falling through to a "special case for byte[]" branch that incorrectly wrapped the type as `ThriftListType(THRIFT_BINARY_TYPE)`.

## Impact
The Hive metastore's `PartitionInternalProperties.rowIdComponent` (thrift `binary`) was reported as `list<binary>` in metadata. The nest thrift-proxy's `TypedTranscoder` overwrites wire types with metadata types, so it called `readListBegin()` on a single binary value, reading garbage as the list header and crashing with `TProtocolException: Not enough bytes`.

## Fix
- Legacy handler (`ThriftMetadataServiceHandler.java`): replaced the reference  equality check with `getProtocolType() == ThriftProtocolType.BINARY`, which  covers both `ByteBuffer` and `byte[]` representations. Removed the dead  `list<binary>` wrapping code.
- Codegen template (`metadata.mustache`): the `thrift_type_expression_metadata`  partial deliberately replicated the legacy bug "for parity." Updated it to  emit `THRIFT_BINARY_TYPE` directly, matching `thrift_type_expression`.
