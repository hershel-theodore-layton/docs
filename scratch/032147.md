Commit title: Fix FOLLY_NOINLINE for CUDA Clang compilation
Commit body:
Summary:
When Clang compiles CUDA code (`-x cuda`), CUDA's `host_defines.h` defines `__noinline__` as a macro expanding to `__attribute__((noinline))`. This causes folly's `FOLLY_NOINLINE` (`__attribute__((__noinline__))`) to expand to the invalid `__attribute__((__attribute__((noinline))))`, breaking all CUDA targets that include folly headers.

The fix mirrors the existing `__HIP_PLATFORM_HCC__` workaround: when `__CUDA__` is defined (Clang's CUDA mode), use `__attribute__((noinline))` instead of `__attribute__((__noinline__))`. Both spellings are equivalent for GCC/Clang, but only the former avoids the macro expansion conflict.
