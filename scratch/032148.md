Commit title: Annotate fire-and-forget (oneway) calls on request edges
Commit body:
Summary:
Oneway Thrift calls create a request edge (ecs=rq) but intentionally never
produce a response edge (ecs=rp). This is indistinguishable from a dropped
edge, making CPA and flamegraph unable to filter out intentional
fire-and-forget calls from the critical path.

This diff adds an `is_oneway` core property annotation on request edges
for oneway calls. The annotation flows through the existing Thrift client
event handler infrastructure:

1. `TClientEventHandler::markCallAsOneway()` — new no-op base hook
2. `ThriftClientBase::sendImplHelper()` — already has is one way, so passes this up the stack
3. `ThriftContextPropClientEventHandler` — overrides to store per-sequence
   oneway state, then annotates the edge in `generatePostSendAnnotation()`

Also adds `setIsOneway()` to Hack `EdgeProperties` for
direct annotation by other instrumentation paths.

A follow-up diff will add the `PROP_IS_ONEWAY` constant to the
artillery2_constants thrift file in the configerator repo.
