Commit title: ensure inner typing of typedefs matches outer typing
Commit body:
Summary:
Previously, thrift container typedefs like `list<list<X>>` generated inconsistent inner typing: the outer container used the concrete type (`ImmutableList`) but inner containers used abstract types (`Sequence`), producing `ImmutableList[Sequence[X]]`.

This diff changes `typedef_pep484_type.mustache` to use `pep484_field_return_type` (instead of `pep484_type`) for inner element, key, and value types. This makes the inner types concrete, matching the outer container: `ImmutableList[ImmutableList[X]]`, `ImmutableMap[K, ImmutableMap[K2, V]]`, etc.

To ensure thrift container constructors continue to accept Python builtins (e.g. `SetI32Lists({(1,2,3)})` or `StrI32ListMap({"bar": [0,1]})`), this diff also widens the `__init__` parameter types in `types.pyi`:
- `ImmutableList.__init__`: `Iterable[ElemT]` → `Iterable[object]`
- `ImmutableSet.__init__`: `Iterable[ElemT]` → `Iterable[object]`
- `ImmutableMap.__init__`: `Mapping[KeyT, ValT]` → `Mapping[KeyT, object]`

Struct `__init__`/`__call__` parameters are unaffected — they already use abstract types (`Sequence`, `Mapping`, `AbstractSet`) via `aliased_pep484_type`, and continue to accept plain Python containers.
