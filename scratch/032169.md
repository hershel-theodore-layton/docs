Commit title: Remove @cpp.Type sema propagation for container fields
Commit body:
Summary:
sema copies field-level `cpp.Type` annotations onto shared container type nodes in the AST. This is a mutation with global side effects — the type node is shared, so one field's annotation leaks to every other field that uses the same container type. The only reason this hasn't caused bugs is that every field with `cpp.Type` on a given container type happens to use the same annotation (the sema visitor even asserts this).

This diff deletes the sema propagation and makes each generator look up `cpp.Type` from the field node directly:

**sema.cc**: Delete the field visitor that copies `cpp.Type` from fields to container type nodes.

**cpp2 generator**: Introduce two thin wrapper types — `cpp2_rendered_type` and `cpp2_rendered_const_value` — that carry field context for field-aware rendering:

- `cpp2_rendered_type` exposes only field-aware properties (`cpp_standard_type`, `cpp_type`) and delegates everything else to the underlying `t_type` handle via a `.type` property.
- `cpp2_rendered_const_value` exposes only context-aware properties (`type`, `structured?`, `structured_elements`/`list_elements`/`map_elements`, `referenceable_from?`) and delegates everything else to the underlying `t_const_value` handle via a `.value` property.

Templates access delegated properties through `value.value.bool?`, `value.type.type.cpp_adapter`, etc. This avoids duplicating the full `t_const_value`/`t_type` prototype definitions.

**python_capi generator**: Make `is_capi_eligible_type` accept an optional field parameter so it can check field-level `cpp.Type` directly instead of relying on propagation to the type node.

Zero output change across all generators (84k cpp2 targets, 55k python_capi targets).
