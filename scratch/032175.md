While working on D100288058 I encountered the crash as seen in P2269754018. It seems this particular V2 server triggered this issue. This diff is similar to D99722198, just for another call site.

As for the root cause quoting claude...

> When the backend server finishes sending responses, it sends a stream-complete frame. The Rocket client processes this and transitions: StreamAndSinkOpen → OnlySinkOpen. Then the server sends a second complete frame (a protocol-level quirk of the sink<>, stream<> method type). The Rocket client tries to call onStreamComplete again from OnlySinkOpen, which hits a DCHECK and crashes.

From the outside, not sure why 2 complete frames would ever be sent but not a bidi expert. Given D99722198 fixed a seemingly similar issue the same way, it seems there a few other call sites to catch.
