Commit title: Expose type enforcement query in hh
Commit body:
Summary:
Add an `--enforcement-at-pos-batch` query to `hh_client` and `hh_single_type_check` that reports whether the runtime enforces the declared type at a given source position and, if so, what the enforced types are.

## Result type

The result is an ADT: `Enforced of enforced_type list | Unenforced`. Enforced positions carry the list of types enforced at runtime. Unenforced positions carry no type information.

## Supported positions

- **Type annotations**: cursor on a type hint (parameter, return, property)
- **Function call arguments**: parameter type from the function declaration
- **Static method call arguments**: `Class::method()`, `self::`, `static::`, `parent::`
- **Instance method call arguments**: `$this->method()` always; `$obj->method()` when the receiver type is exact or the TAST was checked once (no SDT) and the type is not like-typed
- **Constructor arguments**: `new ClassName()`, `new self()`; excludes `new static()` and `new $expr()`
- **Return expressions**: enclosing function's declared return type
- **Property assignment RHS**: `$this->prop = expr` always; `$obj->prop = expr` when receiver is trusted (same rules as instance methods)
- **Array index expressions**: `arraykey` (hardcoded)

## Unpessimised declarations

All declaration lookups bypass SDT pessimisation to report the programmer-written type:
- Functions: `Decl_provider_internals.get_fun_without_pessimise`
- Methods/constructors/properties: shallow class declarations via `Decl_provider_internals.get_shallow_class`, resolving inherited members through `ce_origin`

## Effectively enforced collection types

Collection types with top-type arguments are reported as `Enforced` even though `Typing_enforceability` considers them unenforced: `dict<arraykey, mixed>`, `vec<mixed>`, `keyset<arraykey>`, and legacy equivalents (`Map`, `Vector`, `Set`, `KeyedContainer`, `Container`). The runtime enforces the container type and the arguments are trivially satisfied.

## Generics with upper bounds

For generics with enforceable upper bounds (e.g. `T as I as J as arraykey`), ALL enforceable bounds are returned in the result, not just the first.

## Trusted receiver types

Instance method calls and property assignments on non-`$this` receivers are supported when the inferred receiver type is trustworthy:
- **Exact types** (e.g. from `new C()`): always trusted
- **Non-like types when checked once**: trusted when `under_dynamic_assumptions` is `None` (no SDT double-check)
