Commit title: Extend CPU-thread compression to stream subsequent responses for AsyncGenerator path
Commit body:
Summary:
Extends the CPU-thread compression support from D97570261 to cover subsequent stream items (not just the first response). Currently supports the AsyncGenerator path (ServerStream<T>), which is the most common server stream pattern.

Changes:
- ServerStreamDetail.h: Add std::optional<CompressionConfig> parameter to ServerStreamFactoryFn and store it in ServerStreamFactory for forwarding to the stream lambda. Add StreamCompressionContext struct, makeCompressionContext(), and compressStreamItem() helpers.
- ServerStreamDetail.cpp (new): Implements makeCompressionContext() (resolves CompressionConfig into a cached codec + algorithm) and compressStreamItem() (compresses a stream item on the CPU thread if it exceeds the size limit, with CUSTOM algorithm exclusion and error recovery).
- ServerGeneratorStreamBridge.h: Thread compressionConfig into generateWith() coroutine. Call compressStreamItem() on each stream item in both the WithHeader and non-WithHeader branches of the generation loop.
- RocketThriftRequests.cpp: Pass CompressionConfig to the ServerStreamFactory when the thrift_server_compress_response_on_cpu flag is enabled.
- RocketStreamClientCallback.cpp: In onStreamNext, when cpuCompressionEnabled_ is set, bypass applyCompressionConfigIfNeeded() — use makePreCompressedPayload() to directly serialize metadata and send the already-compressed data.
- RocketServerUtil.h/cpp: Add makePreCompressedPayload() overload for StreamPayloadMetadata (no FDs).
- ServerGeneratorStreamBridge.cpp, ServerPublisherStream.h: Accept the new CompressionConfig parameter in their lambdas (unused — these paths have different threading models where items are pushed from user-controlled threads).

Gated behind the same thrift_server_compress_response_on_cpu THRIFT_FLAG as D97565705.
