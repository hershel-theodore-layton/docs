Commit title: Extend CPU-thread stream compression to ServerPublisherStream and ProducerCallback paths
Commit body:
Summary:
Extends the CPU-thread compression of subsequent stream items (from D97585164) to cover all server stream paths. D97585164 only covered the AsyncGenerator path; this diff adds support for ServerPublisherStream and ProducerCallback.

Changes:
- ServerStreamDetail.h: Extract compressStreamItem() into a shared inline free function, eliminating duplication between stream implementations. Includes CUSTOM algorithm exclusion and try/catch error recovery (falls back to IO-thread compression on failure).
- ServerPublisherStream.h: Store CompressionConfig with atomic flag for thread-safe access from publisher threads. Compress items in both publish() overloads (typed and raw StreamPayload) on the publisher's thread before pushing to the queue.
- ServerGeneratorStreamBridge.h/.cpp: Add pushStreamPayload() and pushComplete() public methods for ProducerCallback producers to get CPU-thread compression transparently. Store compression config on the bridge, set in the fromProducerCallback lambda before provideStream() is called. Producers using raw serverPush() continue to work but fall back to IO-thread compression.
- ServerGeneratorStreamBridge.h: Remove the private compressStreamItem() static method (now uses the shared one from ServerStreamDetail.h). Clean up includes that moved to ServerStreamDetail.h.

Thread safety for both paths uses the same pattern: config is written once (release) on the IO thread in the ServerStreamFactory lambda, read (acquire) from publisher/producer threads. Items published before the config is set fall back to normal IO-thread compression.

Gated behind the same thrift_server_compress_response_on_cpu THRIFT_FLAG as the parent diffs.
