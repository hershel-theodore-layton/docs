Commit title: Add the ability to parse field name as "field-name (field-id)" (1): share enum value and field name parser
Commit body:
Summary:
Today, we can parse both "enum-name", "enum-name (enum-value)" and "(enum-value)". However, for field name, we can only parse "field-name". In this stacked diffs, we will add the ability to parse "field-name (field-id)" as well as "(field-id)".

# Changes

This diff replaced

```
  struct EnumReadResult {
    std::string name;
    std::optional<std::int32_t> value;
  };

  // Parse an enum string in "NAME (value)", "(value)", or "NAME" format.
  static EnumReadResult parseEnumString(std::string s);
```

with

```
  template <typename T = std::int32_t>
  struct IdentifierReadResult {
    std::string name;
    std::optional<T> value;
  };

  // Parse a string in "NAME (value)", "(value)", or "NAME" format.
  // Used for both enum values and field identifiers.
  template <typename T = std::int32_t>
  static IdentifierReadResult<T> parseIdentifierString(std::string s);
```

So that we can reuse `parseIdentifierString` to parse both enum and field name.
