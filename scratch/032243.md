Commit title: Permit refinements in type aliases and type constants under an experimental feature flag
Commit body:
Summary:
Type refinements (`I with { type T = ... }`) were previously banned on the RHS of type aliases (`type T = ...`) and type constants (`const type T = ...`). This removes that restriction under experimental feature flag `with_refinement_alias` while keeping the ban on refinements in is/as expressions. Type structure support was added in the runtime in D94346411.

This requires the feature flag `with_refinement_alias` to be set to `OngoingRelease` or set to `Preview` with a file-level attribute `<<file:__EnableUnstableFeatures('with_refinement_alias')>>`.

Previously, file-level attributes weren't generally available during typechecking phases. I've moved some logic out of `typing.ml` into `typing_check_job.ml`.
