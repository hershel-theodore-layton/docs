Commit title: Add parsing for Priority header required rate.
Commit body:
Summary:
This diff add support for parsing the required rate parameter ("r"), an extension to the RFC 9218 HTTP Priority headers.

This parameter specifies the minimum bandwidth required by a stream, measured in bits per second.

Example header: `Priority: u=0,i,r=5000000 (5 Mbps)`

## Parsed values of required rate
- r > 0:       `requiredBps` set to the parsed value
- r = 0:       `requiredBps = 0` (treated as not specified)
- r omitted:   `requiredBps = 0` (not specified)
- r < 0:       Entire priority header rejected
- r malformed: Entire priority header rejected (structured header parsing failure)

## Changes
- Added `requiredBps` field (as plain `uint64_t`, where `0` = not specified) to `HTTPPriority` struct, consistent with the `orderId` pattern
- Updated `HTTPPriority` constructors to accept the new rate parameter (default `0`)
- Extended `httpPriorityFromString()` to parse the `r` parameter from priority headers
- Updated `httpPriorityToString()` to serialize the rate parameter when `> 0`
- Updated equality operator to include the new field in comparisons
