Commit title: Store required rate in HQSession and expose via getHTTPPriority().
Commit body:
Summary:
This diff caches `requiredBps` on `HQStreamTransportBase` in `onHeadersComplete()` and includes it in the `HTTPPriority` returned by `getHTTPPriority()`. Currently, `getHTTPPriority()` reconstructs `HTTPPriority` from the QUIC socket's stream priority, which only stores urgency, incremental, and order — the `requiredBps` parameter from the Priority header's `r=` is lost. Caching it enables downstream consumers — such as RevProxy response rules (D96933378) — to read it via `conn->getDownstreamHTTPPriority()` and apply egress rate limiting.

## Behavior
**`requiredBps` cached:**
- In `onHeadersComplete()`, always from the parsed headers, regardless of whether a buffered `PRIORITY_UPDATE` arrived first

**Why not from `PRIORITY_UPDATE`:**
- `PRIORITY_UPDATE` frames never contain `r=` (see D93739207), and the QUIC transport's `setPriority` drops `requiredBps` — so it must be cached directly from headers

## Changes
- Added `uint64_t requiredBps_{kDefaultRequiredBps}` member to `HQStreamTransportBase`
- In `onHeadersComplete()`, always cache `requiredBps` from parsed headers
- Updated `getHTTPPriority()` to include `requiredBps_` in the returned `HTTPPriority`
- Updated tests to verify `requiredBps` is exposed via `getHTTPPriority()`
