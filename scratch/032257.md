Commit title: Add UNDER_ACL and ACLs thrift types for getAttributesFromFilesV2
Commit body:
Summary:
Defines the thrift contract for two new getAttributesFromFilesV2
attribute bits that surface path-level ACL metadata.

## UNDER_ACL (bit 10)

Answers "does any ACL apply to this path?" Resolved from tree metadata
— only tree fetches are needed, avoiding the separate access-check
endpoint. Tree fetches may still require network calls if uncached.
Uses UnderAclOrError (not a bare bool) since tree fetches can fail.

Semantically distinct from the existing isRestricted enforcement flag:
underAcl is a structural property of the repo (user-independent), while
isRestricted is a runtime signal that the user was denied access.

## ACLs (bit 11)

Returns an AclInfo struct containing a list of strongly typed AclEntry
objects. Each AclEntry carries its own restrictionRoot, repoRegionAcl,
and optional requestAcl — making each entry self-describing. Requires
hitting a separate endpoint for ACL metadata.

## Design notes

- UnderAclOrError / AclInfoOrError follow the standard OrError union
  pattern used by every other attribute.
- AclEntry is a strongly typed struct replacing the earlier parallel-list
  design (repoRegionAcls + requestAcls).
- restrictionRoot lives per-AclEntry (not top-level) because each nested
  ACL comes from a different ancestor directory. Matches SCS model.
- requestAcl is optional string — absent means no request mechanism
  exists for that ACL. Matches upstream AclManifestEntryBlob pattern.

No behavioral change — subsequent diffs wire these into the C++
attribute pipeline, Rust client, and CLI.
