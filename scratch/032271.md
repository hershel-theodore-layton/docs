Commit title: Fix APK size regression from getEnumFieldExt template bloat
Commit body:
Summary:
D97831968 introduced `getEnumFieldExt<EnumType>()` which creates a duplicate `enum_find<int32_t>` instance for every thrift enum used in table-based serialization. This is redundant with `enum_find_instance<E>()` which already exists for TEnumTraits.

Per enum, the duplication costs ~150-250 bytes of code (4 static locals with guard variables, a lambda for vector init) and ~136 bytes of data (duplicate enum_find, vector<int32_t> copy, metadata). Across all enums in the Oculus Assistant app, this totaled ~382KB compressed APK size regression (T264167819).

# Fix

for the common case where the underlying type is int32_t (vast majority of thrift enums), reuse the existing `enum_find_instance<E>()` singleton instead of creating a duplicate.

For the rare case of enums with non-int32 underlying types (e.g. uint8_t via `cpp.EnumType`), the original logic is preserved since the table-based serializer needs `enum_find<int32_t>` and `enum_find_instance` returns a different type.
