Commit title: better type checking for nested container constructor
Commit body:
Summary:
Previously, `ImmutableList`, `ImmutableSet`, and `ImmutableMap` `__init__` constructors accepted `object` for element/value types, making them too permissive for type checking. This diff tightens those signatures to use the proper type parameters (`ElemT`, `ValT`).

For nested container typedefs like `typedef map<Company, list<City>> CompanyLocationsMap`, the type alias approach (`CompanyLocationsMap = ImmutableMap[Company, ImmutableList[City]]`) doesn't allow the `__init__` to accept mutable equivalents for nested types. With the tightened `__init__`, constructing a `CompanyLocationsMap` would require passing `ImmutableList[City]` values rather than plain `Sequence[City]`.

To solve this, nested container typedefs now generate a class newtype instead of a type alias, with an explicit `__init__` that accepts mutable-equivalent types:

```python
class CompanyLocationsMap(ImmutableMap[Company, ImmutableList[City]]):
    def __init__(self, __items: Mapping[Company, Sequence[City]] = ...) -> None: ...
```

Non-nested container typedefs (e.g. `map<str, str>`) remain as simple type aliases.
