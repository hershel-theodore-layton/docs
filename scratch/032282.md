Commit title: Replace usages of deprecated AST method t_type_ref::get_type in Java deprecated concat generator
Commit body:
Summary:
Replace usages of deprecated method `t_type_ref::get_type`.

In generators, `t_type_ref` will always be either `empty` or `resolved`, because the Thrift compiler does not invoke the generator for ASTs that don't pass semantic validation.

For resolved typedefs, we can translate `get_type` into the following using `t_type_ref`'s `deref`, `operator*` and `operator->`:

| Before | After |
| --- | --- |
| `t_type* = ref.get_type()` | `t_type* = &ref.deref()` |
| `t_type& = *ref.get_type()` | `t_type& = *ref` |
| `ref.get_type()->foo()` | `ref->foo()` |

For truly nullable cases (where the type ref might be empty/unresolved, due to being optional - e.g. `t_function::interaction`), we can translate `ref.get_type()` to the equivalent `t_type* = ref.resolved() ? &ref.deref() : nullptr`.
