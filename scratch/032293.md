Summary:
Follow-up to the small_vector_test migration to replace the env workaround
with a proper library fix.

xplat/folly/container/small_vector.h:

1. makeSizeInternal (line 1339): change annotate_object_leaked(newh) to
   detail::annotate_object_leaked_impl(newh).

   small_vector already knew its internal buffer pointer is stored in a
   non-standard compact layout (e.g. policy_size_type<uint32_t>) that LSAN's
   conservative scanner cannot find. It calls annotate_object_leaked() to
   compensate. However, the public API is gated on kIsSanitizeAddress in the
   calling TU. Under no-san builds (xplat CXX tests use
   set_host_platform_decorator(sanitizers=False)), kIsSanitizeAddress=false so
   the call is a no-op. detail::annotate_object_leaked_impl is unconditional
   -- it stores the raw malloc pointer in a globally-reachable unordered_map
   singleton that LSAN's conservative scan finds at program exit.

2. freeHeap (lines ~1471/1474): change both annotate_object_collected(vp)
   calls to detail::annotate_object_collected_impl(vp).

   Symmetric cleanup for (1). Without this, each reallocation adds an entry
   to the global map but never removes it, causing stale entries to accumulate
   in long-running no-san processes.

xplat/folly/container/test/BUCK: remove env = {ASAN_OPTIONS: detect_leaks=0}
from small_vector_test -- no longer needed with the library fix.

xplat/folly/defs.bzl: revert the env forwarding added to folly_xplat_cxx_test.
That change was added solely to support the detect_leaks=0 workaround. Now
that the library handles LSAN annotation unconditionally, no test needs env
forwarded, so folly_xplat_cxx_test returns to its original form.
