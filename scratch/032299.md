Commit title: Introduce HeadEndpointHandler and TailEndpointHandler concepts
Commit body:
Summary:
Introduces two new endpoint concepts with fixed direction:
- TailEndpointHandler: onRead() + onException() - application side
- HeadEndpointHandler: onWrite() - transport side

The pipeline now has fixed flow:
- fireRead() → Tail's onRead()
- fireWrite() → Head's onWrite()

This makes it a lot easier to reason about it. AI getting confused is also less of a problem now.

Also added lifecycle APIs to endpoints. Now we have 4 lifecycle APIs all throughout:
1. handlerAdded -> Pipeline constructed
2. pipelineActive -> someone activated the pipeline, can be onconnection for rocket
3. pipelineInactive -> someone deactivated the pipeline, i.e. disconnect for rocket
4. handlerRemoved -> Pipeline closed

The legacy EndpointHandler concept (onMessage + onException) is deprecated
but kept for backward compatibility. HeadToTailOp is also deprecated for
new-style endpoints. These will be removed post migration of fast_thrift and fast_sr.
