Commit title: Use typedef name for container typedef struct fields in .pyi
Commit body:
Summary:
After D100865850, nested container typedefs generate class newtypes in thrift_types.pyi. However, struct fields typed with these typedefs still expanded to the raw container type (e.g., `ImmutableList[ImmutableList[str]]` instead of `StrList2D`). This caused type errors when returning a typedef field from a function with the typedef as the return type, since the expanded type is a supertype, not a subtype, of the class newtype.

This diff:
- Generates class newtypes for ALL container typedefs (not just nested ones) in thrift_types.pyi
- Uses the typedef name in struct field return type annotations instead of expanding
- Adds `owning_need_module_path?` / `owning_module_mangle` properties to correctly resolve cross-module container typedef references (since container true types don't have `program()` set)
- Adds typing tests for both same-module and cross-module container typedef fields
