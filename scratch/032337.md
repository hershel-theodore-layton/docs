Commit title: fbthrift: add THRIFT_SERIALIZATION_ONLY option to build without fizz/wangle/mvfst
Commit body:
Summary:
Add a new CMake option `THRIFT_SERIALIZATION_ONLY=ON` that allows building the lightweight Thrift libraries (thriftprotocol, thriftmetadata, thrift-core, rpcmetadata, etc.) without requiring fizz, wangle, or mvfst to be installed.

When `THRIFT_SERIALIZATION_ONLY=ON`:
- `find_package(fizz/wangle/mvfst)` calls are skipped in the top-level CMakeLists.txt
- `thriftcpp2` and `quic_thriftcpp2` targets are not defined (they depend on Rocket transport, wangle, and mvfst)
- The `async` and `thrift` interface targets in lib/cpp are not defined (they depend on wangle)
- Install rules and set_target_properties are guarded accordingly

This unblocks downstream consumers like `facebookincubator/rebalancer` that only use Thrift for serialization and do not need the Rocket transport. It eliminates build failures caused by version skew between fizz, wangle, and mvfst (which are released in lockstep from fbsource but must be pinned independently in external CI).

Also update `fbcode/algopt/rebalancer/oss_root/CMakeLists.txt` to drop the now-unnecessary fizz/wangle/mvfst find_package calls and link against `FBThrift::thriftprotocol` + `FBThrift::thriftmetadata` instead of `FBThrift::thriftcpp2`.
