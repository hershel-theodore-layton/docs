Commit title: getdeps: add sccache support to generated GitHub Actions workflows
Commit body:
Summary:
Add sccache (Mozilla's compiler cache with cloud backend support) to
the GitHub Actions workflows generated by getdeps.py, accelerating
subsequent CI builds by caching compiled objects in the GitHub Actions
cache between runs.

Changes:

- getdeps/manifest.py: add `sccache` field to `[github.actions]` schema,
  allowing per-project opt-out via `sccache = off`

- getdeps/builder.py: in CMakeBuilder._compute_cmake_define_args, prefer
  sccache over ccache when both are on PATH. sccache is auto-detected via
  PATH (mozilla-actions/sccache-action installs it there), so no explicit
  cmake flag is needed in the workflow.

- getdeps.py (GenerateGitHubActionsCmd): read the `sccache` manifest key
  (default on), emit a `mozilla-actions/sccache-action@v0.0.9` step after
  checkout when enabled. Also add `actions: read` permission and a final
  step that reports the repository's GitHub Actions cache space usage
  after every build (useful for monitoring cache pressure).

- getdeps/test/manifest_test.py: tests for the new sccache manifest field
- getdeps/test/builder_test.py: new test file for CMakeBuilder compiler
  cache selection logic (sccache preferred over ccache, fallback to ccache,
  no launcher when neither available)
