Commit title: Fix sink payload metadata type in RSocketRpcClient
Commit body:
Summary:
Fix a bug where the Java Thrift client sends `RequestRpcMetadata` for ALL sink payload frames, but subsequent frames (after the first) should use `StreamPayloadMetadata` per the Rocket protocol.

Root cause: A field ID collision between `RequestRpcMetadata.protocol` (field 1, `ProtocolId.COMPACT=2`) and `StreamPayloadMetadata.compression` (field 1, `CompressionAlgorithm.ZSTD=2`) causes the C++ server to misinterpret the protocol field as a ZSTD compression indicator. The server then attempts ZSTD decompression on uncompressed data, failing with "decompression failure: ZSTD returned an error: Unknown frame descriptor".

The fix differentiates between the first frame (which correctly uses `RequestRpcMetadata` to establish the RPC) and subsequent sink payload frames (which now use `StreamPayloadMetadata`). This mirrors the pattern already used on the receive side in `StreamingResponseHandler` (lines 364-370), which correctly uses `ResponseRpcMetadata` for the first response and `StreamPayloadMetadata` for subsequent stream frames.

The C++ client already correctly uses `StreamPayloadMetadata` for sink payloads (via `RocketSinkServerCallback::onSinkNext`).
