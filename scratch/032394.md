Commit title: Handle inherited class types when passing a string to a class type
Commit body:
Summary:
Handle classname, class and string interactions when any of these are inherited from an overridden method. These are special because they overlap in non-trivial ways by emitting special notices and perform string conversions in certain cases (as outlined in the tables below).

The runtime types of relevance are Str, Class and LazyClass. The interactions of interest are:
1. A string passed to a class type-hint
2. A class or lazy class passed to a string type-hint
3. A class or lazy class passed to a classname type-hint

All other interactions are allowed.

Each of these cases has config switches controlling the behavior. All cases are described below with the expected outcome and explanation

Add tests for various combinations of flags:

**Class/LazyClass through Classname (for all these test cases, inherited tc is classname<C> and the given return value type is Cls | LazyCls)**
* **ClassPassesClassname**: This boolean flag when set to false throws when a class is passed through a classname type hint.
* **ClassnameNoticesSampleRate**: Sampling rate to control warnings emitted when a class is passed to a classname type hint

Inherited classname type hints should have the same behavior as declared type hints. | `Cls|LazyCls` |
