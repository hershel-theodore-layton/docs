Commit title: Compatibility with Xcode Clang
Commit body:
Summary:
D95666672 uses `__clang_major__` in order to ignore `-Wnan-infinity-disabled` in Clang compilers that support the warning.

Apple, in all their wisdom, seems to be using the Xcode version until recently, then did something very weird, and recently decided to change to LLVM upstream.

| Xcode version | Reported Clang version | Actual upstream Clang version included|
|---|
| 16.0 | 16.0.0 | 17 |
| 16.2 | 16.0.0 | 17 |
| 16.3 | 17.0.0 | 19 |
| 16.4 | 17.0.0 | 19 |
| 26.0 | 17.0.0 | 19 |
| 26.1 | 17.0.0 | 19 |
| 26.2 | 17.0.0 | 19 |
| 26.3 | 17.0.0 | 19 |
| 26.4 | 21.0.0 | 21 |

This means that the check written in D95666672 was correct for upstream Clang, but was not correctly working for Apple Clang shipped with Xcode 16.3 thru 26.3.

The new check uses `__apple_build_version__` which is a predefined preprocessor variable only available in Apple Clang and not upstream Clang, in order to detect Apple Clang and use a different version number instead.
