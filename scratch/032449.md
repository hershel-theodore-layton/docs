# Claude

Adds a minimal Python regression test that reproduces the hang introduced by D100259471 (KeepAlive in PyBufferData). When an IOBuf created from Python bytes outlives the asyncio loop that built it, `AsyncioExecutor::drop()` busy-spins in `while (keepAliveCounter_ > 0) { drive(); }` *under the GIL*, which blocks Python GC, which is the only thing that could free the IOBuf — true deadlock. Buck reports as a 600s wall-clock timeout.

The test creates an asyncio loop, builds `IOBuf(b"hello")` inside a coroutine (which routes through `iobuf_from_memoryview` and captures the running loop's `NotificationQueueAsyncioExecutor` as a `KeepAlive<>`), closes the loop, drops it, and forces `gc.collect()` while the IOBuf is still in scope. With the KeepAlive change applied, the test hangs at exit; without it, the test passes in <1s.

This makes the previously-broad failure (60+ tests across configerator/zippy/zgateway/super_context/bastille) reproducible in a single fast-failing target right next to the C++ regression tests.
