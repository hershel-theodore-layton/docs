Commit title: Fix goto-def for `nameof` with type aliases
Commit body:
Summary:
When doing goto-definition on `nameof MyTypeAlias`, the IDE incorrectly navigated to the HHI declaration of `\HH\string` instead of the type alias declaration.

The root cause was in `identifySymbolService.ml`: the `on_class_id` handler for `CI` called `typed_class_id`, which extracts class names from the type annotation via `Tast_env.get_class_ids`. For typedefs in `nameof`, the type annotation is `Tnewtype("\\HH\\typename", ...)`, which resolves through the `typename` newtype upper bound (`as string`) to `\HH\string`.

The fix changes the `CI sid` case to use `process_class_id` directly with the syntactic name from the `CI` variant, bypassing type-based resolution. This is correct for all `CI` cases since the variant always carries the exact name from source.
