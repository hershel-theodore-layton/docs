Summary:
The test was calling `pauseAccepting()` and `resumeAccepting()` from the main thread while the server EventBase was running on a background thread. This caused data races in libevent event registration (`event_add`/`event_del` vs `event_base_loop`).

Fix by wrapping both calls in `sevb.runInEventBaseThreadAndWait()`, consistent with how `startServer()` already dispatches to the event base thread.
