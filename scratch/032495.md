Summary:
Per-statement stats for multi-queries.

#Facebook

Prior diff D101882190 added the `queries_executed` count to the scuba sample but the per-statement row/affected/last_insert_id/matched values were still aggregated away (sum for `rows_received`, last-statement-only for `rows_affected` / `rows_matched`). For multi-queries this hides which statement produced what.

This diff captures per-statement stats as parallel vectors of length N (N = statements that completed successfully before the operation ended) and writes them to scuba as `NormVector<string>` columns. Fields captured per statement:

- `per_query_rows_received` — rows returned by that statement's SELECT (0 for non-SELECT).
- `per_query_rows_affected` — `mysql_affected_rows()` for that statement.
- `per_query_last_insert_id` — per-statement `last_insert_id` (fills a gap that had no scalar equivalent at all).
- `per_query_rows_matched` — parsed from mysql_info on UPDATEs; empty string in the vector for statements where it wasn't produced.

Only emitted when there are >1 statements — for single-statement operations the scalar fields already carry the same info and we'd double the on-disk cost.

Failure attribution falls out for free: the fetch loop bails out of `CompleteQuery` before appending stats on an errored statement, so for a 3-statement multi-query where the 2nd fails you get vectors of length 1 plus `queries_executed=1`, and the reader can infer the 2nd statement was the one that errored.

Implementation:
- `FetchOperationImpl` (squangle base) grows four `std::vector` members and an `appendCurrentQueryStats()` helper. Both `MysqlFetchOperationImpl` and `ThriftFetchOperationImpl` call the helper in their `CompleteQuery` success branch — a single point of truth across protocols.
- `QueryLoggingData` grows matching public fields, populated once in the shared `FetchOperationImpl::logQueryCompletion()`.
- `DBScubaLoggerBase` stringifies the vectors and writes them via `addNormVectorValue` (scuba has no native int-vector column).

Extended the existing `MultiQueryLoggingOnlyLastAffectedIsReported` test to assert the per-statement vectors on the SELECT/SET/INSERT scenario. Note: the SELECT's per-statement `rows_affected` is protocol-dependent (T109961112) so that one slot is not asserted.
