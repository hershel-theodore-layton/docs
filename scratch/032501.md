Commit title: Fix metadata push frame parsing and set M flag per RSocket spec
Commit body:
Summary:
Fix METADATA_PUSH frame parsing in FrameParser and correct the FrameWriter
to set the metadata (M) flag per the RSocket specification.

**Parser fix:** METADATA_PUSH frames have the M flag set but do NOT have a
3-byte metadata length prefix — the entire payload is metadata. The parser
was incorrectly reading the first 3 bytes of metadata content as a length
prefix when M=1, corrupting deserialization. Now we skip the 3-byte read for
METADATA_PUSH and calculate metadataSize from payloadSize instead.

**Writer fix:** The FrameWriter was producing METADATA_PUSH frames with
flags=0, violating the RSocket spec which mandates M=1 for this frame type.
The Rocket server already sets M=1 (with a DCHECK on parse). Now both
implementations are consistent.

**Tests:** Added deterministic tests that construct frames exactly as the
Rocket server does (M flag set, raw metadata, no 3-byte prefix) and verify
the full parse → deserialize → handle path with real ServerPushMetadata
content. This covers the code path that was previously only exercised
non-deterministically by the E2E test.
