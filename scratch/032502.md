Commit title: Add configurable buffer replenish threshold for client streams
Commit body:
Summary:
The credit replenishment threshold for client-side stream consumption is
currently hardcoded to `chunkSize / 2`. This adds a `bufferReplenishThreshold`
field to `BufferOptions` that allows callers to control how many items must be
consumed before credits are replenished.

A value of 0 (default) preserves the existing behavior of `chunkSize / 2`.
Values exceeding `chunkSize` trigger a DCHECK and are clamped in production.

The threshold is applied consistently across all three client stream consumption
paths: `subscribeInline`, `toAsyncGeneratorImpl`, and `Continuation`.
