Commit title: Add configurable buffer replenish threshold for BiDi sinks
Commit body:
Summary:
The credit replenishment threshold for server-side BiDi sink consumption is
currently hardcoded to `bufferSize / 2`. This adds a `bufferReplenishThreshold`
field to `StreamTransformation` that allows callers to control how many items
must be consumed before the server grants additional credits to the client.

A value of 0 (default) preserves the existing behavior of `bufferSize / 2`.
Values exceeding `bufferSize` trigger a DCHECK and are clamped in production.

The threshold is threaded through `ServerBiDiStreamFactory` to
`ServerBiDiSinkBridge`, and used in `getInput()`.
