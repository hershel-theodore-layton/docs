Commit title: Wire BufferOptions through BiDi client stream and add RpcOptions::setBufferReplenishThreshold
Commit body:
Summary:
The BiDi client-side stream direction (server→client) uses
`ClientBufferedStream`, which already supports `bufferReplenishThreshold` via
`BufferOptions`. However, `createBiDiClientCallback` did not accept a
`BufferOptions` parameter (unlike `createStreamClientCallback`), so BiDi
client streams always used default `BufferOptions`.

This diff:
1. Adds `RpcOptions::setBufferReplenishThreshold()` so clients can configure the
   threshold per-RPC for both regular streams and BiDi streams.
2. Wires `BufferOptions` through `createBiDiClientCallback` so that BiDi client
   streams honor `RpcOptions::getBufferOptions()`.
3. Updates the generated code template and OmniClient to pass `BufferOptions`.
