Commit title: Populate Go disambiguated field setter names for all reachable structs
Commit body:
Summary:
Compute disambiguated field names for all structs within the current program *and its includes*. This ensures when emitting a reference to the setter for an included struct's field, the disambiguation logic is applied consistently since the included program's codegen will emit a setter with the disambiguated name, not always `Set{Name}`.

Prior to D102067835, setter names were disambiguated for current program owned structs, and defaulted to `Set{Name}` for all others.

D102067835 broke builds by maintaining the disambiguation logic, but throwing for fields not visited by it (anything that was included from another program).

D102155875 fixed this by restoring the original fallback to `Set{Name}`, which restores builds but brings back the original correctness bug. If a struct has fields `Foo` and `SetFoo`, the disambiguation would emit a setter for `Foo` called `SetFoo_`, but the codegen for a program including it would still try use `SetFoo`.

This fix ensures we visit *all* structs and consistently use the disambiguated setter name. I.e. for the example above, ensures all references (regardless of whether in an included or current program context) will use `SetFoo_` for the `Foo` field.
