Commit body:
Summary:
Adds a portable thread-safety-annotation header to folly:

- `FOLLY_GUARDED_BY` / `FOLLY_PT_GUARDED_BY` / `FOLLY_REQUIRES` /
  `FOLLY_REQUIRES_SHARED` / `FOLLY_ACQUIRE` / `FOLLY_RELEASE` /
  `FOLLY_TRY_ACQUIRE` / `FOLLY_EXCLUDES` / `FOLLY_ASSERT_CAPABILITY` /
  `FOLLY_NO_THREAD_SAFETY_ANALYSIS` macros that expand to Clang's
  thread-safety attributes on Clang and to no-ops on other compilers.
- `folly::AnnotatedMutex` — a capability-annotated wrapper around
  `std::mutex` so the `GUARDED_BY` / `EXCLUDES` checks actually fire on
  it (Clang's `-Wthread-safety` analysis only applies to mutex types
  carrying the `capability("mutex")` attribute, which `std::mutex` and
  the existing folly mutex types do not).
- `folly::AnnotatedLockGuard` — matching scoped lock with the
  `scoped_lockable` attribute. `std::lock_guard` cannot be used as a
  drop-in replacement because the analyzer does not understand that the
  capability is held inside its scope.

On non-Clang compilers `AnnotatedMutex` and `AnnotatedLockGuard` are
plain `using` aliases for `std::mutex` and `std::lock_guard<std::mutex>`,
so there is no extra indirection on platforms that cannot make use of
the analysis.
