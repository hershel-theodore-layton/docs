Commit title: Introduce RpcClientSource as the typed-client acquisition seam
Commit body:
Summary:
Generated Java clients currently depend directly on Mono<RpcClient>, which makes later lifecycle changes hard to stage cleanly. This diff introduces RpcClientSource as a neutral acquisition interface and switches the generated client templates, ClientBuilder, and the warm-storage wrapper over to that seam.

The implementation stays behavior-preserving in this diff: LegacyRpcClientSource simply wraps the existing Mono<RpcClient> surface and keeps dispose() as a no-op, so typed clients still behave exactly like the legacy runtime. This gives the next diffs a clean place to plug in manager-backed ownership without mixing that behavior change into the generator refactor.
