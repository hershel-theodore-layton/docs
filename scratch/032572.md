Commit title: Document the client runtime architecture and migration
Commit body:
Summary:
The legacy Java Thrift client runtime conflates transport creation and connection lifecycle inside opaque Mono<RpcClient> chains. This causes a fundamental ownership ambiguity: when a generated typed client calls close()/dispose(), it cannot know whether it should kill the underlying transport (non-SR standalone clients) or leave it alive (SR sidecar shared connections). The existing diffs D88212402 and D88213257 attempted to solve this with a NonDisposableRpcClient wrapper and per-RPC-call wrapper tracking in generated code, but that approach leaks memory linearly with RPC call volume (decorator factories create new wrapper instances per subscribe) and requires SR-specific suppression hacks.

This diff introduces a v2 client runtime that separates transport creation from connection lifecycle through an explicit manager layer, modeled after rsocket-java's RSocket (live transport) vs RSocketClient (lifecycle manager) pattern.

Manager Composition (standard non-SR factory chain):

  SimpleLoadBalancingRpcClientManager       [N slots, round-robin/sticky]
    +-- slot 0: ReconnectingRpcClientManager  [retry with backoff]
    :             +-- SingleRpcClientManager   [one live transport]
    :                   +-- transport factory   [creates raw connections]
    +-- slot 1: ReconnectingRpcClientManager
    :             +-- SingleRpcClientManager
    :                   +-- transport factory
    +-- slot N: ...

Ownership Scenarios (what happens on client.close()):

  NON-SR client (OWNED):
    close() -> binding(OWNED) -> manager.dispose()
      -> SingleRpcClientManager.doDispose()
      -> rpcClient.dispose() -> ERROR frame -> channel closed
      Result: transport cleaned up, connection gone

  SR non-sticky client (BORROWED):
    clientA.close() -> binding(BORROWED) -> closed=true
      -> transport NOT touched, shared manager stays alive
    clientB.doStuff() -> works fine, same shared connection
      Result: handle closed, transport untouched

  SR sticky client (OWNED):
    close() -> binding(OWNED) -> dedicated manager.dispose()
      -> sticky connection cleaned up
      -> other clients unaffected (separate managers)
      Result: only this client's connection cleaned up

Architecture (3 layers):

1. Transport Layer (RpcClientFactory) - Stateless, per-connection decoration
   - RSocketRpcClientFactory / LegacyRpcClientFactory create raw connections
   - InstrumentedRpcClientFactory, TokenPassingRpcClientFactory, EventHandlerRpcClientFactory, TimeoutRpcClientFactory wrap each connection with per-request behavior
   - No lifecycle management, no caching, no reconnection
   - The manager layer calls this when it needs a new connection

2. Manager Layer (RpcClientManager) - Stateful lifecycle ownership
   - SingleRpcClientManager: owns one lazily-created transport per address, subscribes to onClose() for auto-invalidation, lazily reconnects on next acquire()
   - ReconnectingRpcClientManager: wraps SingleRpcClientManager with Reactor Retry.backoff() for exponential backoff reconnection (100ms base, 30s max, 0.5 jitter)
   - SimpleLoadBalancingRpcClientManager: N child managers with round-robin or sticky-hash selection, dispose() cascades to all children
   - PooledRpcClientManager: dynamic host pool with periodic refresh (1-min interval), reuses managers for unchanged addresses, disposes managers for removed addresses
   - DecoratingRpcClientManager: stateless RpcClient decoration (e.g., ExceptionMappingRpcClient for SR)
   - MonoBackedRpcClientManager: compatibility bridge for existing Mono<RpcClient> sources

3. Binding Layer (RpcClientBinding + ClientOwnership)
   - OWNED: closing the typed client disposes the manager and its transports
   - BORROWED: closing the typed client only closes the handle; the shared manager lives on
   - This is the ONLY class that knows about ownership policy
   - Generated code delegates dispose() to the binding without knowing the policy

Runtime selection is transparent via RpcClientSource (neutral interface):
- LegacyRpcClientSource: wraps Mono<RpcClient>, dispose() is a no-op (preserves historical behavior)
- BindingRpcClientSource: wraps RpcClientBinding, dispose() obeys v2 ownership semantics
- ClientRuntimeSelector routes to legacy or v2 based on ClientRuntimeMode

Generated client changes:
- ReactiveClient.mustache: field changes from Mono<RpcClient> _rpcClient to RpcClientSource _clientSource
- All _subscribedClients tracking and wrapper identity sets are REMOVED
- dispose()/isDisposed() delegate to _clientSource (one line each)
- RPC methods use _clientSource.acquire().flatMap(...) instead of _rpcClient.flatMap(...)
- Backward-compatible constructors accepting Mono<RpcClient> still exist via _clientSourceFromMono() shim

SR integration:
- ServiceRouterV2Sidecar: creates one shared manager for non-sticky (process lifetime), uses buildBorrowed(). Sticky clients get buildOwned() with per-request managers.
- ServiceRouterV2ClientFactoryImpl: PooledRpcClientManagerFactory for direct-tier clients, buildBorrowed() for shared pool
- ServiceRouterV2Bindings + ServiceRouterV2BindingsClientFactoryImpl: same pattern for Java 25+ FFM bindings path
- NonDisposableRpcClientFactory and LogEvery suppression wrapper are DELETED

Additional fixes included:
