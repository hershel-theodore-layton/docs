Commit title: Fix ByteBuf memory counter leaks in thrift Java runtime
Commit body:
Summary:
Fix ByteBuf accounting bugs in the thrift Java serialization utilities
that cause the `netty.unpooled.usedHeapMemory` counter to grow unboundedly,
masking real memory usage and triggering false OOM alerts. In Iris production
this counter reached ~46GB with a 40GB max heap.

**Bug 1 (CRITICAL) — InputStreamByteBuf.readBytes() / readSlice():**
`InputStreamByteBuf.readBytes(int)` uses `Unpooled.buffer(length)` which
creates `InstrumentedUnpooledUnsafeHeapByteBuf` — tracked by the allocator's
`heapCounter`. These ByteBufs are ephemeral: `ByteBufTCompactProtocol.readString()`
calls `readBinaryAsSlice()` → `InputStreamByteBuf.readSlice()` → allocates a
tracked ByteBuf, extracts a String from it, then discards the ByteBuf without
calling `release()`. The counter increments on every string field read but never
decrements. This is the highest-volume leak: every string field in every struct
deserialized via `SerializerUtil.fromInputStream()` hits this path (DeltaWrapper,
GenericQueueEntryData, MessageMetadata, etc).

Additionally, `readSlice()` double-wrapped: `Unpooled.wrappedBuffer(readBytes(length))`
unnecessarily created a second ByteBuf layer.

Fix: read into raw `byte[]` via `readIntoBuffer()` and wrap with
`Unpooled.wrappedBuffer(byte[])`. This creates `UnpooledHeapByteBuf` directly
(bypasses the allocator's `newHeapBuffer()`) — no counter instrumentation,
no leak. Also fixes `readSlice()`/`readRetainedSlice()` to avoid double-wrapping.

**Bug 2 — SerializerUtil.doToByteBuffer():**
`Unpooled.buffer()` allocated but never `release()`d — `nioBuffer()` returns
a view, ByteBuf falls out of scope, counter grows.

Fix: delegate to `doToByteArray()` (which has proper try/finally release)
+ `ByteBuffer.wrap()`.

**Bug 3 — SerializerUtil.doToInputStream():**
`ByteBufInputStream(dst)` default constructor sets `releaseOnClose=false`.
Counter never decrements even if caller closes the stream.

Fix: `new ByteBufInputStream(dst, true)`.

**Bug 4 — RpcClientUtils.getUndeclaredException():**
Used `PooledByteBufAllocator.DEFAULT.buffer()` bypassing the configured allocator.

Fix: use `RpcResources.getByteBufAllocator()`.
