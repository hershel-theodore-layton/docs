Commit title: Propagate @thrift.ExceptionMessage field to super() in generated exception constructors
Commit body:
Summary:
When a Thrift exception has a field annotated with thrift.ExceptionMessage,
the generated Java constructor now calls super(annotatedField) to propagate
the message to the Throwable base class. This ensures getMessage(), toString(),
and getLocalizedMessage() all return the correct value.

Previously, generated exception constructors only did `this.field = field`
without calling super(), so Throwable.getMessage() returned null even when
the exception had a message field. This caused whatUtf8 to be null in
streaming exception metadata (StreamResponseHandlerTemplate).

Changes:
- ThriftConstructor.mustache: Added super() call gated by hasExceptionMessage?
- t_mstch_java_generator.cc: Added hasExceptionMessage? property that checks
  for exception message field without the "field named message" exclusion
  (the existing needsExceptionMessage? skips fields named "message" to avoid
  getMessage() getter conflicts, but super() has no such conflict)
- Updated test IDL to add thrift.ExceptionMessage annotations
- Updated test expectations from null to "exc" for whatUtf8
- Regenerated compiler test fixtures
