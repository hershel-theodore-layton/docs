Commit title: Set declared exception name in request-response replies
Commit body:
Summary:
Pure request-response declared exceptions were sent over the wire with only the `whatUtf8` field populated. The Rocket server-transport contract — the same one that D95857603 enforced for streams — requires both `nameUtf8` (the qualified exception class name, surfaced as the `uex` header) and `whatUtf8` (the message, surfaced as `uexw`) on every declared exception payload. Without `nameUtf8`, clients can read the message but cannot key on the exception type from headers, which breaks parity with C++ and with the stream path.

This diff adds a 4-arg overload to `RpcPayloadUtil.createServerResponsePayload(payload, writer, name, what)` and updates the `RpcServerHandler.whisker` template to pass `_t.getClass().getName()` for declared exceptions thrown from request-response handlers. The 3-arg overload (used elsewhere) still routes through the new code path with `name == null`, preserving existing behavior for callers that don't provide a name.

`PayloadExceptionMetadataBase.Builder` initializes its fields to `null` and its setters simply assign — so `setNameUtf8(null)` is equivalent to never calling it. The 4-arg overload uses the chained-builder form directly without inner null checks.

Affected generated handlers were regenerated via `buck2 run fbsource//xplat/thrift/compiler/test:build_fixtures`.
