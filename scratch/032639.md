Commit title: Fix CoroSSLTransport baton not being signaled on exception
Commit body:
Summary:
When transport_->read() throws an exception (e.g., timeout), the readsBlocked_
baton was not being signaled, leaving it in a locked state. This caused
subsequent reads to wait indefinitely on the baton, even though the original
read had already returned with an exception.

This fix wraps the transport_->read() call in a try-catch block that ensures
readsBlocked_.signal() is called even when an exception is thrown.
