Commit title: Fix SIOF in getEnumFieldExt by using lazy enum_find
Commit body:
Summary:
`getEnumFieldExt()` is initialized in global variable via generated module_types.cpp.

https://www.internalfb.com/code/fbsource/xplat/thrift/compiler/generate/templates/cpp2/module_types.cpp.whisker?lines=225-232

However, `TEnumTraits<EnumType>::values` might not be initialized when calling `getEnumFieldExt` for enums with non-int32_t underlying types, causing a static initialization order fiasco (SIOF).

This is already solved in `st::enum_find_instance<EnumType>` which uses function-local statics for lazy initialization.

https://www.internalfb.com/code/fbsource/fbcode/thrift/lib/cpp2/detail/Enum.h?lines=128-134

Fix by:
1. Changing `EnumFieldExt` to hold a `std::variant` of `st::enum_find<T>*` pointers for all integer types instead of a single `enum_find<int32_t>&`
2. Changing `getEnumFieldExt` to always use `st::enum_find_instance<EnumType>()` regardless of the underlying enum type
3. Updating all callsites to use `std::visit` on the variant
