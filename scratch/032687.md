Commit title: Make "return in generator" a parser error instead of a NAST check error
Commit body:
Summary:
Previously, returning a value from a generator (`return $value;` in a function containing `yield`) was only reported as a typing-phase NAST check error (NastCheck[3019]). This meant HHVM did not enforce it as a hard failure at parse time.

This moves the check to the parser (rust_parser_errors.rs) so it becomes a Parsing[1002] error, which is a hard failure for both the typechecker and HHVM. The parser now tracks whether the current callable is a generator by scanning the function body for `yield` expressions (stopping at nested function/lambda boundaries), and emits an error when a `ReturnStatement` with a value is encountered in a generator context.

The NAST check (`Return_in_gen` / `ReturnInGen`) is removed from naming_coroutine_check.ml, validate_coroutine.rs, nast_check_error.ml/.mli, and compile.rs. Oxidized types are regenerated accordingly.
