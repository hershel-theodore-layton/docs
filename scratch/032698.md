Commit title: In JSON5 Serialization, Make `options=Json5ProtocolWriterOptions()` and `options=None` have same behavior.
Commit body:
Summary:
Today

```
serialize(data, protocol=Protocol.JSON5, options=Json5ProtocolWriterOptions())
```

sets indent_width=2. However

```
serialize(data, protocol=Protocol.JSON5)
```

sets indent_width=0.

This is bit counterintuitive and it broke `test_serialize_json5_default_options_matches_no_options` tests which specifically testing this.

The problem is that in C++ cython layer, both `serializeJson5(...)` and `serialize(...)` can handle JSON5, but they have different behavior.

In addition, during JSON5 serialization, when `options=None`, we will invoke `serialize(...)`, otherwise we will invoke `serializeJson5(...)`.

This diff changed the behavior so that

1. During JSON5 serialization, always invoke `serializeJson5(...)` even if `options=None`.
2. Drop JSON5 support in `serialize(...)` since such code path is never used. (JSON5 always uses `serializeJson5(...)` going forward).
