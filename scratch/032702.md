Commit title: Skip filter_strip_marker for symlinked source files
Commit body:
Summary:
The `oss-mcrouter-windows-getdeps` CI job has been failing continuously since
late February 2026 with a FileNotFoundError in `filter_strip_marker`.

Root cause: mcrouter's `scripts/order_centos-7.2/` directory contains symlinks
(e.g., `15_fbthrift -> ../recipes/fbthrift.sh`). During `ShipitPathMap.mirror()`,
`copy_if_different` recreates these as symlinks in the destination. Then
`filter_strip_marker` tries to `open()` the destination symlink to strip
`fb-only` markers — but on Windows NTFS, `os.walk` processes directories
alphabetically, so `order_centos-7.2` is visited before `recipes`. The symlink
target (`../recipes/fbthrift.sh`) hasn't been copied yet, causing a
FileNotFoundError when following the dangling symlink.

Fix: Skip `filter_strip_marker` for symlinks. This is both correct and
sufficient — the actual target file (e.g., `recipes/fbthrift.sh`) will be
processed directly when `os.walk` reaches its directory, so marker stripping
still happens on the real file content.
