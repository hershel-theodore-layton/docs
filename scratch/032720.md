Commit title: Check shape-field types in `as`-expression package boundary check
Commit body:
Summary:
The `as`/`?as` package-boundary check in `Typing_type_integrity.check_type_integrity` walks the hint and emits errors when a referenced class/typedef crosses a package boundary. The `Tshape` arm previously forced `should_check_package_boundary` to `` `No `` for every shape field type, so `$x as shape('k' => InternType)` did not flag `InternType`, while the analogous `$x as tuple(InternType, int)` did. This is asymmetric and weaker than HHVM's runtime semantics, which deep-check shape field types under `as` (modulo `enforce_deep`).

Propagate the parent reason through `Tshape` only when it is `As_expression` or `LintOnly` (the two reasons that originate from `as` expressions). All other call sites of `check_hint_integrity` (signatures, decl) continue to skip shape field checking, preserving prior behavior outside the `as` context.
