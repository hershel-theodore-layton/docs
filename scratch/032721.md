Commit title: Downgrade ensureConfigDirectoryExists warning to VLOG(1)
Commit body:
Summary:
On read-only filesystems (e.g., Chronos jobs), every tool that links libmcrouter floods stderr with warnings like:

  W0429 16:44:03.093575 1499600 ConfigApi.cpp:75] Failed to create directory
    '"/var/facebook/logs/libmcrouter/config/fb-meta-linux"': Read-only file system

These appear dozens of times per run because each invocation of `meta`, `fbpkg`, or any other mcrouter-linked binary triggers the warning. For example, a single run of the P4P `ts-auto-close` Chronos job (which processes hundreds of stale-package tasks) produces output like this:

```
ts-auto-close: seeding cache...
W0429 16:44:03.093575 1499600 ConfigApi.cpp:75] Failed to create directory '"/var/facebook/logs/libmcrouter/config/fb-meta-linux"': Read-only file system
W0429 16:44:21.771409 1500517 ConfigApi.cpp:75] Failed to create directory '"/var/facebook/logs/libmcrouter/config/fb-meta-linux"': Read-only file system
W0429 16:44:23.054181 1500672 ConfigApi.cpp:75] Failed to create directory '"/var/facebook/logs/libmcrouter/config/fb-meta-linux"': Read-only file system
W0429 16:44:40.092386 1502857 ConfigApi.cpp:75] Failed to create directory '"/var/facebook/logs/libmcrouter/config/fb-meta-linux"': Read-only file system
W0429 16:45:08.649088 1505688 ConfigApi.cpp:75] Failed to create directory '"/var/facebook/logs/libmcrouter/config/fb-meta-linux"': Read-only file system
...
E0429 16:45:54.218086 1510548 FilePoller.cpp:73] Poller context requested after destruction.
E0429 16:45:54.234519 1510548 FilePoller.cpp:73] Poller context requested after destruction.
...
```

This repeats for every tag the job processes (`p4p-stale-image`, `procprint-90-violation`, etc.), burying real diagnostics in noise.

The `ensureConfigDirectoryExists` function already handles the failure gracefully by returning false, and callers cope with that. The sibling `else` branch already uses `VLOG(1)` for the analogous "parent doesn't exist" case. Change `LOG(WARNING)` to `VLOG(1)` for consistency: this is a non-fatal, expected condition that doesn't warrant a warning.

Both copies of `ensureConfigDirectoryExists` are fixed: `ConfigApi.cpp` and `CarbonRouterInstanceBase.cpp`.

Note: the `FilePoller.cpp` "Poller context requested after destruction" error has already been fixed at HEAD (the LOG was replaced with a silent return). The binary just needs a rebuild to pick that up.
