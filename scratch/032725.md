Commit title: Add detailed LLDB pretty printer for HPHP::Func
Commit body:
Summary:
The existing pp_NamedValue formatter for HPHP::Func only showed the function name, hiding all other fields. Nested members like m_funcEntry, m_attrs, and m_atomicFlags appeared as empty values (e.g., `m_funcEntry = (m_s = )`) because the summary formatter prevented default LLDB expansion and the fallback `_default_summary` could not recurse into atomic/smart pointer wrappers.

This diff adds a dedicated pp_Func formatter that extracts and decodes every field of HPHP::Func:

- **Pointer fields** (m_funcEntry, m_fullName, m_name, m_shared, m_unit, m_prologueTable): unwrapped via `rawptr()` and displayed as hex addresses or resolved strings
- **m_attrs**: decoded from the atomic bitmask into human-readable flag names (e.g., `Public|Static|Final`)
- **m_atomicFlags**: decoded into `Optimized|Locked|MaybeIntercepted|...`
- **m_allFlags**: decoded into `isPreFunc|hasPrivateAncestor|...`
- **m_paramCounts**: decoded from the packed uint32 (upper 31 bits = count, LSB = variadic flag)
- **m_requiredCoeffects**: resolved to coeffect names (e.g., `pure`, `defaults`, `zoned`) by calling `RuntimeCoeffects::toString()` via expression evaluation, with caching and hex fallback
- **m_funcId**: extracted when present (skipped gracefully when compiled out with USE_PACKEDPTR)
- **Atomic scalars** (m_jitReqCount, m_cloned): read through `std::atomic` internals via `atomic_get()` with fallback

The formatter is robust against individual field extraction failures (each field is independently try/excepted) and does not require `nameof()` to succeed to display the remaining fields.

Example output:
```
"ClassName::genDeserializeImpl" {funcEntry=0x222ffe06, funcId=42, fullName="ClassName::genDeserializeImpl", name="genDeserializeImpl", cls="ClassName", methodSlot=5, cloned=false, atomicFlags=Optimized, allFlags=None, jitReqCount=0, coeffects=pure, maxStack=8, unit=0x819a7e9c0, shared=0x..., inoutBits=0x0, params=3, attrs=Public, prologue[0]=0x...}
```
