Commit title: folly: guard walkNormalStack against stale coroutine frame pointers
Commit body:
Summary:
walkNormalStack walks the frame-pointer chain by dereferencing normalStackFrame before the existing bounds check fires. Under --shared-libs builds, when throwCallback intercepts __cxa_throw while an async stack root is active, the coroutine frame's sentinel saved-rbp slot (e.g. 0xa) can end up as normalStackFrame, causing a segfault before the monotonicity check has a chance to bail.

Add a kMinValidAddress (0x1000) guard to the while condition so any frame pointer below the first page -- which the Linux kernel never maps in user space -- terminates the walk immediately. Also add a regression test that exercises the exact ThrowsMessage + blockingWait pattern from the bug report.
