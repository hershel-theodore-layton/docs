Commit title: getdeps: fix _compute_project_hash silently skipping patchfile content
Commit body:
Summary: The os.path.exists guard in _compute_project_hash (load.py) caused patchfile content to be silently omitted from the project hash whenever the patchfile was not found on disk. This meant the GitHub Actions cache key (derived via `getdeps query-paths`) would not change when patch contents were updated — so CI would restore the old cached install and never apply the new patch. Removing the guard makes the behavior consistent with _apply_patchfile in builder.py, which also fails loudly on a missing patchfile rather than silently continuing. If a manifest declares `patchfile = foo.patch` but foo.patch is absent, _compute_project_hash now raises FileNotFoundError instead of producing a stale hash.
