Commit body:
Summary:
D102730034 merged the pre-existing non_fbcode_target +
fbcode_target pair for :gflags into a single fb_dirsync_cpp_library
with unconditional srcs = ["GFlags.cpp"] and exported_external_deps =
["gflags"]. That collapsed the original fbcode-vs-non-fbcode
asymmetry: the original non_fbcode_target was header-only and only
included libgflags as a dep on linux/macos/windows/runtime:fbcode (and
when explicitly opted in via constraint or buckconfig), NOT on
mobile-DEFAULT (Android, iOS). The merged rule pulled libgflags into
Android xplat consumers, and gflags' static-init / DEFINE_*
registration code kept the lib in the final APK even though folly's
gflags-using code paths are guarded by FOLLY_HAVE_LIBGFLAGS=0 on
mobile.

Fix:
- srcs gated on ovr_config//runtime:fbcode (matches original
  fbcode_target which had srcs=["GFlags.cpp"]; original
  non_fbcode_target was header-only, so xplat gets [] here).
- exported_external_deps mirrors the original non_fbcode_target's
  exported_deps select shape exactly, plus a runtime:fbcode branch
  that matches the original fbcode_target's unconditional gflags.
  - linux / macos / windows / runtime:fbcode / folly-gflags-enabled
    constraint / should_enable_gflags() buckconfig: link libgflags.
  - mobile xplat (Android, iOS without opt-in): no libgflags. Fixes
    the regression.
