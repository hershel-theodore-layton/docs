Commit title: Add backup carve-out for class-like aliases
Commit body:
Summary:
Motivation:

The previous diff added an enforceable type alias check that fires at runtime-enforced positions on every alias. By default we want that to be the rolled-out behavior — when the main flag (`package_allow_enforceable_type_alias_violations`) is flipped to `false`, errors should fire on aliases that resolve to a class / interface / enum / enum class as well as on structural aliases. Direct class references at the same position already trigger `Cross_pkg_access` at the class's own use-site, so this does add some redundancy at the boundary, but we want to err on the side of catching the actual runtime hazard first and removing the redundancy later if it turns out to matter.

What this diff adds: a *backup* carve-out — `package_allow_enforceable_type_alias_class_like_violations`, default `false`. When set to `true`, aliases that recursively resolve to a name-enforced type are skipped by the enforceable type alias check. We do not expect to flip this flag during the rollout; it exists as a relief valve in case shipping with enforcement on class-like aliases turns out not to be viable.

Note: with the main flag at its default `true`, the check returns `\`No` at the wellformedness layer, so the secondary flag never gets consulted — `(main=true, secondary=false)` produces no new errors anywhere, identical to `(main=true, secondary=true)`.

Implementation:
- New typechecker option `tco_package_allow_enforceable_type_alias_class_like_violations` (default `false`). Plumbed through `config_keys.ml/.mli`, `serverConfig.ml`, `globalOptions.ml/.mli`, `typecheckerOptions.ml`, `typing_env.ml/.mli`, `oxidized/{gen,manual}/global_options*.rs`, `hh_config.rs`.
- `typing_type_integrity.ml`: adds `typedef_resolves_to_class_like` (recursively walks simple-typedef underlying types until it hits a class / interface / enum / enum class, or a structural type; traits are filtered out because they aren't legal in type positions). The `Tapply` cases for `ClassResult` and `TypedefResult` suppress the `Enforceable_type_alias` check when the secondary flag is `true` AND the target is class-like.
