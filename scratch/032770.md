Commit title: MultiplexAsyncProcessorFactory: recover schema from service handlers when factory wrapper doesn't forward
Commit body:
Summary:
`MultiplexAsyncProcessorFactory::getServiceSchema()` iterates through its underlying factories and merges their schemas. When a factory wrapper doesn't override `getServiceSchema()`, the base class returns `nullopt` and the wrapped service is silently dropped from the merged schema.

Fix: when a factory returns `nullopt` from `getServiceSchema()`, `MultiplexAsyncProcessorFactory` now queries the factory's service handlers directly via `dynamic_cast<AsyncProcessorFactory*>(handler)`. Generated `ServiceHandler<T>` classes inherit from both `ServiceHandlerBase` and `AsyncProcessorFactory`, so the cast succeeds and the handler's generated `getServiceSchema()` is called. The same fallback is applied to `getServiceSchemaNodes()`. If the handler doesn't implement `AsyncProcessorFactory` (e.g. a pure Python runtime handler), the `dynamic_cast` returns `nullptr` and we skip it — same behavior as before.
