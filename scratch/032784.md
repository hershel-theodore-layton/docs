Commit title: Include connection idle time in gone-away error messages
Commit body:
Summary:
When a query fails with CR_SERVER_GONE_ERROR (2006), CR_SERVER_LOST (2013), or MYROUTER_TIMEOUT_IDLE (1912), append the connection idle time to the error message so the customer can see how long the connection sat unused before the query was sent. This helps diagnose cases where executor delay between acquiring a connection and sending the query causes the server's wait_timeout to close the connection.

The idle time is tracked via a folly::stop_watch on ConnectionHolder that resets whenever the connection is handed to the user (pool checkout or fresh connect) and after each successful query. The error message is enriched like: "MySQL server has gone away (CONN_IDLE: 3042ms)"

This is similar to how threadOverloadMessage() appends "(CLIENT_OVERLOADED: cb delay Xms)" to timeout errors when the IO thread is congested.
