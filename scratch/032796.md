Commit title: folly/json: template Printer on Pretty for branch-free hot paths
Commit body:
Summary:
Templates `PrinterImpl<bool Pretty>` and selects the instantiation in
`serialize()` based on `opts.pretty_formatting`. Eliminates the runtime
`if (indentLevel_)` branches in `newline()`, `mapColon()`, `indent()`,
and `outdent()` and removes the indirection through the previous
`unsigned* indentLevel_` member. The compiler now compiles the
compact-output path with the indentation logic stripped entirely.

Refactor details:
- Lifts `Context`, `toStringOr`, `contextDescription` out of the old
  `Printer` struct so that `Printer` itself can be templated without
  pulling unrelated symbols into the template.
- Replaces `unsigned* const indentLevel_` with
  `mutable unsigned indentLevel_{0}` (only used when `Pretty=true`).
- `printArray` no longer calls `std::distance` per iteration; it
  carries an explicit `int64_t i` counter for the same indices.

Behavior preservation:
- For `Pretty=false`, all `if constexpr (Pretty)` branches compile to
  no-ops, matching the prior behavior where `indentLevel_` was
  `nullptr`.
- For `Pretty=true`, the `mutable unsigned` starts at 0 and increments
  exactly like the prior local `unsigned indentLevel`.
- `toStringOr` (used for `print_error::what()` text) intentionally
  uses `PrinterImpl<true>` to preserve byte-identical error message
  formatting for the rare case of compound dynamic keys (the prior
  code passed a non-null `&indentLevel` pointer to its inner Printer,
  which made it pretty-format compound keys).
- `dynamic(int64_t{0})` and `dynamic(i)` produce the same INT64-typed
  dynamic as the prior `dynamic(0)` / `dynamic(std::distance(...))`.

Adversarial review:
Two independent reviewers (the diff author + a fresh-perspective
review subagent) both flagged the toStringOr formatting as the only
behavior risk; that was caught and fixed before submission. ASan run
of the json test suite passes 39/39 with no UAF/heap-overflow/leaks.
