Commit title: Invoke async error hook at recv boundary
Commit body:
Summary:
Thrift core already reports recv failures through recvException and recvError, but the async client handler lifecycle only exposed a success-side genAfter callback. The previous version of this work added a separate wrapper around recvImplHelper, which still left the async error hook one layer away from the recv code that actually classifies exceptional replies.

This change moves the async error hook directly into genRecvImplHelper, alongside the existing recvException and recvError paths for unary RPCs and the first-response recv path of stream, sink, and bidirectional calls. If a subclass's genOnError throws, thrift logs that hook failure and still rethrows the original recv exception so the underlying reply/decode failure is not masked.

For the concrete PrivacyLib motivation and integration path that needs this seam, see the next commit in the stack.
