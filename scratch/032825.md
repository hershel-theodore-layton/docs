Commit title: folly/json: short-ASCII fast path in escapeString
Commit body:
Summary:
Adds a fast path to `escapeString` that handles short (<=32 bytes)
ASCII-only strings with no `"`/`\\`/control bytes in a single
scan-and-copy pass into a stack buffer, then a single `out.append`.

This is motivated by strobelight profiles of Scuba sample logging
(`facebook::rfe::ScubaDataSample::toJson` -> `folly::json::serialize`),
which showed ~54% of `folly::json` CPU spent inside `escapeStringImpl`
on short identifier-shaped keys and values that need no escaping.

Behavior preservation:
- The fast path is gated on `extra_ascii_to_escape_bitmap == 0` and
  `!encode_non_ascii`. If the input contains any byte that is not
  printable-ASCII (i.e. < 0x20 or >= 0x80) or is `"` or `\\`, the
  function falls through to the existing `escapeStringImpl<false>`
  unchanged. The original `escapeStringImpl<true>` path is preserved
  verbatim for the `extra_ascii_to_escape_bitmap` case.
- Strings longer than 32 bytes also fall through to the original SIMD
  path, which already amortises its overhead well for long inputs.
- Pure ASCII (< 0x80) strings are valid UTF-8 by definition, so the
  `validate_utf8` / `skip_invalid_utf8` semantics are preserved on the
  fast path without an explicit check.
