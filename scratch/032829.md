Commit title: IOBufQueue: add opt-in `pack` mode to split/splitAtMost
Commit body:
Summary:
Add a `pack` parameter to `IOBufQueue::split` and `splitAtMost`. When `pack` is true, `split` calls into the existing `appendToChain(..., pack=true)` path, which (a) packs small IOBuf nodes into the preceding node's spare tail capacity via memcpy (up to `kMaxPackCopy` bytes per node) and (b) drops fully-empty nodes. The default remains `false`, preserving existing behavior.

Motivation: callers that build a queue from many small upstream IOBufs (e.g. proxygen socket reads producing ~16KB nodes per chunk, yielding ~500-node chains for an 8MB body) would otherwise propagate the long chain through the entire downstream pipeline. Each downstream pass — encryption cursor iteration, parallel chunk splitting, digest computation, chain destruction — then pays O(n) per-node overhead. Coalescing into preceding tailroom at split time eliminates that walk while the data is still cache-warm from the producing copy.

Changes:
- `IOBufQueue::split(size_t, bool throwOnUnderflow, bool pack = false)` — new `pack` parameter forwarded to `appendToChain`. The empty-node skip branch is removed since the same drop-empty behavior is now handled by `appendToChain` when `pack=true`.
- `IOBufQueue::splitAtMost(size_t, bool pack = false)` — new optional `pack` parameter, defaulting to `false` (no behavior change for existing callers).
- Annotated the underflow path with `FOLLY_UNLIKELY`.
- Doc comment on `splitAtMost` describing the new `pack` semantics.
