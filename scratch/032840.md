Commit title: Avoid Key/TVWrapper moves in memo cache setImpl
Commit body:
Summary:
The current `setImpl` does a two-step "construct and move" for both `Key` and `TVWrapper`, but these types are fairly expensive to move.  `TVWrapper` in particular has the same cost to move as to copy.

Here I use in-place construction instead.

We only call `setImpl` when we're *certain* to install a new entry, so we don't need the "or assign" part of `insert_or_assign`'s semantics anyway.

`setImpl` is about [1% of all HHVM cycles](https://fburl.com/scuba/strobelight_services/7nsmnugb), and these moves are about 10% of that, so I expect to save around 0.1% of HHVM cycles with this change.
