Summary:
Runtime changes overview doc: https://docs.google.com/document/d/1w5u7bLLiVpb-fY92N9O6ymJoFX0ZQx36uOmigUea_Jg/edit?tab=t.0#heading=h.q31v41v3qwt9

This diff modifies HackC's bytecode generation to emit named parameter default value funclets after all positional ones, and changes HHVM's func entries to introduce a new NamedParamsFuncEntry. Deals with the consequences in the runtime, and as a consequence we now support calling the func entries of functions with named parameters properly.

The HHVM func entry protocol is modified to be the following:

1. Execute DV funclets for non-passed optional positionals based on the positional argc
2. Execute DV funclets for ALL optional named parameters, which internally check whether a named param was set before writing the default value
3. Jump into the main function entry.

HHBBC is modified to understand this new protocol, and the block value passes etc are modified to deal with this.

As a side effect of this change, positional func entries are now identified with positional argc (as they don't retain the information of which named args were passed in).
