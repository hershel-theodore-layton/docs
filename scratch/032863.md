Commit title: Observe thrift errors via genOnError
Commit body:
Summary:
AI agent thrift calls already emit observation on success through genAfter, but failed calls bypass that path. This follow-up uses the new thrift genOnError seam to observe attempted access on thrift failures so agent oversight can see denied or exceptional reads as well as successful ones.

This split is limited to the Privacy integration on top of that seam: it adds killswitch-gated error handling in TClientPoliciedAsyncHandler, introduces thrift policy-enforcer genProcessError dispatch with default no-op support for existing VPEs, enables ThriftServiceMethodName postRPC observation for error payloads, and adds focused handler coverage for the error-path behavior.

The error observation dispatch is deferred to PSP (Post-Send Processing) via `PSP()->startLaterAndWaitFor` so it does not block the normal thrift error processing path. The validation checks (killswitch, cached state, service name opt-out) remain inline so that future context propagation work on the error path (D103056890) can also run inline.
