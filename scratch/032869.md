Commit title: Fix class constant lookup monotonicity for unloaded classes
Commit body:
Summary:
When resolving a class constant on a class whose ClassInfo2 isn't
loaded, we previously returned a fully conservative result. This
could cause monotonicity violations: if the receiver type narrowed
from a loaded parent to an unloaded child, the result could get
worse.

Fix: walk parent classes to find loaded ancestors whose cnsSubInfo
provides a sound upper bound. The unloaded class's subtree is a
subset of each parent's subtree, so intersecting parent results
gives a tighter bound while preserving monotonicity.
