Commit title: Fix frozen assertion in update_bytecode when block size changes
Commit body:
Summary:
When update_bytecode modifies a block's bytecodes and the block's
bytecode count changes, classify the change as ChangedAnalyze
(requiring re-analysis) rather than Changed.

A block size change can alter speculation outcomes — speculation
depends on block structure, and a successful speculation rewrite
that adds bytecodes (e.g., absorbing a PopC from a speculated
block) changes the outgoing state flowing to successor blocks.
Without re-analysis, the frozen pass sees the rewritten bytecodes,
gets different speculation behavior, and produces new bytecode
changes that trigger the frozen assertion.

Includes a minimal Hack test that reproduces the bug: a foreach
loop with a ternary conditional assignment creates the exact block
structure needed for speculation to succeed, rewrite the block,
and diverge in the frozen pass.
