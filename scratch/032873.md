Commit title: Func-family redesign for distributed analysis
Commit body:
Summary:
Restructure FuncFamilyEntry to inline StaticInfo and aggregate return
types, eliminating the need to load FuncFamily blobs during analysis.

Key changes:
- Extract MethodFamilyStaticInfo from FuncFamily2::StaticInfo for
  shared use between FuncFamily2 and FuncFamilyEntry.
- Rename BothFF/FFAndSingle/FFAndNone to BothMulti/MultiAndSingle/
  MultiAndNone. Inline StaticInfo, MethodLists, and ReturnTypeHints
  into multi-method entry variants.
- Add MethodRetTypeConstraint with TypeIntersectionConstraint plus
  method flags (isAsync, isNative, isGenerator, hasInOutArgs) for
  return type hint aggregation. Stored as TICSet (deduped set).
- Add methodRetTypeConstraints side-table on ClassInfo2 for return
  type constraints, populated during flatten_classes. For expanded
  method family entries (methods in missingMethods, not methods),
  populate the side-table during process_roots so the constraint
  survives serialization across build_subclass_lists rounds.
- Resolve type hints to initial aggregate return types in init_types
  via initAggregatesFromHints, replacing the previous func-family
  blob-based approach.
- Rewrite resolve_method's general() to walk parent methodFamilies
  entries (via commonParentsOfRegSubs or walkParents) and produce
  Isect2 results with inlined components.
- Add TypeIntersectionConstraint ordering, equality, and hashing
  (with case-insensitive class name comparison) to support TICSet.
- Template unserialize_classes_impl on the resolve function.
- Add cnsSubInfo merge optimization with cnsNotMaybeCount tracking
  and conservative entry short-circuit.
- Add invariant checks for expanded entries and regular-subset-of-all
  constraint property.
