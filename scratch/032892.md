Commit title: introduce fb_intercept2_named_args reflection support
Commit body:
Summary:
1. Introduce a variant of fb_intercept2 that takes lambdas accepting named args.
2. Introduce a reflection function to invoke functions with named args, intended to be used from fb_intercept2_named_args.

The basic idea here is that in the future, fb_intercept2 calls should all be named-args-aware. To make the transition easier, this diff introduces a backwards-compatible fb_intercept2 variant. The separate function name allows us to type the lambdas that are passed in, but they behave identically in the runtime (the event hook code just inspects the function you pass in that's mocking.)

The reflection invoke currently supports static method references and function pointers.

To support a smooth transition to unpacked kwarg support in the future (something like f(...$args, kwargs=...$kwargs)), we pass the named args as a name => value dict.
