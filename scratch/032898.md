Commit title: fbthrift CMake: don't require mvfst or build transport under THRIFT_SERIALIZATION_ONLY
Commit body:
Summary:
Two related fixes for the THRIFT_SERIALIZATION_ONLY=ON build mode:

1) thrift/lib/cpp/CMakeLists.txt: skip building and installing the transport target when THRIFT_SERIALIZATION_ONLY is on. transport's sources reference apache::thrift::rocket::CompressionManager (in thriftcpp2), which isn't built in serialization-only mode, so the static archive contains unresolved references and downstream consumers fail to link. The async / thrift INTERFACE / install blocks already gate on THRIFT_SERIALIZATION_ONLY; transport was the straggler.

2) thrift/cmake/FBThriftConfig.cmake.in (xplat copy — no fbcode copy of this file exists): drop REQUIRED from find_package(mvfst). Under THRIFT_SERIALIZATION_ONLY=ON the RPC stack is absent and no installed library references mvfst, so requiring downstream consumers to provide mvfst was a phantom dependency.

Together these let `find_package(FBThrift CONFIG REQUIRED)` succeed in a serialization-only deployment without needing mvfst on the consumer side.
