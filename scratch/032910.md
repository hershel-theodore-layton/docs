Commit title: Fix data race in StripedThrottledLifoSemBalancer::Worker initialization
Commit body:
Summary:
`Worker::shutdown_` is a non-atomic `bool` declared after `thread_`, so member-initialization order initializes the thread (and starts running `loop()`) before the NSDMI for `shutdown_` writes its initial `false`. The worker reads `shutdown_` in `cv_.wait_for`'s predicate, racing with that initial write. The mutex around the read does not help because the write side is unsynchronized.

In practice the storage is zero, so the worker observes `false` and behaves correctly, but it is UB and TSAN intermittently flags it (~3/10 test runs of `striped_edf_thread_pool_executor_test`).

Reorder declarations so `shutdown_` precedes `thread_`. No other changes needed.
