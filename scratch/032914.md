Commit title: Add ConcurrentBSkipList — concurrent B-tree skip list
Commit body:
Summary:
ConcurrentBSkipList is a concurrent B-tree/skip-list hybrid inspired by "Bridging Cache-Friendliness and Concurrency: A Locality-Optimized In-Memory B-Skiplist" (Li et al., ICPP 2025, https://dl.acm.org/doi/10.1145/3754598.3754655). This implementation adapts the ideas and core structure from the Apache-2.0-licensed bskip artifact (https://github.com/Ratbuyer/bskip_artifact) to Folly's API, concurrency, and validation requirements.

It packs multiple keys per node for better locality on skip-heavy scans while keeping a fully concurrent mutation path.

The implementation is organized around two files:
- ConcurrentBSkipList-detail.h centralizes key storage policy, seqlock, adaptive-read machinery, and the shared node layout.
- ConcurrentBSkipList.h keeps the higher-level algorithms grouped by protocol: public API, Skipper read escalation, hand-over-hand traversal, insert/split, and height growth.

Template parameters:
- `T` -- key type. Must have `std::numeric_limits` specialization for sentinel values.
- `PayloadType` -- per-slot payload (void for key-only sets). Must be trivially copyable.
- `B` -- leaf fanout (keys per node). Higher B = better scan locality, worse insert cost.
- `KeyReadPolicy` -- `RelaxedAtomic` (default for hardware-atomic keys) or `Locked`. RelaxedAtomic enables optimistic lock-free reads via seqlock; Locked takes a shared mutex on every read. A `static_assert` enforces that RelaxedAtomic is only used with hardware-atomic key and payload types.
- `LeafStoragePolicy` -- `Separate` (SoA: parallel key/payload arrays) or `Inline` (AoS: interleaved {key, payload} records).
- Named aliases: `ConcurrentBSkipSet` (key-only), `ConcurrentBSkipMap` (SoA with payload), `ConcurrentBSkipInlineMap` (AoS with payload).

Concurrency model:
- Writers use per-node RWSpinLock (exclusive for mutations, shared for reads) plus a seqlock version counter.
- The seqlock follows the standard protocol: writer does store(version+1, relaxed) -> fence(release) -> write data -> store(version+2, release); reader does load(version, acquire) -> read data -> fence(acquire) -> load(version, relaxed) -> compare. All fences use std::atomic_thread_fence directly (compiler barrier on x86, real fence on ARM).
- Keys and payloads are stored in AtomicSlot<T> (wrapping std::atomic<T>) for typed single-instruction loads (e.g. vmovdqa for 16B keys on x86) instead of byte-at-a-time memcpy.
- skipTo() escalation: scan current leaf optimistically -> rescan after range check -> scan adjacent leaf -> optimistic descent from cached internal nodes -> locked HOH descent from root (guaranteed progress).
- The locked fallback exists because profiling showed that taking a shared lock is cheaper than infinite spinning on a contended seqlock.
- The sentinel key at slot 0 of the initial leaf is tombstoned, so all scan paths start at slot 0 and skip it naturally via the tombstone check.

Benchmark highlights (100K keys, mode/opt, vs folly::ConcurrentSkipList):

  RelaxedAtomic mode (optimistic, lock-free reads):
  - skipTo stride-10: 6x faster (uint32), 2.8x (16B key)
  - Iterate: 4.3x (uint32), 2.5x (16B key)
  - Insert 100K: 1.8x (uint32), 1.5x (16B key)

  Locked mode (shared mutex on every read, no seqlock):
  - skipTo stride-10 (16B key): 1.5x faster than CSL
  - Iterate (16B key): 1.2x faster than CSL
  Even the locked path outperforms CSL because the speedup comes from the B-tree leaf structure (cache-friendly linear scan of 24-32 keys per node) not from the seqlock. CSL does one key per node with pointer chasing.

  Regressions vs CSL:
  - contains (point lookup): ~40% slower -- root-to-leaf descent doesn't amortize across a scan
  - skipTo stride-100 (16B key): ~35% slower -- long jumps bypass leaf-scan wins

ARM (AArch64): Built and tested on x86 only. The seqlock uses portable std::atomic_thread_fence orderings (real fences on ARM, compiler barriers on x86), so correctness is architecture-independent. kReadSpins is tuned down to 48 (vs 256 on x86) for the heavier isb spin-wait cost.
