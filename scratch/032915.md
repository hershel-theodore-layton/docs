Commit title: Add BoolOrX definitions to runtime, for legacy PHP APIs
Commit body:
Summary:
Many of our legacy PHP APIs still used "false" as a return value to denote failure. Even in WWW, especially third-party APIs, this is still found. Currently, we can't accurately type these APIs, and resort to `mixed`, or `dynamic`, or just `UNSAFE_CAST` our way around the issue.

Better to at least have the ability to properly type these APIs, prior to providing proper wrappers that use `null` or other means of denoting failure. So introduce types `BoolOrX` that are defined to be `case type BoolOrX = bool | X`.

I'd like to write `case type BoolOr<T> = bool | T` but that has two downsides: (1) it's rejected by `hh` because we don't know that `T` is disjoint from `bool`, and (2) it's not enforced by HHVM, whereas the non-generic case types are.
