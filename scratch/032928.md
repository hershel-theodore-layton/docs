Commit title: Remove __AutocompleteSortText feature from typechecker
Commit body:
Summary:
The `__AutocompleteSortText` attribute and its `autocomplete_sort_text` rollout flag are being abandoned. The attribute was used to influence the order in which IDE autocomplete suggestions appeared, by attaching a sort-text prefix to a class or method. This diff removes the feature end-to-end from the Hack typechecker. The WWW side of the cleanup is in a separate diff.

Removed:
- The `__AutocompleteSortText` attribute special name from `naming_special_names.ml`/`.rs` and `hackrs/special_names/special_names.rs`, and its NAST validation (`check_autocomplete_valid_text` and the two `check_attribute_arity` calls in `attribute_nast_checks.ml`). Also deletes the orphan elab pass file `validate_user_attribute_autocomplete_sort_text_static.rs` (it was never registered in `passes.rs`).
- The decl-level plumbing: `dc_sort_text` / `elt_sort_text` / `ce_sort_text` / `sm_sort_text` fields and their inheritance logic in `decl_inherit.ml`/`fold.rs`/`inherit.rs`. The Rust hackrs `FoldedClass`, `FoldedElement`, and `ShallowMethod` no longer carry `sort_text`. The decl folder no longer extracts the attribute.
- The autocomplete pipeline: `res_sortText` field on `autocomplete_item`, the `(name, ty, sort_text)` tuple in `get_class_elt_types`, the conditional in `clientLsp.ml` that sourced LSP `sortText` from the attribute, and the `using_sort_text_for_autocomplete` telemetry event.
- The rollout flag `autocomplete_sort_text` from `rollout_flags`, `ServerLocalConfig`, `GlobalOptions`, `TypecheckerOptions`, JustKnobs registration, config keys, oxidized Rust types, and test config.
- The Glean autocomplete query for sort_text (`query_for_sort_text` in `gleanQuery.ml` and its caller in `glean_autocomplete_query.ml`).
- Dedicated tests for the feature (autocomplete_sort_*, sort_text_*) and the manual section/extracted file.

`sort_text` was also wired through `FileInfo.id`/`pfh_decls` for the search index. Rather than churning every consumer of those types, this diff just stops populating it (`decl.sort_text()` removed; `direct_decl_parser.rs` passes `None`). The `FileInfo.sort_text` field is now always `None` and can be removed in a follow-up.
