Commit title: Add `strictOrdering` mode to StripedEDFThreadPoolExecutor
Commit body:
Summary:
Add an opt-in `Options::strictOrdering` flag that forces a single stripe regardless of CPU topology. With this set, `StripedEDFThreadPoolExecutor` becomes a strict-EDF executor with submission-order tie-breaking, equivalent to `folly::EDFThreadPoolExecutor`. Useful when callers want the simpler API of `StripedEDFThreadPoolExecutor` (`SoftRealTimeExecutor` interface, `ThrottledLifoSem`-based wakeups) but cannot tolerate the per-LLC EDF approximation.

The goal is to eventually replace `EDFThreadPoolExecutor` entirely.
