Summary:
**Stack Summary**:
This stack of diffs adds support for named parameters in call contexts in HHBBC. These changes are required to ensure that type inference doesn't go wrong in the presence of default named parameters.

Important: This stack relies on the assumption that HackC has reordered all parameter lists such that the named parameters appear first, in lexicographical order (and that the argument lists have been reordered accordingly).

**This Diff**:
1. Adds a list of named arguments in the CallContext struct, and reflects this change in the logic of (i) the equality operator and (ii) hash calculation for the CallContext objects. This struct represents the calling context for a called function, to support its context-sensitive analysis. When instantiated in `fCallTryFold`, the call context is now passed the list of named arguments by extracting it from FCallArgs object. This is also ensured for all brace-init constructions of objects of CallContext.

2. Adds a reference to the list of named arguments in the KnownArgs struct. This struct is instantiated in `analyze_func_inline`, which now takes the list of named arguments at all its call sites (see next points), and passes that list in the initializer of KnownArgs.

3. Passes the list of named arguments to `analyze_func_inline` at all its call sites in `context_sensitive_return_type`.

4. Passes the required list to`context_sensitive_return_type` when it is invoked from `lookup_return_type` (which, in turn, now accepts the list as its argument, for context-sensitive overloads). Also passes the list to `lookup_foldable_return_type`.

5. Extracts and passes namedArgNames in fcallKnownImpl to `lookup_return_type`.

6. Adds information for argNames in FTACE logs for KnownArgs. (This point, #6, was implemented through Claude and the author doesn't understand the generated syntax well enough; needs to be reviewed carefully.)
