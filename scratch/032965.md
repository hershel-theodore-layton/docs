Commit title: Frozen2: Add popcount() to ArrayLayout::View for efficient list<bool>
Commit body:
Summary:
## PROBLEM

Frozen2's `list<bool>` stores bools as packed bits (1 bit per element,
`folly::Bits<uint8_t>` convention). A key use case for packed boolean lists
is validity bitmaps in columnar storage, where each bit indicates whether
the corresponding element in a parallel column is present or null.

A core operation on such bitmaps is `rank(i)` — count the set bits in
positions `[0, i)`. In sparse columnar storage, where only non-null values
are physically stored in a compact array, every logical-row lookup requires
a `rank` over the validity bitmap to find the physical index. Even with a
prefix-sum acceleration scheme that bounds per-lookup work to one block
(typically 512 bits = one cache line), the inner-loop popcount still
dominates lookup cost.

Today, the only way to compute `rank` over a frozen `list<bool>` is to
iterate `operator[]` one element at a time — O(n) individual
`folly::Bits<uint8_t>::test()` calls with no opportunity for hardware
acceleration. There is no API for bulk operations on the packed bit data.

The new benchmark (`FrozenSparseColumnRankBenchmark`) models the realistic
lookup shape (short-circuit on null first, only compute rank for non-null
entries) and shows the iterator path is **~26-27× slower than the new
`popcount()` API** in the rank-dominated regime (d × N ≫ bit-test cost) at
N=512 (one cache line — bounded prefix-sum hot path), N=8K, and N=100K
(typical ODS3 stride scale). At low density (e.g., N=512, d=0.05) the
speedup degrades toward 1× because most lookups short-circuit and per-rank
work is too small to matter — confirming the analysis. See Test Plan for
full numbers.

## SOLUTION

Add two `popcount()` overloads on `ArrayLayout::View`, restricted to
`Item == bool` via SFINAE so the methods only exist for `list<bool>`:

- `size_t popcount() const` — total set bits in the bitmap. O(N/8) using
  hardware POPCNT (`std::popcount`).
- `size_t popcount(size_t until) const` — set bits in `[0, until)`. O(until/8).
  Useful for rank-select. Precondition: `until <= size()`.

Both methods read the packed bit storage internally (folly::Bits<uint8_t>
LSB-first packing) and use `std::popcount` over byte chunks plus a masked
partial byte. The bit layout is **not** exposed — the public API is just
"give me the count," and the implementation can evolve freely (different
packing, compressed variants, etc.) without breaking callers.

The SFINAE guard (`std::enable_if_t<std::is_same_v<I, bool>>`) ensures
calling `frozen.popcount()` on a non-bool list is a compile error.

### Changes
- Added `popcount()` and `popcount(size_t until)` to `ArrayLayout::View`
  in `FrozenRange-inl.h`, restricted to `Item == bool` via SFINAE.
- Added private `popcountImpl(size_t until)` helper that walks the byte
  storage with `std::popcount`. Handles Frozen2's zero-bit optimization
  (returns 0 when `bits == 0`, i.e., all-false lists with no allocated
  storage).
- Added `FrozenBoolListTest.cpp` with 11 tests exercising the new API
  across boundary conditions.
- Added `FrozenSparseColumnRankBenchmark.cpp` exercising the motivating
  workload — sparse-column rank lookups with null short-circuit — at
  N=512 / 8K / 100K and densities 0.05 / 0.5 / 0.9.
- Added `frozen_bool_list_test` and `frozen_sparse_column_rank_bench`
  BUCK targets.

### Notes for reviewers

- **Placement of `popcount()`**: I considered moving this to a dedicated
  `FrozenBoolList-inl.h` to mirror the existing `FrozenBool-inl.h` /
  `FrozenIntegral-inl.h` pattern (specialize `Layout<list<bool>>` from
  `ArrayLayout<list<bool>, bool>`, put `popcount` on the derived View).
  Left it in `FrozenRange-inl.h` for now since SFINAE keeps the symbol
  invisible for non-bool types and avoids a base-class visibility tweak
  (`data_` / `count_` would need to become `protected` for the derived
  View). Happy to restructure if you'd prefer the dedicated file.

- **Standard popcount**: All popcount calls go through `std::popcount`
  (C++20, `<bit>`), not the folly fallback.
