Commit title: Add configurable read buffer allocation size to Proxygen coro sessions
Commit body:
Summary:
Add readBufNewAllocSize to Proxygen coro HTTPServer::SessionConfig, threaded through HTTPCoroAcceptor and HTTPCoroSession. This allows servers to configure the per-read IOBuf allocation size instead of using the hardcoded 4KB default.

Large uploads (e.g., 80MB S3 PUT) produce IOBuf chains with ~20,000 elements at 4KB each. Setting this to 128KB reduces chain length by 32x, which cuts IOBuf::~IOBuf destructor cost by 44%, cloneAtMost by 82%, and improves write throughput by ~10% in S32M benchmarks.

S32M exposes this as the --http_read_buf_alloc_size gflag (default 4000, matching existing behavior).
