# Production crash

A SIGSEGV is firing in production hyperclient (BET TW jobs) at
`fbcode/folly/io/async/AsyncIoUringSocket.cpp:1528` inside
`AsyncIoUringSocket::WriteSqe::callback`. The crashing instruction is
`parent_->writeSqeActive_ = nullptr;` — the `WriteSqe`'s raw `parent_`
pointer is being dereferenced after the parent `AsyncIoUringSocket` has
been freed.

Reference: https://fburl.com/scuba/coredumper/y3r65k7m
https://www.internalfb.com/phabricator/paste/view/P2316734161?view=markdown

# What the crash actually is

The crashing instruction is at `AsyncIoUringSocket.cpp:1528` inside
`WriteSqe::callback`, but `WriteSqe::callback` is reached as a tail call
from `FastOpenSqe::callback` via `processFastOpenResult`. The dangling
pointer is `WriteSqe::parent_` (declared at `AsyncIoUringSocket.h:414`).
Under ASAN locally this same scenario reports the upstream read in
`IoSqeBase::type()` from `IoUringBackend::internalProcessCqe` against a
freed `FastOpenSqe`, which has the same root cause.

# Why `parent_` is dangling — the FastOpen path

`~AsyncIoUringSocket()` (`AsyncIoUringSocket.cpp:155-200`) cancels the
in-flight `readSqe_` (lines 162-168), `closeSqe_` (170-175),
`connectSqe_` (176-180), and `writeSqeActive_` (185-192) — but it does
**not** cancel `fastOpenSqe_`. The `unique_ptr` simply destructs
in-place. Since `cancel()` was never called, the kernel still holds an
in-flight SQE whose `user_data` points at the freed `FastOpenSqe`. When
the late TFO CQE arrives:

1. `IoUringBackend::internalProcessCqe` reads the freed `FastOpenSqe` to
   dispatch the callback.
2. `FastOpenSqe::callback` (`AsyncIoUringSocket.h:476-478`) calls
   `parent_->processFastOpenResult(cqe)`.
3. On a successful TFO CQE, `processFastOpenResult` at
   `AsyncIoUringSocket.cpp:459-465` runs:
   ```
   processConnectResult(&tmp);
   writeSqeActive_ = fastOpenSqe_->initialWrite.release();
   writeSqeActive_->callback(cqe);
   ```
4. That last call drops directly into `WriteSqe::callback`, which writes
   `parent_->writeSqeActive_ = nullptr;` at line 1528 against a
   `WriteSqe::parent_` that points at the freed `AsyncIoUringSocket`.

The destructor handles the analogous case for `connectSqe_`
(`AsyncIoUringSocket.cpp:176-180`) — `fastOpenSqe_` was simply
overlooked.

# Why this diff is test-only

This diff makes the bug visible on Phabricator with a deterministic
ASAN reproducer so the audit trail clearly states "here is the failing
test that proves the bug". The child diff lands the one-line destructor
fix immediately after this one, flipping the test from red to green and
removing the regression from trunk.
