Commit title: Discover more dependencies statically
Commit body:
Summary:
When distc resolves missing decls during typechecking, it currently only follows class parent edges transitively in the decl graph. This means types referenced in decl signatures (method param/return types, property types, etc.) are not discovered until the worker reports them as missing, requiring additional round-trips.

This diff adds "weak edge" decl discovery: workers now collect type names from decl type signatures and report them alongside the existing parent and ref data. The orchestrator stores these as weak edges in the decl graph, separate from the graph containing strong/parent edges. During dependency resolution, weak edges are expanded one hop from directly looked-up types — the referenced types and their transitive parents are pulled in, but weak edges from those targets are not followed further. This technique applied only to retries and not to the initial batches to avoid over-fetching decls.

This is gated behind the `distc_weak_edge_decl_discovery` JK at the moment. The RE action key includes `-weak-refs` when enabled so RE memory predictor can account for larger decl sets.
