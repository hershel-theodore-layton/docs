Commit title: Allow specifying min require memory for RE worker when building an action
Commit body:
Summary:
While working on D104233100 I've noticed that initial runs with my changes were super slow. Looking at https://fburl.com/scuba/remote_execution_action/jy2c8lbd revealed some interesting things. Since I've modified action keys, RE memory predictor didn't know anything about these batches so it defaulted to 256MB memory which took ages running these actions before OOMing or timing and subsequently retrying. I assume very similar situation might happen when batches change and we see a  new batch emerging so it would end up running for long time on a small memory working and will end retrying anyway.

This diff allows us to set up minimum amount of memory while allowing predictor to override it based on the historic data. That means, in practices, new batches will start with some reasonable amount of memory instead of starting from 256MB and taking multiple iterations to finish while taking a lot of time doing that.
