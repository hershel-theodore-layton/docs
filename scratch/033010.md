Commit title: Handle null connection in pool connect timeout path
Commit body:
Summary:
When a sync connection pool operation times out before a connection is established (e.g., pool replaced mid-connect), `completeOperation` calls `isInEventBaseThread()` which calls `conn()` which CHECKs the connection is non-null — crashing the process. This can happen in stress tests where the pool is replaced while connections are in-flight.

Fix `isInEventBaseThread()` to return true when there's no connection (no event base to verify). Also guard the `hasInitialized()`/`close()` call in `completeOperationInner` to skip when connection is null — there's nothing to close if we never established a connection.
