Commit title: fbcode_builder: per-dependency feature spec
Commit body:
Summary:
Adds a feature system to manifests so each dependency edge can pick which parts of a project to build. Before, the only way to do this was a global CLI flag. Now it lives in the manifest, where it belongs.

A manifest declares features in a new `[features]` section, then gates other sections on `feature_<name>=on/off`:

```ini
# example consumer manifest
[features]
default = rpc
rpc =

[cmake.defines.feature_rpc=off]
PROJECT_RPC=OFF

[dependencies.feature_rpc=on]
fizz
wangle
mvfst
```

A consumer picks features per dep entry:

```ini
[dependencies]
project           # gets rpc (the default)
project = !rpc    # skips rpc — fizz/wangle/mvfst are not pulled in
```

How it resolves: each root project starts with its own defaults. Each dep edge can request a feature, prohibit one (`!name`), or opt out of the dep's defaults (`!default`). Requests union across edges. If one consumer wants a feature and another forbids it, that's a hard error naming both consumers. The resolver loops until nothing changes, because feature-gated `[dependencies]` sections can pull in new edges that contribute new requests.

The resolved feature set is folded into the project cache hash so a `!rpc` build does not collide with a default build of the same project.

This diff only adds the framework — no manifest is migrated here. Child diffs opt fbthrift in to the system.
