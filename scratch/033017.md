Commit title: fbthrift CMake: split RPC and benchmarks into their own options
Commit body:
Summary:
The CMake var was named `THRIFT_SERIALIZATION_ONLY`. That name made it sound like a hard mode switch, but really it just turned RPC off. Drop it and replace with two positive options:

- `THRIFT_RPC` (default ON) — when OFF, skip the RPC link graph (transport, async, thriftcpp2 RPC pieces) and the fizz/wangle/mvfst `find_package` calls.
- `THRIFT_BENCHMARKS` (default ON) — when OFF, skip the benchmark executables (`ProtocolBench`, `VarintUtilsBench`).

Example, before:

```
cmake -DTHRIFT_SERIALIZATION_ONLY=ON ...
```

After:

```
cmake -DTHRIFT_RPC=OFF ...           # RPC off; benchmarks auto-off
cmake -DTHRIFT_BENCHMARKS=OFF ...    # just skip benchmarks
```

`THRIFT_RPC=OFF` force-clears `THRIFT_BENCHMARKS=OFF`, since the benchmark targets link `thriftcpp2`. Asking for benchmarks without RPC would otherwise produce a confusing link error. The clamp prints a status message so the user sees what happened. The gate on each benchmark target is then a single check on `THRIFT_BENCHMARKS`.

This diff also opts the fbthrift manifest in to fbcode_builder's per-dependency feature spec (parent diff), declaring `rpc` and `benchmark` features that map to the new CMake options:

```ini
# manifests/fbthrift
[features]
default = rpc, benchmark
rpc =
benchmark =

[cmake.defines.feature_rpc=off]
THRIFT_RPC=OFF

[cmake.defines.feature_benchmark=off]
THRIFT_BENCHMARKS=OFF

[dependencies.feature_rpc=on]
fizz
libsodium
wangle
mvfst

[dependencies.feature_benchmark=on]
benchmark
```

Default features stay ON, so consumers see no change. A consumer that says `fbthrift = !rpc` skips both the CMake RPC stack and the fetch of fizz/wangle/mvfst. A consumer that says `fbthrift = !benchmark` skips the benchmark fetch and the benchmark targets.
