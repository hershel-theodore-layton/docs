Commit title: Add X25519MLKEM768 to default key shares to avoid HelloRetryRequest
Commit body:
Summary:
D96781701 added X25519MLKEM768 to fizz's default `supportedGroups_` and `defaultShares_`. However, hq's `createFizzClientContext()` overrides `defaultShares` with only `{x25519, secp256r1}`, stripping out the MLKEM768 key share. This creates a mismatch: the client advertises X25519MLKEM768 in the `supported_groups` extension but doesn't include a key share for it in the `key_share` extension. When the server negotiates X25519MLKEM768, it finds no matching key share and sends a HelloRetryRequest (HRR), adding a full round trip to the handshake. This diff adds the MLKEM768 to the defaultShares, thereby avoiding the HRR and the extra RTT.

**Impact**

The fix eliminates one full RTT from the TLS handshake for hq connections when the server negotiates X25519MLKEM768. The initial CWND (10 packets / ~12,520 bytes) has ample room for the larger ClientHello (~1,544 bytes across 2 Initial packets), so no congestion-related delay is introduced.

Note: any application that overrides `setDefaultShares` without including `X25519MLKEM768` will have the same HRR issue if the server negotiates that group. Application owners should audit their fizz client context configuration.
