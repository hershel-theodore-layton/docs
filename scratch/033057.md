Commit title: Respect __IgnoreReadonlyError in constraint_method_call mode
Commit body:
Summary:
The constraint_method_call typing path did not respect the <<__IgnoreReadonlyError>> attribute on function parameters. In the normal call path, `call_param` extracts the per-parameter `ignore_readonly_error` flag and passes it via `Subtype_env.ignore_readonly` to suppress readonly mismatch errors. But in the constraint_method_call path, the entire function type is compared via `sub_type_i`, which creates a `Subtype_env` with `ignore_readonly = false` — silently ignoring the attribute.

Two changes in `simplify_subtype_for_matching_parameters`:
1. `simplify_param_readonly` now also checks `get_fp_ignore_readonly_error` on both fn_param_sub and fn_param_super, so parameter-level readonly mismatches are suppressed when the attribute is present.
2. `subtype_env_for_param` now sets `ignore_readonly = true` when either parameter has the flag, so inner function type comparisons (e.g., lambda vs readonly callable) also respect the attribute.
