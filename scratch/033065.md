Commit title: Fix sys.path in getdeps.py shim shadowing stdlib platform module
Commit body:
Summary:
D104495377 refactored getdeps.py into a thin shim plus getdeps/cli.py, but the shim inserted the wrong directory onto sys.path:

  sys.path.insert(0, os.path.join(os.path.dirname(...), "getdeps"))

This put fbcode_builder/getdeps/ (the package internals) on sys.path, so bare `import platform` anywhere in the package found getdeps/platform.py instead of the stdlib platform module, causing `AttributeError: module platform has no attribute machine` in HostType.__init__ -> is_current_host_arm().

Fix: insert fbcode_builder/ (the parent) instead, so getdeps is importable as a package and stdlib imports are not shadowed.
