Commit title: Expose ConcurrentBSkipList payload hooks for RTIndex hazard pointers
Commit body:
Summary:
Add the narrow ConcurrentBSkipList APIs needed by RTIndex to store spilled hitdata pointers directly in BSkip leaf payload slots with hazard-pointer reclamation.

Skipper now exposes the current leaf, slot, and a fresh payload read so a reader can publish a hazard pointer and then verify that the same payload pointer is still live before dereferencing it. Payload-bearing lists also get removeAndGetPayload(), which tombstones a key and returns the old payload from the same locked leaf visit so callers can retire overwritten storage without a separate find-before-remove.

Skipper copy is also made explicit: copying preserves the current key plus advisory leaf/path cache. Those copied node pointers are safe because BSkip nodes live with the list, and every optimistic use still revalidates or falls back to locked descent if stale. RTIndex uses this to keep its adaptor mechanical instead of carrying lazy restore state.

These APIs are deliberately specific to existing BSkip skipper/removal mechanics; they do not change default set/map behavior.
