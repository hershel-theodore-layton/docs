Commit title: Add configuration support for custom map functions
Commit body:
Summary:
Currently, we hardcode types which should be mapped over. This include stdlib data types like list, option, ref etc but also some types which are specific to Hack. This diff adds configuration which lets us specify the details in the derive clause.

Changes:
- Added Maps module to hold configuration for custom map functions
- Updated Analyse module to include maps in analysis state
- Updated Gen_traverse to accept and use maps parameter
- Modified aux_constr to check configured maps before default handling
- Removed hard-coded cases for SMap.t, TShapeMap.t, Either.t, and fun_type
- Stdlib types (option, list, array, lazy_t, result, ref) remain hard-coded

This allows users to configure custom map functions for their own container
types without modifying the PPX. For example:
  [@deriving transform ~maps:["SMap.t", "SMap.map"]]
