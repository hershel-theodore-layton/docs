## What

Implement typing for shape and tuple destructuring, per spec:  https://fburl.com/hack_shape_destructuring_hip

Gated behind unstable syntax feature `shape_and_tuple_destructuring.

Note: I also tweaked a few test file names so that files with no errors have basenames ending in "_good" and files with errors have basenames ending in "_bad".

## Details

See doc comments in the implementation for the algorithms and design considerations.

Note that the HIP did not get into much detail about how shape and tuple destructuring interact with subtyping and dynamic, but arguably the desired behavior was implied by the desugaring explanation for the runtime semantics, the safety considerations, and how we do subtyping elsewhere. Imo the choices for user-facing behavior were mostly forced.

## Disclaimer–and request for help with Sound Dynamic

Written under extreme time pressure due to my being yoinked to join Applied AI, so I leaned harder on Claude than I would otherwise.

I'm hazy about the interaction with sound dynamic: the dynamic pass, dynamic, and like types. The actual behavior seems right, but the implementation seems a little complicated. I'd welcome it if there were pre-existing infrastructure or patterns the reviewer recommends, hope we're not reinventing any wheels here.
