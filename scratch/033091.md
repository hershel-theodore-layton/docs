Commit title: folly: AsyncUDPSocket: support receiving and setting destination address via PKTINFO
Commit body:
Summary:
Adds opt-in support to AsyncUDPSocket for receiving and setting the per-packet destination address via `IPV6_PKTINFO` / `IP_PKTINFO` cmsgs. Useful for UDP servers bound to a wildcard address that need to reply with the original destination as the source IP (the UDP analogue of TCP's `accept()` auto-pinning the SYN's destination).

## Why we need this?
For TTLS tunneled UDP traffic, we establish tunneling via CONNECT-UDP. For TTLS tunneling to SVC1 addresses in gedge, the receiving TTLS revproxy subsumes an SVC1 ip but actually runs on the gedge task. In order for the TTLS fwdproxy to accept the returned traffic, it needs revproxy to reply back with the same SVC1 address. This change allows us to bind the address to the socket.

## Key changes:
Changes (folly):
- New `setRecvDstAddr(bool)` setter (mirrors `setRecvTos`); when enabled, `init()` applies `IPV6_RECVPKTINFO` / `IP_PKTINFO`.
- New `OnDataAvailableParams::localAddress` field populated from `IPV6_PKTINFO` / `IP_PKTINFO` cmsgs.
- Extended `fromMsg()` to parse PKTINFO cmsgs.
- Bumped `kCmsgSpace` so the cmsg buffer in folly's recvmsg loop fits PKTINFO.

Changes (mvfst):
- `mvfst` keeps its own copy of `kCmsgSpace` in `quic/common/udpsocket/QuicAsyncUDPSocket.h` and `FollyQuicAsyncUDPSocket::onDataAvailable` runtime-checks the two are identical (`MVCHECK_EQ`). Bumped the mvfst mirror in lockstep so the assertion still holds. This is a 4-line constant change and is required for any folly `kCmsgSpace` bump — without it every QUIC server using `FollyQuicAsyncUDPSocket` crashes on the first packet (`Check failed: ... 112 vs 184`).

Default off — every existing caller sees zero behavior change. Mirrors apply to both `fbcode/folly` and `xplat/folly`; the mvfst change goes through the standard `fbcode/quic` → `xplat/quic` dirsync.

The TX side (attaching `IPV6_PKTINFO` cmsgs to outbound packets) uses the existing `setNontrivialCmsgs` API and does not require folly changes.
