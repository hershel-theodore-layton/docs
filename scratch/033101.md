Commit title: Replace --shared-libs with --shared-lib (static-PIC deps)
Commit body:
Summary:
The previous --shared-libs flag built every dep as its own .so and wired up rpath fixups so the .so graph could find its siblings — useful when shipping a tree of shared libraries, but not what most consumers actually want.

The more common need is a single shared library at the consumer that statically links a tree of getdeps deps. That requires every dep archive to be position-independent, which projects today achieve by hand-injecting -DCMAKE_POSITION_INDEPENDENT_CODE=ON into --extra-cmake-defines for every dep — error-prone and easy to forget for one dep.

This diff replaces --shared-libs with --shared-lib (singular), which:
- Sets CMAKE_POSITION_INDEPENDENT_CODE=ON for every cmake-built dep
- Appends -fPIC to CFLAGS/CXXFLAGS for autotools and make-built deps
- Passes cxxflags=-fPIC/cflags=-fPIC to boost b2
- Leaves BUILD_SHARED_LIBS alone — the consumer's CMakeLists decides whether it produces a .so/.dylib or .a

Migrations in this diff:
- Folly's OSS shared-libs CI variant moves to --shared-lib + a per-package BUILD_SHARED_LIBS=ON for folly itself (preserves the shared-output test while exercising the new flag pattern end-to-end).
- Rebalancer's CI drops its manual CMAKE_POSITION_INDEPENDENT_CODE=ON injection in favor of --shared-lib.
- Four Sandcastle owners (fbthrift-shared, folly-shared, glean, hsthrift) switch to shared_lib=True. glean/hsthrift's BOOST_LINK_STATIC=OFF override is dropped — that coordinated with the old shared-everywhere semantics and would now point to nonexistent shared boost.

Cleanup: the dead `shared_libs` manifest predicate is removed from ALLOWED_VARIABLES and the four manifests that referenced it (c-ares, libaio, libevent, libevent-python) are simplified to express the static-build defaults unconditionally.
