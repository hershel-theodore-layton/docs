Commit title: Introduce InterceptorResult<T> variant for processClientInterceptorsOnResponse
Commit body:
Summary:
Introduce InterceptorResult<T> = std::variant<folly::Try<T>> as the return type for processClientInterceptorsOnResponse, along with blockingWaitInterceptorResult helper. This prepares for async-capable client interceptors by converting all callers to use the helper now, while the variant only contains Try<T> today. A follow-up diff adds the Task<Try<T>> variant — callers will not need to change.

No interceptor API changes — onResponse stays void. No behavior change. noexcept preserved.

Callers use blockingWaitInterceptorResult instead of accessing Try<T> directly:
- co_ generated methods: blockingWaitInterceptorResult (no-op on Try<T>)
- semifuture_ methods: blockingWaitInterceptorResult (returns Try<T> for deferValue chain)
- Legacy header_semifuture and OmniClient: blockingWaitInterceptorResult
