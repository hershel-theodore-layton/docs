Commit title: Make ClientInterceptor::onResponse async-capable
Commit body:
Summary:
Change ClientInterceptor::onResponse from void to std::optional<folly::coro::Task<void>>. Interceptors returning std::nullopt (the default) incur zero overhead. Interceptors needing async work return a Task<void>.

Add Task<Try<T>> as a second variant to InterceptorResult<T> (now std::variant<Try<T>, Task<Try<T>>>). Update blockingWaitInterceptorResult to handle both variants. Callers updated in Diff 1 do not change — the helper absorbs the new variant.

processClientInterceptorsOnResponse remains a regular function (not a coroutine) to avoid coroutine frame allocation on the sync hot path. When it encounters the first interceptor that returns a Task, it delegates to processRemainingInterceptorsAsync (a private static coroutine) which snapshots owned copies of interceptor references, service name, and storage pointers before any co_await to avoid ContextStack lifetime issues.

Codegen template for co_ methods uses inline std::get_if + co_await dispatch to get true async on the coroutine path. Non-coroutine paths (semifuture, sync, OmniClient) use blockingWaitInterceptorResult.

All interceptor overrides (thrift tests + external consumers) updated to return std::nullopt — no behavior change.
