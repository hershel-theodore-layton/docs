Commit body:
Summary:
Regenerate all OSS GitHub Actions workflow files via `update-all-github-actions.sh`. Three fixes bundled:

1. **Test step cmake defines** (`D104914460` follow-up): the generator fix was not applied to the already-committed workflow files. The test step was missing `--extra-cmake-defines`, so it computed different dep-install-dir hashes than the build steps — `CMAKE_CXX_COMPILER_LAUNCHER=sccache` was folded into every dep's hash via `GETDEPS_CMAKE_DEFINES`, so the test step looked in the wrong directories and LD_LIBRARY_PATH was broken at test time. CacheLib was the known-failing case; openr, rebalancer, folly-shared-lib, and others with test steps had the same latent bug.

2. **sccache cmake define removed from generator**: `workflow_generator.py` was manually injecting `CMAKE_CXX_COMPILER_LAUNCHER=sccache` into `--extra-cmake-defines`, which put it into `GETDEPS_CMAKE_DEFINES` and thus into every dep's install-dir hash. This is the root cause of the hash-mismatch bug above. `builder.py`'s `_compute_cmake_define_args` already calls `path_search(env, "sccache")` and injects `CMAKE_CXX_COMPILER_LAUNCHER` automatically when sccache is in PATH — outside the hash — so the explicit injection is redundant and harmful. Remove it.

3. **Regen script cmake side-channel removed**: `update-all-github-actions.sh` had a `--package-extra-cmake-defines "fbthrift=..."` cmake side-channel for the rebalancer. The rebalancer manifest already declares `fbthrift = !rpc, !benchmark`, and the feature spec drives the cmake defines at runtime — no side-channel needed.
