Commit title: Enable request context invalidation by default with killswitch
Commit body:
Summary:
Enable request context invalidation by default for all Python thrift handlers. The invalidator is automatically installed in `RequestContext._fbthrift_create`, so accessing a stale `RequestContext` after the request completes raises `RuntimeError`.

Controlled by the `py_request_context_invalidation_killswitch` thrift flag (default `false` = invalidation enabled). Setting the killswitch to `true` disables invalidation, reverting to the previous behavior (dangling pointer, no error).

**Changes:**
- New C++ flag wrapper in `server/flagged/PromptRequestContextInvalidation.{h,cpp}` — killswitch defaults to `false` (feature on)
- `request_context.pyx`: `_fbthrift_create` calls `installInvalidator` when the killswitch is off
- Removed `_enable_validity_enforcement()` — no longer needed since invalidation is automatic
- New Cython test helper `test/flag_helpers.{pxd,pyx,pyi}` with `mock_prompt_request_context_invalidation` context manager and `mockSetRequestContextInvalidationKillswitch` C++ mock

**Tests:**
- `test_request_context_invalidated_by_default`: verifies invalidation works without any explicit opt-in
- `test_request_context_killswitch_disables_invalidation`: verifies the killswitch disables invalidation
- `test_request_context_invalidated_in_background_task`: verifies background tasks get RuntimeError on stale access
