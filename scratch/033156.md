Commit body:
Summary: This flag is now globally `false` (i.e. transparent type alias package boundary violations are always reported as hard errors), so the carve-out is no longer needed. This diff removes the flag definition and all of its scaffolding from globalOptions / typecheckerOptions / typing_env / serverConfig / config_keys (OCaml side) and hh_config / oxidized (Rust side), simplifies the single call site in `typing_type_wellformedness.ml` to take the always-`Yes Transparent_type_alias` path, removes the two `in_typedef` branches in `identifySymbolService.ml` that consulted the flag (they now always mark the typedef body as affecting prod build), updates the package boundary tests (`test/package/BUCK` no longer threads the now-removed config; expectations regenerated), and deletes the four `identify_symbol/{typedef,newtype}_{allow,no}_typedef_violations.*` tests that parameterized symbol identification over this flag (their coverage is preserved by the existing `typedef.php` and `newtype.php` tests in that directory).
