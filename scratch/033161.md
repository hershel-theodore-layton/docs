Commit title: thrift HTTPClientChannel: expose enablePingProbes() pass-through
Commit body:
Summary:
Add a public `enablePingProbes()` method on `HTTPClientChannel` that delegates to the underlying `proxygen::HTTPSession::enablePingProbes`. proxygen already implements full periodic-PING / reply-timeout / reset-on-ingress logic; this exposes that capability to fbthrift HTTP/2 clients that previously had no way to reach it.

Use case: keep an HTTP/2 channel alive across layer-7 reverse proxies (e.g. HTTP CONNECT through fwdproxy, AWS ALB) whose connection idle timers would otherwise tear down a long-tail request-response RPC -- a thrift call whose server side processes for 10+ minutes without any bytes flowing on the stream.

Additive only. Default behavior unchanged for callers that don't call `enablePingProbes`. No-op for HTTP/1.1 sessions and when the session is closed.
