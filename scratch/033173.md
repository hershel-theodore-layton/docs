Commit title: Add AF_XDP UAPI compat definitions to NetOps.h
Commit body:
Summary:
The build env's kernel headers may predate Linux kernel 6.8 and therefore
lack the AF_XDP TX metadata UAPI types (`xsk_tx_metadata`,
`tx_metadata_len` field on `xdp_umem_reg`) and constants
(`XDP_TX_METADATA`, `XDP_TXMD_FLAGS_CHECKSUM`). Add the standard
"copied from uapi/linux/foo.h" compat definitions for these in
NetOps.h, alongside the existing copies for `tcp_zerocopy_receive`,
`sock_txtime`, `enum timestamping_flags`, etc.

This is a precursor to a quic/xsk change that uses
`XDP_TXMD_FLAGS_CHECKSUM` to offload UDP checksums via AF_XDP TX
metadata. Putting the UAPI defs here (rather than locally in
quic/xsk) follows the existing precedent and means future Meta
networking code that touches AF_XDP can pick these up without
re-copying.

The kernel parses XDP_UMEM_REG by `optlen`, so passing the
larger `xdp_umem_reg` struct on an older kernel just causes the
trailing field to be ignored — there's no kernel-version-gated
behavior change here, just type availability for callers.
