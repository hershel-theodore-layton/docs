Commit title: Add _or_none property accessors for RequestContext
Commit body:
Summary:
Add non-throwing property accessors for `RequestContext` that return `None` instead of raising `RuntimeError` when the request context is no longer valid. This provides a safe, race-free way to access context properties without needing a separate `is_valid()` check.

**New properties:**
- `read_headers_or_none`
- `write_headers_or_none`
- `priority_or_none`
- `request_timeout_or_none`

These wrap the corresponding raising properties with a `none_on_error` decorator that catches `RuntimeError` and returns `None`.

Safe properties that use eagerly-copied data (`connection_context`, `request_id`, `method_name`) remain unchanged — they never raise.
