Commit title: Store small_vector capacity inline when sizeof(HeapPtrWithCapacity) == sizeof(InlineStorageType)
Commit body:
Summary:
There is no reason not to do this, and it's an outright logical bug.

The effect of this is that `kHasInlineCapacity` == false -> `kAlwaysHasCapacity` == false; for a small container under `kHeapifyCapacityThreshold` == 800, we won't have heapified capacity, thus `hasCapacity()` returns false.

Without capacity, we rely on malloc to answer the `capacity()` question. This is much more expensive: has to call `malloc_usable_size` and do the prefix tree walk.

Obviously this `<=` is not the sole component for this malloc overhead, but this bug fix should reduce the cost a bit.
