Commit title: Use per-key session queue for TLS 1.3 single-use tickets
Commit body:
Summary:
TLS 1.3 session tickets are single-use, unlike TLS 1.2 where a single cached session could be reused by unlimited concurrent connections. This caused SSL session reuse to drop from ~100% to ~50% after upgrading to TLS 1.3, because the single-slot-per-key cache meant only one concurrent connection could resume per host.

Changes:
- ThreadSafeSSLSessionCache: Replace single SSLSessionVariant per key with a std::deque (capped at 4 entries). On get, TLS 1.3 sessions are popped (consumed) while TLS 1.2 sessions are copied via SSL_SESSION_up_ref, preserving backward compatibility.
- SSLOptionsProviderBase::storeMysqlSSLSession: Always store the session after connect, not just on non-reused connections. TLS 1.3 sends new single-use tickets even on resumed connections, so we need to cache them for future use.
- Added unit tests for queue mechanics, eviction, and cache miss behavior.
