Commit title: Fix arm64 build failure in generated co_* methods
Commit body:
Summary:
D103914232 introduced async-capable `ClientInterceptor::onResponse` which added `std::get_if` dispatch on the `InterceptorResult` variant in generated `co_*` method bodies. The generated code used `(co_await std::move(*task)).throwUnlessValue()` which fails on arm64 clang19 (`cfg:opt-linux-arm64-clang19-no-san`) with "insufficient contextual information to determine type" — the compiler cannot deduce the type of the `co_await` expression when used directly as a temporary.

Fix: split into an explicitly-typed intermediate variable `folly::Try<void> interceptorTry = co_await std::move(*task)` followed by `interceptorTry.throwUnlessValue()`. This gives the compiler sufficient type context while preserving identical runtime behavior. Applied to both the inline header template (`async_client_functions.whisker`) and the cpp template (`coroutine_functions.whisker`).
