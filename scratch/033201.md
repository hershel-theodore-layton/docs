Summary:
Per draft-ietf-scone-protocol §6, scone_supported is a unilateral advertisement of receive-willingness. mvfst was conflating it with peer advertisement, dropping network-element-injected SCONE on flows where the peer didn't advertise.

- Split TransportSettings.enableScone into advertiseSconeSupport and enableSconeSend.
- Renamed SconeState::negotiated to top-level QuicConnectionStateBase::peerAdvertisedSconeSupport.
- Initialize SconeState based on local advertise alone; gate sending on peer advertise + local enableSconeSend.
- Java mEnableScone maps to advertise; server thrift enable_scone maps to send.
