# Facebook

This diff adds a new flag `cldp_member_selection` to `hh --find-my-test-staging`. If enabled, we now selected individual members `Foo::testBar::X` of CLDP test families. The idea is that `X` is selected as a member of the CLDP test family `Foo::testBar` if X appears in our selection graph and is a subtype of the base type of the CLDP used by `Foo::testBar`

Selection works in two stages:

## Precomputation
At the start of the test selection process, we discover all CLDPs in the repo (subclasses of `ClassLevelDataProvider`), resolve each one's `TBaseClass` type constant to find the top of the hierarchy it acts on, and build a mapping from base types to CLDPs. There are ~250 of them at the moment in www, this takes 1-3 seconds (on a freshly started hh_server). I've also seen it take up to 30s. I think the latter may happen when Eden does not have the necessary files cached. I'm logging the duration of the precomputation step as part of our telemetry to figure out how things will look like on sandcastle.

## During graph traversal:
For each class `C` we reach during the traversal, we now traverse all of its  ancestors `A` and check if `A` is the `TBaseType` of any CLDP `L`. This is cheap thanks to the precomputation: For each `A` we just do a hashtable lookup.

If `C` does indeed have such an ancestor `A`, we create a new node storing C, A, and L using a new dedicated strategy `CCLDPBaseType`. This node is subsequently expanded by computing all test methods `T::m` that use `L` as their CLDP. We then add an edge to the graph that ultimately causes `T::m::C` to be marked as a selected CLDP test member.
The computation which test methods actually use a CLDP L is cached in case we see another usage of L later on.

## Code structure
- `Testinfra_conventions`: I've moved the various names and other conventions (test framework classes, CLDP class/trait/typeconst names, `is_test_method`, `is_test_class`, `get_test_method_cldp`) into this new module. The idea is that this is the main place that may need to change if there are changes on the Testinfra side.
- `Cldp_selection`: Handles precomputation of CLDPs, lazy computation of potential CLDP test files, per-CLDP lookup of matching test methods
