Commit title: Add tests documenting non-owning IOBuf serialization bug
Commit body:
Summary:
The thrift-python serializer silently drops `folly::IOBuf`-typed binary fields when the IOBuf is non-owning (has `_this` set but `_ours` unset). This happens because `get_cIOBuf()` in `thrift/lib/python/types.pyx` returns `_ours.get()`, which is NULL for non-owning IOBufs, causing `getIOBuf()` to return an empty `OptionalThriftValue`. The table-based serializer then silently skips the field.

Non-owning IOBufs are produced by:
- Thrift-py3 struct property accessors (via `IOBuf.create()`)
- Chained IOBuf iteration (`.next` / `.prev` properties)

This adds two tests documenting the current trunk behavior:

1. `thrift/lib/python/test/iobuf.py` — `NonOwningIOBufSerializationTest`: creates a chained `WritableIOBuf`, extracts a non-owning link via `.next`, constructs a thrift-python struct with it, and verifies that serialization-deserialization drops the IOBuf data (no py3 types dependency needed).

2. `thrift/lib/py3/test/auto_migrate/iobuf.py` — `test_iobuf_survives_serialization_round_trip`: constructs a thrift-python struct using IOBuf from a py3 struct, and verifies that the round-trip works when `is_auto_migrated()` is True (IOBuf is owning because py3 types are redirected to thrift-python types), but drops the data when False (IOBuf is non-owning from the real py3 struct).
