## Summary

`StripedThrottledLifoSem.cpp` uses bare `DEFINE_uint64` from gflags, but on Android the gflags library is not available (`FOLLY_HAVE_LIBGFLAGS=0` via the `DEFAULT` branch in `//folly/portability:gflags`). The bare macro is only defined when `<gflags/gflags.h>` is included, which requires `FOLLY_HAVE_LIBGFLAGS=1`.

Every other non-test folly production file uses the portable `FOLLY_GFLAGS_DEFINE_*` macros from `<folly/portability/GFlags.h>`, which provide a fallback implementation (plain global variable with the default value) when gflags is unavailable. This file was the only outlier.

The bug was latent since the file was introduced (August 2025) but only manifested recently when Android build targets (`xrdriver-starship`, `xrdriver-dragon`) started transitively depending on `striped_throttled_lifo_sem` via `folly/executors`.

See https://www.internalfb.com/sandcastle/workflow/1202461100524933495

## Fix

Replace bare `DEFINE_uint64` with `FOLLY_GFLAGS_DEFINE_uint64` (2 lines). The `FLAGS_*` variable references remain unchanged — both the real gflags macro and the `FOLLY_GFLAGS_DEFINE_FALLBACK_` create the same `FLAGS_*` variables.
