## What

Implement emit for shape and tuple destructuring, per spec:  https://fburl.com/hack_shape_destructuring_hip

## Note about `rhs_readonly` flag

We don't propagate `rhs_readonly`: the flag was for nested non-var lvalues like $obj->prop, which aren't allowed in shape/tuple destructuring:

```
// OK: `list` is very permissive
list($a->prop, $b->prop) = vec[get_a(), get_b()];

// OK
tuple($a, $b) = tuple(get_a(), get_b());

// NOT ALLOWED
tuple($a->prop, $b->prop) = tuple(get_a(), get_b());
```

This sort of flag is for bytecode, and is independent of the readonly check in the parser. We tweak the parser's readonly checking for shape/tuple destructuring in D105299418

## Note about emit_lvalue_op_destructure

It only pertains to `list`, not shape/tuple destructuring, so is renamed to emit_lvalue_op_list. Sorry, I'd mis-named it in a previous commit: https://fburl.com/code/h5pkxmko
