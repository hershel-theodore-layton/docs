Commit title: Emit runtime deprecation warning on thrift-py-deprecated module import
Commit body:
Summary:
Runtime warnings expose still-unmigrated `thrift-py-deprecated` usage when generated py-deprecated modules load. This gives migration owners a concrete signal in logs rather than static checks alone.

Interactive CLIs get one short notice instead of a wall of repeated warnings. Job logs and other non-interactive output keep detailed warning records, one per source module by default.

Generated code stays compatible with older thrift runtime packages. If a prebuilt artifact has new generated code but an older runtime, the warning call safely becomes a no-op.

On startup paths that combine Cinder lazy imports with custom warning hooks, the runtime outputs a fallback migration message directly. That keeps the migration notice visible without the risk that warning-display hooks run while lazy imports are active and cause Cinder to raise `ImportCycleError`.

Reviewers can inspect the E2E tests to see the expected visible output. Those tests use the full visible output as the correctness check.

Historical context:
Instagram startup crashes with `ImportCycleError` due to cinder lazy imports forced a revert of {D103347992}. The current version includes the startup-safety coverage and IG Django E2E canary validation needed to land and monitor.
