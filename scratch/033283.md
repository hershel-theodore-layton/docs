Commit title: fix silent dropping of IOBuf view on serialization
Commit body:
Summary:
Fix silent dropping of non-owning `folly::IOBuf` fields during thrift-python serialization.

When a non-owning IOBuf (one created via `IOBuf.create()`, which sets `_this` but not `_ours`) is stored in a thrift-python struct field, the serializer's `getIOBuf()` checks `_ours.get()`, gets NULL, and silently skips the field — writing zero bytes with no error.

Non-owning IOBufs are produced by thrift-py3 struct property accessors and by chained IOBuf iteration (`.next` / `.prev`). This means any code that reads an IOBuf field from a py3 struct and passes it to a thrift-python struct (e.g. via `_to_python()` conversion or manual construction) will silently lose the field data on serialization.

The fix adds a check in `IOBufTypeInfo.to_internal_data`: if the incoming IOBuf has `_this` but not `_ours`, clone and coalesce it into a new owning IOBuf via `cloneCoalesced()`. This preserves the full chain data starting from the current node.
