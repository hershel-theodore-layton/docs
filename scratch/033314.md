Commit title: clean up hot path to reduce instruction cache pressure / less cache misses
Commit body:
Summary:
This change extracts error handling code from the fast path into separate
FOLLY_NOINLINE methods to keep the instruction cache smaller. The goal is to
ensure only the happy path is inlined, reducing I-cache pressure in production
workloads.
Benchmark Results:
- FastThrift_Request cache-misses: -19.0% (497,994 → 403,387)
- FastThrift_Request L1-dcache-misses: -9.2% (1,166,118 → 1,059,035)
- FastThrift_Response cache-misses: -20.9% (575,380 → 454,935)
- FastThrift_Response L1-dcache-misses: -4.3% (1,123,679 → 1,074,988)
- Cycle counts remain neutral (±0.3%), as expected since errors are rare
The optimization successfully reduces instruction cache pressure by ~20% while
maintaining the same performance characteristics. This benefits real-world
workloads where multiple fast_thrift handlers are active simultaneously.
