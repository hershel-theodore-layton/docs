Commit title: Fix `TransportHandler` death tests segfaulting under opt-tsan
Commit body:
Summary:
`EXPECT_DEBUG_DEATH` in opt builds (where `NDEBUG` is defined) executes the statement inline rather than forking a subprocess, and `DCHECK` compiles to a no-op. This means death tests that rely on `DCHECK` to abort before hitting dangerous code will instead run past the guard and crash. In `OnConnectFromCreatedDeath`, `onConnect()` dereferences `pipeline_` which is `nullptr` (since `setPipeline` was intentionally never called), causing a segfault.

Two-part fix:
1. **Harden production code**: Add runtime early-return guards after DCHECKs in `onConnect()`, `setPipeline()`, `onWrite()`, and `resetPipeline()` so precondition violations are no-ops in opt mode instead of undefined behavior.
2. **Guard death tests**: Wrap all 5 `EXPECT_DEBUG_DEATH` tests with `#ifdef NDEBUG` / `GTEST_SKIP()` so they are explicitly skipped in opt builds where DCHECKs are inactive.
