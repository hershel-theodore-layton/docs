Commit title: Fix sink/bidi first response decompression on caller thread
Commit body:
Summary:
D97352193 added decompressResponse() calls in the generated code to decompress unary and stream first responses on the caller thread. However, the sink/bidi coroutine path in coroutine_functions.whisker was missed — it calls recv_*() without decompressing first, and also uses raw getChannel() instead of getChannelShared() (risking use-after-free if the channel is destroyed before the callback fires).

This diff fixes the codegen and the underlying transport plumbing so that all four E2E `StreamCompressionE2ETest` tests now pass:

- `StreamCompressionE2ETest.StreamDeclaredExceptionWithCpuDecompression`
- `StreamCompressionE2ETest.StreamUndeclaredExceptionWithCpuDecompression`
- `SinkCompressionE2ETest.SinkFinalResponseExceptionWithCpuDecompression`
- `BiDiCompressionE2ETest.BiDiStreamExceptionWithCpuDecompression`

Changes:

1. `coroutine_functions.whisker`: Captures `getChannelShared()` as a `std::weak_ptr` instead of a raw pointer or shared_ptr, and calls `channel->decompressResponse(returnState)` before `recv_*()` (guarded by `weak_ptr::lock()`), matching the decompression pattern already used for unary/stream in `sync_functions.whisker` and `async_client_functions.whisker`.
2. `async_client_functions.whisker`: Similarly changed to store `getChannelShared()` as a `std::weak_ptr` and guard `decompressResponse()` with `weak_ptr::lock()`, preventing use-after-free if the channel is destroyed before the callback fires.
3. `RocketClient::handleFirstResponse`: When `thrift_client_compress_request_on_cpu` is enabled, uses `unpackAsCompressed<FirstResponsePayload>` to skip IO-thread decompression — the caller thread handles it via `decompressResponse()`. This was intentionally excluded from D102375558 because the sink/bidi generated code didn't call `decompressResponse()` yet.
4. `Flags.h`: Made the `THRIFT_FLAG_REGISTER__` macro variable `const` to fix the `facebook-avoid-non-const-global-variables` lint warning. This variable is only used for its side effect (eager flag registration at static init), so `const` is safe and silences the lint for all `THRIFT_FLAG_DEFINE_*` usages.
5. **NEW** `RocketClientChannelBase::decompressResponse` override: `decompressResponse` was a no-op on every channel except `ServiceRouterClientChannel`. Raw `RocketClientChannel` (used by tests and by anyone constructing a channel without SR) silently skipped decompression, leaving the still-compressed bytes for `CompactProtocolReader` to choke on. Now `RocketClientChannelBase` (parent of `RocketClientChannel` and `SecureRocketClientChannel`) reads the algorithm from `THeader::getResponseCompressionAlgorithm()` and uncompresses via `rocket::CompressionManager`.
6. **NEW** `PooledRequestChannel::decompressResponse` override: `PooledRequestChannel` is what `ScopedServerInterfaceThread::newChannel` (and most non-SR client setups) actually return — it wraps per-EventBase `RocketClientChannel` impls. The generated code calls `decompressResponse` on the *outer* `PooledRequestChannel`, so the override on the inner `RocketClientChannelBase` would never fire. Since decompression is purely a function of `ClientReceiveState` + the algorithm on `THeader` (no per-connection state), the wrapper does the work inline rather than hopping to an IO thread.
