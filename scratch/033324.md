Commit title: vsdebug: load startup document inside `SourceRootInfo::WithRoot` scope
Commit body:
Summary:
The vsdebug debugger was loading the startup document (which initializes the autoloader via `flib_init_script()`) after the `SourceRootInfo::WithRoot` RAII scope had ended, so the autoloader was initialized against the deployed www source root instead of the user's sandbox source tree. This meant class constants added to the user's local checkout (but not yet landed) could not be resolved in the REPL.

hphpd does not have this bug because its `dummy_sandbox.cpp` loads the startup doc inside the `WithRoot` scope (line 114, within the block starting at line 89).

The fix moves `invokeDummyStartupDocument()` inside the `WithRoot` scope so the autoloader sees the correct source root, matching hphpd behavior.
