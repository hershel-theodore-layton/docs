Commit title: Add `PostRenderCallback` to squangle query execution path
Commit body:
Summary:
Add a new `PostRenderCallback` hook to squangle's query execution path that fires after `renderQuery()` produces the final SQL string but before `mysql_real_query()` sends it to the server. The callback receives the rendered query string and returns a bool — `false` aborts the operation with `SQ_INVALID_API_USAGE`.

This enables callers to validate that the rendered SQL contains expected values (e.g., correct table names, key fields) before the query is executed, catching corruption that occurs during `Query::renderFb(conn)` (which does escaping and memory copying).

Changes:
- Add `PostRenderCallback` type alias in `Operation.h`: `std::function<bool(const folly::fbstring&)>`
- Add storage in `OperationBase::Callbacks`, setter on `OperationBase` and `Operation`
- Invoke the callback in `MysqlFetchOperationImpl::specializedRunImpl()` between `renderQuery()` and `setupQueryAttributes()`
- Propagate from `Connection` to operations in `setupOperationCallbacks()`, following the same pattern as `render_prefix_callback_`
- Add `setPostRenderCallback` setter and `setCallbacks` propagation on `Connection`
