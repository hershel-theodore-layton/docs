Commit title: getdeps: always use Homebrew LLVM clang on macOS CI
Commit body:
Summary:
AppleClang lags upstream LLVM on C++ standards support — among other gaps, AppleClang 16 rejects floating-point non-type template parameters (a C++20 feature). Using Homebrew LLVM uniformly across all macOS CI jobs gives every project a consistent, more capable compiler without per-project opt-in.

The generator now unconditionally sets `CC`/`CXX` to `/opt/homebrew/opt/llvm/bin/clang{,++}` and emits a `brew install llvm` step on darwin. sccache continues to work correctly with the Homebrew toolchain.
