Commit title: Optional SO_REUSEPORT cBPF random spread
Commit body:
Summary:
The kernel's default SO_REUSEPORT selector hashes the connection 4-tuple to pick a listening socket. When client source addresses are concentrated — one IP per geographic POP, or a small NAT egress range — that hash lands on the same worker, leaving the rest idle and capping per-host throughput on the unlucky worker.

This commit adds an opt-in cBPF program attached via `SO_ATTACH_REUSEPORT_CBPF` that returns a random `u32` per accept. The kernel mods the value by the REUSEPORT group size internally, so the program is group-size oblivious — every worker installs the same 2-instruction program on its own listening fd (last-write-wins is harmless).

Wiring:
- `ConnectionHandler::setEnableReusePortBpfSpread(bool)` sets a per-handler flag; the program is attached at `startAccepting()` time after the socket is bound and listening.
- `ConnectionManager::setEnableReusePortBpfSpread(bool)` records the flag once and applies it to each `ConnectionHandler` as new EventBases are registered.
- `FastThriftServer::setEnableReusePortBpfSpread(bool)` exposes the knob to embedders; must be called before `start()`/`serve()`.

`attachReusePortBpfSpread` is best-effort: a failed `setsockopt` is rate-limited-logged and the kernel's default hash selection stays in place (pre-change behavior). Compiled out on non-Linux.

Also splits `ConnectionHandler` into `.h` (declarations) + `.cpp` (definitions) to keep the new BPF logic and its Linux-only includes out of the header.
