Commit title: Add SocketOptions for listen backlog, TFO, accept budget
Commit body:
Summary:
Adds `rocket::server::connection::SocketOptions` — a pure-data struct of listening-socket tuning knobs (`listenBacklog`, `tfoEnabled`/`tfoQueueSize`, `maxReadsPerEvent`) that flows from the embedder through `FastThriftServer` → `ConnectionManager` → per-EVB `ConnectionHandler`. Defaults mirror folly's `AsyncServerSocket` defaults except `listenBacklog{1024}`, which is sized for retry-storm tolerance (the prior hardcoded `listen(1024)` was prone to SYN drops under reconnect bursts, surfacing to clients as ETIMEDOUT).

Embedders configure the knobs via `FastThriftServer::setSocketOptions(...)` (or `FastThriftServerT<Stats>::setSocketOptions` on `FastThriftChannelServer`) before `start()`/`serve()`. `ConnectionHandler::startAccepting()` applies them once: TFO via `setTFOEnabled(true, tfoQueueSize)` when enabled, `setMaxAcceptAtOnce(maxReadsPerEvent)` always, and `listen(socketOptions_.listenBacklog)` replacing the hardcoded value. No new BPF state — the existing `enableReusePortBpfSpread_` standalone setter is left alone per its earlier "separate-from-SocketOptions" design.

Plumbing details: `SocketOptions` is added as a required ctor parameter on both `ConnectionHandler` and `ConnectionManager::create`/ctor (no default arguments, per project convention — every call site is updated explicitly). New `:socket_options` Buck target so callers can depend on the header without pulling in the rest of `connection_manager`.
