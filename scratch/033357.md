Commit title: KeyUpdate: call configureServerRecordLayer on new AppTraffic layers
Commit body:
Summary:
the `Event::KeyUpdate` handler in `ServerProtocol.cpp` (server receiving a KeyUpdate from the peer) creates new `AppTraffic` `EncryptedReadRecordLayer` + `EncryptedWriteRecordLayer` instances but does not call the corresponding `configureServerRecordLayer` hook. without this symmetric fix, a client-initiated KeyUpdate would still cause AAD mismatch: client write layer reconfigured (via parent diff), but server read layer regresses to standard framing → AEAD authentication fails.

the `Event::KeyUpdateInitiation` handler on the server already calls the hook correctly — only the received-KeyUpdate handler was missing it.
