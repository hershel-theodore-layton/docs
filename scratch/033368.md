Commit title: Fix use-after-free of VasmBlockCounters in jit-serialize mode
Commit body:
Summary:
discardProfData() unconditionally enqueues VasmBlockCounters::free() on the Treadmill (prof-data.cpp:283). When the Treadmill fires between requests, free() deletes the ProfCounters chunks. However, live JIT Optimize translations still contain atomic decrement instructions with hardcoded addresses pointing into those freed chunks. When the next request executes these translations, it writes to freed memory, corrupting whatever now occupies those addresses.

This was exposed by D102164392 which reduced ProfCounters chunk size from 16MB to 2MB. With 16MB chunks, the freed memory was rarely reused for small allocations. With 2MB chunks, the freed memory gets reused promptly (e.g., for NameValueTable's m_table), and the stale atomic decrements write -1 (0xffffffffffffffff) into it, causing corruption.

The fix: guard VasmBlockCounters::free() with !isJitSerializing(). Block counters are only inserted when isJitSerializing() is true (vasm-block-counters.cpp insert() asserts this), so when not serializing there are no references to free. When serializing, the counters must outlive the translations that reference them.

This also could be the root issue of T191826077.
