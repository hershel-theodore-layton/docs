Commit title: Add regression test for stale remote old decl fanout
Commit body:
Summary:
Adds an end-to-end saved-state integration regression test for stale remote old decl fanout with the Rust provider.

The repro is:

1. Create a saved state where `AlertThreshold::getStructMetadata()` returns `string`, and the caller expects `string`. The test remote-old-decl fixture returns this same saved-state decl.

2. Start a real `hh_server` from that saved state with the Rust provider, `fetch_remote_old_decls=true`, and `only_fetch_remote_old_decl_during_init=false`.

3. Edit the repo into a clean local state where `AlertThreshold::getStructMetadata()` returns `int`, and the caller expects `int`. This verifies the server has accepted the newer local decl.

4. Edit the parent class API. This triggers descendant invalidation. Before the fix, Rust removes the child class shallow decl even though the child source file did not change.

5. Revert only `AlertThreshold::getStructMetadata()` back to the saved-state `string` return type, leaving the caller expecting `int`.

6. The server should fan out to the caller and report the `int` versus `string` error. The bug is that unrestricted remote old decl fetching can fill the missing old child decl from the saved-state remote decl, compare `string` against `string`, suppress fanout, and incorrectly report no errors.
