Commit title: Refine RepresentableAs case-type variants cleanly across files
Commit body:
Summary:
# Context
When a case type has variants that are newtypes constrained `as HH\Runtime\RepresentableAs<T>`, refining and consuming the case type in a file other than the one that defines the newtypes hits two problems.

First, `Typing_refinement.split_ty` follows `RepresentableAs<T>`'s bound chain (which has no `as` clause and so resolves to mixed) instead of using `T` directly for partitioning. The if-branch of `is int` then includes the not-int variants rather than narrowing to the int variant. The case-type code in `split_ty` also always meets the variants' partition with a partition of the case type's upper bound. When that bound is the default mixed (`?nonnull`), the meet decomposes mixed into `null | nonnull` and produces noisy `(X & null) | (X & nonnull)` shapes downstream.

Second, in `Typing_subtype`, the `T <: RepresentableAs<U>` rule reduces directly to `T <: U`. For an opaque newtype `T` whose declared bound is `RepresentableAs<V>`, that reduction walks `T`'s bound chain into `RepresentableAs<V>` and then through `RepresentableAs`'s implicit `?nonnull` upper bound, ending at mixed, so the value cannot flow as `RepresentableAs<U>` even when `V <: U`.

# Solution
Three surgical changes, all exercised by `representable_as_case_type_refinement_multifile.php`.

In `typing_refinement.ml`, add a special case for `HH\Runtime\RepresentableAs<T>` in `split_ty` that recursively partitions `T` directly, mirroring the existing special case in `typing_data_type.ml` that uses `T`'s runtime data type for case-type disjointness checks. After this change, `is int` on `RepresentableAs<int>` narrows to int instead of falling through to mixed.

Also in `typing_refinement.ml`, skip the meet with the upper bound's partition for case types without where clauses. The variants alone capture all values; the bound meet only adds noise in the common case where the bound is the default mixed. Where-clause case types still meet because they need the bound to apply to the unrefined cases.

In `typing_subtype.ml`, fall back to `default_subtype` after the `T <: U` reduction in the `T <: RepresentableAs<U>` rule. `default_subtype` resolves `T <: RepresentableAs<U>` via `T`'s bound chain, which for a newtype with bound `RepresentableAs<V>` reaches the existing covariance rule (`RepresentableAs<V> <: RepresentableAs<U>` iff `V <: U`) and avoids the mixed-bound dilution. The iff-U reduction is still tried first to preserve fast paths like `int <: RepresentableAs<int>`.

After these changes, the user-visible scenario from the manual works end-to-end: a case type whose variants are RepresentableAs-bounded newtypes, defined and discriminated in a file separate from the newtypes, narrows cleanly on `is int` / `is string` and the narrowed value flows both as the variant type itself (UserId, Username) and as `RepresentableAs<int>` / `RepresentableAs<string>`.
