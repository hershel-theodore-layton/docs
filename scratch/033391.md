# Context
The previous step in this stack made `T <: RepresentableAs<U>` fall back to `default_subtype` when T is a non-RA newtype, or a generic with a non-mixed upper bound. Two related cases are still broken.

A generic with a structural bound — for example `<T as (int, int)>` — cannot flow into `RepresentableAs<vec<int>>`. The bound chain reaches `(int, int)`, but the existing tuple arm of the rule is only consulted when the *immediate* subtype is a tuple, not when a tuple appears via a generic's bound. The previous step handled this for non-RA newtypes via `default_subtype` but skipped generics whose only bound was structural rather than RA-shaped.

A `Tdependent` whose declared bound is `RepresentableAs<V>` — for example a type constant `abstract const type T as RepresentableAs<int>` accessed as `this::T` — has the same shape as the newtype-with-RA-bound case but fell through to the iff-U reduction and lost the RA wrapper.

There is also a subtle interaction with constraint storage. Adding `<T as RepresentableAs<V>>` calls `decompose_subtype` → `Subtype.simplify`. If we naively run `simplify ||| default_subtype` for Tgeneric LHS, the result is `TL.Disj([IsSubtype(T, V), IsSubtype(T, RepresentableAs<V>)])`. `decompose_subtype_add_prop` cannot extract a single `(sub, super)` pair from a `Disj` and silently drops both — T's upper bound is never stored, leaving only the implicit mixed.

# Solution
Two changes in `typing_subtype.ml`, both in the `T <: RepresentableAs<U>` rule, exercised by the new `representable_as_generic_tuple_bound.php`.

Replace the previous gated `default_subtype` arm with a `simplify ||| default_subtype` disjunction over `Tnewtype | Tgeneric | Tdependent` LHS. The iff-U arm preserves fast paths like `int <: RepresentableAs<int>`. The `default_subtype` arm walks the bound chain so a generic with bound `(int, int)` hits the existing tuple arm, and a dependent type with bound `RepresentableAs<V>` hits the existing covariance arm.

Above the disjunction, add an explicit arm for `Tgeneric _ when require_completeness` that delegates to `default_subtype`. In completeness mode `default_subtype` already defers `Tgeneric` LHS via `mk_issubtype_prop(T, RepresentableAs<V>)`, so the original constraint flows through `decompose_subtype_add_prop` cleanly and `RepresentableAs<V>` is stored as T's upper bound. At usage time `require_completeness` is false, so the disjunction runs normally and the iff-U reduction can succeed via T's stored bound.
