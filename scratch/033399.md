Commit title: Add enableRequestContext flag for opt-in conn/req context
Commit body:
Summary:
Adds `enableRequestContext` to `FastThriftServerConfig` (default `false`). When set, `FastThriftServer` constructs a per-connection `ThriftConnContext` on accept and wires `ThriftServerRequestContextHandler` + `ThriftServerConnectionContextHandler` into both the composite and simple thrift pipelines so each request's `ThriftRequestContext` is populated with the connection context.

The `OnConnectionAcceptedFn` signature changes to take `ThriftConnContext*` (pointer instead of reference): the callback still fires on every accept, but receives `nullptr` when `enableRequestContext` is off. This lets embedders react to accept (e.g., logging) even without context propagation, while making it impossible to call `setUserData` on a context that nobody will see.

Default is opt-in to match `enableMetadataService` precedent and to keep existing callers' behavior unchanged.
