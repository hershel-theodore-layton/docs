Commit title: Preserve Rust shallow decls when invalidating descendants
Commit body:
Summary:
The Rust provider backend was invalidating shallow decls (both old decls and decl cache) when a parent class changes. This is unnecessary since only folded classes would be affected by what is happening above the hierarchy.

This diff changes it so that only folded decls are invalidated.

In addition to the redundancy, there is a correctness reason to do this. I'm reintroducing old decl fetch during recheck. The invalidation was causing us to fetch a version of the old decl that is stale and leading to fanout bugs (see D106080298 for details), with this that bug should go away.

This diff adds a folded-class-only Rust provider removal API and uses it from `Decl_provider.remove_classes`, preserving current shallow decls for unchanged descendants.

The parent commit adds an end-to-end regression test. Without this fix, that test reports `No errors!` when it should fan out to a caller and report an `int` versus `string` error.
