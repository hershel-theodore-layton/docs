Commit title: Fix non-regularity detection in ppx_transform for concrete type substitutions
Commit body:
Summary:
`is_nonregular_in_core_ty` detects non-regular (polymorphically recursive) types so the PPX can generate explicit universal quantifiers, which OCaml requires for polymorphic recursion. The detection had an inverted match that missed concrete type substitutions.

The bug is in a helper, which compares type arguments at a self-recursive occurrence against the declared type parameters. The old logic was:
```
  | Ptyp_var nm when not (String.equal nm tv) -> true  (* different tyvar *)
  | _ -> auxs tys tyvars  (* everything else: keep looking *)
```

This only caught type `'a t = Foo of 'b t` (different type parameter name) but missed `type 'a t = Foo of int t` (concrete type), because `int` falls through to `_` and is silently treated as matching. The fix inverts the logic:
```
  | Ptyp_var nm when String.equal nm tv -> auxs tys tyvars  (* same tyvar: ok *)
  | _ -> true  (* anything else is non-regular *)
```

In practice this bug was masked because the regularity flag was computed but never used since the PPX always generates explicit quantifiers regardless. Cleaned up the dead _regular binding and stale TODOs to make that intent explicit.

Also adds `Nonregular_concrete` test case (`type 'a t = Leaf | Node of int t`) and a new Buck-based compilation test for ppx_transform.
