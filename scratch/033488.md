Commit title: Fix static property xrefs being silently dropped
Commit body:
Summary:
`Sym_def.resolve` returned `None` for every static-property occurrence (`Class::$prop`, `self::$prop`, `static::$prop`), so the Glean indexer never emitted xref facts for them. `hack.TargetUses` queries on a static `PropertyDeclaration` returned 0 facts even when uses existed.

Static-prop occurrences from `IdentifySymbolService` carry the `$` in the name (e.g. `"$dryRun"`). The Property arm of `Sym_def.resolve` then prepends another `$` when building the lookup key for `Folded_class.get_sprop` and `get_sprop_from_req_constraints`, producing `"$$dryRun"`. The sprop map stores keys with a single `$` prefix (e.g. `"$dryRun"`), so the doubled-up key never matches.

The arm was already calling `IdentifySymbolService.clean_member_name` to strip the leading `$`, but the result was stored in a variable the lookups never read — they kept reading the raw `property_name`. The fix binds the cleaned value to a new variable `clean_member_name` and feeds that into each lookup site, so the lookups now build `"$dryRun"` instead of `"$$dryRun"`.

This logic was introduced in D92058757 when the `get_sprop` and `get_sprop_from_req_constraints` fallbacks were added; both miss for the same reason.

Existing test fixtures already exercised this path and now produce the previously-missing facts as additions in the regenerated `.out` files. No new instance-property facts are introduced; the `get_sprop` branch only runs when `get_prop` returns `None`.
