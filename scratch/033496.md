Commit title: Fix null dereference in BiDi `ClientCallbackStapler::onStreamError`
Commit body:
Summary:
A crash in `dvaar.mysql` (SIGSEGV at `ClientBiDiBridge.h:88`) occurs when a late ERROR frame from the server reaches `ClientCallbackStapler::onStreamError` after the stream half has already been cancelled. `std::exchange(stream_, nullptr)` returns `nullptr`, and the subsequent `->onStreamError(...)` dereferences it.

**Root cause**: `RocketBiDiServerCallback::onStreamError` is the only terminal stream handler missing an `isStreamOpen()` guard — `onStreamComplete`, `onStreamPayload`, and `onConnectionClosed` all have one. This allows the error to propagate through the entire callback chain even after the stream is closed.

**Layer 1 fix**: Add `isStreamOpen()` guard to `RocketBiDiServerCallback::onStreamError`, matching the existing guards in `onStreamComplete` and `onStreamPayload`.

**Layer 2 fix** (defense in depth): Add null guards to `ClientCallbackStapler::onStreamError`, `onStreamComplete`, and `onSinkCancel` using `if (auto* s = std::exchange(...))`, matching the existing guarded pattern in `onStreamNext`.
