Commit title: Cap streamId at 0x7FFFFFFF, wrap with collision skipping
Commit body:
Summary:
The fast_thrift client streamId generator was a bare `uint32_t` counter incrementing by 2 — no cap, no wrap, no collision check. After ~2^31 requests it would walk past the RSocket 31-bit limit, eventually emit `0` (the connection-frame reserved value), and silently collide with live streams in `activeStreams_`. The existing DCHECK in `onWrite` would catch this only in debug builds and was compiled out in opt.

This diff ports the three missing behaviors from legacy `RocketClient::makeStreamId` (`thrift/lib/cpp2/transport/rocket/client/RocketClient.cpp`):

1. Cap at `kMaxStreamId = (1u << 31) - 1` — the RSocket 31-bit client stream ID limit.
2. On reaching the cap, wrap `nextStreamId_` back to `1` and latch `hitMaxStreamId_`.
3. After wrap, probe `activeStreams_.contains(id)` each iteration and skip live IDs.

The collision loop is bounded by `activeStreams_.size() + 1` via `XCHECK_LE` — a contiguous run of collisions cannot exceed the number of live streams. Pre-wrap (`hitMaxStreamId_ == false`), the `do/while` exits after a single iteration, so the hot path is unchanged: one load, one add, one return.

`hitMaxStreamId_` is intentionally NOT reset on `onPipelineActive` — it latches for the lifetime of the handler, matching legacy semantics. After a reconnect, `activeStreams_` is empty so the post-wrap collision probe is effectively a no-op (single `contains()` call returning false).

The `kMaxStreamId` constant is defined locally in the handler rather than reusing legacy `apache::thrift::rocket::StreamId::maxClientStreamId()` — this keeps fast_thrift self-contained per the rocket-pipeline split.
