Commit title: Add opt-in TLS 1.3 session ticket renewal to TLSTicketKeyManager
Commit body:
Summary:
TLS 1.3 session tickets are single-use, unlike TLS 1.2 where a session can be reused by unlimited connections. When OpenSSL calls the tlsext_ticket_key_cb for ticket decryption, the return value controls whether OpenSSL issues a new NewSessionTicket message:
- Return 1: ticket decrypted successfully, do NOT issue new ticket
- Return 2: ticket decrypted successfully, issue new ticket (renew)

TLSTicketKeyManager::decryptCallback always returns 1, and ticketCallback passes this value through to OpenSSL unchanged. This means OpenSSL never issues new tickets after TLS 1.3 resumed connections. Clients alternate between full handshakes and resumed connections (~50% session reuse instead of ~100%), because the single-use ticket is consumed on resumption and no replacement is provided.

Add setRenewTicketsOnResume(bool) to allow callers to opt into ticket renewal. When enabled, ticketCallback upgrades the decrypt result from 1 to 2 for TLS 1.3 connections (checked via SSL_version(ssl) == TLS1_3_VERSION), causing OpenSSL to issue fresh NewSessionTicket messages after every resumed connection. TLS 1.2 connections are unaffected since their tickets are reusable. Default is false for backward compatibility.

The member is std::atomic<bool> to support concurrent access from multiple IO worker threads without data races.

Note: the stats recording via recordTLSTicket(encrypt, result) converts result to bool, so result=2 is recorded identically to result=1 (both truthy). No dashboard impact.
