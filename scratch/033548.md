Commit title: Generalize OptionalLayout with ValueLayout template parameter
Commit body:
Summary:
Add a second template parameter `ValueLayout` to `OptionalLayout<T>`, defaulting
to `Layout<T>`. This is a pure refactor with zero behavior change at existing
call sites: the default specialization `Layout<folly::Optional<T>>` continues
to resolve to `OptionalLayout<T, Layout<T>>`, which is identical to today's
`OptionalLayout<T>`.

This enables a follow-up diff that implements field-level cpp.Frozen2Exclude
by emitting `OptionalLayout<T, ExcludedLayout<T>>` for the field's value
layout — mirroring struct-level cpp.Frozen2Exclude semantics at field
granularity. See the design spec for full context.

The following invariants on the generalized `OptionalLayout<T, ValueLayout>`
are load-bearing for the field-level exclude design and are preserved here:
  - `layout`, `freeze`, and `thaw` gate on the isset bit and do not invoke
    the value layout when the optional is unset.
  - `maximize`, `print`, `view`, and the `View` typedef defer to
    `ValueLayout` for the value side (the `View` typedef is now
    `OptionalFieldView<typename ValueLayout::View>` instead of
    `OptionalFieldView<typename Layout<T>::View>`).
