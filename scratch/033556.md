Commit title: StressTest: fix SIGSEGV with StopTLSv2 in the client
Commit body:
Summary:
The thrift stresstest client crashed with SIGSEGV when run with
`--client_threads >= 2 --stopTLSv2`. Two threads concurrently call
`createFizzSocket`, which mutates a process-wide singleton
`FizzClientContext` via `setFactory(...)` on every connection while
fizz's connect path concurrently reads `factory_` from
`FizzClientContext::validate()`. `shared_ptr` assignment is not
atomic, so the racing reader sees a torn pointer; the freed
`Factory` chunk gets reused as backing memory for the CA-path
string, and the next virtual call dereferences character bytes as a
vtable pointer.

ThreadSanitizer report:
```
WARNING: ThreadSanitizer: data race
ThreadSanitizer: data race
  fbcode/fizz/client/FizzClientContext.cpp:28
  in fizz::client::FizzClientContext::validate(fizz::Error&) const
```

`FizzThriftFactory` is a stateless default-constructed factory; it
does not depend on per-connection state. Hoist the
`setFactory(make_shared<FizzThriftFactory>())` call into the
singleton's static-init lambda in `getFizzContext` so the factory is
installed once and never written again. Drop the corresponding
per-connection `setFactory` calls in `createFizzSocket` and
`createIOUringFizz`.
