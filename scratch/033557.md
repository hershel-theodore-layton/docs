Commit title: StressTest: enable fizz aligned-reads optimizations on client and server
Commit body:
Summary:
Wire the StopTLSv2 fizz read/write optimizations through the thrift
stresstest client and server so the iperf3-style benchmark exercises the
same code path as production servers and SR clients.

Client (xplat/thrift/conformance/stresstest/client/ClientFactory.cpp):
At the two AsyncFizzClient construction sites, when --stopTLSv2 is set
on the client, call:

  - setAlignedRecordReads(true)        - one page-aligned IOBuf per
                                         large plaintext record
  - setPreallocFromRecordHint(true)    - widen getReadBuffer
                                         preallocation to readSizeHint_
                                         so the body lands contiguously
  - setShouldSlicePredicate(           - skip the
      [](const folly::IOBuf& buf) {      kPartialWriteThreshold slice
        return !SecureThriftUtil::       on writes for tagged
            isUnencrypted(buf); })       unencrypted IOBufs

Each setter is guarded with `if constexpr (requires { ... })` so OSS
fizz builds without these APIs are unaffected.

Server (xplat/thrift/conformance/stresstest/server/StressTestServer.cpp):
The matching server-side optimizations are already wired in
fbcode/thrift/lib/cpp2/security/FizzPeeker.cpp and gated by three
THRIFT_FLAGs. When --stopTLSv2 is selected, force them on with
THRIFT_FLAG_SET_MOCK so the stresstest server applies the optimizations
without requiring configerator overrides:

  - server_fizz_aligned_record_reads
  - server_fizz_prealloc_from_record_hint
  - server_fizz_skip_slice_partial_writes

The flags fire only when the corresponding StopTLSV2 connection
negotiates, so other connection types are unaffected.
