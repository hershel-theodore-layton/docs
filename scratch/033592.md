Commit title: Wrap classname-in-class-position uses with explicit class load in tests
Commit body:
Summary:
The classname-to-class migration no longer allows a `classname<T>` value to be used where a `class<T>` is required (Hack error 4482, "It is no longer allowed to use a `classname<T>` in this position. Please use a `class<T>` instead."). This wraps every such value-position use in `__tests__` files with an explicit class load, using the exact transformation logic from `ClassnameToClassTransformHelper` (the same helper that backs `ClassnameToClassCodemod` and the `CodemodConfigClassnameToClass` CodemodService config).

Each flagged `$var::member(...)` is rewritten to `HH\classname_to_class($var) |> $$::member(...)` when `$var` resolves to `string`, or to `HH_FIXME::tryClassnameToClass($var) |> $$::member(...)` otherwise — exactly what the helper emits. 105 test files, 247 conversions (132 `HH\classname_to_class`, 115 `HH_FIXME::tryClassnameToClass`).

Notes to reviewer:
- The codemod's own test fixture (`flib/intern/scripts/hf/class_pointers/__tests__/ClassnameToClassCodemodTest.php`) is intentionally excluded — it contains pre-migration `log-meta-apac`/`exn` fixtures that must stay un-wrapped.
- 6 files were left out because the wrap does not typecheck there (abstract class / `__NeedsConcrete` static methods, or the wrap makes a downstream `as` assertion redundant) — these need manual migration: CSTRegenerationBaseConfigTest, ZippyDBSerdeTest, EntSchemaConfigTTLTestCase, EntPhotoMessagingRegulatoryComplianceTest, ADRReviewProviderTest, XPVObservabilityObserverBaseTest.
