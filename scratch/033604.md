Commit title: Fix -Wunsafe-buffer-usage errors in folly using safer C++ abstractions
Commit body:
Summary:
Fix the subset of `-Wunsafe-buffer-usage` errors in `fbcode/folly/...` that can be resolved without changing externally-exposed function signatures, by replacing raw C-style arrays and pointer-walking patterns with safer C++ abstractions.

- `folly/container/SparseByteSet.h`: Change private member arrays `uint8_t sparse_[kCapacity]` and `uint8_t dense_[kCapacity]` to `std::array<uint8_t, kCapacity>`. All subscript accesses now go through `std::array::operator[]`, which the compiler can verify is safe and which does not trigger `-Wunsafe-buffer-usage`.

- `folly/functional/Invoke.h`: Change `constexpr bool r[] = {…}` (a raw C-style array) to `constexpr std::array<bool, sizeof...(Idx) + 1> r = {…}`. The loop subscript `r[i]` now uses `std::array::operator[]` instead of raw array subscript.

- `folly/detail/base64_detail/test/Base64PlatformTest.cpp`: Rewrite `expectedEncodeToIndexes` and `expectedPackIndexesToBytes` test helpers from pointer-walking loops (`f[0]`, `f[1]`, `f[2]`, `f += 3`, `o += 4`) to index-based loops over `std::array` with `operator[]`. Change `expectedLookupByIndex` to accept `std::string_view` instead of `const char*` so table lookups use bounds-checked subscript. Replace `std::iota(arr.data(), arr.data() + n, v)` calls with iterator-based or explicit-index equivalents.

The remaining `-Wunsafe-buffer-usage` errors in folly (SpookyHash, MurmurHash, farmhash, fast-crc32, CRC detail, ReentrantAllocator, StackTrace, SafeAssert, CString, Libgen, RangeSse42, FileUtilDetail, and various header utilities) cannot be fixed without either changing externally-exposed function signatures or using diagnostic suppression pragmas, because they involve: (1) low-level hash/SIMD algorithms where raw pointer arithmetic is intrinsic to correctness, (2) POSIX/C APIs that must accept `char*` or `void*`, or (3) the fundamental `std::span(ptr, size)` constructor which itself triggers `-Wunsafe-buffer-usage-in-container` and provides no way to construct a span from a runtime-sized raw pointer without that warning.
