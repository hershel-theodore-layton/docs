Commit title: Add CAresResolver::setChannelInitOptions for caller-controlled timeout/tries
Commit body:
Summary:
Add `ChannelInitOptions{timeout, tries}` and `setChannelInitOptions()` to `CAresResolver`. Lets callers override `ares_init_options` per-attempt timeout (`ARES_OPT_TIMEOUTMS`) and tries (`ARES_OPT_TRIES`).

Both fields use `0` to mean "don't set the option bit" — c-ares falls back to its built-in default. The struct's own defaults (`timeout{kMaxTimeout}`, `tries{0}`) preserve the pre-existing CAresResolver behavior so callers that don't override are unaffected.

Needed by fwdproxy to bound the c-ares trailing work after its per-request timeout fires (c-ares has no per-query cancel API), and to let configerator-driven overrides fall back to c-ares defaults when unset (via the 0 sentinel).
