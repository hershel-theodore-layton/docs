Commit title: Fix lint 5655 false positive for override into an included (non-caller) package
Commit body:
Summary: Lint 5655 fired on an `intern` file calling `gen_execx`, which lives in package `scripts` but is overridden into `prod` via `<<file: __PackageOverride('prod')>>`. Because `intern` includes `prod`, the guard `package_includes current_pkg target_pkg` matched and emitted a contradictory message ("callee is already in the caller package intern via __PackageOverride('prod')") even though the callee was pulled into `prod`, which `intern` reaches natively. Per D93584558 the lint should only fire when the override pulls the callee into the caller's own package, so gate it on the caller's package assignment matching the override target instead. `lint_into_override_03` is isomorphic to this case and now expects no lint; override-into-own-package cases still fire.
