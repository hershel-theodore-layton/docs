Commit title: add per-request request_encryption_state column to thrift_request_events
Commit body:
Summary:
Add a per-request encryption state signal to the thrift logging pipeline so that perfpipe_thrift_request_events gains a new `request_encryption_state` string column reporting per-request whether the application payload was encrypted.

Per-review feedback from Ming: this column is the canonical "is this request encrypted?" signal for ALL thrift requests, not just StopTLSv2. Distinguishes the StopTLSv2 case (where encryption is per-record and may flip to plaintext mid-connection) from standard encrypted/plaintext connections via 4 values: "plaintext", "encrypted", "stoptls_encrypted", "stoptls_skipped".

Changes:
- New header `thrift/lib/cpp2/server/RequestEncryptionState.h` defining the enum + `toString()` helper
- `Cpp2RequestContext`: replaced `bool encryptionSkipped_` with `RequestEncryptionState requestEncryptionState_` (defaults to `Plaintext` to fail safely)
- `RequestLoggingContext`: same field type change
- `ThriftRequest::buildRequestLoggingContext`: copies the enum into logging context
- `EventLogEntry::getSample`: writes `addNormalValue("request_encryption_state", toString(state).str())` to Scuba

The dispatch logic that sets the enum is in a follow-up diff (5b in this stack). The dispatch reads `getSecurityProtocol()` + the StopTLSv2 record layer state at request-dispatch time.
