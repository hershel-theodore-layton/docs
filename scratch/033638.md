Commit title: Support far literal loads on Arm64
Commit body:
Summary: ARM64's LDR (literal) reaches only ±1MB, so when a translation region's literal pool ends up farther away HHVM currently fails an always_assert and crashes (T255251763); the workaround of lowering Eval.JitMaxRegionInstrs hurts performance. This diff adds a far literal load (ADRP + LDR [base, #offset], ±4GB reach) behind a new LoadLiteral abstraction that unifies the near (1-instruction) and far (2-instruction) forms for emission, smashing, and relocation. Far literals are emitted only for code that will be relocated (local→global TC) or when Jit.ArmForceFarLiteral is set, and the relocator shrinks the ADRP/LDR pair back to a single near LDR whenever the final literal is in range (with a JmpOutOfRange retry that pins out-of-range loads to the far form, converging because env.far only grows), so in-range code stays byte-identical to before while out-of-range literals are now handled instead of crashing.
