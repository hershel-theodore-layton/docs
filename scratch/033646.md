Commit title: folly/AsyncUDPSocket: add createPeerOnSameFd factory for SO_REUSEPORT sharing
Commit body:
Summary:
Adds `AsyncUDPSocket::createPeerOnSameFd()`, a factory that constructs a new `AsyncUDPSocket` on the listener's `EventBase` and wires it up to share this socket's kernel fd via `FDOwnership::SHARED`, share its per-fd `ZeroCopyFdBookkeeping`, and enable MSG_ZEROCOPY (`setZeroCopy(true)`).

The intended use case is SO_REUSEPORT workers that need a single fd shared across many `AsyncUDPSocket` instances on the same `EventBase` — for example, mvfst's `QuicServerWorker`, where a listener accepts new connections and per-connection writers send replies on the same fd. The kernel's `sk_zckey` counter and `SO_EE_ORIGIN_ZEROCOPY` completion cmsgs are per-fd, so any instance sharing the fd must also share the bookkeeping for the kernel's release callbacks to route back to the originating writer.

`ZeroCopyFdBookkeeping` is internal to folly; this factory is the sanctioned way for callers to opt in to fd-aliasing while keeping the bookkeeping correct. Only the listener should `resumeRead`/drain `POLLERR` for the shared fd.

Preconditions: the socket must already be bound. `setZeroCopy(true)` is invoked on the peer; the underlying `SO_ZEROCOPY` `setsockopt` is per-fd and idempotent, so it succeeds even if the listener already has ZC enabled.
