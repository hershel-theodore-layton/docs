Commit title: add write_encryption_state column to thrift_request_events for response-direction observability
Commit body:
Summary: Adds a sibling column to `request_encryption_state` capturing the encryption state of the outbound response (server-emit direction). Uses D102861984's bidirectional `hasObservedPlaintext()` latch via a new `CompositeWriteRecordLayer::hasObservedPlaintext()` accessor (D102861984 only added the read-side delegation). Semantics are per-connection-sticky (latch is sticky for the connection lifetime), not per-request — discussed in D100111050 reply with Ellen as the tradeoff for not introducing a new client-side emit pipeline. Reuses the existing `RequestEncryptionState` enum since the 4 values are identical. The column name `write_encryption_state` matches the existing `write_latency_us` lifecycle-phase precedent in `thrift_request_events` and pairs naturally with `request_encryption_state` (request-direction).
