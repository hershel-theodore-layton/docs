Commit title: Always deliver preReceivedData via readBufferAvailable with io_uring
Commit body:
Summary:
When a ThriftServer has SSLPolicy::PERMITTED and a plaintext client connects
with io_uring nativeAsyncSocketSupport enabled (`--io_uring_async_socket`),
the connection fails with "received invalid flags 895" from the Rocket
parser.

Root cause: the connection goes through two peeking rounds — first
SocketPeeker (TLS detection, N bytes) then TransportPeeker (protocol
detection, 13 bytes). When the second peek needs more bytes than the
first peek provided, `checkForImmediateRead()` delivers the
preReceivedData (first N bytes) via `handleRead()` → `readDataAvailable()`,
while the remaining bytes arrive via io_uring recv → `readBufferAvailable()`.

TransportPeeker tracks data differently per callback path:
`readBufferAvailable()` populates `readData_` (an IOBuf chain), while
`readDataAvailable()` does not. When `TransportPeekingManager::peekSuccess()`
calls `moveReadData()`, the IOBuf chain is missing the first N bytes that
came through `readDataAvailable()`. It stores this incomplete data as
`preReceivedData_`, losing the initial bytes. The Rocket parser then starts
parsing mid-frame, producing the "invalid flags" error.

In order to fix that, when io_uring is active, always deliver preReceivedData via
`readBufferAvailable()` — the same path that io_uring recv uses. This
removes the `maxBufferSize() >= kSmallRecvSize` gate that previously
forced small peeks through the `handleRead()` path, keeping the callback
path consistent with the rest of the io_uring recv pipeline.
