Commit title: Add `caller_identities` to Carbon protocol blocks
Commit body:
Summary:
D101865746 added `caller_identities` to the Thrift protocol path via `TArtilleryLowlevelServerHandler::postWrite()`, but production ucache traffic uses the Carbon/memcache protocol path (`ArtilleryTracing.cpp` → `TracingData::~TracingData()`), which never extracts identities. This means all ucache/server Artillery blocks in production have empty `caller_identities` despite the instrumentation code being deployed in R559.2.

This change adds identity extraction to the Carbon path by: (1) adding a `callerIdentities` field to `TracingData`, (2) implementing `extractAndSetCallerIdentities()` which reuses the same `IdentitiesExtractorUtil::getIdentitiesFromContext()` + `identity::serializer::serialize()` pattern as the Thrift path, (3) calling it from `CarbonRequestHandler::onRequestImplWithTracingEnabled()` before `ctx` is moved, using `ctx.getThriftRequestContext()` to access the session-level `Cpp2RequestContext` with X.509 identity hooks.

Gated by the same `THRIFT_FLAG(artillery_log_caller_identities)` as the Thrift path (fully rolled out, `defaultOverride=True` in `configerator/source/thrift/flags_overrides.cconf`). Zero cost on the untraced path — `extractAndSetCallerIdentities()` is only called when `TracingData` is non-null (~0.1% of requests).

Rollback: Set `THRIFT_FLAG(artillery_log_caller_identities)` to false in `configerator/source/thrift/flags_overrides.cconf`. This disables identity extraction on both the Carbon path (this diff) and the Thrift path (D101865746) simultaneously.
