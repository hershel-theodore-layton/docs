Commit title: thrift-python: test ApplicationError type propagation from handler to client
Commit body:
Summary:
Adds a client/server test in `client_server.py` exercising what happens when a service handler raises `ApplicationError` with an explicit, non-`UNKNOWN` type (`ApplicationErrorType.LOADSHEDDING`). The expectation is that the client receives an `ApplicationError` with the same `.type`.

That is not what happens today: although the server-side handler bridge passes the original type through (`python_async_processor.pyx`, via `ex.type.value`), the type the client observes is coerced to `UNKNOWN` somewhere on the C++ response path. This test asserts the current (buggy) `UNKNOWN` behavior so it is locked in and a future fix becomes visible. The assertion and accompanying `#BAD` comment call out that it should be `LOADSHEDDING`.

A follow-up commit will attempt to fix the type-preservation behavior and flip this assertion to `LOADSHEDDING`.
