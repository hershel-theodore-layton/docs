Commit title: Preload refcount into register to eliminate redundant memory loads in DecRef
Commit body:
Summary:
The PGO-optimized DecRef lowering in `irlower-refcount.cpp` previously used `cmplim` (compare-immediate-to-memory) to check an object's refcount against `OneReference`, then performed a separate `declm` (decrement-memory) to actually decrement it. On ARM64, both of these vasm ops are lowered to explicit load/op/store sequences — meaning the refcount was loaded from memory twice per DecRef.

This diff adds an arch-dispatch layer (`emitCmpRefCountArch` / `emitDecRefArch`) that on ARM64 loads the refcount into a register once via `emitLoadRefCount`, compares with `cmpli`, and passes the preloaded value through to `emitDecRefCount` which decrements the register and stores it back — eliminating the redundant second load.

On x86, the original `cmplim`/`declm` path is preserved — those are single CISC instructions that micro-fuse and are more compact; breaking them apart would increase code size and register pressure for no benefit.

Changes:
- Add `emitLoadRefCount(v, base)` helper that loads the refcount at `FAST_REFCOUNT_OFFSET` into a `Vreg`
- Add `emitDecRefCount(v, base, preloadedCount)` overload that decrements a preloaded count register and stores it back
- Add `emitDecRef(v, base, preloadedCount, reason)` overload with a defensive assertion (when `GenerateAsserts` is enabled, verifies the preloaded value matches actual memory, trapping on mismatch)
- Add `emitCmpRefCountArch` / `emitDecRefArch` arch-dispatch helpers in `irlower-refcount.cpp`
- Update all four PGO DecRef emission sites (`emitDecRefOptDestroy`, `emitDecRefOptSurvive`, `emitDecRefOptPersist`, `cgDecReleaseCheck`) to use the arch-dispatch helpers
- Add `decref_preloaded_count.php` test exercising destroy, survive, collection, and generic DecRef paths
