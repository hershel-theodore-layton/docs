Commit title: thrift: test TrustedServerException propagates ApplicationException type over Rocket
Commit body:
Summary:
Adds a C++ client/server test (`AsyncClientTest.ApplicationExceptionTypeIsPreserved`) verifying that a service handler can propagate a non-`UNKNOWN` `TApplicationException` type to the client via the sanctioned `TrustedServerException` mechanism.

Handler-thrown exceptions are untrusted by design: a plain `TApplicationException` raised from a handler has its type discarded and arrives at the client as `UNKNOWN`, so a rogue handler cannot invalidate the error-code invariants a client relies on. `TrustedServerException` is the intended backdoor for trusted code (primarily generated handler code) to preserve the type — its error code is mapped to a `ResponseRpcErrorCode` on the server and mapped back to a `TApplicationExceptionType` on the client.

The test has a handler throw `TrustedServerException::appOverloadError(...)` and asserts the client observes a `TApplicationException` with type `LOADSHEDDING` and the original message. No runtime changes are required — this exercises the existing error-code mapping.
