Commit title: Make generated code pass pyrefly typing checks
Commit body:
Summary:
Scout's `PACKAGE` enables **Pyrefly** type checking + typing validation
(`python.set_pyrefly(True)` / `set_typing_validation(True)`), so every
generated thrift-python target under scout/ runs Pyrefly. Pyrefly is
stricter than Pyre — it enforces metaclass-of-bases consistency,
ClassVar-vs-attribute discipline, and is unforgiving about the
`getFunctionTable` return-type lie — and the current `.pyi` stubs +
`services.whisker` template emit shapes that trip all three. Under Pyre
(which most of fbcode uses) the same generated code is fine, which is
why this hadn't shown up before.

T274273798 surfaced this when `fbcode//scout/intern/if:scout_intern_service`
was added without the usual `python_typing = False` escape hatch. The
auto-fix D107492370 was about to add that opt-out; this diff fixes the
typeshed and template instead so typing actually works.

Changes:
- `types.pyi`: `StructMeta` / `UnionMeta` extend `ABCMeta` so generated
  classes can multi-inherit `Struct, abstract_types.X` without a
  metaclass conflict (Pyrefly enforces metaclass compatibility across
  bases; Pyre didn't); loosen `FieldInfo.__init__(type_info=...)` to
  `object` so mutable typeinfos satisfy it without a new import cycle;
  loosen `StructTypeInfo`/`EnumTypeInfo` `klass` and `fill_specs`
  varargs to `Type[Any]`; loosen `ServiceInterface.getFunctionTable`
  return to `Mapping[bytes, object]` — the values are actually
  `(RpcKind, handler_callable)` tuples, not callables.
- `mutable_types.pyi`: `MutableStructMeta`/`MutableUnionMeta` extend
  `ABCMeta`; add missing `fill_specs` declaration.
- `mutable_typeinfos.pyi`: add `MutableStructTypeInfo.__init__(klass)`.
- `client/client_wrapper.py`: `Client.Async`/`Client.Sync` become
  `ClassVar[Type[...]]` so generated nested-class overrides aren't
  flagged as inconsistent overrides under Pyrefly.
- `services.whisker`: generated `getFunctionTable` returns
  `Mapping[bytes, object]` matching the loosened base.
- Regenerated affected python service fixtures.

All changes are backwards-compatible with Pyre (verified — the
`fbcode//thrift/lib/python:{types,mutable_types}-type-checking` Pyre
targets still pass), and they unblock typing for any tree on Pyrefly.
