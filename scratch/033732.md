Commit title: Guard MoQ transport stats after session close
Commit body:
Summary: D105051199 moved the WebTransport handler from `MoQClientBase` to `MoQSession`, which removed the old `MoQClientBase::onSessionEnd()` cleanup that exchanged `quicWebTransport_` to null after WebTransport teardown. After that change, `MoQClient::getTransportInfo()` could observe a non-null `quicWebTransport_` whose underlying `QuicWebTransport::quicSocket_` had already been cleared by connection close, so a later `getNetworkStats()` poll passed the wrapper null check and hit `XCHECK(quicSocket_)`, causing the fbios v565 SIGABRT in T274269884. This combined fix treats both `MoQSession::isClosed()` and a missing `QuicWebTransport::quicSocket_` as inactive transport state. It also incorporates Hani Lamaj's hardening suggestion by exposing a const `QuicSocket` snapshot from `QuicWebTransport` and having `MoQClient` read stats and flow-control state from that snapshot, so teardown returns `std::nullopt` or `CONNECTION_CLOSED` instead of entering `QuicWebTransport::getTransportInfo()` after the socket has been cleared.
