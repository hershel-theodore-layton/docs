Commit title: Do not generate intersection when refining an enforced type against dynamic
Commit body:
Summary:
A common pattern is the use of `is` and `as` on variables of type `dynamic`. Currently, these refine the variable to have an intersection type, for example, doing `as C` on a variable of type `dynamic` produces a variable of type `C & dynamic`. Unfortunately, this provides no additional type-checking as downstream operations will go through the `dynamic` conjunct.

Instead, for fully-enforceable types at first, refine to `C`.

A small change to the simplification of unions is necessary in order that true and false branches of conditionals properly union to restore the original type of the local.
