Commit body:
Summary:
test_hh_cargo runs hh_cargo_check.sh, which runs `cargo check` over the
hphp/hack/src workspace. The hand-written build.rs files for the cxx FFI
bridges hardcode `-std=c++17`.

folly recently moved folly/lang/cstring_view.h onto C++20 (it now has
`static_assert(FOLLY_CPLUSPLUS >= 202002L)`). hhvm_runtime_options's build
script compiles hphp/util/process-cpu.cpp, which includes
folly/system/HardwareConcurrency.h -> folly/lang/cstring_view.h. Under
C++17 that static_assert fires, the C++ build fails, and `cargo check`
exits 101.

Bump every hack cargo C++ FFI build.rs from c++17 to c++20 so they match
the C++ standard buck already uses to compile these same .cpp files. Doing
all of them (not just the one failing today) keeps the workspace on a
single standard and avoids the next folly C++20 header re-breaking a
sibling bridge.
