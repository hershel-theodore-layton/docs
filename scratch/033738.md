Commit title: Honor __PackageOverride on dependents in --package-lint-full
Commit body:
Summary:
`serverPackageLint`'s `--package-lint-full` was resolving dependents' packages via `get_package_for_file`, ignoring any `__PackageOverride` on the dependent side. This made the "can the dependent still reach the target without the target's override?" test  give wrong answers when the dependent itself has an override.

This diff updates `serverPackageLint` so that it resolves dependents' effective package via the override-honored `get_package_with_override_for_file` while keeping the target side path-only (since the question is "what if we removed the target's  override?").  Also adds a same-file carveout matching Typing_packages.can_access_by_package_rules.

REMARK: the new function `get_package_with_override_for_file` is expensive as it scans the file content and should never be used from the typecheck, where precise package information can be obtained by querying decls.
