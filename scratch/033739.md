Commit title: Clamp oversized user-exception message in Rocket->THeader
Commit body:
Summary:
When SR proxy translates a Rocket response back to THeader for a legacy
THeader client, the user-exception message (uexw/puexw header) is copied
verbatim out of the size-unbounded Rocket payload. A ~8MB downstream
exception overflowed THeader's 16-bit header-length field, producing a
frame the client could not decode and leaking the response ByteBuf,
which drove Iris hosts to direct-memory OOM (S669483).

Clamp the exception message to a size that always fits the THeader header
budget (32KiB) before writing it into the uexw/puexw header, appending a
truncation marker so the diagnostic is visibly cut rather than corrupt.
The fix lives at the translation copy site
(RocketClientChannelBase::processFirstResponse) via a helper next to the
header-name constants in RpcMetadataUtil.h.

Note: this guards the exception path that caused the SEV. Hardening
THeader's writer to reject any header that cannot round-trip is a broader
follow-up.
