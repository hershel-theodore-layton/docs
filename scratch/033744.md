Commit title: Roll back partial materialization in insertDefinitions
Commit body:
Summary:
TypeSystem nodes get populated in a two-phase (stub + fill) approach, as there can be circular dependencies between types.

This conflicts with the atomicity guarantees of `AccumulatingTypeSystem`, as we don't want to apply partial changes. This diffs ensures that `insertDefinitions` is wrapped in a scope guard that erases every node and source-index entry the call added if it throws, giving it strong exception safety, making it an atomic action.
