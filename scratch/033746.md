Commit body:
Summary: The `dtoa_mode` / `dtoa_flags` fallback in `folly::json::serialization_opts` was the last coupling between `folly/json` and Google's double-conversion library. All callers have migrated to `float_format` (the final gap was `FloatFormat::SHORTEST_SINGLE{,_TRAILING_DOT_ZERO}`, landed in the previous diff). This diff completes the removal: fixes a bug where `SHORTEST_SINGLE` and `SHORTEST_SINGLE_TRAILING_DOT_ZERO` were added twice to `FloatFormat`; removes `dtoa_mode` and `dtoa_flags` from `serialization_opts` (keeping `double_num_digits` for `FIXED`/`GENERAL`); removes the `!opts_.float_format` branch in `appendDouble` that called `folly::toAppend` with DtoaMode/DtoaFlags (unset `float_format` now defaults to `SHORTEST` via `value_or`); deletes the two tests whose only purpose was validating the removed fallback. Applied to both `fbcode/folly/json` and `xplat/folly/json`.
